# Known pitfalls: all languages

From the reviews of the trial translations (cs, ar). Check each one in every sentence.

- **Literal English phrases.** Do not copy the English sentence pattern. "runs late", "is late",
  "in place", "start on the project start", "in on-mode", "as it were", "only" placed after the verb:
  write what the language's own software documentation says.
- **A term outside its meaning.** The same English word can name two things: a lunch *break* is not a
  task *interruption*, a house *extension* is not a software *extension*, *calculate* in a sentence is
  not the *Calculate* command. Use the term only where `definition` fits.
- **Small words dropped or added.** Check every adjective, modal verb (can, must, may) and small adverb
  (only, also, after all, still, already) against the English. "the Dutch public holidays" keeps
  "Dutch"; "you can zoom in further" keeps "can".
- **Ribbon tabs.** In a menu path `*A › B*` and in "on the *X* tab", X is a ribbon or settings tab. Use
  the tab's own label (cs *Plán*, not *Plánování*).
- **Example names.** Names of example tasks, projects, calendars and resources stay in English exactly
  as in the source, also in plain sentences and link text.
- **UI placeholders.** Never copy `{{n}}` or another `{{…}}` from a UI text into the guide; write what
  the source shows.
- **One word per thing.** The same panel, heading, label line ("Default:", "Where:") or example name is
  written the same way in the whole article.
