# باز کردن فایل MS Project (.mpp)

هدف: باز کردن برنامه‌ای از Microsoft Project مستقیم در نرم‌افزار، بدون اینکه ابتدا آن را صادر کنید.

## زمانی که این را لازم دارید

یک پیمانکار، مشاور یا کارفرما برنامهٔ خود را به‌صورت فایل `.mpp` برای شما می‌فرستد. شما می‌خواهید آن را ببینید، محاسبه کنید یا بیشتر توسعه دهید. نرم‌افزار فایل‌های `.mpp` مربوط به MS Project 2010 تا 2021 را می‌خواند. فقط می‌خواند: `.mpp` نمی‌نویسد و فایل شما را هرگز تغییر نمی‌دهد. نرم‌افزار از فایل، خود برنامه را می‌گیرد: وظیفه‌ها با ساختار، مدت و محدودیت‌ها، رابطه‌ها با تأخیر، تقویم‌ها، منابع، تخصیص‌ها و پیشرفت. نرم‌افزار همچنین تاریخ‌ها و شناوری‌هایی را که خود MS Project محاسبه کرده است می‌خواند، اما آن‌ها را فقط برای نمای *تاریخ‌های ثبت‌شده* به کار می‌برد، هرگز به‌عنوان ورودی.

## مراحل

1. *خانه › فایل › باز کردن* را انتخاب کنید یا Ctrl+O را فشار دهید. فایل `.mpp` را انتخاب کنید.
2. پروژه در زبانه‌ای تازه باز می‌شود، یا در زبانهٔ فعلی اگر هنوز خالی و بدون تغییر بوده باشد. پروژه فایل ندارد: بعداً *ذخیره* یک فایل IFC جدید می‌نویسد. پنجره‌ای کوتاه توضیح می‌دهد که نرم‌افزار چه چیزهایی از فایل گرفته است و ذخیره چطور کار می‌کند؛ [باز کردن و ذخیرهٔ فایل](docs://howto-bestand-openen-en-opslaan) را ببینید.
3. پیام پایین را بخوانید: *این پروژه به‌صورت Microsoft Project محاسبه می‌شود. از فایل ← اطلاعات پروژه ← پروفایل محاسبه و گزینه‌ها تغییر دهید.* نرم‌افزار این پروژه را با قواعد محاسبهٔ MS Project محاسبه می‌کند: پروفایل محاسبهٔ *Microsoft Project*. با *باز کردن پروفایل محاسبه* به تنظیم می‌روید، *بیشتر بخوانید* راهنمای پروفایل‌های محاسبه را باز می‌کند.
4. بررسی کنید آیا زیر نوار فرمان‌ها پیامی هست: *شما تاریخ‌ها را همان‌طور که در فایل ثبت شده مشاهده می‌کنید؛ محاسبه مجدد 4 فعالیت را جابه‌جا می‌کند.* آنگاه روی آن وظیفه‌ها، نتیجهٔ نرم‌افزار با تاریخ‌هایی که MS Project ذخیره کرده فرق دارد. زیر پیام مرحلهٔ 3 یک خط دیگر هم هست: *4 فعالیت تاریخ‌های ثبت‌شده در فایل را نشان می‌دهند (بدون محاسبه مجدد).* آنچه این یعنی و اینکه چطور به محاسبهٔ خود نرم‌افزار بروید، در [تاریخ‌های ثبت‌شده](docs://uitleg-datums-zoals-opgeslagen) آمده است.
5. اگر *این فایل شامل برنامه‌ریزی ساعتی است.* و دکمهٔ *فعال‌سازی برنامه‌ریزی ساعتی* را نشان دهد، فایل داده‌هایی بر حسب ساعت دارد. [روشن کردن برنامه‌ریزی ساعتی](docs://howto-urenplanning-aanzetten) را ببینید.

اگر فایل وظیفه‌هایی با زمان‌بندی شکسته‌شده، تسطیح‌شده یا منبع‌محور داشته باشد، پیام دیگری اضافه می‌شود، مانند *این فایل MS Project شامل 3 وظیفه با زمان‌بندی شکسته‌شده، تراز‌شده یا منابع‌محور است. به همین صورت وارد و نمایش داده می‌شوند.* اگر فقط یک وظیفه باشد، پیام به‌صورت مفرد است.

## مشکل‌ها و آنچه نرم‌افزار در آن حالت انجام می‌دهد

**همه‌چیز همراه نمی‌آید.** پس از باز کردن، نرم‌افزار در یک پیام می‌گوید چه چیزی را وارد نکرده است: *برخی از محتوای این فایل MS Project وارد نشد.* زیر آن برای هر مورد یک خط با تعداد آن هست، برای مثال *2 خط مبنا وارد نشد.* برای یک `.mpp`، جملهٔ مربوط به پروفایل محاسبه از مرحلهٔ 3 در این پیام خط اول است. پیام تا وقتی می‌ماند که روی ضربدر کلیک کنید. اگر چیزی گم نشده باشد، این پیام را نمی‌بینید. یک خط می‌تواند دربارهٔ این موارد باشد:

- پروژه‌های درج‌شده (زیرپروژه): نرم‌افزار آنها را مانند یک وظیفهٔ عادی می‌خواند، بدون ارتباط با فایل دیگر؛
- وظیفه‌های خارجی از پروژهٔ دیگر: نرم‌افزار آنها را مانند یک وظیفهٔ عادی می‌خواند؛
- خطوط مبنا: از یک `.mpp` نرم‌افزار هیچ خط مبنایی نمی‌گیرد؛ از XML مربوط به MS Project فقط خط مبنای 0 وظیفه‌ها را می‌گیرد، و از آن فقط تاریخ‌ها و مدت را (برای وظیفه‌ای بر حسب ساعت، زمان را هم؛ نه کار و هزینه، و نه خطوط مبنای منابع و تخصیص‌ها);
- با XML مربوط به MS Project: تخصیصی که خط مبنایش تاریخ‌هایی غیر از وظیفهٔ خودش دارد. نرم‌افزار فقط خط مبنای وظیفه را نگه می‌دارد؛ اگر تاریخ‌ها یکی باشند، چیزی گم نمی‌شود و نرم‌افزار چیزی گزارش نمی‌کند. زمان دیگری در همان روز هم یک تفاوت به حساب می‌آید؛
- فیلدهای سفارشی با مقدار، مانند خود فیلدهای سفارشی، مقادیر جدول جستجو و کدهای ساختار (نرم‌افزار فیلدهای بله/خیر را در یک `.mpp` نمی‌شمارد);
- یادداشت‌ها (همچنین یادداشتی که فقط تصویر دارد) روی منابع و تخصیص‌ها، و از یک `.mpp` روی وظیفه‌ها هم (از XML مربوط به MS Project، یادداشت یک وظیفه به‌عنوان توضیح آن وارد می‌شود);
- ابرپیوندها;
- هزینه‌های ثابت وظیفه‌ها;
- نرخ‌های منابع: از یک `.mpp` هیچ نرخی نمی‌گیرد، از XML مربوط به MS Project فقط نرخ استاندارد;
- فقط با XML مربوط به MS Project: وظیفه‌های زمان‌بندی دستی (نرم‌افزار آنها را خودکار زمان‌بندی می‌کند)، وظیفه‌های غیرفعال (آنها در محاسبه قرار می‌گیرند) و تأخیر تسطیح;
- فقط با یک `.mpp`: آستانهٔ بحرانی از MS Project؛ نرم‌افزار آستانهٔ 0 را به کار می‌برد.

کد WBS که خودتان در MS Project وارد کرده‌اید گرفته می‌شود؛ در غیر این صورت نرم‌افزار وظیفه‌ها را بر اساس ساختار شماره‌گذاری می‌کند.

**فایلی از MS Project 2007 یا قدیمی‌تر.** نرم‌افزار آن را نمی‌پذیرد و این پیام را نشان می‌دهد: *این فایل .mpp از قالبی قدیمی (Project 2007 یا قدیمی‌تر) استفاده می‌کند. آن را در MS Project به‌صورت XML صادر کنید (فایل ← ذخیره به‌عنوان ← XML) و آن فایل را باز کنید.* زیر پیام، نرم‌افزار یک دلیل فنی به انگلیسی اضافه می‌کند.

**فایل با رمز عبور.** نرم‌افزار این پیام را نشان می‌دهد: *این فایل .mpp با رمز عبور محافظت شده است. آن را در MS Project به‌صورت XML صادر کنید (فایل ← ذخیره به‌عنوان ← XML) و آن فایل را باز کنید.* اینجا هم پیام همراه یک دلیل فنی به انگلیسی می‌آید.

**فایلی که معلوم می‌شود `.mpp` نیست.** پیام *باز کردن فایل ناموفق بود* را می‌بینید، همراه با یک دلیل فنی.

**مسیر XML جور دیگری محاسبه می‌کند.** اگر به جای فایل `.mpp`، خروجی XML از MS Project را باز کنید، نرم‌افزار با پروفایل محاسبهٔ *Open Planner Studio* محاسبه می‌کند و پیام دربارهٔ *Microsoft Project* را نمی‌بینید. در این صورت تاریخ‌ها ممکن است با فایل `.mpp` فرق داشته باشند. با خروجی XML هم نرم‌افزار می‌گوید چه چیزی را وارد نمی‌کند؛ به *همه‌چیز همراه نمی‌آید* نگاه کنید.

**یک ویرایش، هدایت MS Project را رها می‌کند.** اگر وظیفه‌ای را ویرایش کنید که برنامه‌اش با پنجرهٔ تاریخ MS Project هدایت می‌شد، نرم‌افزار این پیام را برای هر پروژه یک بار نشان می‌دهد: *توزیع ساعات MS Project پس از این ویرایش دیگر 2 وظیفه را هدایت نمی‌کند؛ توزیع اصلی در فایل نگه داشته می‌شود.* اگر فقط یک وظیفه باشد، پیام به‌صورت مفرد است.

**ذخیره هرگز `.mpp` شما را بازنویسی نمی‌کند.** پروژه فایل ندارد. *ذخیره* می‌پرسد فایل IFC جدید کجا ذخیره شود.
