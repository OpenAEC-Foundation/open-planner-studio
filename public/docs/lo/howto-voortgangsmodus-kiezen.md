# ເລືອກຮູບແບບຄວາມຄືບໜ້າ

ເປົ້າໝາຍ: ຕັດສິນໃຈວ່າ ແອັບຈະວາງແຜນວຽກທີ່ເຫຼືອຂອງໜ້າວຽກ ທີ່ເລີ່ມແລ້ວ ໃນຂະນະທີ່ໜ້າວຽກກ່ອນໜ້າຍັງດຳເນີນຢູ່ ແນວໃດ: ຕາມສາຍສຳພັນ (Retained Logic) ຫຼື ຕາມສິ່ງທີ່ເກີດຂຶ້ນຈິງ (Progress Override).

## ເມື່ອໃດທີ່ທ່ານຕ້ອງການສິ່ງນີ້

ໃນສະຖານທີ່ກໍ່ສ້າງ ວຽກມັກຈະລ້ຳໜ້າກວ່າລຳດັບໃນຕາລາງ. ຊ່າງທາສີເລີ່ມໃນຫ້ອງທີ່ສາຍປູນແລ້ວ ໃນຂະນະທີ່ຊ່າງສາຍປູນຍັງຢູ່ບ່ອນອື່ນ. ໃນແຜນງານ ນັ້ນແມ່ນ ຕົວຢ່າງ ສາຍສຳພັນ ສຳເລັດ-ເລີ່ມຕົ້ນ ທີ່ໜ້າວຽກຖັດໄປເລີ່ມກ່ອນໜ້າວຽກກ່ອນໜ້າສຳເລັດ. ແອັບເອີ້ນສິ່ງນັ້ນວ່າ **ຄວາມຄືບໜ້າຂ້າມລຳດັບ**. ຖ້າແຖບສະຖານະສະແດງ *ສາຍສຳພັນຂ້າມລຳດັບ N ລາຍການ*, ທ່ານມີກໍລະນີແບບນີ້. ຮູບແບບຄວາມຄືບໜ້າ ກຳນົດວ່າ ແອັບຈະວາງແຜນວຽກທີ່ເຫຼືອຂອງໜ້າວຽກຖັດໄປ ແນວໃດ. ສອງຮູບແບບເຮັດຫຍັງ ພ້ອມຕົວຢ່າງ ຢູ່ໃນ [ຄວາມຄືບໜ້າ, ວັນທີສະຖານະ ແລະ ແຜນຫຼັກ](docs://uitleg-voortgang).

## ຂັ້ນຕອນ

1. ອັບເດດຄວາມຄືບໜ້າ ແລະ ຕັ້ງວັນທີສະຖານະ ຕາມທີ່ໄດ້ອະທິບາຍໄວ້ໃນ [ການອັບເດດຄວາມຄືບໜ້າ](docs://howto-voortgang-bijwerken).
2. ໄປທີ່ *ການວາງແຜນ › ແຜນຖານ ແລະ ຄວາມຄືບໜ້າ › ຮູບແບບຄວາມຄືບໜ້າ* ແລ້ວເປີດລາຍການ.
3. ເລືອກ *ຮັກສາຕາມເງື່ອນໄຂເດີມ (Retained Logic)* ຫຼື *ຂ້າມເງື່ອນໄຂເດີມ (Progress Override)*.
4. ກົດ **ຄິດໄລ່** (F5), ຕົວຢ່າງ ຜ່ານ *ການວາງແຜນ › ຕາຕະລາງເວລາ › ຄິດໄລ່*. ການເລືອກນີ້ ເຮັດໃຫ້ແຜນງານເປັນຂໍ້ມູນເກົ່າ: ແຖບສະຖານະ ສະແດງ *ຂໍ້ມູນເກົ່າແລ້ວ — ກະລຸນາຄິດໄລ່ຄືນໃໝ່ (F5)*. ຖ້າ *ຄິດໄລ່ອັດຕະໂນມັດ* ເປີດຢູ່ ແອັບຈະເຮັດສິ່ງນີ້ດ້ວຍຕົນເອງ.

ທ່ານຈະເລືອກແນວໃດ?

- **Retained Logic** ແມ່ນ ຄ່າເລີ່ມຕົ້ນ. ສາຍສຳພັນຍັງມີຜົນຢູ່: ວຽກທີ່ເຫຼືອຂອງໜ້າວຽກຖັດໄປ ຈະເລີ່ມພຽງແຕ່ເມື່ອໜ້າວຽກກ່ອນໜ້າສຳເລັດແລ້ວ. ເລືອກອັນນີ້ ຖ້າລຳດັບຖືກກຳນົດແທ້ໆ ຫຼື ຖ້າທ່ານຕ້ອງການວາງແຜນຢ່າງລະມັດລະວັງ.
- **Progress Override** ໃຫ້ຄວາມເປັນຈິງຊະນະ. ວຽກທີ່ເຫຼືອຂອງໜ້າວຽກຖັດໄປ ເລີ່ມໃນວັນທີສະຖານະ ໂດຍບໍ່ລໍຖ້າໜ້າວຽກກ່ອນໜ້າ. ເລືອກອັນນີ້ ຖ້າໜ້າວຽກຖັດໄປຍັງເຮັດວຽກຢູ່ແທ້ໆ ແລະ ວັນສິ້ນສຸດບໍ່ຄວນຂຶ້ນກັບໜ້າວຽກກ່ອນໜ້າທີ່ຍັງດຳເນີນຢູ່.

## ກວດສອບຜົນລັບ

- ກົດຂໍ້ຄວາມ *ສາຍສຳພັນຂ້າມລຳດັບ N ລາຍການ* ໃນແຖບສະຖານະ. ແຜງ *ຄຳເຕືອນ* ເປີດຂຶ້ນ ເຊິ່ງກໍ່ເປີດໄດ້ຜ່ານ *ການວາງແຜນ › ຕາຕະລາງເວລາ › ຄຳເຕືອນ* ເຊັ່ນກັນ. ທຸກສາຍສຳພັນຢູ່ໃນນັ້ນ ພ້ອມຂໍ້ຄວາມ *ຂ້າມລຳດັບ: ຄວາມຄືບໜ້າຂອງໜ້າວຽກຖັດໄປຂັດກັບສາຍສຳພັນທີ່ຕັ້ງໄວ້* ຕົວຢ່າງ *4.2 Plastering → 4.5 Painting (FS)*.
- ເບິ່ງ ແຖບໜ້າວຽກ ຂອງໜ້າວຽກຖັດໄປ. ພາຍໃຕ້ Retained Logic ແຖບຈະດຳເນີນໄປຈົນຫຼັງວັນສິ້ນສຸດຂອງໜ້າວຽກກ່ອນໜ້າ. ພາຍໃຕ້ Progress Override ແຖບຈະສິ້ນສຸດກ່ອນ. ໃນຕົວຢ່າງຂອງຄຳອະທິບາຍ ນັ້ນແມ່ນ ວັນອັງຄານ 27 ກໍລະກົດ ເທຽບກັບ ວັນພະຫັດ 22 ກໍລະກົດ.

## ຂໍ້ຄວນລະວັງ ແລະ ສິ່ງທີ່ແອັບເຮັດ

**ບໍ່ມີຄວາມແຕກຕ່າງ.** ຮູບແບບນີ້ມີຜົນພຽງແຕ່ກັບໜ້າວຽກທີ່ເລີ່ມແລ້ວ ໃນຂະນະທີ່ໜ້າວຽກກ່ອນໜ້າຍັງບໍ່ສຳເລັດ. ຖ້າບໍ່ມີໜ້າວຽກແບບນີ້ ຈະບໍ່ມີຫຍັງປ່ຽນແປງ.

**ຂໍ້ຄວາມຍັງຢູ່.** Progress Override ບໍ່ແກ້ຂໍ້ຄວາມກ່ຽວກັບຄວາມຄືບໜ້າຂ້າມລຳດັບ. ຮູບແບບເປັນຕົວກຳນົດວິທີທີ່ແອັບຄິດໄລ່; ຄວາມຂັດແຍ້ງລະຫວ່າງສາຍສຳພັນ ແລະ ຄວາມຄືບໜ້າ ຍັງຄົງຢູ່. ຖ້າສາຍສຳພັນບໍ່ຖືກຕ້ອງອີກຕໍ່ໄປ ໃຫ້ປ່ຽນມັນ ([ການເພີ່ມສາຍສຳພັນ](docs://howto-relaties-leggen)).

**ມັນເປັນຂອງໂຄງການ.** ການເລືອກຖືກບັນທຶກກັບໄຟລ໌ໂຄງການ, ໃຊ້ກັບທັງໂຄງການ ແລະ ຍົກເລີກໄດ້ດ້ວຍ Ctrl+Z. ໂຄງການໃໝ່ຢູ່ໃນ Retained Logic.

**ໄຟລ໌ P6.** ຖ້າທ່ານເປີດໄຟລ໌ Primavera P6 (.xer), ແອັບຈະເອົາຮູບແບບຈາກໄຟລ໌. ນອກຈາກ Retained Logic ແລະ Progress Override, P6 ຍັງມີຮູບແບບ ວັນທີຕົວຈິງ (Actual Dates). ແອັບບໍ່ຮູ້ຮູບແບບທີສາມນັ້ນ; ໄຟລ໌ແບບນັ້ນຄິດໄລ່ເປັນ Retained Logic. ຂໍ້ຄວາມນຳເຂົ້າ ນັບເລື່ອງນັ້ນເປັນ *ການຕັ້ງຄ່າຕາຕະລາງ P6 ໃຊ້ຄ່າສຳຮອງທີ່ປອດໄພ 1 ລາຍການ.*

**ໂປຣໄຟລ໌ການຄິດໄລ່.** ໃນໂປຣໄຟລ໌ Primavera P6, Progress Override ກໍ່ເຮັດວຽກຍ້ອນຫຼັງ, ໃນ ວັນທີ late ແລະ ໃນ free float ຂອງໜ້າວຽກກ່ອນໜ້າ (ຂໍ້ກຳນົດ *Progress Override ຈະລະເລີຍໜ້າວຽກຖັດໄປທີ່ເລີ່ມແລ້ວໃນຝັ່ງ late ນຳ*). ໃນໂປຣໄຟລ໌ Open Planner Studio ແລະ Microsoft Project ບໍ່ເປັນແບບນັ້ນ. ທ່ານຈະພົບຂໍ້ກຳນົດ ໃນ *ການຕັ້ງຄ່າ › ໂຄງການ › ການຕັ້ງຄ່າໂຄງການ*, ໃນສ່ວນ *ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ*. ໃນຕົວຢ່າງຂອງຄຳອະທິບາຍ ຜົນຍ້ອນຫຼັງນັ້ນ ບໍ່ສາມາດເຫັນໄດ້.
