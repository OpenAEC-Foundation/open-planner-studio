# ຮູບແບບການນຳເຂົ້າ ແລະ ສົ່ງອອກ

ສຳລັບແຕ່ລະຮູບແບບໄຟລ໌: ທ່ານເປີດໄດ້ບໍ່, ບັນທຶກໄດ້ບໍ່ ແລະ ສົ່ງອອກໄດ້ບໍ່, ຂໍ້ມູນໃດຕິດໄປນຳ ແລະ ໃດບໍ່ຕິດໄປ, ແລະ ເປີດດ້ວຍໂປຣໄຟລ໌ການຄິດໄລ່ໃດ. ເຫດຜົນເບື້ອງຫຼັງທັງໝົດນີ້ ແລະ ຕົວຢ່າງທີ່ມີຕົວເລກ ຢູ່ໃນ [ໄຟລ໌ ແລະ ຮູບແບບ](docs://uitleg-bestanden).

## ພາບລວມ

**ການເປີດ** ໃຊ້ໄດ້ກັບ IFC, CSV, MS Project XML, Primavera P6 XML, `.mpp` ແລະ `.xer`. ໄຟລ໌ທີ່ມີນາມສະກຸນອື່ນ ແອັບຈະຖືວ່າເປັນ IFC.

**ການບັນທຶກ** ຂຽນເປັນ IFC ສະເໝີ. ມີແຕ່ໄຟລ໌ IFC ທີ່ເປີດແລ້ວເທົ່ານັ້ນ ທີ່ກາຍເປັນເປົ້າໝາຍການບັນທຶກ; ໂຄງການຈາກຮູບແບບອື່ນ ບໍ່ມີໄຟລ໌ຫຼັງຈາກເປີດ ແລະ *ບັນທຶກ* ຈະຖາມວ່າໄຟລ໌ IFC ຄວນຖືກບັນທຶກໄວ້ບ່ອນໃດ.

**ການສົ່ງອອກ** ໃຊ້ໄດ້ກັບ IFC, MS Project XML, Primavera P6 XML, CSV ແລະ ໃບຄວາມຄືບໜ້າ ສອງແບບ (Excel ແລະ CSV). ການສົ່ງອອກ ບໍ່ປ່ຽນໂຄງການຂອງທ່ານ.

**ອ່ານຢ່າງດຽວ** ແມ່ນ `.mpp` ແລະ `.xer`: ແອັບເປີດໄຟລ໌ເຫຼົ່ານີ້ໄດ້ ແຕ່ຂຽນບໍ່ໄດ້.

**PDF** ມາຈາກລາຍງານເທົ່ານັ້ນ (ເບິ່ງ [ປະເພດບົດລາຍງານ](docs://ref-rapporttypes)). ແອັບບໍ່ອ່ານ PDF.

**ບ່ອນ.** ການເປີດ: *ໜ້າຫຼັກ › ໄຟລ໌ › ເປີດ*, *ໄຟລ໌ › ເປີດ* ຫຼື Ctrl+O. ການສົ່ງອອກ: *ໜ້າຫຼັກ › ໄຟລ໌ › ສົ່ງອອກ* ຫຼື *ໄຟລ໌ › ສົ່ງອອກ*. ທ່ານອ່ານໃບຄວາມຄືບໜ້າທີ່ຕື່ມຂໍ້ມູນແລ້ວ ໂດຍ *ໄຟລ໌ › ນຳເຂົ້າ* ຫຼືດ້ວຍປຸ່ມ *ອັບເດດຄວາມຄືບໜ້າຈາກສະເປຣດຊີດ* ໃນກຸ່ມ *ຄວາມຄືບໜ້າ* ຂອງແຖບເຄື່ອງມື ໃນແຖບ *ການວາງແຜນ*, *ຕາຕະລາງ* ແລະ *ລາຍງານ*.

**ໂປຣໄຟລ໌ການຄິດໄລ່ເມື່ອເປີດ.** ທຸກຮູບແບບເປີດດ້ວຍໂປຣໄຟລ໌ການຄິດໄລ່. ໂປຣໄຟລ໌ນັ້ນແມ່ນຫຍັງ ຢູ່ໃນ [ຕົວເລືອກການຄິດໄລ່ ແລະ ຂໍ້ກຳນົດ](docs://ref-rekenopties-en-conventies). `.xer` ເປີດດ້ວຍ *Primavera P6*, `.mpp` ດ້ວຍ *Microsoft Project*, ແລະ CSV, MS Project XML ແລະ P6 XML ດ້ວຍ *Open Planner Studio*. IFC ຮັກສາໂປຣໄຟລ໌ທີ່ບັນທຶກໄວ້ໃນໄຟລ໌. ສຳລັບ `.xer` ແລະ `.mpp` ແອັບບອກວ່າໂຄງການຄິດໄລ່ດ້ວຍວິທີນີ້. ມີແຕ່ IFC ທີ່ບັນທຶກໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກການຄິດໄລ່; ໃນຕົວເລືອກການຄິດໄລ່ MS Project XML ຂຽນຢ່າງຫຼາຍແຕ່ເກນກຳນົດວິກິດ. ໄຟລ໌ສົ່ງອອກຈາກຮູບແບບອື່ນ ເມື່ອເປີດຄືນ ຈະຄິດໄລ່ເປັນ *Open Planner Studio*.

## IFC

**ເປີດ** — ໄດ້, `.ifc`. ແອັບອ່ານ IFC4 ແລະ IFC 4.3 (ລວມທັງ ADD2). ໄຟລ໌ໃນສະກີມອື່ນ ເຊັ່ນ IFC2X3 ກໍເປີດໄດ້ເຊັ່ນກັນ. ເມື່ອບັນທຶກຄັ້ງທຳອິດ ທ່ານຈຶ່ງເລືອກສະກີມທີ່ແອັບສາມາດຂຽນໄດ້ (ເບິ່ງ [ການເລືອກສະກີມ IFC](docs://howto-ifc-schema-kiezen)). ໂປຣໄຟລ໌ການຄິດໄລ່: ອັນທີ່ຢູ່ໃນໄຟລ໌.

**ບັນທຶກ** — ໄດ້, ແລະ ນີ້ແມ່ນຮູບແບບດຽວທີ່ບັນທຶກໄດ້. *ບັນທຶກ* ຂຽນທັງໂຄງການຂອງທ່ານເປັນໄຟລ໌ IFC ໃນສະກີມຂອງໂຄງການ (ຄ່າເລີ່ມຕົ້ນ IFC 4.3 ADD2). ໄຟລ໌ນັ້ນກາຍເປັນເປົ້າໝາຍການບັນທຶກ.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *IFC*, ໃນສະກີມ IFC ຂອງໂຄງການ (ຄ່າເລີ່ມຕົ້ນ IFC 4.3 ADD2). ຊື່ເລີ່ມຕົ້ນ: ຊື່ໂຄງການ ພ້ອມນາມສະກຸນ `.ifc`. ຖ້າໂຄງການຂອງທ່ານເຊື່ອມກັບຄັງຂໍ້ມູນ, ຊ່ອງໝາຍ *ບັນທຶກໄຟລ໌ຄັງຂໍ້ມູນໄວ້ຄຽງຄູ່ກັນ* ຢູ່ລຸ່ມກາດ ໃນ *ໄຟລ໌ › ສົ່ງອອກ*. ເມື່ອໝາຍຖືກ ແອັບຈະຖາມຫາບ່ອນເກັບ *ຊື່ໂຄງການ-bibliotheek.ifc* ຫຼັງຈາກໂຄງການ. ຊ່ອງໝາຍນີ້ບໍ່ຢູ່ໃນລາຍການໃນແຖບ *ໜ້າຫຼັກ*.

**ສິ່ງທີ່ຕິດໄປນຳ** — ທຸກຢ່າງທີ່ເປັນຂອງໂຄງການ: ໜ້າວຽກພ້ອມໂຄງສ້າງ, ໄລຍະເວລາ, ວັນທີ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ເງື່ອນໄຂ ແລະ ກຳນົດສົ່ງ; ປະຕິທິນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ ລວມທັງການກະຈາຍຕາມຊົ່ວໂມງ; ແຜນຫຼັກ; ລະຫັດກິດຈະກຳ ແລະ ຊ່ອງກຳນົດເອງ; ໝາຍເຫດ; ສາຍສຳພັນພາຍນອກກັບໂຄງການອື່ນ; ຊ່ວງພັກ; ປະເພດໜ້າວຽກ ແລະ ໝວດວຽກກຳນົດເອງ; ການຕັ້ງຄ່າໂຄງການ ເຊັ່ນ ວັນທີສະຖານະ, ຮູບແບບຄວາມຄືບໜ້າ, ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກການຄິດໄລ່; ການເຊື່ອມກັບຄັງຂໍ້ມູນ. ສຳລັບໂຄງການຈາກ `.xer`, ໄຟລ໌ຕົ້ນສະບັບກໍຕິດໄປນຳເຊັ່ນກັນ. ໝວດວຽກກຳນົດເອງ ຖືກເກັບເປັນປະເພດ IFC `USERDEFINED` ໂດຍມີຊື່ຂອງມັນຢູ່ໃນຊ່ອງ ObjectType, ດັ່ງນັ້ນໂປຣແກຣມ IFC ອື່ນອ່ານໜ້າວຽກໄດ້ປົກກະຕິ; ແອັບຍັງເກັບ id ຄົງທີ່ຂອງໝວດວຽກ, ດັ່ງນັ້ນການປ່ຽນຊື່ບໍ່ທຳລາຍການເຊື່ອມ. ຖ້າຜູ້ໜຶ່ງເປີດໄຟລ໌ໃນຄອມພິວເຕີອື່ນ ໝວດວຽກນັ້ນຈະປາກົດຢູ່ທີ່ນັ້ນພາຍໃຕ້ *ຈາກໂຄງການນີ້*, ບໍ່ແມ່ນໃນ *ໝວດວຽກຂອງຂ້ອຍ* ຂອງເພິ່ນ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ການຕັ້ງຄ່າໜ້າຈໍຂອງທ່ານ (ການຊູມ, ຕຳແໜ່ງເລື່ອນ, ໜ້າວຽກທີ່ເລືອກ, ກຸ່ມທີ່ພັບໄວ້, ຕົວກອງ ແລະ ການຈັດກຸ່ມທີ່ເລືອກ) ແລະ ການຕັ້ງຄ່າແອັບ ([ການຕັ້ງຄ່າແອັບ](docs://ref-instellingen)). ແຖບ *IFC* ເປັນຕົວແກ້ໄຂທີ່ສະແດງຂໍ້ຄວາມ IFC ຂອງໂຄງການທ່ານ. *ສ້າງ IFC* ໂຫຼດຂໍ້ຄວາມໃໝ່, *ສຳເນົາ* ຄັດລອກໃສ່ຄລິບບອດ ແລະ *ນຳໃຊ້* ໂຫຼດຂໍ້ຄວາມເປັນໂຄງການຂອງທ່ານ ແລະ ແທນທີ່ໂຄງການໃນແຖບນັ້ນ.

## MS Project XML (MSPDI)

**ເປີດ** — ໄດ້. ແອັບຈຳໄຟລ໌ `.xml` ວ່າເປັນ MS Project XML ຈາກອົງປະກອບຮາກ `Project` ໃນຊ່ອງຊື່ (namespace) ຂອງ MS Project (ຫຼືບໍ່ມີຊ່ອງຊື່). ໂປຣໄຟລ໌ການຄິດໄລ່: *Open Planner Studio*. ຫຼັງຈາກເປີດ ແອັບບອກທ່ານໃນຂໍ້ຄວາມດຽວວ່າມັນບໍ່ໄດ້ເອົາສິ່ງໃດມາ; ເບິ່ງ [ການເປີດໄຟລ໌ Microsoft Project (.mpp)](docs://howto-mpp-openen).

**ບັນທຶກ** — ບໍ່ໄດ້. ໂຄງການແບບນີ້ບໍ່ມີເປົ້າໝາຍການບັນທຶກ.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *MS Project XML* (*ເປີດໃນ Microsoft Project ໄດ້. ຮັກສາໂຄງສ້າງ WBS ຄົບຖ້ວນ.*). ຊື່ເລີ່ມຕົ້ນ: ຊື່ໂຄງການ ພ້ອມ `.xml`.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໜ້າວຽກພ້ອມໂຄງສ້າງ (ລະດັບ ແລະ WBS), ໄລຍະເວລາ, ວັນທີ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag, ທັງເປັນຊົ່ວໂມງ ຫຼື ເປັນເປີເຊັນ; ເງື່ອນໄຂ ລວມທັງກຳນົດສົ່ງ; ປະຕິທິນ ລວມທັງປະຕິທິນຂອງໜ້າວຽກ ແລະ ຂອງຊັບພະຍາກອນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ ລວມທັງເສັ້ນໂຄ້ງ ຫຼື ການກະຈາຍຕາມຊົ່ວໂມງ; ວັນທີສະຖານະ; ເກນກຳນົດວິກິດ ເປັນຈຳນວນເຕັມຂອງມື້ເຮັດວຽກ 0 ຂຶ້ນໄປ ພ້ອມ *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ*; ລາຍລະອຽດຂອງໜ້າວຽກ (ເປັນໝາຍເຫດ); ປະເພດໜ້າວຽກຂອງໜ້າວຽກ (ເປັນປະເພດໜ້າວຽກຂອງ Microsoft Project); ໝວດວຽກກຳນົດເອງ ໃນຊ່ອງອິດສະຫຼະ (`ExtendedAttribute`) ທີ່ແອັບອ່ານກັບຄືນ ແລະ ທີ່ Microsoft Project ອາດບໍ່ສົນໃຈ. ໃນບັນດາແຜນຫຼັກຂອງທ່ານ ມີແຕ່ແຜນທີ່ໃຊ້ຢູ່ເທົ່ານັ້ນ ທີ່ຕິດໄປນຳ, ເປັນແຜນຫຼັກ 0. ໜ້າວຽກທີ່ເປັນຊົ່ວໂມງ ຮັກສາຫົວໜ່ວຍຂອງມັນ, ແລະ ຫຼັກໝາຍ ຮັກສາປະເພດຂອງມັນ (ເລີ່ມ, ສິ້ນສຸດ ຫຼື ອັດຕະໂນມັດ).

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ໝາຍເຫດ (ລາຍການກວດສອບຂອງໜ້າວຽກ), ສາຍສຳພັນພາຍນອກກັບໂຄງການອື່ນ, ລະຫັດກິດຈະກຳ ແລະ ຊ່ອງກຳນົດເອງ, ເງື່ອນໄຂທີສອງ, ເຄື່ອງໝາຍ *ກຳນົດເວລາດ້ວຍຕົນເອງ*, ຄວາມຊັກຊ້າຈາກການປັບສົມດຸນ, ຈຸດດຳເນີນຕໍ່ ແລະ ຈຸດຢຸດຂອງໜ້າວຽກທີ່ມີຄວາມຄືບໜ້າຂ້າມລຳດັບ, ຂໍ້ກຳນົດ *ວຽກທີ່ເຫຼືອເລີ່ມຕໍ່ຫຼັງຈາກໄລຍະເວລາທີ່ຜ່ານໄປ* ແລະ *ບໍ່ຍ້າຍໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມໄປທີ່ວັນທີສະຖານະ* ຂອງໂປຣໄຟລ໌ MS Project, ແລະ ຕົວເລືອກການຄິດໄລ່ອື່ນໆ. ໜ້າວຽກທີ່ມີຊ່ວງພັກ ທີ່ບໍ່ມີການກະຈາຍຕາມຊົ່ວໂມງ ຕິດໄປນຳໂດຍບໍ່ມີຊ່ວງພັກຂອງມັນ.

**ວັນພັກເມື່ອເປີດ.** ປະຕິທິນທີ່ສືບທອດມາ ຈະຮັບຊ່ວງຍົກເວັ້ນຂອງປະຕິທິນຫຼັກ. ປະຕິທິນທີ່ມີອາທິດເຮັດວຽກຂອງມັນເອງ ແລະ ບໍ່ມີຊ່ວງຍົກເວັ້ນ ຈະບໍ່ໄດ້ວັນພັກ. ມີແຕ່ປະຕິທິນເປົ່າ ທີ່ບໍ່ມີປະຕິທິນຫຼັກ, ອາທິດເຮັດວຽກ ຫຼື ຊ່ວງຍົກເວັ້ນ ເທົ່ານັ້ນ ທີ່ຍັງຮັກສາວັນພັກມາດຕະຖານຂອງເນເທີແລນ. ຖ້າວັນພັກຂາດຫາຍ ວັນສິ້ນສຸດຂອງທ່ານອາດຈະແຕກຕ່າງ: ເບິ່ງ [ການສ້າງວັນພັກ ແລະ ວັນພັກຊ່າງກໍ່ສ້າງ](docs://howto-feestdagen-genereren).

**ສິ່ງທີ່ປ່ຽນລະຫວ່າງທາງ** — ເງື່ອນໄຂ *ຕ້ອງເລີ່ມໃນວັນທີ (MSO)* ຫຼື *ຕ້ອງສິ້ນສຸດໃນວັນທີ (MFO)* ໂດຍບໍ່ມີທາງເລືອກ *ບັງຄັບ (ປັກໝຸດແໜ້ນ)* ຈະກາຍເປັນ *ເລີ່ມບໍ່ກ່ອນ (SNET)* ຫຼື *ສິ້ນສຸດບໍ່ກ່ອນ (FNET)*. ແຮມມັອກກາຍເປັນໜ້າວຽກທຳມະດາ ທີ່ມີວັນທີທີ່ຄິດໄລ່ແລ້ວ. MS Project XML ເກັບຊົ່ວໂມງຕໍ່ມື້ສະເພາະປະຕິທິນໂຄງການເທົ່ານັ້ນ. ປະຕິທິນອື່ນທີ່ມີຊົ່ວໂມງຕໍ່ມື້ຂອງມັນເອງ ຈະໄດ້ເວລາເຮັດວຽກຂອງມັນເປັນຊົ່ວໂມງຕໍ່ມື້ ເມື່ອທ່ານເປີດໄຟລ໌: 8 ຊົ່ວໂມງຕໍ່ມື້ ທີ່ມີເວລາເຮັດວຽກ 10 ຊົ່ວໂມງ ກາຍເປັນ 10. ໜ້າວຽກທີ່ເປັນມື້ໃນປະຕິທິນແບບນີ້ ຈະສັ້ນລົງ, ຕົວຢ່າງ 4 ມື້ແທນ 5.

## ໄຟລ໌ Microsoft Project (`.mpp`)

**ເປີດ** — ໄດ້, ຈາກ MS Project 2010 ຫາ 2021. ໂປຣໄຟລ໌ການຄິດໄລ່: *Microsoft Project*. ແອັບອ່ານໄຟລ໌ເທົ່ານັ້ນ: ມັນບໍ່ປ່ຽນ `.mpp` ຂອງທ່ານເລີຍ. ໄຟລ໌ຈາກ MS Project 2007 ຫຼື ເກົ່າກວ່າ ແລະ ໄຟລ໌ທີ່ມີລະຫັດຜ່ານ ແອັບຈະປະຕິເສດ ດ້ວຍຂໍ້ຄວາມທີ່ຊີ້ໄປຫາການສົ່ງອອກ XML ຂອງ MS Project. ຫຼັງຈາກເປີດ ແອັບບອກທ່ານໃນຂໍ້ຄວາມດຽວວ່າມັນບໍ່ໄດ້ເອົາສິ່ງໃດມາ.

**ບັນທຶກ** — ບໍ່ໄດ້, ແລະ ບໍ່ມີເປົ້າໝາຍການບັນທຶກ: *ບັນທຶກ* ຂຽນໄຟລ໌ IFC ໃໝ່.

**ສົ່ງອອກ** — ບໍ່ໄດ້.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໜ້າວຽກພ້ອມໂຄງສ້າງ, ໄລຍະເວລາ ແລະ ເງື່ອນໄຂ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ປະຕິທິນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ; ຄວາມຄືບໜ້າ; ລະຫັດ WBS ທີ່ທ່ານໃສ່ເອງໃນ MS Project. ວັນທີ ແລະ float ທີ່ MS Project ຄິດໄລ່ເອງ ກໍຖືກອ່ານເຊັ່ນກັນ ສຳລັບມຸມມອງ *ວັນທີຕາມທີ່ບັນທຶກ*.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ແຜນຫຼັກ, ຕົ້ນທຶນ ແລະ ອັດຕາຄ່າໃຊ້ຈ່າຍ, ໝາຍເຫດ, ທີ່ຢູ່ເວັບ, ຊ່ອງກຳນົດເອງຂອງ MS Project, ການເຊື່ອມໂຍງໂຄງການຍ່ອຍ ແລະ ໜ້າວຽກພາຍນອກ, ແລະ ເກນກຳນົດວິກິດ. ເບິ່ງ [ການເປີດໄຟລ໌ Microsoft Project (.mpp)](docs://howto-mpp-openen).

**ທີ່ມາ ແລະ ໃບອະນຸຍາດ** — ໂຕອ່ານ `.mpp` ຖືກຂຽນສຳລັບ Open Planner Studio ແລະ ໄດ້ມາຈາກໂຄ້ດຕົ້ນສະບັບ ແລະ ຄວາມຮູ້ດ້ານໂຄງສ້າງຂອງ MPXJ (`github.com/joniles/mpxj`, Jon Iles ແລະ ຄະນະ), ເປັນຫໍສະໝຸດ Java ພາຍໃຕ້ LGPL-2.1. ໂຄງສ້າງ ແລະ ຄ່າຄົງທີ່ຂອງຊ່ອງຖືກປ່ຽນເປັນ TypeScript. Open Planner Studio ເອງເປັນຊອບແວເປີດພາຍໃຕ້ LGPL-3.0. ໂຕອ່ານ `.xer` ບໍ່ແມ່ນອະນຸພັນ: MPXJ ຖືກປຶກສາໃນສ່ວນນັ້ນ ພຽງແຕ່ເປັນແຫຼ່ງຄວາມເຂົ້າໃຈ.

## Primavera P6 XML

**ເປີດ** — ໄດ້. ແອັບຈຳໄຟລ໌ `.xml` ວ່າເປັນ P6 XML ຈາກອົງປະກອບຮາກ `APIBusinessObjects`. ໂປຣໄຟລ໌ການຄິດໄລ່: *Open Planner Studio*.

**ຫຼາຍໂຄງການໃນໄຟລ໌ດຽວ.** ແຕ່ລະໂຄງການທີ່ມີໜ້າວຽກ ເປີດໃນແຖບຂອງມັນເອງ ຊື່ *ຊື່ໂຄງການ (ID ໂຄງການ)*. ແອັບຂ້າມໂຄງການທີ່ບໍ່ມີໜ້າວຽກ. ແຖບທີ່ເຮັດວຽກແມ່ນໂຄງການທີ່ມີໜ້າວຽກຫຼາຍທີ່ສຸດ. ແອັບບໍ່ນຳສາຍສຳພັນໄປຫາໂຄງການອື່ນ, ແລະ ບໍ່ນຳໜ້າວຽກທີ່ບໍ່ຂຶ້ນກັບໂຄງການໃດມາ. ຫຼັງຈາກເປີດ ແອັບບອກວ່າເປີດໄດ້ຈັກໂຄງການ.

**ວັນພັກເມື່ອເປີດ.** ກົດດຽວກັນໃຊ້ໄດ້ກັບ MS Project XML: ປະຕິທິນທີ່ມີອາທິດເຮັດວຽກຂອງມັນເອງ ແລະ ບໍ່ມີຊ່ວງຍົກເວັ້ນ ຈະບໍ່ໄດ້ວັນພັກ.

**ແຜນຫຼັກ.** `<BaselineProject>` ໃນໄຟລ໌ ກາຍເປັນແຜນຫຼັກຂອງໂຄງການຂອງມັນ. ແຜນຫຼັກທີ່ P6 ໝາຍວ່າໃຊ້ຢູ່ ກໍຈະໃຊ້ຢູ່ໃນແອັບເຊັ່ນກັນ.

**ອັດຕາຂອງການມອບໝາຍ.** ຖ້າຍັງມີວຽກເຫຼືອ ອັດຕາທີ່ເຫຼືອ (`RemainingUnitsPerTime`) ກາຍເປັນ *ຫົວໜ່ວຍ/ມື້*. ຖ້າບໍ່ດັ່ງນັ້ນ ມັນເປັນອັດຕາຕາມແຜນ (`PlannedUnitsPerTime`). ສຳລັບວັດສະດຸ ອັດຕາຕາມແຜນຍັງຄົງເດີມ. ແອັບບໍ່ຄິດໄລ່ຄືນໃໝ່ຫຍັງເລີຍ ເມື່ອເປີດໄຟລ໌. ເມື່ອສົ່ງອອກເປັນ P6 XML ມັນຂຽນອັດຕາຕາມແຜນເປັນ `PlannedUnitsPerTime`. ມັນຂຽນອັດຕາທີ່ເຫຼືອເປັນ `RemainingUnitsPerTime` ພຽງແຕ່ເມື່ອການມອບໝາຍມີອັດຕາຕາມແຜນແຍກຕ່າງຫາກ.

**ບໍ່ມີໜ້າວຽກທີ່ອ່ານໄດ້.** ຖ້າແອັບບໍ່ພົບໜ້າວຽກທີ່ມັນອ່ານໄດ້, ມັນຈະບໍ່ເປີດແຖບ. ມັນບອກເລື່ອງນີ້, ພ້ອມເຫດຜົນເມື່ອຮູ້. ຕົວຢ່າງ: ໜ້າວຽກທີ່ບໍ່ມີ `ObjectId`, ຫຼື ຊື່ຖັນ XER ໃນໄຟລ໌ XML. ຈາກນັ້ນ ໃຫ້ສົ່ງອອກໂຄງການຈາກ P6 ໃໝ່ເປັນ P6 XML, ຫຼື ເປີດມັນເປັນ `.xer`.

**ບັນທຶກ** — ບໍ່ໄດ້.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *Primavera P6 XML* (*ສຳລັບ Oracle Primavera P6.*). ຊື່ເລີ່ມຕົ້ນ: ຊື່ໂຄງການ ພ້ອມ `.xml`, ໂດຍມີ ID ໂຄງການຢູ່ໃນວົງເລັບ ຖ້າໂຄງການມີ ID. ການສົ່ງອອກ MS Project XML ກໍໄດ້ຊື່ດຽວກັນ: ທ່ານຕ້ອງຕັ້ງຊື່ໃຫ້ແຕກຕ່າງກັນດ້ວຍຕົນເອງ.

**ຊື່ໂຄງການ ແລະ ID ໂຄງການ.** ແອັບເກັບ ID ໂຄງການຈາກ P6 ແຍກຈາກຊື່ໂຄງການ, ຄືກັບໃນ `.xer`. *ການຕັ້ງຄ່າໂຄງການ* ສະແດງພຽງແຕ່ຊື່, ຕົວຢ່າງ *Bid for Facility Extension*. ແຖບສະແດງ *Bid for Facility Extension (OZB-05)*. ຖ້າທ່ານປ່ຽນຊື່ໂຄງການເປັນ *Hall extension*, ແຖບຈະຊື່ *Hall extension (OZB-05)*. ການສົ່ງອອກເປັນ P6 XML ຂຽນ *OZB-05* ກັບຄືນເປັນ ID ໂຄງການ ແລະ *Hall extension* ເປັນຊື່. ດ້ວຍວິທີນັ້ນ P6 ຈຶ່ງຮູ້ຈັກໂຄງການ. ໂຄງການຈາກ `.xer` ກໍນຳ ID ໂຄງການໄປນຳເຊັ່ນກັນ. ID ໂຄງການຢູ່ຄົງເດີມ ເມື່ອທ່ານບັນທຶກໂຄງການເປັນ IFC. ວົງເລັບທີ່ຢູ່ໃນຊື່ເອງ ເຊັ່ນ *New build (phase 2)* ຍັງຄົງຢູ່ໃນຊື່. ໂຄງການທີ່ບໍ່ມີ ID ໂຄງການ ຈະໄດ້ ID ທີ່ບໍ່ຊ້ຳຂອງມັນເອງຈາກແອັບເວລາສົ່ງອອກ, ເລີ່ມດ້ວຍ *OPS:*.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໂຄງສ້າງ WBS ແລະ ໜ້າວຽກທີ່ມີໄລຍະເວລາ, ວັນທີ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ເງື່ອນໄຂ (ລວມເງື່ອນໄຂທີສອງ ເປັນເງື່ອນໄຂອ່ອນ); ປະຕິທິນ; ຊັບພະຍາກອນ ແລະ ການມອບໝາຍ; ວັນທີສະຖານະ (ເປັນ `DataDate`); ໝວດວຽກກຳນົດເອງ ໃນຊ່ອງຂອງມັນເອງ `OPS Custom Task Type` ທີ່ແອັບອ່ານກັບຄືນ ແລະ ທີ່ P6 ອາດບໍ່ສົນໃຈ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ແຜນຫຼັກ ແລະ ກຳນົດສົ່ງ; ລະຫັດກິດຈະກຳ, ຊ່ອງກຳນົດເອງ, ໝາຍເຫດ ແລະ ສາຍສຳພັນພາຍນອກ; ຕົວເລືອກການຄິດໄລ່; ຊື່ວັນພັກ. P6 ບໍ່ມີຊື່ສຳລັບແຕ່ລະວັນພັກ: ຫຼັງເປີດຄືນ ວັນພັກຈະຊື່ *Holiday* ແລະ ວັນເຮັດວຽກພິເສດຊື່ *Working exception*. ວັນພັກທີ່ຕິດກັນຈະກັບມາເປັນຊ່ວງດຽວ. ແອັບຕັດຊື່ ຫຼື ລະຫັດທີ່ຍາວກວ່າທີ່ P6 ອະນຸຍາດ: ຊື່ໜ້າວຽກເປັນ 120 ຕົວອັກສອນ, ID ໜ້າວຽກ ຫຼື ລະຫັດ WBS ເປັນ 40, ຊື່ WBS ຫຼື ໂຄງການເປັນ 100. ແອັບບອກວ່າຕັດຊື່ ແລະ ລະຫັດໄປຈັກອັນ. P6 ບໍ່ມີ ຄ່າ Lag ເປັນເປີເຊັນ: ແອັບປ່ຽນມັນເປັນຈຳນວນມື້ຄົງທີ່. ຄ່າ Lag ເປັນມື້ຕາມປະຕິທິນ ກາຍເປັນຄ່າ Lag ເປັນເວລາເຮັດວຽກ: 3 ມື້ຕາມປະຕິທິນ ກາຍເປັນ 3 ມື້ເຮັດວຽກ. ແຮມມັອກກາຍເປັນໜ້າວຽກທຳມະດາ, ໜ້າວຽກທີ່ກຳນົດເວລາດ້ວຍຕົນເອງ ກາຍເປັນໜ້າວຽກທຳມະດາທີ່ມີວັນທີທີ່ຄິດໄລ່ແລ້ວ, ແລະ ຄວາມຊັກຊ້າຈາກການປັບສົມດຸນທີ່ໜ້ອຍກວ່າໜຶ່ງມື້ ຖືກຕັດອອກ.

## ໄຟລ໌ Primavera (`.xer`)

**ເປີດ** — ໄດ້. ໂປຣໄຟລ໌ການຄິດໄລ່: *Primavera P6*. ແອັບອ່ານໄຟລ໌ເທົ່ານັ້ນ: ມັນບໍ່ຂຽນ `.xer` ແລະ ບໍ່ປ່ຽນໄຟລ໌ຂອງທ່ານເລີຍ. ມັນເປີດໜຶ່ງແຖບຕໍ່ໂຄງການທີ່ມີໜ້າວຽກ. ໄຟລ໌ທີ່ບໍ່ມີໜ້າວຽກ ຫຼື ມີຕາຕະລາງເສຍຫາຍ ແອັບຈະປະຕິເສດດ້ວຍຂໍ້ຄວາມ.

**ບັນທຶກ** — ບໍ່ໄດ້, ແລະ ບໍ່ມີເປົ້າໝາຍການບັນທຶກ: *ບັນທຶກ* ຂຽນໄຟລ໌ IFC ໃໝ່, ໂດຍມີ `.xer` ຕົ້ນສະບັບຢູ່ຂ້າງໃນ.

**ສົ່ງອອກ** — ບໍ່ໄດ້. ຖ້າທ່ານສົ່ງອອກໂຄງການຈາກ `.xer` ເປັນ CSV, MS Project XML ຫຼື P6 XML, ແອັບແຈ້ງວ່າຂໍ້ມູນຕົ້ນສະບັບ XER ສູນຫາຍ, ເຖິງແມ່ນທ່ານຈະບັນທຶກໂຄງການເປັນ IFC ໃນລະຫວ່າງນັ້ນແລ້ວກໍຕາມ. ເປັນ IFC ບໍ່ມີຫຍັງສູນຫາຍ.

**ສິ່ງທີ່ຕິດໄປນຳ** — ໂຄງສ້າງ WBS ແລະ ໜ້າວຽກທີ່ມີໄລຍະເວລາ, ວັນທີ, ເງື່ອນໄຂ ແລະ ຄວາມຄືບໜ້າ; ສາຍສຳພັນພ້ອມຄ່າ Lag; ປະຕິທິນ; ຊັບພະຍາກອນພ້ອມການມອບໝາຍ; ລະຫັດກິດຈະກຳ; ຊ່ອງກຳນົດເອງ (UDF); ໝາຍເຫດ; ການຕັ້ງຄ່າແຜນງານຂອງ P6. ໜ້າວຽກປະເພດ *ລະດັບຄວາມພະຍາຍາມ* ກາຍເປັນແຮມມັອກ. ໂຄງການແຜນຫຼັກ ກາຍເປັນແຜນຫຼັກທີ່ໃຊ້ຢູ່ຂອງໂຄງການທີ່ອ້າງເຖິງມັນ. ສາຍສຳພັນລະຫວ່າງສອງໂຄງການ ແອັບເກັບໄວ້ເປັນຂໍ້ມູນຕົ້ນສະບັບ.

**ອັດຕາຂອງການມອບໝາຍ.** ຖ້າຍັງມີວຽກເຫຼືອ, ອັດຕາທີ່ເຫຼືອ (`remain_qty_per_hr`) ກາຍເປັນ *ຫົວໜ່ວຍ/ມື້*. ຖ້າບໍ່ດັ່ງນັ້ນ ມັນເປັນອັດຕາຕາມແຜນ (`target_qty_per_hr`). ປະລິມານວຽກຕາມແຜນ, ຕົວຈິງ ແລະ ວຽກທີ່ເຫຼືອ ຍັງຄືເດີມໃນໄຟລ໌. ສຳລັບວັດສະດຸ ອັດຕາຕາມແຜນຍັງຄືເດີມ.

**ວັນເສົາ ຫຼື ວັນອາທິດທີ່ເປັນວັນພັກ ແຕ່ບໍ່ຢູ່ໃນໄຟລ໌.** ບາງການສົ່ງອອກ P6 ຍ້າຍວັນພັກທ້າຍອາທິດ ທີ່ຢູ່ໃນຊຸດວັນພັກຫຼາຍວັນ ໄປວັນສຸກກ່ອນໜ້າ ຫຼື ວັນຈັນຖັດໄປ. ຖ້າປະຕິທິນເຮັດວຽກໃນວັນເສົາ ຫຼື ວັນອາທິດ ວັນນັ້ນຈະກາຍເປັນມື້ເຮັດວຽກຜິດພາດ. ຖ້າແອັບເຫັນຮູບແບບນັ້ນໃນຊຸດວັນພັກຢ່າງໜ້ອຍສາມວັນ ມັນຈະເຮັດໃຫ້ວັນທ້າຍອາທິດນັ້ນເປັນວັນພັກຢ່າງໃດກໍຕາມ. ໃນປະຕິທິນ ວັນນັ້ນຖືກເອີ້ນວ່າ *ຂໍ້ຍົກເວັ້ນປະຕິທິນ (ການສ້າງວັນທ້າຍອາທິດຄືນໃໝ່)* ແລະ ມັນນັບເຂົ້າໃນແຖວ *ພົບບັນຫາກ່ຽວກັບປະຕິທິນ N ຈຸດ.* ຂອງຂໍ້ຄວາມ. ໃນປະຕິທິນທີ່ບໍ່ເຮັດວຽກໃນທ້າຍອາທິດ ບໍ່ມີຫຍັງປ່ຽນ.

**ຄິດໄລ່ float ຮອດວັນສິ້ນສຸດໂຄງການ ໂດຍບໍ່ມີວັນສິ້ນສຸດ.** ຖ້າຕົວເລືອກ P6 ເປີດຢູ່ເພື່ອຄິດໄລ່ float ຮອດວັນສິ້ນສຸດໂຄງການ ແຕ່ໄຟລ໌ບໍ່ມີວັນສິ້ນສຸດໂຄງການ ແລະ ບໍ່ມີວັນສິ້ນສຸດຕາມແຜນຂອງໜ້າວຽກໃດເລີຍ, ແອັບຈະປິດຕົວເລືອກ *ຄິດໄລ່ float ຮອດວັນສິ້ນສຸດໂຄງການ*. ມັນຈະຄິດໄລ່ວັນທີ late ຍ້ອນຄືນຈາກ ສິ້ນສຸດໄວສຸດທີ່ຫຼ້າສຸດ. ນັ້ນນັບເຂົ້າໃນແຖວ *ການຕັ້ງຄ່າຕາຕະລາງ P6 ໃຊ້ຄ່າສຳຮອງທີ່ປອດໄພ N ລາຍການ.*

**ໜ້າວຽກທີ່ສຳເລັດໃນວັນທີສະຖານະ.** ບາງໄຟລ໌ບໍ່ບັນທຶກວັນທີຕົວຈິງຂອງໜ້າວຽກທີ່ສຳເລັດ, ແຕ່ບັນທຶກຊ່ວງໃນວັນທີສະຖານະ. ໃນມຸມມອງ *ວັນທີຕາມທີ່ບັນທຶກ* ໜ້າວຽກແບບນັ້ນເປັນແຖບໜ້າວຽກທີ່ແຄບ ໃນວັນທີສະຖານະ. ຖ້າການຄິດໄລ່ຄືນໃໝ່ວາງມັນໄວ້ບ່ອນອື່ນ ມັນນັບເຂົ້າໃນຈຳນວນໜ້າວຽກທີ່ຊ່ວງນັ້ນໃຫ້. ຂໍ້ກຳນົດ *ໜ້າວຽກທີ່ສຳເລັດແລ້ວໃນຊ່ວງ data-date* ຄິດໄລ່ຊ່ວງແບບນັ້ນ, ແລະ ມີແຕ່ດ້ວຍຂໍ້ກຳນົດນັ້ນເທົ່ານັ້ນ ທີ່ໜ້າວຽກທີ່ສຳເລັດຈະໄດ້ float ຈິງ ຜ່ານຕົວເລືອກການຄິດໄລ່ *ໜ້າວຽກທີ່ສຳເລັດ: late dates ເລີ່ມຈາກ data date*. ຂໍ້ກຳນົດນີ້ເປັນການປະມານ: ແອັບເຫັນພຶດຕິກຳນີ້ພຽງໃນຜົນລັບ P3 ເທົ່ານັ້ນ, ແລະ Primavera ບໍ່ຢືນຢັນເລື່ອງນີ້ຢູ່ບ່ອນໃດເລີຍ. ນັ້ນແມ່ນເຫດຜົນທີ່ມັນປິດຢູ່ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ, ລວມທັງພາຍໃຕ້ *Primavera P6*. ທ່ານເປີດມັນໃນສ່ວນ *ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ*; ຈາກນັ້ນໂຄງການຈະໄດ້ໂປຣໄຟລ໌ກຳນົດເອງ. ເບິ່ງ [ຕົວເລືອກການຄິດໄລ່ ແລະ ຂໍ້ກຳນົດ](docs://ref-rekenopties-en-conventies).

**ຕົວເລກທີ່ມີຈໍ້າເປັນຕົວແຍກທົດສະນິຍົມ.** P6 ບັນທຶກຕົວແຍກທົດສະນິຍົມ ແລະ ຕົວແຍກຫຼັກພັນ ໃນຕາຕະລາງ `CURRTYPE`. ແອັບອ່ານຕົວອັກສອນເຫຼົ່ານັ້ນ ກ່ອນມັນແປງໄລຍະເວລາ, ປະລິມານວຽກ ແລະ float. ຖ້າຂໍ້ມູນນັ້ນຫາຍໄປ ແອັບໃຊ້ຈຸດເປັນຕົວແຍກທົດສະນິຍົມ. ຖ້າໄຟລ໌ຍັງມີຕົວເລກທີ່ໃຊ້ຈໍ້າເປັນທົດສະນິຍົມ ແອັບຈະບໍ່ເປີດຫຍັງເລີຍ. ດ້ວຍວິທີນີ້ ແຜນງານທີ່ມີຕົວເລກອ່ານຜິດ ຈະບໍ່ເປີດເລີຍ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ໂຄງການທີ່ບໍ່ມີໜ້າວຽກ, ແລະ ສາຍສຳພັນລະຫວ່າງສອງໂຄງການ ເປັນສາຍສຳພັນຈິງໃນແຜນງານຂອງທ່ານ. ເບິ່ງ [ການເປີດໄຟລ໌ Primavera P6 (.xer)](docs://howto-xer-openen).

## CSV

**ເປີດ** — ໄດ້. ແອັບອ່ານ `;` ແລະ `,` ເປັນຕົວແຍກ. ມັນຈຳຫົວຖັນເປັນພາສາອັງກິດ ແລະ ພາສາດັດ (ຕົວຢ່າງ `Name` ຫຼື `Naam`, `Duration` ຫຼື `Duur`, `Predecessors` ຫຼື `Voorgangers`). ວັນທີອາດເປັນ *ປປປປ-ດດ-ວວ*, *ວວ-ດດ-ປປປປ* ຫຼື *ວວ/ດດ/ປປປປ*. ທ່ານຂຽນໜ້າວຽກກ່ອນໜ້າເປັນລະຫັດ WBS, ປະເພດສາຍສຳພັນ ແລະ ຄ່າ Lag, ຕົວຢ່າງ `1.2FS+2d`. ໂປຣໄຟລ໌ການຄິດໄລ່: *Open Planner Studio*. ໂຄງການຖືກເອີ້ນວ່າ *CSV Import*. ຖັນ `Task Type` ເກັບໝວດວຽກ, ບໍ່ແມ່ນປະເພດໜ້າວຽກ; ແອັບອ່ານຫົວຖັນ `Werksoort` ແລະ `Work category` ນຳ. ຄ່າ `Task Type` ທີ່ບໍ່ແມ່ນລະຫັດຄົງທີ່ໃດໆ (ເຊັ່ນ `CONSTRUCTION` ຫຼື `INSTALLATION` ທີ່ແອັບຂຽນເອງ) ກາຍເປັນໝວດວຽກກຳນົດເອງ ພາຍໃຕ້ *ຈາກໂຄງການນີ້*, ບໍ່ແມ່ນໃນ *ໝວດວຽກຂອງຂ້ອຍ*; ດ້ວຍ `OPS Custom Task Type ID` id ຂອງໝວດວຽກກຳນົດເອງຖືກເກັບໄວ້.

**ບັນທຶກ** — ບໍ່ໄດ້.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *CSV (;)* (*ການສົ່ງອອກຕາຕະລາງແບບທົ່ວໄປ. ລວມທຸກວຽກພ້ອມວັນທີ ແລະ ໄລຍະເວລາ.*), ໃນກາດ *CSV (ຂັ້ນດ້ວຍຈໍ້າຈຸດ ;)*. ໄຟລ໌ໃຊ້ຈໍ້າຈຸດເປັນຕົວແຍກ, ເປັນ UTF-8 ມີ BOM ແລະ ມີຫົວຖັນເປັນພາສາອັງກິດ.

**ສິ່ງທີ່ຕິດໄປນຳ** — ສຳລັບແຕ່ລະໜ້າວຽກ ມີຖັນເຫຼົ່ານີ້: `OPS Task ID`, `WBS`, `Outline Level`, `Name`, `Duration (days)`, `Start`, `Finish`, `Predecessors`, `Task Type`, `OPS Custom Task Type ID`, `Status`, `Completion (%)`, `Actual Start`, `Actual Finish`, `Critical`, `Total Float` ແລະ `Description`. ຖັນ `Task Type` ເກັບໝວດວຽກ. ເປີເຊັນສຳເລັດເປັນຈຳນວນເຕັມ. ຄ່າ Lag ເປັນຊົ່ວໂມງ ຈະໄດ້ເຄື່ອງໝາຍຊົ່ວໂມງຂອງພາສາແອັບ: `1.2FS+2h` ໃນພາສາອັງກິດ, `1.2FS+2u` ໃນພາສາດັດ. ການເປີດອ່ານທັງສອງແບບ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ຊັບພະຍາກອນ, ການມອບໝາຍ, ປະຕິທິນ, ເງື່ອນໄຂ, ກຳນົດສົ່ງ, ແຜນຫຼັກ ແລະ ວັນທີສະຖານະ. ຖ້າວັນທີຢູ່ໃນມຸມມອງ *ວັນທີຕາມທີ່ບັນທຶກ*, ການສົ່ງອອກຈະເຮັດໃຫ້ `Critical` ແລະ `Total Float` ວ່າງເປົ່າ ສຳລັບໜ້າວຽກທີ່ໄຟລ໌ຕົ້ນສະບັບບໍ່ໄດ້ບັນທຶກຂໍ້ມູນນັ້ນ.

## ໃບຄວາມຄືບໜ້າ (Excel ແລະ CSV)

**ເປີດ** — ໄດ້, ດ້ວຍ *ໄຟລ໌ › ນຳເຂົ້າ* (*ອັບເດດຄວາມຄືບໜ້າຈາກສະເປຣດຊີດ*) ຫຼື ດ້ວຍປຸ່ມທີ່ຊື່ດຽວກັນ ໃນກຸ່ມ *ຄວາມຄືບໜ້າ* ຂອງແຖບເຄື່ອງມື ໃນ *ການວາງແຜນ*, *ຕາຕະລາງ* ແລະ *ລາຍງານ*. ແອັບອ່ານ `.xlsx` ແລະ `.csv` ໄດ້ເຖິງ 16 MB ແລະ 50,000 ແຖວ. ນີ້ບໍ່ເປີດໂຄງການ: ມັນອັບເດດຄວາມຄືບໜ້າຂອງໂຄງການທີ່ເປີດຢູ່ຂອງທ່ານ. ເບິ່ງ [ການນຳເຂົ້າຄວາມຄືບໜ້າຈາກສະເປຣດຊີດ](docs://howto-voortgang-importeren).

**ບັນທຶກ** — ບໍ່ໄດ້.

**ສົ່ງອອກ** — ໄດ້, ເປັນ *ໃບຄວາມຄືບໜ້າ (Excel)* (*ຄວາມຄືບໜ້າ (Excel)* ໃນລາຍການ) ແລະ *ໃບຄວາມຄືບໜ້າ (CSV)* (*ຄວາມຄືບໜ້າ (CSV)*). ຊື່ເລີ່ມຕົ້ນ: *ຊື່ໂຄງການ-ຄວາມຄືບໜ້າ*. ປຸ່ມ *ສົ່ງອອກໃບຄວາມຄືບໜ້າ* ໃນກຸ່ມ *ຄວາມຄືບໜ້າ* ດຽວກັນ ສ້າງໃບ Excel ໃນການກົດຄັ້ງດຽວ. ໃບ Excel ມີຄວາມກວ້າງຖັນຄົງທີ່, ຊ່ອງທີ່ລັອກ ແລະ ການກວດວັນທີ; ໃບ CSV ມີເນື້ອຫາດຽວກັນເປັນຂໍ້ຄວາມທຳມະດາ.

**ສິ່ງທີ່ຕິດໄປນຳ** — ຖັນ `OPS Task ID`, `WBS`, `Name`, `Start`, `Finish`, `Completion (%)`, `Actual Start` ແລະ `Actual Finish`. ເມື່ອນຳເຂົ້າ ແອັບໃຊ້ `Completion (%)`, `Actual Start` ແລະ `Actual Finish`; `Start` ແລະ `Finish` ໃຊ້ພຽງເພື່ອຮັບຮູ້ຮູບແບບວັນທີ ແລະ ບໍ່ປ່ຽນແຜນງານຂອງທ່ານ. ແອັບເຊື່ອມແຖວກັບໜ້າວຽກດ້ວຍ `OPS Task ID`, ຫຼືຖ້າບໍ່ມີ ດ້ວຍລະຫັດ WBS ທີ່ບໍ່ຊ້ຳກັນ.

**ສິ່ງທີ່ບໍ່ຕິດໄປນຳ** — ທຸກຢ່າງນອກຖັນເຫຼົ່ານີ້: ໄລຍະເວລາ, ສາຍສຳພັນ, ຊັບພະຍາກອນ ແລະ ສ່ວນທີ່ເຫຼືອຂອງແຜນງານຂອງທ່ານ. ໜ້າວຽກຫຼັກ ບໍ່ໄດ້ຮັບຄວາມຄືບໜ້າຈາກໃບ.
