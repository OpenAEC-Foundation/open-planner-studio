# ໄຟລ໌ ແລະ ຮູບແບບ

ໄຟລ໌ທີ່ທ່ານບັນທຶກ ມີຫຍັງຢູ່ໃນນັ້ນແທ້? ແລະແຜນງານຂອງທ່ານຈະເປັນແນວໃດ ເມື່ອທ່ານສົ່ງອອກໄປຍັງແພັກເກັດອື່ນ? ໃນບົດຄວາມນີ້ ທ່ານຈະອ່ານວ່າແອັບຈັດການກັບໄຟລ໌ແນວໃດ: IFC ເປັນຮູບແບບຂອງຕົນເອງ, ຮູບແບບອື່ນເປັນຕົວແປ, ການສົ່ງອອກຈະປ່ອຍຫຍັງໄວ້, ແລະການບັນທຶກ, AutoSave ແລະລະບົບກູ້ຄືນຂໍ້ມູນແຕກຕ່າງກັນແນວໃດ. ຕົວຢ່າງທີ່ທ້າຍບົດ ສະແດງດ້ວຍຕົວເລກ ວ່າການສົ່ງອອກເຮັດຫຍັງ.

## ແນວຄິດ

Open Planner Studio ມີຮູບແບບໄຟລ໌ຂອງຕົນເອງ ແບບດຽວ: **IFC**, ເປັນຮູບແບບແລກປ່ຽນແບບເປີດສຳລັບຂໍ້ມູນການກໍ່ສ້າງ ຈາກ buildingSMART. ແອັບຂຽນໂຄງສ້າງ IFC ຂອງໂຄງການ, ໂດຍຄ່າເລີ່ມຕົ້ນ IFC 4.3 ADD2 (ເບິ່ງ [ການເລືອກໂຄງສ້າງ IFC](docs://howto-ifc-schema-kiezen)); ໃນລາຍການສົ່ງອອກ ມັນຖືກເອີ້ນວ່າ *IFC*. ບໍ່ມີໄຟລ໌ໂຄງການທີ່ສອງ ທີ່ເປັນກຳມະສິດ. *ບັນທຶກ* ຂຽນໂຄງການທັງໝົດຂອງທ່ານເປັນໄຟລ໌ IFC (`.ifc`) ແລະ *ເປີດ* ອ່ານໄຟລ໌ແບບນັ້ນກັບຄືນມາ. ຢາກເຫັນວ່າມີຫຍັງຢູ່ໃນໄຟລ໌ບໍ? ແຖບ *IFC* ເປັນຕົວແກ້ໄຂທີ່ສະແດງຂໍ້ຄວາມ IFC ຂອງໂຄງການ. *ສ້າງ IFC* ອັບເດດຂໍ້ຄວາມນັ້ນ. *ສຳເນົາ* ສົ່ງຂໍ້ຄວາມນັ້ນໄປຄລິບບອດ. ຖ້າທ່ານປ່ຽນຂໍ້ຄວາມ, *ນຳໃຊ້* ຈະໂຫຼດມັນເປັນໂຄງການຂອງທ່ານ. ນັ້ນແທນທີ່ໂຄງການທັງໝົດໃນແຖບນັ້ນ.

ຮູບແບບອື່ນທັງໝົດເປັນ **ຕົວແປ**: ຕົວແປລະຫວ່າງແບບຈຳລອງຂອງໂປຣແກຣມອື່ນ ແລະແບບຈຳລອງຂອງແອັບ. ແອັບອ່ານ CSV, MS Project XML, Primavera P6 XML, ໄຟລ໌ MS Project (`.mpp`) ແລະໄຟລ໌ Primavera (`.xer`). ມັນຂຽນ CSV, MS Project XML, Primavera P6 XML ແລະ ແຜ່ນຄວາມຄືບໜ້າສອງແຜ່ນ. ທ່ານບໍ່ສາມາດສົ່ງອອກເປັນ `.mpp` ຫຼື `.xer` ໄດ້.

ເປັນຫຍັງການແຍກນີ້ຈຶ່ງສຳຄັນ? ຕົວແປພາໄປໄດ້ແຕ່ສິ່ງທີ່ທັງສອງຝ່າຍຮູ້. ໄຟລ໌ IFC ຂອງແອັບເກັບທຸກຢ່າງທີ່ເປັນຂອງໂຄງການຂອງທ່ານ. ທຸກຮູບແບບອື່ນຂາດບາງສ່ວນ, ແລະສ່ວນນັ້ນຈະຫາຍໄປ.

## ແອັບຈັດການໄຟລ໌ແນວໃດ

### ການເປີດໄຟລ໌ເຮັດຫຍັງ

ແອັບເລືອກຕົວອ່ານຕາມນາມສະກຸນໄຟລ໌: `.ifc`, `.csv`, `.xml`, `.mpp` ຫຼື `.xer`. ສຳລັບໄຟລ໌ `.xml` ແອັບເບິ່ງພາຍໃນໄຟລ໌ເພື່ອເບິ່ງວ່າເປັນ MS Project XML ຫຼື Primavera P6 XML. ນາມສະກຸນທີ່ບໍ່ຮູ້ຈັກ ຖືວ່າເປັນ IFC. ຖ້າໄຟລ໌ບໍ່ແມ່ນ IFC ແອັບຈະລາຍງານ *ບໍ່ສາມາດເປີດໄຟລ໌ໄດ້* ພ້ອມເຫດຜົນ.

ທຸກໄຟລ໌ເປີດໃນແຖບຂອງຕົນເອງ. ຂໍ້ຍົກເວັ້ນແມ່ນແຖບທີ່ຍັງຫວ່າງ ແລະບໍ່ໄດ້ປ່ຽນ: ແຖບນັ້ນຮັບເອົາໄຟລ໌ນັ້ນ. ໄຟລ໌ Primavera ໜຶ່ງໄຟລ໌ ອາດສ້າງຫຼາຍແຖບ ໜຶ່ງສຳລັບແຕ່ລະໂຄງການທີ່ມີໜ້າວຽກ.

ຫຼັງເປີດ ແອັບຄິດໄລ່ຄືນໃໝ່ສະເໝີ. ຖ້າໄຟລ໌ມາຈາກແພັກເກັດອື່ນ ວັນທີອາດຕ່າງຈາກທີ່ໄຟລ໌ບອກ. ເລື່ອງນີ້ອະທິບາຍໄວ້ໃນ [ວັນທີຕາມທີ່ບັນທຶກໄວ້](docs://uitleg-datums-zoals-opgeslagen).

ມີພຽງໄຟລ໌ IFC ເທົ່ານັ້ນທີ່ກາຍເປັນ **ເປົ້າໝາຍການບັນທຶກ**: ໄຟລ໌ທີ່ *ບັນທຶກ* ຂຽນກັບໄປ. ໄຟລ໌ CSV, XML, `.mpp` ຫຼື `.xer` ບໍ່ເປັນ. ໂຄງການແບບນັ້ນບໍ່ມີໄຟລ໌ເປົ້າໝາຍຫຼັງເປີດ. *ບັນທຶກ* ຈະຖາມວ່າໄຟລ໌ IFC ໃໝ່ຄວນໄປບ່ອນໃດ. ດ້ວຍວິທີນີ້ ການກົດ Ctrl+S ຈະບໍ່ຂຽນທັບໄຟລ໌ຕົ້ນສະບັບຂອງທ່ານດ້ວຍຂໍ້ຄວາມ IFC.

### ການບັນທຶກຂຽນຫຍັງ

*ບັນທຶກ* ຂຽນໂຄງການທັງໝົດສະເໝີ. ນີ້ແມ່ນສິ່ງທີ່ລົງໄປໃນໄຟລ໌:

- ໜ້າວຽກທີ່ມີໂຄງສ້າງ, ໄລຍະເວລາ, ວັນທີ ແລະຄວາມຄືບໜ້າ;
- ສາຍສຳພັນພ້ອມຄ່າ Lag, ເງື່ອນໄຂ ແລະກຳນົດສົ່ງ;
- ປະຕິທິນ, ຊັບພະຍາກອນ ແລະການມອບໝາຍ, ລວມທັງເສັ້ນໂຄ້ງ;
- ແຜນຫຼັກ, ລະຫັດກິດຈະກຳ, ຊ່ອງກຳນົດເອງ ແລະໝາຍເຫດ;
- ສາຍສຳພັນພາຍນອກກັບໂຄງການອື່ນ;
- ການຕັ້ງຄ່າໂຄງການ, ເຊັ່ນ ວັນທີສະຖານະ, ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະຕົວເລືອກການຄິດໄລ່;
- ການເຊື່ອມໂຍງກັບຄັງຂໍ້ມູນ.

ສິ່ງທີ່ທ່ານຕັ້ງໃນໜ້າຈໍ ບໍ່ເປັນຂອງໂຄງການ ແລະບໍ່ໄປກັບໄຟລ໌. ນີ້ແມ່ນການຊູມ, ຕຳແໜ່ງເລື່ອນ, ໜ້າວຽກທີ່ເລືອກ ແລະໄລຍະທີ່ຫຍໍ້ລົງ. ການຕັ້ງຄ່າແອັບຂອງທ່ານ, ເຊັ່ນ ພາສາ ແລະຮູບແບບສີ ກໍບໍ່ຢູ່ໃນໄຟລ໌ເຊັ່ນກັນ. ແອັບເກັບສິ່ງເຫຼົ່ານັ້ນໄວ້ເອງ, ໃນແອັບ ຫຼືໃນບຣາວເຊີຂອງທ່ານ.

ການສົ່ງອອກໄປຮູບແບບອື່ນ ບໍ່ແຕະຕ້ອງໂຄງການຂອງທ່ານ. ຫຼັງການສົ່ງອອກ ໂຄງການຍັງມີເປົ້າໝາຍການບັນທຶກດຽວກັນ ແລະຍັງຖືກໝາຍ *ຍັງບໍ່ໄດ້ບັນທຶກ* ຖ້າມັນຖືກໝາຍແຕ່ກ່ອນ.

### ການສົ່ງອອກເຮັດໃຫ້ຫຍັງຫາຍໄປ

ແຕ່ລະຕົວແປພາໄປສະເພາະສິ່ງທີ່ຮູບແບບຂອງມັນຮູ້.

**MS Project XML** ພາໄປໜ້າວຽກ, ສາຍສຳພັນ, ປະຕິທິນ, ຊັບພະຍາກອນ, ການມອບໝາຍ, ເງື່ອນໄຂ, ກຳນົດສົ່ງ ແລະວັນທີສະຖານະ. ໃນບັນດາແຜນຫຼັກຂອງທ່ານ ມີພຽງແຜນທີ່ເປີດໃຊ້ຢູ່ເທົ່ານັ້ນທີ່ໄປນຳ. ລະຫັດກິດຈະກຳ, ຊ່ອງກຳນົດເອງ, ໝາຍເຫດ ແລະສາຍສຳພັນພາຍນອກ ບໍ່ໄປນຳ. ເງື່ອນໄຂທີ່ສອງຂອງໜ້າວຽກ ບໍ່ໄປນຳ. ເງື່ອນໄຂ *ຕ້ອງເລີ່ມໃນວັນທີ (MSO)* ຫຼື *ຕ້ອງສິ້ນສຸດໃນວັນທີ (MFO)* ທີ່ບໍ່ມີທາງເລືອກ *ບັງຄັບ (ປັກໝຸດແໜ້ນ)* ຈະກັບມາເປັນ *ເລີ່ມບໍ່ກ່ອນ (SNET)* ຫຼື *ສິ້ນສຸດບໍ່ກ່ອນ (FNET)*. *ກຳນົດເວລາດ້ວຍຕົນເອງ* ແລະ *ຄວາມຊັກຊ້າຈາກການປັບສົມດຸນ* ຂອງໜ້າວຽກ ບໍ່ກັບມາ. ແຮມມັອກກາຍເປັນໜ້າວຽກທຳມະດາ ທີ່ມີວັນທີທີ່ຄິດໄລ່ແລ້ວ.

**Primavera P6 XML** ພາໄປໜ້າວຽກ, ສາຍສຳພັນ, ປະຕິທິນ, ຊັບພະຍາກອນ, ການມອບໝາຍ, ເງື່ອນໄຂ ແລະວັນທີສະຖານະ. ແຜນຫຼັກ ແລະກຳນົດສົ່ງ ບໍ່ໄປນຳ, ແລະລະຫັດກິດຈະກຳ, ຊ່ອງກຳນົດເອງ, ໝາຍເຫດ ແລະສາຍສຳພັນພາຍນອກກໍບໍ່ໄປນຳເຊັ່ນກັນ. ແຮມມັອກກາຍເປັນໜ້າວຽກທຳມະດາເຊັ່ນກັນ. P6 ບໍ່ມີຄ່າ Lag ເປັນເປີເຊັນ: ແອັບປ່ຽນຄ່າ Lag ແບບນັ້ນເປັນຈຳນວນມື້ຄົງທີ່. ຄ່າ Lag ເປັນມື້ປະຕິທິນ ກາຍເປັນຄ່າ Lag ເປັນມື້ເຮັດວຽກ.

**CSV** ແມ່ນລາຍການໜ້າວຽກ. ໄຟລ໌ມີຖັນເຫຼົ່ານີ້ສຳລັບແຕ່ລະໜ້າວຽກ: ລະຫັດໜ້າວຽກ, WBS, ລະດັບ, ຊື່, ໄລຍະເວລາ, ວັນເລີ່ມ, ວັນສິ້ນສຸດ, ໜ້າວຽກກ່ອນໜ້າ, ໝວດວຽກ, ລະຫັດຂອງໝວດວຽກທີ່ກຳນົດເອງ (`OPS Custom Task Type ID`), ສະຖານະ, ເປີເຊັນສຳເລັດ, ວັນເລີ່ມຕົວຈິງ ແລະວັນສິ້ນສຸດຕົວຈິງ, ວິກິດ, ໄລຍະຜ່ອນຜັນລວມ ແລະຄຳອະທິບາຍ. ຊັບພະຍາກອນ, ການມອບໝາຍ, ປະຕິທິນ, ເງື່ອນໄຂ, ກຳນົດສົ່ງ, ແຜນຫຼັກ ແລະວັນທີສະຖານະ ບໍ່ຢູ່ໃນນັ້ນ. ຫົວຖັນເປັນພາສາອັງກິດສະເໝີ.

**ມີແຕ່ IFC ເທົ່ານັ້ນທີ່ພາໂປຣໄຟລ໌ການຄິດໄລ່ ແລະຕົວເລືອກການຄິດໄລ່ໄປນຳ.** ຖ້າທ່ານສົ່ງອອກເປັນ CSV, MS Project XML ຫຼື Primavera P6 XML ໂປຣໄຟລ໌ຈະບໍ່ຢູ່ໃນໄຟລ໌. ໃນຕົວເລືອກການຄິດໄລ່, MS Project XML ເກັບໄວ້ໄດ້ຢ່າງຫຼາຍແຕ່ເກນກຳນົດວິກິດ. ໄຟລ໌ແບບນັ້ນເປີດຄືນດ້ວຍໂປຣໄຟລ໌ *Open Planner Studio*. ຖ້າໂຄງການຂອງທ່ານຄິດໄລ່ດ້ວຍ *Primavera P6* ຫຼື *Microsoft Project*, ເຊັ່ນ ເພາະມັນມາຈາກ `.xer` ຫຼື `.mpp`, ວັນທີອາດຍ້າຍໄປເພາະເລື່ອງນັ້ນ. ໂປຣໄຟລ໌ການຄິດໄລ່ແມ່ນຫຍັງ ອະທິບາຍໄວ້ໃນ [ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະຂໍ້ກຳນົດ](docs://uitleg-rekenprofielen).

ຖ້າໂຄງການຂອງທ່ານມາຈາກໄຟລ໌ Primavera (`.xer`) ເຖິງແມ່ນທ່ານບັນທຶກເປັນ IFC ລະຫວ່າງທາງ, ຫຼັງການສົ່ງອອກເປັນ CSV, MS Project XML ຫຼື P6 XML ແອັບລາຍງານ: *ການສົ່ງອອກເປັນ CSV ຈະສູນເສຍຂໍ້ມູນຕົ້ນສະບັບຂອງ XER.* ສຳລັບ MS Project XML ແອັບບອກ *MSPDI* ແທນ *CSV*, ສຳລັບ P6 XML ມັນບອກ *P6*. ທ່ານຈະບໍ່ໄດ້ຂໍ້ຄວາມນັ້ນສຳລັບ IFC: ໄຟລ໌ IFC ພາໄຟລ໌ຕົ້ນສະບັບ Primavera ໄປນຳ. ເບິ່ງ [ການເປີດໄຟລ໌ Primavera P6 (.xer)](docs://howto-xer-openen).

ແອັບເຮັດສອງຢ່າງເພີ່ມກ່ຽວກັບການສົ່ງອອກ. ຖ້າແຜນງານບໍ່ເປັນປັດຈຸບັນ ແອັບຈະຄິດໄລ່ຄືນໃໝ່ກ່ອນ ແລ້ວຈຶ່ງສົ່ງອອກ. ແລະມັນບໍ່ສົ່ງອອກແຜນງານທີ່ມີສາຍສຳພັນວົນລູບ: ທ່ານຈະໄດ້ຂໍ້ຄວາມທີ່ມີວົງວົນນັ້ນ, ເຊັ່ນ *ມີສາຍພົວພັນວົນລູບລະຫວ່າງໜ້າວຽກ: Set up site → Demolish existing extension → Set up site*.

### ບັນທຶກ, AutoSave ແລະລະບົບກູ້ຄືນຂໍ້ມູນ

ເຫຼົ່ານີ້ແມ່ນສາມສິ່ງທີ່ແຕກຕ່າງກັນ. ພວກມັນຄ້າຍກັນ ແຕ່ຂຽນໄປບ່ອນຕ່າງກັນ.

**ບັນທຶກ** ແມ່ນສິ່ງທີ່ທ່ານເຮັດ. ແອັບຂຽນໂຄງການຂອງທ່ານໄປໃສ່ໄຟລ໌ຂອງທ່ານ ແລະເອົາເຄື່ອງໝາຍ *ຍັງບໍ່ໄດ້ບັນທຶກ* ອອກ.

**AutoSave** ປິດຢູ່ໂດຍຄ່າເລີ່ມຕົ້ນ, ແລະທ່ານເປີດມັນເອງສຳລັບແຕ່ລະໂຄງການ. ແອັບຈະຂຽນ, ໂດຍບໍ່ມີໜ້າຕ່າງ, ໄປໃສ່ໄຟລ໌ດຽວກັນທຸກຄັ້ງທີ່ມີການປ່ຽນແປງ, ຢ່າງຫຼາຍໜຶ່ງຄັ້ງທຸກສິບວິນາທີ. ມັນເຮັດວຽກພຽງເມື່ອໂຄງການມີໄຟລ໌ແລ້ວ. ເບິ່ງ [ການເປີດໃຊ້ AutoSave](docs://howto-automatisch-opslaan).

**ລະບົບກູ້ຄືນຂໍ້ມູນ** ເປີດຢູ່ສະເໝີ. ທຸກຄັ້ງທີ່ມີການປ່ຽນແປງບ່ອນໃດກໍຕາມ ແອັບເກັບສຳເນົາກູ້ຄືນຂອງທຸກໂຄງການທີ່ເປີດຢູ່, ຢ່າງຫຼາຍໜຶ່ງຄັ້ງທຸກສິບວິນາທີເຊັ່ນກັນ, ລວມທັງໂຄງການທີ່ທ່ານບໍ່ໄດ້ປ່ຽນເອງ. ສຳເນົານັ້ນບໍ່ຢູ່ໃນໄຟລ໌ໂຄງການຂອງທ່ານ: ໃນແອັບເດັສທັອບ ມັນຢູ່ໃນໂຟນເດີຂໍ້ມູນຂອງແອັບ, ໃນບຣາວເຊີ ມັນຢູ່ໃນບ່ອນເກັບຂໍ້ມູນຂອງບຣາວເຊີ. ເມື່ອເລີ່ມໃໝ່ຄັ້ງຕໍ່ໄປ ແອັບສະເໜີສຳເນົານັ້ນ. ເບິ່ງ [ການກູ້ຄືນຫຼັງລະບົບຂັດຂ້ອງ](docs://howto-herstellen-na-een-crash). ລະບົບກູ້ຄືນຂໍ້ມູນບໍ່ເຄີຍຂຽນໄປໃສ່ໄຟລ໌ໂຄງການຂອງທ່ານ.

ເພາະສຳເນົາຖືກເກັບຢ່າງຫຼາຍໜຶ່ງຄັ້ງທຸກສິບວິນາທີ, ທ່ານອາດສູນເສຍວິນາທີສຸດທ້າຍຂອງວຽກໄດ້ ໃນເວລາລະບົບຂັດຂ້ອງ.

### ເດັສທັອບ ແລະ ບຣາວເຊີ

ແອັບເດັສທັອບ ແລະເວີຊັນບຣາວເຊີ ເຮັດກັບໂຄງການຂອງທ່ານຄືກັນ ແຕ່ຂຽນໄຟລ໌ຕ່າງກັນ.

ໃນເດັສທັອບ ແອັບເຮັດວຽກກັບເສັ້ນທາງຈິງ. *ບັນທຶກ* ຂຽນກົງໄປໃສ່ໄຟລ໌ຂອງທ່ານ. ປົກກະຕິ ແອັບຂຽນໄປໃສ່ໄຟລ໌ຊົ່ວຄາວຂ້າງໆກ່ອນ (`.ops-save.tmp`) ແລ້ວຈຶ່ງແທນທີ່ໄຟລ໌ຂອງທ່ານ, ດັ່ງນັ້ນລະບົບຂັດຂ້ອງກາງການຂຽນຈະບໍ່ຕັດໄຟລ໌ເກົ່າຂອງທ່ານ. ຖ້າທ່ານປິດແອັບດ້ວຍການປ່ຽນແປງ ມັນຈະຖາມທຸກໂຄງການວ່າທ່ານຢາກບັນທຶກບໍ. ເມື່ອປິດຢ່າງສະອາດ ມັນລຶບສຳເນົາກູ້ຄືນຂອງມັນ.

ໃນບຣາວເຊີທີ່ສາມາດເກັບໄຟລ໌ໄວ້ບ່ອນໃດກໍໄດ້ (ເຊັ່ນ Chrome ແລະ Edge) ທ່ານໄດ້ໜ້າຕ່າງເປີດ ແລະບັນທຶກແບບທຳມະດາ. ຫຼັງຈາກນັ້ນ *ບັນທຶກ* ຂຽນກົງໄປໃສ່ໄຟລ໌; ສຳລັບໄຟລ໌ທີ່ທ່ານເປີດ ບຣາວເຊີຖາມຂໍອະນຸຍາດຄັ້ງດຽວ. ລາຍການ *ຫຼ້າສຸດ* ໃຊ້ໄດ້, ໂດຍມີແຕ່ຊື່ໄຟລ໌.

ໃນບຣາວເຊີທີ່ບໍ່ມີຄວາມສາມາດນັ້ນ (ເຊັ່ນ Firefox) ແອັບເປີດໄຟລ໌ຜ່ານຕົວເລືອກໄຟລ໌ ແລະບັນທຶກຜ່ານການດາວໂຫຼດ. ດ້ວຍ *ບັນທຶກ* ຂໍ້ຄວາມ *ບັນທຶກເປັນໄຟລ໌ດາວໂຫຼດ: 'name.ifc' ຢູ່ໃນໂຟນເດີດາວໂຫຼດຂອງທ່ານ. …* ອະທິບາຍເລື່ອງນີ້ຄັ້ງດຽວຕໍ່ເຊດຊັນ. ດ້ວຍ *ບັນທຶກເປັນ* ແລະການສົ່ງອອກ ທ່ານເຫັນ *ບັນທຶກເປັນໄຟລ໌ດາວໂຫຼດ: ຕອນນີ້ 'name.ifc' ຢູ່ໃນໂຟນເດີດາວໂຫຼດຂອງທ່ານແລ້ວ. ລະບົບບໍ່ອະນຸຍາດໃຫ້ແອັບຂຽນທັບໃສ່ບ່ອນທີ່ທ່ານເລືອກໂດຍກົງ*. ຖ້າບຣາວເຊີສາມາດສະແດງໜ້າຕ່າງບັນທຶກໄດ້ ແຕ່ຂຽນກັບໄປໄຟລ໌ຂອງໂຄງການບໍ່ໄດ້, *ບັນທຶກ* ຈະຖາມຫາບ່ອນໃໝ່ທຸກຄັ້ງ. ຂໍ້ຄວາມອະທິບາຍເລື່ອງນີ້ຄັ້ງດຽວຕໍ່ເຊດຊັນເຊັ່ນກັນ. *ໄຟລ໌ › ຫຼ້າສຸດ* ມີຢູ່, ແຕ່ເປີດໜ້າຫວ່າງເປົ່າ, ແລະ AutoSave ໃຊ້ບໍ່ໄດ້. ທ່ານຈະເຫັນຂໍ້ຄວາມດຽວກັນໃນທຸກສະພາບແວດລ້ອມທີ່ບໍ່ອະນຸຍາດໃຫ້ແອັບຂຽນໄປບ່ອນທີ່ທ່ານເລືອກ.

## ຕົວຢ່າງ: ການສົ່ງອອກໂຄງການຕົວຢ່າງ

ໃຊ້ຕົວຢ່າງ *Refurbishment & Extension of a Family Home* (*ໄຟລ໌ › ຕົວຢ່າງ*). ມີ 20 ໜ້າວຽກ, ໃນນັ້ນ 4 ໄລຍະ ແລະ 2 ຫຼັກໝາຍ, ແລະ 16 ສາຍສຳພັນ. ມີ 6 ຊັບພະຍາກອນ ພ້ອມ 8 ການມອບໝາຍ, 1 ແຜນຫຼັກ ແລະການເຊື່ອມໂຍງກັບ *Demo resource library*. ໜ້າວຽກ *Demolish existing extension* ມີເງື່ອນໄຂ *ເລີ່ມບໍ່ກ່ອນ (SNET)* ໃນວັນທີ 14 ພຶດສະພາ 2027, ແລະ *Handover inspection* ມີກຳນົດສົ່ງໃນວັນທີ 29 ກໍລະກົດ 2027. ແຜນງານສິ້ນສຸດໃນວັນທີ 7 ກໍລະກົດ 2027.

ນີ້ແມ່ນວິທີທີ່ໂຄງການກັບຄືນມາຈາກແຕ່ລະຮູບແບບ, ວັດຫຼັງຈາກເປີດໄຟລ໌ສົ່ງອອກອີກຄັ້ງ:

- ໄຟລ໌ IFC ໃຫ້ທຸກຢ່າງຄືນ: 20 ໜ້າວຽກ, 16 ສາຍສຳພັນ, 6 ຊັບພະຍາກອນ, 8 ການມອບໝາຍ, ແຜນຫຼັກ, ເງື່ອນໄຂ, ກຳນົດສົ່ງ ແລະການເຊື່ອມໂຍງກັບຄັງຂໍ້ມູນ. ແຜນງານສິ້ນສຸດໃນວັນທີ 7 ກໍລະກົດ 2027 ອີກຄັ້ງ.
- ໄຟລ໌ MS Project XML ກໍໃຫ້ທຸກຢ່າງຄືນເຊັ່ນກັນ, ຍົກເວັ້ນການເຊື່ອມໂຍງກັບຄັງຂໍ້ມູນ. ແຜນງານສິ້ນສຸດໃນວັນທີ 7 ກໍລະກົດ 2027.
- ໄຟລ໌ P6 XML ໃຫ້ໜ້າວຽກ, ສາຍສຳພັນ, ຊັບພະຍາກອນ, ການມອບໝາຍ ແລະເງື່ອນໄຂຄືນ. ແຜນຫຼັກ ແລະກຳນົດສົ່ງຫາຍໄປ. ແຜນງານຍັງສິ້ນສຸດໃນວັນທີ 7 ກໍລະກົດ 2027, ເພາະເງື່ອນໄຂຍັງຢູ່ໃນນັ້ນ.
- ໄຟລ໌ CSV ໃຫ້ 20 ໜ້າວຽກ ແລະ 16 ສາຍສຳພັນຄືນ. ຊັບພະຍາກອນ, ການມອບໝາຍ, ແຜນຫຼັກ, ເງື່ອນໄຂ ແລະກຳນົດສົ່ງຫາຍໄປ, ແລະໂຄງການຖືກເອີ້ນວ່າ *CSV Import*. ເມື່ອບໍ່ມີເງື່ອນໄຂ ວຽກກໍເລື່ອນໄປໜ້າ: ແຜນງານສິ້ນສຸດໃນວັນທີ 2 ກໍລະກົດ 2027, ກ່ອນໜ້າຫ້າມື້ປະຕິທິນ.

ຖ້າບໍ່ມີເງື່ອນໄຂນັ້ນ ໂຄງການຕົວຢ່າງເອງກໍສິ້ນສຸດໃນວັນທີ 2 ກໍລະກົດ 2027 ເຊັ່ນກັນ. ດັ່ງນັ້ນ ຄວາມແຕກຕ່າງມາຈາກເງື່ອນໄຂທີ່ໄຟລ໌ CSV ບໍ່ພາໄປ.

## ຜົນທີ່ຕາມມາ ແລະຄວາມເຂົ້າໃຈຜິດ

**ການສົ່ງອອກບໍ່ແມ່ນການສຳຮອງຂໍ້ມູນ.** ມີແຕ່ IFC ທີ່ເກັບທຸກຢ່າງໄວ້. ຖ້າທ່ານຢາກເກັບໂຄງການຂອງທ່ານ ໃຫ້ບັນທຶກເປັນ IFC. ສົ່ງອອກພຽງເມື່ອມີຄົນທີ່ຕ້ອງການຮູບແບບອື່ນ.

**ການເປີດໄຟລ໌ສົ່ງອອກອີກຄັ້ງ ບໍ່ໄດ້ໃຫ້ແຜນງານດຽວກັນສະເໝີໄປ.** ແອັບຄິດໄລ່ຄືນໃໝ່ທຸກຄັ້ງທີ່ເປີດ ດ້ວຍໂປຣໄຟລ໌ການຄິດໄລ່ທີ່ເປັນຂອງຮູບແບບນັ້ນ. ຖ້າເຫດຜົນຂອງແຜນງານຂາດໄປ ເຊັ່ນເງື່ອນໄຂໃນຕົວຢ່າງ CSV, ຫຼືໂປຣໄຟລ໌ການຄິດໄລ່ຄິດຕ່າງກັນ, ຜົນຈະປ່ຽນ.

**ການສົ່ງອອກກໍຢູ່ໃນ *ຫຼ້າສຸດ* ເຊັ່ນກັນ.** ໃນເດັສທັອບ ແລະບຣາວເຊີທີ່ມີການເຂົ້າເຖິງໄຟລ໌, ການສົ່ງອອກຢູ່ໃນ *ຫຼ້າສຸດ* ເໝືອນໂຄງການທີ່ບັນທຶກ (ແຜ່ນຄວາມຄືບໜ້າບໍ່ຢູ່ນັ້ນ). ຖ້າທ່ານເປີດມັນຈາກບ່ອນນັ້ນ ມັນຈະເປີດເປັນການນຳເຂົ້າຂອງຮູບແບບນັ້ນ.

**ການບັນທຶກບໍ່ແມ່ນຄືກັນກັບລະບົບກູ້ຄືນຂໍ້ມູນ.** ລະບົບກູ້ຄືນຂໍ້ມູນຊ່ວຍຫຼັງລະບົບຂັດຂ້ອງ ແຕ່ບໍ່ແທນການບັນທຶກ. ສະນັ້ນ ໃຫ້ບັນທຶກກ່ອນທ່ານປິດແຖບ ຫຼືແອັບ.
