# ຕົວເລືອກການຄິດໄລ່ ແລະ ຂໍ້ກຳນົດ

ທຸກທາງເລືອກທີ່ກຳນົດວິທີທີ່ແອັບຄິດໄລ່ແຜນງານ ທ່ານພົບໄດ້ໃນສ່ວນ *ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ*: ໂປຣໄຟລ໌, ຂໍ້ກຳນົດ 27 ຂໍ້ຕໍ່ໂປຣໄຟລ໌ ແລະ ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການ. ເຫດໃດ P6 ແລະ MS Project ຈຶ່ງຄິດໄລ່ຕ່າງກັນ ຢູ່ໃນ [ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຂໍ້ກຳນົດ](docs://uitleg-rekenprofielen). ສິ່ງນັ້ນໝາຍເຖິງວັນທີຂອງທ່ານແນວໃດ ຢູ່ໃນ [ວັນທີຕາມທີ່ບັນທຶກ](docs://uitleg-datums-zoals-opgeslagen).

## ບ່ອນຊອກຫາ ແລະ ວິທີການເຮັດວຽກ

ເລືອກ *ການຕັ້ງຄ່າ › ໂຄງການ › ການຕັ້ງຄ່າໂຄງການ* ຫຼື *ໄຟລ໌ › ການຕັ້ງຄ່າໂຄງການ*. ດ້ານລຸ່ມແມ່ນສ່ວນ *ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ*. ໃນໜ້າຕ່າງ *ໂຄງການໃໝ່* ມີພຽງກ່ອງເລືອກ *ໂປຣໄຟລ໌ການຄິດໄລ່*: ເມື່ອທ່ານເລືອກ ແອັບຈະນຳໃຊ້ຕົວເລືອກຄ່າເລີ່ມຕົ້ນຂອງໂປຣໄຟລ໌ນັ້ນທັນທີ.

**ຕໍ່ໂຄງການ, ບໍ່ແມ່ນຕໍ່ແອັບ.** ໂປຣໄຟລ໌ ແລະ ຕົວເລືອກເປັນຂອງໄຟລ໌ໂຄງການ ແລະ ຖືກບັນທຶກໄປນຳເມື່ອ *ບັນທຶກ* (IFC). ດັ່ງນັ້ນ ສອງຄົນທີ່ເປີດໄຟລ໌ດຽວກັນຈະຄິດໄລ່ແບບດຽວກັນ. CSV ແລະ P6 XML ບໍ່ເກັບຂໍ້ມູນນີ້. ໃນບັນດາຕົວເລືອກການຄິດໄລ່ MS Project XML ເກັບໄວ້ໄດ້ຢ່າງຫຼາຍພຽງເກນກຳນົດວິກິດເທົ່ານັ້ນ. ເບິ່ງ [ຮູບແບບການນຳເຂົ້າ ແລະ ສົ່ງອອກ](docs://ref-import-exportformaten). ແມ່ແບບຂອງທ່ານເປັນຂອງທັງແອັບ: ແອັບເກັບໄວ້ໃນອຸປະກອນນີ້.

**ເມື່ອນຳໃຊ້ເທົ່ານັ້ນ.** ສິ່ງທີ່ທ່ານປ່ຽນໃນສ່ວນນີ້ເປັນຮ່າງຈົນກວ່າທ່ານກົດ *ນຳໃຊ້*. ຈາກນັ້ນແອັບຈະຄິດໄລ່ຄືນໃໝ່ແຜນງານ ເຖິງແມ່ນ *ຄິດໄລ່ອັດຕະໂນມັດ* ປິດຢູ່. ຖ້າໜ້າວຽກຖືກຍ້າຍ ມັນຈະບອກຈຳນວນ (*ຫຼັງຈາກນຳໃຊ້, ມີ 3 ໜ້າວຽກຖືກຍ້າຍ.*). ຖ້າບໍ່ມີໜ້າວຽກຖືກຍ້າຍ ຈະບໍ່ມີຂໍ້ຄວາມ. ທ່ານສາມາດຍົກເລີກໄດ້ໃນຂັ້ນຕອນດຽວດ້ວຍ *ຍົກເລີກຄຳສັ່ງ*. ການນຳໃຊ້ຍັງສະຫຼັບໄປທີ່ມຸມມອງ *ວັນທີຕາມທີ່ບັນທຶກ*. ການປ່ຽນແປງທີ່ບໍ່ປ່ຽນຫຍັງ ກໍບໍ່ເຮັດຫຍັງ. ໃນ *ໄຟລ໌ › ການຕັ້ງຄ່າໂຄງການ* ທ່ານຖິ້ມຮ່າງດ້ວຍ *ຍົກເລີກການປ່ຽນແປງ*.

## ໂປຣໄຟລ໌ການຄິດໄລ່

**ໂປຣໄຟລ໌ການຄິດໄລ່** — ພື້ນຖານທີ່ແອັບໃຊ້ຄິດໄລ່. ເລືອກໄດ້ຈາກ *Primavera P6*, *Microsoft Project* ແລະ *Open Planner Studio*, ພ້ອມແມ່ແບບຂອງທ່ານ ແລະ ໂປຣໄຟລ໌ກຳນົດເອງຂອງໂຄງການນີ້. ຄ່າເລີ່ມຕົ້ນ: *Open Planner Studio* ສຳລັບໂຄງການໃໝ່ ແລະ ສຳລັບໂຄງການທີ່ບໍ່ມີໂປຣໄຟລ໌. ຜົນ: ໂປຣໄຟລ໌ເປີດ ຫຼື ປິດແຕ່ລະຂໍ້ກຳນົດທັງ 27 ຂໍ້ຂ້າງລຸ່ມ. ໄຟລ໌ທີ່ທ່ານເປີດຈະໄດ້ໂປຣໄຟລ໌ຕາມຮູບແບບຂອງມັນ: `.xer` ຄິດໄລ່ເປັນ *Primavera P6*, `.mpp` ເປັນ *Microsoft Project*, ແລະ CSV, MS Project XML ແລະ P6 XML ເປັນ *Open Planner Studio*. ໄຟລ໌ IFC ຮັກສາໂປຣໄຟລ໌ທີ່ເກັບໄວ້ໃນມັນ. ໂປຣໄຟລ໌ທີ່ມີມາໃນຕົວ ເຊິ່ງມີການແຕກຕ່າງຈາກໄຟລ໌ເກົ່າ ເອີ້ນວ່າ *Primavera P6 (ແກ້ໄຂແລ້ວ)*, ໂດຍມີຊື່ຂອງພື້ນຖານ. ແຖວນັ້ນຍັງແຍກຕ່າງຫາກໃນລາຍການ ໃນຂະນະທີ່ໂຄງການຄິດໄລ່ແບບນັ້ນ. ແຖວທຳມະດາ *Primavera P6* ແມ່ນພື້ນຖານເປົ່າ ບໍ່ມີການແຕກຕ່າງເຫຼົ່ານັ້ນ. ຖ້າທ່ານເລືອກມັນ ແອັບຈະສະແດງຂໍ້ຄວາມບອກໄວ້. ຖ້າທ່ານເລືອກໂປຣໄຟລ໌ທີ່ມີມາໃນຕົວອື່ນ ເຊັ່ນ *Microsoft Project* ການແຕກຕ່າງເຫຼົ່ານັ້ນຍັງຄົງເດີມ. ການກັບໄປ *Primavera P6* ຈະໃຫ້ມັນຄືນມາອີກ, ແມ້ຫຼັງຈາກບັນທຶກ ແລະ ເປີດອີກຄັ້ງ. ຖ້າທ່ານເລືອກໂປຣໄຟລ໌ອື່ນໃນ *ການຕັ້ງຄ່າໂຄງການ* ຕົວເລືອກການຄິດໄລ່ຍັງຄົງເດີມ. ຖ້າຄ່າເຫຼົ່ານັ້ນແຕກຕ່າງຈາກຄ່າເລີ່ມຕົ້ນຂອງໂປຣໄຟລ໌ໃໝ່, ສ່ວນສີສົ້ມຢູ່ເໜືອຕົວເລືອກການຄິດໄລ່ຈະບອກໄວ້ (ເບິ່ງ *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*). ບ່ອນ: ສ່ວນ *ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ*, ກ່ອງເລືອກ *ໂປຣໄຟລ໌ການຄິດໄລ່*.

**ໂປຣໄຟລ໌ໃໝ່** — ສ້າງໂປຣໄຟລ໌ກຳນົດເອງຈາກໂປຣໄຟລ໌ທີ່ເລືອກ. ຜົນ: ແອັບຖາມຫາຊື່ ແລະ ແນະນຳ *ສຳເນົາຂອງ Primavera P6* (ຫຼື ຂອງໂປຣໄຟລ໌ທີ່ທ່ານເລີ່ມຈາກ). *ສ້າງ* ໃຫ້ໂປຣໄຟລ໌ກຳນົດເອງທີ່ມີຄ່າປັດຈຸບັນທັງໝົດ ລວມທັງການແຕກຕ່າງຂອງໄຟລ໌ເກົ່າ ແລະ ຂະຫຍາຍ *ຂໍ້ກຳນົດຂອງໂປຣໄຟລ໌ນີ້*. ຊື່ວ່າງບໍ່ໄດ້. ຊ່ອງ *ຊື່ໂປຣໄຟລ໌ກຳນົດເອງ* ປ່ຽນຊື່ໃນພາຍຫຼັງ. ຖ້າບໍ່ມີຊື່, *ນຳໃຊ້* ຈະບໍ່ຍອມຮັບ. ໂຄງການໃຊ້ໂປຣໄຟລ໌ໃໝ່ພຽງຫຼັງຈາກ *ນຳໃຊ້*. ບ່ອນ: ຂ້າງກ່ອງເລືອກ *ໂປຣໄຟລ໌ການຄິດໄລ່*. ໃນ *ໂຄງການໃໝ່* ປຸ່ມນີ້ບໍ່ສະແດງ.

**ການເປີດ ຫຼື ປິດຂໍ້ກຳນົດ** — ໃຊ້ໄດ້ພຽງໃນໂປຣໄຟລ໌ກຳນົດເອງເທົ່ານັ້ນ. ຜົນ: ໂປຣໄຟລ໌ນັ້ນຈະແຕກຕ່າງຈາກພື້ນຖານຂອງມັນ. *ກັບຄືນເປັນຄ່າຫຼັກ* ຄືນຄ່າພື້ນຖານ. ທັງ 3 ໂປຣໄຟລ໌ທີ່ມີມາໃນຕົວ ອ່ານຢ່າງດຽວ. ບ່ອນ: ສ່ວນ *ຂໍ້ກຳນົດຂອງໂປຣໄຟລ໌ນີ້*.

**ບັນທຶກເປັນແມ່ແບບ**, **ອັບເດດແມ່ແບບຈາກໂຄງການນີ້**, **ອັບເດດຈາກແມ່ແບບ** ແລະ **ລຶບແມ່ແບບ** — ຈັດການໂປຣໄຟລ໌ກຳນົດເອງຂອງທ່ານເປັນແມ່ແບບ. ຜົນ: ແມ່ແບບແມ່ນໂປຣໄຟລ໌ທີ່ບັນທຶກໄວ້ ທີ່ທ່ານເລືອກໄດ້ໃນທຸກໂຄງການ. ໂຄງການຮັກສາສຳເນົາຂອງຕົນເອງ. ຖ້າໂປຣໄຟລ໌ຂອງໂຄງການແຕກຕ່າງຈາກແມ່ແບບຂອງມັນ ແອັບຈະບອກວ່າ *ໂປຣໄຟລ໌ນີ້ແຕກຕ່າງຈາກແມ່ແບບ “…”.* ແມ່ແບບບໍ່ຢູ່ໃນໄຟລ໌ໂຄງການ. *ບັນທຶກເປັນແມ່ແບບ* ແຈ້ງວ່າບັນທຶກແມ່ແບບແລ້ວ. ຖ້າບໍ່ສຳເລັດ ເພາະມີແມ່ແບບ 100 ອັນແລ້ວ ຫຼື ບ່ອນເກັບຂໍ້ມູນຂອງແອັບເຕັມ ຈະມີຂໍ້ຄວາມຜິດພາດຕາມມາ. *ລຶບແມ່ແບບ* ຖາມກ່ອນເພື່ອຢືນຢັນ. ບ່ອນ: ຢູ່ລຸ່ມກ່ອງເລືອກ, ເມື່ອມີໂປຣໄຟລ໌ກຳນົດເອງ.

## ຂໍ້ກຳນົດຕາມໂປຣໄຟລ໌

ຂໍ້ກຳນົດ ແມ່ນກົດທີ່ໂປຣໄຟລ໌ການວາງແຜນແຕ່ລະອັນອາດແຕກຕ່າງກັນ. ທຸກຂໍ້ກຳນົດແມ່ນເປີດ ຫຼື ປິດ. ພາກ *ຂໍ້ກຳນົດຂອງໂປຣໄຟລ໌ນີ້* ຖືກຍຸບໄວ້ໂດຍຄ່າເລີ່ມຕົ້ນ. ຫົວຂໍ້ຂອງມັນສະແດງຈຳນວນຂໍ້ກຳນົດ ແລະ ຖ້າໂປຣໄຟລ໌ມີຄວາມແຕກຕ່າງ, ປ້າຍ *ປ່ຽນແລ້ວ: 2*. ເມື່ອຂະຫຍາຍອອກ ພາກນີ້ສະແດງຄ່າຂອງແຕ່ລະຂໍ້ກຳນົດ ແລະ ປ້າຍ *ປ່ຽນແລ້ວ: 2* ຢູ່ກຸ່ມທີ່ມີຄວາມແຕກຕ່າງ. ຄ່າຫຼັກ (*ຄ່າຫຼັກ: ເປີດ* ຫຼື *ຄ່າຫຼັກ: ປິດ*) ສະແດງສະເໝີສຳລັບໂປຣໄຟລ໌ກຳນົດເອງ, ແລະ ສຳລັບໂປຣໄຟລ໌ທີ່ມາພ້ອມ ສະແດງພຽງເມື່ອມີຄວາມແຕກຕ່າງ. ສຳລັບໂປຣໄຟລ໌ທີ່ມາພ້ອມ ຄ່າແມ່ນປ້າຍ *ON* ຫຼື *OFF* ເພື່ອໃຫ້ຂໍ້ມູນເທົ່ານັ້ນ. ສຳລັບໂປຣໄຟລ໌ກຳນົດເອງ ມັນເປັນຊ່ອງໝາຍຖືກ, ແລະ ຄວາມແຕກຕ່າງມີປຸ່ມ *ກັບຄືນເປັນຄ່າຫຼັກ*. ຄວາມແຕກຕ່າງໃນໂປຣໄຟລ໌ທີ່ມາພ້ອມ ມາຈາກໄຟລ໌ເກົ່າ. ແຖວນັ້ນມີພື້ນສີສົ້ມ ແລະ ກ່ອງໜຶ່ງບອກວ່າມັນຖືກໃຊ້; ເພື່ອປ່ຽນມັນ ໃຫ້ໃຊ້ *ໂປຣໄຟລ໌ໃໝ່*. ໄອຄອນ i ຫຼັງແຖວ ສະແດງຄຳອະທິບາຍ: ເມື່ອທ່ານຊີ້ໃສ່ມັນດ້ວຍເມົ້າ, ດ້ວຍປຸ່ມ Tab, ແລະ ເມື່ອຄລິກ ຫຼື ແຕະ. ປຸ່ມ Escape ປິດພຽງແຕ່ຄຳອະທິບາຍ ບໍ່ແມ່ນໜ້າຕ່າງທີ່ຢູ່ລຸ່ມ. ການຄລິກບ່ອນອື່ນກໍປິດມັນເຊັ່ນກັນ. ເມື່ອໜ້າເລື່ອນ, ຄຳອະທິບາຍຂອງໄອຄອນທີ່ຖືກເລືອກຍັງຢູ່. ຖ້າຂໍ້ກຳນົດໃຊ້ໄດ້ພຽງແຕ່ກັບການວາງແຜນລາຍຊົ່ວໂມງ ຫຼື ພຽງແຕ່ກັບໜ້າວຽກຈາກໄຟລ໌ `.xer`, ປ້າຍສີຟ້າຢູ່ຂ້າງແຖວຈະບອກແນວນັ້ນ: *ສະເພາະການວາງແຜນລາຍຊົ່ວໂມງ* ຫຼື *ສະເພາະໜ້າວຽກຈາກ .xer*. *ສະເພາະການວາງແຜນລາຍຊົ່ວໂມງ* ໃນ *ເງື່ອນໄຂ* ດ້ານລຸ່ມ ມີຄວາມໝາຍດຽວກັນກັບປ້າຍນັ້ນ: ດ້ວຍປະຕິທິນທີ່ມີຊ່ວງເວລາເຮັດວຽກ, ສຳລັບໜ້າວຽກທີ່ມີໄລຍະເວລາເປັນຊົ່ວໂມງ, ຫຼື ເມື່ອ *ປະຕິທິນໄລຍະຊັກຊ້າ (Lag)* ຕັ້ງເປັນ *24 ຊົ່ວໂມງ* (ເມື່ອນັ້ນ lag ນັບເປັນຊົ່ວໂມງ). ຄ່າເລີ່ມຕົ້ນຂອງແຕ່ລະຂໍ້ກຳນົດ ແມ່ນສິ່ງທີ່ໂປຣໄຟລ໌ທີ່ມາພ້ອມທີ່ເລືອກກຳນົດໄວ້. *Open Planner Studio* ປິດທຸກຂໍ້ກຳນົດ. ພາຍໃຕ້ແຕ່ລະຂໍ້ກຳນົດດ້ານລຸ່ມ ແມ່ນສິ່ງທີ່ *Primavera P6* ແລະ *Microsoft Project* ເຮັດ.

### ຄວາມຄືບໜ້າ ແລະ ວຽກທີ່ສຳເລັດແລ້ວ

**ຄົງວັນທີຕົວຈິງໄວ້ໃນການຄິດໄລ່ຍ້ອນກັບ (Backward Pass)** — ເມື່ອຄິດໄລ່ຍ້ອນກັບ, ໜ້າວຽກທີ່ເລີ່ມແລ້ວຈະຮັກສາວັນເລີ່ມທີ່ບັນທຶກໄວ້ເປັນເລີ່ມຕົ້ນຊ້າສຸດຂອງມັນ, ເວັ້ນແຕ່ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ* ເປີດຢູ່ (ດັ່ງທີ່ *Primavera P6* ເຮັດ). ຈາກນັ້ນເລີ່ມຕົ້ນຊ້າສຸດຂອງມັນແມ່ນຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ. ໜ້າວຽກທີ່ສຳເລັດແລ້ວຈະຮັກສາວັນທີຕົວຈິງຂອງມັນເປັນວັນ late. ດ້ວຍເຫດນີ້ ໜ້າວຽກຖັດໄປທີ່ສຳເລັດແລ້ວ ຈະບໍ່ດຶງໜ້າວຽກກ່ອນໜ້າທີ່ຍັງເປີດຢູ່ກັບໄປສູ່ອະດີດ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ເມື່ອມີ ວັນທີສະຖານະ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ** — ເລີ່ມຕົ້ນໄວສຸດ ແລະ ເລີ່ມຕົ້ນຊ້າສຸດຂອງໜ້າວຽກທີ່ພວມດຳເນີນຢູ່ ຊີ້ໄປທີ່ຈຸດທີ່ວຽກທີ່ເຫຼືອເລີ່ມ (ຊ້າກວ່າລະຫວ່າງ ວັນທີສະຖານະ ແລະ ຂອບເຂດສາຍສຳພັນ), ບໍ່ແມ່ນວັນເລີ່ມຕົວຈິງ. ເມື່ອຄິດໄລ່ຍ້ອນກັບ ໃນສາຍສຳພັນ start-to-start ນັບພຽງ ໄລຍະເວລາທີ່ເຫຼືອ ຂອງໜ້າວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່ເທົ່ານັ້ນ. ສ່ວນສຸດທ້າຍນີ້ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ. ເງື່ອນໄຂ: ເປັນພື້ນຖານຂອງຕົວເລືອກ *ຄິດໄລ່ໄລຍະຊັກຊ້າ SS ຈາກວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່ ຈາກ* ແລະ ຂອງຂໍ້ກຳນົດ *ຄ່າ SS lag ທີ່ຜ່ານໄປແລ້ວຈາກໜ້າວຽກກ່ອນໜ້າທີ່ພວມເຮັດ ຈະບໍ່ຖືກນັບ*. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ໜ້າວຽກ physical-progress ທີ່ສຳເລັດແລ້ວຈະຕັ້ງຢູ່ທີ່ data date** — ໜ້າວຽກທີ່ສຳເລັດແລ້ວຢູ່ເປັນຈຸດດຽວ ທີ່ວັນທີສະຖານະ, ຫຼື ຊ້າກວ່ານັ້ນ ຖ້າໜ້າວຽກກ່ອນໜ້າຕ້ອງການ, ແທນທີ່ຈະຢູ່ທີ່ວັນທີຕົວຈິງຂອງມັນ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ ແລະ ເມື່ອມີ ວັນທີສະຖານະ, ສຳລັບໜ້າວຽກ ແລະ ຫຼັກໝາຍທີ່ສຳເລັດແລ້ວຈາກ `.xer` ໄຟລ໌ ທີ່ມີປະເພດເປີເຊັນສຳເລັດ *ທາງກາຍະພາບ*, ທີ່ມີວັນສຳເລັດຕົວຈິງຢູ່ ຫຼື ກ່ອນວັນທີສະຖານະ, ແລະ ບໍ່ມີການຢຸດຊົ່ວຄາວ ແລະ ດຳເນີນຕໍ່ (suspend/resume). ສຳລັບປະເພດເປີເຊັນສຳເລັດອື່ນ, ລວມທັງ *ໄລຍະເວລາ* ເລີ່ມຕົ້ນຂອງ P6, ຍັງບໍ່ໄດ້ວັດ ແລະ ແອັບບໍ່ນຳໃຊ້. ຕ້ອງການ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ*. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ວັນເລີ່ມຕາມແຜນບໍ່ແມ່ນຂອບເຂດຕ່ຳສຸດສຳລັບໜ້າວຽກທີ່ເລີ່ມແລ້ວ** — ວັນເລີ່ມຕາມແຜນຈາກໄຟລ໌ ບໍ່ແມ່ນຂອບເຂດຕ່ຳສຸດຂອງໜ້າວຽກທີ່ພວມດຳເນີນຢູ່ (ມີວັນເລີ່ມຕົວຈິງ ແລະ ໜ້ອຍກວ່າ 100%): ວຽກທີ່ເຫຼືອຂອງມັນເລີ່ມທີ່ ວັນທີສະຖານະ, ຫຼັງໜ້າວຽກກ່ອນໜ້າທັນທີ, ເຖິງແມ່ນວ່າວັນເລີ່ມຕາມແຜນຈະຊ້າກວ່າ. ນີ້ເປັນອີກດ້ານກົງກັນຂ້າມຂອງ *ວັນເລີ່ມຕາມແຜນເປັນຂອບເຂດຕ່ຳສຸດເພີ່ມເຕີມ*. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ເມື່ອ *ວັນເລີ່ມຕາມແຜນເປັນຂອບເຂດຕ່ຳສຸດເພີ່ມເຕີມ* ເປີດຢູ່. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**Progress Override ບໍ່ສົນໃຈໜ້າວຽກຖັດໄປທີ່ເລີ່ມແລ້ວ ດ້ານ late ເຊັ່ນກັນ** — ສາຍສຳພັນຈາກໜ້າວຽກກ່ອນໜ້າທີ່ຍັງບໍ່ສຳເລັດ ໄປຍັງໜ້າວຽກຖັດໄປທີ່ເລີ່ມແລ້ວ ແລະ ຍັງບໍ່ສຳເລັດ ບໍ່ນັບໃນດ້ານ late ຫຼື ໃນ free float ຂອງໜ້າວຽກກ່ອນໜ້ານັ້ນ. ໜ້າວຽກຖັດໄປຈຶ່ງບໍ່ກົດດັນກັບຄືນ ແລະ ບໍ່ເປັນສາຍພົວພັນຄວບຄຸມ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ກັບຮູບແບບຄວາມຄືບໜ້າ *ຂ້າມເງື່ອນໄຂເດີມ (Progress Override)*. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

### ສາຍສຳພັນ ແລະ Lag

**ໜ້າວຽກຖັດໄປເລີ່ມທີ່ຂອບເຂດສິ້ນສຸດ** — ສາຍສຳພັນ ສຳເລັດ-ເລີ່ມຕົ້ນ ທີ່ບໍ່ມີ ຄ່າ Lag, ເຊິ່ງໜ້າວຽກຖັດໄປເລີ່ມພໍດີທີ່ສິ້ນສຸດຂອງໜ້າວຽກກ່ອນໜ້າ ທີ່ທ້າຍຊ່ວງເວລາເຮັດວຽກ, ໃຫ້ໜ້າວຽກຖັດໄປເລີ່ມທີ່ສິ້ນສຸດນັ້ນທັນທີ ແທນທີ່ຈະເລີ່ມທີ່ຕົ້ນຊ່ວງເວລາເຮັດວຽກຖັດໄປ. ເມື່ອຄິດໄລ່ຍ້ອນກັບ ໜ້າວຽກຖັດໄປພຽງແຕ່ສະແດງເລີ່ມຕົ້ນຊ້າສຸດຂອງມັນເປັນຈຸດເລີ່ມຕົ້ນຂອງຊ່ວງເວລາເຮັດວຽກ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ. ໄຟລ໌ບໍ່ໄດ້ໝາຍຫຍັງ: ແອັບຈະຈຳແນກເອງ ເມື່ອເປີດ `.xer` ໄຟລ໌. ສາຍສຳພັນທີ່ທ່ານສ້າງເອງບໍ່ຢູ່ໃນນີ້. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**Lag ເມື່ອຄິດໄລ່ຍ້ອນກັບຈາກຂອບເຂດສິ້ນສຸດ** — ເມື່ອແອັບລົບ ຄ່າ Lag ຕາມເວລາເຮັດວຽກ ຈາກຂອບເຂດສິ້ນສຸດທີ່ແນ່ນອນຂອງຊ່ວງເວລາເຮັດວຽກ ໃນຕອນຄິດໄລ່ຍ້ອນກັບ ແລະ ລົງພໍດີທີ່ຈຸດເລີ່ມຕົ້ນຂອງຊ່ວງ, ມັນຈະກາຍເປັນຂອບເຂດສິ້ນສຸດຂອງຊ່ວງກ່ອນໜ້າ. ນອກຈາກນີ້ກັບສາຍສຳພັນ ສຳເລັດ-ສຳເລັດ ທີ່ບໍ່ມີ ຄ່າ Lag, ສິ້ນສຸດຊ້າສຸດທີ່ທ້າຍຊ່ວງ ຍັງຢູ່ທີ່ຂອບເຂດນັ້ນ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ຄ່າ Lag ທີ່ຜ່ານໄປແລ້ວຂອງໜ້າວຽກກ່ອນໜ້າທີ່ສຳເລັດແລ້ວ ບໍ່ນັບ** — ຄ່າ Lag ຕາມເວລາເຮັດວຽກທີ່ເປັນບວກ ຫຼັງໜ້າວຽກກ່ອນໜ້າທີ່ສຳເລັດແລ້ວ ນັບພຽງສ່ວນທີ່ຍັງບໍ່ທັນຜ່ານໄປ ຕອນວັນທີສະຖານະ: ຄ່າ lag ລົບເວລາເຮັດວຽກລະຫວ່າງ ວັນສຳເລັດຕົວຈິງ ແລະ ວັນທີສະຖານະ, ບໍ່ຕ່ຳກວ່າ 0. ເມື່ອຄິດໄລ່ຍ້ອນກັບ ພວກມັນນັບໃນດ້ານ late. ເມື່ອຄິດໄລ່ໄປໜ້າ ນັບພຽງແຕ່ຈາກໜ້າວຽກກ່ອນໜ້າທີ່ສຳເລັດແລ້ວທີ່ມີຈຸດ ຫຼື ຊ່ວງ ວັນທີສະຖານະ (ເບິ່ງ *ໜ້າວຽກ physical-progress ທີ່ສຳເລັດແລ້ວຈະຕັ້ງຢູ່ທີ່ data date* ແລະ *ໜ້າວຽກທີ່ສຳເລັດແບບຂ້າມລຳດັບຈະລໍຖ້າໜ້າວຽກກ່ອນໜ້າ*). ໜ້າວຽກທີ່ສຳເລັດແລ້ວ ທີ່ພຽງແຕ່ຢູ່ທີ່ວັນທີຕົວຈິງຂອງມັນ ຍັງຮັກສາ lag ເຕັມ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ ແລະ ເມື່ອມີ ວັນທີສະຖານະ ແລະ ສະເພາະໜ້າວຽກຈາກ `.xer` ໄຟລ໌ເທົ່ານັ້ນ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ຄ່າ SS lag ທີ່ຜ່ານໄປແລ້ວຈາກໜ້າວຽກກ່ອນໜ້າທີ່ພວມເຮັດ ຈະບໍ່ຖືກນັບ** — ດ້ວຍສາຍສຳພັນ start-to-start ທີ່ມີ ຄ່າ Lag ຕາມເວລາເຮັດວຽກເປັນບວກ ຈາກໜ້າວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່, ນັບພຽງສ່ວນຂອງ lag ທີ່ຍັງບໍ່ທັນຜ່ານໄປ: lag ລົບເວລາເຮັດວຽກລະຫວ່າງ ວັນເລີ່ມຕົວຈິງ ແລະ ວັນທີສະຖານະ, ຢ່າງໜ້ອຍ 0. ຄິດໄລ່ໄປໜ້າ ນັບຈາກຈຸດເລີ່ມຂອງວຽກທີ່ເຫຼືອຂອງໜ້າວຽກກ່ອນໜ້າ; ເມື່ອຄິດໄລ່ຍ້ອນກັບ ເລີ່ມຕົ້ນຊ້າສຸດຂອງໜ້າວຽກກ່ອນໜ້າ ແມ່ນເລີ່ມຕົ້ນຊ້າສຸດຂອງໜ້າວຽກຖັດໄປ ລົບ lag ທີ່ເຫຼືອນັ້ນ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ. ຕ້ອງການ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ*. ຕົວເລືອກ *ຄິດໄລ່ໄລຍະຊັກຊ້າ SS ຈາກວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່ ຈາກ* ເລືອກຈຸດເລີ່ມ. **ສິ້ນສຸດໄວສຸດ ບໍ່ກ່ອນຂອບເຂດ ສຳເລັດ-ສຳເລັດ** — ດ້ວຍສາຍສຳພັນ ສຳເລັດ-ສຳເລັດ, ສິ້ນສຸດໄວສຸດຂອງໜ້າວຽກຖັດໄປ ບໍ່ເຄີຍກ່ອນສິ້ນສຸດຂອງໜ້າວຽກກ່ອນໜ້າບວກ lag. ຖ້າຂອບເຂດນັ້ນຕົກນອກເວລາເຮັດວຽກຂອງໜ້າວຽກຖັດໄປ, ສິ້ນສຸດໄວສຸດກາຍເປັນຂອບເຂດເຮັດວຽກທຳອິດ ທີ່ເວລານັ້ນ ຫຼື ຫຼັງຈາກນັ້ນ; ເລີ່ມຕົ້ນຄືເກົ່າ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ ແລະ ກັບ lag ເວລາເຮັດວຽກ; ບໍ່ໃຊ້ກັບເງື່ອນໄຂສິ້ນສຸດທີ່ແໜ້ນ ຫຼື ແຮມມັອກ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

### ຫຼັກໝາຍ ແລະ ກິດຈະກຳ LOE

**ຫຼັກໝາຍຕາມຂອບເຂດປະຕິທິນທີ່ວາງແຜນໄວ້** — ຫຼັກໝາຍທີ່ບໍ່ມີໄລຍະເວລາ ຢູ່ຕາມຂອບເຂດປະຕິທິນທີ່ໄຟລ໌ວາງແຜນໄວ້: ຫຼັກໝາຍທີ່ຢູ່ຕົ້ນມື້ ຈະຢູ່ເປັນຫຼັກໝາຍເລີ່ມຕົ້ນ, ແລະ ຫຼັກໝາຍທີ່ຢູ່ທ້າຍຊ່ວງເວລາເຮັດວຽກ ອາດລົງທີ່ສິ້ນສຸດຂອງໜ້າວຽກກ່ອນໜ້າ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ. ໜ້າວຽກທີ່ມີໄລຍະເວລາ 0 ອາດຢູ່ສອງຂອບເຂດນີ້ໄດ້ເຊັ່ນກັນ (ເລີ່ມຕົ້ນທີ່ຈຸດເລີ່ມຂອງຊ່ວງຖັດໄປ, ສິ້ນສຸດທີ່ຈຸດສິ້ນສຸດຂອງຊ່ວງກ່ອນໜ້າ), ແຕ່ພຽງແຕ່ຖ້າມາຈາກ `.xer` ໄຟລ໌ ແລະ ວັນສິ້ນສຸດຕາມແຜນຢູ່ກ່ອນວັນເລີ່ມຕາມແຜນ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**LOE ທີ່ຍັງບໍ່ເລີ່ມໃຊ້ຊ່ວງເປົ້າໝາຍ** — ກິດຈະກຳ LOE ທີ່ຍັງບໍ່ເລີ່ມ (ແຮມມັອກໃນແອັບ) ທີ່ມີຊ່ວງເປົ້າໝາຍຄົບ ຈະໃຊ້ຊ່ວງເປົ້າໝາຍນັ້ນເປັນຊ່ວງຂອງມັນ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ, ແລະ ພຽງແຕ່ຖ້າກິດຈະກຳນີ້ມາຈາກ `.xer` ໄຟລ໌ ທີ່ມີພຽງສາຍສຳພັນ start-to-start ຂາເຂົ້າ ແລະ finish-to-finish ຂາອອກ ທີ່ບໍ່ມີ lag. ຫຼັກຖານສຳລັບກົດນີ້ອ່ອນ: ມາຈາກໄຟລ໌ດຽວ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ສາຍສຳພັນ ສຳເລັດ-ສຳເລັດ ກັບຫຼັກໝາຍເລີ່ມຕົ້ນ ຜູກກັບຫຼັກໝາຍນັ້ນເອງ** — ສາຍສຳພັນ ສຳເລັດ-ສຳເລັດ ກັບຫຼັກໝາຍເລີ່ມຕົ້ນ (ໄລຍະເວລາ 0, ປະເພດ *ເລີ່ມຕົ້ນ*) ຜູກກັບສິ້ນສຸດຊ້າສຸດຂອງຫຼັກໝາຍນັ້ນເອງ, ແທນທີ່ຈະຜູກກັບຕົ້ນມື້ຂອງຫຼັກໝາຍ. ### Float ແລະ ວັນທີ late

**Free float ບໍ່ເປັນລົບເລີຍ** — ເມື່ອມີເງື່ອນໄຂ late ທີ່ບໍ່ສາມາດບັນລຸໄດ້, ໄລຍະຜ່ອນຜັນລວມ ຍັງເປັນລົບ, ແຕ່ Free float ກາຍເປັນ 0 ແທນທີ່ຈະເປັນລົບ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**Free float ຕາມປະຕິທິນຂອງໜ້າວຽກເອງ** — Free float ຂອງໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມ ນັບຕໍ່ສາຍສຳພັນແຕ່ລະເສັ້ນ ໃນປະຕິທິນຂອງໜ້າວຽກເອງ, ບໍ່ແມ່ນໃນປະຕິທິນຂອງໜ້າວຽກຖັດໄປ. ນັ້ນໃຊ້ກັບ ສຳເລັດ-ເລີ່ມຕົ້ນ, start-to-start ແລະ ສຳເລັດ-ສຳເລັດ. ສາຍສຳພັນທີ່ມີ ຄ່າ Lag (ບໍ່ແມ່ນ 0) ຕົກໃນກົດນີ້ພຽງແຕ່ຖ້າ *ປະຕິທິນໄລຍະຊັກຊ້າ (Lag)* ເປັນ *ວຽກກ່ອນໜ້າ*; ຖ້າບໍ່ດັ່ງນັ້ນ ປະຕິທິນຂອງໜ້າວຽກຖັດໄປຍັງຄົງຢູ່. ສາຍສຳພັນທີ່ບໍ່ມີ lag ຕົກໃນກົດນີ້ສະເໝີ. ໜ້າວຽກທີ່ເລີ່ມແລ້ວ ແລະ ຍັງບໍ່ສຳເລັດ ຕາມນີ້ພຽງແຕ່ກັບສາຍສຳພັນ ສຳເລັດ-ເລີ່ມຕົ້ນ ທີ່ບໍ່ມີ lag. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ສິ້ນສຸດຊ້າສຸດຕາມປະຕິທິນຂອງໜ້າວຽກເອງ** — ຖ້າໜ້າວຽກຖັດໄປບັງຄັບ ສິ້ນສຸດຊ້າສຸດ ທີ່ຕົກນອກເວລາເຮັດວຽກຂອງໜ້າວຽກ, ສິ້ນສຸດຊ້າສຸດຈະກາຍເປັນທ້າຍຂອງຊ່ວງເຮັດວຽກກ່ອນໜ້າ ໃນປະຕິທິນຂອງໜ້າວຽກເອງ. ເງື່ອນໄຂທີ່ເຂັ້ມກວ່າ ຫຼື ກຳນົດສົ່ງ ຊະນະ. ນີ້ແມ່ນດ້ານ late ຂອງ *Free float ຕາມປະຕິທິນຂອງໜ້າວຽກເອງ*. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ ແລະ ບໍ່ແມ່ນສຳລັບວັນສິ້ນສຸດໂຄງການ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ໜ້າວຽກ ALAP ຈະຢູ່ຊ້າທີ່ສຸດເທົ່າທີ່ໜ້າວຽກຖັດໄປອະນຸຍາດ** — ໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມ ທີ່ມີເງື່ອນໄຂ *ຊ້າເທົ່າທີ່ຈະຊ້າໄດ້ (ALAP)* ໄດ້ສິ້ນສຸດໄວສຸດເປັນຂອບເຂດທີ່ເຂັ້ມທີ່ສຸດ ທີ່ໜ້າວຽກຖັດໄປອະນຸຍາດດ້ວຍວັນໄວສຸດຂອງພວກມັນ, ຖືກຕ້ອງເຖິງນາທີ, ແລະ ເລີ່ມຕົ້ນໄວສຸດເປັນສິ້ນສຸດນັ້ນລົບໄລຍະເວລາ. ຊ່ວງຕາມແຜນຂອງມັນເອງບໍ່ນັບ; ຂອບຕ່ຳສຸດແມ່ນໜ້າວຽກກ່ອນໜ້າ ແລະ ວັນທີສະຖານະ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ; ໃນປະຕິທິນມື້ ຂັ້ນຕອນເປັນມື້ເຮັດວຽກທັງໝົດຍັງຄົງຢູ່. ການທີ່ໜ້າວຽກ ALAP ຈະຊ້າທີ່ສຸດ ແລະ ໜ້າວຽກຖັດໄປໄປກ່ອນ ເພື່ອໃຫ້ສາຍ ALAP ເຊື່ອມກັນ, ໃຊ້ໄດ້ໃນທຸກໂປຣໄຟລ໌ ໃນມື້ເຮັດວຽກທັງໝົດ. ຂໍ້ກຳນົດນີ້ເພີ່ມການວາງໃນລະດັບນາທີທີ່ແນ່ນອນ ຈາກວັນໄວສຸດຂອງໜ້າວຽກຖັດໄປ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

### ວັນທີ ແລະ ຊ່ວງເວລາຈາກໄຟລ໌

**ວັນເລີ່ມຕາມແຜນເປັນຂອບເຂດຕ່ຳສຸດເພີ່ມເຕີມ** — ວັນເລີ່ມຕາມແຜນຈາກໄຟລ໌ ນັບເປັນຂອບເຂດຕ່ຳສຸດເພີ່ມເຕີມຂ້າງເຄືອຂ່າຍ, ແຕ່ພຽງແຕ່ຖ້າທັງເລີ່ມ ແລະ ສິ້ນສຸດ ຊ້າກວ່າທີ່ເຄືອຂ່າຍອະນຸຍາດເກີນໜຶ່ງມື້ປະຕິທິນ. ການເລີ່ມທຳມະດາທີ່ຊ່ວງເວລາເຮັດວຽກຖັດໄປ ບໍ່ເຮັດໃຫ້ກົດນີ້ເກີດຂຶ້ນ. ເງື່ອນໄຂ: ມັນບໍ່ໃຊ້ກັບໜ້າວຽກທີ່ພວມດຳເນີນຢູ່ ຕາບໃດທີ່ *ວັນເລີ່ມຕາມແຜນບໍ່ແມ່ນຂອບເຂດຕ່ຳສຸດສຳລັບໜ້າວຽກທີ່ເລີ່ມແລ້ວ* ເປີດຢູ່; ແລະ ກໍບໍ່ໃຊ້ກັບໜ້າວຽກ ALAP ທີ່ຍັງບໍ່ເລີ່ມ ທີ່ *ໜ້າວຽກ ALAP ຈະຢູ່ຊ້າທີ່ສຸດເທົ່າທີ່ໜ້າວຽກຖັດໄປອະນຸຍາດ* ຈັດວາງຈາກໜ້າວຽກຖັດໄປ. ຂໍ້ກຳນົດນີ້ບໍ່ເບິ່ງວ່າໜ້າວຽກມາຈາກໃສ, ພຽງແຕ່ເບິ່ງວັນເລີ່ມ ແລະ ສິ້ນສຸດຕາມແຜນ. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ຄົງວັນທີຕົວຈິງໄວ້ຢ່າງຊັດເຈນ** — ວັນທີຕົວຈິງທີ່ບັນທຶກໄວ້ ພ້ອມເວລາຂອງມື້, ຍັງຊັດເຈນ ແລະ ບໍ່ຖືກຍ້າຍໄປຂອບຊ່ວງເວລາເຮັດວຽກ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ກັບໜ້າວຽກຈາກ `.xer` ໄຟລ໌. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

**ເວລາເງື່ອນໄຂທີ່ແນ່ນອນຂອງຫຼັກໝາຍ** — ເງື່ອນໄຂທີ່ມີວັນທີ ແລະ ເວລາ (SNLT, MSO, FNLT ຫຼື MFO) ໃນຫຼັກໝາຍທີ່ບໍ່ມີໄລຍະເວລາ ແມ່ນຈຸດທີ່ແນ່ນອນ, ເຖິງແມ່ນຈຸດນັ້ນຈະເປັນຈຸດເລີ່ມຂອງຊ່ວງເວລາເຮັດວຽກ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ ແລະ ດ້ານ late; ຄິດໄລ່ໄປໜ້າ ຈຸດດັ່ງກ່າວແນ່ນອນຢູ່ແລ້ວໃນທຸກໂປຣໄຟລ໌. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Primavera P6*, ປິດ ພາຍໃຕ້ *Microsoft Project* ແລະ *Open Planner Studio*.

### ຄວາມຄືບໜ້າຄືກັບ Microsoft Project

**ວຽກທີ່ເຫຼືອດຳເນີນຕໍ່ຫຼັງເວລາລ່ວງເລີຍ** — ໜ້າວຽກທີ່ພວມດຳເນີນຢູ່ ດຳເນີນຕໍ່ວຽກທີ່ເຫຼືອຂອງມັນ ທີ່ຈຸດທີ່ຊ້າທີ່ສຸດລະຫວ່າງ ວັນທີສະຖານະ, ຂອບເຂດຂອງໜ້າວຽກກ່ອນໜ້າ ແລະ ວັນເລີ່ມຕົວຈິງບວກເວລາລ່ວງເລີຍ. ພາຍໃຕ້ *Primavera P6* (Retained Logic) ພຽງສອງຢ່າງທຳອິດນັບ; ຂອບຊັ້ນທີສາມນັ້ນພຽງແຕ່ຍ້າຍວຽກທີ່ເຫຼືອໄປຊ້າກວ່າ. ເງື່ອນໄຂ: ບໍ່ໃຊ້ກັບ *ຂ້າມເງື່ອນໄຂເດີມ (Progress Override)*, ບໍ່ເມື່ອບໍ່ມີວຽກທີ່ເຫຼືອ, ແລະ ບໍ່ເມື່ອໄຟລ໌ໃຫ້ວັນດຳເນີນຕໍ່ (Resume) ສຳລັບໜ້າວຽກ (ດ້ວຍການມອບໝາຍຢ່າງຫຼາຍໜຶ່ງ). ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Microsoft Project*, ປິດ ພາຍໃຕ້ *Primavera P6* ແລະ *Open Planner Studio*.

**ຢ່າຍ້າຍໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມໄປທີ່ວັນທີສະຖານະ** — ໜ້າວຽກທີ່ບໍ່ມີຄວາມຄືບໜ້າ ບໍ່ຍ້າຍເອງໄປ ເປັນ ຫຼື ຫຼັງ ວັນທີສະຖານະ. ເມື່ອປິດ ໃຊ້ຂອບຕ່ຳສຸດທີ່ P6 ມີກັບ Retained Logic. ຄ່າເລີ່ມຕົ້ນ: ເປີດ ພາຍໃຕ້ *Microsoft Project*, ປິດ ພາຍໃຕ້ *Primavera P6* ແລະ *Open Planner Studio*.

### ສະເພາະໂປຣໄຟລ໌ກຳນົດເອງ

ຂໍ້ກຳນົດເຫຼົ່ານີ້ປິດຢູ່ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ, ລວມທັງ *Primavera P6*. ມີພຽງໂປຣໄຟລ໌ກຳນົດເອງເທົ່ານັ້ນທີ່ເປີດມັນໄດ້: ສ້າງໜຶ່ງດ້ວຍ *ໂປຣໄຟລ໌ໃໝ່*.

**ຫຼັກໝາຍສິ້ນສຸດເປັນຊ່ວງຂອບເຂດ** — ຫຼັກໝາຍສິ້ນສຸດອາດຢູ່ໃນສອງຂອບເຂດປະຕິທິນຕິດກັນ: ເລີ່ມໄວສຸດຢູ່ຈຸດເລີ່ມຂອງຊ່ວງເວລາເຮັດວຽກ ແລະ ສິ້ນສຸດໄວສຸດຢູ່ທ້າຍຊ່ວງກ່ອນໜ້າ. ດ້ານ late, ຫຼັກໝາຍສິ້ນສຸດທີ່ບໍ່ມີໜ້າວຽກຖັດໄປ ແຕ່ມີໜ້າວຽກກ່ອນໜ້າ ຈະໄດ້ວັນໄວສຸດຂອງມັນເປັນວັນ late, ແລະ ດັ່ງນັ້ນຈຶ່ງກົດດັນກັບຄືນໄປຫາສາຍຂອງມັນ, ເວັ້ນແຕ່ *ຄິດໄລ່ float ຮອດວັນສິ້ນສຸດໂຄງການ* ເປີດຢູ່. Free float ຂອງມັນຍັງເປັນພື້ນທີ່ເຖິງວັນສິ້ນສຸດໂຄງການ. ເງື່ອນໄຂ: ຊ່ວງຂອບເຂດ (ເລີ່ມໄວສຸດ ແລະ ສິ້ນສຸດໄວສຸດໃນສອງຂອບເຂດ) ໃຊ້ໄດ້ພຽງແຕ່ຖ້າໄຟລ໌ວາງແຜນຫຼັກໝາຍແບບນັ້ນ: ສິ້ນສຸດຕາມແຜນກ່ອນເລີ່ມຕາມແຜນ. ແຮງກົດດັນໃສ່ສາຍໃຊ້ກັບທຸກຫຼັກໝາຍສິ້ນສຸດທີ່ບໍ່ມີໜ້າວຽກຖັດໄປ. ເຫັນພຽງແຕ່ໃນຜົນ P3; ບໍ່ມີຜົນກັບໄຟລ໌ທີ່ P6 ຄິດໄລ່. ຄ່າເລີ່ມຕົ້ນ: ປິດ ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ.

**ໜ້າວຽກທີ່ສຳເລັດແລ້ວໃນຊ່ວງ data-date** — ໜ້າວຽກທີ່ສຳເລັດແລ້ວ ໄດ້ຊ່ວງວັນທີສະຖານະເປັນວັນໄວສຸດຂອງມັນ, ແລະ ຊ່ວງນັ້ນນັບໄປຫາວັນສິ້ນສຸດໂຄງການ ແລະ float. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ເມື່ອມີ ວັນທີສະຖານະ, ສຳລັບໜ້າວຽກທີ່ສຳເລັດແລ້ວຈາກ `.xer` ໄຟລ໌ ທີ່ມີປະເພດເປີເຊັນສຳເລັດ *ໄລຍະເວລາ* ແລະ ປະເພດໜ້າວຽກ *ຄົງທີ່ໄລຍະເວລາ ແລະ ວຽກ* (ໃນ P6: Fixed Duration & Units); ບໍ່ແມ່ນຫຼັກໝາຍ. ຕ້ອງການ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ*. ເຫັນພຽງແຕ່ໃນຜົນ P3. ຄ່າເລີ່ມຕົ້ນ: ປິດ ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ.

**ກິດຈະກຳ LOE ທີ່ສຳເລັດແລ້ວຜ່ານວັນສຳເລັດຕົວຈິງ** — ກິດຈະກຳ LOE ທີ່ສຳເລັດແລ້ວ ທີ່ມີພຽງສາຍສຳພັນ start-to-start ຂາເຂົ້າ ແລະ ບໍ່ມີໜ້າວຽກຖັດໄປ, ໄປຕາມເສັ້ນທາງຜ່ານວັນສຳເລັດຕົວຈິງຂອງມັນ ແທນເສັ້ນທາງແຮມມັອກປົກກະຕິ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ກັບໜ້າວຽກຈາກ `.xer` ໄຟລ໌; ຕ້ອງການ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ*, *ຄົງວັນທີຕົວຈິງໄວ້ໃນການຄິດໄລ່ຍ້ອນກັບ (Backward Pass)* ແລະ *ຄົງວັນທີຕົວຈິງໄວ້ຢ່າງຊັດເຈນ*. ເຫັນພຽງແຕ່ໃນຜົນ P3. ຄ່າເລີ່ມຕົ້ນ: ປິດ ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ.

**ໜ້າວຽກກ່ອນໜ້າທີ່ສຳເລັດແລ້ວ ບໍ່ຄ້າງຢູ່ຫຼັງວັນທີສະຖານະ** — ຖ້າໜ້າວຽກກ່ອນໜ້າທີ່ສຳເລັດແລ້ວ ສິ້ນສຸດຫຼັງວັນທີສະຖານະ ຕາມວັນສຳເລັດຕົວຈິງຂອງມັນ, ສາຍສຳພັນ ສຳເລັດ-ເລີ່ມຕົ້ນ ແລະ ສຳເລັດ-ສຳເລັດ ຄິດໄລ່ຈາກຂອບເຂດຂອງຊ່ວງວັນທີສະຖານະ ແທນທີ່ຈະຈາກວັນສຳເລັດຕົວຈິງນັ້ນ. ສາຍສຳພັນ start-to-start ຢູ່ກັບວັນເລີ່ມຕົວຈິງ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ ແລະ ເມື່ອມີ ວັນທີສະຖານະ. ຄ່າເລີ່ມຕົ້ນ: ປິດ ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ.

**ໜ້າວຽກທີ່ສຳເລັດແບບຂ້າມລຳດັບຈະລໍຖ້າໜ້າວຽກກ່ອນໜ້າ** — ໜ້າວຽກທີ່ສຳເລັດແລ້ວ ທີ່ໜ້າວຽກກ່ອນໜ້າຍັງບໍ່ສຳເລັດ (ຄວາມຄືບໜ້າຂ້າມລຳດັບ) ໄດ້ຊ່ວງທີ່ບໍ່ມີວຽກເຫຼືອ ບໍ່ຢູ່ທີ່ວັນທີສະຖານະ ແຕ່ຢູ່ທີ່ຊ້າກວ່າລະຫວ່າງ ວັນທີສະຖານະ ແລະ ຂອບເຂດສາຍສຳພັນປົກກະຕິຂອງໜ້າວຽກກ່ອນໜ້ານັ້ນ. ເງື່ອນໄຂ: ໃຊ້ໄດ້ພຽງແຕ່ໃນປະຕິທິນຊົ່ວໂມງ. ເຮັດວຽກຕາມເສັ້ນທາງວັນທີສະຖານະຂອງ *ໜ້າວຽກທີ່ສຳເລັດແລ້ວໃນຊ່ວງ data-date*, ສະນັ້ນກໍໃຊ້ໄດ້ພຽງແຕ່ກັບໜ້າວຽກຈາກ `.xer` ໄຟລ໌. ຂໍ້ກຳນົດນັ້ນ ແລະ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ* ຕ້ອງເປີດຢູ່ດ້ວຍ. ບໍ່ໃຊ້ກັບ *ຂ້າມເງື່ອນໄຂເດີມ (Progress Override)*. ຄ່າເລີ່ມຕົ້ນ: ປິດ ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ.

## ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້

ຕົວເລືອກເຫຼົ່ານີ້ຢູ່ໃຕ້ *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*, ຢູ່ລຸ່ມຂໍ້ກຳນົດ. ຖ້າຕົວເລືອກການຄິດໄລ່ທີ່ນຳໃຊ້ຂອງໂຄງການແຕກຕ່າງຈາກຄ່າເລີ່ມຕົ້ນຂອງໂປຣໄຟລ໌ທີ່ເລືອກ ກ່ອງສີສົ້ມຈະປາກົດຢູ່ດ້ານເທິງ. ຖ້າທ່ານປ່ຽນຄ່າໃນຊ່ອງເອງ ກ່ອງຈະລໍຖ້າຈົນກວ່າທ່ານເລືອກ *ນຳໃຊ້* ຫຼື *ຍົກເລີກການປ່ຽນແປງ*; ບໍ່ດັ່ງນັ້ນມັນຈະສະແດງຄ່າອື່ນທີ່ບໍ່ກົງກັບຊ່ອງ. ເມື່ອທ່ານເລືອກໂປຣໄຟລ໌ອື່ນ ກ່ອງຈະອັບເດດທັນທີ. ສຳລັບແຕ່ລະຄວາມແຕກຕ່າງ ມັນຈະບອກຊື່ຊ່ອງ ຄ່າປັດຈຸບັນ ແລະ ຄ່າເລີ່ມຕົ້ນ, ຕົວຢ່າງ *ນິຍາມເສັ້ນທາງວິກິດ: ເສັ້ນທາງທີ່ຍາວທີ່ສຸດ (ຄ່າເລີ່ມຕົ້ນ: ໄລຍະຜ່ອນຜັນລວມ ≤ 0 ຊົ່ວໂມງ)*. ຊ່ອງທີ່ວ່າງນັບເປັນຄ່າເລີ່ມຕົ້ນທີ່ຊ່ອງນັ້ນສະແດງ. ສຳລັບໂປຣໄຟລ໌ທີ່ກຳນົດເອງ ໃຊ້ຄ່າເລີ່ມຕົ້ນຂອງໂປຣໄຟລ໌ພື້ນຖານຂອງມັນ. ປຸ່ມ *ໃຊ້ການຕັ້ງຄ່າເລີ່ມຕົ້ນຂອງ Primavera P6* (ໂດຍມີຊື່ຂອງໂປຣໄຟລ໌) ຕັ້ງຊ່ອງເປັນຄ່າເລີ່ມຕົ້ນນັ້ນ; ແອັບຄິດໄລ່ພຽງແຕ່ຫຼັງຈາກ *ນຳໃຊ້*, ເປັນຂັ້ນຕອນດຽວ ດັ່ງນັ້ນ *ຍົກເລີກຄຳສັ່ງ* ກັບຄືນໄດ້ໃນຄັ້ງດຽວ. ເຄື່ອງໝາຍ × ຊ່ອນກ່ອງນີ້ສຳລັບໄຟລ໌ທີ່ເປີດຢູ່ນີ້. ເມື່ອເປີດໄຟລ໌ອີກຄັ້ງ ຫຼື ມີຄວາມແຕກຕ່າງໃໝ່, ກ່ອງຈະກັບມາ. ຖ້າບໍ່ມີຄວາມແຕກຕ່າງ ກໍ່ບໍ່ມີກ່ອງ. ປຸ່ມເຮັດຫຍັງກັບຕົວເລືອກຕົ້ນສະບັບ ໃຫ້ເບິ່ງໃຕ້ *ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບ*. ຄ່າເລີ່ມຕົ້ນຕໍ່ໂປຣໄຟລ໌: *Open Planner Studio* ແລະ *Microsoft Project* ບໍ່ມີຄ່າຂອງຕົນເອງ, ສະນັ້ນທຸກຕົວເລືອກຢູ່ຄ່າເລີ່ມຕົ້ນຂ້າງລຸ່ມ (ສຳລັບ *Microsoft Project*, *ອັດຕະໂນມັດ (ຄ່າເລີ່ມຕົ້ນ)* ພ້ອມວັນທີສະຖານະ ກໍ່ເປັນກົດ float ຂອງ MS Project ເອງເຊັ່ນກັນ); *Primavera P6* ຕັ້ງ *ປະຕິທິນໄລຍະຊັກຊ້າ (Lag)* ເປັນ *ໜ້າວຽກກ່ອນໜ້າ*, *ນິຍາມເສັ້ນທາງວິກິດ* ເປັນ *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ* ພ້ອມເກນກຳນົດ 0 ຊົ່ວໂມງ, *ການຄິດໄລ່ໄລຍະເວລາຜ່ອນຜັນ(Float)* ເປັນ *ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ*, *ໃຫ້ວຽກທີ່ບໍ່ມີຈຸດສິ້ນສຸດເປັນວຽກວິກິດ* ປິດ, ແລະ *ຄິດໄລ່ໄລຍະຊັກຊ້າ SS ຈາກວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່ ຈາກ* ເປັນ *ການເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ (P6: Early Start)*. ໄຟລ໌ `.xer` ກໍ່ນຳເອົາຄ່າຈາກໄຟລ໌ນັ້ນເອງມາດ້ວຍ.

**ນິຍາມເສັ້ນທາງວິກິດ** — ສິ່ງທີ່ເຮັດໃຫ້ໜ້າວຽກເປັນວິກິດ. ເລືອກຈາກ *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ* ແລະ *ເສັ້ນທາງທີ່ຍາວທີ່ສຸດ*. ຄ່າເລີ່ມຕົ້ນ: *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ* ພ້ອມເກນກຳນົດ 0. ຜົນ: ດ້ວຍ *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ* ໜ້າວຽກເປັນວິກິດ ຖ້າໄລຍະຜ່ອນຜັນລວມຂອງມັນນ້ອຍກວ່າ ຫຼື ເທົ່າກັບເກນກຳນົດ. ດ້ວຍ *ເສັ້ນທາງທີ່ຍາວທີ່ສຸດ* ໜ້າວຽກເປັນວິກິດ ຖ້າມັນຢູ່ໃນສາຍໜ້າວຽກທີ່ນຳໄປສູ່ການສິ້ນສຸດສຸດທ້າຍ; ຖ້າມີໜ້າວຽກສຸດທ້າຍຫຼາຍອັນທີ່ສິ້ນສຸດວັນດຽວກັນ ນັບທຸກສາຍຂອງພວກມັນ. ເມື່ອນັ້ນ float ບໍ່ມີບົດບາດ. ໃນທັງສອງກໍລະນີ ໜ້າວຽກທີ່ສຳເລັດແລ້ວບໍ່ເປັນວິກິດ, ແລະ ແຮມມັອກກໍ່ບໍ່ເປັນເຊັ່ນກັນ. ມັນໃຊ້ກັບ Gantt, ຕາຕະລາງ, ພາບລວມຫຼັກໝາຍ ແລະ ລາຍງານ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*.

**ເກນກຳນົດ (ມື້ເຮັດວຽກ)** — ຂີດຈຳກັດສຳລັບ *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ*. ຄ່າເລີ່ມຕົ້ນ: 0. ຜົນ: ເກນກຳນົດອາດເປັນລົບໄດ້. ເກນກຳນົດຈາກໄຟລ໌ `.xer`, ຫຼື ເກນກຳນົດທີ່ຕັ້ງໂດຍຄ່າເລີ່ມຕົ້ນຂອງ *Primavera P6* (0 ຊົ່ວໂມງ), ເປັນຊົ່ວໂມງ ແລະ ຖືກເອີ້ນວ່າ *ເກນກຳນົດ (ຊົ່ວໂມງ, ຕາມປະຕິທິນວຽກ)*: ແອັບປຽບທຽບມັນຕໍ່ໜ້າວຽກ ເປັນຊົ່ວໂມງຂອງປະຕິທິນວຽກຂອງໜ້າວຽກນັ້ນ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*, ຢູ່ຂ້າງ *ນິຍາມເສັ້ນທາງວິກິດ*.

**ການຄິດໄລ່ໄລຍະເວລາຜ່ອນຜັນ(Float)** — ໄລຍະຜ່ອນຜັນລວມແມ່ນ float ແບບໃດ. ເລືອກຈາກ *ອັດຕະໂນມັດ (ຄ່າເລີ່ມຕົ້ນ)*, *ໜ້ອຍທີ່ສຸດ (ເລີ່ມຕົ້ນ/ສິ້ນສຸດ)*, *ໄລຍະຜ່ອນຜັນຕອນເລີ່ມຕົ້ນ* ແລະ *ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ*. ຄ່າເລີ່ມຕົ້ນ: *ອັດຕະໂນມັດ (ຄ່າເລີ່ມຕົ້ນ)*, ຄືກັນພາຍໃຕ້ *Microsoft Project*; *Primavera P6* ຕັ້ງ *ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ*. ຜົນ: *ໄລຍະຜ່ອນຜັນຕອນເລີ່ມຕົ້ນ* ແມ່ນ ເລີ່ມຕົ້ນຊ້າສຸດ ລົບ ເລີ່ມຕົ້ນໄວສຸດ, *ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ* ແມ່ນ ສິ້ນສຸດຊ້າສຸດ ລົບ ສິ້ນສຸດໄວສຸດ, ແລະ *ໜ້ອຍທີ່ສຸດ (ເລີ່ມຕົ້ນ/ສິ້ນສຸດ)* ແມ່ນຄ່າທີ່ນ້ອຍກວ່າໃນສອງຄ່ານັ້ນ. *ອັດຕະໂນມັດ (ຄ່າເລີ່ມຕົ້ນ)* ໃຊ້ *ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ* ສຳລັບໜ້າວຽກທີ່ພວມດຳເນີນຢູ່ (ມີ ວັນເລີ່ມຕົວຈິງ ຫຼື ຄວາມຄືບໜ້າ, ແລະ ວັນທີສະຖານະ) ແລະ ໃຊ້ຄ່າໜ້ອຍທີ່ສຸດສຳລັບໜ້າວຽກອື່ນທັງໝົດ. ມີວັນທີສະຖານະ ນັ້ນແມ່ນກົດຂອງ MS Project. ບໍ່ມີວັນທີສະຖານະ ຄວາມຄືບໜ້າບໍ່ນັບ, ແລະ ໜ້າວຽກທີ່ເລີ່ມແລ້ວກໍ່ໄດ້ຄ່າໜ້ອຍທີ່ສຸດ; MS Project ຍັງໃຊ້ *ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ* ສຳລັບໜ້າວຽກທີ່ເລີ່ມແລ້ວຢູ່ດີ. ໄຟລ໌ .mpp ທີ່ເປີດແລ້ວ ແລະ ໂຄງການໃໝ່ດ້ວຍ *Microsoft Project* ຄິດໄລ່ແບບນີ້. *ໜ້ອຍທີ່ສຸດ (ເລີ່ມຕົ້ນ/ສິ້ນສຸດ)* ເລືອກຄ່າທີ່ນ້ອຍກວ່າ ແມ່ນແຕ່ສຳລັບໜ້າວຽກທີ່ພວມດຳເນີນຢູ່. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*.

**ໃຫ້ວຽກທີ່ບໍ່ມີຈຸດສິ້ນສຸດເປັນວຽກວິກິດ** — ໜ້າວຽກທີ່ບໍ່ມີໜ້າວຽກຖັດໄປ. ຄ່າເລີ່ມຕົ້ນ: ປິດ. ຜົນ: ເປີດ ເຮັດໃຫ້ໜ້າວຽກດັ່ງກ່າວມີ ໄລຍະຜ່ອນຜັນລວມ ແລະ free float ເປັນ 0, ດັ່ງນັ້ນພາຍໃຕ້ນິຍາມເສັ້ນທາງວິກິດ *ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ* ມັນກາຍເປັນວິກິດ (ເວັ້ນແຕ່ມັນສຳເລັດແລ້ວ). ປິດ ຄິດໄລ່ float ຕາມປົກກະຕິ ຈົນຮອດສິ້ນສຸດຂອງໂຄງການ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*.

**ໝາຍໃກ້ວິກິດ** — ໝາຍໜ້າວຽກທີ່ມີ float ເກືອບບໍ່ມີ. ຄ່າເລີ່ມຕົ້ນ: ປິດ. ຜົນ: ເປີດ ເຮັດໃຫ້ມີເກນກຳນົດ, ຄ່າເລີ່ມຕົ້ນ 2 ມື້ເຮັດວຽກ (ໃນຊ່ອງ *ເກນກຳນົດ*). ໜ້າວຽກທີ່ມີ ໄລຍະຜ່ອນຜັນລວມ ຫຼາຍກວ່າ 0 ແຕ່ບໍ່ເກີນເກນກຳນົດນັ້ນ ຖືກເອີ້ນວ່າ *ໃກ້ວິກິດ*; ໜ້າວຽກທີ່ມີ float ເປັນ 0 ພໍດີ ເປັນວິກິດ ແລະ ບໍ່ນັບ. ທ່ານເຫັນມັນໃນຖັນຕາຕະລາງ *ໃກ້ວິກິດ*, ໃນລາຍງານ, ແລະ ໃນ Gantt ບ່ອນທີ່ແຖບໜ້າວຽກປ່ຽນເປັນສີເຫຼືອງອຳພັນ (ເວັ້ນແຕ່ໜ້າວຽກເປັນວິກິດ). ຊ່ອງນີ້ສະແດງເປັນມື້ເຮັດວຽກ. ດ້ວຍ *ເປີດໃຊ້ການວາງແຜນລາຍຊົ່ວໂມງ* ມັນສະແດງເປັນຊົ່ວໂມງ ຖ້າການສະແດງໄລຍະເວລາເປັນ *ເປັນຊົ່ວໂມງສະເໝີ*, ຫຼື ເປັນ *ອັດຕະໂນມັດ (ຕາມຫົວໜ່ວຍເດີມຂອງແຕ່ລະໜ້າວຽກ)* ຖ້າປະຕິທິນໂຄງການເປັນປະຕິທິນຊົ່ວໂມງ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*.

**ເສັ້ນທາງຜ່ອນຜັນຫຼາຍສາຍ** — ໃສ່ເລກໃຫ້ສາຍໜ້າວຽກຕາມ float ຂອງພວກມັນ. ຄ່າເລີ່ມຕົ້ນ: ປິດ. ຜົນ: ເປີດ ໃຫ້ໜ້າວຽກມີເລກໃນຖັນຕາຕະລາງ *ເສັ້ນທາງຜ່ອນຜັນ*. ໃນ Gantt ແຖບໜ້າວຽກຂອງເສັ້ນທາງ 2 ຂຶ້ນໄປໄດ້ສີອ່ອນຂອງຕົນເອງ, ເວັ້ນແຕ່ພວກມັນເປັນວິກິດ ຫຼື ໃກ້ວິກິດ. ປິດ ຖັນນັ້ນຈະວ່າງ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*.

**ວິທີ** — ເສັ້ນທາງເກີດຂຶ້ນແນວໃດ, ດ້ວຍ *ເສັ້ນທາງຜ່ອນຜັນຫຼາຍສາຍ*. ເລືອກຈາກ *ໄລຍະຜ່ອນຜັນອິດສະຫຼະ (ແຍກສ່ວນ)* ແລະ *ໄລຍະຜ່ອນຜັນລວມ (ຈັດອັນດັບ)*. ຄ່າເລີ່ມຕົ້ນ: *ໄລຍະຜ່ອນຜັນອິດສະຫຼະ (ແຍກສ່ວນ)*. ຜົນ: ດ້ວຍ *ໄລຍະຜ່ອນຜັນອິດສະຫຼະ (ແຍກສ່ວນ)* ແອັບແຍກສາຍອອກເທື່ອລະສາຍ. ມັນເລືອກໜ້າວຽກທີ່ມີວັນສິ້ນສຸດສຸດທ້າຍ ແລະ ເພີ່ມໜ້າວຽກກ່ອນໜ້າທີ່ມີສາຍພົວພັນຄວບຄຸມກັບມັນ: ນັ້ນແມ່ນເສັ້ນທາງ 1. ຈາກໜ້າວຽກທີ່ເຫຼືອ ມັນເຮັດແບບດຽວກັນສຳລັບເສັ້ນທາງ 2 ແລະ ຕໍ່ໄປ; ໜ້າວຽກກ່ອນໜ້າທີ່ໃຊ້ຮ່ວມກັນຮັກສາເລກຂອງເສັ້ນທາງທຳອິດທີ່ມັນປາກົດ. ດ້ວຍ *ໄລຍະຜ່ອນຜັນລວມ (ຈັດອັນດັບ)* ເລກແມ່ນອັນດັບຂອງ ໄລຍະຜ່ອນຜັນລວມ ຂອງໜ້າວຽກ: 1 ສຳລັບຄ່າທີ່ນ້ອຍທີ່ສຸດ, 2 ສຳລັບຄ່າທີ່ນ້ອຍເປັນອັນດັບສອງ. ແຮມມັອກບໍ່ເຂົ້າຮ່ວມ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*.

**ຈຳນວນເສັ້ນທາງສູງສຸດ** — ມີຈັກເສັ້ນທາງທີ່ໄດ້ເລກ. ຄ່າເລີ່ມຕົ້ນ: 10. ຜົນ: ໜ້າວຽກນອກເສັ້ນທາງ ຫຼື ອັນດັບທຳອິດ ຕາມ *ຈຳນວນເສັ້ນທາງສູງສຸດ* ບໍ່ໄດ້ເລກ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*, ພ້ອມກັບ *ເສັ້ນທາງຜ່ອນຜັນຫຼາຍສາຍ*.

**ປະຕິທິນໄລຍະຊັກຊ້າ (Lag)** — ໃນປະຕິທິນໃດທີ່ ຄ່າ Lag ເປັນເວລາເຮັດວຽກຖືກນັບ. ເລືອກຈາກ *ໜ້າວຽກກ່ອນໜ້າ*, *ໜ້າວຽກຖັດໄປ*, *24 ຊົ່ວໂມງ* ແລະ *ປະຕິທິນໂຄງການ*. ຄ່າເລີ່ມຕົ້ນ: *ໜ້າວຽກກ່ອນໜ້າ*. ຜົນ: ຄ່າ Lag 2 ມື້ຖືກນັບໃນມື້ເຮັດວຽກຂອງປະຕິທິນທີ່ທ່ານເລືອກ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*. ເບິ່ງ [ສາຍສຳພັນ ແລະ ຄ່າ Lag](docs://uitleg-relaties).

**ຄິດໄລ່ໄລຍະຊັກຊ້າ SS ຈາກວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່ ຈາກ** — ຕົວແປຂອງຂໍ້ກຳນົດ *ຄ່າ SS lag ທີ່ຜ່ານໄປແລ້ວຈາກໜ້າວຽກກ່ອນໜ້າທີ່ພວມເຮັດ ຈະບໍ່ຖືກນັບ*. ເລືອກຈາກ *ການເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ (P6: Early Start)* ແລະ *ວັນທີສະຖານະ (P6: Actual Start)*. ຄ່າເລີ່ມຕົ້ນ: *ການເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ (P6: Early Start)*. ຜົນ: ສຳລັບສາຍສຳພັນ start-to-start ທີ່ມີ ຄ່າ Lag ເວລາເຮັດວຽກບວກ ຈາກໜ້າວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່, ໜ້າວຽກຖັດໄປດ້ວຍ *ການເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ (P6: Early Start)* ເລີ່ມທີ່ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອຂອງໜ້າວຽກກ່ອນໜ້າ ບວກ ຄ່າ Lag ທີ່ເຫຼືອ. ດ້ວຍ *ວັນທີສະຖານະ (P6: Actual Start)* ມັນເລີ່ມທີ່ວັນທີສະຖານະ ບວກ ຄ່າ Lag ທີ່ເຫຼືອ, ແລະ ສາຍສຳພັນບໍ່ຈຳກັດໜ້າວຽກກ່ອນໜ້າທີ່ພວມດຳເນີນຢູ່ຍ້ອນຫຼັງ. ຄ່າ Lag ທີ່ເຫຼືອແມ່ນ ຄ່າ Lag ລົບເວລາເຮັດວຽກລະຫວ່າງ ວັນເລີ່ມຕົວຈິງ ແລະ ວັນທີສະຖານະ, ແລະ ບໍ່ເຄີຍຕ່ຳກວ່າ 0. ຄ່າ Lag 0 ຫຼື ຕ່ຳກວ່າ, ຄ່າ Lag ເປັນຊົ່ວໂມງຕາມໂມງ, ແລະ ແຜນງານເປັນວັນ ຮັກສາພຶດຕິກຳປົກກະຕິ. ທາງເລືອກນີ້ເຮັດວຽກສະເພາະເມື່ອຂໍ້ກຳນົດ *ຄ່າ SS lag ທີ່ຜ່ານໄປແລ້ວຈາກໜ້າວຽກກ່ອນໜ້າທີ່ພວມເຮັດ ຈະບໍ່ຖືກນັບ* ແລະ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ* ເປີດທັງສອງ; ຖ້າບໍ່ດັ່ງນັ້ນ ລາຍການເລື່ອນລົງຖືກປິດໃຊ້ງານ ແລະ ມັນຂຽນວ່າ *ໃຊ້ໄດ້ສະເພາະເມື່ອເປີດຂໍ້ກຳນົດ “…” ເທົ່ານັ້ນ.* ຖ້າບໍ່ມີການວາງແຜນລາຍຊົ່ວໂມງໃນປະຕິທິນ Lag ທີ່ເລືອກ ລາຍການເລື່ອນລົງກໍ່ຖືກປິດໃຊ້ງານເຊັ່ນກັນ ແລະ ມັນຂຽນວ່າ *ໃຊ້ໄດ້ພຽງແຕ່ໃນການວາງແຜນລາຍຊົ່ວໂມງ: ປະຕິທິນທີ່ມີຊ່ວງເວລາເຮັດວຽກ ຫຼື ໜ້າວຽກເປັນຊົ່ວໂມງ. ໂຄງການນີ້ບໍ່ມີທັງສອງຢ່າງ ໃນປະຕິທິນ Lag ທີ່ເລືອກ.* ມີການວາງແຜນລາຍຊົ່ວໂມງສະເໝີດ້ວຍ *24 ຊົ່ວໂມງ*, ດ້ວຍ *ປະຕິທິນໂຄງການ* ຖ້າປະຕິທິນໂຄງການມີຊ່ວງເວລາເຮັດວຽກ, ແລະ ດ້ວຍ *ໜ້າວຽກກ່ອນໜ້າ* ແລະ *ໜ້າວຽກຖັດໄປ* ຖ້າປະຕິທິນຂອງໂຄງການມີຊ່ວງເວລາເຮັດວຽກ ຫຼື ໜ້າວຽກເປັນຊົ່ວໂມງ. ຢູ່ໃສ: *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*.

### ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບ

ຕົວເລືອກເຫຼົ່ານີ້ມາຈາກໄຟລ໌ `.xer` ຂອງ Primavera P6 ແລະ ອ່ານຢ່າງດຽວ. ກ່ອງ *ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບ* ປາກົດສະເພາະເມື່ອໂຄງການມີພວກມັນ, ນັ້ນແມ່ນໂຄງການຈາກໄຟລ໌ `.xer`. ພວກມັນນັບໃນການຄິດໄລ່. ປຸ່ມ *ໃຊ້ການຕັ້ງຄ່າເລີ່ມຕົ້ນຂອງ …* ແລະ ໂປຣໄຟລ໌ອື່ນ ປ່ອຍພວກມັນໄວ້ຕາມທີ່ໄຟລ໌ໃຫ້ມາ. ພວກມັນກໍ່ບໍ່ນັບເປັນຄວາມແຕກຕ່າງ. ໂຄງການໃໝ່ບໍ່ໄດ້ຮັບພວກມັນ, ເຖິງແມ່ນດ້ວຍ *Primavera P6*.

**ໃຊ້ວັນສຳເລັດທີ່ຄາດໄວ້ (P6: Use Expected Finish Dates)** — ຄ່າເລີ່ມຕົ້ນ (ຖ້າໄຟລ໌ບໍ່ໄດ້ລະບຸຫຍັງ): ເປີດ. ຜົນ: ໜ້າວຽກ P6 ທີ່ພວມດຳເນີນຢູ່ ແລະ ມີວັນສຳເລັດທີ່ຄາດໄວ້ ຈະໄດ້ວັນນັ້ນເປັນ ສິ້ນສຸດໄວສຸດ ຂອງມັນ. ຢູ່ໃສ: *ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບ*.

**ຄິດໄລ່ float ຮອດວັນສິ້ນສຸດໂຄງການ** — ຄ່າເລີ່ມຕົ້ນ: ປິດ. ຜົນ: ວັນສິ້ນສຸດຂອງໂຄງການເປັນຈຸດຍຶດສຳລັບ ວັນທີ late. ຖ້າບໍ່ມີວັນສິ້ນສຸດໃນໄຟລ໌ ແອັບຄິດໄລ່ຈົນຮອດສຸດຂອງເຄືອຂ່າຍ. ຢູ່ໃສ: *ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບ*.

**ໜ້າວຽກທີ່ສຳເລັດ: ວັນທີ late ເລີ່ມຈາກວັນທີສະຖານະ** — ຄ່າເລີ່ມຕົ້ນ (ຖ້າໄຟລ໌ບໍ່ໄດ້ລະບຸຫຍັງ): ເປີດ. ຜົນ: ໜ້າວຽກທີ່ສຳເລັດແລ້ວກໍ່ໄດ້ໄລຍະເວລາທີ່ເຫຼືອເປັນ 0 ໃນວັນທີສະຖານະ ດ້ານ late, ພ້ອມ float ທີ່ມີຄວາມໝາຍ. ມັນເຮັດວຽກສະເພາະຮ່ວມກັບຂໍ້ກຳນົດ *ໜ້າວຽກທີ່ສຳເລັດແລ້ວໃນຊ່ວງ data-date*, ທີ່ປິດຢູ່ໃນທຸກໂປຣໄຟລ໌ທີ່ມີມາໃນຕົວ; ຖ້າມັນປິດ ແອັບຂຽນວ່າ *ໃຊ້ຮ່ວມກັນໄດ້ສະເພາະກັບຂໍ້ກຳນົດ “…” ເຊິ່ງປະຈຸບັນປິດຢູ່.* ຢູ່ໃສ: *ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບ*.
