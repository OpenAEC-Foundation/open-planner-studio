# ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຂໍ້ກຳນົດ

ແຜນງານດຽວກັນອາດໃຫ້ວັນທີທີ່ແຕກຕ່າງກັນ, ຂຶ້ນກັບກົດການຄິດໄລ່ທີ່ທ່ານໃຊ້. ບົດຄວາມນີ້ອະທິບາຍວ່າເປັນຫຍັງ Primavera P6 ແລະ Microsoft Project ຄິດໄລ່ຕ່າງກັນໃນບາງຈຸດ. ມັນອະທິບາຍວ່າແອັບບັນທຶກຄວາມແຕກຕ່າງນັ້ນໄວ້ໃນ **ໂປຣໄຟລ໌ການຄິດໄລ່** ແນວໃດ, ແລະ ໂປຣໄຟລ໌ຕ່າງຈາກ ຕົວເລືອກການຄິດໄລ່ ທີ່ທ່ານຕັ້ງເອງໃນແຕ່ລະໂຄງການແນວໃດ. ຕົວຢ່າງເຄືອຂ່າຍນ້ອຍໜຶ່ງ ສະແດງໃຫ້ເຫັນຜົນຂອງສິ່ງນີ້ຕໍ່ວັນທີ.

## ແນວຄິດ

ໜ້າວຽກ, ສາຍສຳພັນ ແລະ ປະຕິທິນ ກຳນົດສ່ວນໃຫຍ່ຂອງແຜນງານ ແຕ່ບໍ່ທັງໝົດ. ເກີດຫຍັງຂຶ້ນກັບວຽກທີ່ຍັງບໍ່ເລີ່ມ ເມື່ອທ່ານຕັ້ງ ວັນທີສະຖານະ? ວຽກທີ່ເຫຼືອຂອງໜ້າວຽກທີ່ພວມດຳເນີນຢູ່ແລ້ວ ເລີ່ມຕົ້ນຈາກໃສ? free float ຂອງໜ້າວຽກແມ່ນເທົ່າໃດ ເມື່ອ ກຳນົດສົ່ງ ຖືກພາດ? ເຄືອຂ່າຍບໍ່ໄດ້ບອກຫຍັງກ່ຽວກັບເລື່ອງນັ້ນ. ໂປຣແກຣມແຜນງານຕ້ອງເລືອກກົດໜຶ່ງໃຫ້ມັນ. ແອັບຮູ້ຈຸດຈຳນວນໜຶ່ງ ທີ່ກົດຂອງ Primavera P6 ແລະ ກົດຂອງ Microsoft Project ແຕກຕ່າງກັນ.

ແອັບເອີ້ນທາງເລືອກແບບນັ້ນວ່າ **ຂໍ້ກຳນົດ**. **ໂປຣໄຟລ໌ການຄິດໄລ່** ແມ່ນຊຸດຂອງຂໍ້ກຳນົດທີ່ເປັນຂອງແພັກເກດໜຶ່ງ. ແອັບມີສາມອັນ:

- *Open Planner Studio*: ໂປຣໄຟລ໌ທີ່ໂຄງການໃໝ່ຄິດໄລ່ດ້ວຍ. ບໍ່ມີຂໍ້ກຳນົດໃດເປີດຢູ່.
- *Primavera P6*: ຂໍ້ກຳນົດທີ່ແອັບຮູ້ຈັກຈາກ P6.
- *Microsoft Project*: ຂໍ້ກຳນົດທີ່ແອັບຮູ້ຈັກຈາກ Microsoft Project.

ດັ່ງນັ້ນ ໂປຣໄຟລ໌ບອກວ່າແພັກເກດໜຶ່ງຄິດໄລ່ແນວໃດ. ສິ່ງທີ່ທ່ານຕ້ອງການສຳລັບໂຄງການຂອງທ່ານບໍ່ແມ່ນສ່ວນໜຶ່ງຂອງມັນ. ນັ້ນແມ່ນ **ຕົວເລືອກການຄິດໄລ່**: ທາງເລືອກເຊັ່ນ float ໜ້ອຍປານໃດທີ່ເຮັດໃຫ້ໜ້າວຽກວິກິດ, ຫຼື ຄ່າ Lag ນັບໃນປະຕິທິນໃດ. ທ່ານຕັ້ງຄ່າເຫຼົ່ານັ້ນໃນແຕ່ລະໂຄງການ.

## ແອັບຄິດໄລ່ແນວໃດ

### ຂໍ້ກຳນົດ ແລະ ຕົວເລືອກການຄິດໄລ່

ຂໍ້ກຳນົດແມ່ນສະວິດໜຶ່ງ: ເປີດ ຫຼື ປິດ. ໂປຣໄຟລ໌ເປັນຕົວກຳນົດວ່າສະວິດໃດເປີດຢູ່. ຕົວເລືອກການຄິດໄລ່ແມ່ນທາງເລືອກທີ່ທ່ານເຮັດເອງ. ທ່ານສາມາດເຫັນຄວາມແຕກຕ່າງໃນແອັບເອງ ໃນສ່ວນ *ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ*:

- **ຂໍ້ກຳນົດ** ຢູ່ໃຕ້ *ຂໍ້ກຳນົດຂອງໂປຣໄຟລ໌ນີ້*, ຈັດກຸ່ມຕາມຫົວຂໍ້. ຕົວຢ່າງເຊັ່ນ *ຄວາມຄືບໜ້າ ແລະ ວຽກທີ່ສຳເລັດ*, *ສາຍສຳພັນ ແລະ ຄ່າ lag* ແລະ *Float ແລະ ວັນທີ late*. ສ່ວນນີ້ຖືກພັບໄວ້ຕອນທຳອິດ. ຫົວຂໍ້ຂອງມັນບອກຈຳນວນຂໍ້ກຳນົດ ແລະ ຖ້າໂປຣໄຟລ໌ຖືກປ່ຽນແປງ ມັນຈະມີປ້າຍ *ປ່ຽນແລ້ວ: 1*. ຄລິກທີ່ຫົວຂໍ້ເພື່ອຂະຫຍາຍ. ດ້ວຍໂປຣໄຟລ໌ທີ່ມາກັບແອັບ ແຕ່ລະແຖວມີປ້າຍ *ເປີດ* ຫຼື *ປິດ*. ຄ່າເຫຼົ່ານັ້ນແມ່ນເພື່ອຂໍ້ມູນ ແລະ ປ່ຽນບໍ່ໄດ້. ດ້ວຍໂປຣໄຟລ໌ຂອງທ່ານເອງ ແຕ່ລະແຖວມີຊ່ອງໝາຍຖືກ, ແລະ ຄ່າຫຼັກຢູ່ທ້າຍ (*ຄ່າຫຼັກ: ເປີດ* ຫຼື *ຄ່າຫຼັກ: ປິດ*). ຖ້າທາງເລືອກຂອງທ່ານຕ່າງຈາກນັ້ນ ແຖວນັ້ນຈະເດັ່ນຂຶ້ນ ແລະ *ກັບຄືນເປັນຄ່າຫຼັກ* ຈະປາກົດ. ໄອຄອນ i ຫຼັງແຖວສະແດງຄຳອະທິບາຍຂອງຂໍ້ກຳນົດນັ້ນ. ຊີ້ດ້ວຍເມົ້າ, ເລື່ອນໄປດ້ວຍ Tab ຫຼື ແຕະມັນ. ອ່ານຄຳອະທິບາຍນັ້ນກ່ອນ ຖ້າທ່ານຢາກປ່ຽນຂໍ້ກຳນົດ. ຖ້າຂໍ້ກຳນົດໃຊ້ໄດ້ພຽງກັບການວາງແຜນລາຍຊົ່ວໂມງ ຫຼື ພຽງກັບໜ້າວຽກຈາກໄຟລ໌ .xer, ປ້າຍສີຟ້າຢູ່ຂ້າງມັນຈະບອກແນວນັ້ນ: *ສະເພາະການວາງແຜນລາຍຊົ່ວໂມງ* ຫຼື *ສະເພາະໜ້າວຽກຈາກ .xer*. ການວາງແຜນລາຍຊົ່ວໂມງໝາຍເຖິງ: ປະຕິທິນທີ່ມີຊ່ວງເວລາເຮັດວຽກ, ໜ້າວຽກທີ່ມີໄລຍະເວລາເປັນຊົ່ວໂມງ, ຫຼື ປະຕິທິນໄລຍະຊັກຊ້າ (Lag) ຕັ້ງເປັນ *24 ຊົ່ວໂມງ*. ໂຄງການທີ່ມີແຕ່ປະຕິທິນມື້ ແລະ ໜ້າວຽກເປັນມື້ ຈະບໍ່ສັງເກດເຫັນຂໍ້ກຳນົດທີ່ມີປ້າຍ *ສະເພາະການວາງແຜນລາຍຊົ່ວໂມງ*, ເວັ້ນແຕ່ປະຕິທິນໄລຍະຊັກຊ້າຈະຕັ້ງເປັນ *24 ຊົ່ວໂມງ*. ແລ້ວຄ່າ Lag ຈະນັບເປັນຊົ່ວໂມງ, ແລະ ຂໍ້ກຳນົດກ່ຽວກັບ Lag ສາມາດປ່ຽນແປງບາງຢ່າງໄດ້.
- **ຕົວເລືອກການຄິດໄລ່** ຢູ່ໃຕ້ *ຕົວເລືອກການຄິດໄລ່ຂອງໂຄງການນີ້*: ໃນນັ້ນມີ *ນິຍາມເສັ້ນທາງວິກິດ*, *ການຄິດໄລ່ໄລຍະເວລາຜ່ອນຜັນ(Float)*, *ໃຫ້ວຽກທີ່ບໍ່ມີຈຸດສິ້ນສຸດເປັນວຽກວິກິດ*, *ໝາຍວ່າເກືອບວິກິດ* ແລະ *ປະຕິທິນໄລຍະຊັກຊ້າ (Lag)*. ພວກມັນບອກວ່າທ່ານຢາກໃຫ້ໂຄງການນີ້ເປັນແນວໃດ, ບໍ່ແມ່ນວ່າໂປຣໄຟລ໌ໜຶ່ງຄິດໄລ່ແນວໃດ. ສິ່ງທີ່ພວກມັນເຮັດ ອະທິບາຍໄວ້ໃນ [ເສັ້ນທາງວິກິດ ແລະ float](docs://uitleg-kritiek-pad) ແລະ [ສາຍສຳພັນ ແລະ ຄ່າ Lag](docs://uitleg-relaties).

ຕົວຢ່າງຂອງແຕ່ລະອັນ. “ໜ້າວຽກເປັນວິກິດ ຖ້າ ໄລຍະຜ່ອນຜັນລວມ ເປັນ 0 ຫຼື ໜ້ອຍກວ່າ” ແມ່ນຕົວເລືອກການຄິດໄລ່: ທ່ານສາມາດຕັ້ງເກນກຳນົດເປັນ 4, ແລະ ທຸກຢ່າງທີ່ມີ float 4 ມື້ເຮັດວຽກ ຫຼື ໜ້ອຍກວ່າ ຈະເປັນວິກິດ. “ໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມຍ້າຍໄປທີ່ວັນທີສະຖານະ” ແມ່ນຂໍ້ກຳນົດ: Open Planner Studio ແລະ Primavera P6 ເຮັດແບບນັ້ນ, ແຕ່ Microsoft Project ບໍ່ເຮັດ.

ໂປຣໄຟລ໌ ແລະ ຕົວເລືອກການຄິດໄລ່ເປັນຂອງໄຟລ໌ໂຄງການ, ບໍ່ແມ່ນຂອງແອັບ. ຖ້າທ່ານບັນທຶກໂຄງການ ມັນຈະໄປພ້ອມກັບໄຟລ໌. ດັ່ງນັ້ນ ສອງໂຄງການໃນແອັບດຽວກັນສາມາດຄິດໄລ່ດ້ວຍໂປຣໄຟລ໌ທີ່ຕ່າງກັນ. ໂຄງການທີ່ບໍ່ມີໂປຣໄຟລ໌ ຄິດໄລ່ເປັນ Open Planner Studio.

ຖ້າໂຄງການຂອງທ່ານມາຈາກໄຟລ໌ .xer, ສ່ວນນີ້ຈະສະແດງ *ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບ* ຢູ່ລຸ່ມສຸດ: ຕົວເລືອກການຄິດໄລ່ທີ່ມີແຕ່ Primavera ຮູ້ຈັກ ແລະ ທີ່ໄຟລ໌ນຳມາ. ທ່ານບໍ່ສາມາດປ່ຽນແປງມັນທີ່ນີ້ໄດ້. ປຸ່ມຕັ້ງຄ່າເລີ່ມຕົ້ນ ແລະ ການປ່ຽນໄປອີກໂປຣໄຟລ໌ໜຶ່ງກໍປ່ອຍມັນໄວ້ຄືເກົ່າ. ໂຄງການໃໝ່ບໍ່ມີມັນ, ແມ່ນແຕ່ກັບ *Primavera P6*.

### ບ່ອນທີ່ທ່ານເລືອກໂປຣໄຟລ໌

ສຳລັບໂຄງການໃໝ່ ໂປຣໄຟລ໌ຢູ່ໃນໜ້າຕ່າງ *ໂຄງການໃໝ່*, ເຊິ່ງທ່ານເປີດຜ່ານ *ໜ້າຫຼັກ › ໄຟລ໌ › ໃໝ່*. ທີ່ນັ້ນ *ໂປຣໄຟລ໌ການຄິດໄລ່* ເປັນລາຍການແບບເລື່ອນລົງ. ຖ້າທ່ານເລືອກໂປຣໄຟລ໌ຢູ່ທີ່ນັ້ນ ແອັບຈະແທນທີ່ຕົວເລືອກການຄິດໄລ່ທີ່ທ່ານຕື່ມໄວ້ແລ້ວ ດ້ວຍຄ່າເລີ່ມຕົ້ນຂອງໂປຣໄຟລ໌ນັ້ນ. ມີແຕ່ການຕັ້ງຄ່າຈາກໄຟລ໌ຕົ້ນສະບັບເທົ່ານັ້ນທີ່ຍັງຄົງຢູ່. ດ້ວຍ *Primavera P6*, *ການຄິດໄລ່ໄລຍະເວລາຜ່ອນຜັນ(Float)* ຈະເປັນ *ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ*. ດ້ວຍ *Microsoft Project* ແລະ *Open Planner Studio* ທຸກຕົວເລືອກການຄິດໄລ່ຢູ່ຄ່າເລີ່ມຕົ້ນ, ດັ່ງນັ້ນ *ການຄິດໄລ່ໄລຍະເວລາຜ່ອນຜັນ(Float)* ແມ່ນ *ອັດຕະໂນມັດ (ຄ່າເລີ່ມຕົ້ນ)*. ເມື່ອມີວັນທີສະຖານະ MS Project ເອງກໍຄິດໄລ່ແບບນີ້ເຊັ່ນກັນ: ໜ້າວຽກທີ່ເລີ່ມແລ້ວໄດ້ໄລຍະຜ່ອນຜັນຕອນສິ້ນສຸດ ແລະ ໜ້າວຽກອື່ນທຸກອັນໄດ້ຄ່າທີ່ນ້ອຍກວ່າລະຫວ່າງໄລຍະຜ່ອນຜັນຕອນເລີ່ມຕົ້ນ ແລະ ຕອນສິ້ນສຸດ.

ສຳລັບໂຄງການທີ່ມີຢູ່ແລ້ວ ທ່ານເລືອກໂປຣໄຟລ໌ໃນ *ການຕັ້ງຄ່າ › ໂຄງການ › ການຕັ້ງຄ່າໂຄງການ*, ໃນສ່ວນ *ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ*, ໃນລາຍການແບບເລື່ອນລົງ *ໂປຣໄຟລ໌ການຄິດໄລ່*. ທ່ານຍັງເຂົ້າໄປບ່ອນດຽວກັນໄດ້ຜ່ານ *ໄຟລ໌ › ການຕັ້ງຄ່າໂຄງການ*. ການປ່ຽນໂປຣໄຟລ໌ຢູ່ທີ່ນີ້ປ່ຽນແຕ່ຂໍ້ກຳນົດເທົ່ານັ້ນ. ຕົວເລືອກການຄິດໄລ່ຂອງທ່ານຍັງຄົງຢູ່ຄືເກົ່າ. ຖ້າຕົວເລືອກການຄິດໄລ່ຂອງທ່ານແຕກຕ່າງຈາກຄ່າເລີ່ມຕົ້ນຂອງໂປຣໄຟລ໌, ສ່ວນສີສົ້ມຢູ່ເໜືອຕົວເລືອກຈະບອກແນວນັ້ນ. ມັນມັກຈະເປັນແບບນັ້ນໂດຍເຈດຕະນາ, ຕົວຢ່າງ ເພາະຕົວເລືອກມາຈາກໄຟລ໌ທີ່ເປີດ. ຖ້າທ່ານຢາກໄດ້ຄ່າເລີ່ມຕົ້ນຢ່າງໃດກໍຕາມ ໃຫ້ເລືອກ *ໃຊ້ການຕັ້ງຄ່າເລີ່ມຕົ້ນຂອງ …* ໃນສ່ວນນັ້ນ. ປຸ່ມ × ເຊື່ອງສ່ວນນີ້ສຳລັບໄຟລ໌ທີ່ເປີດນີ້.

ຈົນກວ່າທ່ານຈະກົດ *ນຳໃຊ້*, ການປ່ຽນແປງຢູ່ໃນແບບຟອມເທົ່ານັ້ນ. ດ້ວຍ *ນຳໃຊ້* ແອັບຄິດໄລ່ແຜນງານຄືນໃໝ່ທັນທີ, ເຖິງແມ່ນ *ຄິດໄລ່ອັດຕະໂນມັດ* ປິດຢູ່. ຖ້າໜ້າວຽກຍ້າຍ ມັນບອກຈຳນວນ, ຕົວຢ່າງ *ຫຼັງຈາກນຳໃຊ້, ມີ 4 ໜ້າວຽກຖືກຍ້າຍ.* ການປ່ຽນແປງທັງໝົດນີ້ເປັນຂັ້ນຕອນດຽວສຳລັບ *ຍົກເລີກຄຳສັ່ງ*. ຖ້າທ່ານກົດ *ຍົກເລີກຄຳສັ່ງ* ຫຼື *ເຮັດຄືນ* ໃນຂະນະທີ່ *ການຕັ້ງຄ່າໂຄງການ* ເປີດຢູ່, ສ່ວນນັ້ນຈະຕາມສະຖານະຂອງໂຄງການ. ຖ້າທ່ານໄດ້ປ່ຽນບາງຢ່າງໃນສ່ວນນັ້ນເອງແລ້ວ, ທາງເລືອກຂອງທ່ານຍັງຄົງຢູ່ ແລະ ສ່ວນສີເຫຼືອງຈະບອກວ່າ ກົດ *ນຳໃຊ້* ຈະນຳທາງເລືອກນັ້ນກັບມາ.

ໂປຣໄຟລ໌ທີ່ມາກັບແອັບ ສາມອັນປ່ຽນແປງບໍ່ໄດ້. ສຳລັບຂໍ້ກຳນົດອື່ນ ທ່ານສ້າງໂປຣໄຟລ໌ເອງ; ທ່ານສາມາດເກັບມັນໄວ້ເປັນແມ່ແບບສຳລັບໂຄງການອື່ນໃນແອັບນີ້ເຊັ່ນກັນ. ໂຄງການມີສຳເນົາຂອງຕົນເອງສະເໝີ: ຖ້າທ່ານປ່ຽນແມ່ແບບພາຍຫຼັງ ໂຄງການຈະບໍ່ປ່ຽນຕາມ. ຂັ້ນຕອນຢູ່ໃນ [ການເລືອກ ຫຼື ສ້າງໂປຣໄຟລ໌ການຄິດໄລ່](docs://howto-rekenprofiel-kiezen).

### ເມື່ອແອັບເລືອກໂປຣໄຟລ໌ເອງ

ເມື່ອທ່ານເປີດໄຟລ໌, ແອັບແນະນຳໂປຣໄຟລ໌ຕາມຮູບແບບ:

- ໄຟລ໌ .mpp (Microsoft Project) ເປີດດ້ວຍໂປຣໄຟລ໌ *Microsoft Project*.
- ໄຟລ໌ .xer (Primavera P6) ເປີດດ້ວຍໂປຣໄຟລ໌ *Primavera P6*.
- ໄຟລ໌ໃນຮູບແບບ *MS Project XML*, *Primavera P6 XML* ຫຼື *CSV (ຂັ້ນດ້ວຍຈໍ້າຈຸດ ;)* ເປີດດ້ວຍ *Open Planner Studio*, ໂດຍບໍ່ມີຂໍ້ຄວາມກ່ຽວກັບໂປຣໄຟລ໌.
- ໂຄງການຂອງທ່ານເອງ (.ifc) ເປີດດ້ວຍໂປຣໄຟລ໌ທີ່ເກັບໄວ້ໃນນັ້ນ.

ສຳລັບໄຟລ໌ .mpp ຫຼື .xer ແອັບລາຍງານໂປຣໄຟລ໌: *ໂຄງການນີ້ຄິດໄລ່ຕາມໂປຣໄຟລ໌ Microsoft Project. ປ່ຽນແປງໄດ້ທີ່ ໄຟລ໌ → ຂໍ້ມູນໂຄງການ → ໂປຣໄຟລ໌ການຄິດໄລ່ ແລະ ຕົວເລືອກ.* ປຸ່ມ *ເປີດໂປຣໄຟລ໌ການຄິດໄລ່* ໃນຂໍ້ຄວາມຈະພາທ່ານໄປທີ່ *ການຕັ້ງຄ່າໂຄງການ* ໂດຍກົງ. ສຳລັບໄຟລ໌ .xer ແຖວນີ້ແມ່ນແຖວລາຍລະອຽດທຳອິດຂອງຂໍ້ຄວາມເປີດໄຟລ໌. ຂໍ້ມູນເພີ່ມເຕີມກ່ຽວກັບຂໍ້ຄວາມນີ້ຢູ່ໃນ [ການເປີດໄຟລ໌ Primavera P6 (.xer)](docs://howto-xer-openen) ແລະ [ການເປີດໄຟລ໌ MS Project (.mpp)](docs://howto-mpp-openen).

ສຳລັບໄຟລ໌ .mpp ແອັບພຽງແຕ່ຕັ້ງໂປຣໄຟລ໌. ຕົວເລືອກການຄິດໄລ່ຍັງວ່າງຢູ່, ຄືກັບໂຄງການໃໝ່ທີ່ມີໂປຣໄຟລ໌ *Microsoft Project*: *ການຄິດໄລ່ໄລຍະເວລາຜ່ອນຜັນ(Float)* ແມ່ນ *ອັດຕະໂນມັດ (ຄ່າເລີ່ມຕົ້ນ)*. ດັ່ງນັ້ນ ໄຟລ໌ .mpp ທີ່ເປີດແລ້ວ ແລະ ໂຄງການໃໝ່ທີ່ມີ *Microsoft Project* ຈະຄິດໄລ່ float ແບບດຽວກັນ.

## ຕົວຢ່າງ: ເຄືອຂ່າຍໜຶ່ງ, ສາມໂປຣໄຟລ໌

ຕົວຢ່າງນີ້ແມ່ນເຄືອຂ່າຍນ້ອຍໜຶ່ງ. ປະຕິທິນມີອາທິດເຮັດວຽກຈາກວັນຈັນຫາວັນສຸກ ແລະ ບໍ່ມີມື້ພັກໃນອາທິດເຫຼົ່ານີ້. ຮູບແບບຄວາມຄືບໜ້າແມ່ນ Retained Logic (ຄ່າເລີ່ມຕົ້ນ). ໂຄງການເລີ່ມວັນຈັນ 7 ມິຖຸນາ 2027. ໜ້າວຽກທັງໝົດໃຊ້ໄລຍະເວລາເປັນມື້ເຮັດວຽກ.

- *Pour foundation*: 5 ມື້ເຮັດວຽກ, ຕາມແຜນຈາກວັນຈັນ 7 ມິຖຸນາ.
- *Lay walls*: 5 ມື້ເຮັດວຽກ, ຫຼັງ *Pour foundation* (ສຳເລັດ-ເລີ່ມຕົ້ນ).
- *Order window frames*: 3 ມື້ເຮັດວຽກ, ບໍ່ມີໜ້າວຽກກ່ອນໜ້າ, ຕາມແຜນຈາກວັນຈັນ 7 ມິຖຸນາ.
- *Fit roof*: 2 ມື້ເຮັດວຽກ, ຫຼັງ *Lay walls* ແລະ ຫຼັງ *Order window frames*. ການສິ້ນສຸດຂອງໜ້າວຽກນີ້ແມ່ນການສົ່ງມອບ.

ຕົວເລກເຫຼົ່ານີ້ຖືກຄິດໄລ່ດ້ວຍເຄື່ອງຈັກຄິດໄລ່ຂອງແອັບ. ທ່ານອ່ານມັນໄດ້ໃນແຜງ *ຄຸນສົມບັດ* ພາຍໃຕ້ *ຜົນການຄິດໄລ່ CPM*.

**ຖ້າບໍ່ມີວັນທີສະຖານະ ແລະ ບໍ່ມີຄວາມຄືບໜ້າ, ທັງສາມໂປຣໄຟລ໌ຄິດໄລ່ເຄືອຂ່າຍນີ້ຄືກັນ.** *Pour foundation* ດຳເນີນຈາກວັນຈັນ 7 ຫາວັນສຸກ 11 ມິຖຸນາ, *Lay walls* ຈາກວັນຈັນ 14 ຫາວັນສຸກ 18 ມິຖຸນາ ແລະ *Fit roof* ວັນຈັນ 21 ແລະ ວັນອັງຄານ 22 ມິຖຸນາ. ການສົ່ງມອບແມ່ນວັນອັງຄານ 22 ມິຖຸນາ. *Order window frames* (ວັນຈັນ 7 ຫາວັນພຸດ 9 ມິຖຸນາ) ມີໄລຍະຜ່ອນຜັນລວມ 7 ມື້ເຮັດວຽກ.

ທຸກຢ່າງເໝືອນກັບໃນ Open Planner Studio, ຍົກເວັ້ນຈຸດໜຶ່ງ: ເລີ່ມຕົ້ນໄວສຸດຂອງ *Pour foundation* ແມ່ນວັນພຸດ 9 ມິຖຸນາ. ນັ້ນແມ່ນຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ, ບໍ່ແມ່ນວັນເລີ່ມຕົວຈິງ. ນີ້ເຮັດໄດ້ດ້ວຍຂໍ້ກຳນົດ *ໜ້າວຽກທີ່ພວມດຳເນີນການ: early start = ຈຸດເລີ່ມຕົ້ນຂອງວຽກທີ່ເຫຼືອ*, ໃນກຸ່ມ *ຄວາມຄືບໜ້າ ແລະ ວຽກທີ່ສຳເລັດ*. ວັນສິ້ນສຸດ ແລະ float ບໍ່ປ່ຽນເພາະເລື່ອງນີ້. ການສົ່ງມອບແມ່ນວັນຈັນ 21 ມິຖຸນາ.

### Microsoft Project

ທີ່ນີ້ວັນທີແຕກຕ່າງກັນ. ຂໍ້ກຳນົດສອງອັນໃນກຸ່ມ *ຄວາມຄືບໜ້າແບບ Microsoft Project* ເປັນສາເຫດ.

*ບໍ່ຍ້າຍໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມໄປທີ່ວັນທີສະຖານະ*: *Order window frames* ຢູ່ຄືເກົ່າ ຈາກວັນຈັນ 7 ຫາວັນພຸດ 9 ມິຖຸນາ, ເຖິງແມ່ນວ່າສ່ວນໜຶ່ງຂອງມັນຢູ່ກ່ອນວັນທີສະຖານະ. ໄລຍະຜ່ອນຜັນລວມແມ່ນ 7 ມື້ເຮັດວຽກ.

*ວຽກທີ່ເຫຼືອເລີ່ມຕໍ່ຫຼັງຈາກໄລຍະເວລາທີ່ຜ່ານໄປ*: ວຽກທີ່ເຫຼືອເລີ່ມບໍ່ກ່ອນວັນທີສະຖານະ, ແລະ ບໍ່ກ່ອນວັນເລີ່ມຕົວຈິງບວກກັບເວລາລ່ວງເລີຍແລ້ວ. ທີ່ 60 % ຂອງ 5 ມື້ເຮັດວຽກ, 3 ມື້ເຮັດວຽກແມ່ນສຳເລັດແລ້ວ. ວັນຈັນ 7 ມິຖຸນາບວກ 3 ມື້ເຮັດວຽກແມ່ນວັນພະຫັດ 10 ມິຖຸນາ. ນັ້ນຢູ່ຫຼັງວັນທີສະຖານະ, ດັ່ງນັ້ນວຽກທີ່ເຫຼືອດຳເນີນວັນພະຫັດ 10 ແລະ ວັນສຸກ 11 ມິຖຸນາ. *Lay walls* ດຳເນີນຈາກວັນຈັນ 14 ຫາວັນສຸກ 18 ມິຖຸນາ ແລະ *Fit roof* ວັນຈັນ 21 ແລະ ວັນອັງຄານ 22 ມິຖຸນາ. ການສົ່ງມອບແມ່ນວັນອັງຄານ 22 ມິຖຸນາ: ຊ້າກວ່າໂປຣໄຟລ໌ອີກສອງອັນໜຶ່ງມື້ເຮັດວຽກ.

### ຖ້າຈະເປັນແນວໃດ

**ຮາກຖານຢູ່ທີ່ 20 % ແທນ 60 %.** ວຽກທີ່ເຫຼືອແມ່ນ 4 ມື້ເຮັດວຽກ. ພາຍໃຕ້ທັງສາມໂປຣໄຟລ໌, ຮາກຖານສິ້ນສຸດວັນຈັນ 14 ມິຖຸນາ ແລະ ການສົ່ງມອບແມ່ນວັນພຸດ 23 ມິຖຸນາ. ຂໍ້ກຳນົດ Microsoft Project ສຳລັບວຽກທີ່ເຫຼືອບໍ່ສ້າງຄວາມແຕກຕ່າງທີ່ນີ້: ວັນຈັນ 7 ມິຖຸນາບວກ 1 ມື້ເຮັດວຽກທີ່ລ່ວງເລີຍແລ້ວ ແມ່ນວັນອັງຄານ 8 ມິຖຸນາ, ແລະ ນັ້ນກ່ອນວັນທີສະຖານະ. ຂໍ້ກຳນົດແບບນີ້ເປັນຂອບເຂດຕ່ຳສຸດ ທີ່ເຮັດໃຫ້ວຽກທີ່ເຫຼືອຊ້າລົງໄດ້ເທົ່ານັ້ນ. *Order window frames* ແລະ ການເລີ່ມຕົ້ນໄວສຸດພາຍໃຕ້ Primavera P6 ຍັງຕ່າງກັນ, ດັ່ງທີ່ກ່າວຂ້າງເທິງ. ພາຍໃຕ້ Microsoft Project, *Order window frames* ຈະມີໄລຍະຜ່ອນຜັນລວມ 8 ມື້ເຮັດວຽກ.

**ທ່ານຕັ້ງວັນທີສະຖານະເທົ່ານັ້ນ ແລະ ບໍ່ໃສ່ຄວາມຄືບໜ້າ.** ພາຍໃຕ້ Open Planner Studio ແລະ Primavera P6 ເຄືອຂ່າຍທັງໝົດຍ້າຍໄປວັນພຸດ 9 ມິຖຸນາ. ຮາກຖານຈາກນັ້ນດຳເນີນຈາກວັນພຸດ 9 ຫາວັນອັງຄານ 15 ມິຖຸນາ ແລະ ການສົ່ງມອບກາຍເປັນວັນພະຫັດ 24 ມິຖຸນາ: ຊ້າກວ່າເມື່ອບໍ່ມີວັນທີສະຖານະ ສອງມື້ເຮັດວຽກ. ພາຍໃຕ້ Microsoft Project ທຸກຢ່າງຢູ່ບ່ອນເດີມ ແລະ ການສົ່ງມອບແມ່ນວັນອັງຄານ 22 ມິຖຸນາ.

**ທ່ານສ້າງໂປຣໄຟລ໌ເອງ.** ພາຍໃຕ້ Open Planner Studio ໃຫ້ສ້າງໂປຣໄຟລ໌ດ້ວຍ *ໂປຣໄຟລ໌ໃໝ່* ຈາກ *ສຳເນົາຂອງ Open Planner Studio*, ແລ້ວເປີດພຽງຢ່າງດຽວ *ບໍ່ຍ້າຍໜ້າວຽກທີ່ຍັງບໍ່ເລີ່ມໄປທີ່ວັນທີສະຖານະ*. ດ້ວຍຄວາມຄືບໜ້າ 60 % ຮາກຖານຈະຮັກສາວັນທີຂອງ Open Planner Studio (ສິ້ນສຸດວັນພະຫັດ 10 ມິຖຸນາ, ການສົ່ງມອບວັນຈັນ 21 ມິຖຸນາ). *Order window frames* ຢູ່ຄືເກົ່າຈາກວັນຈັນ 7 ຫາວັນພຸດ 9 ມິຖຸນາ, ມີໄລຍະຜ່ອນຜັນລວມ 6 ມື້ເຮັດວຽກ. ດັ່ງນັ້ນ ໂປຣໄຟລ໌ແມ່ນຊຸດຂອງສະວິດແຍກກັນ, ແລະ ທ່ານສາມາດປ່ຽນແປງທີລະອັນໄດ້.

**ຕົວເລືອກການຄິດໄລ່ແທນຂໍ້ກຳນົດ.** ຖ້າທ່ານຕັ້ງ *ນິຍາມເສັ້ນທາງວິກິດ* (*ໄລຍະຜ່ອນຜັນລວມ ≤ ເກນກຳນົດ*) ແລະ *ເກນກຳນົດ (ມື້ເຮັດວຽກ)* ເປັນ 4 ພາຍໃຕ້ Open Planner Studio, *Order window frames* ຈະກາຍເປັນວິກິດ, ເພາະໄລຍະຜ່ອນຜັນລວມຂອງມັນເທົ່າກັບ 4 ພໍດີ. ບໍ່ມີວັນທີໃດປ່ຽນ. ຕົວເລືອກການຄິດໄລ່ແມ່ນທາງເລືອກຂອງທ່ານສຳລັບໂຄງການ ແລະ ເປັນເອກະລາດຈາກໂປຣໄຟລ໌.

**ກຳນົດສົ່ງທີ່ຖືກພາດ.** ໃຫ້ *Fit roof* ມີກຳນົດສົ່ງວັນສຸກ 18 ມິຖຸນາ. ພາຍໃຕ້ Open Planner Studio ໄລຍະຜ່ອນຜັນລວມຂອງ *Fit roof* ແມ່ນ −1 ມື້ເຮັດວຽກ ແລະ free float ແມ່ນ −1 ເຊັ່ນກັນ. ພາຍໃຕ້ Primavera P6 ໄລຍະຜ່ອນຜັນລວມຍັງຄົງ −1, ແຕ່ free float ກາຍເປັນ 0. ນັ້ນແມ່ນສິ່ງທີ່ຂໍ້ກຳນົດ *Free float ບໍ່ຕິດລົບ* ເຮັດ, ໃນກຸ່ມ *Float ແລະ ວັນທີ late*. ພາຍໃຕ້ Microsoft Project ທັງສອງເປັນ −2, ເພາະການສົ່ງມອບຕົກຢູ່ຊ້າກວ່າໜຶ່ງມື້ເຮັດວຽກຢູ່ທີ່ນັ້ນ. ວິທີການເຮັດວຽກຂອງກຳນົດສົ່ງຢູ່ໃນ [ເງື່ອນໄຂ ແລະ ກຳນົດສົ່ງ](docs://uitleg-constraints).

## ຜົນທີ່ຕາມມາ ແລະ ຄວາມເຂົ້າໃຈຜິດ

**“ໂປຣໄຟລ໌ເປັນການຕັ້ງຄ່າຂອງແອັບ.”** ບໍ່ແມ່ນ. ໂປຣໄຟລ໌ ແລະ ຕົວເລືອກການຄິດໄລ່ ເປັນຂອງໂຄງການ ແລະ ຖືກບັນທຶກໄປພ້ອມກັບໄຟລ໌. ມີແຕ່ແມ່ແບບທີ່ທ່ານເກັບໄວ້ເທົ່ານັ້ນທີ່ເປັນຂອງແອັບ. ໂຄງການຈະເກັບສຳເນົາຂອງຕົນເອງສະເໝີ.

**“ຖ້າຂ້ານ້ອຍສົ່ງອອກ, ໂປຣໄຟລ໌ຂອງຂ້ານ້ອຍກໍຈະໄປນຳ.”** ມີພຽງແຕ່ກັບຮູບແບບໂຄງການຂອງທ່ານເອງ (.ifc) ເທົ່ານັ້ນ. ຖ້າທ່ານສົ່ງອອກເປັນ *MS Project XML*, *Primavera P6 XML* ຫຼື *CSV (ຂັ້ນດ້ວຍຈໍ້າຈຸດ ;)*, ໂປຣໄຟລ໌ຈະບໍ່ຢູ່ໃນໄຟລ໌. ໃນຕົວເລືອກການຄິດໄລ່, ການສົ່ງອອກ MS Project XML ຂຽນໄດ້ຢ່າງຫຼາຍແຕ່ເກນກຳນົດວິກິດເທົ່ານັ້ນ. ແອັບຈະເຕືອນກ່ຽວກັບເລື່ອງນີ້ສະເພາະໂຄງການທີ່ມາຈາກໄຟລ໌ .xer. ສຳລັບໂຄງການທີ່ທ່ານສ້າງເອງ ທ່ານຈະບໍ່ໄດ້ຮັບຂໍ້ຄວາມໃດໆ. ຈາກນັ້ນໄຟລ໌ຈະເປີດເປັນ Open Planner Studio ໂດຍບໍ່ມີຂໍ້ຄວາມກ່ຽວກັບໂປຣໄຟລ໌. ໃຫ້ເບິ່ງຕົວຢ່າງນີ້: ໂປຣໄຟລ໌ Microsoft Project ແລະ ຄວາມຄືບໜ້າ 60 %. ຖ້າທ່ານສົ່ງອອກເປັນ *MS Project XML* ແລ້ວເປີດອີກຄັ້ງ, ແອັບຈະສະແດງວັນທີຈາກໄຟລ໌ກ່ອນ ໂດຍມີການສົ່ງມອບໃນວັນອັງຄານທີ 22 ມິຖຸນາ. ຖ້າທ່ານໃຫ້ແອັບຄິດໄລ່ຄືນໃໝ່ເອງ, ວັນທີນັ້ນຈະກາຍເປັນວັນຈັນທີ 21 ມິຖຸນາ. ສິ່ງອື່ນທີ່ການສົ່ງອອກເຮັດໃຫ້ຫາຍໄປ ຢູ່ໃນ [ໄຟລ໌ ແລະ ຮູບແບບ](docs://uitleg-bestanden).

**“ໂປຣໄຟລ໌ Primavera P6 ໃຫ້ຜົນດຽວກັນກັບ P6.”** ແອັບບໍ່ສາມາດຮັບປະກັນເລື່ອງນັ້ນໄດ້. ໂປຣໄຟລ໌ເປີດໃຊ້ຂໍ້ກຳນົດທີ່ແອັບຮູ້ຈັກຈາກ P6, ແຕ່ຂໍ້ກຳນົດເຫຼົ່ານັ້ນບໍ່ແມ່ນການຕັ້ງຄ່າທັງໝົດຂອງ P6. ນອກຈາກ Retained Logic ແລະ Progress Override, P6 ມີຮູບແບບຄວາມຄືບໜ້າທີ່ສາມ ຄື Actual Dates. ແອັບບໍ່ຮູ້ຈັກຮູບແບບນີ້. ໄຟລ໌ .xer ແບບນັ້ນຈະຄິດໄລ່ເປັນ Retained Logic, ແລະ ຂໍ້ຄວາມເປີດຈະແຈ້ງເລື່ອງນັ້ນ, ເຊັ່ນ *ການຕັ້ງຄ່າຕາຕະລາງ P6 ໃຊ້ຄ່າສຳຮອງທີ່ປອດໄພ 1 ລາຍການ.* ຂໍ້ກຳນົດບາງອັນຂອງໂປຣໄຟລ໌ Primavera P6 ກໍ່ໃຊ້ໄດ້ພຽງໜ້າວຽກທີ່ມາຈາກໄຟລ໌ .xer ເທົ່ານັ້ນ, ເຊັ່ນ *LOE ທີ່ຍັງບໍ່ເລີ່ມໃຊ້ຊ່ວງເວລາເປົ້າໝາຍ* ແລະ *ຄົງວັນທີຕົວຈິງໄວ້ຢ່າງຊັດເຈນ*. ສຳລັບບາງອັນ ຄຳອະທິບາຍຈະບອກເລື່ອງນີ້: “ພຽງໜ້າວຽກທີ່ມີແຫຼ່ງທີ່ມາຈາກ P6”. ສຳລັບໜ້າວຽກທີ່ທ່ານສ້າງເອງ ຂໍ້ກຳນົດເຫຼົ່ານັ້ນຈະບໍ່ເຮັດຫຍັງເລີຍ.

**“ຮູບແບບຄວາມຄືບໜ້າເປັນສ່ວນໜຶ່ງຂອງໂປຣໄຟລ໌.”** ບໍ່ແມ່ນ. Retained Logic ຫຼື Progress Override ເປັນທາງເລືອກແຍກຕ່າງຫາກສຳລັບແຕ່ລະໂຄງການ. ທ່ານຕັ້ງມັນແຍກຈາກໂປຣໄຟລ໌, ເບິ່ງ [ການເລືອກຮູບແບບຄວາມຄືບໜ້າ](docs://howto-voortgangsmodus-kiezen). ຂໍ້ກຳນົດໜຶ່ງຂອງ Primavera P6, *Progress Override ຈະລະເລີຍໜ້າວຽກຖັດໄປທີ່ເລີ່ມແລ້ວໃນຝັ່ງ late ນຳ*, ເຮັດວຽກພຽງແຕ່ພາຍໃຕ້ Progress Override ເທົ່ານັ້ນ.

**“ຂ້ານ້ອຍພຽງແຕ່ປ່ຽນໂປຣໄຟລ໌ເພື່ອເບິ່ງວ່າຈະເກີດຫຍັງຂຶ້ນ.”** ທ່ານເຮັດໄດ້, ເພາະ *ນຳໃຊ້* ເປັນຂັ້ນຕອນດຽວສຳລັບ *ຍົກເລີກຄຳສັ່ງ*: ໂປຣໄຟລ໌ ແລະ ວັນທີ ຈະກັບຄືນພ້ອມກັນ. ແຕ່ວັນທີສາມາດຍ້າຍຈິງໆ. ໃນຕົວຢ່າງ, ການປ່ຽນຈາກ Open Planner Studio ໄປເປັນ Microsoft Project ຍ້າຍທຸກໜ້າວຽກ 4 ໜ້າວຽກ. ຂໍ້ຄວາມນັບຈຳນວນໃຫ້ທ່ານ. ໃຫ້ເບິ່ງແຜນງານຫຼັງຈາກນັ້ນ ກ່ອນທ່ານຈະດຳເນີນຕໍ່. ຖ້າແອັບຍັງສະແດງວັນທີຈາກໄຟລ໌ ຫຼັງເປີດໄຟລ໌ .xer ຫຼື .mpp, ການປ່ຽນໂປຣໄຟລ໌ຈະອອກຈາກມຸມມອງນັ້ນ ແລະ ແອັບຈະຄິດໄລ່ເອງ. ວິທີການເຮັດວຽກນີ້ຢູ່ໃນ [ວັນທີຕາມທີ່ບັນທຶກໄວ້](docs://uitleg-datums-zoals-opgeslagen).

**ຕົວຢ່າງສະແດງສີ່ຂໍ້ກຳນົດ ແລະ ລາຍການໃນແອັບຍາວກວ່ານັ້ນ.** ແຕ່ລະແຖວໃນສ່ວນນັ້ນມີຄຳອະທິບາຍຂອງຕົນເອງ. ກະລຸນາອ່ານມັນກ່ອນ. ໃຫ້ເບິ່ງກຸ່ມ *ສະເພາະໂປຣໄຟລ໌ກຳນົດເອງ* ນຳ: ຂໍ້ກຳນົດເຫຼົ່ານັ້ນປິດຢູ່ໃນທຸກໂປຣໄຟລ໌ທີ່ມາພ້ອມ, ລວມທັງ Primavera P6. ມີແຕ່ໂປຣໄຟລ໌ກຳນົດເອງເທົ່ານັ້ນທີ່ເປີດໃຊ້ໄດ້: ສ້າງດ້ວຍ *ໂປຣໄຟລ໌ໃໝ່*.
