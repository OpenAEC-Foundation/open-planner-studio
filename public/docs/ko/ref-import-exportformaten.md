# 가져오기 및 내보내기 형식

파일 형식별로 설명합니다. 파일을 열거나, 저장하거나, 내보낼 수 있는지 확인하세요. 무엇이 함께 넘어가고 무엇이 넘어가지 않는지도 설명합니다. 또한 파일을 열 때 쓰는 계산 프로필도 설명합니다. 이 모든 이유와 숫자 예시는 [파일과 형식](docs://uitleg-bestanden)에 있습니다.

## 한눈에 보기

**열기**는 IFC, CSV, MS Project XML, Primavera P6 XML, `.mpp`, `.xer` 형식을 지원합니다. 다른 확장자의 파일은 앱이 IFC로 처리합니다.

**저장**은 항상 IFC 파일로 씁니다. 열린 IFC 파일만 저장 대상이 됩니다. 다른 형식에서 연 프로젝트는 열린 뒤 파일이 없습니다. 그런 경우 *저장*을 누르면 앱이 IFC 파일을 어디에 저장할지 묻습니다.

**내보내기**는 IFC, MS Project XML, Primavera P6 XML, CSV, 진행률 시트 두 가지(Excel과 CSV)로 가능합니다. 내보내도 프로젝트는 바뀌지 않습니다.

**읽기 전용**은 `.mpp`와 `.xer` 파일입니다. 앱은 이 파일을 열 수는 있지만 쓸 수는 없습니다.

**PDF**는 보고서에서만 나옵니다([보고서 유형](docs://ref-rapporttypes) 참조). 앱은 PDF를 읽지 않습니다.

**위치.** 열기: *홈 › 파일 › 열기*, *파일 › 열기* 또는 Ctrl+O. 내보내기: *홈 › 파일 › 내보내기* 또는 *파일 › 내보내기*. 채워진 진행률 시트는 *파일 › 가져오기*로 읽어 들이거나, *계획*, *테이블*, *보고서* 탭의 리본 그룹 *진행률*에 있는 버튼 *시트에서 진행률 업데이트*로 읽어 들입니다.

**열 때의 계산 프로필.** 모든 형식은 계산 프로필과 함께 열립니다. 계산 프로필이 무엇인지는 [계산 옵션과 규칙](docs://ref-rekenopties-en-conventies)에 있습니다. `.xer`은 *Primavera P6*으로, `.mpp`는 *Microsoft Project*으로 열립니다. CSV, MS Project XML, P6 XML은 *Open Planner Studio*로 열립니다. IFC는 파일에 저장된 프로필을 유지합니다. `.xer`과 `.mpp`의 경우 앱은 프로젝트가 이 방식으로 계산된다고 알려 줍니다. 계산 프로필과 계산 옵션을 담는 것은 IFC뿐입니다. 계산 옵션 중에서 MS Project XML은 주공정 임계값까지만 기록합니다. 다른 형식으로 내보낸 파일을 다시 열면 *Open Planner Studio*로 계산됩니다.

## IFC

**열기** — 예, `.ifc`. 앱은 IFC4와 IFC 4.3을 읽습니다(ADD2도 포함). IFC2X3 같은 다른 스키마의 파일도 열립니다. 처음 저장할 때 앱이 쓸 수 있는 스키마를 직접 고르세요([IFC 스키마 선택](docs://howto-ifc-schema-kiezen) 참조). 계산 프로필: 파일에 있는 프로필.

**저장** — 예. 저장할 수 있는 형식은 이것뿐입니다. *저장*은 프로젝트 전체를 IFC 파일로 씁니다. 스키마는 프로젝트의 IFC 스키마이며 기본은 IFC 4.3 ADD2입니다. 이 파일이 저장 대상이 됩니다.

**내보내기** — 예, *IFC*로 내보낼 수 있습니다. 프로젝트의 IFC 스키마로 내보내며, 기본은 IFC 4.3 ADD2입니다. 기본 이름은 프로젝트 이름에 확장자 `.ifc`를 붙인 이름입니다. 프로젝트가 리소스 라이브러리에 연결되어 있으면 *파일 › 내보내기*의 카드 아래에 체크 상자 *라이브러리 파일도 함께 저장*이 있습니다. 선택하면 앱은 프로젝트 다음에 *projectname-bibliotheek.ifc*의 저장 위치를 묻습니다. 이 체크 상자는 *홈* 탭의 목록에 없습니다.

**함께 넘어가는 것** — 프로젝트에 속한 모든 것입니다. 구조, 기간, 날짜, 진행률이 있는 작업. 지연이 있는 관계. 제약 조건과 기한. 달력. 시간 분배를 포함한 리소스와 할당. 기준선. 활동 코드와 사용자 지정 필드. 메모. 다른 프로젝트로의 외부 관계. 중단. 작업 유형과 사용자 지정 공종. 상태 날짜, 진행 모드, 계산 프로필, 계산 옵션 같은 프로젝트 설정. 리소스 라이브러리와의 연결. `.xer`에서 가져온 프로젝트라면 원본 파일도 함께 넘어갑니다. 사용자 지정 공종은 IFC 유형 `USERDEFINED`로 저장되고, 이름은 ObjectType 필드에 들어갑니다. 그래서 다른 IFC 프로그램도 작업을 정상적으로 읽습니다. 앱은 또한 공종의 고정 ID를 보관하므로 이름을 바꿔도 연결이 끊어지지 않습니다. 다른 컴퓨터에서 파일을 열면 그 공종은 *이 프로젝트에서* 아래에 나타납니다. 그 사람의 *내 공종*에는 나타나지 않습니다.

**넘어가지 않는 것** — 화면 설정(확대/축소, 스크롤 위치, 선택한 작업, 접힌 단계, 선택한 필터와 그룹화)과 앱 설정([앱 설정](docs://ref-instellingen)). *IFC* 탭은 프로젝트의 IFC 텍스트를 담은 편집기입니다. *IFC 생성*은 텍스트를 다시 만들고, *복사*는 클립보드에 넣습니다. *적용*은 텍스트를 프로젝트로 읽어 들이며, 그 탭의 프로젝트를 바꿉니다.

## MS Project XML (MSPDI)

**열기** — 예. 앱은 MS Project 네임스페이스의 루트 요소 `Project`(또는 네임스페이스가 없는 경우)로 `.xml` 파일을 MS Project XML로 인식합니다. 계산 프로필: *Open Planner Studio*. 열고 나면 앱은 넘어가지 않은 항목을 한 메시지로 알려 줍니다. [MS Project 파일(.mpp) 열기](docs://howto-mpp-openen)를 참조하세요.

**저장** — 아니요. 이런 프로젝트에는 저장 대상이 없습니다.

**내보내기** — 예, *MS Project XML*로 내보낼 수 있습니다(*Microsoft Project에서 열 수 있습니다. 전체 WBS 구조*). 기본 이름은 프로젝트 이름에 `.xml`을 붙인 이름입니다.

**함께 넘어가는 것** — 구조(수준과 WBS), 기간, 날짜, 진행률이 있는 작업. 시간이나 백분율로 된 지연이 있는 관계. 기한을 포함한 제약 조건. 작업 달력과 리소스 달력을 포함한 달력. 곡선 또는 시간 분배를 포함한 리소스와 할당. 상태 날짜. 0 이상의 정수인 근무일 수로 된 주공정 임계값(*총 여유 ≤ 임계값*). 작업 설명(메모로). 작업의 작업 유형(MS Project 작업 유형으로). 자유 필드(`ExtendedAttribute`)에 담긴 사용자 지정 공종. 앱은 이 필드를 다시 읽지만, MS Project는 무시할 수 있습니다. 기준선 중에서는 활성 기준선만 기준선 0으로 넘어갑니다. 시간 단위 작업은 단위를 유지하고, 마일스톤은 종류(시작, 완료 또는 자동)를 유지합니다.

**넘어가지 않는 것** — 메모(작업의 체크리스트), 다른 프로젝트로의 외부 관계, 활동 코드와 사용자 지정 필드, 두 번째 제약 조건, *수동 일정* 표시, 평준화 지연, 순서 위반 작업의 재개 지점과 중지 지점, MS Project 프로필의 규칙 *남은 작업은 경과 기간 후에 재개*와 *시작되지 않은 작업을 상태 날짜로 옮기지 않음*, 그리고 그 밖의 계산 옵션. 시간 분배가 없는 중단된 작업은 중단 없이 넘어갑니다.

**열 때의 공휴일.** 파생 달력은 기반 달력의 예외를 물려받습니다. 자체 근무 주가 있고 예외가 없는 달력에는 공휴일이 없습니다. 기반 달력, 근무 주, 예외가 모두 없는 단순한 달력만 표준 네덜란드 공휴일을 유지합니다. 공휴일이 빠지면 완료 날짜가 달라질 수 있습니다. [공휴일과 건설 휴가 생성](docs://howto-feestdagen-genereren)을 참조하세요.

**도중에 바뀌는 것** — 옵션 *필수(고정 로직)* 없이 제약 조건 *지정일에 시작 (MSO)* 또는 *지정일에 완료 (MFO)*는 *지정일 이후 시작 (SNET)* 또는 *지정일 이후 완료 (FNET)*가 됩니다. 해먹은 계산된 날짜를 가진 일반 작업이 됩니다. MS Project XML은 하루 시간을 프로젝트 달력에만 저장합니다. 자체 하루 시간이 있는 다른 달력은 파일을 열 때 근무 시간이 하루 시간으로 바뀝니다. 예를 들어 하루 8시간 설정이 있고 근무 시간이 10시간이면 10시간이 됩니다. 그런 달력에서 일 단위 작업은 더 짧아집니다. 예를 들어 5일 대신 4일이 됩니다.

## MS Project 파일 (`.mpp`)

**열기** — 예. MS Project 2010부터 2021까지 지원합니다. 계산 프로필: *Microsoft Project*. 앱은 파일을 읽기만 합니다. `.mpp` 파일은 절대 바꾸지 않습니다. MS Project 2007 이하 파일과 암호가 걸린 파일은 앱이 열지 않습니다. 이때 앱은 MS Project의 XML 내보내기를 안내하는 메시지를 표시합니다. 열고 나면 앱은 넘어가지 않은 항목을 한 메시지로 알려 줍니다.

**저장** — 아니요. 저장 대상도 없습니다. *저장*은 새 IFC 파일을 씁니다.

**내보내기** — 아니요.

**함께 넘어가는 것** — 구조, 기간, 제약 조건이 있는 작업. 지연이 있는 관계. 달력. 리소스와 할당. 진행률. MS Project에서 직접 입력한 WBS 코드. MS Project가 직접 계산한 날짜와 여유도 읽습니다. 이 날짜와 여유는 보기 *기록된 날짜*에 표시하기 위해 함께 읽습니다.

**넘어가지 않는 것** — 기준선, 비용과 단가, 메모, 하이퍼링크, MS Project의 사용자 지정 필드, 하위 프로젝트와 외부 작업의 연결, 주공정 임계값. [MS Project 파일(.mpp) 열기](docs://howto-mpp-openen)를 참조하세요.

**출처와 라이선스** — `.mpp` 리더는 Open Planner Studio를 위해 작성되었습니다. LGPL-2.1 라이선스의 Java 라이브러리 MPXJ(`github.com/joniles/mpxj`, Jon Iles 외)의 소스 코드와 구조에 관한 지식을 바탕으로 합니다. 구조와 필드 상수는 TypeScript으로 옮겼습니다. Open Planner Studio 자체는 LGPL-3.0에 따른 오픈 소스입니다. `.xer` 리더는 파생물이 아닙니다. 거기서는 MPXJ를 이해를 위한 자료로만 참고했습니다.

## Primavera P6 XML

**열기** — 예. 앱은 루트 요소 `APIBusinessObjects`로 `.xml` 파일을 P6 XML로 인식합니다. 계산 프로필: *Open Planner Studio*.

**한 파일의 여러 프로젝트.** 작업이 있는 각 프로젝트는 자체 탭에서 열리며, 이름은 *프로젝트 이름 (프로젝트 ID)*입니다. 앱은 작업이 없는 프로젝트를 건너뜁니다. 활성 탭은 작업이 가장 많은 프로젝트입니다. 앱은 다른 프로젝트로의 관계와 어떤 프로젝트에도 속하지 않는 작업은 넘어가지 않습니다. 열고 나면 앱은 몇 개의 프로젝트를 열었는지 알려 줍니다.

**열 때의 공휴일.** MS Project XML과 같은 규칙이 적용됩니다. 자체 근무 주가 있고 예외가 없는 달력에는 공휴일이 없습니다.

**기준선.** 파일의 `<BaselineProject>`는 해당 프로젝트의 기준선이 됩니다. P6가 활성으로 표시한 기준선은 앱에서도 활성입니다.

**할당의 비율.** 남은 작업이 있으면 남은 비율(`RemainingUnitsPerTime`)이 *단위/일*이 됩니다. 그렇지 않으면 계획 비율(`PlannedUnitsPerTime`)이 됩니다. 자재의 경우 계획 비율이 그대로 남습니다. 앱은 파일을 열 때 아무것도 다시 계산하지 않습니다. P6 XML로 내보낼 때는 계획 비율을 `PlannedUnitsPerTime`으로 씁니다. 남은 비율은 할당에 별도의 계획 비율이 있을 때만 `RemainingUnitsPerTime`으로 씁니다.

**읽을 수 있는 작업이 없을 때.** 앱이 읽을 수 있는 작업을 찾지 못하면 탭을 열지 않습니다. 앱은 이를 알리며, 이유를 알 수 있으면 이유도 알려 줍니다. 예: `ObjectId`가 없는 작업, 또는 XML 파일 안의 XER 열 이름. 그럴 때는 P6에서 프로젝트를 P6 XML로 다시 내보내거나, `.xer`로 여세요.

**저장** — 아니요.

**내보내기** — 예, *Primavera P6 XML*로 내보낼 수 있습니다(*Oracle Primavera P6용*). 기본 이름은 프로젝트 이름에 `.xml`을 붙인 이름입니다. 프로젝트에 ID가 있으면 ID를 괄호 안에 넣습니다. MS Project XML 내보내기도 같은 이름을 받습니다. 직접 서로 다른 이름을 지정하세요.

**프로젝트 이름과 프로젝트 ID.** 앱은 `.xer`에서처럼 P6의 프로젝트 ID를 프로젝트 이름과 따로 보관합니다. *프로젝트 설정*에는 이름만 표시됩니다. 예: *Bid for Facility Extension*. 탭에는 *Bid for Facility Extension (OZB-05)*이 표시됩니다. 프로젝트 이름을 *Hall extension*으로 바꾸면 탭 이름은 *Hall extension (OZB-05)*이 됩니다. P6 XML로 내보내면 프로젝트 ID로 *OZB-05*를, 이름으로 *Hall extension*을 씁니다. 그래야 P6가 프로젝트를 알아봅니다. `.xer`에서 온 프로젝트는 프로젝트 ID도 함께 가져옵니다. 프로젝트를 IFC로 저장해도 프로젝트 ID는 남습니다. *New build (phase 2)*처럼 이름 자체에 있는 괄호는 이름에 그대로 남습니다. 프로젝트 ID가 없는 프로젝트는 내보낼 때 앱이 *OPS:*으로 시작하는 고유 ID를 새로 받습니다.

**함께 넘어가는 것** — WBS 구조와 기간, 날짜, 진행률이 있는 작업. 지연이 있는 관계. 제약 조건(두 번째 제약 조건도 소프트 제약 조건으로). 달력. 리소스와 할당. 상태 날짜(`DataDate`으로). 자체 필드 `OPS Custom Task Type`에 담긴 사용자 지정 공종. 앱은 이 필드를 다시 읽지만, P6는 무시할 수 있습니다.

**넘어가지 않는 것** — 기준선과 기한. 활동 코드, 사용자 지정 필드, 메모, 외부 관계. 계산 옵션. 공휴일의 이름. P6에는 휴무일마다 이름을 붙이는 기능이 없습니다. 다시 열면 공휴일은 *공휴일*, 근무 예외는 *근무 예외*라고 불립니다. 연속된 휴무일은 하나의 범위로 돌아옵니다. 앱은 P6가 허용하는 길이보다 긴 이름이나 코드를 줄입니다. 작업 이름은 120자, 작업 ID 또는 WBS 코드는 40자, WBS 또는 프로젝트 이름은 100자까지입니다. 앱은 줄인 이름과 코드의 개수를 알려 줍니다. P6에는 백분율 지연이 없습니다. 앱은 이를 고정된 일수로 바꿉니다. 달력 일 기준 지연은 근무 시간 기준 지연이 됩니다. 예: 달력 3일은 근무일 3일이 됩니다. 해먹은 일반 작업이 되고, 수동 일정 작업은 계산된 날짜를 가진 일반 작업이 됩니다. 하루보다 짧은 평준화 지연은 버려집니다.

## Primavera 파일 (`.xer`)

**열기** — 예. 계산 프로필: *Primavera P6*. 앱은 파일을 읽기만 합니다. `.xer`을 쓰지 않으며 파일을 절대 변경하지 않습니다. 작업이 있는 프로젝트마다 탭을 하나씩 엽니다. 작업이 없거나 테이블이 손상된 파일은 열지 않고 메시지를 표시합니다.

**저장** — 아니요. 저장 대상도 없습니다. *저장*은 새 IFC 파일을 씁니다. 원본 `.xer`이 그 안에 포함됩니다.

**내보내기** — 아니요. `.xer`에서 가져온 프로젝트를 CSV, MS Project XML 또는 P6 XML로 내보내면 앱은 XER 원본 정보가 손실된다고 알립니다. 그 사이에 IFC로 저장했더라도 마찬가지입니다. IFC로 저장하면 아무것도 손실되지 않습니다.

**함께 넘어가는 것** — WBS 구조와 기간, 날짜, 제약 조건, 진행률이 있는 작업. 지연이 있는 관계. 달력. 할당이 있는 리소스. 활동 코드. 사용자 지정 필드(UDF). 메모. P6의 일정 설정. 유형이 *Level of Effort*인 작업은 해먹이 됩니다. 기준선 프로젝트는 그 프로젝트를 참조하는 프로젝트의 활성 기준선이 됩니다. 두 프로젝트 사이의 관계는 앱이 원본 데이터로 보관합니다.

**할당의 단위 비율.** 남은 작업량이 있으면 남은 비율(`remain_qty_per_hr`)이 *단위/일*이 됩니다. 그렇지 않으면 계획 비율(`target_qty_per_hr`)이 됩니다. 계획, 실제 및 남은 작업량은 파일에 있는 그대로 유지됩니다. 자재의 경우 계획 비율은 그대로 유지됩니다.

**파일에 없는 쉬는 토요일 또는 일요일.** 일부 P6 내보내기는 여러 쉬는 날이 이어진 구간 안의 주말 쉬는 날을 앞의 금요일 또는 뒤의 월요일로 옮깁니다. 달력이 토요일이나 일요일에 근무한다면, 그 날은 잘못 근무일이 됩니다. 앱이 쉬는 날이 3일 이상 이어진 구간에서 그 패턴을 발견하면, 그 주말 날을 결국 쉬는 날로 만듭니다. 달력에서 그 날은 *달력 예외 (주말 재구성)*라고 부르며, 메시지의 *달력 발견 사항: N* 줄에 집계됩니다. 주말에 근무하지 않는 달력에서는 아무것도 바뀌지 않습니다.

**종료일 없이 프로젝트 종료일까지 여유.** P6 옵션이 프로젝트 종료일까지 여유를 계산하도록 켜져 있습니까? 그런데 파일에 프로젝트 종료일이 없고 어떤 작업에도 계획 완료일이 없습니까? 그러면 앱은 *프로젝트 완료일까지 여유 계산* 옵션을 끕니다. 그다음 앱은 가장 늦은 빠른 완료에서 거꾸로 늦은 날짜를 계산합니다. 이 경우는 *안전한 대체를 사용한 P6 일정 설정: N* 줄에 집계됩니다.

**상태 날짜의 완료 작업.** 일부 파일은 완료된 작업의 실제 날짜를 기록하지 않고, 대신 상태 날짜 창을 기록합니다. *기록된 날짜* 보기에서 그런 작업은 상태 날짜 위의 좁은 막대가 됩니다. 일정을 다시 계산했을 때 막대가 다른 위치에 놓이면, 그 작업은 띠가 보여 주는 작업 수에 집계됩니다. 규칙 *상태 날짜 창 안의 완료 작업*은 그런 창을 계산합니다. 이 규칙을 사용할 때만 완료된 작업이 계산 옵션 *완료된 작업: 데이터 날짜부터 늦은 날짜*를 통해 실제 여유를 얻습니다. 이 규칙은 근사값입니다. 앱은 이 동작을 P3 출력에서만 확인했고, Primavera는 어디에서도 이를 확인하지 않습니다. 그래서 기본 제공 프로필 모두에서, *Primavera P6*에서도 이 규칙은 꺼져 있습니다. *계산 프로필 및 옵션* 영역에서 켭니다. 그러면 프로젝트는 사용자 지정 프로필을 받습니다. 자세한 내용은 [계산 옵션 및 규칙](docs://ref-rekenopties-en-conventies)을 참조하세요.

**소수점 구분 기호로 쉼표를 쓰는 숫자.** P6은 소수점 구분 기호와 천 단위 구분 기호를 테이블 `CURRTYPE`에 기록합니다. 앱은 기간, 작업량, 여유를 변환하기 전에 이 문자를 읽습니다. 그 정보가 없으면 앱은 점을 소수점 구분 기호로 사용합니다. 파일에 소수점 쉼표가 있는 숫자가 여전히 있으면 앱은 아무것도 열지 않습니다. 이렇게 하면 잘못 읽힌 숫자가 있는 일정이 절대 열리지 않습니다.

**넘어가지 않는 것** — 작업이 없는 프로젝트, 그리고 두 프로젝트 사이의 관계가 일정의 실제 관계로 넘어가는 것. [Primavera P6 파일(.xer) 열기](docs://howto-xer-openen)를 참조하세요.

## CSV

**열기** — 예. 앱은 `;`과 `,`를 구분 기호로 읽습니다. 열 머리글은 영어와 네덜란드어로 인식합니다(예: `Name` 또는 `Naam`, `Duration` 또는 `Duur`, `Predecessors` 또는 `Voorgangers`). 날짜는 *년-월-일*, *일-월-년* 또는 *일/월/년* 형식일 수 있습니다. 선행 작업은 WBS 코드, 관계 유형, 지연으로 씁니다. 예: `1.2FS+2d`. 계산 프로필: *Open Planner Studio*. 프로젝트 이름은 *CSV Import*입니다. `Task Type` 열에는 작업 유형이 아니라 공종이 들어 있습니다. 앱은 `Werksoort` 및 `Work category` 머리글도 읽습니다. 앱이 직접 쓰는 고정 코드(예: `CONSTRUCTION` 또는 `INSTALLATION`)가 아닌 `Task Type` 값은 *이 프로젝트에서* 목록의 사용자 지정 공종이 됩니다. *내 공종*에는 나타나지 않습니다. `OPS Custom Task Type ID`가 있으면 사용자 지정 공종의 ID가 유지됩니다.

**저장** — 아니요.

**내보내기** — 예. *CSV (;)*로 내보낼 수 있습니다(*범용 테이블 내보내기. 날짜 및 기간이 포함된 모든 작업.*). 카드 *CSV (세미콜론 구분)*에서 선택합니다. 파일은 세미콜론을 구분 기호로 쓰고, BOM이 포함된 UTF-8이며, 열 머리글은 영어입니다.

**함께 넘어가는 것** — 작업마다 다음 열이 들어갑니다: `OPS Task ID`, `WBS`, `Outline Level`, `Name`, `Duration (days)`, `Start`, `Finish`, `Predecessors`, `Task Type`, `OPS Custom Task Type ID`, `Status`, `Completion (%)`, `Actual Start`, `Actual Finish`, `Critical`, `Total Float` 그리고 `Description`. `Task Type` 열에는 공종이 들어 있습니다. 완료율은 정수 백분율입니다. 시간 단위 지연에는 앱 언어의 시간 기호가 붙습니다. 영어에서는 `1.2FS+2h`, 네덜란드어에서는 `1.2FS+2u`입니다. 열 때는 두 형식을 모두 읽습니다.

**넘어가지 않는 것** — 리소스, 할당, 달력, 제약 조건, 기한, 기준선 및 상태 날짜. 날짜가 *기록된 날짜* 보기에 있으면, 원본 파일에 그 값이 기록되지 않은 작업에서는 내보내기가 `Critical`과 `Total Float`를 비워 둡니다.

## 진행률 시트 (Excel 및 CSV)

**열기** — 예. *파일 › 가져오기*(*시트에서 진행률 업데이트*)로 열거나, *계획*, *테이블*, *보고서* 탭의 리본 그룹 *진행률*에 있는 같은 이름의 버튼으로 엽니다. 앱은 `.xlsx`과 `.csv`를 읽습니다. 최대 16 MB, 50,000행까지입니다. 이 기능은 프로젝트를 열지 않습니다. 열린 프로젝트의 진행률을 업데이트합니다. 자세한 내용은 [시트에서 진행률 가져오기](docs://howto-voortgang-importeren)를 참조하세요.

**저장** — 아니요.

**내보내기** — 예, *진행률 시트(Excel)*(목록에서는 *진행률(Excel)*)와 *진행률 시트(CSV)*(목록에서는 *진행률(CSV)*)로 내보낼 수 있습니다. 기본 이름은 *projectname-voortgang*입니다. 같은 리본 그룹의 버튼 *진행률 시트 내보내기*를 누르면 Excel 시트가 한 번에 만들어집니다. Excel 시트는 열 너비가 고정되어 있고, 필드가 잠겨 있으며, 날짜를 검사합니다. CSV 시트는 같은 내용의 일반 텍스트입니다.

**함께 넘어가는 것** — 열 `OPS Task ID`, `WBS`, `Name`, `Start`, `Finish`, `Completion (%)`, `Actual Start`, `Actual Finish`. 읽어 들일 때 앱은 `Completion (%)`, `Actual Start`, `Actual Finish`를 사용합니다. `Start`와 `Finish`는 날짜 표기를 인식하는 데만 쓰이며 일정을 바꾸지 않습니다. 앱은 행을 `OPS Task ID`로 작업에 연결합니다. 그 값이 없으면 고유한 WBS 코드로 연결합니다.

**넘어가지 않는 것** — 이 열 밖의 모든 것: 기간, 관계, 리소스, 일정의 나머지 부분. 요약 작업은 시트에서 진행률을 받지 않습니다.

## PDF

**열기** — 아니요.

**저장** — 아니요.

**내보내기** — 예, 보고서에서 내보냅니다. *보고서* 탭의 버튼 *PDF 내보내기*를 사용합니다. 앱은 보고서를 프린터로 직접 보내지 않습니다. 종이로 출력하려면 PDF를 거칩니다. 내용은 보고서 유형에 따라 다릅니다. 자세한 내용은 [보고서 유형](docs://ref-rapporttypes)과 [보고서 만들기와 출력](docs://howto-rapport-maken-en-afdrukken)을 참조하세요.
