# MCP 클라이언트 연결

목표: MCP 클라이언트가 일정을 함께 읽고 다루도록 하는 것입니다. 클라이언트가 무엇을 하는지 확인할 수 있으며, 사용자가 직접 정한 한도가 적용됩니다.

## 빠른 방법: Claude에게 맡기기

Claude Desktop 또는 Claude Code를 사용하십니까? 그렇다면 Claude가 연결을 직접 설치할 수 있습니다:

1. 아래의 *프롬프트 복사*를 클릭합니다.
2. 프롬프트를 Claude와의 새 채팅에 붙여 넣고 보내세요.

그런 다음 Claude가 Open Planner Studio용 확장 프로그램을 설치하고, 진행하면서 무엇을 하는지 설명합니다. 직접 해야 할 일이 있으면, 예를 들어 Claude Desktop에서 *설치*를 클릭하는 일이라면, Claude가 정확히 어느 클릭인지 알려 줍니다. 이 과정에는 토큰이 필요하지 않습니다.

```prompt
저를 위해 Open Planner Studio 확장 프로그램을 설치해 주세요. 그래야 제 건설 일정을 Open Planner Studio에서 읽고 변경할 수 있습니다. 가능한 한 많은 것을 직접 하세요. 각 단계 전에, 무엇을 할지와 왜 하는지를 쉬운 문장 한 개로 말해 주세요. 제 도움이 필요하면 한 번에 한 가지만 물어보고, 제 답을 기다리세요. 제가 직접 해야 하는 일이 있으면, 정확히 어떤 클릭 한 번이나 동작인지, 그리고 어디에서 하는지 알려 주세요.

알아야 할 사항:
- 확장 프로그램은 파일 한 개입니다. 이름은 open-planner-studio-<version>.mcpb이며, 최신 릴리스에 있습니다: https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest. 직접 링크는 https://api.github.com/repos/OpenAEC-Foundation/open-planner-studio/releases/latest 의 응답에 있습니다(이름이 .mcpb로 끝나는 파일). 이 파일은 ZIP 파일입니다.
- 확장 프로그램은 Open Planner Studio 데스크톱 앱과 함께 작동하며, 앱 없이도 작동합니다. 앱이 열려 있고 MCP 브리지가 실행 중이면, 앱에 열린 일정을 다룹니다. 앱이 닫혀 있으면, 제가 고른 작업 폴더의 일정 파일을 다룹니다.
- 설치에는 토큰도 비밀번호도 필요하지 않습니다. 저에게 토큰이나 비밀번호를 요구하지 마세요. 이를 읽거나 보여 주지도 마세요.

Claude Desktop에서 실행하는 경우:
1. 파일을 내려받아 제 컴퓨터에서 열 수 있으면, .mcpb 파일로 그렇게 하세요. 그럴 수 없으면, 직접 내려받기 링크를 저에게 주고, 내려받기가 끝나면 파일을 두 번 클릭하라고 알려 주세요.
2. 그러면 Claude Desktop에 확장 프로그램 Open Planner Studio가 나타납니다. 저에게 설치를 클릭하라고 알려 주세요. 그다음 작업 폴더에서 제 일정 파일이 든 폴더를 고르라고 알려 주세요.
3. 새 채팅을 시작해서 Claude에게 어떤 Open Planner Studio 도구가 보이는지 물어보라고 저에게 알려 주세요.

Claude Code에서 실행하는 경우:
1. Node.js 22 이상이 설치되어 있는지 확인하세요. 설치되어 있지 않으면, 설치 방법을 저에게 알려 주고 멈추세요.
2. 제 일정 파일이 들어 있는 폴더가 어디인지 저에게 물어보세요. 그 폴더가 작업 폴더입니다.
3. .mcpb 파일을 내려받아, 제 사용자 폴더 안의 새 전용 폴더에 압축을 푸세요. 그곳에서 manifest.json 파일을 읽으세요. server.mcp_config 항목에 서버가 시작하는 방법이 나와 있습니다. ${__dirname} 자리에는 압축을 푼 폴더를, ${user_config.workdir} 자리에는 작업 폴더를 넣으세요.
4. claude mcp list 명령을 실행하세요. open-planner-studio 이름의 서버가 이미 있으면, 그 서버를 바꿔도 되는지 저에게 물어보세요. 설정에는 토큰이 들어 있을 수 있으니 설정을 보여 주지 마세요.
5. 제 사용자 계정에 서버를 추가하세요. 예를 들면: claude mcp add open-planner-studio --scope user -e OPS_MCP_ROOT=<working folder> -- node <unpacked folder>/server/index.mjs
6. 새 Claude Code 세션을 시작하라고 저에게 알려 주세요. 그 세션의 /mcp 명령이 open-planner-studio 서버의 연결 여부를 보여 준다고도 알려 주세요.

다른 곳에서 실행하는 경우, 예를 들어 브라우저에서 쓰는 claude.ai 같은 곳이라면, 이 방법에는 Claude Desktop 또는 Claude Code가 필요하다고 저에게 알려 주세요. 어디에서 실행하는지 모르면 저에게 물어보세요.

설치가 끝나면 몇 문장으로 다음을 설명하세요:
- 열린 앱에서 Claude가 일정을 다루도록 허용하는 방법: Open Planner Studio에서 설정 › 프로젝트 › 앱 설정을 선택하고, 고급 탭에서 MCP 연결 허용을 켜세요. 그다음 MCP 탭에서 브리지 시작을 클릭하세요.
- 앱 없이는 변경 내용이 저장한 뒤에야 파일에 반영된다는 점, 그리고 앱이 열려 있는 동안에는 Claude가 기존 파일을 덮어쓰지 않는다는 점.
단계가 실패하면, 무엇이 잘못되었고 제가 무엇을 할 수 있는지 한 문장으로 알려 주세요. 추측하지 마세요.
```

직접 하기를 원하십니까, 아니면 다른 MCP 클라이언트를 사용하십니까? 그렇다면 아래 단계를 따르세요.

## 이 방법이 필요한 경우

사용자가 MCP 클라이언트에게 일정을 읽거나, 분석하거나, 변경하도록 하려는 경우입니다. 예를 들어 첫 WBS 초안을 작성하게 하거나, 작업을 바로잡거나, 주공정 경로를 설명하게 하는 경우입니다. 이는 **Model Context Protocol** (MCP)를 통해 이루어집니다. 이 표준은 AI 프로그램인 **MCP 클라이언트**가 다른 프로그램의 도구를 사용하도록 합니다. 이를 위해 Open Planner Studio는 사용자의 컴퓨터에서 작은 서버를 실행합니다. 그 서버가 **브리지**입니다. 서버는 도구 한 묶음을 제공하며, 도구 이름은 모두 `planner_`로 시작합니다. 도구로 작업과 관계, 리소스, 달력, 기준선, 문서, 파일을 읽고 변경합니다. 어떤 도구가 있고 무엇을 허용하지 않는지는 [MCP 도구](docs://ref-ai-tools)에 나와 있습니다. MCP 클라이언트는 사용자가 열어 둔 프로젝트에서 작동하며, 복사본에서 작동하지 않습니다. 클라이언트가 추가한 작업은 Gantt에 바로 나타납니다. 클라이언트는 사용자와 같은 계산과 같은 *실행 취소* 기록을 사용합니다.

브리지는 데스크톱 앱에서만 작동합니다. 브라우저에서 MCP 연결을 허용하면 *MCP* 탭이 보이지만, *브리지 시작* 버튼은 회색으로 표시되고 *브리지는 데스크톱 앱에서만 작동합니다*라는 텍스트가 함께 나옵니다. 이 문서의 나머지 부분은 데스크톱 앱에 관한 내용입니다. 브라우저에서는 *지금 백업*과 *백업 폴더 열기*도 회색으로 표시됩니다.

## 단계

### 1. MCP 연결 허용

1. *설정 › 프로젝트 › 앱 설정*을 선택합니다. *파일 › 앱 설정*을 선택할 수도 있고, 상단의 톱니바퀴 아이콘을 선택할 수도 있습니다.
2. *고급* 탭을 선택하고 *MCP 연결 허용*을 켭니다. 리본에 *MCP* 탭이 나타납니다.
3. 앱이 시작되자마자 브리지가 실행 중이기를 원하면 *브리지 자동 시작*도 켭니다. 이 설정은 MCP 연결이 켜져 있을 때에만 적용되며, 데스크톱 앱에서만 작동합니다. 포트를 여는 일은 의도적인 선택이므로 기본값은 꺼짐입니다.

MCP 연결을 끄면 브리지가 중지되고 *MCP* 탭이 사라집니다.

### 2. 브리지 시작

1. *MCP* 탭으로 이동하여 *서버* 아래의 *브리지 시작*을 선택합니다.
2. 버튼 옆의 상태를 확인합니다. 상태에는 *꺼짐*, *포트 3877에서 실행 중*, *포트 3877 사용 중* 또는 *오류*가 표시됩니다. 시작에 성공하면 상태에는 *포트 3877에서 실행 중*이 표시되고, 버튼 이름은 *브리지 중지*가 됩니다. *포트 3877 사용 중*이나 *오류*가 표시되면 버튼은 *브리지 시작*으로 그대로 남습니다. 주의할 점을 참고하세요.

브리지는 본인의 컴퓨터에서만, 포트 하나에서 수신합니다. 기본 포트는 3877입니다. *연결* 그룹의 *포트*에서 다른 포트를 고를 수 있지만, 이는 브리지가 중지된 동안에만 가능합니다. 연결은 본인의 컴퓨터 안에서 이루어지는 일반 HTTP입니다. 앱 자체는 아무것도 외부로 보내지 않습니다. MCP 클라이언트가 일정으로 무엇을 하는지, 예를 들어 그 제공자가 일정을 어떻게 처리하는지는 앱의 범위 밖입니다.

### 3. MCP 클라이언트 연결

1. *연결* 아래의 *연결*을 선택합니다. *연결 정보* 창이 열립니다.
2. 클라이언트에 필요한 방식을 아래에서 선택합니다.
3. 토큰은 숨겨져 있습니다. 눈 아이콘을 선택하면 토큰이 표시됩니다. 복사 버튼은 화면에서 토큰이 가려져 있어도 항상 실제 값을 복사합니다.
4. MCP 클라이언트가 도구 목록을 요청하게 합니다. 이 확인은 연결 프롬프트에도 들어 있습니다. 클라이언트에는 접두사 `planner_`가 붙은 도구가 보여야 합니다. 예상 개수는 연결 프롬프트에 있습니다.

이 창은 연결 방법을 네 가지 제공합니다:

- *Claude에게 맡기기*: 이 문서 맨 위에 있는 것과 같은 프롬프트입니다. 버튼 *프롬프트 복사*로 복사합니다. Claude Desktop과 Claude Code용입니다. 이 방법에는 토큰이 필요하지 않습니다.
- *구성 스니펫*: 클라이언트의 MCP 설정에 붙여 넣는 구성 조각입니다.
- *연결 프롬프트*: MCP 클라이언트에 붙여 넣는 텍스트입니다. 그러면 클라이언트가 스스로 연결합니다.
- *엔드포인트* 및 *인증*: 별도의 세부 정보입니다. 엔드포인트는 `http://localhost:3877/mcp`고, 전송 방식은 *스트리밍 가능 HTTP*입니다. 모든 요청에는 헤더 `Authorization: Bearer`가 필요하며, 그 뒤에 본인의 토큰을 씁니다. 클라이언트는 MCP 세션도 지원해야 합니다. 클라이언트가 연결하면 브리지는 헤더 `Mcp-Session-Id`에 세션 코드를 넣어 주고, 그 코드가 없는 이후 요청은 모두 거부합니다. Claude Code와 `mcp-remote`는 이를 스스로 처리합니다.

**앱을 업데이트한 후에는 다시 연결하세요.** 이전 버전의 앱에 이미 연결되어 있던 MCP 클라이언트는 아직 세션 코드를 보내지 않으므로, 브리지가 모든 요청을 거부합니다. 그래서 업데이트 후에 다시 연결해야 합니다. Claude Code에서는 새 세션을 시작하고, Claude Desktop은 완전히 종료한 뒤 다시 시작하세요.

**Claude Code.** 구성 스니펫은 Claude Code에 바로 맞습니다. 터미널에서 다음 명령을 입력합니다. `<token>` 대신 본인의 토큰을 넣습니다:

```
claude mcp add --transport http open-planner-studio http://localhost:3877/mcp --header "Authorization: Bearer <token>"
```

프로젝트 폴더의 파일 `.mcp.json`에 스니펫을 넣을 수도 있습니다. 그러면 이 파일을 git에 넣지 마세요. 토큰이 본인의 공정표에 대한 접근을 허용하기 때문입니다. `.mcp.json`의 서버는 Claude Code에서 처음 한 번 승인해야 합니다.

**Claude Desktop.** Claude Desktop용 확장 프로그램이 있으며, 파일은 `open-planner-studio-<version>.mcpb`입니다. Claude Desktop은 더블 클릭으로 설치합니다. 이 방법에는 Node.js가 필요하지 않습니다. 이 확장 프로그램은 앱이 있을 때와 없을 때 모두 작동합니다. 이 문서 맨 위의 프롬프트를 쓰면 더 빠릅니다. 아래는 직접 하는 단계입니다.

1. 최신 릴리스에서 `.mcpb` 파일을 내려받습니다: `https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest`.
2. 파일을 더블 클릭합니다. Claude Desktop이 열리고 확장 프로그램 *Open Planner Studio*가 표시됩니다. 이를 설치합니다. 더블 클릭이 작동하지 않으면 Claude Desktop에서 *설정 › 확장 프로그램*을 열고, 거기에서 파일을 설치합니다.
3. *Working folder* 항목에서 일정 파일이 들어 있는 폴더를 선택합니다. Claude는 앱이 닫혀 있을 때에만 이 폴더를 사용합니다. 그러면 Claude는 그 폴더 안에서만 읽고 씁니다.
4. 확장 프로그램을 켜고 새 채팅을 시작합니다. Claude에게 Open Planner Studio의 어떤 도구가 보이는지 묻습니다.

토큰이나 포트는 입력하지 않습니다. 브리지가 실행 중이면 확장 프로그램이 앱을 스스로 찾습니다. Claude가 요청할 때마다 확장 프로그램이 다시 고릅니다:

- *앱이 열려 있고 브리지가 실행 중*: Claude는 앱에 열려 있는 공정표에서 작업합니다. 각 변경 사항을 앱에서 바로 볼 수 있습니다.
- *앱이 닫혀 있거나 브리지가 꺼져 있음*: Claude는 작업 폴더의 일정 파일에서 작업합니다. 변경 사항은 Claude가 파일을 저장할 때에만 파일에 들어갑니다. 자동 저장은 없습니다. 앱이 열려 있는 동안 Claude는 기존 파일을 덮어쓰지 않고 새 이름으로 저장합니다.

앱이 Claude의 작업 중에 열리거나 닫히면, 확장 프로그램이 전환되고 Claude에게 알립니다. 그러면 Claude는 먼저 공정표를 다시 고르거나 열고, 그다음에야 무언가를 바꿉니다. Claude가 앱 없이 한 변경 중 아직 저장하지 않은 것이 남아 있으면, 확장 프로그램은 Claude가 저장할 때까지 앱 없이 계속 작업합니다. 이렇게 하면 작업이 사라지지 않습니다. 확장 프로그램이 앱에 닿을 수 없고 쓸 수 있는 작업 폴더도 없으면, Claude에게는 도구 `open_planner_studio_status`만 보이며, 무엇을 해야 하는지 알려 주는 메시지가 함께 표시됩니다.

**확장 프로그램 없이 Claude Desktop을 사용하는 경우.** 확장 프로그램을 쓸 수 없으면 외부 도구 `mcp-remote`로 Claude Desktop을 연결합니다. 구성 스니펫은 Claude Desktop에 바로 맞지 않습니다. 파일 `claude_desktop_config.json`에는 주소가 아니라 Claude Desktop이 직접 시작하는 프로그램을 적습니다. `mcp-remote`에는 Node.js가 필요합니다. Claude Desktop에서 *설정 › Developer › Edit Config*를 선택하고, 파일에 다음 내용을 넣은 뒤(본인의 토큰을 넣어서) Claude Desktop을 다시 시작합니다:

```
{
  "mcpServers": {
    "open-planner-studio": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:3877/mcp", "--header", "Authorization:${AUTH_HEADER}"],
      "env": { "AUTH_HEADER": "Bearer <token>" }
    }
  }
}
```

토큰은 `args`가 아니라 `env`에 넣습니다. 이는 의도한 것입니다. Windows에서는 Claude Desktop이 공백이 들어 있는 인수를 깨뜨리기 때문입니다. Claude의 *커스텀 커넥터*(*Customize › Connectors*)는 브리지와 함께 작동하지 않습니다. 그러면 Claude는 Anthropic 클라우드에서 연결하는데, 그 클라우드는 본인의 컴퓨터에 있는 브리지에 닿을 수 없습니다.

*연결* 그룹에는 *토큰* 필드도 있습니다. 토큰은 앱이 만들어 이 컴퓨터에 저장하는 길고 무작위인 코드입니다. 창에는 *이 토큰은 열려 있는 공정표에 대한 접근을 허용합니다. 다른 사람과 공유하지 마세요*라고 표시됩니다. *새 토큰* 아이콘을 선택하면 새 토큰이 만들어집니다. 앱은 먼저 *새 토큰을 생성하면 기존 연결이 모두 끊어집니다. 계속하시겠습니까?*라고 묻습니다. 브리지가 실행 중이면 새 토큰으로 다시 시작되고, 이전 토큰은 더 이상 작동하지 않습니다.

**확장 프로그램이 앱을 찾는 방법.** 브리지가 실행되는 동안 데스크톱 앱은 포트와 토큰을 앱 데이터 폴더의 파일 `mcp/runtime.json`에 씁니다. Claude Desktop용 확장 프로그램은 요청마다 이 파일을 읽습니다. Linux 및 macOS에서는 사용자 계정만 이 파일을 읽을 수 있습니다. Windows에서는 프로필 폴더의 기본 접근 권한이 이 파일을 보호합니다. 앱은 이를 따로 확인하지 않습니다. 브리지를 중지하거나 MCP 연결을 끄면 앱이 이 파일을 삭제합니다. 앱은 MCP 연결이 꺼져 있을 때에도 열린 파일 목록을 `mcp/open-files.json`에 보관합니다. 이 파일이 있는 동안에는 확장 프로그램과 헤드리스 MCP 서버가 기존 파일을 덮어쓰지 않습니다. 방금 연 파일이면서 아직 목록에 없는 파일도 덮어쓰지 않습니다. 새 파일은 허용됩니다. 읽기도 허용됩니다. 그러면 Claude는 디스크에 있는 버전을 보며, 본인이 아직 저장하지 않은 변경 사항은 보지 못합니다.

### 4. MCP 클라이언트의 동작 확인

1. *활동* 아래의 *활동 패널*을 선택합니다. 측면 열에 *MCP 활동* 패널이 열립니다.
2. 브리지의 모든 호출은 한 줄씩 표시되며, 가장 최근 줄이 맨 위에 있습니다. 한 줄에는 시간, 무슨 일이 있었는지, 걸린 시간, 성공 여부가 나옵니다. 줄을 선택하면 *인수* 및 *응답*이 펼쳐집니다.
3. *지우기*를 선택하면 목록이 비워집니다. 패널은 마지막 호출 500개를 보관합니다. 아직 아무 일도 없으면 패널에 *아직 MCP 활동이 없습니다. 브리지 호출이 여기에 표시됩니다*라고 나옵니다.

MCP 연결이 켜져 있으면 상태 표시줄 오른쪽 아래에 *MCP*가 적힌 점이 있습니다. 점의 색은 브리지의 상태를 보여 주며, 점을 선택하면 *MCP* 탭으로 이동합니다.

### 5. 제한 설정

*보안* 아래에는 MCP 클라이언트를 제한하는 버튼이 있습니다:

- *일시 중지*: MCP 클라이언트는 잠시 아무것도 바꿀 수 없습니다. 읽기는 계속 허용됩니다. 브리지는 활성 상태로 남습니다. 버튼은 *재개*로 바뀝니다.
- *읽기 전용*: 이 설정이 켜져 있으면 무언가를 바꾸는 모든 도구가 거부됩니다.
- *자동 백업: 켜짐*: 문서에서 MCP 클라이언트가 처음 바꾸기 전에 앱이 IFC 백업을 만듭니다. 기본값은 켜짐입니다. 버튼으로 끌 수 있으며, 그러면 *자동 백업: 꺼짐*이 표시됩니다. 이 백업은 브리지를 시작할 때마다 문서당 한 번 만들어집니다.
- *지금 백업*: 활성 문서의 백업을 바로 만듭니다. 그 뒤에는 파일 이름과 함께 *백업 생성됨:*이 표시됩니다.
- *백업 폴더 열기*: 백업이 들어 있는 폴더를 엽니다.

백업은 앱 데이터 폴더의 `ai-backups` 폴더에 있습니다. 앱은 최근 백업은 남기고, 오래된 백업은 솎아 냅니다. 정확한 방식은 [MCP 도구](docs://ref-ai-tools)에서 설명합니다.

### 6. MCP 클라이언트가 일정을 잘 세우게 하기

MCP 클라이언트는 일정 규칙을 알아야 일정을 잘 세울 수 있습니다. 다음은 직접 하는 일입니다:

1. **핵심 규칙은 따로 할 일이 없습니다.** 규칙은 연결할 때 함께 전달됩니다. 브리지는 이를 MCP 핸드셰이크의 `instructions` 필드에 담아 보냅니다. 클라이언트가 이 규칙을 시스템 프롬프트에 넣을지는 클라이언트에 따라 다릅니다.
2. **가이드를 읽게 하세요.** *연결 정보* 창의 연결 프롬프트는 MCP 클라이언트에게 도구 `planner_get_planning_guide`로 가이드를 읽도록 요청합니다. 프롬프트를 쓰지 않는다면 다음과 같이 요청하세요: *무엇이든 바꾸기 전에 먼저 planner_get_planning_guide로 일정 가이드를 읽으세요.* 직접 `https://open-planner-studio.open-aec.com/agent/planning-guide.md`에서 가이드를 읽을 수도 있습니다.
3. **선택 사항: 스킬을 설치하세요.** 이 방법은 스킬을 지원하는 MCP 클라이언트에서만 작동합니다. *goed-plannen* 및 *progress-update*의 `SKILL.md`를 MCP 클라이언트가 작업하는 프로젝트 폴더의 `.claude/skills/goed-plannen/SKILL.md` 및 `.claude/skills/progress-update/SKILL.md`에 넣으세요. 또는 모든 프로젝트에 쓰도록 `~/.claude/skills/` 아래에 넣으세요.

파일은 두 가지 방법으로 받을 수 있습니다. MCP 클라이언트에 도구 `planner_get_planning_guide`를 `part`를 `skill`로 설정하여 호출하도록 요청하세요. 응답에는 두 텍스트와 각 스킬이 들어갈 위치가 함께 들어 있습니다. 또는 `https://open-planner-studio.open-aec.com/skills/goed-plannen/SKILL.md` 및 `https://open-planner-studio.open-aec.com/skills/progress-update/SKILL.md`에서 내려받을 수도 있습니다. 앱의 이전 버전에서 온 *goed-plannen*이 아직 있으면 교체하세요. 그 예전 텍스트는 네덜란드어이며, MCP 클라이언트용 가이드 대신 도움말 문서를 가리킵니다.

MCP 클라이언트가 가이드를 실제로 읽었는지는 *활동 패널*에서 볼 수 있습니다. 그러면 그곳에 `planner_get_planning_guide` 호출이 있습니다. 클라이언트의 최종 답변에는 가정 목록이 있어야 합니다: 예상 기간, 선택한 작업 분해, 클라이언트가 직접 만든 관계, 설정한 모든 제약 조건. 그 목록이 없으면 요청하세요. *progress-update*에 따라 진행률을 갱신한 뒤에는 답변에 상태 날짜, 새 완료 날짜, 기준선과의 차이가 나와야 합니다.

## 주의할 점과 그때 앱의 동작

**MCP 클라이언트가 바꾼 내용을 되돌리고 싶은 경우.** MCP 클라이언트가 한 변경은 각각 하나의 단계이며, *실행 취소*(Ctrl+Z)로 되돌릴 수 있습니다. MCP 클라이언트가 하나의 묶음으로 넘긴 변경들은 하나의 단계입니다. 그 뒤 프로젝트는 저장되지 않은 상태로 표시됩니다. 변경 후에는 일정이 다시 계산되므로 F5를 직접 누를 필요가 없습니다.

**앱이 MCP 클라이언트의 호출을 거부하는 경우.** *일시 중지*와 *읽기 전용*이 켜져 있으면 앱은 모든 변경을 거부합니다. 읽기는 가능하며, 오래된 일정의 다시 계산도 포함됩니다. 본인이 편집 중이라면, 예를 들어 막대를 끌거나 입력란에 입력하는 중이라면, MCP 클라이언트는 편집 전의 날짜를 받으며 그 날짜가 오래되었다는 알림도 받습니다. 설정, 작업 대화 상자, 시작 창 같은 대화 상자를 열어 두었거나 프레젠테이션 모드가 켜져 있으면, 앱은 대화 상자를 닫을 때까지 읽기를 포함한 모든 호출을 거부합니다. 그러면 MCP 클라이언트는 열려 있는 항목의 내부 이름이 들어 있는 오류 메시지를 받습니다. 예를 들어 `showTaskDialog`입니다. `planner_get_planning_guide`만 계속 작동하는데, 이 도구는 일정을 읽지 않기 때문입니다.

**MCP 클라이언트가 작업하는 동안 탭을 전환하는 경우.** MCP 클라이언트는 첫 변경이 들어간 문서에서 작업합니다. 그 사이에 탭을 전환하면, 앱은 다른 탭에서 작업하겠다는 확인을 받을 때까지 다음 변경을 거부합니다. 이렇게 하면 어떤 것도 잘못된 프로젝트에 들어가지 않습니다. MCP 클라이언트가 문서를 직접 열거나 복제하면, 그 뒤에는 새 문서에서 작업합니다.

**MCP 클라이언트가 파일을 쓰거나 여는 경우.** MCP 클라이언트는 일정을 IFC 파일로 쓸 수 있고, 일정 파일을 새 탭으로 열 수 있습니다. 이는 본인의 사용자 폴더 안에서만 할 수 있습니다. 기존 파일은 명시적으로 요청할 때에만 덮어씁니다.

**상태가 *포트 3877 사용 중*인 경우.** 다른 프로그램이 그 포트를 사용하고 있습니다. 앱의 메시지가 그 아래에 표시됩니다. 그러면 포트 입력란이 잠긴 채 남습니다(*서버가 중지된 동안에만 편집할 수 있습니다.*). 브리지가 실행 중이 아닌데도 그렇습니다. 중지 버튼도 없습니다. 이는 알려진 문제입니다. 수정되기 전까지는 *MCP 연결 허용*을 껐다가 다시 켜세요. 그러면 상태가 다시 *꺼짐*이 되고, 다른 포트를 선택할 수 있습니다. 엔드포인트에 포트가 들어 있으므로, 그다음 연결 정보를 다시 복사하세요.

**새 토큰을 만든 뒤 클라이언트가 연결할 수 없는 경우.** 새 토큰을 만들면 기존 연결이 모두 끊어집니다. 클라이언트에 새 토큰을 전달하거나 구성 스니펫을 다시 붙여 넣으세요. Claude Desktop의 확장 프로그램은 새 토큰을 스스로 읽으므로, 그곳에서 따로 할 일은 없습니다.

**브리지를 직접 중지했고 스스로 시작하지 않는 경우.** *브리지 자동 시작*은 앱을 시작할 때마다 한 번씩 작동합니다. 브리지를 직접 중지하면 앱이 이를 조용히 다시 켜지 않습니다.

**탭 *MCP*가 보이지 않는 경우.** MCP 연결이 꺼져 있습니다. 1단계에서 MCP 연결을 켜세요.

**브라우저의 웹 페이지가 브리지와 통신하지 못하는 경우.** 브리지는 브라우저에서 오는 모든 요청과 올바른 토큰이 없는 모든 요청을 거부합니다.

## 앱 없이 사용하기

데스크톱 앱 없이 작동하는 MCP 서버도 있습니다. 바로 **헤드리스 MCP 서버**입니다. 이 서버는 같은 `planner_*` 도구를 제공하지만, 열린 프로젝트 대신 디스크의 일정 파일에서 작동합니다. 따라서 변경 사항이 Gantt 차트에 표시되지 않으며, 앱의 *실행 취소*도 이 변경 사항에는 적용되지 않습니다. 앱을 열고 싶지 않거나 화면이 없는 컴퓨터에서 이 서버를 사용하세요.

Claude Desktop용 확장 프로그램은 앱이 닫혀 있으면 이 서버를 자동으로 시작합니다(3단계 참조). 아래 단계는 Claude Code 같은 다른 MCP 클라이언트를 위한 것입니다.

릴리스에는 미리 빌드된 서버 다운로드가 포함되어 있지 않습니다. 소스 코드에서 `npm run build:mcp-server` 명령으로 직접 빌드합니다. 이를 위해 Node.js 22 이상이 필요합니다. 결과물은 `server.mjs` 파일 하나입니다.

1. 일정 파일이 있는 작업 폴더를 선택합니다. 서버는 이 폴더 안에서만 읽고 씁니다.
2. MCP 클라이언트를 연결합니다. Claude Code의 경우 명령은 이 단계들 아래에 있습니다.
3. MCP 클라이언트에 일정을 열어 달라고 요청합니다(예: `~/plan.ifc`). 이 서버에서 `~`의 뜻은 작업 폴더입니다.
4. MCP 클라이언트에 결과를 저장하도록 요청합니다. 자동 저장은 없습니다. MCP 클라이언트가 `planner_export_ifc` 도구로 파일을 씁니다. 저장하지 않은 내용은 서버가 중지되면 사라집니다.

Claude Code에서 2단계를 진행하려면 본인의 경로를 넣어 터미널에 다음 명령을 입력하세요:

```
claude mcp add open-planner -- node /path/to/server.mjs --root /path/to/working-folder
```

문서마다 처음 변경하기 전에, 서버는 앱과 같이 MCP 백업을 만듭니다. 작업 폴더 밖의 경로를 선택하는 MCP 클라이언트는 거부됩니다. 바로가기(심볼릭 링크)로 선택하더라도 마찬가지입니다. 앱이 열려 있는 동안에는 서버가 기존 파일을 덮어쓰지 않습니다.
