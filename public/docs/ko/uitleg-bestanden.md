# 파일과 형식

저장한 파일에는 실제로 무엇이 들어 있습니까? 그리고 일정을 다른 패키지로 내보내면 일정에 무슨 일이 일어납니까? 이 글에서는 앱이 파일을 다루는 방법을 설명합니다. 자체 형식인 IFC, 변환기 역할을 하는 다른 형식, 내보내기에서 빠지는 내용, 그리고 저장, 자동 저장, 충돌 복구의 차이를 설명합니다. 마지막 예제는 내보내기가 무엇을 바꾸는지 숫자로 보여 줍니다.

## 개념

Open Planner Studio에는 자체 파일 형식이 하나 있습니다: **IFC**입니다. IFC는 buildingSMART가 만든 건설 정보용 개방형 교환 형식입니다. 앱은 프로젝트의 IFC 스키마를 기록하며, 기본값은 IFC 4.3 ADD2입니다([IFC 스키마 선택](docs://howto-ifc-schema-kiezen)을 참조하세요). 내보내기 목록에서는 *IFC*라고 합니다. 두 번째 독점 프로젝트 파일은 없습니다. *저장*은 프로젝트 전체를 IFC 파일(`.ifc`)로 씁니다. *열기*는 이런 파일을 다시 읽습니다. 파일에 무엇이 들어가는지 보고 싶습니까? *IFC* 탭은 프로젝트의 IFC 텍스트를 보여 주는 편집기입니다. *IFC 생성*은 이 텍스트를 새로 고치고, *복사*는 클립보드에 넣습니다. 텍스트를 바꾸면 *적용*이 그 내용을 프로젝트로 불러옵니다. 그러면 해당 탭의 프로젝트가 완전히 바뀝니다.

다른 모든 형식은 **어댑터**입니다. 어댑터는 다른 프로그램의 모델과 이 앱의 모델 사이를 옮기는 변환기입니다. 앱은 CSV, MS Project XML, Primavera P6 XML, MS Project 파일(`.mpp`), Primavera 파일(`.xer`)을 읽습니다. 앱은 CSV, MS Project XML, Primavera P6 XML과 진행 기록표 두 종을 씁니다. `.mpp`나 `.xer`로는 내보낼 수 없습니다.

이 구분이 왜 중요합니까? 변환기는 양쪽이 모두 아는 내용만 옮길 수 있습니다. 앱의 IFC 파일은 프로젝트에 속한 모든 내용을 보존합니다. 다른 형식에는 그 일부가 없으며, 그 부분은 빠집니다.

## 앱이 파일을 다루는 방법

### 열 때 일어나는 일

앱은 확장자에 따라 파일을 읽는 방법을 고릅니다: `.ifc`, `.csv`, `.xml`, `.mpp` 또는 `.xer`입니다. `.xml` 파일이면 앱은 파일 안을 살펴서 MS Project XML인지 Primavera P6 XML인지 확인합니다. 알 수 없는 확장자는 IFC로 취급합니다. 파일이 IFC가 아니면 앱은 이유와 함께 *파일을 열 수 없습니다*라고 표시합니다.

파일은 각각 자체 탭에서 열립니다. 예외는 아직 비어 있고 변경되지 않은 탭입니다. 그 탭에 파일이 열립니다. Primavera 파일 하나에서 탭이 여러 개 생길 수 있습니다. 작업이 있는 프로젝트마다 탭이 하나씩 생깁니다.

열고 나면 앱은 항상 다시 계산합니다. 파일이 다른 패키지에서 왔다면 날짜가 파일에 적힌 날짜와 다를 수 있습니다. 이 내용은 [기록된 날짜](docs://uitleg-datums-zoals-opgeslagen)에 설명되어 있습니다.

IFC 파일만 **저장 대상**이 됩니다. 저장 대상은 *저장*이 다시 쓰는 파일입니다. CSV, XML, `.mpp` 또는 `.xer` 파일은 저장 대상이 되지 않습니다. 이런 프로젝트는 열고 나서 파일이 없습니다. 그러면 *저장*은 새 IFC 파일을 어디에 만들지 묻습니다. 이렇게 하면 Ctrl+S를 눌러도 원본 파일이 IFC 텍스트로 덮어써지지 않습니다.

### 저장할 때 기록되는 내용

*저장*은 항상 프로젝트 전체를 씁니다. 다음 내용이 들어갑니다:

- 구조, 기간, 날짜, 진행률이 있는 작업;
- 지연, 제약 조건, 기한이 있는 관계;
- 곡선을 포함한 달력, 리소스, 할당;
- 기준선, 활동 코드, 사용자 지정 필드, 메모;
- 다른 프로젝트와의 외부 관계;
- 상태 날짜, 계산 프로필, 계산 옵션 같은 프로젝트 설정;
- 리소스 라이브러리와의 연결.

화면에서 설정하는 값은 프로젝트에 속하지 않으므로 함께 저장되지 않습니다. 확대/축소, 스크롤 위치, 선택한 작업, 접힌 단계가 여기에 해당합니다. 언어와 테마 같은 앱 설정도 파일에 들어가지 않습니다. 앱은 이런 설정을 앱 안에 또는 브라우저에 직접 보관합니다.

다른 형식으로 내보내도 프로젝트는 건드리지 않습니다. 내보낸 뒤에도 프로젝트의 저장 대상은 같습니다. 내보내기 전에 *저장되지 않음*으로 표시되었다면 내보낸 뒤에도 계속 그렇게 표시됩니다.

### 내보내기에서 잃는 내용

각 어댑터는 해당 형식이 아는 내용만 옮깁니다.

**MS Project XML**은 작업, 관계, 달력, 리소스, 할당, 제약 조건, 기한, 상태 날짜를 옮깁니다. 기준선 중에서는 활성 기준선 하나만 함께 옮겨집니다. 활동 코드, 사용자 지정 필드, 메모, 외부 관계는 함께 옮겨지지 않습니다. 작업의 두 번째 제약 조건도 함께 옮겨지지 않습니다. *필수(고정 로직)*을 선택하지 않은 *지정일에 시작 (MSO)* 또는 *지정일에 완료 (MFO)* 제약 조건은 *지정일 이후 시작 (SNET)* 또는 *지정일 이후 완료 (FNET)*로 돌아옵니다. *수동 일정*과 작업의 *평준화 지연*은 돌아오지 않습니다. 해먹은 계산된 날짜가 있는 일반 작업이 됩니다.

**Primavera P6 XML**은 작업, 관계, 달력, 리소스, 할당, 제약 조건, 상태 날짜를 옮깁니다. 기준선과 기한은 함께 옮겨지지 않습니다. 활동 코드, 사용자 지정 필드, 메모, 외부 관계도 마찬가지입니다. 이 형식에서도 해먹은 일반 작업이 됩니다. P6에는 백분율로 된 지연이 없습니다. 앱은 이런 지연을 고정된 일수로 바꿉니다. 달력 일 단위의 지연은 근무일 단위의 지연이 됩니다.

**CSV**는 작업 목록입니다. 파일에는 작업마다 다음 열이 있습니다: 작업 ID, WBS, 수준, 이름, 기간, 시작, 완료, 선행 작업, 공종, 사용자 지정 공종의 ID(`OPS Custom Task Type ID`), 상태, 완료율, 실제 시작과 실제 완료, 주공정, 총 여유, 설명입니다. 리소스, 할당, 달력, 제약 조건, 기한, 기준선, 상태 날짜는 들어 있지 않습니다. 열 머리글은 항상 영어입니다.

**IFC만 계산 프로필과 계산 옵션을 보존합니다.** CSV, MS Project XML 또는 Primavera P6 XML로 내보내면 파일에 프로필이 들어가지 않습니다. 계산 옵션 중에서는 MS Project XML이 최대 주공정 임계값까지만 씁니다. 이런 파일은 *Open Planner Studio*로 다시 열립니다. 프로젝트가 예를 들어 `.xer`나 `.mpp`에서 왔기 때문에 *Primavera P6* 또는 *Microsoft Project* 방식으로 계산되었다면, 날짜가 그 때문에 달라질 수 있습니다. 계산 프로필이 무엇인지는 [계산 프로필과 규칙](docs://uitleg-rekenprofielen)에 설명되어 있습니다.

프로젝트가 Primavera 파일(`.xer`)에서 왔다면, 그 사이에 IFC로 저장했더라도, 앱은 CSV, MS Project XML 또는 P6 XML로 내보낸 뒤 다음 메시지를 표시합니다: *CSV 형식으로 내보내면 XER 원본 정보가 손실됩니다.* MS Project XML에서는 *CSV* 대신 *MSPDI*라고 표시합니다. P6 XML에서는 *P6*라고 표시합니다. IFC로 내보낼 때는 이 메시지가 나오지 않습니다. IFC 파일에는 Primavera의 원본 파일이 함께 들어 있기 때문입니다. [Primavera P6 파일(.xer) 열기](docs://howto-xer-openen)를 참조하세요.

앱은 내보내기에서 두 가지를 더 합니다. 일정이 최신 상태가 아니면 앱은 먼저 다시 계산한 뒤 내보냅니다. 또한 순환 관계가 있는 일정은 내보내지 않습니다. 대신 순환 고리가 들어 있는 메시지를 보여 줍니다. 예를 들어 *작업 간 순환 관계: Set up site → Demolish existing extension → Set up site*라는 메시지가 표시됩니다.

### 저장, 자동 저장, 충돌 복구

이들은 서로 다른 세 가지입니다. 비슷해 보이지만 기록하는 위치가 다릅니다.

**저장**은 직접 하는 작업입니다. 앱은 프로젝트를 파일에 쓰고 *저장되지 않음* 표시를 지웁니다.

**자동 저장**은 기본적으로 꺼져 있으며, 프로젝트마다 직접 켜야 합니다. 그러면 앱은 창을 띄우지 않고, 변경이 있을 때마다 같은 파일에 씁니다. 최대 열 초에 한 번입니다. 프로젝트에 이미 파일이 있어야만 작동합니다. [자동 저장 켜기](docs://howto-automatisch-opslaan)를 참조하세요.

**충돌 복구**는 항상 켜져 있습니다. 어디서든 변경이 생기면 앱은 열려 있는 모든 프로젝트의 복구 사본을 보관합니다. 직접 바꾸지 않은 프로젝트도 포함됩니다. 이 사본도 최대 열 초에 한 번씩 만듭니다. 이 사본은 프로젝트 파일에 들어 있지 않습니다. 데스크톱 앱에서는 앱의 데이터 폴더에 있고, 브라우저에서는 브라우저 저장소에 있습니다. 다음 시작 때 앱은 그 사본을 제안합니다. 이 내용은 [충돌 후 복구](docs://howto-herstellen-na-een-crash)에서 읽을 수 있습니다. 충돌 복구는 프로젝트 파일에 절대 쓰지 않습니다.

사본은 최대 열 초에 한 번만 보관되므로, 충돌이 나면 마지막 몇 초 동안의 변경 내용을 잃을 수 있습니다.

### 데스크톱과 브라우저

데스크톱 앱과 브라우저 버전은 프로젝트를 같은 방식으로 처리하지만, 파일을 기록하는 방식은 다릅니다.

데스크톱에서는 앱이 실제 경로를 사용합니다. *저장*은 파일에 바로 씁니다. 보통 앱은 먼저 옆에 있는 임시 파일(`.ops-save.tmp`)에 쓰고, 그다음에 원본 파일을 바꿉니다. 그래서 쓰기 도중에 충돌이 나도 기존 파일이 잘리지 않습니다. 변경 내용이 있는 상태로 앱을 닫으면 앱은 프로젝트마다 저장할지 묻습니다. 정상적으로 종료하면 앱은 복구 사본을 지웁니다.

원하는 곳에 파일을 저장할 수 있는 브라우저(예: Chrome, Edge)에서는 일반적인 열기 및 저장 창이 나옵니다. 그 뒤에는 *저장*이 파일에 바로 씁니다. 연 파일이라면 브라우저가 권한을 한 번 묻습니다. *최근* 목록이 작동하며, 파일 이름만 보입니다.

그 기능이 없는 브라우저(예: Firefox)에서는 앱이 파일 선택기로 파일을 열고, 다운로드로 저장합니다. *저장*을 사용하면 *다운로드로 저장했습니다. 'name.ifc' 파일이 다운로드 폴더에 있습니다. …* 메시지가 세션마다 한 번 이를 설명합니다. *다른 이름으로 저장*과 내보내기에서는 *다운로드로 저장했습니다. 'name.ifc' 파일이 다운로드 폴더에 있습니다. 이 환경에서는 앱이 선택한 위치에 직접 쓸 수 없습니다.* 메시지가 표시됩니다. 브라우저가 저장 창은 보여 줄 수 있지만 프로젝트 파일에 다시 쓸 수 없으면, *저장*은 매번 위치를 다시 묻습니다. 이 내용도 세션마다 한 번 메시지로 설명합니다. *파일 › 최근*은 있지만 빈 페이지를 열며, 자동 저장은 사용할 수 없습니다. 앱이 선택한 위치에 쓰지 못하게 하는 환경에서는 같은 메시지가 나옵니다.

## 예제: 예제 프로젝트 내보내기

예제 *Refurbishment & Extension of a Family Home*을 사용하세요 (*파일 › 예제*). 작업이 20개이며, 그중 단계 4개와 마일스톤 2개입니다. 관계는 16개입니다. 리소스는 6개이며 할당은 8개, 기준선은 1개입니다. 또 *Demo resource library*에 대한 링크가 있습니다. 작업 *Demolish existing extension*에는 2027년 5월 14일에 적용되는 *지정일 이후 시작 (SNET)* 제약 조건이 있습니다. *Handover inspection*에는 2027년 7월 29일 기한이 있습니다. 일정은 2027년 7월 7일에 끝납니다.

다음은 각 형식에서 프로젝트가 돌아오는 방식입니다. 내보낸 파일을 다시 연 뒤에 측정한 값입니다:

- IFC 파일은 모든 내용을 돌려줍니다. 작업 20개, 관계 16개, 리소스 6개, 할당 8개, 기준선, 제약 조건, 기한, 라이브러리 링크입니다. 일정은 다시 2027년 7월 7일에 끝납니다.
- MS Project XML 파일도 라이브러리 링크를 제외한 모든 내용을 돌려줍니다. 일정은 2027년 7월 7일에 끝납니다.
- P6 XML 파일은 작업, 관계, 리소스, 할당, 제약 조건을 돌려줍니다. 기준선과 기한은 없습니다. 제약 조건이 아직 들어 있으므로 일정은 여전히 2027년 7월 7일에 끝납니다.
- CSV 파일은 작업 20개와 관계 16개를 돌려줍니다. 리소스, 할당, 기준선, 제약 조건, 기한은 없습니다. 프로젝트 이름은 *CSV Import*입니다. 제약 조건이 없으면 일정이 앞당겨집니다. 일정은 2027년 7월 2일에 끝나며, 달력 기준으로 닷새 앞당겨집니다.

그 제약 조건이 없으면 예제 자체도 2027년 7월 2일에 끝납니다. 따라서 차이는 CSV 파일이 담지 않는 제약 조건에서 옵니다.

## 결과와 오해

**내보내기는 백업이 아닙니다.** IFC 형식만 모든 내용을 보존합니다. 프로젝트를 보관하려면 IFC로 저장하세요. 다른 형식이 필요한 사람에게만 내보내세요.

**내보낸 파일을 다시 열면 항상 같은 일정이 나오지는 않습니다.** 앱은 열 때 항상 다시 계산하며, 이때 해당 형식에 속한 계산 프로필을 사용합니다. CSV 예제의 제약 조건처럼 논리가 빠져 있거나, 프로필이 다르게 계산하면 결과가 달라집니다.

**내보내기 파일도 최근 목록에 있습니다.** 데스크톱과 파일 접근이 가능한 브라우저에서는 내보낸 파일도 저장한 프로젝트처럼 최근 목록에 들어갑니다(진행 기록표는 제외). 거기서 열면 그 형식의 가져오기로 열립니다.

**저장은 충돌 복구와 같지 않습니다.** 충돌 복구는 충돌 후에 도움이 되지만 저장을 대신하지 않습니다. 그러므로 탭이나 앱을 닫기 전에 저장하세요.
