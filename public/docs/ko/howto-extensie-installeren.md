# 확장 프로그램 설치 및 관리

목표: 확장 프로그램을 설치하고, 권한 질문을 읽은 다음, 나중에 확장 프로그램을 사용 안 함으로 설정하거나 제거합니다.

## 이런 때 필요합니다

확장 프로그램을 사용하면 새 버전을 기다리지 않고도 앱에 기능을 추가할 수 있습니다. 예를 들어 확장 프로그램은 *파일 › 가져오기*에 나타나는 가져오기 형식을 추가하거나, 리본에 버튼을 넣거나, PDF 내보내기에 사용할 글꼴을 제공할 수 있습니다. 공식 카탈로그는 확장 프로그램을 다음 범주로 나눕니다: *가져오기/내보내기*, *계획*, *보고서*, *유틸리티*, *글꼴*, *기타*.

설치하기 전에 신중하게 생각하세요. 확장 프로그램은 앱 자체와 동일한 권한으로 실행되는 프로그램 코드이며, 앱은 이를 제한할 수 없습니다. 그래서 앱은 설치할 때마다 권한을 묻습니다. 그 질문에서 무엇을 보게 되는지는 아래에서 설명합니다.

## 단계

### 카탈로그에서 확장 프로그램 설치

1. *파일 › 확장 프로그램*을 선택합니다.
2. *찾아보기* 탭을 선택합니다. 앱은 *카탈로그 불러오는 중...*이라고 표시되는 동안 카탈로그를 불러옵니다. 카탈로그에 무엇이 들어 있는지는 이를 관리하는 OpenAEC Foundation이 정하며, 이는 바뀔 수 있습니다.
3. 입력란 *확장 프로그램 검색...*에서 확장 프로그램을 검색합니다. 이름, 설명, 작성자와 태그에서 검색합니다.
4. 각 카드에는 이름, 버전, 범주, 설명, 작성자가 표시됩니다. *설치*를 클릭합니다.
5. *확장을 설치할까요?* 창이 열립니다. 이 창을 읽고 다음 단계를 확인하세요.
6. 계속하려면 *설치*를 클릭합니다. *설치 안 함*을 선택하면 아무 일도 일어나지 않습니다. Esc 키를 누르거나 창 옆을 클릭해도 거부한 것으로 처리되며, 앱은 이때 오류 메시지를 표시하지 않습니다.

설치한 후 확장 프로그램은 바로 사용으로 설정됩니다. *찾아보기*의 카드에는 이제 *설치됨*이라고 표시됩니다. 확장 프로그램이 추가하는 항목은 앱 자체에서 확인합니다. 리본에 새 버튼이 나타나거나 *파일 › 가져오기*에 가져오기 형식이 나타납니다. 일부 확장 프로그램은 메시지도 표시합니다. 이 메시지는 *확장 프로그램* 접두어와 확장 프로그램 이름으로 알아볼 수 있습니다.

**튜토리얼.** 튜토리얼은 확장 프로그램입니다. *도움말*의 *튜토리얼* 아래에 *튜토리얼 설치* 버튼이 보이면, 이 버튼은 *파일 › 확장 프로그램*을 *찾아보기* 탭으로 엽니다. 첫 번째 둘러보기 뒤에 나오는 질문으로도 이 확장 프로그램을 설치합니다. 두 경로 모두 같은 권한 질문을 표시하며, 이를 거부할 수 있습니다.

### 파일에서 확장 프로그램 설치

확장 프로그램을 파일로 받았다면 다음과 같이 설치하세요.

1. *파일 › 확장 프로그램*을 선택합니다.
2. 오른쪽 위에서 ZIP 파일은 *ZIP*을, 별도의 JavaScript 파일은 *JS*를 클릭합니다.
3. 파일을 선택합니다. 위에서처럼 *확장을 설치할까요?* 창이 열립니다.

ZIP 파일에는 `manifest.json`과 확장 프로그램의 주 파일이 들어 있어야 합니다. 이미 설치된 확장 프로그램을 설치하면 새 버전이 이전 버전을 대체합니다. 예를 들어 ZIP 파일이 손상되어 앱이 파일을 설치할 수 없으면 아무 일도 일어나지 않습니다. 앱은 ZIP과 JS에 대해 오류 메시지를 표시하지 않으며, 확장 프로그램은 목록에 나타나지 않습니다. 다만 이유는 디버그 터미널에 표시됩니다. *설정 › 프로젝트 › 앱 설정*의 *고급* 탭에서 *디버그 터미널 활성화*를 선택해 켜고, 상태 표시줄의 *디버그 터미널 표시* 버튼으로 엽니다. 거기에는 예를 들어 *[Extensies] ZIP-installatie mislukt: Error: Geen manifest.json gevonden in ZIP*라고 표시됩니다(앱은 이 기술 문구를 네덜란드어로 표시합니다).

### 권한 질문 읽기

이 질문은 결정해야 할 사항을 보여 줍니다.

- *작성자*와 *저장소*는 확장 프로그램을 만든 사람과 소스 코드의 위치를 알려 줍니다.
- *출처*에는 파일의 출처와 검증 여부가 표시됩니다. 다운로드가 검증되지 않았다고 빨간색으로 표시되면, 출처를 알 때만 설치하세요.
- *무엇에 동의하는지*에는 확장 프로그램이 앱 자체와 같은 권한으로 실행되는 프로그램 코드라는 점이 다시 표시되며, 사용 중인 플랫폼에서 그것이 무엇을 뜻하는지도 표시됩니다. 작성자를 신뢰하는 확장 프로그램만 설치하세요.
- *이 확장이 사용한다고 밝힌 항목*에는 작성자가 신고한 권한이 작은 표시로 나타납니다. 이는 신고이며 제한이 아닙니다. *신고된 항목 없음*이라고 표시되면, 확장 프로그램은 여전히 일정의 데이터를 읽고 바꿀 수 있습니다.

각 표시의 뜻과 창의 정확한 문구는 [확장 프로그램 권한](docs://ref-extensiepermissies)에 있습니다.

### 확장 프로그램 사용 안 함, 다시 사용 또는 제거

1. *파일 › 확장 프로그램*을 선택하고 *설치됨* 탭을 선택합니다. 각 확장 프로그램에는 이름, 버전, 범주, 설명, 작성자가 적힌 카드가 있습니다.
2. 카드의 스위치로 확장 프로그램을 *사용 안 함*으로 설정하거나 다시 *사용*으로 설정합니다. 사용 안 함으로 설정하면 확장 프로그램이 추가한 버튼과 가져오기 형식이 사라지지만, 확장 프로그램은 계속 설치되어 있습니다. 앱을 다시 시작해도 꺼진 상태로 남습니다. 사용으로 설정된 확장 프로그램은 앱이 시작될 때 자동으로 시작됩니다.
3. *제거*를 클릭합니다. 버튼이 *확인*으로 바뀌고 *완전히 제거하려면 다시 클릭하세요*라는 설명이 표시됩니다. 확장 프로그램을 제거하려면 한 번 더 클릭합니다. 앱은 확장 프로그램이 저장한 설정도 함께 정리합니다.

## 문제가 생길 때와 앱의 동작

**카탈로그를 불러오지 못합니다.** 앱은 *카탈로그를 불러올 수 없습니다:* 뒤에 기술적 이유를 표시하고, *다시 시도* 버튼을 보여 줍니다. 인터넷 연결이 없기 때문일 수 있습니다.

**카탈로그의 카드 아래에 *설치 실패.*라고 표시됩니다.** 다운로드나 설치가 실패했습니다. 예를 들어 체크섬이 일치하지 않았기 때문입니다. 이때는 아무것도 설치되지 않습니다. 이는 질문을 거부한 것과 다릅니다. 거부했을 때는 오류 메시지가 없습니다.

**목록 위에 *건너뛴 카탈로그 항목: 1*이라고 표시됩니다.** 카탈로그에 앱이 사용할 수 없는 항목이 있었습니다. 나머지 확장 프로그램은 평소처럼 설치할 수 있습니다.

**확장 프로그램이 시작되지 않습니다.** 그러면 카드에 오류 메시지가 표시됩니다. 예를 들어 확장 프로그램에 더 새로운 버전의 Open Planner Studio가 필요하다고 표시되고 현재 버전이 함께 나타나거나, 확장 프로그램 자체가 낸 오류가 표시됩니다. 이때 확장 프로그램은 활성 상태가 아닙니다. 앱을 업데이트하거나 확장 프로그램을 제거하세요.

**카드에 *격리* 표시가 있습니다.** 앱은 저장된 확장 프로그램을 사용할 수 없었습니다. 이름 아래에 *사유:*와 원인이 표시됩니다. *보관소에서 제거*를 선택하면 정리됩니다.

**확장 프로그램을 직접 작성하기.** 확장 프로그램 작성자를 위한 안내(manifest, API, 권한)는 GitHub의 저장소 `OpenAEC-Foundation/open-planner-studio`에 있으며, 파일은 `docs/extensions.md`입니다.

**확장 프로그램은 프로젝트에 속하지 않습니다.** 확장 프로그램은 앱에 저장됩니다. 데스크톱 앱에서는 이 컴퓨터에, 브라우저에서는 그 브라우저의 저장 공간에 저장됩니다. 확장 프로그램은 모든 프로젝트에 적용되며 프로젝트 파일에 포함되지 않습니다. 브라우저에서 사이트 데이터를 지우면 확장 프로그램도 사라집니다.
