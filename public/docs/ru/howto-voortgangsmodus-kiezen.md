# Выбор режима учета выполнения

Цель: определить, как приложение планирует оставшиеся трудозатраты задачи, которая уже начата, пока ее предшественник еще выполняется: по связи (Retained Logic) или по тому, что фактически происходит (Progress Override).

## Когда это нужно

На объекте часто делают раньше, чем это предусмотрено логикой графика. Маляр уже начинает в комнатах, где штукатурка готова, а штукатур еще занят в других местах. В графике это, например, связь окончание-начало, у которой последователь начинается раньше, чем завершен предшественник. Приложение называет такую ситуацию **выполнением с нарушением последовательности**. Если строка состояния показывает *N связь(-ей) с нарушением последовательности*, у вас есть такой случай, и режим учета выполнения определяет, как приложение планирует оставшиеся трудозатраты последователя. Что делают оба режима, с примером, описано в [Ход выполнения, дата отчета о состоянии и базовый план](docs://uitleg-voortgang).

## Шаги

1. Обновите ход выполнения и задайте дату отчета о состоянии, как описано в [Обновление хода выполнения](docs://howto-voortgang-bijwerken).
2. Перейдите к *График › Базовые планы и ход выполнения › Режим учета выполнения* и откройте список.
3. Выберите *Retained Logic* или *Progress Override*.
4. Нажмите **Рассчитать** (F5), например через *График › График › Рассчитать*. Выбор делает график устаревшим: строка состояния показывает *Устарело — пересчитайте (F5)*. Если включен параметр *Автоматический расчет*, приложение делает это само.

Как выбрать?

- **Retained Logic** установлен по умолчанию. Связь остается в силе: оставшиеся трудозатраты последователя начинаются только после того, как завершен предшественник. Выберите его, если порядок действительно фиксирован или если вы хотите планировать осторожно.
- **Progress Override** отдает приоритет фактическому ходу выполнения. Оставшиеся трудозатраты последователя начинаются с даты отчета о состоянии, не дожидаясь предшественника. Выберите его, если последователь действительно продолжает выполняться, а дата окончания не должна зависеть от предшественника, который еще не завершен.

## Проверка результата

- Щелкните сообщение *N связь(-ей) с нарушением последовательности* в строке состояния. Откроется панель *Предупреждения*, которую также можно открыть через *График › График › Предупреждения*. В ней есть каждая связь с текстом *Выполнение с нарушением последовательности: ход выполнения последователя противоречит связи*, например *4.2 Plastering → 4.5 Painting (FS)*.
- Посмотрите на полосу последователя. При Retained Logic она тянется дальше окончания предшественника. При Progress Override она заканчивается раньше. В примере из пояснения это вторник, 27 июля, против четверга, 22 июля.

## Возможные ошибки и что делает приложение

**Разницы нет.** Режим учета выполнения действует только на задачи, которые уже начаты, пока их предшественник еще не завершен. Без таких задач ничего не меняется.

**Сообщение остается.** Progress Override не устраняет сообщение о выполнении с нарушением последовательности. Режим учета выполнения определяет, как приложение рассчитывает; противоречие между связью и ходом выполнения остается. Если связь уже не верна, измените ее ([Добавление связей](docs://howto-relaties-leggen)).

**Режим привязан к проекту.** Выбор сохраняется в файле проекта, действует на весь проект и его можно отменить с помощью Ctrl+Z. В новом проекте по умолчанию выбран режим Retained Logic.

**Файл P6.** Если вы откроете файл Primavera P6 (.xer), приложение возьмет режим учета выполнения из файла. Помимо Retained Logic и Progress Override, в P6 есть еще Actual Dates. Приложение не знает этот третий режим, поэтому такой файл рассчитывается как Retained Logic. В сообщении об импорте это отмечено так: *1 настройка графика P6 заменена безопасным значением по умолчанию.*

**Профиль расчета.** В профиле Primavera P6 режим Progress Override также работает в обратную сторону: в поздних датах и в свободном резерве времени предшественника (правило *Progress Override также в обратном расчете игнорирует начатого последователя*). В профилях Open Planner Studio и Microsoft Project это не так. Правила расчета находятся в *Настройки › Проект › Сведения о проекте*, в блоке *Профиль расчета и параметры расчета*. В примере из пояснения этот обратный эффект не виден.
