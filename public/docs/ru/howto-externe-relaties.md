# Внешние зависимости к другому проекту

Цель: связать задачу в этом проекте с задачей в другом файле проекта, чтобы ваш график учитывал работы, которые запланированы в другом месте.

## Когда это нужно

Ваша пристройка может начаться только после того, как площадка будет подготовлена под строительство, и эти работы входят в проект подрядчика. Или монтажник может начать работу только после того, как будет готова ваша конструкция, и он планирует работу в своем файле. Обычная связь работает только между задачами одного проекта. **Внешняя зависимость** связывает задачу с задачей в другом файле.

Внешняя зависимость не пересчитывается в реальном времени вместе с другим проектом. Приложение сохраняет фиксированную **дату привязки**: дату исходной задачи на момент создания связи. При расчете эта дата используется как граница. Если другой проект изменится, в вашем проекте ничего не сдвинется, пока вы не обновите дату привязки.

## Шаги

1. Выберите ровно одну задачу в этом проекте: задачу, которая зависит от исходной задачи, или задачу, от которой зависит исходная задача.
2. Выберите *Главная › Задачи › Связь ▾ › Добавить внешнюю зависимость…*. То же меню есть в *График › Связи* и в *Таблица › Задачи*. Пункт доступен, только если выбрана ровно одна задача.
3. В окне *Внешняя зависимость (межпроектная)* выберите один из двух способов. С помощью кнопки *Исходный файл* вы выбираете файл проекта в разделе *Выберите недавний файл*, а затем поле *Исходная задача*. Приложение читает файл только для чтения, не открывает его как документ и само берет дату привязки. Этот способ работает только в настольном приложении и только для файла из списка недавних файлов; в ином случае кнопка *Исходный файл* недоступна. С вариантом *Вручную (запасной вариант)* вы заполняете поля *ID проекта* и *ID задачи* исходной задачи, при необходимости поле *Название задачи (необязательно)* и поле *Дата привязки*. В веб-версии это единственный способ.
4. В блоке *Направление* выберите, является ли исходная задача вашим предшественником или последователем: *Предшественник (внешний → текущая задача)* или *Последователь (текущая задача → внешний)*.
5. Выберите *Тип связи* (FS, SS, FF или SF) и при необходимости заполните поле *Задержка (рабочие дни)*, например `0d` или `2d`.
6. Нажмите *Добавить внешнюю зависимость*, затем нажмите **Рассчитать** (F5).

Какую дату вводить в качестве даты привязки для ручной зависимости, зависит от направления и типа:

- При внешнем **предшественнике** важна первая буква типа: F означает дату окончания исходной задачи, S — дату начала. При FS и FF вы поэтому вводите окончание, при SS и SF — начало.
- При внешнем **последователе** важна вторая буква типа: S — дата начала исходной задачи, F — дата окончания. При FS и SS вы поэтому вводите начало, при FF и SF — окончание.

Если вы планируете в часах (включено почасовое планирование, а задача работает по календарю с рабочим временем), поле *Дата привязки* также запрашивает время.

Пример: дата окончания проекта строительной площадки — пятница, 18 июня 2027 года. Вы связываете *Groundwork* с внешним предшественником типа FS, дата привязки 18 июня 2027 года. После нажатия **Рассчитать** задача *Groundwork* начинается в понедельник, 21 июня, то есть в первый рабочий день после даты привязки. Внешний последователь работает наоборот: он ограничивает, насколько поздно может закончиться ваша задача.

## Что вы видите и как этим управлять

- Внешние зависимости отображаются как текст в столбцах *Предшественники* и *Последователи* таблицы задач (добавьте их с помощью **+** в заголовке таблицы, в разделе *Связи*), с названием проекта и задачи, а также с типом. Маленький треугольник с надписью *Источник отсутствует* означает, что источник не был прочитан. Наведите указатель мыши на зависимость, чтобы увидеть проект (строка *ID проекта* показывает название проекта, как только оно известно), ID задачи, дату привязки и состояние источника.
- На диаграмме Ганта у задачи есть серая призрачная полоса. При предшественнике она заканчивается в дате привязки, при последователе начинается с нее. Пунктирная рамка с красной надписью *устарело* означает, что источник не был прочитан. У ручной внешней зависимости это всегда так.
- Щелкните правой кнопкой мыши зависимость в столбце: в контекстном меню есть *Изменить внешнюю зависимость…* и *Удалить связь*. Если у зависимости есть исходный файл, там также есть *Обновить источник*.
- Выберите *Связь ▾ › Обновить все внешние зависимости*, чтобы заново прочитать исходные файлы и обновить даты привязки. Это работает только в настольном приложении. Если у вас только ручные зависимости, приложение выводит сообщение *Нет внешних источников для обновления (путь к файлу отсутствует).* После обновления нажмите **Рассчитать**.
- Если вы меняете тип или направление так, что для даты привязки нужна другая сторона исходной задачи (начало вместо окончания или наоборот), приложение для ручной зависимости запрашивает новую дату привязки: *Выберите новую дату привязки: тип связи теперь использует другую сторону исходной задачи*. У зависимости с исходным файлом приложение само заново читает дату привязки.

## Подводные камни и что делает приложение

**Другой проект не сдвигает ваш график.** Если дата исходной задачи меняется, ваш график продолжает расчет по старой дате привязки, пока вы не обновите ее или не измените дату привязки. При ручном способе вы сами меняете дату привязки, щелкнув правой кнопкой мыши по зависимости и выбрав *Изменить внешнюю зависимость…*.

**Внешний предшественник — это нижняя граница.** Если из-за собственных предшественников ваша задача начинается позже даты привязки, решают эти предшественники. Дата привязки только подталкивает задачу.

**Внешний последователь — это верхняя граница.** Если дата привязки слишком жесткая, это видно как отрицательный резерв времени у вашей задачи и у задач перед ней. Отдельного предупреждения при этом не появляется, поэтому следите за столбцом *Общий резерв времени*.

**Только фиксированная задержка.** Для внешней зависимости нельзя задать задержку в календарных днях или в процентах. Приложение выводит сообщение *Внешние зависимости поддерживают только фиксированную задержку в рабочих днях или в рабочем времени.* Рабочие дни считаются по календарю вашей задачи. Задержка в часах учитывается только для задачи, которая планируется в часах; для задачи в днях расчет ее игнорирует. В таком случае используйте рабочие дни.

**ID проекта другого файла.** ID проекта не хранится в поле или столбце. Он записан как `InternalProjectId` в IFC этого проекта: откройте проект, перейдите на вкладку *IFC* и выберите *Создать IFC*. При расчете используется только дата привязки; ID — не просто метка. При обновлении приложение сначала распознает исходный файл по ID проекта, затем по пути к файлу. Если при ручной зависимости вы вводите тот же ID, что и у исходного файла, зависимость обновляется вместе с этим файлом при его обновлении. *ID задачи* нужной задачи в другом проекте находится в таблице этого проекта, в столбце *ID задачи* в группе *Технические*.
