# Параметры расчета и правила расчета

Все выборы, которые определяют, как приложение рассчитывает график, как вы их найдете в разделе *Профиль расчета и параметры расчета*: профиль расчета, 27 правил расчета в каждом профиле и параметры расчета проекта. Почему P6 и MS Project рассчитывают по-разному, описано в [Профили расчета и правила расчета](docs://uitleg-rekenprofielen); что это значит для ваших дат, описано в [Даты как записаны](docs://uitleg-datums-zoals-opgeslagen).

## Где их найти и как они работают

Выберите *Настройки › Проект › Настройки проекта* или *Файл › Настройки проекта*. Внизу находится раздел *Профиль расчета и параметры расчета*. В окне *Новый проект* есть только выпадающий список *Профиль расчета*: выбор сразу применяет параметры по умолчанию этого профиля.

**Для каждого проекта, а не для всего приложения.** Профиль расчета и параметры относятся к файлу проекта и сохраняются вместе с ним при *Сохранить* (IFC). Поэтому два человека, которые открывают один и тот же файл, рассчитывают одинаково. CSV и P6 XML их не содержат; из параметров расчета MS Project XML сохраняет только пороговое значение, по которому задача считается критической. См. [Форматы импорта и экспорта](docs://ref-import-exportformaten). Ваши собственные шаблоны действуют для всего приложения: приложение хранит их на этом устройстве.

**Только при применении.** Ваши изменения в этом разделе остаются черновиком, пока вы не нажмете *Применить*. Затем приложение пересчитывает график, даже если *Автоматический расчет* выключен. Если задачи сдвинулись, приложение сообщает, сколько (*После применения 3 задачи сдвинулись.*). Если ни одна задача не сдвинулась, сообщения нет. Это изменение можно отменить одним нажатием кнопки *Отменить*. Применение также переводит вид в режим *Даты как записаны*. Изменение, которое ничего не меняет, ничего не делает. В *Файл › Настройки проекта* вы отклоняете черновик кнопкой *Отклонить*.

## Профиль расчета

**Профиль расчета** — основа, по которой приложение рассчитывает. Можно выбрать *Primavera P6*, *Microsoft Project* или *Open Planner Studio*, а также собственные шаблоны и собственный профиль расчета этого проекта. По умолчанию: *Open Planner Studio* для нового проекта и для проекта без профиля расчета. Результат: профиль расчета включает или выключает каждое из 27 правил расчета ниже. Открытый файл получает профиль расчета своего формата: файл `.xer` рассчитывается как *Primavera P6*, файл `.mpp` как *Microsoft Project*, а CSV, MS Project XML и P6 XML как *Open Planner Studio*. Файл IFC сохраняет профиль расчета, который в нем записан. Встроенный профиль расчета, который отличается от своей основы из старого файла, называется *Primavera P6 (изменен)*, по названию основы. Эта строка остается отдельной в списке, пока проект рассчитывается так. Строка *Primavera P6* без отличий — это чистая основа; если вы ее выбрали, появляется надпись об этом. Если вы выберете другой встроенный профиль расчета, например *Microsoft Project*, отличия сохраняются: при возврате к *Primavera P6* они появятся снова, в том числе после сохранения и повторного открытия. Если вы выберете другой профиль расчета в настройках проекта, параметры расчета остаются прежними; если они отличаются от значений по умолчанию нового профиля, над параметрами расчета появляется оранжевая надпись (см. *Параметры расчета этого проекта*). Где: раздел *Профиль расчета и параметры расчета*, выпадающий список *Профиль расчета*.

**Новый профиль** — создает собственный профиль из выбранного профиля. Результат: приложение запрашивает название и предлагает *Копия Primavera P6* (или копию профиля, с которого вы начали). Кнопка *Создать* создает собственный профиль со всеми текущими значениями, в том числе с отличиями старого файла, и раскрывает *Правила расчета этого профиля*. Пустое название невозможно. Поле *Название этого собственного профиля* позволяет изменить название позже; без названия кнопка *Применить* не сработает. Проект использует новый профиль только после *Применить*. Где: рядом со списком *Профиль расчета*. В окне *Новый проект* эта кнопка не показывается.

**Включение или выключение правила расчета** — только в собственном профиле. Результат: профиль тогда отличается от своей основы. *Вернуть базовое* возвращает базовое значение. Три встроенных профиля доступны только для чтения. Где: раздел *Правила расчета этого профиля*.

**Сохранить как шаблон**, **Обновить шаблон из этого проекта**, **Обновить из шаблона** и **Удалить шаблон** — управляют вашими собственными профилями как шаблонами. Результат: шаблон — это сохраненный профиль расчета, который можно выбрать в любом проекте; проект хранит собственную копию. Если профиль проекта отличается от своего шаблона, появляется надпись *Этот профиль отличается от шаблона «…».* Шаблоны не входят в файл проекта. Кнопка *Сохранить как шаблон* сообщает, что шаблон сохранен. Если это не удалось, потому что уже есть 100 шаблонов или хранилище приложения заполнено, появляется сообщение об ошибке. *Удалить шаблон* сначала запрашивает подтверждение. Где: под выпадающим списком, для собственного профиля.

## Правила расчета по профилям

Правило расчета — это правило, в котором программные пакеты планирования различаются. Каждое правило расчета включено или выключено. Раздел *Правила расчета этого профиля* по умолчанию свернут. Его заголовок показывает число правил расчета и, если профиль отклоняется от базового, значок *изменено: 2*. В развернутом виде блок показывает значение каждого правила и значок *изменено: 2* у группы с отклонениями. Базовое значение (*базовое: вкл.* или *базовое: выкл.*) всегда показано для пользовательского профиля, а для встроенного профиля только при отклонении. У встроенного профиля значение — это метка *ВКЛ.* или *ВЫКЛ.*, только для информации. У пользовательского профиля это флажок, а при отклонении есть кнопка *Вернуть базовое*. Отклонение во встроенном профиле возникает из старого файла. Такая строка имеет оранжевый фон, и блок говорит, что она используется. Чтобы ее изменить, используйте *Создать профиль*. Значок «i» после строки показывает объяснение: когда вы наводите на него мышь, при клавише Tab и при щелчке или касании. Клавиша Esc закрывает только объяснение, а не окно под ним. Щелчок в другом месте тоже закрывает его. Когда страница прокручивается, объяснение активного значка остается на месте. Если правило работает только с почасовым планированием или только для задач из файла `.xer`, синяя метка рядом со строкой говорит об этом: *только при почасовом планировании* или *только задачи из .xer*. *Только с почасовым планированием* в разделе *Условия* ниже значит то же, что эта метка: календарь с рабочими блоками, задача с длительностью в часах или *Календарь задержки* в режиме *24-часовой* (тогда задержка считается в часах). Значение по умолчанию для каждого правила задает выбранный встроенный профиль. *Open Planner Studio* выключает все правила расчета. Под каждым правилом ниже описано, что делают *Primavera P6* и *Microsoft Project*.

### Ход выполнения и завершенные трудозатраты

**Сохранять фактические даты в обратном расчете** — При обратном расчете начатая задача сохраняет свое зафиксированное начало как позднее начало, если не включено *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат* (как в *Primavera P6*). Тогда ее позднее начало — это начало оставшихся трудозатрат. Завершенная задача сохраняет свои фактические даты как поздние даты. Поэтому завершенный последователь не сдвигает незавершенного предшественника назад в прошлое. Условия: только с датой отчета о состоянии. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат** — Раннее и позднее начало задачи в ходе выполнения указывают на то, где начинаются оставшиеся трудозатраты (более поздняя из даты отчета о состоянии и границы связи), а не на фактическое начало. При обратном расчете по связи начало-начало учитывается только оставшаяся длительность предшественника в ходе выполнения. Эта часть действует только с почасовым планированием. Условия: это основа для параметра *Рассчитывать задержку SS для начатого предшественника от* и для правила *Прошедшая задержка SS от предшественника в ходе выполнения не учитывается*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Завершенная задача с физическим ходом выполнения стоит на дате отчета о состоянии** — Завершенная задача стоит одной точкой на дате отчета о состоянии или позже, если этого требует предшественник. Она не стоит на своих фактических датах. Условия: только с почасовым планированием и с датой отчета о состоянии, для завершенных задач и вех из файла `.xer` с типом процента завершения *физический*, с фактическим окончанием не позже даты отчета о состоянии и без приостановки и возобновления (suspend/resume). Для других типов процента завершения, включая длительность по умолчанию в P6, это не измерено, и приложение это не применяет. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Плановое начало не служит нижней границей для задачи в ходе выполнения** — Плановое начало из файла не служит нижней границей для задачи в ходе выполнения (с фактическим началом и меньше 100%). Ее оставшиеся трудозатраты начинаются на дате отчета о состоянии, сразу после предшественников, даже если ее плановое начало позже. Это противоположность правила *Плановое начало как дополнительный нижний предел*. Условия: работает, только если включено *Плановое начало как дополнительный нижний предел*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Progress Override также не учитывает начатого последователя на позднем расчете** — Связь от незавершенного предшественника к последователю, который уже начат и не завершен, не учитывается на позднем расчете и в свободном резерве времени этого предшественника. Поэтому последователь не создает давления назад, и эта связь не становится определяющей связью. Условия: только с режимом учета выполнения *Progress Override*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Связи и задержка

**Последователь начинается на границе окончания** — Связь окончание-начало без задержки, при которой последователь начинается ровно на окончании предшественника в конце блока рабочего времени, позволяет последователю начаться сразу на этом окончании, а не с начала следующего блока. При обратном расчете последователь просто показывает свое позднее начало как начало блока. Условия: только с почасовым планированием. Файл ничего не помечает: приложение само распознает такую связь при открытии файла `.xer`. Связь, которую вы создаете сами, под это правило не попадает. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Обратная задержка от границы окончания** — Если при обратном расчете приложение вычитает рабочую задержку из точной границы окончания блока рабочего времени и попадает ровно на начало блока, этот момент становится границей окончания предыдущего блока. Также для связи окончание-окончание без задержки позднее окончание на конце блока остается на этой границе. Условия: только с почасовым планированием. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Прошедшая задержка завершенного предшественника не учитывается** — Из положительной рабочей задержки после завершенного предшественника учитывается только та часть, которая на дате отчета о состоянии еще не прошла: задержка минус рабочее время между фактическим окончанием и датой отчета о состоянии, но не меньше 0. Условия: только с почасовым планированием, с датой отчета о состоянии и только для задач из файла `.xer`. Правило действует на позднем расчете и, при прямом расчете, только от завершенных предшественников с точкой или окном даты отчета о состоянии (см. *Завершенная задача с физическим ходом выполнения стоит на дате отчета о состоянии* и *Завершенная задача с нарушением последовательности ждет своих предшественников*). Завершенная задача, которая просто стоит на своих фактических датах, сохраняет полную задержку. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Прошедшая задержка SS от предшественника в ходе выполнения не учитывается** — При связи начало-начало с положительной рабочей задержкой от предшественника в ходе выполнения учитывается только та часть задержки, которая еще не прошла: задержка минус рабочее время между фактическим началом и датой отчета о состоянии, но не меньше 0. При прямом расчете это считается от начала оставшихся трудозатрат предшественника. При обратном расчете позднее начало предшественника равно позднему началу последователя минус эта оставшаяся задержка. Условия: только с почасовым планированием. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*. Параметр *Рассчитывать задержку SS для начатого предшественника от* выбирает отправную точку. Задержки 0 или меньше, задержки в календарных часах и связи окончание-начало остаются как обычно. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Раннее окончание не раньше границы связи окончание-окончание** — При связи окончание-окончание раннее окончание последователя никогда не бывает раньше окончания предшественника плюс задержка. Если эта граница выпадает за рабочее время последователя, раннее окончание становится первой рабочей границей на ней или после нее. Начало остается прежним. Условия: только с почасовым планированием и с рабочими задержками. Правило не действует при жестком ограничении окончания и для гамака. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Вехи и задачи LOE

**Веха следует за плановой границей календаря** — Веха без длительности остается на границе календаря, которую запланировал файл. Веха, которая стояла в начале дня, остается вехой начала. Веха, которая стояла в конце блока рабочего времени, может попасть на окончание предшественника. Условия: только с почасовым планированием. Задача с длительностью 0 тоже может стоять на двух границах так (начало на начале следующего блока, окончание на конце предыдущего блока). Но это возможно, только если задача из файла `.xer` и ее плановое окончание раньше планового начала. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Не начатая задача LOE использует целевое окно** — Задача LOE, которая еще не начата (в приложении это гамак), с полным целевым окном принимает это целевое окно как свой отрезок. Условия: только с почасовым планированием, и только если задача из файла `.xer` с входящими связями только начало-начало и исходящими связями только окончание-окончание без задержки. Доказательство этого правила слабое: один файл. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Связь окончание-окончание с вехой начала привязывается к самой вехе** — Связь окончание-окончание с вехой начала (длительность 0, вид *Начало*) привязывается к позднему окончанию самой этой вехи, а не к началу дня вехи. Свободный резерв времени предшественника тогда больше не становится на один рабочий день короче. Раннее начало вехи никогда не меняется. Условия: только с почасовым планированием; веха окончания не меняется. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Резерв времени и поздние даты

**Значение свободного резерва времени никогда не бывает отрицательным** — Если позднее ограничение нельзя выполнить, общий резерв времени остается отрицательным. Для свободного резерва времени получается 0, а не отрицательное число. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Свободный резерв времени в собственном календаре задачи** — Свободный резерв времени незапущенной задачи считается по каждой связи в календаре самой задачи, а не в календаре последователя. Это верно для связей окончание-начало, начало-начало и окончание-окончание. Связь с задержкой (не 0) подпадает под это правило, только если *Календарь задержки* — *Предшественник*. Иначе остается календарь последователя. Связь без задержки всегда подпадает под это правило. Начатая, но не завершенная задача следует этому правилу только при связи окончание-начало без задержки. Условия: только с почасовым планированием. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Позднее окончание в собственном календаре задачи** — Если последователь навязывает позднее окончание, которое выпадает за рабочее время задачи, позднее окончание становится концом предыдущего рабочего периода в собственном календаре задачи. Более жесткое ограничение или крайний срок побеждает. Это парное правило к правилу *Свободный резерв времени в собственном календаре задачи* для позднего расчета. Условия: только с почасовым планированием и не для окончания проекта. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Задачи ALAP как можно позже, насколько позволяют последователи** — Незапущенная задача с ограничением *Как можно позже (ALAP)* получает как раннее окончание самую строгую границу, которую допускают ее последователи с их ранними датами, с точностью до минуты. Ее раннее начало — это окончание минус ее длительность. Собственное плановое окно не учитывается. Нижняя граница — предшественники и дата отчета о состоянии. Условия: только с почасовым планированием; без него остается обычный шаг в целых рабочих днях. Что задача ALAP размещается как можно позже и что последователи считаются первыми, так что цепочка ALAP сходится, верно во всех профилях; без почасового планирования это верно в целых рабочих днях. Это правило добавляет размещение с точностью до минуты по ранним датам последователей. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Даты и моменты из файла

**Плановое начало как дополнительный нижний предел** — Плановое начало из файла считается дополнительным нижним пределом рядом с сетью. Но только если и начало, и окончание позже, чем допускает сеть, больше чем на один календарный день. Обычное начало на следующем блоке рабочего времени это правило не запускает. Условия: правило не действует для задачи в ходе выполнения, пока включено *Плановое начало не служит нижней границей для задачи в ходе выполнения*. Оно также не действует для незапущенной задачи ALAP, которую *Задачи ALAP как можно позже, насколько позволяют последователи* размещает от ее последователей. Правило не смотрит, откуда задача пришла. Оно смотрит только на ее плановое начало и окончание. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Переносить фактические даты точно** — Записанные фактические даты начала и окончания, с их временем суток, остаются точными. Их не переносят на край блока рабочего времени. Условия: только для задач из файла `.xer`. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Точный момент ограничения у вехи** — Ограничение с датой и временем (SNLT, MSO, FNLT или MFO) на вехе без длительности — это точный момент. Это верно, даже если этот момент — начало блока рабочего времени. Условия: только с почасовым планированием и на позднем расчете. При прямом расчете такой момент уже точный во всех профилях. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Ход выполнения, как в Microsoft Project

**Оставшиеся трудозатраты возобновляются после прошедшей астрономической длительности** — Задача в ходе выполнения возобновляет свои оставшиеся трудозатраты на самой поздней из трех точек: дата отчета о состоянии, граница предшественника и фактическое начало плюс уже прошедшая астрономическая длительность. В *Primavera P6* (Retained Logic) учитываются только первые две точки. Третий предел может только сдвинуть оставшиеся трудозатраты позже. Условия: не с *Progress Override*, не когда оставшихся трудозатрат не осталось и не когда файл задает дату возобновления (Resume) для задачи (с максимум одним назначением). По умолчанию: вкл. в Microsoft Project, выкл. в Primavera P6 и Open Planner Studio.

**Не сдвигать не начатые задачи на дату отчета о состоянии** — Задача без хода выполнения сама по себе не сдвигается на дату отчета о состоянии или после нее. Если выключено, применяется нижний предел, который у P6 есть при Retained Logic. По умолчанию: вкл. в Microsoft Project, выкл. в Primavera P6 и Open Planner Studio.

### Только для пользовательских профилей

Эти правила выключены во всех встроенных профилях, в том числе в Primavera P6. Только пользовательский профиль может их включить: создайте его с помощью *Создать профиль*.

**Веха окончания как окно границ** — Веха окончания может стоять на двух соседних границах календаря: раннее начало в начале блока рабочего времени и раннее окончание на конце предыдущего блока. На позднем расчете веха окончания без последователя, но с предшественниками, получает свои ранние даты как поздние. Поэтому она давит на свою цепочку назад, если не включено *Рассчитывать резерв времени до окончания проекта*. Ее свободный резерв времени остается запасом до окончания проекта. Условия: окно границ (раннее начало и раннее окончание на двух границах) действует, только если файл запланировал веху так, что плановое окончание раньше планового начала. Давление на цепочку действует для каждой вехи окончания без последователя. Встречалось только в выводе P3; на файлах, рассчитанных P6, не действует. По умолчанию: выкл. во всех встроенных профилях.

**Завершенная задача в окне даты отчета о состоянии** — Завершенная задача получает в качестве ранних дат окно даты отчета о состоянии. Это окно учитывается в окончании проекта и в резерве времени. Условия: только с датой отчета о состоянии, для завершенных задач из файла `.xer` с типом процента завершения *длительность* и типом задачи *Фиксированная длительность и трудозатраты* (в P6: Fixed Duration & Units). Без вех. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*. Встречалось только в выводе P3. По умолчанию: выкл. во всех встроенных профилях.

**Завершенная LOE-задача через ее фактическое окончание** — Завершенная задача LOE только с входящей связью начало-начало и без последователя идет по пути через свое фактическое окончание. Обычный путь гамака она не использует. Условия: только для задач из файла `.xer`. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*, *Сохранять фактические даты в обратном расчете* и *Переносить фактические даты точно*. Встречалось только в выводе P3. По умолчанию: выкл. во всех встроенных профилях.

**Завершенный предшественник не удерживается за датой отчета о состоянии** — Если завершенный предшественник по своему фактическому окончанию заканчивается позже даты отчета о состоянии, связи окончание-начало и окончание-окончание считаются от границы окна даты отчета о состоянии. Они не считаются от этого фактического окончания. Связи начало-начало остаются на фактическом начале. Условия: только с почасовым планированием и с датой отчета о состоянии. По умолчанию: выкл. во всех встроенных профилях.

**Завершенная задача с нарушением последовательности ждет своих предшественников** — Завершенная задача, у которой предшественник еще не завершен (с нарушением последовательности), получает свое окно без оставшихся трудозатрат не на дате отчета о состоянии. Оно попадает на более позднее из двух: дата отчета о состоянии и обычная граница связи этого предшественника. Условия: только с почасовым планированием. Работает на маршруте даты отчета о состоянии правила *Завершенная задача в окне даты отчета о состоянии*, поэтому также только для задач из файла `.xer`. Это правило и *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат* должны быть включены. Не работает с *Progress Override*. По умолчанию: выкл. во всех встроенных профилях.

## Параметры расчета этого проекта

Эти параметры находятся в разделе *Параметры расчета этого проекта*, под правилами расчета. Если примененные параметры расчета проекта отличаются от значения по умолчанию выбранного профиля, сверху появляется оранжевый блок. Если вы сами меняете поля, блок ждет, пока вы выберете *Применить* или *Отклонить*. Иначе он назвал бы другие значения, чем показывают поля. Выбор другого профиля сразу обновляет блок. Для каждого отличия блок называет поле, текущее значение и значение по умолчанию, например: *Определение критичности: Самый длинный путь (по умолчанию: общий резерв времени ≤ 0 часов)*. Пустое поле считается значением по умолчанию, которое показывает поле. Для пользовательского профиля действует значение по умолчанию его базового профиля. Кнопка *Использовать настройки по умолчанию для «Primavera P6»* (с названием профиля) задает полям это значение по умолчанию. Приложение рассчитывает только после *Применить*, одним шагом. Этот расчет можно отменить через *Отменить*. Крестик скрывает блок для этого открытого файла. После повторного открытия или при новом отличии блок появляется снова. Без отличий блока нет. Что кнопка делает с параметрами из исходного файла, описано в разделе *Параметры из исходного файла*. Значения по умолчанию для каждого профиля: *Open Planner Studio* и *Microsoft Project* не имеют собственных значений, поэтому каждый параметр ниже имеет значение по умолчанию (для *Microsoft Project* правило *Автоматически (по умолчанию)* с датой отчета о состоянии также является правилом резерва времени MS Project). *Primavera P6* задает: *Календарь задержки* — *Предшественник*; *Определение критичности* — *Общий резерв времени ≤ пороговое значение* с пороговым значением 0 часов; *Расчет резерва времени* — *Резерв окончания*; *Задачи с открытым окончанием критические* — выключено; *Рассчитывать задержку SS для начатого предшественника от* — *Раннее начало (начало оставшейся длительности)*. Файл `.xer` также передает значения из самого файла.

**Определение критичности** — что делает задачу критической. Выберите *Общий резерв времени ≤ пороговое значение* или *Самый длинный путь*. По умолчанию: *Общий резерв времени ≤ пороговое значение* с пороговым значением 0. Эффект: при значении *Общий резерв времени ≤ пороговое значение* задача критическая, если ее общий резерв времени меньше или равен пороговому значению. При значении *Самый длинный путь* задача критическая, если она лежит на цепочке, которая ведет к последнему окончанию. При нескольких последних задачах с одинаковым окончанием учитываются все их цепочки. Резерв времени в этом случае не играет роли. В обоих случаях завершенная задача никогда не критическая, и гамак тоже не может быть критическим. Это действует на диаграмму Ганта, таблицу, обзор вех и отчеты. Где: в разделе *Параметры расчета этого проекта*.

**Пороговое значение (рабочие дни)** — предельное значение для *Общий резерв времени ≤ пороговое значение*. По умолчанию: 0. Эффект: пороговое значение может быть отрицательным. Пороговое значение из файла `.xer` или заданное по умолчанию для *Primavera P6* (0 часов) измеряется в часах. Тогда оно называется *Пороговое значение (часов, по календарю задачи)*, и приложение сравнивает его для каждой задачи в часах календаря этой задачи. Где: в разделе *Параметры расчета этого проекта*, рядом с полем *Определение критичности*.

**Расчет резерва времени** — какой резерв является общим резервом времени. Выберите *Автоматически (по умолчанию)*, *Наименьший (начало/окончание)*, *Резерв начала* или *Резерв окончания*. По умолчанию: *Автоматически (по умолчанию)*, так же для *Microsoft Project*. *Primavera P6* задает *Резерв окончания*. Эффект: *Резерв начала* — это позднее начало минус раннее начало. *Резерв окончания* — это позднее окончание минус раннее окончание. *Наименьший (начало/окончание)* — это меньшее из двух значений. *Автоматически (по умолчанию)* использует резерв окончания для задачи в ходе выполнения, то есть для задачи с фактическим началом или ходом выполнения и с датой отчета о состоянии. Для всех остальных задач оно использует наименьший резерв. При наличии даты отчета о состоянии это правило MS Project. Без даты отчета о состоянии ход выполнения не учитывается, и начатая задача также получает наименьший резерв. MS Project в этом случае все равно берет резерв окончания для начатой задачи. Открытый файл .mpp и новый проект с *Microsoft Project* рассчитываются именно так. *Наименьший (начало/окончание)* берет меньшее значение и для задачи в ходе выполнения. Где: в разделе *Параметры расчета этого проекта*.

**Задачи с открытым окончанием критические** — задача без последователя. По умолчанию: выключено. Эффект: при включении такая задача получает общий и свободный резерв времени 0. Поэтому при определении критичности *Общий резерв времени ≤ пороговое значение* она становится критической, если она не выполнена. При выключении резерв рассчитывается обычным образом, до конца проекта. Где: в разделе *Параметры расчета этого проекта*.

**Отмечать почти критические** — отмечает задачи с почти нулевым резервом времени. По умолчанию: выключено. Эффект: при включении появляется пороговое значение, по умолчанию 2 рабочих дня (поле *Пороговое значение*). Задача с общим резервом времени больше 0 и не больше этого порога называется *Почти критическая*. Задача с резервом времени ровно 0 критическая и сюда не входит. Вы видите это в столбце *Почти критическая*, в отчетах и на диаграмме Ганта, где полоса становится янтарной, если задача не критическая. Поле показывает рабочие дни. При включенном параметре *Включить почасовое планирование* поле показывает часы, если отображение длительности — *Всегда в часах*, или *Автоматически (собственная единица каждой задачи)*, если календарь проекта часовой. Где: в разделе *Параметры расчета этого проекта*.

**Несколько путей резерва времени** — нумерует цепочки задач по их резерву времени. По умолчанию: выключено. Эффект: при включении задачи получают номер в столбце *Путь резерва времени*. На диаграмме Ганта полосы пути 2 и выше получают собственный оттенок, если они не критические и не почти критические. При выключении столбец остается пустым. Где: в разделе *Параметры расчета этого проекта*.

**Способ** — как возникают пути при включенном параметре *Несколько путей резерва времени*. Выберите *Свободный резерв времени (peeling)* или *Общий резерв времени (ranking)*. По умолчанию: *Свободный резерв времени (peeling)*. Эффект: при значении *Свободный резерв времени (peeling)* приложение отсекает цепочки. Оно выбирает задачу с последним окончанием и добавляет ее предшественников по определяющим связям. Это путь 1. Из оставшихся задач оно делает то же самое для пути 2 и так далее. Общий предшественник сохраняет номер первого пути, в котором он встречается. При значении *Общий резерв времени (ranking)* номер — это ранг общего резерва времени задачи: 1 для наименьшего значения, 2 для следующего наименьшего. Гамаки в этом не участвуют. Где: в разделе *Параметры расчета этого проекта*.

**Макс. путей** — сколько путей получают номер. По умолчанию: 10. Эффект: задачи, которые не попадают в первые пути или ранги до значения *Макс. путей*, номера не получают. Где: в разделе *Параметры расчета этого проекта*, вместе с параметром *Несколько путей резерва времени*.

**Календарь задержки** — в каком календаре задержка в рабочем времени считается. Выберите *Предшественник*, *Последователь*, *24-часовой* или *Календарь проекта*. По умолчанию: *Предшественник*. Эффект: задержка в 2 дня считается в рабочих днях выбранного вами календаря. Где: в разделе *Параметры расчета этого проекта*. См. [Связи и задержка](docs://uitleg-relaties).

**Рассчитывать задержку SS для начатого предшественника от** — вариант правила расчета *Прошедшая задержка SS от предшественника в ходе выполнения не учитывается*. Выберите *Раннее начало (начало оставшейся длительности)* или *Дата отчета о состоянии (P6: Actual Start)*. По умолчанию: *Раннее начало (начало оставшейся длительности)*. Эффект: для связи «начало-начало» с положительной задержкой в рабочем времени от предшественника в ходе выполнения последователь при значении *Раннее начало (начало оставшейся длительности)* начинается с начала оставшихся трудозатрат предшественника плюс оставшаяся задержка. При значении *Дата отчета о состоянии (P6: Actual Start)* он начинается с даты отчета о состоянии плюс оставшаяся задержка. Связь при этом не ограничивает предшественника в ходе выполнения назад. Оставшаяся задержка — это задержка минус рабочее время между фактическим началом и датой отчета о состоянии, но не меньше 0. Задержка 0 или меньше, задержка в календарных часах и график в днях сохраняют обычное поведение. Выбор работает, только если включены оба правила: *Прошедшая задержка SS от предшественника в ходе выполнения не учитывается* и *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*. Иначе раскрывающийся список отключен, и появляется текст *Работает, только если правило расчета «…» включено.* Если в выбранном календаре задержек нет почасового планирования, раскрывающийся список также отключен, и появляется текст *Работает только в режиме почасового планирования: нужен календарь с рабочими блоками или задачами в часах. В этом проекте в выбранном календаре для задержек нет ни того, ни другого.* Почасовое планирование всегда есть при значении *24-часовой*, при значении *Календарь проекта*, если в календаре проекта есть рабочие блоки, и при значениях *Предшественник* и *Последователь*, если в каком-либо календаре проекта есть рабочие блоки или задача в часах. Где: в разделе *Параметры расчета этого проекта*.

### Параметры из исходного файла

Эти параметры берутся из файла Primavera P6 `.xer` и доступны только для чтения. Блок *Параметры из исходного файла* появляется, только если проект содержит эти параметры, то есть для проекта из файла `.xer`. Они учитываются в расчете. Кнопка *Использовать настройки по умолчанию для «…»* и переход на другой профиль оставляют их такими, как их задал файл. Они также не считаются отличием. Новый проект их не получает, даже с *Primavera P6*.

**Использовать ожидаемые даты окончания (P6: Use Expected Finish Dates)** — По умолчанию (если файл ничего не говорит): включено. Эффект: задача P6 в ходе выполнения с ожидаемой датой окончания получает эту дату как свое раннее окончание. Где: в разделе *Параметры из исходного файла*.

**Рассчитывать резерв времени до окончания проекта** — По умолчанию: выключено. Эффект: дата окончания проекта служит опорной точкой для поздних дат. Без даты окончания в файле приложение рассчитывает до конца сети. Где: в разделе *Параметры из исходного файла*.

**Завершенная задача: поздние даты от даты отчета о состоянии** — По умолчанию (если файл ничего не говорит): включено. Эффект: завершенная задача также получает нулевую оставшуюся длительность на дате отчета о состоянии на позднюю сторону, с осмысленным резервом времени. Это работает только вместе с правилом *Завершенная задача в окне даты отчета о состоянии*, которое выключено во всех встроенных профилях. Если оно выключено, появляется текст *Действует только вместе с правилом расчета «…», которое сейчас выключено.* Где: в разделе *Параметры из исходного файла*.
