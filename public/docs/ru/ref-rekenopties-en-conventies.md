# Параметры расчета и правила расчета

Все выборы, которые определяют, как приложение рассчитывает график, как вы их найдете в разделе *Профиль расчета и параметры расчета*: профиль расчета, 27 правил расчета в каждом профиле и параметры расчета проекта. Почему P6 и MS Project рассчитывают по-разному, описано в [Профили расчета и правила расчета](docs://uitleg-rekenprofielen); что это значит для ваших дат, описано в [Даты как записаны](docs://uitleg-datums-zoals-opgeslagen).

## Где их найти и как они работают

Выберите *Настройки › Проект › Сведения о проекте* или *Файл › Сведения о проекте*. Внизу находится раздел *Профиль расчета и параметры расчета*. В окне *Новый проект* есть только выпадающий список *Профиль расчета*: выбор сразу применяет параметры по умолчанию этого профиля.

**Для каждого проекта, а не для всего приложения.** Профиль расчета и параметры относятся к файлу проекта и сохраняются с ним при *Сохранить* (IFC). Поэтому два человека, которые открывают один и тот же файл, рассчитывают одинаково. CSV и P6 XML их не содержат; из параметров расчета MS Project XML сохраняет только пороговое значение критичности. См. [Форматы импорта и экспорта](docs://ref-import-exportformaten). Ваши собственные шаблоны действуют для всего приложения: приложение хранит их на этом устройстве.

**Только при применении.** Ваши изменения в этом разделе остаются черновиком, пока вы не нажмете *Применить*. Затем приложение выполняет пересчет графика, даже если *Автоматический расчет* выключен. Если задачи сдвинулись, приложение сообщает, сколько (*После применения 3 задачи сдвинулись.*). Если ни одна задача не сдвинулась, сообщения нет. Это изменение можно отменить кнопкой *Отменить*. Применение также переключает вид на *Даты как записаны*. Изменение, которое ничего не меняет, ничего не делает. В *Файл › Сведения о проекте* вы отклоняете черновик кнопкой *Отклонить*.

## Профиль расчета

**Профиль расчета** — основа, по которой приложение рассчитывает. Можно выбрать *Primavera P6*, *Microsoft Project* или *Open Planner Studio*, а также собственные шаблоны и собственный профиль расчета этого проекта. По умолчанию: *Open Planner Studio* для нового проекта и для проекта без профиля расчета. Результат: профиль расчета включает или выключает каждое из 27 правил расчета ниже. Открытый файл получает профиль расчета своего формата: файл `.xer` рассчитывается как *Primavera P6*, файл `.mpp` как *Microsoft Project*, а CSV, MS Project XML и P6 XML как *Open Planner Studio*. Файл IFC сохраняет профиль расчета, который в нем записан. Профиль расчета, который отличается от своей основы, называется *Primavera P6 (изменен)*, по названию основы. Если вы выберете другой профиль расчета в диалоге Сведения о проекте, параметры расчета останутся прежними. Установите для них значения по умолчанию нового профиля кнопкой *Применить стандартные параметры этого профиля*. Где: раздел *Профиль расчета и параметры расчета*, выпадающий список *Профиль расчета*.

**Включение или выключение правила расчета** — меняет профиль расчета. Результат: во встроенном профиле приложение само создает собственный профиль с именем *Копия Primavera P6* (или копия профиля, с которого вы начали), со всеми текущими значениями. Поле *Название этого собственного профиля* задает ему имя; без имени *Применить* не сработает. Где: раздел *Правила расчета этого профиля*.

**Сохранить как шаблон**, **Обновить шаблон из этого проекта**, **Обновить из шаблона** и **Удалить шаблон** — управляют вашим собственным профилем как шаблоном. Результат: шаблон — это сохраненный профиль расчета, который можно выбрать в любом проекте; проект хранит собственную копию. Если профиль проекта отличается от своего шаблона, появляется надпись *Этот профиль отличается от шаблона «…».* Шаблоны не входят в файл проекта. Где: под выпадающим списком, для собственного профиля.

## Правила расчета по профилям

Правило расчета — это правило, в котором программные пакеты планирования различаются. Каждое правило расчета включено или выключено. В разделе показан флажок для каждого правила, базовое значение (*базовое: вкл.* или *базовое: выкл.*) и, если вы отклонились от базы, кнопка *Вернуть базовое* и значок *изменено: 2* у группы. Стрелка перед строкой открывает ее объяснение. По умолчанию для каждого правила задает выбранный встроенный профиль. *Open Planner Studio* выключает все правила расчета. Под каждым правилом ниже описано, что делают *Primavera P6* и *Microsoft Project*.

### Выполнение и завершенные трудозатраты

**Сохранять фактические даты в обратном расчете** — При обратном расчете начатая задача сохраняет свое зафиксированное начало как позднее начало, если не включено *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат* (как в *Primavera P6*). Тогда ее позднее начало — это начало оставшихся трудозатрат. Завершенная задача сохраняет свои фактические даты как поздние даты. Поэтому завершенный последователь не сдвигает незавершенного предшественника назад в прошлое. Условия: только с датой отчета о состоянии. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат** — Раннее и позднее начало задачи в ходе выполнения указывают на то, где начинаются оставшиеся трудозатраты (более поздняя из даты отчета о состоянии и границы связи), а не на фактическое начало. При обратном расчете по связи начало-начало учитывается только оставшаяся длительность предшественника в ходе выполнения. Эта часть действует только на календаре в часах. Условия: это основа для параметра *Рассчитывать задержку SS для начатого предшественника от* и для правила *Прошедшая задержка SS от предшественника в ходе выполнения не учитывается*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Завершенная задача с физическим ходом выполнения стоит на дате отчета о состоянии** — Завершенная задача стоит одной точкой на дате отчета о состоянии, или позже, если этого требует предшественник. Она не стоит на своих фактических датах. Условия: только на календаре в часах и с датой отчета о состоянии. Правило относится к завершенным задачам и вехам из файла `.xer` с типом процента завершения *физический*, с фактическим окончанием не позже даты отчета о состоянии и без приостановки и возобновления (suspend/resume). Для других типов процента завершения, включая длительность по умолчанию в P6, это не измерено, и приложение это не применяет. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Плановое начало не служит нижней границей для задачи в ходе выполнения** — Плановое начало из файла не служит нижней границей для задачи в ходе выполнения (с фактическим началом и меньше 100%). Ее оставшиеся трудозатраты начинаются на дате отчета о состоянии, сразу после предшественников, даже если ее плановое начало позже. Это противоположность правила *Плановое начало как дополнительный нижний предел*. Условия: работает, только если включено *Плановое начало как дополнительный нижний предел*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Progress Override также не учитывает начатого последователя на позднем расчете** — Связь от незавершенного предшественника к последователю, который уже начат и не завершен, не учитывается на позднем расчете и в свободном резерве времени этого предшественника. Поэтому последователь не создает давления назад и не является определяющей связью. Условия: только с режимом учета выполнения *Progress Override*. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Связи и задержка

**Последователь начинается на границе окончания** — Связь окончание-начало без задержки, при которой последователь начинается ровно на окончании предшественника в конце блока рабочего времени, позволяет последователю начаться сразу на этом окончании, а не с начала следующего блока. При обратном расчете последователь просто показывает свое позднее начало как начало блока. Условия: только на календаре в часах. Файл ничего не помечает: приложение само распознает такую связь при открытии файла `.xer`. Связь, которую вы создаете сами, под это правило не попадает. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Обратная задержка от границы окончания** — Если при обратном расчете приложение вычитает рабочую задержку из точной границы окончания блока рабочего времени и попадает ровно на начало блока, этот момент становится границей окончания предыдущего блока. Также для связи окончание-окончание без задержки позднее окончание на конце блока остается на этой границе. Условия: только на календаре в часах. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Прошедшая задержка завершенного предшественника не учитывается** — Из положительной рабочей задержки после завершенного предшественника учитывается только та часть, которая на дате отчета о состоянии еще не прошла: задержка минус рабочее время между фактическим окончанием и датой отчета о состоянии, но не меньше 0. Условия: только на календаре в часах и с датой отчета о состоянии. Правило действует на позднем расчете и, при прямом расчете, только от завершенных предшественников с точкой или окном даты отчета о состоянии (см. *Завершенная задача с физическим ходом выполнения стоит на дате отчета о состоянии* и *Завершенная задача с нарушением последовательности ждет своих предшественников*). Завершенная задача, которая просто стоит на своих фактических датах, сохраняет полную задержку. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Прошедшая задержка SS от предшественника в ходе выполнения не учитывается** — При связи начало-начало с положительной рабочей задержкой от предшественника в ходе выполнения учитывается только та часть задержки, которая еще не прошла: задержка минус рабочее время между фактическим началом и датой отчета о состоянии, но не меньше 0. При прямом расчете это считается от начала оставшихся трудозатрат предшественника. При обратном расчете позднее начало предшественника равно позднему началу последователя минус эта оставшаяся задержка. Условия: только на календаре в часах. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*. Параметр *Рассчитывать задержку SS для начатого предшественника от* выбирает отправную точку. Задержки 0 или меньше, задержки в календарных часах и связи окончание-начало остаются как обычно. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Раннее окончание не раньше границы связи окончание-окончание** — При связи окончание-окончание раннее окончание последователя никогда не бывает раньше окончания предшественника плюс задержка. Если эта граница выпадает за рабочее время последователя, раннее окончание становится первой рабочей границей на этой границе или после нее. Начало остается прежним. Условия: только на календаре в часах и с рабочими задержками. Правило не действует при жестком ограничении окончания и для гамака. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Вехи и задачи LOE

**Веха следует за плановой границей календаря** — Веха без длительности остается на границе календаря, которую запланировал файл. Веха, которая стояла в начале дня, остается вехой начала. Веха, которая стояла в конце блока рабочего времени, может попасть на окончание предшественника. Условия: только на календаре в часах. Задача с длительностью 0 тоже может стоять на двух границах так (начало на начале следующего блока, окончание на конце предыдущего блока). Но это возможно, только если задача из файла `.xer` и ее плановое окончание раньше планового начала. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Не начатая задача LOE использует целевое окно** — Задача LOE, которая еще не начата (в приложении это гамак), с полным целевым окном принимает это целевое окно как свой отрезок. Условия: только на календаре в часах. Задача должна быть из файла `.xer` с входящими связями только начало-начало и исходящими связями только окончание-окончание без задержки. Доказательство этого правила слабое: один файл. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Связь окончание-окончание с вехой начала привязывается к самой вехе** — Связь окончание-окончание с вехой начала (длительность 0, вид *Начало*) привязывается к позднему окончанию самой этой вехи, а не к началу дня вехи. Свободный резерв времени предшественника тогда больше не становится на один рабочий день короче. Раннее начало вехи никогда не меняется. Условия: только на календаре в часах. Веха окончания не меняется. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Резерв времени и поздние даты

**Значение свободного резерва времени никогда не бывает отрицательным** — Если позднее ограничение нельзя выполнить, общий резерв времени остается отрицательным. Для свободного резерва времени получается 0, а не отрицательное число. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Свободный резерв времени в собственном календаре задачи** — Свободный резерв времени незапущенной задачи считается по каждой связи в календаре самой задачи, а не в календаре последователя. Это верно для связей окончание-начало, начало-начало и окончание-окончание. Связь с задержкой (не 0) подпадает под это правило, только если календарь задержки — *Предшественник*. Иначе остается календарь последователя. Связь без задержки всегда подпадает под это правило. Начатая, но не завершенная задача следует этому правилу только при связи окончание-начало без задержки. Условия: только на календаре в часах. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Позднее окончание в собственном календаре задачи** — Если последователь навязывает позднее окончание, которое выпадает за рабочее время задачи, позднее окончание становится концом предыдущего рабочего периода в собственном календаре задачи. Более жесткое ограничение или крайний срок побеждает. Это обратная сторона правила *Свободный резерв времени в собственном календаре задачи* для позднего расчета. Условия: только на календаре в часах и не для окончания проекта. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Задачи ALAP как можно позже, насколько позволяют последователи** — Незапущенная задача с ограничением *Как можно позже (ALAP)* получает как раннее окончание самую строгую границу, которую допускают ее последователи с их ранними датами, с точностью до минуты. Ее раннее начало — это окончание минус ее длительность. Собственное плановое окно не учитывается. Нижняя граница — предшественники и дата отчета о состоянии. Условия: только на календаре в часах. На календаре в днях остается обычный шаг в целых рабочих днях. Что задача ALAP размещается как можно позже и что последователи считаются первыми, так что цепочка ALAP сходится, верно во всех профилях, в целых рабочих днях. Это правило добавляет размещение с точностью до минуты по ранним датам последователей. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Даты и моменты из файла

**Плановое начало как дополнительный нижний предел** — Плановое начало из файла считается дополнительным нижним пределом рядом с сетью. Но только если и начало, и окончание позже, чем допускает сеть, больше чем на один календарный день. Обычное начало на следующем блоке рабочего времени это правило не запускает. Условия: правило не действует для задачи в ходе выполнения, пока включено *Плановое начало не служит нижней границей для задачи в ходе выполнения*. Оно также не действует для незапущенной задачи ALAP, которую *Задачи ALAP как можно позже, насколько позволяют последователи* размещает от ее последователей. Правило не смотрит, откуда задача пришла. Оно смотрит только на ее плановое начало и окончание. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Переносить фактические даты точно** — Записанные фактические даты начала и окончания, с их временем суток, остаются точными. Их не переносят на край блока рабочего времени. Условия: только для задач из файла `.xer`. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

**Точный момент ограничения у вехи** — Ограничение с датой и временем (SNLT, MSO, FNLT или MFO) на вехе без длительности является точным моментом. Это верно, даже если этот момент — начало блока рабочего времени. Условия: только на календаре в часах и на позднем расчете. При прямом расчете такой момент уже точный во всех профилях. По умолчанию: вкл. в Primavera P6, выкл. в Microsoft Project и Open Planner Studio.

### Выполнение, как в Microsoft Project

**Оставшиеся трудозатраты возобновляются после прошедшей астрономической длительности** — Задача в ходе выполнения возобновляет свои оставшиеся трудозатраты на самой поздней из трех точек: дата отчета о состоянии, граница предшественника и фактическое начало плюс уже прошедшая астрономическая длительность. В *Primavera P6* (Retained Logic) учитываются только первые две точки. Третий предел может только сдвинуть оставшиеся трудозатраты позже. Условия: не с *Progress Override*, не когда оставшихся трудозатрат не осталось и не когда файл задает дату возобновления (Resume) для задачи (с максимум одним назначением). По умолчанию: вкл. в Microsoft Project, выкл. в Primavera P6 и Open Planner Studio.

**Не сдвигать не начатые задачи на дату отчета о состоянии** — Задача без хода выполнения сама по себе не сдвигается на дату отчета о состоянии или после нее. Если выключено, применяется нижний предел, который у P6 есть при Retained Logic. По умолчанию: вкл. в Microsoft Project, выкл. в Primavera P6 и Open Planner Studio.

### Только для пользовательских профилей

Эти правила выключены во всех встроенных профилях, в том числе в Primavera P6. Если включить одно из них, профиль становится пользовательским.

**Веха окончания как окно границ** — Веха окончания может стоять на двух соседних границах календаря: раннее начало в начале блока рабочего времени и раннее окончание на конце предыдущего блока. На позднем расчете веха окончания без последователя, но с предшественниками, получает свои ранние даты как поздние. Поэтому она давит на свою цепочку назад, если не включено *Рассчитывать резерв времени до окончания проекта*. Ее свободный резерв времени остается запасом до окончания проекта. Условия: окно границ (раннее начало и раннее окончание на двух границах) действует, только если файл запланировал веху так, что плановое окончание раньше планового начала. Давление на цепочку действует для каждой вехи окончания без последователя. Встречалось только в выводе P3; на файлах, рассчитанных P6, не действует. По умолчанию: выкл. во всех встроенных профилях.

**Завершенная задача в окне даты отчета о состоянии** — Завершенная задача получает в качестве ранних дат окно даты отчета о состоянии. Это окно учитывается в окончании проекта и в резерве времени. Условия: только с датой отчета о состоянии, для завершенных задач из файла `.xer` с типом процента завершения *длительность* и типом длительности *Фиксированная длительность и трудозатраты* (в P6: Fixed Duration & Units). Без вех. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*. Встречалось только в выводе P3. По умолчанию: выкл. во всех встроенных профилях.

**Завершенная LOE-задача через ее фактическое окончание** — Завершенная задача LOE только с входящей связью начало-начало и без последователя идет по пути через свое фактическое окончание. Обычный путь гамака она не использует. Условия: только для задач из файла `.xer`. Требует *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат*, *Сохранять фактические даты в обратном расчете* и *Переносить фактические даты точно*. Встречалось только в выводе P3. По умолчанию: выкл. во всех встроенных профилях.

**Завершенный предшественник не удерживается за датой отчета о состоянии** — Если завершенный предшественник по своему фактическому окончанию заканчивается позже даты отчета о состоянии, связи окончание-начало и окончание-окончание считаются от границы окна даты отчета о состоянии. Они не считаются от этого фактического окончания. Связи начало-начало остаются на фактическом начале. Условия: только на календаре в часах и с датой отчета о состоянии. По умолчанию: выкл. во всех встроенных профилях.

**Завершенная задача с нарушением последовательности ждет своих предшественников** — Завершенная задача, у которой предшественник еще не завершен (с нарушением последовательности), получает свое окно без оставшихся трудозатрат не на дате отчета о состоянии. Оно попадает на более позднее из двух: дата отчета о состоянии и обычная граница связи этого предшественника. Условия: работает на маршруте даты отчета о состоянии из правила *Завершенная задача в окне даты отчета о состоянии*. Не работает с *Progress Override*. По умолчанию: выкл. во всех встроенных профилях.

## Параметры расчета этого проекта

Эти параметры находятся в разделе *Параметры расчета этого проекта*, под правилами расчета. Кнопка *Применить стандартные параметры этого профиля* возвращает редактируемые параметры к значениям по умолчанию выбранного профиля. Что она делает с параметрами из исходного файла, описано в разделе *Параметры из исходного файла*. Значения по умолчанию для каждого профиля: *Open Planner Studio* и *Microsoft Project* не имеют собственных значений, поэтому каждый параметр ниже имеет значение по умолчанию. Для *Microsoft Project* правило *Автоматически (по умолчанию)* с датой отчета о состоянии также является правилом резерва времени MS Project. *Primavera P6* задает: *Календарь задержки* — *Предшественник*; *Определение критичности* — *Общий резерв времени ≤ пороговое значение* с пороговым значением 0 часов; *Расчет резерва времени* — *Резерв окончания*; *Задачи с открытым окончанием критические* — выключено; *Рассчитывать задержку SS для начатого предшественника от* — *Раннее начало (начало оставшейся длительности)*. Файл `.xer` также передает значения из самого файла.

**Определение критичности** — что делает задачу критической. Выберите из *Общий резерв времени ≤ пороговое значение* и *Самый длинный путь*. По умолчанию: *Общий резерв времени ≤ пороговое значение* с пороговым значением 0. Эффект: при значении *Общий резерв времени ≤ пороговое значение* задача критическая, если ее общий резерв времени меньше или равен пороговому значению. При значении *Самый длинный путь* задача критическая, если она лежит на цепочке, которая ведет к последнему окончанию. При нескольких последних задачах с одинаковым окончанием учитываются все их цепочки. Резерв времени в этом случае не играет роли. В обоих случаях выполненная задача никогда не критическая, и гамак тоже не может быть критическим. Это действует на диаграмму Ганта, таблицу, обзор вех и отчеты. Где: в разделе *Параметры расчета этого проекта*.

**Пороговое значение (рабочие дни)** — предельное значение для *Общий резерв времени ≤ пороговое значение*. По умолчанию: 0. Эффект: пороговое значение может быть отрицательным. Пороговое значение из файла `.xer` или заданное по умолчанию для *Primavera P6* (0 часов) измеряется в часах. Тогда оно называется *Пороговое значение (часов, по календарю задачи)*, и приложение сравнивает его для каждой задачи в часах календаря этой задачи. Где: в разделе *Параметры расчета этого проекта*, рядом с *Определение критичности*.

**Расчет резерва времени** — какой резерв является общим резервом времени. Выберите из *Автоматически (по умолчанию)*, *Наименьший (начало/окончание)*, *Резерв начала* и *Резерв окончания*. По умолчанию: *Автоматически (по умолчанию)*, так же для *Microsoft Project*. *Primavera P6* задает *Резерв окончания*. Эффект: *Резерв начала* — это позднее начало минус раннее начало. *Резерв окончания* — это позднее окончание минус раннее окончание. *Наименьший (начало/окончание)* — это меньшее из двух значений. *Автоматически (по умолчанию)* использует резерв окончания для задачи в ходе выполнения, то есть с фактическим началом или ходом выполнения и с датой отчета о состоянии. Для всех остальных задач оно использует наименьший резерв. При наличии даты отчета о состоянии это правило MS Project. Без даты отчета о состоянии ход выполнения не учитывается, и начатая задача также получает наименьший резерв. MS Project в этом случае все равно берет резерв окончания для начатой задачи. Открытый файл .mpp и новый проект с *Microsoft Project* рассчитываются именно так. *Наименьший (начало/окончание)* берет меньшее значение также для задачи в ходе выполнения. Где: в разделе *Параметры расчета этого проекта*.

**Задачи с открытым окончанием критические** — задача без последователя. По умолчанию: выключено. Эффект: при включении такая задача получает общий и свободный резерв времени 0. Поэтому при *Общий резерв времени ≤ пороговое значение* она становится критической, если она не выполнена. При выключении резерв рассчитывается обычно, до конца проекта. Где: в разделе *Параметры расчета этого проекта*.

**Отмечать почти критические** — отмечает задачи с почти нулевым резервом времени. По умолчанию: выключено. Эффект: при включении появляется пороговое значение, по умолчанию 2 рабочих дня (поле *Пороговое значение*). Задача с общим резервом времени больше 0 и не больше этого порога называется *Почти критическая*. Задача с резервом времени ровно 0 критическая и сюда не входит. Вы видите это в столбце *Почти критическая*, в отчетах и на диаграмме Ганта, где полоса становится желтой, если задача не критическая. Поле показывает рабочие дни. При включенном *Включить почасовое планирование* оно показывает часы, если отображение длительности *Всегда в часах*, или *Автоматически (собственная единица каждой задачи)*, если календарь проекта является часовым. Где: в разделе *Параметры расчета этого проекта*.

**Несколько путей резерва времени** — нумерует цепочки задач по их резерву времени. По умолчанию: выключено. Эффект: при включении задачи получают номер в столбце *Путь резерва времени*. На диаграмме Ганта полосы пути 2 и выше получают собственный оттенок, если они не критические и не почти критические. При выключении столбец остается пустым. Где: в разделе *Параметры расчета этого проекта*.

**Способ** — как возникают пути при включенных *Несколько путей резерва времени*. Выберите из *Свободный резерв времени (peeling)* и *Общий резерв времени (ranking)*. По умолчанию: *Свободный резерв времени (peeling)*. Эффект: при значении *Свободный резерв времени (peeling)* приложение отсекает цепочки. Оно выбирает задачу с последним окончанием и добавляет ее предшественников по определяющим связям. Это путь 1. Из оставшихся задач оно делает то же самое для пути 2 и так далее. Общий предшественник сохраняет номер первого пути, в котором он встречается. При значении *Общий резерв времени (ranking)* номер — это ранг общего резерва времени задачи: 1 для наименьшего значения, 2 для следующего наименьшего. Гамаки в этом не участвуют. Где: в разделе *Параметры расчета этого проекта*.

**Макс. путей** — сколько путей получают номер. По умолчанию: 10. Эффект: задачи, не попавшие в первые *Макс. путей* путей или рангов, не получают номера. Где: в разделе *Параметры расчета этого проекта*, вместе с *Несколько путей резерва времени*.

**Календарь задержки** — в каком календаре задержка в рабочем времени считается. Выберите из *Предшественник*, *Последователь*, *24-часовой* и *Календарь проекта*. По умолчанию: *Предшественник*. Эффект: задержка в 2 дня считается в рабочих днях выбранного вами календаря. Где: в разделе *Параметры расчета этого проекта*. См. [Связи и задержка](docs://uitleg-relaties).

**Рассчитывать задержку SS для начатого предшественника от** — вариант правила *Прошедшая задержка SS от предшественника в ходе выполнения не учитывается*. Выберите из *Раннее начало (начало оставшейся длительности)* и *Фактическое начало (дата отчета о состоянии)*. По умолчанию: *Раннее начало (начало оставшейся длительности)*. Эффект: для связи начало-начало с положительной задержкой в рабочем времени от предшественника в ходе выполнения последователь при значении *Раннее начало (начало оставшейся длительности)* начинается с начала оставшихся трудозатрат предшественника плюс оставшаяся задержка. При значении *Фактическое начало (дата отчета о состоянии)* он начинается с даты отчета о состоянии плюс оставшаяся задержка. Связь при этом не ограничивает предшественника в ходе выполнения назад. Оставшаяся задержка — это задержка минус рабочее время между фактическим началом и датой отчета о состоянии, но не меньше 0. Задержка 0 или меньше, задержка в календарных часах и график в днях сохраняют обычное поведение. Выбор работает, только если оба правила *Прошедшая задержка SS от предшественника в ходе выполнения не учитывается* и *Задача в ходе выполнения: раннее начало = начало оставшихся трудозатрат* включены. Иначе раскрывающийся список отключен, и появляется текст *Работает, только если правило расчета «…» включено.* Где: в разделе *Параметры расчета этого проекта*.

### Параметры из исходного файла

Эти параметры берутся из файла Primavera P6 `.xer` и доступны только для чтения. Блок *Параметры из исходного файла* появляется, только если в проекте есть эти параметры. Они учитываются в расчете. *Использовать ожидаемые даты окончания (P6: Use Expected Finish Dates)* и *Выполненная задача: поздние даты от даты отчета о состоянии* также задают значение по умолчанию *Primavera P6*: при создании через *Новый проект* или через *Применить стандартные параметры этого профиля*. *Применить стандартные параметры этого профиля* оставляет *Рассчитывать резерв времени до окончания проекта* без изменений. Кнопка задает для двух других параметров значение по умолчанию профиля: для профиля *Primavera P6* они включаются, даже если файл говорит «выключено». При профилях *Microsoft Project* и *Open Planner Studio* они исчезают.

**Использовать ожидаемые даты окончания (P6: Use Expected Finish Dates)** — По умолчанию в P6: включено. Эффект: задача P6 в ходе выполнения с ожидаемой датой окончания получает эту дату как свое раннее окончание. Где: в разделе *Параметры из исходного файла*.

**Рассчитывать резерв времени до окончания проекта** — По умолчанию: выключено. Эффект: дата окончания проекта служит опорной точкой для поздних дат. Без даты окончания в файле приложение рассчитывает до конца сети. Где: в разделе *Параметры из исходного файла*.

**Выполненная задача: поздние даты от даты отчета о состоянии** — По умолчанию в P6: включено. Эффект: выполненная задача также получает нулевую оставшуюся длительность на дате отчета о состоянии на позднюю сторону, с осмысленным резервом времени. Это работает только вместе с правилом *Завершенная задача в окне даты отчета о состоянии*, которое выключено во всех встроенных профилях. Если оно выключено, появляется текст *Действует только вместе с правилом расчета «…», которое сейчас выключено.* Где: в разделе *Параметры из исходного файла*.
