# Импорт и экспорт форматов

Для каждого формата файла: можно ли его открыть, сохранить и экспортировать, что переносится, а что нет, и с каким профилем расчета он открывается. Причины этого и пример с числами описаны в [Файлы и форматы](docs://uitleg-bestanden).

## Кратко

**Открытие** работает с IFC, CSV, MS Project XML, Primavera P6 XML, `.mpp` и `.xer`. Файл с любым другим расширением приложение считает IFC.

**Сохранение** всегда записывает IFC. Целью сохранения становится только открытый файл IFC. Проект из другого формата после открытия не имеет файла, и *Сохранить* тогда спрашивает, куда записать файл IFC.

**Экспорт** возможен в IFC, MS Project XML, Primavera P6 XML, CSV и две таблицы хода выполнения (Excel и CSV). Экспорт не меняет ваш проект.

**Только для чтения** — это `.mpp` и `.xer`: приложение может их открыть, но не записать.

**PDF** появляется только из отчета (см. [Типы отчетов](docs://ref-rapporttypes)). Приложение не читает PDF.

**Где.** Открытие: *Главная › Файл › Открыть*, *Файл › Открыть* или Ctrl+O. Экспорт: *Главная › Файл › Экспорт* или *Файл › Экспорт*. Заполненную таблицу хода выполнения вы загружаете через *Файл › Импорт* или кнопкой *Обновить ход выполнения из таблицы* в группе *Ход выполнения* на вкладках *График*, *Таблица* и *Отчет*.

**Профиль расчета при открытии.** Каждый формат открывается с профилем расчета. Что это такое, описано в [Параметры расчета и правила расчета](docs://ref-rekenopties-en-conventies). `.xer` открывается с *Primavera P6*, `.mpp` с *Microsoft Project*, а CSV, MS Project XML и P6 XML с *Open Planner Studio*. IFC сохраняет профиль, который хранится в файле. Для `.xer` и `.mpp` приложение сообщает, что проект рассчитывается именно так. Только IFC хранит профиль расчета и параметры расчета. Из параметров расчета MS Project XML записывает не более порогового значения критичности. Экспорт в другой формат, открытый снова, рассчитывается как *Open Planner Studio*.

## IFC

**Открытие** — да, `.ifc`. Приложение читает IFC4 и IFC 4.3 (включая ADD2). Файл в другой схеме, например IFC2X3, тоже открывается. При первом сохранении вы выбираете схему, которую приложение умеет записывать (см. [Выбор схемы IFC](docs://howto-ifc-schema-kiezen)). Профиль расчета: тот, что в файле.

**Сохранение** — да, и это единственный формат, в котором можно сохранять. *Сохранить* записывает весь ваш проект в файл IFC в схеме IFC проекта (по умолчанию IFC 4.3 ADD2). Файл становится целью сохранения.

**Экспорт** — да, как *IFC*, в схеме IFC проекта (по умолчанию IFC 4.3 ADD2). Имя по умолчанию: имя проекта с расширением `.ifc`. Если ваш проект связан с библиотекой ресурсов, флажок *Сохранить файл библиотеки рядом* находится под карточками в *Файл › Экспорт*. Если флажок установлен, приложение после файла проекта запрашивает место для *projectname-bibliotheek.ifc*. Флажка нет в списке на вкладке *Главная*.

**Что переносится** — все, что относится к проекту: задачи со структурой, длительностью, датами и ходом выполнения; связи с задержкой; ограничения и крайние сроки; календари; ресурсы и назначения, включая распределение трудозатрат по часам; базовые планы; коды задач и настраиваемые поля; примечания; внешние зависимости от других проектов; перерывы; правила трудозатрат и типы задач; настройки проекта, например дату отчета о состоянии, режим учета выполнения, профиль расчета и параметры расчета; связь с библиотекой ресурсов. Для проекта из `.xer` вместе с ним переносится и исходный файл. Настраиваемый вид работ сохраняется как тип IFC `USERDEFINED` с именем в поле ObjectType, поэтому другие программы IFC читают задачу как обычно. Приложение также сохраняет постоянный идентификатор вида работ, поэтому переименование не разрывает связь. Если кто-то откроет файл на другом компьютере, вид работ появится там в разделе *Из этого проекта*, а не в его списке *Мои виды работ*.

**Что не переносится** — настройка экрана (масштаб, положение прокрутки, выбранная задача, свернутые фазы, фильтр и группировка) и настройки приложения ([Настройки](docs://ref-instellingen)). Вкладка *IFC* — это редактор с текстом IFC вашего проекта. *Создать IFC* обновляет его, *Копировать* помещает его в буфер обмена, а *Применить* загружает текст как ваш проект, заменяя проект на этой вкладке.

## MS Project XML (MSPDI)

**Открытие** — да. Приложение распознает файл `.xml` как MS Project XML по корневому элементу `Project` в пространстве имен MS Project (или без пространства имен). Профиль расчета: *Open Planner Studio*. После открытия приложение в одном сообщении сообщает, что не перенесло; см. [Открытие файла MS Project (.mpp)](docs://howto-mpp-openen).

**Сохранение** — нет. У такого проекта нет цели сохранения.

**Экспорт** — да, как *MS Project XML* (*Открывается в Microsoft Project. Полная структура СДР.*). Имя по умолчанию: имя проекта с расширением `.xml`.

**Что переносится** — задачи со структурой (уровень и СДР), длительностью, датами и ходом выполнения; связи с задержкой, также в часах или процентах; ограничения, включая крайний срок; календари, включая календари задач и ресурсов; ресурсы и назначения, включая кривую или распределение трудозатрат по часам; дату отчета о состоянии; пороговое значение критичности в виде целого числа рабочих дней, 0 или больше, с отметкой *Общий резерв времени ≤ пороговое значение*; описание задачи (как примечание); тип задачи (как тип задачи MS Project); настраиваемый вид работ в свободном поле (`ExtendedAttribute`), которое приложение читает обратно и которое MS Project может игнорировать. Из ваших базовых планов переносится только активный, как базовый план 0. Задача в часах сохраняет свою единицу, а веха — свой вид (начало, окончание или автоматический).

**Что не переносится** — примечания (контрольный список задачи), внешние зависимости от других проектов, коды задач и настраиваемые поля, второе ограничение, отметку *Планируемая вручную*, выравнивающую задержку, точку возобновления и остановки задачи с выполнением с нарушением последовательности, правила расчета *Оставшиеся трудозатраты продолжаются после астрономической длительности* и *Незапущенные задачи не переносятся к дате отчета о состоянии* профиля MS Project, а также остальные параметры расчета. Задачи с перерывами без распределения трудозатрат по часам переносятся без этих перерывов.

**Праздничные дни при открытии.** Производный календарь наследует исключения своего базового календаря. Календарь с собственной рабочей неделей и без исключений праздничных дней не получает. Только простой календарь, без базового календаря, рабочей недели и исключений, сохраняет стандартные нидерландские праздничные дни. Если праздничных дней нет, ваша дата окончания может отличаться: см. [Создание праздничных дней и строительного отпуска](docs://howto-feestdagen-genereren).

**Что меняется по пути** — ограничение *Фиксированное начало (MSO)* или *Фиксированное окончание (MFO)* без выбора *Обязательная (жёсткая привязка)* становится *Начало не ранее (SNET)* или *Окончание не ранее (FNET)*. Гамак становится обычной задачей с рассчитанными датами. Файл MS Project XML хранит часы в день только для календаря проекта. Другой календарь со своими часами в день получает при открытии файла свое рабочее время как часы в день: 8 часов в день при рабочем времени 10 часов становится 10. Задача в днях на таком календаре тогда становится короче, например 4 дня вместо 5.

## Файл MS Project (`.mpp`)

**Открытие** — да, от MS Project 2010 до 2021. Профиль расчета: *Microsoft Project*. Приложение только читает файл: оно никогда не меняет ваш `.mpp`. Файл MS Project 2007 или старше, а также файл с паролем приложение не открывает и выводит сообщение с указанием на экспорт MS Project в XML. После открытия приложение в одном сообщении сообщает, что не перенесло.

**Сохранение** — нет, и цели сохранения нет: *Сохранить* записывает новый файл IFC.

**Экспорт** — нет.

**Что переносится** — задачи со структурой, длительностью и ограничениями; связи с задержкой; календари; ресурсы и назначения; ход выполнения; код СДР, который вы сами заполнили в MS Project. Даты и резерв времени, которые MS Project рассчитал сам, тоже читаются, для вида *Даты как записаны*.

**Что не переносится** — базовые планы, затраты и стандартные ставки, примечания, гиперссылки, настраиваемые поля MS Project, связь подпроектов и внешних задач, а также пороговое значение критичности. См. [Открытие файла MS Project (.mpp)](docs://howto-mpp-openen).

**Происхождение и лицензия** — модуль чтения `.mpp` написан для Open Planner Studio и основан на исходном коде и знании структуры MPXJ (`github.com/joniles/mpxj`, Jon Iles et al.), библиотеки Java по лицензии LGPL-2.1. Структура и константы полей перенесены на TypeScript. Сам Open Planner Studio — проект с открытым исходным кодом по лицензии LGPL-3.0. Модуль чтения `.xer` не является производным: MPXJ здесь использовалась только для ознакомления.

## Primavera P6 XML

**Открытие** — да. Приложение распознает файл `.xml` как P6 XML по корневому элементу `APIBusinessObjects`. Профиль расчета: *Open Planner Studio*.

**Несколько проектов в одном файле.** Каждый проект с задачами открывается на своей вкладке с именем *Название проекта (Код проекта)*. Приложение пропускает проект без задач. Активной вкладкой становится проект с наибольшим числом задач. Приложение не переносит связь с другим проектом и задачу, которая не относится ни к одному проекту. После открытия приложение сообщает, сколько проектов оно открыло.

**Праздничные дни при открытии.** Действуют те же правила, что и для MS Project XML: календарь с собственной рабочей неделей и без исключений не получает праздничных дней.

**Базовые планы.** `<BaselineProject>` в файле становится базовым планом своего проекта. Базовый план, который P6 отмечает как активный, в приложении тоже активен.

**Ставка назначения.** Если еще остаются трудозатраты, оставшаяся ставка (`RemainingUnitsPerTime`) становится *Ед./день*. Иначе ставкой становится плановая ставка (`PlannedUnitsPerTime`). Для материала плановая ставка сохраняется. Приложение при открытии файла ничего не пересчитывает. При экспорте в P6 XML оно записывает плановую ставку как `PlannedUnitsPerTime`. Оставшуюся ставку оно записывает как `RemainingUnitsPerTime` только тогда, когда у назначения есть отдельная плановая ставка.

**Нет читаемых задач.** Если приложение не находит ни одной читаемой задачи, оно не открывает вкладку. Оно сообщает об этом и, если причина известна, называет ее. Примеры: задачи без `ObjectId` или имена столбцов XER в файле XML. Тогда экспортируйте проект из P6 снова как P6 XML или откройте его как `.xer`.

**Сохранение** — нет.

**Экспорт** — да, как *Primavera P6 XML* (*Для Oracle Primavera P6.*). Имя по умолчанию: имя проекта с расширением `.xml`, а в скобках код проекта, если он у проекта есть. Экспорт в MS Project XML получает то же имя: дайте им разные имена сами.

**Название проекта и код проекта.** Приложение хранит код проекта из P6 отдельно от названия проекта, как и для `.xer`. *Настройки проекта* показывает только название, например *Bid for Facility Extension*. Вкладка показывает *Bid for Facility Extension (OZB-05)*. Если вы переименуете проект в *Hall extension*, вкладка называется *Hall extension (OZB-05)*. Экспорт в P6 XML записывает *OZB-05* обратно как код проекта, а *Hall extension* как название. Так P6 распознает проект. Проект из `.xer` также берет с собой свой код проекта. Код проекта остается, когда вы сохраняете проект как IFC. Скобки в самом названии, например *New build (phase 2)*, остаются в названии. Проект без кода проекта получает при экспорте собственный уникальный код от приложения, начинающийся с *OPS:*.

**Что переносится** — структура СДР и задачи с длительностью, датами и ходом выполнения; связи с задержкой; ограничения (также второе, как мягкое ограничение); календари; ресурсы и назначения; дата отчета о состоянии (как `DataDate`); настраиваемый вид работ в собственном поле `OPS Custom Task Type`, которое приложение читает обратно и которое P6 может игнорировать.

**Что не переносится** — базовые планы и крайние сроки; коды задач, настраиваемые поля, примечания и внешние зависимости; параметры расчета; названия праздничных дней. P6 не хранит название для каждого нерабочего дня: после повторного открытия праздничный день называется *Праздничный день*, а рабочее исключение — *Рабочее исключение*. Подряд идущие нерабочие дни возвращаются одним диапазоном. Приложение сокращает название или код, если они длиннее, чем допускает P6: название задачи до 120 символов, код задачи или код СДР до 40, название СДР или проекта до 100. Оно сообщает, сколько названий и кодов сократило. P6 не имеет задержки в процентах: приложение переводит ее в фиксированное число дней. Задержка в календарных днях становится задержкой в рабочем времени: 3 календарных дня становятся 3 рабочими днями. Гамак становится обычной задачей, задача, планируемая вручную, — обычной задачей с рассчитанными датами, а выравнивающая задержка меньше одного дня отбрасывается.

## Файл Primavera (`.xer`)

**Открытие** — да. Профиль расчета: *Primavera P6*. Приложение только читает файл: оно не записывает `.xer` и никогда не меняет ваш файл. Для каждого проекта с задачами открывается одна вкладка. Файл без задач или с поврежденными таблицами приложение не открывает и выводит сообщение.

**Сохранение** — нет, и цели сохранения нет: *Сохранить* записывает новый файл IFC, внутри которого находится исходный `.xer`.

**Экспорт** — нет. Если вы экспортируете проект из `.xer` в CSV, MS Project XML или P6 XML, приложение сообщает, что сведения об источнике XER теряются, даже если вы сохранили проект как IFC в промежутке. В IFC ничего не теряется.

**Что переносится** — структура СДР и задачи с длительностью, датами, ограничениями и ходом выполнения; связи с задержкой; календари; ресурсы с назначениями; коды задач; настраиваемые поля (UDF); примечания; настройки графика P6. Задача типа *Level of Effort* становится гамаком. Проект, служащий базовым планом, становится активным базовым планом того проекта, который на него ссылается. Связь между двумя проектами приложение сохраняет как исходные данные.

**Ставка назначения.** Если остались трудозатраты, остаточная ставка (`remain_qty_per_hr`) становится значением *Ед./день*. Иначе это плановая ставка (`target_qty_per_hr`). Плановые, фактические и оставшиеся трудозатраты остаются такими, как в файле. Для материала плановая ставка сохраняется.

**Свободная суббота или воскресенье, которых нет в файле.** Некоторые экспорты P6 переносят свободный выходной день внутри цепочки из нескольких свободных дней на предыдущую пятницу или на следующий понедельник. Если календарь работает в субботу или воскресенье, этот день ошибочно стал бы рабочим. Если приложение видит такой шаблон в цепочке не менее чем из трех свободных дней, оно все же делает этот выходной день свободным. В календаре этот день называется *Исключение календаря (восстановление выходных)*, и он учитывается в строке *N замечаний по календарю.* сообщения. В календаре, который не работает на выходных, ничего не меняется.

**Резерв времени до окончания проекта без даты окончания.** Включен ли в P6 параметр расчета резерва времени до окончания проекта, но в файле нет ни даты окончания проекта, ни плановой даты окончания ни у одной задачи? Тогда приложение отключает параметр *Рассчитывать резерв времени до окончания проекта*. Затем оно рассчитывает поздние даты, двигаясь назад от самого позднего раннего окончания. Это учитывается в строке *N настроек графика P6 заменены безопасными значениями по умолчанию.* сообщения.

**Выполненные задачи на дате отчета о состоянии.** Некоторые файлы не записывают фактические даты выполненной задачи, а записывают окно на дате отчета о состоянии. В представлении *Даты как записаны* такая задача тогда показана узкой полосой на дате отчета о состоянии. Если пересчет ставит ее в другое место, она попадает в число задач, которое дает полоса. Правило расчета *Завершенная задача в окне даты отчета о состоянии* рассчитывает такое окно, и только с этим правилом выполненная задача получает настоящий резерв времени через параметр расчета *Выполненная задача: поздние даты от даты отчета о состоянии*. Это правило расчета — приближение: приложение видело такое поведение только в выводе P3, а Primavera нигде это не подтверждает. Поэтому оно выключено в каждом встроенном профиле, в том числе в *Primavera P6*. Вы включаете его в блоке *Профиль расчета и параметры расчета*; тогда проект получает собственный профиль. См. [Параметры расчета и правила расчета](docs://ref-rekenopties-en-conventies).

**Числа с запятой как десятичным разделителем.** P6 записывает десятичный разделитель и разделитель тысяч в таблице `CURRTYPE`. Приложение считывает эти символы, прежде чем преобразовать длительности, трудозатраты и резерв времени. Если этих сведений нет, приложение использует точку как десятичный разделитель. Если в файле все еще есть числа с десятичной запятой, приложение ничего не открывает. Так график с неверно прочитанными числами никогда не открывается.

**Что не переносится** — проект без задач и связь между двумя проектами как настоящая связь в вашем графике. См. [Открытие файла Primavera P6 (.xer)](docs://howto-xer-openen).

## CSV

**Открытие** — да. Приложение читает `;` и `,` как разделитель. Оно распознает заголовки столбцов на английском и нидерландском языках (например, `Name` или `Naam`, `Duration` или `Duur`, `Predecessors` или `Voorgangers`). Даты могут быть в формате *гггг-мм-дд*, *дд-мм-гггг* или *дд/мм/гггг*. Предшественник записывается как код СДР, тип связи и задержка, например `1.2FS+2d`. Профиль расчета: *Open Planner Studio*. Проект называется *CSV Import*. Столбец `Task Type` содержит вид работ, а не тип задачи; приложение также читает заголовки `Werksoort` и `Work category`. Значение `Task Type`, которое не является ни одним из фиксированных кодов (например, `CONSTRUCTION` или `INSTALLATION`, которые приложение записывает само), становится настраиваемым видом работ в разделе *Из этого проекта*, а не в *Мои виды работ*; с `OPS Custom Task Type ID` сохраняется идентификатор настраиваемого вида работ.

**Сохранение** — нет.

**Экспорт** — да, как *CSV (;)* (*Универсальный экспорт таблицы. Все задачи с датами и длительностью.*), на карточке *CSV (разделитель «;»)*. Файл использует точку с запятой как разделитель, находится в кодировке UTF-8 с BOM и имеет заголовки столбцов на английском языке.

**Что переносится** — для каждой задачи эти столбцы: `OPS Task ID`, `WBS`, `Outline Level`, `Name`, `Duration (days)`, `Start`, `Finish`, `Predecessors`, `Task Type`, `OPS Custom Task Type ID`, `Status`, `Completion (%)`, `Actual Start`, `Actual Finish`, `Critical`, `Total Float` и `Description`. Столбец `Task Type` содержит вид работ. Процент завершения записывается целыми процентами. Задержка в часах получает обозначение часов языка приложения: `1.2FS+2h` на английском и `1.2FS+2u` на нидерландском. При открытии приложение читает оба варианта.

**Что не переносится** — ресурсы, назначения, календари, ограничения, крайние сроки, базовые планы и дата отчета о состоянии. Если даты показаны в представлении *Даты как записаны*, экспорт оставляет `Critical` и `Total Float` пустыми для задач, в исходном файле которых это не записано.

## Лист хода выполнения (Excel и CSV)

**Открытие** — да, через *Файл › Импорт* (*Обновить ход выполнения из таблицы*) или кнопкой с таким же названием в группе *Ход выполнения* на вкладках *График*, *Таблица* и *Отчет*. Приложение читает `.xlsx` и `.csv` размером до 16 МБ и до 50 000 строк. Проект это не открывает: оно обновляет ход выполнения вашего открытого проекта. См. [Импорт хода выполнения из таблицы](docs://howto-voortgang-importeren).

**Сохранение** — нет.

**Экспорт** — да, как *Лист хода выполнения (Excel)* (в списке *Ход выполнения (Excel)*) и *Лист хода выполнения (CSV)* (*Ход выполнения (CSV)*). Имя по умолчанию: *projectname-voortgang*. Кнопка *Экспортировать таблицу хода выполнения* в той же группе создает лист Excel в один щелчок. Лист Excel имеет фиксированную ширину столбцов, заблокированные поля и проверку дат; лист CSV содержит то же самое в виде обычного текста.

**Что переносится** — столбцы `OPS Task ID`, `WBS`, `Name`, `Start`, `Finish`, `Completion (%)`, `Actual Start` и `Actual Finish`. При загрузке приложение использует `Completion (%)`, `Actual Start` и `Actual Finish`; `Start` и `Finish` нужны только для распознавания формата дат и не меняют ваш график. Приложение связывает строки с задачами по `OPS Task ID` или иначе по уникальному коду СДР.

**Что не переносится** — все, что находится вне этих столбцов: длительность, связи, ресурсы и остальной график. Суммарная задача не получает ход выполнения из таблицы.

## PDF

**Открытие** — нет.

**Сохранение** — нет.

**Экспорт** — да, из отчета: на вкладке *Отчет* кнопка *Экспортировать в PDF*. Приложение само не отправляет отчет на принтер; бумажная версия получается через PDF. Содержание зависит от типа отчета: см. [Типы отчетов](docs://ref-rapporttypes) и [Создание и печать отчета](docs://howto-rapport-maken-en-afdrukken).
