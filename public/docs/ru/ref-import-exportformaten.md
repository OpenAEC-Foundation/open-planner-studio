# Импорт и экспорт форматов

Для каждого формата файла: можно ли его открыть, сохранить и экспортировать, что переносится, а что нет, и с каким профилем расчета он открывается. Причины этого и пример с числами описаны в [Файлы и форматы](docs://uitleg-bestanden).

## Кратко

**Открытие** работает с IFC, CSV, MS Project XML, Primavera P6 XML, `.mpp` и `.xer`. Файл с любым другим расширением приложение считает IFC.

**Сохранение** всегда записывает IFC. Целью сохранения становится только открытый файл IFC. Проект из другого формата после открытия не имеет файла, и *Сохранить* тогда спрашивает, куда записать файл IFC.

**Экспорт** выполняется в IFC 4x3, MS Project XML, Primavera P6 XML, CSV и две таблицы хода выполнения (Excel и CSV). Экспорт не меняет ваш проект.

**Только для чтения** — это `.mpp` и `.xer`: приложение может их открыть, но не записать.

**PDF** появляется только из отчета (см. [Типы отчетов](docs://ref-rapporttypes)). Приложение не читает PDF.

**Где.** Открытие: *Главная › Файл › Открыть*, *Файл › Открыть* или Ctrl+O. Экспорт: *Главная › Файл › Экспорт* или *Файл › Экспорт*. Заполненную таблицу хода выполнения вы загружаете через *Файл › Импорт* или кнопкой *Обновить ход выполнения из таблицы* в группе *Ход выполнения* на вкладках *График*, *Таблица* и *Отчет*.

**Профиль расчета при открытии.** Каждый формат открывается с профилем расчета. Что это такое, описано в [Параметры расчета и правила расчета](docs://ref-rekenopties-en-conventies). `.xer` открывается с *Primavera P6*, `.mpp` с *Microsoft Project*, а CSV, MS Project XML и P6 XML с *Open Planner Studio*. IFC сохраняет профиль, который хранится в файле. Для `.xer` и `.mpp` приложение сообщает, что проект рассчитывается именно так. Только IFC хранит профиль расчета и параметры расчета. Из параметров расчета MS Project XML записывает не более порогового значения критичности. Повторно открытый экспорт другого формата рассчитывается как *Open Planner Studio*.

## IFC

**Открытие** — да, `.ifc`. Приложение читает IFC 4.3. Профиль расчета: тот, что в файле.

**Сохранение** — да, и это единственный формат, в который можно сохранять. *Сохранить* записывает весь ваш проект в файл IFC. Файл становится целью сохранения.

**Экспорт** — да, как *IFC 4x3* (описан как *Стандарт BuildingSMART. 4D-связь с моделями BIM.*). Имя по умолчанию: имя проекта с расширением `.ifc`. Если ваш проект связан с библиотекой ресурсов, флажок *Сохранить файл библиотеки рядом* находится под карточками в *Файл › Экспорт*. Если флажок установлен, приложение запрашивает место для *projectname-bibliotheek.ifc* после файла проекта. Флажка нет в списке на вкладке *Главная*.

**Что переносится** — все, что относится к проекту: задачи со структурой, длительностью, датами и ходом выполнения; связи с задержкой; ограничения и крайние сроки; календари; ресурсы и назначения, включая распределение трудозатрат по часам; базовые планы; коды задач и настраиваемые поля; примечания; внешние зависимости от других проектов; перерывы; правила работы и типы задач; настройки проекта, например дату отчета о состоянии, режим учета выполнения, профиль расчета и параметры расчета; связь с библиотекой ресурсов. Для проекта из `.xer` вместе с ним переносится и исходный файл. Настраиваемый тип задачи сохраняется как тип IFC `USERDEFINED` с именем в поле ObjectType, поэтому другие программы IFC читают задачу как обычно. Приложение также сохраняет постоянный идентификатор типа, поэтому переименование не разрывает связь. Если кто-то откроет файл на другом компьютере, тип появится там в разделе *Из этого проекта*, а не в своем списке *Мои типы задач*.

**Что не переносится** — настройка экрана (масштаб, положение прокрутки, выбранная задача, свернутые фазы, фильтр и группировка) и настройки приложения ([Настройки](docs://ref-instellingen)). Вкладка *IFC* показывает текст IFC вашего проекта.

## MS Project XML (MSPDI)

**Открытие** — да. Приложение распознает файл `.xml` как MS Project XML по корневому элементу `Project` в пространстве имен MS Project (или без пространства имен). Профиль расчета: *Open Planner Studio*.

**Сохранение** — нет. Такой проект не получает цели сохранения.

**Экспорт** — да, как *MS Project XML* (*Открывается в Microsoft Project. Полная структура СДР.*). Имя по умолчанию: имя проекта с расширением `.xml`.

**Что переносится** — задачи со структурой (уровень и СДР), длительностью, датами и ходом выполнения; связи с задержкой, также в часах или процентах; ограничения, включая крайний срок; календари, включая календари задач и ресурсов; ресурсы и назначения, включая кривую или распределение трудозатрат по часам; дату отчета о состоянии; пороговое значение критичности в виде целого числа рабочих дней, 0 или больше, с отметкой *Общий резерв времени ≤ пороговое значение*; описание задачи (как примечание); правило работы задачи (как тип задачи MS Project); настраиваемый тип задачи в свободном поле (`ExtendedAttribute`), которое приложение читает обратно и которое MS Project может игнорировать. Из ваших базовых планов переносится только активный, как базовый план 0. Задача в часах сохраняет свою единицу, а веха — свой вид (начало, окончание или автоматический).

**Что не переносится** — примечания (контрольный список задачи), внешние зависимости от других проектов, коды задач и настраиваемые поля, вторую связь ограничения, отметку *Планируемая вручную*, выравнивающую задержку, точку возобновления и остановки задачи с выполнением с нарушением последовательности, правила расчета *Оставшиеся трудозатраты продолжаются после астрономической длительности* и *Незапущенные задачи не переносятся к дате отчета о состоянии* профиля MS Project, а также остальные параметры расчета. Задачи с перерывами без распределения трудозатрат по часам переносятся без этих перерывов.

**Что меняется по пути** — ограничение *Фиксированное начало (MSO)* или *Фиксированное окончание (MFO)* без выбора *Обязательная (жёсткая привязка)* становится *Начало не ранее (SNET)* или *Окончание не ранее (FNET)*. Гамак становится обычной задачей с рассчитанными датами.

## Файл MS Project (`.mpp`)

**Открытие** — да, от MS Project 2010 до 2021. Профиль расчета: *Microsoft Project*. Приложение только читает файл: оно никогда не меняет ваш `.mpp`. Файл MS Project 2007 или старше, а также файл с паролем приложение не открывает и выводит сообщение с указанием на экспорт MS Project в XML.

**Сохранение** — нет, и цели сохранения нет: *Сохранить* записывает новый файл IFC.

**Экспорт** — нет.

**Что переносится** — задачи со структурой, длительностью и ограничениями; связи с задержкой; календари; ресурсы и назначения; ход выполнения; код СДР, который вы сами заполнили в MS Project. Даты и резерв времени, которые MS Project рассчитал сам, тоже читаются, для представления *Даты как записаны*.

**Что не переносится** — базовые планы, затраты и стандартные ставки, примечания и настраиваемые поля MS Project. См. [Открытие файла MS Project (.mpp)](docs://howto-mpp-openen).

**Происхождение и лицензия** — модуль чтения `.mpp` написан для Open Planner Studio и основан на исходном коде и знании структуры MPXJ (`github.com/joniles/mpxj`, Jon Iles et al.), библиотеки Java по лицензии LGPL-2.1. Структура и константы полей перенесены на TypeScript. Сам Open Planner Studio — проект с открытым исходным кодом по лицензии LGPL-3.0. Модуль чтения `.xer` не является производным: MPXJ там использовалась только для ознакомления.

## Primavera P6 XML

**Открытие** — да. Приложение распознает файл `.xml` как P6 XML по корневому элементу `APIBusinessObjects`. Профиль расчета: *Open Planner Studio*.

**Сохранение** — нет.

**Экспорт** — да, как *Primavera P6 XML* (*Для Oracle Primavera P6.*). Имя по умолчанию: имя проекта с расширением `.xml`, то есть такое же имя, как у экспорта MS Project XML. Дайте им разные имена сами.

**Что переносится** — структура СДР и задачи с длительностью, датами и ходом выполнения; связи с задержкой; ограничения (также второе, как мягкое ограничение); календари; ресурсы и назначения; дата отчета о состоянии (как `DataDate`); настраиваемый тип задачи в собственном поле `OPS Custom Task Type`, который приложение читает обратно и который P6 может игнорировать.

**Что не переносится** — базовые планы и крайние сроки; коды задач, настраиваемые поля, примечания и внешние зависимости; параметры расчета; исключение из рабочего календаря (исключение, которое делает день рабочим). В P6 нет задержки в процентах: приложение переводит ее в фиксированное число дней. Задержка в календарных днях становится задержкой в рабочем времени: 3 календарных дня становятся 3 рабочими днями. Гамак становится обычной задачей, задача, планируемая вручную, — обычной задачей с рассчитанными датами, а выравнивающая задержка меньше одного дня отбрасывается.

## Файл Primavera (`.xer`)

**Открытие** — да. Профиль расчета: *Primavera P6*. Приложение только читает файл: оно не записывает `.xer` и никогда не меняет ваш файл. Для каждого проекта с задачами открывается одна вкладка. Файл без задач или с поврежденными таблицами приложение не открывает и выводит сообщение.

**Сохранение** — нет, и цели сохранения нет: *Сохранить* записывает новый файл IFC, внутри которого находится исходный `.xer`.

**Экспорт** — нет. Если вы экспортируете проект из `.xer` в CSV, MS Project XML или P6 XML, приложение сообщает, что сведения об источнике XER теряются, даже если вы сохранили проект как IFC в промежутке. В IFC ничего не теряется.

**Что переносится** — структура СДР и задачи с длительностью, датами, ограничениями и ходом выполнения; связи с задержкой; календари; ресурсы с назначениями; коды задач; настраиваемые поля (UDF); примечания; настройки планирования P6. Задача типа *Level of Effort* становится гамаком. Базовый проект становится активным базовым планом проекта, который на него ссылается. Связь между двумя проектами приложение сохраняет как исходные данные.

**Что не переносится** — проект без задач и связь между двумя проектами как настоящая связь в вашем графике. См. [Открытие файла Primavera P6 (.xer)](docs://howto-xer-openen).

## CSV

**Открытие** — да. Приложение читает `;` и `,` как разделитель. Оно распознает заголовки столбцов на английском и нидерландском языках (например, `Name` или `Naam`, `Duration` или `Duur`, `Predecessors` или `Voorgangers`). Даты могут быть в формате *гггг-мм-дд*, *дд-мм-гггг* или *дд/мм/гггг*. Предшественник записывается как код СДР, тип связи и задержка, например `1.2FS+2d`. Профиль расчета: *Open Planner Studio*. Проект называется *CSV Import*. Значение `Task Type`, которое не является ни одним из фиксированных кодов (например, `CONSTRUCTION` или `INSTALLATION`, которые приложение записывает само), становится настраиваемым типом задачи в разделе *Из этого проекта*, а не в *Мои типы задач*; с `OPS Custom Task Type ID` сохраняется идентификатор настраиваемого типа.

**Сохранение** — нет.

**Экспорт** — да, как *CSV (;)* (*Универсальный экспорт таблицы. Все задачи с датами и длительностью.*), на карточке *CSV (разделитель «;»)*. Файл использует точку с запятой как разделитель, находится в кодировке UTF-8 с BOM и имеет заголовки столбцов на английском языке.

**Что переносится** — для каждой задачи эти столбцы: `OPS Task ID`, `WBS`, `Outline Level`, `Name`, `Duration (days)`, `Start`, `Finish`, `Predecessors`, `Task Type`, `OPS Custom Task Type ID`, `Status`, `Completion (%)`, `Actual Start`, `Actual Finish`, `Critical`, `Total Float` и `Description`. Процент завершения записывается целыми числами.

**Что не переносится** — ресурсы, назначения, календари, ограничения, крайние сроки, базовые планы и дата отчета о состоянии. Если даты показаны в представлении *Даты как записаны*, экспорт оставляет `Critical` и `Total Float` пустыми для задач, чей исходный файл этого не записал.

## Лист хода выполнения (Excel и CSV)

**Открытие** — да, через *Файл › Импорт* (*Обновить ход выполнения из таблицы*) или кнопкой с таким же названием в группе *Ход выполнения* на вкладках *График*, *Таблица* и *Отчет*. Приложение читает `.xlsx` и `.csv` размером до 16 МБ и до 50 000 строк. Проект это не открывает: оно обновляет ход выполнения вашего открытого проекта. См. [Импорт хода выполнения из таблицы](docs://howto-voortgang-importeren).

**Сохранение** — нет.

**Экспорт** — да, как *Лист хода выполнения (Excel)* (в списке *Ход выполнения (Excel)*) и *Лист хода выполнения (CSV)* (*Ход выполнения (CSV)*). Имя по умолчанию: *projectname-voortgang*. Кнопка *Экспортировать таблицу хода выполнения* в той же группе создает лист Excel в один щелчок. Лист Excel имеет фиксированную ширину столбцов, заблокированные поля и проверку дат; лист CSV содержит то же самое в виде обычного текста.

**Что переносится** — столбцы `OPS Task ID`, `WBS`, `Name`, `Start`, `Finish`, `Completion (%)`, `Actual Start` и `Actual Finish`. При загрузке приложение использует `Completion (%)`, `Actual Start` и `Actual Finish`; `Start` и `Finish` нужны только для распознавания формата дат и не меняют ваш график. Приложение связывает строки с задачами по `OPS Task ID` или иначе по уникальному коду СДР.

**Что не переносится** — все, что находится вне этих столбцов: длительность, связи, ресурсы и остальной график. Суммарная задача не получает ход выполнения из таблицы.

## PDF

**Открытие** — нет.

**Сохранение** — нет.

**Экспорт** — да, из отчета: на вкладке *Отчет* кнопка *Экспортировать в PDF*. Приложение само не отправляет отчет на принтер; бумажная версия получается через PDF. Содержание зависит от типа отчета: см. [Типы отчетов](docs://ref-rapporttypes) и [Создание и печать отчета](docs://howto-rapport-maken-en-afdrukken).
