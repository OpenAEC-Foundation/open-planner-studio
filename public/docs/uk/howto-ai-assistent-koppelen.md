# Підключення MCP-клієнта

Мета: дозволити MCP-клієнту переглядати ваш графік і працювати з ним, із можливістю бачити, що він робить, і з обмеженнями, які ви встановлюєте самі.

## Швидко: дозвольте Claude зробити це

Ви працюєте з Claude Desktop або Claude Code? Тоді Claude може сам встановити підключення:

1. Натисніть *Копіювати промпт* нижче.
2. Вставте запит у новий чат із Claude і надішліть його.

Потім Claude встановлює розширення для Open Planner Studio і під час роботи пояснює, що він робить. Якщо вам самим треба щось зробити, наприклад натиснути *Встановити* у Claude Desktop, Claude точно скаже, який клік зробити. Для цього токен не потрібен.

```prompt
Встановіть для мене розширення Open Planner Studio, щоб ви могли читати й змінювати мої будівельні графіки в Open Planner Studio. Зробіть самі якомога більше. Перед кожним кроком напишіть одним простим реченням, що саме ви зробите і чому. Якщо вам потрібна моя участь, ставте одне питання за раз і чекайте на мою відповідь. Якщо я маю щось зробити сам, скажіть мені точно, який один клік або яку одну дію зробити і де.

Що вам треба знати:
- Розширення — це один файл, open-planner-studio-<версія>.mcpb, у найновішому релізі: https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest. Пряме посилання є в https://api.github.com/repos/OpenAEC-Foundation/open-planner-studio/releases/latest (файл, назва якого закінчується на .mcpb). Файл є ZIP-файлом.
- Розширення працює із застосунком Open Planner Studio для комп'ютера і без нього. Коли застосунок відкрито і його міст MCP працює, ви працюєте з графіком, який відкрито в застосунку. Коли застосунок закрито, ви працюєте з файлами графіків у робочій папці, яку вибираю я.
- Для встановлення не потрібні ні токен, ні пароль. Не запитуйте їх у мене і не читайте й не показуйте жодного з них.

Якщо ви працюєте в Claude Desktop:
1. Якщо ви можете завантажити файл і відкрити його на моєму комп'ютері, зробіть це з файлом .mcpb. Якщо не можете, дайте мені пряме посилання для завантаження і скажіть мені двічі клацнути файл, коли завантаження завершиться.
2. Потім Claude Desktop показує розширення Open Planner Studio. Скажіть мені натиснути Встановити. Потім скажіть мені вибрати в полі Working folder папку з моїми файлами графіків.
3. Скажіть мені почати новий чат і там запитати вас, які інструменти Open Planner Studio ви бачите.

Якщо ви працюєте в Claude Code:
1. Перевірте, що встановлено Node.js 22 або новішої версії. Якщо ні, поясніть мені, як його встановити, і зупиніться.
2. Запитайте мене, у якій папці лежать мої файли графіків. Це і є робоча папка.
3. Завантажте файл .mcpb і розпакуйте його в нову окрему папку в моїй папці користувача. Прочитайте там manifest.json: server.mcp_config показує, як запускається сервер. Замініть ${__dirname} на розпаковану папку, а ${user_config.workdir} на робочу папку.
4. Виконайте claude mcp list. Якщо сервер із назвою open-planner-studio вже є, запитайте мене, чи можна його замінити. Не показуйте його налаштування, бо вони можуть містити токен.
5. Додайте сервер для мого облікового запису користувача, наприклад: claude mcp add open-planner-studio --scope user -e OPS_MCP_ROOT=<робоча папка> -- node <розпакована папка>/server/index.mjs
6. Скажіть мені почати нову сесію Claude Code і що /mcp там показує, чи підключено open-planner-studio.

Якщо ви працюєте деінде, наприклад claude.ai у браузері, скажіть мені, що для цього потрібен Claude Desktop або Claude Code. Якщо ви не знаєте, де працюєте, запитайте мене.

Коли встановлення завершено, поясніть кількома реченнями:
- як я дозволяю вам працювати у відкритому застосунку: в Open Planner Studio виберіть Налаштування › Проєкт › Налаштування застосунку, вкладку Додатково, і увімкніть Дозволити підключення MCP. Потім натисніть Запустити міст на вкладці MCP.
- що без застосунку зміна потрапляє у файл лише після збереження, і що наявний файл не перезаписується, поки застосунок відкрито.
Якщо крок не вдається, скажіть мені одним реченням, що пішло не так і що я можу зробити. Не вгадуйте.
```

Ви хочете зробити це самостійно або використовуєте інший MCP-клієнт? Тоді дотримуйтеся кроків нижче.

## Коли це потрібно

Ви хочете, щоб MCP-клієнт читав, аналізував або змінював ваш графік. Наприклад, щоб він склав першу робочу структуру проєкту, виправив завдання або пояснив критичний шлях. Це працює через **Model Context Protocol** (MCP): стандарт, що дозволяє програмі штучного інтелекту, **MCP-клієнту**, використовувати інструменти іншої програми. Для цього Open Planner Studio запускає на власному комп'ютері невеликий сервер, **міст**. Він пропонує набір інструментів, усі з назвами, що починаються з `planner_`: читання й зміна завдань, залежностей, ресурсів, календарів, базових планів, документів і файлів. Які саме є й яких дій вони відмовляються виконувати, описано в [Інструменти MCP](docs://ref-ai-tools). MCP-клієнт працює в проєкті, який ви відкрили, а не в копії: завдання, яке він додає, одразу з'являється в Gantt. Він використовує той самий розрахунок і ту саму історію дій, що й ви, через *Скасувати*.

Міст працює лише в застосунку для комп'ютера. Якщо ви дозволите підключення MCP у браузері, ви таки побачите вкладку *MCP*, але кнопка *Запустити міст* буде сірою з текстом *Міст працює лише в застосунку для комп'ютера*. Решта цієї статті стосується застосунку для комп'ютера. У браузері сірими є також *Зробити бекап* і *Відкрити папку бекапів*.

## Кроки

### 1. Дозволення підключення MCP

1. Виберіть *Налаштування › Проєкт › Налаштування застосунку*. Також можна вибрати *Файл › Налаштування застосунку* або значок шестерні вгорі.
2. Виберіть вкладку *Додатково* і увімкніть *Дозволити підключення MCP*. Вкладка *MCP* з’являється у стрічці.
3. Якщо хочете, щоб міст був активним одразу після запуску застосунку, увімкніть також *Автоматично запускати міст*. Ця опція спрацьовує лише тоді, коли підключення MCP увімкнено, і лише в настільному застосунку. За замовчуванням її вимкнено, бо відкриття порту — свідомий вибір.

Якщо вимкнути підключення MCP, міст зупиниться і вкладка *MCP* зникне.

### 2. Запуск мосту

1. Перейдіть на вкладку *MCP* і натисніть *Запустити міст* у групі *Сервер*.
2. Подивіться на стан поруч із кнопкою. Там написано *Вимкнено*, *Активний на порту 3877*, *Порт 3877 зайнятий* або *Помилка*. Якщо запуск вдався, там написано *Активний на порту 3877*, а кнопка називається *Зупинити міст*. Якщо там *Порт 3877 зайнятий* або *Помилка*, кнопка лишається *Запустити міст*; див. розділ «Типові проблеми і що тоді робить застосунок».

Міст слухає лише ваш комп’ютер, на одному порту. За замовчуванням це порт 3877. У групі *Підключення* можна вказати інший порт у полі *Порт*, але лише тоді, коли міст зупинено. Підключення — це звичайний HTTP на вашому комп’ютері. Застосунок сам нічого не надсилає назовні. Що клієнт MCP робить з вашим графіком, зокрема що робить його постачальник, виходить за межі застосунку.

### 3. Підключення клієнта MCP

1. Натисніть *Підключитися* у групі *Підключення*. Відкриється вікно *Дані з'єднання*.
2. Виберіть, що потрібно вашому клієнту, див. нижче.
3. Токен приховано. Значком ока ви його показуєте. Кнопки копіювання завжди копіюють справжнє значення, навіть якщо на екрані токен приховано.
4. Попросіть клієнта MCP отримати список інструментів. Цю перевірку також описано в підказці для підключення: клієнт має побачити інструменти з префіксом `planner_`. Очікувана кількість є в підказці для підключення.

Вікно пропонує чотири способи підключення:

- *Доручити це Claude*: та сама підказка, що й угорі цієї статті, з кнопкою *Копіювати промпт*. Вона призначена для Claude Desktop і Claude Code. Токен для неї вам не потрібен.
- *Фрагмент конфігурації*: частина конфігурації, яку ви вставляєте в налаштування MCP свого клієнта.
- *Підказка для підключення*: текст, який ви вставляєте у свого клієнта MCP, після чого він підключається сам.
- *Endpoint* і *Автентифікація*: окремі дані. Endpoint — це `http://localhost:3877/mcp` з транспортом *streamable HTTP*. Кожен запит потребує заголовка `Authorization: Bearer`, після якого йде ваш токен. Клієнт також має підтримувати сесії MCP: під час підключення міст видає код сесії в заголовку `Mcp-Session-Id` і відхиляє кожен наступний запит без цього коду. Claude Code і `mcp-remote` роблять це самостійно.

**Підключіться знову після оновлення застосунку.** Якщо ваш клієнт MCP уже був підключений до старішої версії застосунку, він ще не надсилає код сесії, і міст відхиляє кожен запит. Тому підключіться знову після оновлення: почніть нову сесію в Claude Code і повністю закрийте Claude Desktop, а потім запустіть його знову.

**Claude Code.** Фрагмент конфігурації підходить для Claude Code безпосередньо. Виконайте в терміналі цю команду, а замість `<token>` вставте свій токен:

```
claude mcp add --transport http open-planner-studio http://localhost:3877/mcp --header "Authorization: Bearer <token>"
```

Фрагмент можна також вставити у файл `.mcp.json` у папці проєкту. Тоді не додавайте цей файл до git, бо токен дає доступ до вашого графіка. Сервер із `.mcp.json` потрібно вперше схвалити в Claude Code.

**Claude Desktop.** Для Claude Desktop є розширення: файл `open-planner-studio-<version>.mcpb`. Claude Desktop встановлює його подвійним клацанням. Node.js для нього не потрібен. Розширення працює із застосунком і без нього. Швидше це зробити за допомогою підказки угорі цієї статті; нижче наведено кроки вручну.

1. Завантажте файл `.mcpb` з останнього випуску: `https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest`.
2. Двічі клацніть файл. Claude Desktop відкривається і показує розширення *Open Planner Studio*. Натисніть кнопку встановлення. Якщо подвійне клацання не працює, відкрийте в Claude Desktop *Налаштування › Розширення* і встановіть файл там.
3. У полі *Working folder* виберіть папку з файлами ваших графіків. Claude використовує цю папку, лише коли застосунок закрито. Тоді Claude читає і записує лише в цій папці.
4. Увімкніть розширення і почніть новий чат. Запитайте Claude, які інструменти Open Planner Studio він бачить.

Токен або порт вводити не потрібно: поки міст працює, розширення саме знаходить застосунок. Для кожного запиту від Claude розширення щоразу вибирає знову:

- *Застосунок відкрито і міст працює*: Claude працює в графіку, який відкрито в застосунку. Кожну зміну ви одразу бачите в застосунку.
- *Застосунок закрито або міст вимкнено*: Claude працює з файлом графіка в робочій папці. Зміна є у файлі лише тоді, коли Claude зберігає файл. Автоматичного збереження немає. Поки застосунок відкрито, Claude не перезаписує наявний файл, а зберігає його під новою назвою.

Якщо застосунок відкривається або закривається, поки Claude працює, розширення перемикається і повідомляє про це Claude. Тоді Claude спочатку знову вибирає або відкриває графік і лише потім щось змінює. Якщо в Claude ще є незбережені зміни без застосунку, розширення продовжує працювати без застосунку, доки Claude їх не збереже. Так ніщо не втрачається. Якщо розширення не може зв’язатися із застосунком і немає придатної робочої папки, Claude бачить лише інструмент `open_planner_studio_status` з повідомленням, яке каже, що вам робити.

**Claude Desktop без розширення.** Якщо ви не можете використати розширення, підключіть Claude Desktop через зовнішній інструмент `mcp-remote`. Фрагмент конфігурації не підходить для Claude Desktop безпосередньо: у файлі `claude_desktop_config.json` ви вказуєте програму, яку Claude Desktop запускає сам, а не адресу. Для `mcp-remote` потрібен Node.js. У Claude Desktop виберіть *Налаштування › Розробник › Редагувати конфігурацію*, вставте в файл (зі своїм токеном) і знову запустіть Claude Desktop:

```
{
  "mcpServers": {
    "open-planner-studio": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:3877/mcp", "--header", "Authorization:${AUTH_HEADER}"],
      "env": { "AUTH_HEADER": "Bearer <token>" }
    }
  }
}
```

Токен стоїть у `env`, а не в `args`, навмисно: у Windows Claude Desktop ламає аргумент, який містить пробіл. *Власний конектор* у Claude (*Налаштувати › Конектори*) з мостом не працює. Claude тоді підключається з хмари Anthropic, а вона не може дістатися до моста на вашому комп’ютері.

У групі *Підключення* є ще поле *Токен*. Це довгий випадковий код, який застосунок створює для вас і зберігає на цьому комп’ютері. У вікні написано *Цей токен надає доступ до відкритого графіка. Не діліться ним з іншими*. За допомогою значка *Створити новий токен* ви створюєте новий токен. Спершу застосунок питає: *Створення нового токена розриває всі наявні з'єднання. Продовжити?* Якщо міст працює, він перезапускається з новим токеном, і старий більше не працює.

**Як розширення знаходить застосунок.** Поки міст працює, настільний застосунок записує порт і токен у файл `mcp/runtime.json` у папці даних застосунку. Розширення для Claude Desktop читає цей файл для кожного запиту. У Linux і macOS читати файл може лише ваш обліковий запис користувача. У Windows файл захищає стандартний ACL папки вашого профілю; застосунок цього окремо не перевіряє. Коли ви зупиняєте міст або вимикаєте підключення MCP, застосунок видаляє файл. Застосунок також веде список відкритих файлів у `mcp/open-files.json`, навіть коли підключення MCP вимкнено. Поки цей файл існує, розширення і сервер MCP без інтерфейсу не перезаписують жоден наявний файл, також файл, який ви щойно відкрили і якого ще немає у списку. Створювати новий файл дозволено. Читання також дозволено: Claude тоді бачить версію на диску, без ваших ще не збережених змін.

### 4. Перевірка дій клієнта MCP

1. Натисніть *Панель активності* у групі *Активність*. У бічній колонці відкривається панель *Активність MCP*.
2. Кожен виклик моста є в окремому рядку, найновіший угорі: час, що сталося, скільки тривало і чи виклик вдався, чи ні. Клацніть рядок, щоб розгорнути *Аргументи* і *Відповідь*.
3. Кнопкою *Очистити* ви очищаєте список. Панель зберігає останні 500 викликів. Доки нічого не відбулося, там написано *Поки немає активності MCP. Виклики моста з’являтимуться тут*.

Коли підключення MCP увімкнено, внизу праворуч у рядку стану є крапка з написом *MCP*. Її колір показує стан моста, а клік по ній переводить вас на вкладку *MCP*.

### 5. Встановлення обмежень

У групі *Безпека* є кнопки, якими ви обмежуєте клієнта MCP:

- *Призупинити*: клієнт MCP тимчасово не може нічого змінювати, читання і далі дозволено. Міст лишається активним. Кнопка стає *Відновити*.
- *Лише для читання*: усі інструменти, які щось змінюють, відхиляються, поки це ввімкнено.
- *Авто-бекап: увімкнено*: перед першою зміною клієнтом MCP у документі застосунок записує IFC-бекап. За замовчуванням це увімкнено. Кнопкою ви це вимикаєте, і тоді там написано *Авто-бекап: вимкнено*. Бекап створюється раз на документ щоразу, коли ви запускаєте міст.
- *Зробити бекап*: одразу створює бекап активного документа. Потім там написано *Бекап створено:* і назву файлу.
- *Відкрити папку бекапів*: відкриває папку з бекапами.

Бекапи лежать у папці `ai-backups` в папці даних застосунку. Застосунок зберігає останні бекапи, а старіші поступово прибирає. Докладно, як саме це відбувається, описано в [Інструменти MCP](docs://ref-ai-tools).

### 6. Підготовка клієнта MCP до побудови графіка

Клієнт MCP добре будує графік, лише якщо знає правила побудови графіка. Це ви робите самостійно:

1. **Для основних правил нічого робити не потрібно.** Вони передаються під час підключення: міст надсилає їх у полі `instructions` рукостискання MCP. Те, чи ваш клієнт вставляє їх у свою системну підказку, залежить від самого клієнта.
2. **Дайте клієнту прочитати посібник.** Підказка для підключення з вікна *Дані з'єднання* просить клієнта MCP прочитати посібник інструментом `planner_get_planning_guide`. Якщо ви не використовуєте підказку, напишіть клієнту: *Спершу прочитайте посібник за допомогою planner_get_planning_guide, перш ніж щось змінювати.* Посібник можна прочитати самостійно за адресою `https://open-planner-studio.open-aec.com/agent/planning-guide.md`.
3. **Необов’язково: встановіть навички.** Це працює лише з клієнтом MCP, який підтримує навички. Покладіть `SKILL.md` для *goed-plannen* і *progress-update* у `.claude/skills/goed-plannen/SKILL.md` і `.claude/skills/progress-update/SKILL.md` у папці проєкту, з якою працює клієнт MCP, або в `~/.claude/skills/` для кожного проєкту.

Файли можна отримати двома способами. Попросіть клієнта MCP викликати інструмент `planner_get_planning_guide` з параметром `part` зі значенням `skill`: відповідь містить обидва тексти і для кожної навички вказано, де вона має бути. Або завантажте їх з `https://open-planner-studio.open-aec.com/skills/goed-plannen/SKILL.md` і `https://open-planner-studio.open-aec.com/skills/progress-update/SKILL.md`. Якщо *goed-plannen* ще є від старішої версії застосунку, замініть його: той старий текст нідерландською мовою і посилається на статтю довідки, а не на посібник для клієнтів MCP.

Перевірити, чи клієнт MCP справді прочитав посібник, можна так: *Панель активності* показує виклик `planner_get_planning_guide`. Остаточна відповідь має містити список припущень: оцінені тривалості, обрану розбивку, залежності, які клієнт створив сам, і кожне обмеження, яке він встановив. Якщо цього списку немає, попросіть його. Після оновлення прогресу за *progress-update* відповідь має назвати такі значення: дата звітування про стан, нова дата завершення і відхилення від базового плану.

## Типові проблеми і що тоді робить застосунок

**Клієнт MCP змінює щось, що ви хочете скасувати.** Кожна зміна клієнтом MCP — це один крок, який ви скасовуєте кнопкою *Скасувати* (Ctrl+Z). Серія змін, яку клієнт MCP передає разом, — це теж один крок. Після цього проєкт показується як незбережений. Після зміни графік знову обчислюється, тому F5 натискати не потрібно.

**Застосунок відхиляє виклик клієнта MCP.** Коли увімкнено *Призупинити* або *Лише для читання*, застосунок відхиляє всі зміни, але читання лишається можливим, зокрема перерахунок застарілого графіка. Якщо ви самі щось редагуєте, наприклад перетягуєте смугу або вводите значення в полі, клієнт MCP отримує дати з часу до вашого редагування з повідомленням, що вони застарілі. Якщо відкрито діалогове вікно, наприклад вікно налаштувань, вікно завдання або вітальне вікно, або увімкнено режим презентації, застосунок відхиляє всі виклики, також читання, доки ви не закриєте це вікно. Тоді клієнт MCP отримує повідомлення про помилку з внутрішньою назвою того, що відкрито, наприклад `showTaskDialog`. Лише `planner_get_planning_guide` працює далі, бо він не читає ваш графік.

**Ви перемикаєте вкладки, поки клієнт MCP працює.** Клієнт MCP працює з документом, де сталася його перша зміна. Якщо ви тим часом перемкнете вкладки, застосунок відхиляє його наступну зміну, доки клієнт не підтвердить, що хоче працювати з іншою вкладкою. Так ніщо не потрапляє в неправильний проєкт. Якщо клієнт MCP сам відкриває або дублює документ, далі він працює в цьому новому документі.

**Клієнт MCP записує або відкриває файл.** Клієнт MCP може записати графік як файл IFC і відкрити файл графіка як нову вкладку. Він може це робити лише в межах папки вашого користувача. Він перезаписує наявний файл, лише якщо явно про це просить.

**Стан: *Порт 3877 зайнятий*.** Інша програма використовує порт. Повідомлення застосунку показано під ним. Поле порту тоді лишається заблокованим (*Змінювати можна лише тоді, коли сервер зупинено.*), хоча міст не працює, і кнопки зупинки немає. Це відомий недолік. Поки його не виправлено, вимкніть і знову ввімкніть *Дозволити підключення MCP*. Тоді стан знову *Вимкнено*, і ви можете вибрати інший порт. Потім знову скопіюйте дані з'єднання, бо *Endpoint* містить порт.

**Клієнт не може підключитися після нового токена.** Новий токен розриває всі наявні підключення. Передайте клієнту новий токен або знову вставте фрагмент конфігурації. Розширення в Claude Desktop читає новий токен самостійно, вам там нічого робити не потрібно.

**Ви самі зупинили міст, і він сам не запускається.** *Автоматично запускати міст* працює один раз щоразу, коли застосунок запускається. Якщо ви самі зупинили міст, застосунок його тихо знову не вмикає.

**Вкладка *MCP* зникла.** Підключення MCP вимкнено. Увімкніть його в кроці 1.

**Веб-сторінка у вашому браузері не може звертатися до моста.** Міст відхиляє кожен запит, що надходить із браузера, і кожен запит без правильного токена.

## Без застосунку

Є також MCP-сервер, який працює без настільного застосунку: **MCP-сервер без інтерфейсу**. Він пропонує ті самі інструменти `planner_*`, але працює з файлом графіка на диску, а не з вашим відкритим проєктом. Тому ви не бачите змін у діаграмі Gantt, а команда *Скасувати* в застосунку на них не діє. Використовуйте його, коли не хочете відкривати застосунок або коли працюєте на комп'ютері без екрана.

Розширення для Claude Desktop запускає цей сервер самостійно, коли застосунок закрито (див. крок 3). Кроки нижче стосуються іншого MCP-клієнта, наприклад Claude Code.

Випуск не містить готового завантаження сервера. Ви збираєте його з вихідного коду за допомогою `npm run build:mcp-server`; для цього потрібен Node.js 22 або новіший. Результатом є один файл, `server.mjs`.

1. Виберіть робочу папку з файлами графіка. Сервер читає та записує дані лише в цій папці.
2. Підключіть вашого MCP-клієнта. Для Claude Code команду наведено нижче цих кроків.
3. Попросіть MCP-клієнта відкрити графік, наприклад `~/plan.ifc`. На цьому сервері `~` означає робочу папку.
4. Попросіть MCP-клієнта зберегти результат. Автоматичного збереження немає: MCP-клієнт записує файл за допомогою `planner_export_ifc`. Те, що він не зберіг, втрачається, коли сервер зупиняється.

Для кроку 2 у Claude Code введіть цю команду в терміналі, з вашими шляхами:

```
claude mcp add open-planner -- node /path/to/server.mjs --root /path/to/working-folder
```

Перед першою зміною в кожному документі сервер створює резервну копію MCP, як і застосунок. MCP-клієнт, який вибирає шлях поза робочою папкою, зокрема через ярлик (символічне посилання), отримує відмову. Поки застосунок відкрито, сервер не перезаписує наявний файл.
