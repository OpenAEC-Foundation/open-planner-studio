# Options de calcul et conventions

Tous les choix qui déterminent la manière dont l'application calcule un planning, tels que vous les trouvez dans le bloc *Profil de calcul et options* : le profil, les 27 conventions par profil et les options de calcul du projet. Pourquoi P6 et MS Project calculent différemment est expliqué dans [Profils de calcul et conventions](docs://uitleg-rekenprofielen). Ce que cela signifie pour vos dates est expliqué dans [Dates telles qu'enregistrées](docs://uitleg-datums-zoals-opgeslagen).

## Où les trouver et leur fonctionnement

Choisissez *Paramètres › Projet › Paramètres du projet* ou *Fichier › Paramètres du projet*. En bas se trouve le bloc *Profil de calcul et options*. Dans la fenêtre *Nouveau projet*, il n'y a que la liste déroulante *Profil de calcul* : un choix applique immédiatement les options par défaut de ce profil.

**Par projet, pas par application.** Le profil et les options appartiennent au fichier du projet et voyagent avec *Enregistrer* (IFC). Deux personnes qui ouvrent le même fichier calculent donc de la même façon. CSV et P6 XML ne les transportent pas ; parmi les options de calcul, MS Project XML conserve au plus le seuil critique. Voir [Formats d'import et d'export](docs://ref-import-exportformaten). Vos propres modèles valent pour toute l'application : l'application les garde sur cet appareil.

**Uniquement après Appliquer.** Ce que vous modifiez dans ce bloc reste un brouillon jusqu'à ce que vous cliquiez sur *Appliquer*. L'application recalcule alors le planning, même si *Calculer automatiquement* est désactivé. Si des tâches ont bougé, elle signale combien (*Après application, 3 tâches ont été déplacées.*). Si aucune tâche n'a bougé, aucun message n'apparaît. Il s'agit d'une seule étape pour *Annuler*. L'application passe aussi à la vue *Dates telles qu'enregistrées*. Une modification sans effet ne fait rien. Dans *Fichier › Paramètres du projet*, vous abandonnez le brouillon avec *Abandonner*.

## Profil de calcul

**Profil de calcul** — la base sur laquelle l'application calcule. Choisissez parmi *Primavera P6*, *Microsoft Project* et *Open Planner Studio*, ainsi que vos propres modèles et le profil personnalisé de ce projet. Par défaut : *Open Planner Studio* pour un nouveau projet et pour un projet sans profil. Effet : le profil active ou désactive chacune des 27 conventions ci-dessous. Un fichier que vous ouvrez reçoit le profil de son format : un `.xer` calcule comme *Primavera P6*, un `.mpp` comme *Microsoft Project*, et CSV, MS Project XML et P6 XML comme *Open Planner Studio*. Un fichier IFC conserve le profil qui y est enregistré. Un profil intégré avec des écarts par rapport à un ancien fichier s'appelle *Primavera P6 (modifié)*, avec le nom de la base. Cette ligne reste séparée dans la liste tant que le projet calcule de cette façon. La ligne simple *Primavera P6* est la base sans ces écarts ; si vous la choisissez, un bloc l'indique. Si vous choisissez un autre profil intégré, par exemple *Microsoft Project*, les écarts restent tels quels : revenir à *Primavera P6* les rétablit, y compris après avoir enregistré et rouvert le fichier. Si vous choisissez un autre profil dans Paramètres du projet, les options de calcul restent inchangées ; si elles diffèrent de la valeur par défaut du nouveau profil, un bloc orange au-dessus des options de calcul l'indique (voir *Options de calcul de ce projet*). Où : le bloc *Profil de calcul et options*, liste déroulante *Profil de calcul*.

**Nouveau profil** — crée un profil personnalisé à partir du profil choisi. Effet : l'application demande un nom et propose *Copie de Primavera P6* (ou du profil de départ). *Créer* donne un profil personnalisé avec toutes les valeurs actuelles, y compris les écarts d'un ancien fichier, et développe *Conventions de ce profil*. Un nom vide n'est pas possible. Le champ *Nom de ce profil personnalisé* permet de modifier le nom ensuite ; sans nom, *Appliquer* le refuse. Le projet n'utilise le nouveau profil qu'après *Appliquer*. Où : à côté de la liste *Profil de calcul*. *Nouveau projet* n'affiche pas ce bouton.

**Cocher ou décocher une convention** — uniquement dans un profil personnalisé. Effet : le profil s'écarte alors de sa base. *revenir à la base* rétablit la valeur de base. Les trois profils intégrés sont en lecture seule. Où : la partie *Conventions de ce profil*.

**Enregistrer comme modèle**, **Mettre à jour le modèle depuis ce projet**, **Mettre à jour depuis le modèle** et **Supprimer le modèle** — gèrent vos profils personnalisés sous forme de modèle. Effet : un modèle est un profil enregistré que vous pouvez choisir dans n'importe quel projet ; le projet garde sa propre copie. Si le profil du projet diffère de son modèle, l'application affiche *Ce profil diffère du modèle « … ».* Les modèles ne figurent pas dans le fichier du projet. *Enregistrer comme modèle* indique que le modèle a été enregistré. Si cela échoue, parce qu'il existe déjà 100 modèles ou parce que le stockage de l'application est plein, un message d'erreur s'affiche. *Supprimer le modèle* demande d'abord une confirmation. Où : sous la liste déroulante, pour un profil personnalisé.

## Conventions par profil

Une convention est une règle dans laquelle les profils de calcul diffèrent. Chaque convention est activée ou désactivée. La partie *Conventions de ce profil* est repliée par défaut. Son titre affiche le nombre de conventions et, si le profil s'en écarte, un badge *modifié : 2*. Déployé, le bloc affiche la valeur par convention et un badge *modifié : 2* sur un groupe qui présente des écarts. La valeur de base (*base : activée* ou *base : désactivée*) est toujours affichée pour un profil personnalisé, et pour un profil intégré seulement en cas d'écart. Avec un profil intégré, la valeur est une étiquette *ACTIVÉ* ou *DÉSACTIVÉ*, à titre indicatif. Avec un profil personnalisé, c'est une case à cocher, et un écart a le bouton *revenir à la base*. Un écart sur un profil intégré vient d'un ancien fichier. Cette ligne a un fond orange, et un bloc indique qu'elle est utilisée ; pour la modifier, utilisez *Nouveau profil*. L'icône i après une ligne affiche l'explication : quand vous pointez dessus avec la souris, avec Tab, ou avec un clic ou un toucher. Échap ferme seulement l'explication, pas la fenêtre en dessous. Un clic ailleurs la ferme aussi. Quand la page défile, l'explication de l'icône qui a le focus reste affichée. Si une convention ne fonctionne qu'avec la planification horaire ou seulement sur des tâches d'un fichier `.xer`, une étiquette bleue à côté de la ligne l'indique : *uniquement avec la planification horaire* ou *uniquement pour les tâches .xer*. *Uniquement avec la planification horaire* dans les *Conditions* ci-dessous a le même sens que cette étiquette : avec un calendrier à plages de travail, pour une tâche dont la durée est en heures, ou avec le *Calendrier de décalage* réglé sur *24 heures* (un décalage compte alors en heures). La valeur par défaut de chaque convention est celle du profil intégré choisi. *Open Planner Studio* désactive toutes les conventions. Sous chaque convention ci-dessous, vous lisez ce que *Primavera P6* et *Microsoft Project* font.

### Avancement et travail terminé

**Conserver les dates réelles dans le calcul au plus tard** — Lors du calcul à rebours, une tâche commencée conserve son début enregistré comme début au plus tard, sauf si *Tâche en cours : début au plus tôt = début du travail restant* est activée (comme sous *Primavera P6*) : son début au plus tard est alors le début du travail restant. Une tâche terminée conserve ses dates réelles comme dates au plus tard. Ainsi, un successeur terminé ne ramène pas un prédécesseur ouvert dans le passé. Conditions : uniquement avec une date d'état. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Tâche en cours : début au plus tôt = début du travail restant** — Le début au plus tôt et le début au plus tard d'une tâche en cours pointent vers le moment où le travail restant commence (le plus tard entre la date d'état et la limite de la relation), et non vers le début réel. Lors du calcul à rebours sur une relation début-début, seule la durée restante d'un prédécesseur en cours compte ; cette dernière partie ne s'applique qu'avec la planification horaire. Conditions : sert de base à l'option *Calculer le décalage SS d'un prédécesseur en cours à partir du* et à la convention *Le décalage SS écoulé d'un prédécesseur en cours ne compte pas*. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Tâche terminée à avancement physique placée à la date d'état** — Une tâche terminée se place comme un seul point à la date d'état, ou plus tard si un prédécesseur l'exige, au lieu de ses dates réelles. Conditions : uniquement avec la planification horaire et avec une date d'état, pour les tâches et jalons terminés d'un fichier `.xer` dont le type de pourcentage d'avancement est *physique*, avec une fin réelle au plus tard à la date d'état et sans suspension ni reprise (suspend/resume). Pour les autres types de pourcentage d'avancement, y compris le type durée par défaut de P6, ce comportement n'a pas été mesuré et l'application ne l'applique pas. Nécessite *Tâche en cours : début au plus tôt = début du travail restant*. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Le début planifié n’est pas un plancher pour une tâche en cours** — Le début planifié du fichier n'est pas un plancher pour une tâche en cours (avec un début réel et moins de 100 %) : son travail restant commence à la date d'état, juste après ses prédécesseurs, même si son début planifié est plus tardif. C'est le pendant de *Début planifié comme plancher supplémentaire*. Conditions : fonctionne seulement si *Début planifié comme plancher supplémentaire* est activée. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Progress Override ignore aussi un successeur déjà commencé côté au plus tard** — La relation allant d'un prédécesseur non terminé vers un successeur déjà commencé et non terminé ne compte ni côté au plus tard ni dans la marge libre de ce prédécesseur : le successeur n'exerce donc aucune pression en amont et n'est pas une relation déterminante. Conditions : uniquement avec le mode d'avancement *Progress Override*. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

### Relations et décalage

**Le successeur commence à la limite de fin** — Une relation fin-début sans décalage dont le successeur commence exactement à la fin du prédécesseur, à la fin d'une plage, permet au successeur de commencer juste à cette fin au lieu du début de la plage suivante. Lors du calcul à rebours, le successeur affiche simplement son début au plus tard comme début d'une plage. Conditions : uniquement avec la planification horaire. Le fichier ne marque rien : l'application reconnaît elle-même une telle relation à l'ouverture d'un fichier `.xer`. Une relation que vous créez vous-même n'entre pas dans cette convention. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Décalage arrière depuis une limite de fin** — Quand l'application soustrait un décalage en horaires de travail de la limite de fin exacte d'une plage, lors du calcul à rebours, et tombe exactement sur le début d'une plage, ce point devient la limite de fin de la plage précédente. Également avec une relation fin-fin sans décalage, une fin au plus tard sur une fin de plage reste sur cette limite. Conditions : uniquement avec la planification horaire. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Le décalage écoulé d'un prédécesseur terminé ne compte pas** — Sur un décalage positif en horaires de travail après un prédécesseur terminé, seule la part qui ne s'est pas encore écoulée à la date d'état compte : le décalage moins les horaires de travail entre la fin réelle et la date d'état, au minimum 0. Conditions : uniquement avec la planification horaire et avec une date d'état, et uniquement pour les tâches d'un fichier `.xer`. Agit côté au plus tard et, en avant, seulement depuis les prédécesseurs terminés avec un point ou une fenêtre de date d'état (voir *Tâche terminée à avancement physique placée à la date d'état* et *Une tâche achevée hors séquence attend ses prédécesseurs*) ; une tâche terminée qui se place simplement sur ses dates réelles garde le décalage complet. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Le décalage SS écoulé d'un prédécesseur en cours ne compte pas** — Sur une relation début-début (SS) avec un décalage positif en horaires de travail depuis un prédécesseur en cours, seule la part du décalage qui ne s'est pas encore écoulée compte : le décalage moins les horaires de travail entre le début réel et la date d'état, au minimum 0. En avant, cela compte à partir du début du travail restant du prédécesseur ; lors du calcul à rebours, le début au plus tard du prédécesseur est le début au plus tard du successeur moins ce décalage restant. Conditions : uniquement avec la planification horaire. Nécessite *Tâche en cours : début au plus tôt = début du travail restant*. L'option *Calculer le décalage SS d'un prédécesseur en cours à partir du* choisit le point de départ. Les décalages de 0 ou moins, les décalages en heures d'horloge et les relations fin-début restent inchangés. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Fin au plus tôt pas avant une limite fin-fin** — Avec une relation fin-fin, la fin au plus tôt du successeur n'est jamais avant la fin du prédécesseur plus le décalage. Si cette limite tombe hors des horaires de travail du successeur, la fin au plus tôt devient la première limite de travail sur ou après elle ; le début reste. Conditions : uniquement avec la planification horaire et avec des décalages en horaires de travail ; pas avec une contrainte de fin ferme ni un hamac. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

### Jalons et tâches LOE

**Le jalon suit la limite de calendrier planifiée** — Un jalon sans durée reste sur la limite de calendrier que le fichier avait planifiée : un jalon placé au début d'une journée reste un jalon de début, et un jalon placé à la fin d'une plage peut tomber sur la fin du prédécesseur. Conditions : uniquement avec la planification horaire. Une tâche de durée 0 peut aussi se trouver sur deux limites de cette façon (début sur le début de la plage suivante, fin sur la fin de la plage précédente), mais seulement si elle provient d'un fichier `.xer` et que sa fin planifiée est avant son début planifié. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Tâche LOE non commencée suit la fenêtre cible** — Une tâche LOE non commencée (un hamac dans l'application) avec une fenêtre cible complète prend cette fenêtre cible comme étendue. Conditions : uniquement avec la planification horaire, et seulement si la tâche provient d'un fichier `.xer` avec uniquement des relations entrantes début-début et sortantes fin-fin, sans décalage. La preuve de cette règle est faible : un seul fichier. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**La relation fin-fin vers un jalon de début se lie au jalon lui-même** — Une relation fin-fin vers un jalon de début (durée nulle, type *Début*) se lie à la fin au plus tard de ce jalon lui-même, au lieu du début du jour du jalon. La marge libre du prédécesseur n'est alors plus raccourcie d'un jour ouvré. Le début au plus tôt du jalon ne change jamais. Conditions : uniquement avec la planification horaire ; un jalon de fin reste inchangé. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

### Marge et dates au plus tard

**La marge libre n'est jamais négative** — Avec une contrainte au plus tard qui ne peut pas être respectée, la marge totale reste négative, mais la marge libre devient 0 au lieu de négative. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Marge libre dans le calendrier de la tâche** — La marge libre d'une tâche non commencée se calcule par relation dans le calendrier de la tâche elle-même, et non dans celui du successeur. Cela vaut pour fin-début, début-début et fin-fin. Une relation avec un décalage (non 0) n'y entre que si le calendrier du décalage est *Prédécesseur* ; sinon, le calendrier du successeur reste. Une relation sans décalage y entre toujours. Une tâche commencée et non terminée ne suit cela qu'avec une relation fin-début sans décalage. Conditions : uniquement avec la planification horaire. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Fin au plus tard dans le calendrier de la tâche** — Si un successeur impose une fin au plus tard qui tombe hors des horaires de travail de la tâche, la fin au plus tard devient la fin de la plage de travail précédente dans le calendrier de la tâche. Une contrainte plus stricte ou une échéance l'emporte. C'est la contrepartie côté au plus tard de *Marge libre dans le calendrier de la tâche*. Conditions : uniquement avec la planification horaire et pas pour la fin du projet. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Tâches ALAP aussi tard que les successeurs le permettent** — Une tâche non commencée avec la contrainte *Le plus tard possible (ALAP)* obtient comme fin au plus tôt la limite la plus stricte que ses successeurs permettent avec leurs dates au plus tôt, à la minute près, et comme début au plus tôt cette fin moins sa durée. Sa propre fenêtre planifiée ne compte pas ; le plancher est constitué par ses prédécesseurs et la date d'état. Conditions : uniquement avec la planification horaire ; sans planification horaire, reste le pas habituel en jours ouvrés entiers. Qu'une tâche ALAP soit placée le plus tard possible, les successeurs passant d'abord pour qu'une chaîne ALAP se raccorde, vaut dans chaque profil, en jours ouvrés entiers. Cette convention ajoute le placement à la minute près à partir des dates au plus tôt des successeurs. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

### Dates et moments du fichier

**Début planifié comme plancher supplémentaire** — Le début planifié du fichier compte comme plancher supplémentaire à côté du réseau, mais seulement si le début et la fin sont tous deux de plus d'un jour calendaire plus tard que ce que le réseau permet. Un début ordinaire sur la plage de travail suivante ne déclenche pas la règle. Conditions : elle ne s'applique pas à une tâche en cours tant que *Le début planifié n’est pas un plancher pour une tâche en cours* est activée ; elle ne s'applique pas non plus à une tâche ALAP non commencée que *Tâches ALAP aussi tard que les successeurs le permettent* place à partir de ses successeurs. La convention ne regarde pas d'où vient la tâche, seulement son début et sa fin planifiés. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Conserver les dates réelles exactement** — Les dates de début et de fin réelles enregistrées, avec leur heure, restent exactes et ne sont pas déplacées au bord d'une plage de travail. Conditions : uniquement pour les tâches d'un fichier `.xer`. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

**Moment de contrainte exact sur un jalon** — Une contrainte avec date et heure (SNLT, MSO, FNLT ou MFO) sur un jalon sans durée est un point exact, même si ce point est le début d'une plage de travail. Conditions : uniquement avec la planification horaire et côté au plus tard ; en avant, un tel moment est déjà exact dans chaque profil. Par défaut : activée sous Primavera P6, désactivée sous Microsoft Project et Open Planner Studio.

### Avancement comme dans Microsoft Project

**Le travail restant reprend après le temps écoulé** — Une tâche en cours reprend son travail restant le plus tard entre la date d'état, la limite du prédécesseur et le début réel plus le temps déjà écoulé. Sous *Primavera P6* (Retained Logic), seules les deux premières limites comptent ; ce troisième plancher ne peut que décaler le travail restant plus tard. Conditions : pas avec *Progress Override*, pas quand il ne reste plus de travail restant et pas quand le fichier donne une date de reprise (Resume) pour la tâche (avec au plus une affectation). Par défaut : activée sous Microsoft Project, désactivée sous Primavera P6 et Open Planner Studio.

**Ne pas déplacer les tâches non commencées à la date d'état** — Une tâche sans avancement ne se déplace pas d'elle-même à la date d'état ou après. Désactivée, cette convention applique le plancher que P6 possède avec Retained Logic. Par défaut : activée sous Microsoft Project, désactivée sous Primavera P6 et Open Planner Studio.

### Profils personnalisés uniquement

Ces conventions sont désactivées dans chaque profil intégré, y compris Primavera P6. Seul un profil personnalisé peut les activer : créez-en un avec *Nouveau profil*.

**Jalon de fin comme fenêtre de limite** — Un jalon de fin peut se trouver sur deux limites de calendrier voisines : le début au plus tôt au début d'une plage de travail et la fin au plus tôt à la fin de la plage précédente. Côté au plus tard, un jalon de fin sans successeur mais avec des prédécesseurs reçoit ses dates au plus tôt comme dates au plus tard et exerce donc une pression en amont sur sa chaîne, sauf si *Calculer la marge jusqu’à la date de fin du projet* est activée. Sa marge libre reste l'espace jusqu'à la fin du projet. Conditions : la fenêtre de limite (début au plus tôt et fin au plus tôt sur deux limites) ne s'applique que si le fichier a planifié le jalon ainsi : fin planifiée avant début planifié. La pression sur la chaîne s'applique à chaque jalon de fin sans successeur. Vu seulement dans des sorties de P3 ; sans effet sur les fichiers calculés par P6. Par défaut : désactivée dans chaque profil intégré.

**Tâche terminée dans la fenêtre de la date d’état** — Une tâche terminée reçoit comme dates au plus tôt la fenêtre de la date d'état, et cette fenêtre compte pour la fin du projet et pour la marge. Conditions : uniquement avec une date d'état, pour les tâches terminées d'un fichier `.xer` avec le type de pourcentage d'avancement *durée* et le type de tâche *Durée et travail fixes* (dans P6 : Fixed Duration & Units) ; pas de jalons. Nécessite *Tâche en cours : début au plus tôt = début du travail restant*. Vu seulement dans des sorties de P3. Par défaut : désactivée dans chaque profil intégré.

**Tâche LOE terminée via sa fin réelle** — Une tâche LOE terminée qui n'a qu'une relation entrante début-début et aucun successeur suit la route via sa fin réelle au lieu de la route habituelle du hamac. Conditions : uniquement pour les tâches d'un fichier `.xer` ; nécessite *Tâche en cours : début au plus tôt = début du travail restant*, *Conserver les dates réelles dans le calcul au plus tard* et *Reprendre les dates réelles exactement*. Vu seulement dans des sorties de P3. Par défaut : désactivée dans chaque profil intégré.

**Un prédécesseur terminé ne tient pas au-delà de la date d'état** — Si un prédécesseur terminé se termine après la date d'état selon sa fin réelle, les relations fin-début et fin-fin se calculent à partir de la limite de la fenêtre de date d'état au lieu de cette fin réelle. Les relations début-début restent sur le début réel. Conditions : uniquement avec la planification horaire et avec une date d'état. Par défaut : désactivée dans chaque profil intégré.

**Une tâche achevée hors séquence attend ses prédécesseurs** — Une tâche terminée dont un prédécesseur n'est pas encore terminé (hors séquence) reçoit sa fenêtre de travail restant nul non à la date d'état, mais à la plus tardive entre la date d'état et la limite ordinaire de la relation de ce prédécesseur. Conditions : uniquement avec la planification horaire. Fonctionne sur la route de date d'état de *Tâche terminée dans la fenêtre de la date d’état*, donc aussi uniquement pour les tâches d'un fichier `.xer`. Cette convention et *Tâche en cours : début au plus tôt = début du travail restant* doivent donc aussi être activées. Pas avec *Progress Override*. Par défaut : désactivée dans chaque profil intégré.

## Options de calcul de ce projet

Ces options se trouvent sous *Options de calcul de ce projet*, sous les conventions. Si les options de calcul appliquées du projet diffèrent de la valeur par défaut du profil choisi, un bloc orange apparaît en haut. Si vous modifiez vous-même un champ, le bloc attend que vous choisissiez *Appliquer* ou *Abandonner*. Sinon, il indiquerait d'autres valeurs que celles des champs. Le choix d'un autre profil met le bloc à jour immédiatement. Pour chaque différence, il indique le champ, la valeur actuelle et la valeur par défaut, par exemple *Définition du critique : Chemin le plus long (par défaut : marge totale ≤ 0 heure)*. Un champ vide compte pour la valeur par défaut qu'il affiche. Pour un profil personnalisé, c'est la valeur par défaut de sa base qui s'applique. Le bouton *Utiliser les paramètres par défaut de Primavera P6* (avec le nom du profil) règle les champs sur cette valeur par défaut. L'application ne calcule qu'après *Appliquer*, en une seule étape que *Annuler* peut défaire. La croix masque le bloc pour ce fichier ouvert. Après une nouvelle ouverture, ou avec une nouvelle différence, il réapparaît. Sans différence, il n'y a pas de bloc. Ce que le bouton fait avec les options du fichier source se trouve sous *Paramètres du fichier source*. Valeurs par défaut par profil : *Open Planner Studio* et *Microsoft Project* n'ont pas de valeurs propres ; chaque option y est donc à sa valeur par défaut ci-dessous (pour *Microsoft Project*, *Automatique (par défaut)* avec une date d'état correspond aussi à la règle de marge propre à MS Project). *Primavera P6* règle *Calendrier de décalage* sur *Prédécesseur*, *Définition du critique* sur *Marge totale ≤ seuil* avec un seuil de 0 heure, *Calcul de la marge* sur *Marge de fin*, *Tâches à extrémité ouverte critiques* sur désactivé, et *Calculer le décalage SS d'un prédécesseur en cours à partir du* sur *Début du reste à faire (P6 : Early Start)*. Un fichier `.xer` apporte aussi des valeurs provenant du fichier lui-même.

**Définition du critique** — ce qui rend une tâche critique. Choisissez parmi *Marge totale ≤ seuil* et *Chemin le plus long*. Par défaut : *Marge totale ≤ seuil* avec un seuil de 0. Effet : avec *Marge totale ≤ seuil*, une tâche est critique si sa marge totale est inférieure ou égale au seuil. Avec *Chemin le plus long*, une tâche est critique si elle se trouve sur la chaîne qui mène à la dernière fin. Si plusieurs tâches finales ont la même fin, toutes leurs chaînes comptent. La marge n'entre alors pas en jeu. Dans les deux cas, une tâche terminée n'est jamais critique, et un hamac non plus. Cela s'applique au Gantt, au tableau, à l'aperçu des jalons et aux rapports. Où : *Options de calcul de ce projet*.

**Seuil (jours ouvrés)** — la limite pour *Marge totale ≤ seuil*. Par défaut : 0. Effet : le seuil peut être négatif. Un seuil venant d'un fichier `.xer`, ou fixé par la valeur par défaut de *Primavera P6* (0 heure), est exprimé en heures. Il s'appelle alors *Seuil (heures, par calendrier de tâche)* : l'application le compare par tâche, en heures du calendrier de cette tâche. Où : *Options de calcul de ce projet*, à côté de *Définition du critique*.

**Calcul de la marge** — quelle marge sert de marge totale. Choisissez parmi *Automatique (par défaut)*, *Le plus petit (début/fin)*, *Marge de début* et *Marge de fin*. Par défaut : *Automatique (par défaut)*, aussi sous *Microsoft Project* ; *Primavera P6* règle *Marge de fin*. Effet : *Marge de début* est le début au plus tard moins le début au plus tôt. *Marge de fin* est la fin au plus tard moins la fin au plus tôt. *Le plus petit (début/fin)* est le plus petit des deux. *Automatique (par défaut)* utilise la marge de fin pour une tâche en cours (avec un début réel ou un avancement, et une date d'état). Pour toutes les autres tâches, il utilise la plus petite. Avec une date d'état, c'est la règle de MS Project. Sans date d'état, l'avancement ne compte pas, et une tâche commencée reçoit aussi la plus petite. MS Project prend alors quand même la marge de fin pour une tâche commencée. Un fichier .mpp ouvert et un nouveau projet avec *Microsoft Project* calculent tous deux de cette façon. *Le plus petit (début/fin)* prend aussi la plus petite des deux pour une tâche en cours. Où : *Options de calcul de ce projet*.

**Tâches à extrémité ouverte critiques** — une tâche sans successeur. Par défaut : désactivé. Effet : activé donne à une telle tâche une marge totale et une marge libre de 0. Ainsi, avec la définition du critique *Marge totale ≤ seuil*, elle devient critique (sauf si elle est terminée). Désactivé calcule la marge comme d'habitude jusqu'à la fin du projet. Où : *Options de calcul de ce projet*.

**Marquer les quasi critiques** — marque les tâches qui ont presque aucune marge. Par défaut : désactivé. Effet : activé donne un seuil, par défaut 2 jours ouvrés (le champ *Seuil*). Une tâche dont la marge totale est supérieure à 0 et inférieure ou égale à ce seuil s'appelle *Quasi critique*. Une tâche dont la marge est exactement 0 est critique et n'entre pas dans ce compte. Vous le voyez dans la colonne *Quasi critique*, dans les rapports et dans le Gantt, où la barre devient ambre (sauf si la tâche est critique). Le champ affiche des jours ouvrés. Avec *Activer la planification horaire* activé, il affiche des heures si l'affichage de la durée est *Toujours en heures*, ou *Automatique (unité propre à chaque tâche)* si le calendrier du projet est un calendrier en heures. Où : *Options de calcul de ce projet*.

**Plusieurs chemins de marge** — numérote les chaînes de tâches selon leur marge. Par défaut : désactivé. Effet : activé donne à chaque tâche un numéro dans la colonne *Chemin de marge*. Dans le Gantt, les barres du chemin 2 et plus reçoivent une teinte propre, sauf si elles sont critiques ou quasi critiques. Désactivé laisse la colonne vide. Où : *Options de calcul de ce projet*.

**Méthode** — comment naissent les chemins, avec *Plusieurs chemins de marge*. Choisissez parmi *Marge libre (peeling)* et *Marge totale (classement)*. Par défaut : *Marge libre (peeling)*. Effet : avec *Marge libre (peeling)*, l'application retire des chaînes. Elle prend la tâche dont la fin est la dernière et ajoute ses prédécesseurs liés par une relation déterminante : c'est le chemin 1. Parmi les tâches restantes, elle fait de même pour le chemin 2, et ainsi de suite. Un prédécesseur commun garde le numéro du premier chemin où il apparaît. Avec *Marge totale (classement)*, le numéro est le rang de la marge totale de la tâche : 1 pour la plus petite, 2 pour la valeur suivante la plus petite. Les hamacs ne participent pas. Où : *Options de calcul de ce projet*.

**Chemins max** — combien de chemins reçoivent un numéro. Par défaut : 10. Effet : les tâches hors des premiers *Chemins max* chemins ou rangs ne reçoivent pas de numéro. Où : *Options de calcul de ce projet*, avec *Plusieurs chemins de marge*.

**Calendrier de décalage** — dans quel calendrier un décalage exprimé en horaires de travail compte. Choisissez parmi *Prédécesseur*, *Successeur*, *24 heures* et *Calendrier du projet*. Par défaut : *Prédécesseur*. Effet : un décalage de 2 jours compte en jours ouvrés du calendrier que vous choisissez. Où : *Options de calcul de ce projet*. Voir [Relations et décalage](docs://uitleg-relaties).

**Calculer le décalage SS d'un prédécesseur en cours à partir du** — la variante de la convention *Le décalage SS écoulé d'un prédécesseur en cours ne compte pas*. Choisissez parmi *Début du reste à faire (P6 : Early Start)* et *Date d'état (P6 : Actual Start)*. Par défaut : *Début du reste à faire (P6 : Early Start)*. Effet : pour une relation début-début (SS) avec un décalage positif en horaires de travail depuis un prédécesseur en cours, le successeur avec *Début du reste à faire (P6 : Early Start)* commence au début du travail restant du prédécesseur, plus le décalage restant. Avec *Date d'état (P6 : Actual Start)*, il commence à la date d'état, plus le décalage restant ; la relation ne borne alors pas en arrière le prédécesseur en cours. Le décalage restant est le décalage moins les horaires de travail écoulés entre le début réel et la date d'état, sans jamais descendre sous 0. Un décalage de 0 ou moins, un décalage en heures d'horloge et un planning en jours gardent le comportement normal. Le choix ne fonctionne que si les conventions *Le décalage SS écoulé d'un prédécesseur en cours ne compte pas* et *Tâche en cours : début au plus tôt = début du travail restant* sont toutes deux activées. Sinon, la liste déroulante est désactivée et affiche *S'applique uniquement si la convention « … » est activée*. Si la planification horaire n'est pas active sur le calendrier de décalage choisi, la liste déroulante est aussi désactivée et affiche *Ne s'applique qu'avec la planification horaire : un calendrier avec des plages ou des tâches en heures. Ce projet n'a ni l'un ni l'autre sur le calendrier de décalage choisi*. La planification horaire est toujours active avec *24 heures*, avec *Calendrier du projet* si ce calendrier a des plages, et avec *Prédécesseur* et *Successeur* si un calendrier du projet a des plages ou si une tâche est en heures. Où : *Options de calcul de ce projet*.

### Paramètres du fichier source

Ces options proviennent d'un fichier `.xer` de Primavera P6 et sont en lecture seule. Le bloc *Paramètres du fichier source* n'apparaît que si le projet les contient, donc pour un projet issu d'un fichier `.xer`. Elles entrent dans le calcul. Le bouton *Utiliser les paramètres par défaut de …* et un autre profil les laissent tels que le fichier les donnait. Elles ne comptent pas non plus comme une différence. Un nouveau projet ne les reçoit pas, pas même avec *Primavera P6*.

**Utiliser les dates de fin prévues (P6 : Use Expected Finish Dates)** — Par défaut (si le fichier ne dit rien) : activé. Effet : une tâche P6 en cours avec une date de fin prévue reçoit cette date comme fin au plus tôt. Où : *Paramètres du fichier source*.

**Calculer la marge jusqu’à la date de fin du projet** — Par défaut : désactivé. Effet : la fin du projet sert de point d'ancrage pour les dates au plus tard. Sans date de fin dans le fichier, l'application calcule jusqu'à la fin du réseau. Où : *Paramètres du fichier source*.

**Tâche terminée : dates au plus tard à partir de la date d’état** — Par défaut (si le fichier ne dit rien) : activé. Effet : une tâche terminée reçoit aussi une durée restante nulle à la date d'état, côté au plus tard, avec une marge qui a un sens. Cela ne fonctionne qu'avec la convention *Tâche terminée dans la fenêtre de la date d’état*, qui est désactivée dans chaque profil intégré. Si elle est désactivée, l'application affiche *Ne fonctionne qu’avec la convention « … », actuellement désactivée*. Où : *Paramètres du fichier source*.
