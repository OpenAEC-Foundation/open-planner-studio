# 計算オプションと規則

アプリがスケジュールを計算する方法を決めるすべての設定です。これらは *計算プロファイルとオプション* ブロックにあります。内容は、プロファイル、プロファイルごとの 27 の規則、そしてプロジェクトの計算オプションです。P6 と MS Project が異なる計算をする理由は [計算プロファイルと規則](docs://uitleg-rekenprofielen) に書かれています。それが日付にどう影響するかは [記録どおりの日付](docs://uitleg-datums-zoals-opgeslagen) に書かれています。

## 場所と仕組み

*設定 › プロジェクト › プロジェクト設定* または *ファイル › プロジェクト設定* を選択します。一番下に *計算プロファイルとオプション* ブロックがあります。*新しいプロジェクト* ウィンドウには、ドロップダウン *計算プロファイル* しかありません。ここで選ぶと、そのプロファイルの既定オプションがすぐに適用されます。

**アプリ単位ではなく、プロジェクトごと。** プロファイルとオプションは、プロジェクトファイルに属し、*保存*（IFC）で一緒に保存されます。そのため、同じファイルを開く二人は、同じ方法で計算します。CSV と P6 XML はこれらを保持しません。計算オプションのうち、MS Project XML が保持するのは、最大でもクリティカルのしきい値だけです。詳しくは [インポートとエクスポートの形式](docs://ref-import-exportformaten) を参照してください。独自のテンプレートは、アプリ全体で有効です。アプリはそれらをこの端末に保持します。

**適用したときだけ。** このブロックで変更した内容は、*適用* を選択するまで下書きです。その後、アプリは *自動計算* がオフでも、スケジュールを再計算します。タスクが移動した場合は、移動した件数も表示します（*適用後に 3 件のタスクが移動しました。*）。タスクが移動しなかった場合は、メッセージは表示されません。*元に戻す* で一度に取り消せます。適用すると、表示も *記録どおりの日付* になります。何も変わらない変更は、何もしません。*ファイル › プロジェクト設定* では、*破棄* で下書きを捨てます。

## 計算プロファイル

**計算プロファイル** — アプリが計算に使う基準です。選べるのは *Primavera P6*、*Microsoft Project*、*Open Planner Studio* です。加えて、独自のテンプレートと、このプロジェクトのカスタムプロファイルも選べます。既定: 新しいプロジェクトと、プロファイルがないプロジェクトでは *Open Planner Studio* です。効果: このプロファイルは、下の 27 の規則それぞれを、オンまたはオフに切り替えます。開くファイルは、その形式のプロファイルになります。`.xer` は *Primavera P6* として、`.mpp` は *Microsoft Project* として計算されます。CSV、MS Project XML、P6 XML は *Open Planner Studio* として計算されます。IFC ファイルは、そこに保存されたプロファイルを保持します。古いファイルからの逸脱がある組み込みプロファイルは、基準の名前を付けて *Primavera P6（変更済み）* と呼ばれます。その行は、プロジェクトがその方法で計算する間、一覧に別の行として残ります。通常の *Primavera P6* の行は、逸脱のない基準そのものです。これを選ぶと、その旨を示すブロックが表示されます。別の組み込みプロファイル（例: *Microsoft Project*）を選んでも、逸脱はそのまま残ります。*Primavera P6* に戻すと、逸脱が再び現れます。保存して開き直した後も同じです。プロジェクト設定で別のプロファイルを選んでも、計算オプションは変わりません。新しいプロファイルの既定値と異なる場合は、計算オプションの上にオレンジ色のブロックが表示されます（*このプロジェクトの計算オプション* を参照）。場所: *計算プロファイルとオプション* ブロックの、ドロップダウン *計算プロファイル*。

**新しいプロファイル** — 選んだプロファイルから、カスタムプロファイルを作ります。効果: アプリは名前を尋ね、*Primavera P6 のコピー*（または開始したプロファイルのコピー）を提案します。*作成* を選ぶと、現在のすべての値を持つカスタムプロファイルができます。古いファイルからの逸脱も含まれ、*このプロファイルの規則* が展開されます。空の名前は使えません。*このカスタムプロファイルの名前* 欄で、後から名前を変えられます。名前がないと、*適用* はこのプロファイルを受け付けません。プロジェクトが新しいプロファイルを使うのは、*適用* の後だけです。場所: 一覧 *計算プロファイル* の横。*新しいプロジェクト* ウィンドウには、このボタンは表示されません。

**規則にチェックを入れる、またはチェックを外す** — カスタムプロファイルでのみ行えます。効果: プロファイルは、その基準から逸脱します。*基準に戻す* を選ぶと、基準の値に戻ります。組み込みの三つのプロファイルは変更できません。場所: *このプロファイルの規則* の部分。

**テンプレートとして保存**、**このプロジェクトからテンプレートを更新**、**テンプレートから更新**、そして **テンプレートを削除** — 独自のカスタムプロファイルを、テンプレートとして管理します。効果: テンプレートは、どのプロジェクトでも選べる保存済みプロファイルです。プロジェクトは、独自のコピーを保持します。プロジェクトのプロファイルがテンプレートと異なる場合、*このプロファイルはテンプレート「…」と異なります。* と表示されます。テンプレートはプロジェクトファイルに含まれません。*テンプレートとして保存* を選ぶと、テンプレートが保存されたと表示されます。失敗した場合は、すでに 100 件のテンプレートがあるか、アプリの保存領域がいっぱいなので、エラーメッセージが表示されます。*テンプレートを削除* を選ぶと、まず確認を求められます。場所: ドロップダウンの下。カスタムプロファイルを選んでいるときに表示されます。

## プロファイルごとの規則

規則とは、計画パッケージによって異なる決まりです。どの規則も有効か無効のどちらかです。「*このプロファイルの規則*」の部分は、既定では折りたたまれています。その見出しには、規則の数が表示されます。プロファイルから外れている場合は、バッジ *変更: 2* も表示されます。開くと、ブロックに規則ごとの値が表示されます。外れがあるグループには、バッジ *変更: 2* が付きます。基準値（*基準: 有効* または *基準: 無効*）は、カスタムプロファイルでは常に表示されます。組み込みプロファイルでは、外れがある場合にだけ表示されます。組み込みプロファイルでは、値は情報として *有効* または *無効* のラベルで示されます。カスタムプロファイルでは、チェックボックスになります。外れがある場合は、*基準に戻す* ボタンがあります。組み込みプロファイルで外れがある場合は、古いファイルから来ています。その行の背景はオレンジになり、ブロックに、それが使われていることが示されます。変更するには、*新しいプロファイル* を使います。行の後ろにある i アイコンには、その説明があります。マウスでポイントしたとき、Tab キーでフォーカスしたとき、クリックまたはタップしたときに表示されます。Escape キーは説明だけを閉じ、その下のウィンドウは閉じません。説明の外をクリックしても閉じます。ページをスクロールしても、フォーカスされた i アイコンの説明は残ります。規則が時間計画のときだけ、または `.xer` ファイルのタスクだけで働く場合は、その行の横に青いラベルが表示され、*時間計画のときのみ* または *.xer のタスクのみ* と書かれます。下の *条件* にある *時間計画のときのみ* は、そのラベルと同じ意味です。稼働時間帯のあるカレンダーを使う場合、期間が時間で表されるタスクの場合、または *ラグカレンダー* が *24時間* に設定されている場合（その場合はラグが時間で数えられます）を指します。規則ごとの既定値は、選んだ組み込みプロファイルの設定どおりです。*Open Planner Studio* ではすべての規則が無効です。以下の各規則の下に、*Primavera P6* と *Microsoft Project* の動作を記載しています。

### 進捗と完了した作業

**逆算で実績日付を保持** — 逆算するとき、開始済みのタスクは、記録された開始日を最遅開始として保持します。ただし *進行中タスク：最早開始 = 残作業の開始* が有効な場合（*Primavera P6* と同様）は、残作業の開始日が最遅開始になります。完了したタスクは、実績日付を遅い日付として保持します。その結果、完了した後続タスクが、未完了の先行タスクを過去へ引き戻すことはありません。条件: 状態日がある場合のみ。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**進行中タスク：最早開始 = 残作業の開始** — 進行中タスクの最早開始と最遅開始は、実績開始日ではなく、残作業が始まる日を指します（状態日と関係の境界のうち遅い方）。開始-開始（SS）の関係で逆算するとき、進行中の先行タスクについては残存期間だけが数えられます。この最後の部分は、時間単位のカレンダーでのみ適用されます。条件: オプション *進行中の先行作業の開始-開始 (SS) ラグの計算起点* と、規則 *進行中の先行タスクからの経過済みSSラグは数えない* の基準になります。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**物理的進捗の完了タスクはデータ日付に置かれる** — 完了したタスクは、実績日付の代わりに、状態日に単一の時点として置かれます。先行タスクが求める場合は、それより後になります。条件: 時間単位のカレンダーでのみ、かつ状態日がある場合のみ。対象は、完了率の種類が *物理的* の `.xer` ファイルの完了したタスクとマイルストーンです。さらに、実績終了日が状態日以前で、中断と再開（suspend/resume）がないものに限ります。P6 の既定値である期間など、他の完了率の種類については測定されていないため、アプリは適用しません。*進行中タスク：最早開始 = 残作業の開始* が必要です。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**計画開始は進行中タスクの下限ではない** — 進行中のタスク（実績開始があり、100% 未満のタスク）では、ファイルの計画開始は下限になりません。残作業は、先行タスクの直後の状態日から始まります。計画開始がそれより後の場合も同じです。これは *計画開始を追加の下限にする* の反対側です。条件: *計画開始を追加の下限にする* が有効な場合のみ動作します。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**Progress Override では、開始済みの後続タスクを遅い側でも無視する** — 未完了の先行タスクから、開始済みで、まだ終了していない後続タスクへの関係は、その先行タスクの遅い側やフリーフロートに数えません。そのため後続タスクは逆方向の圧力をかけず、駆動関係にもなりません。条件: 進捗モード *Progress Override* の場合のみ。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

### 関係とラグ

**後続タスクは終了の境界から始まる** — ラグのない終了-開始の関係で、後続タスクが先行タスクの終了時点ちょうどに始まる場合（稼働帯の終わり）、後続タスクは次の稼働帯の始まりではなく、その終了時点からすぐに始められます。逆算すると、後続タスクの最遅開始は、単に帯の始まりとして表示されます。条件: 時間単位のカレンダーのみ。ファイルには何も印が付いていません。アプリは `.xer` ファイルを開くとき、そのような関係を自分で認識します。利用者が自分で作成した関係は対象外です。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**終了の境界からの逆算ラグ** — 逆算中に、稼働帯の正確な終了境界から稼働時間のラグを引き、その結果が帯の始まりにちょうど一致する場合、その時点は前の帯の終了境界になります。ラグのない終了-終了の関係でも、稼働帯の終わりにある最遅終了は、その境界に留まります。条件: 時間単位のカレンダーのみ。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**完了した先行タスクの経過済みラグは数えない** — 完了した先行タスクの後の、正の稼働時間のラグのうち、状態日時点でまだ経過していない部分だけが数えられます。ラグから、実績終了日と状態日の間の稼働時間を引いた値で、0 未満にはなりません。条件: 時間単位のカレンダーでのみ、かつ状態日がある場合のみ。`.xer` ファイルのタスクだけが対象です。遅い側で働きます。前方計算では、状態日の時点またはウィンドウを持つ完了した先行タスクからのみ働きます（*物理的進捗の完了タスクはデータ日付に置かれる* と *順序外で完了したタスクは先行タスクを待つ* を参照）。実績日付のまま完了しているだけのタスクは、ラグ全体を保持します。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**進行中の先行タスクからの経過済みSSラグは数えない** — 進行中の先行タスクからの、正の稼働時間のラグを伴う開始-開始（SS）の関係では、ラグのうちまだ経過していない部分だけが数えられます。ラグから、実績開始日と状態日の間の稼働時間を引いた値で、0 以上です。前方計算では、先行タスクの残作業の開始から数えます。逆算では、先行タスクの最遅開始は、後続タスクの最遅開始から残りのラグを引いた日付です。条件: 時間単位のカレンダーのみ。*進行中タスク：最早開始 = 残作業の開始* が必要です。オプション *進行中の先行作業の開始-開始 (SS) ラグの計算起点* が起点を選びます。0 以下のラグ、時計の時間で表したラグ、終了-開始の関係は、通常どおりです。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**終了-終了の境界より前には最早終了にならない** — 終了-終了の関係では、後続タスクの最早終了は、先行タスクの終了にラグを加えた時点より前にはなりません。その境界が後続タスクの稼働時間の外に当たる場合、最早終了は、その後の最初の稼働境界になります。開始日は変わりません。条件: 時間単位のカレンダーで、稼働時間のラグがある場合のみ。確定終了の制約やハンモックがある場合は対象外です。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

### マイルストーンと LOE タスク

**マイルストーンは計画されたカレンダーの境界に従う** — 期間のないマイルストーンは、ファイルで計画されたカレンダーの境界に留まります。日の始まりにあったマイルストーンは、開始マイルストーンのままです。稼働帯の終わりにあったマイルストーンは、先行タスクの終了に一致することがあります。条件: 時間単位のカレンダーのみ。期間が 0 のタスクも、この方法で二つの境界に置かれることがあります（開始は次の帯の始まり、終了は前の帯の終わり）。ただし `.xer` ファイルから来ていて、計画された終了が計画された開始より前の場合に限ります。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**未開始の LOE は目標ウィンドウを使う** — 未開始の LOE タスク（アプリではハンモック）で、完全な目標ウィンドウがある場合、その目標ウィンドウを期間の範囲として使います。条件: 時間単位のカレンダーのみ。さらに、タスクが `.xer` ファイルから来ていて、入ってくる関係が開始-開始だけで、出ていく関係が終了-終了だけで、ラグがない場合に限ります。この規則の根拠は弱く、ファイル一件だけで確認しています。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**開始マイルストーンへの終了-終了の関係は、マイルストーン自体に結び付く** — 開始マイルストーン（期間ゼロ、種類 *開始*）への終了-終了の関係は、そのマイルストーン自体の最遅終了に結び付きます。マイルストーンの日の開始には結び付きません。これにより、先行タスクのフリーフロートは、稼働日一日分短くなりません。マイルストーンの最早開始は変わりません。条件: 時間単位のカレンダーのみ。終了マイルストーンは変わりません。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

### フロートと遅い日付

**フリーフロートは決して負にならない** — 満たせない遅い制約があると、トータルフロートは負のままです。しかし、フリーフロートは負ではなく 0 になります。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**フリーフロートをタスク自身のカレンダーで計算** — 未開始タスクのフリーフロートは、後続タスクのカレンダーではなく、タスク自身のカレンダーで関係ごとに数えられます。これは終了-開始、開始-開始、終了-終了のすべてに当てはまります。ラグ（0 以外）のある関係は、ラグカレンダーが *先行タスク* の場合のみこれに従います。そうでなければ、後続タスクのカレンダーのままです。ラグのない関係は常にこれに従います。開始済みで未完了のタスクは、ラグのない終了-開始の関係の場合のみこれに従います。条件: 時間単位のカレンダーのみ。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**タスク自身のカレンダーでの最遅終了** — 後続タスクが、タスクの稼働時間の外に当たる最遅終了を課す場合、最遅終了は、タスク自身のカレンダーでの前の稼働期間の終わりになります。より厳しい制約や期限が優先します。これは *フリーフロートをタスク自身のカレンダーで計算* の、遅い側の対応物です。条件: 時間単位のカレンダーのみ。プロジェクト終了日の場合は対象外です。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**ALAP タスクを後続タスクが許す限り遅く** — 制約 *できるだけ遅く (ALAP)* を持つ未開始タスクは、後続タスクが最早日付で許す最も厳しい境界を、最早終了として得ます。分単位の正確さで決まります。最早開始は、その最早終了から期間を引いた値になります。タスク自身の計画されたウィンドウは数えません。下限は先行タスクと状態日です。条件: 時間単位のカレンダーのみ。日単位のカレンダーでは、稼働日単位の通常の段階が残ります。ALAP タスクができるだけ遅く置かれ、後続タスクが先に確定して、ALAP の連鎖がつながることは、すべてのプロファイルで、稼働日単位で成り立ちます。この規則は、後続タスクの最早日付から、分単位で正確な配置を追加します。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

### ファイルからの日付と時点

**計画開始を追加の下限にする** — ファイルの計画開始は、ネットワークに加えた追加の下限として数えます。ただし、開始も終了も、ネットワークが許す日より一暦日を超えて後の場合のみです。次の稼働帯での通常の開始では、このルールは発動しません。条件: *計画開始は進行中タスクの下限ではない* が有効な間は、進行中タスクには適用されません。この規則は、*ALAP タスクを後続タスクが許す限り遅く* が後続タスクから配置する未開始の ALAP タスクにも適用されません。この規則は、タスクの出どころを見るのではなく、計画された開始と終了だけを見ます。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**実績日付を正確に取り込む** — 記録された実績開始日と実績終了日は、時刻も含めて正確なまま保たれます。稼働帯の端には移されません。条件: `.xer` ファイルのタスクのみ。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

**マイルストーンの制約時点を正確にする** — 日付と時刻を持つ制約（SNLT、MSO、FNLT、MFO）が、期間のないマイルストーンにつくと、その時点は正確な一点になります。その時点が稼働帯の始まりである場合も同じです。条件: 時間単位のカレンダーのみで、遅い側に限ります。前方計算では、そのような時点はすべてのプロファイルで、すでに正確です。既定: *Primavera P6* では有効、*Microsoft Project* と *Open Planner Studio* では無効。

### Microsoft Project と同じ進捗

**残作業は経過時間の後に再開する** — 進行中のタスクは、残作業を、状態日、先行タスクの境界、実績開始日に既に経過している経過時間を足した日、のうち最も遅い日から再開します。*Primavera P6*（Retained Logic）では、最初の二つだけが数えられます。その三つ目の下限は、残作業を後ろへ動かすことしかできません。条件: *Progress Override* の場合は対象外です。残作業がなくなった場合も対象外です。ファイルがタスクの再開日（Resume）を与えている場合も対象外です（割り当ては多くても一件の場合）。既定: *Microsoft Project* では有効、*Primavera P6* と *Open Planner Studio* では無効。

**未開始のタスクを状態日へ移動しない** — 進捗のないタスクは、自分から状態日以降へずれることはありません。オフにすると、P6 が Retained Logic で持つ下限が適用されます。既定: *Microsoft Project* では有効、*Primavera P6* と *Open Planner Studio* では無効。

### カスタムプロファイルのみ

これらの規則は、*Primavera P6* を含むすべての組み込みプロファイルで無効です。有効にできるのはカスタムプロファイルだけです。*新しいプロファイル* で作成します。

**終了マイルストーンを境界ウィンドウにする** — 終了マイルストーンは、隣り合う二つのカレンダーの境界に置かれることがあります。最早開始は稼働帯の始まりに、最早終了は前の帯の終わりに置かれます。遅い側では、後続タスクのない、先行タスクのある終了マイルストーンは、その最早日付を遅い日付として得ます。そして、*プロジェクト終了日までのフロートを計算* が有効でない限り、その連鎖に後ろ向きの圧力をかけます。そのフリーフロートは、プロジェクト終了日までの余裕のままです。条件: 境界のウィンドウ（二つの境界上の最早開始と最早終了）は、ファイルがマイルストーンをそのように計画した場合（計画された終了が計画された開始より前）にのみ適用されます。連鎖への圧力は、後続タスクのないすべての終了マイルストーンに適用されます。P3 の出力でのみ確認しています。P6 が計算したファイルには影響しません。既定: どの組み込みプロファイルでも無効。

**ステータス日付ウィンドウ内の完了タスク** — 完了したタスクは、状態日のウィンドウを最早日付として得ます。そのウィンドウは、プロジェクト終了日とフロートに数えられます。条件: 状態日がある場合のみ。`.xer` ファイルの完了したタスクで、完了率の種類が *期間*、タスク種類が *固定期間・固定作業*（P6 では Fixed Duration & Units）の場合のみです。マイルストーンは対象外です。*進行中タスク：最早開始 = 残作業の開始* が必要です。P3 の出力でのみ確認しています。既定: どの組み込みプロファイルでも無効。

**完了した LOE タスクは実績終了日の経路をたどる** — 開始-開始の入ってくる関係だけを持ち、後続タスクがない完了した LOE タスクは、通常のハンモックの経路の代わりに、実績終了日の経路をたどります。条件: `.xer` ファイルのタスクのみ。*進行中タスク：最早開始 = 残作業の開始*、*逆算で実績日付を保持*、*実績日付を正確に取り込む* が必要です。P3 の出力でのみ確認しています。既定: どの組み込みプロファイルでも無効。

**完了した先行タスクは状態日を過ぎて保持されない** — 完了した先行タスクの実績終了日が、状態日より後になる場合、終了-開始と終了-終了の関係は、その実績終了日ではなく、状態日のウィンドウの境界から計算します。開始-開始の関係は、実績開始日のままです。条件: 時間単位のカレンダーのみで、状態日がある場合のみ。既定: どの組み込みプロファイルでも無効。

**順序外で完了したタスクは先行タスクを待つ** — 先行タスクがまだ終わっていない（順序外進捗の）完了したタスクは、残作業ゼロのウィンドウを状態日ではなく、状態日と、その先行タスクの通常の関係の境界のうち遅い方に得ます。条件: 時間単位のカレンダーのみ。*ステータス日付ウィンドウ内の完了タスク* の状態日の経路で働くため、`.xer` ファイルのタスクだけが対象です。そのため、その規則と *進行中タスク：最早開始 = 残作業の開始* も有効でなければなりません。*Progress Override* の場合は対象外です。既定: どの組み込みプロファイルでも無効。

## このプロジェクトの計算オプション

これらのオプションは、規則の下の *このプロジェクトの計算オプション* にあります。プロジェクトに適用されている計算オプションが、選択したプロファイルの既定値と異なる場合、上部にオレンジ色のブロックが表示されます。欄を自分で変更した場合、ブロックは *適用* または *破棄* を選択するまで更新されません。そうしないと、ブロックに欄とは異なる値が示されてしまいます。別のプロファイルを選択すると、ブロックはすぐに更新されます。差異ごとに、欄の名前、現在の値、既定値を示します。例：*クリティカルの定義：最長パス（既定：トータルフロート ≤ 0 時間）*。空の欄は、その欄が示す既定値として扱われます。計算プロファイルを独自に作った場合は、その基になるプロファイルの既定値が適用されます。*Primavera P6 の既定の設定を使う*（プロファイルの名前が入ります）ボタンは、欄をその既定値に設定します。アプリは *適用* を選択した後にだけ計算します。計算は一度の操作でまとめて行われ、*元に戻す* で一度の操作で取り消せます。×印を選ぶと、開いているこのファイルについてブロックが非表示になります。ファイルを開き直すか、新しい差異が生じると、ブロックが再び表示されます。差異がなければ、ブロックは表示されません。ボタンがソースファイルのオプションをどう扱うかは、*ソースファイルの設定* にあります。プロファイルごとの既定値は次のとおりです。*Open Planner Studio* と *Microsoft Project* には独自の値がないため、以下のすべてのオプションが既定値になります（*Microsoft Project* では、状態日がある場合の *自動（既定）* も MS Project 独自のフロートルールです）。*Primavera P6* では、*ラグカレンダー* が *先行*、*クリティカルの定義* が *トータルフロート ≤ しきい値*（しきい値は 0 時間）、*フロート計算* が *終了フロート*、*オープンエンドタスクをクリティカルにする* がオフ、*進行中の先行作業の開始-開始 (SS) ラグの計算起点* が *残作業の最早開始（P6: Early Start）* に設定されます。`.xer` ファイルからは、ファイル自体の値も読み込まれます。

**クリティカルの定義** — タスクをクリティカルにする条件です。*トータルフロート ≤ しきい値* と *最長パス* から選びます。既定値：しきい値 0 の *トータルフロート ≤ しきい値*。効果：*トータルフロート ≤ しきい値* では、トータルフロートがしきい値以下のタスクがクリティカルになります。*最長パス* では、最後の終了につながる連鎖上にあるタスクがクリティカルになります。同じ終了日の終端タスクが複数ある場合は、それぞれの連鎖がすべて数えられます。この場合、フロートは関係しません。どちらの場合も、完了したタスクはクリティカルになりません。ハンモックもクリティカルになりません。この設定は、Gantt、表、マイルストーンの概要、レポートに適用されます。場所：*このプロジェクトの計算オプション*。

**しきい値（稼働日）** — *トータルフロート ≤ しきい値* の上限です。既定値：0。効果：しきい値は負の値にすることもできます。`.xer` ファイルからのしきい値、または *Primavera P6* の既定値（0 時間）によるしきい値は時間単位です。その場合は *しきい値（時間、タスクカレンダーごと）* と呼ばれます。アプリは、タスクごとに、そのタスクのカレンダーの時間単位でしきい値を比較します。場所：*このプロジェクトの計算オプション*、*クリティカルの定義* の隣。

**フロート計算** — トータルフロートとして、どのフロートを使うかを決めます。*自動（既定）*、*最小（開始/終了）*、*開始フロート*、*終了フロート* から選びます。既定値：*自動（既定）*。*Microsoft Project* でも同じです。*Primavera P6* では *終了フロート* に設定されます。効果：*開始フロート* は最遅開始から最早開始を引いた値です。*終了フロート* は最遅終了から最早終了を引いた値です。*最小（開始/終了）* は、この二つのうち小さい方の値です。*自動（既定）* は、進行中のタスク（実績開始日または進捗があり、状態日がある）には終了フロートを使います。それ以外のすべてのタスクには最小値を使います。状態日がある場合、これは MS Project のルールです。状態日がない場合、進捗は数えられず、開始済みのタスクにも最小値が使われます。その場合も MS Project は、開始済みのタスクに終了フロートを使います。開いた .mpp ファイルと、*Microsoft Project* の新しいプロジェクトは、どちらもこの方法で計算します。*最小（開始/終了）* は、進行中のタスクにも小さい方の値を使います。場所：*このプロジェクトの計算オプション*。

**オープンエンドタスクをクリティカルにする** — 後続タスクがないタスクです。既定値：オフ。効果：オンにすると、そのようなタスクのトータルフロートとフリーフロートが 0 になります。そのため、*クリティカルの定義* が *トータルフロート ≤ しきい値* のとき、そのタスクはクリティカルになります（完了している場合を除く）。オフの場合は、プロジェクトの終わりまで通常どおりフロートを計算します。場所：*このプロジェクトの計算オプション*。

**準クリティカルをマークする** — フロートがほとんどないタスクをマークします。既定値：オフ。効果：オンにすると、しきい値が設定されます。既定値は 2 稼働日です（欄 *しきい値*）。トータルフロートが 0 より大きく、そのしきい値以下のタスクは *準クリティカル* と呼ばれます。フロートがちょうど 0 のタスクはクリティカルであり、この対象にはなりません。表の列 *準クリティカル*、レポート、Gantt で確認できます。Gantt では、タスクがクリティカルでない場合、バーが琥珀色になります。欄は稼働日で表示されます。*時間計画を有効にする* がオンのとき、期間の表示が *常に時間* であれば時間で表示されます。プロジェクトカレンダーが時間カレンダーの場合、表示は *自動（タスクごとの単位）* になります。場所：*このプロジェクトの計算オプション*。

**複数フロートパス** — フロートに基づいて、タスクの連鎖に番号を付けます。既定値：オフ。効果：オンにすると、表の列 *フロートパス* にタスクの番号が付きます。Gantt では、パス 2 以上のバーに専用の色合いが付きます（クリティカルまたは準クリティカルでない場合）。オフの場合、列は空のままです。場所：*このプロジェクトの計算オプション*。

**方式** — *複数フロートパス* と組み合わせて、パスがどのように生じるかを決めます。*フリーフロート（ピーリング）* と *トータルフロート（ランキング）* から選びます。既定値：*フリーフロート（ピーリング）*。効果：*フリーフロート（ピーリング）* では、アプリが連鎖を順に取り除いていきます。終了が最も遅いタスクを選び、その駆動関係にある先行タスクを加えます。これがパス 1 です。残りのタスクから、同じ方法でパス 2 などを求めます。複数のパスで共有される先行タスクには、最初に現れたパスの番号が付きます。*トータルフロート（ランキング）* では、番号はタスクのトータルフロートの順位です。最小の値が 1、次に小さい値が 2 です。ハンモックは対象になりません。場所：*このプロジェクトの計算オプション*。

**最大パス数** — 番号が付くパスの数です。既定値：10。効果：最初の *最大パス数* 個のパスまたは順位の外にあるタスクには、番号が付きません。場所：*このプロジェクトの計算オプション*（*複数フロートパス* と併せて）。

**ラグカレンダー** — 稼働時間のラグを、どのカレンダーで数えるかを決めます。*先行*、*後続*、*24時間*、*プロジェクトカレンダー* から選びます。既定値：*先行*。効果：ラグが 2 日の場合、選んだカレンダーの稼働日で数えられます。場所：*このプロジェクトの計算オプション*。詳しくは [関係とラグ](docs://uitleg-relaties) を参照してください。

**進行中の先行作業の開始-開始 (SS) ラグの計算起点** — 規則 *進行中の先行タスクからの経過済みSSラグは数えない* の変形です。*残作業の最早開始（P6: Early Start）* と *状態日（P6: Actual Start）* から選びます。既定値：*残作業の最早開始（P6: Early Start）*。効果：進行中の先行タスクから、稼働時間で正のラグを持つ開始-開始の関係では、*残作業の最早開始（P6: Early Start）* を選んだ場合、後続タスクは先行タスクの残作業の開始に残りのラグを足した日から始まります。*状態日（P6: Actual Start）* を選ぶと、後続タスクは状態日に残りのラグを足した日から始まります。この関係は、進行中の先行タスクを後ろ向きに制限しません。残りのラグは、ラグから実績開始日と状態日の間の稼働時間を引いた値です。0 未満にはなりません。ラグが 0 以下の場合、時計時間のラグの場合、および日単位のスケジュールの場合は、通常の動作のままです。この選択は、規則 *進行中の先行タスクからの経過済みSSラグは数えない* と *進行中タスク：最早開始 = 残作業の開始* の両方がオンのときにのみ有効です。それ以外の場合、ドロップダウンは無効になり、*規則「…」がオンのときのみ適用されます。* と表示されます。選んだラグカレンダーで時間計画が有効でない場合も、ドロップダウンは無効になり、*時間計画でのみ有効です。カレンダーに帯があるか、タスクが時間単位である必要があります。このプロジェクトは、選択したラグ用カレンダーのどちらも満たしていません。* と表示されます。時間計画は、*24時間* では常に有効です。*プロジェクトカレンダー* では、プロジェクトカレンダーに帯がある場合に有効です。*先行* と *後続* では、いずれかのカレンダーに帯がある場合、またはタスクが時間単位である場合に有効です。場所：*このプロジェクトの計算オプション*。

### ソースファイルの設定

これらのオプションは Primavera P6 の `.xer` ファイルから来ており、読み取り専用です。*ソースファイルの設定* のブロックは、プロジェクトにこれらのオプションがある場合にのみ表示されます。つまり、`.xer` ファイルから開いたプロジェクトの場合です。これらは計算に含まれます。*… の既定の設定を使う* ボタンと別のプロファイルは、これらをファイルの値のまま残します。また、これらは差異にも数えられません。新しいプロジェクトにはこれらは設定されません。*Primavera P6* を選んだ場合でも同じです。

**予定終了日を使用（P6: Use Expected Finish Dates）** — 既定値（ファイルに記載がない場合）：オン。効果：予定終了日がある、進行中の P6 タスクは、その日付を最早終了として受け取ります。場所：*ソースファイルの設定*。

**プロジェクト終了日までのフロートを計算** — 既定値：オフ。効果：プロジェクト終了日が、遅い日付の基準になります。ファイルに終了日がない場合、アプリはネットワークの終わりまで計算します。場所：*ソースファイルの設定*。

**完了タスク：状態日からの遅い日付** — 既定値（ファイルに記載がない場合）：オン。効果：完了したタスクも、遅い側の計算では、状態日に残存期間がゼロになり、意味のあるフロートを持ちます。この設定は、規則 *ステータス日付ウィンドウ内の完了タスク* と組み合わせたときにのみ機能します。この規則は、どの組み込みの計算プロファイルでもオフです。その規則がオフの場合は、*現在オフの規則「…」と組み合わせたときのみ有効です。* と表示されます。場所：*ソースファイルの設定*。
