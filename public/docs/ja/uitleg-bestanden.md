# ファイルと形式

保存したファイルには、実際に何が入っているのでしょうか。また、別のパッケージへエクスポートすると、スケジュールはどうなるのでしょうか。この記事では、アプリがファイルをどのように扱うかを説明します。アプリ独自の形式は IFC です。ほかの形式は変換ツールとして扱われます。エクスポートで失われるものも説明します。さらに、保存、自動保存、クラッシュ復元の違いを説明します。最後の例では、エクスポートの結果を数字で示します。

## 基本の考え方

Open Planner Studio には、独自のファイル形式が一つあります。それが **IFC** です。IFC は buildingSMART が定めた、建設情報のためのオープンな交換形式です。アプリは、プロジェクトの IFC スキーマで書き込みます。既定では IFC 4.3 ADD2 です（[IFC スキーマの選択](docs://howto-ifc-schema-kiezen) を参照）。エクスポートの一覧では *IFC* と呼ばれます。独自のプロジェクトファイルは、ほかにはありません。*保存* は、プロジェクト全体を IFC ファイル（`.ifc`）として書き込みます。*開く* は、そのようなファイルを読み込みます。ファイルに何が含まれるか確認したいですか。その場合は、*IFC* タブを開きます。このタブは、プロジェクトの IFC テキストを表示する編集画面です。*IFC を生成* で、そのテキストを更新します。*コピー* で、テキストをクリップボードに入れます。テキストを変更した場合は、*適用* で、そのテキストをプロジェクトとして読み込みます。これにより、そのタブのプロジェクトは完全に置き換えられます。

ほかのすべての形式は **アダプター** です。アダプターは、別のプログラムのモデルとアプリのモデルを変換します。アプリは CSV、MS Project XML、Primavera P6 XML、MS Project ファイル（`.mpp`）、Primavera ファイル（`.xer`）を読み込めます。書き込めるのは CSV、MS Project XML、Primavera P6 XML と、二種類の進捗シートです。`.mpp` や `.xer` へはエクスポートできません。

なぜこの違いが重要なのでしょうか。変換ツールが引き継げるのは、両方の側が知っている情報だけです。アプリの IFC ファイルには、プロジェクトに属するすべての情報が残ります。ほかの形式には、その一部がありません。その部分は残りません。

## アプリがファイルをどう扱うか

### 開くときの動作

アプリは、ファイル名の末尾で読み込み方法を選びます: `.ifc`、`.csv`、`.xml`、`.mpp`、`.xer`。`.xml` ファイルの場合は、ファイルの中を調べて、MS Project XML か Primavera P6 XML かを判断します。ファイル名の末尾が認識できない場合は、IFC として扱われます。ファイルが IFC でない場合、アプリは理由とともに *ファイルを開けませんでした* と表示します。

ファイルは、それぞれ独自のタブで開きます。例外は、まだ空で変更されていないタブです。そのタブがファイルを引き継ぎます。一つの Primavera ファイルから、複数のタブができることがあります。タスクを持つプロジェクトごとに一つのタブです。

開いたあと、アプリは必ず再計算します。ファイルが別のパッケージから来た場合、日付がファイルの記載と異なることがあります。その内容は [記録どおりの日付](docs://uitleg-datums-zoals-opgeslagen) で説明しています。

**保存先** になるのは IFC ファイルだけです。*保存* は、この保存先へ書き戻します。CSV、XML、`.mpp`、`.xer` のファイルは保存先になりません。そのようなプロジェクトは、開いたあとにファイルを持ちません。その場合、*保存* を選択すると、新しい IFC ファイルの保存先を尋ねられます。こうすると、Ctrl+S を押しても、元のファイルが IFC テキストで上書きされることはありません。

### 保存で書き込まれる内容

*保存* は、必ずプロジェクト全体を書き込みます。含まれる内容は次のとおりです。

- 構造、期間、日付、進捗のあるタスク；
- ラグ、制約、期限を含む関係；
- 曲線を含むカレンダー、リソース、割り当て；
- ベースライン、アクティビティコード、カスタムフィールド、メモ；
- 他のプロジェクトへの外部関係；
- プロジェクトの設定（状態日、計算プロファイル、計算オプションなど）；
- リソースライブラリへのリンク。

画面で設定した内容は、プロジェクトには属さず、一緒に保存されません。例えば、ズーム、スクロール位置、選択したタスク、折りたたんだフェーズです。言語やテーマなど、アプリの設定もファイルには入りません。これらはアプリ自身が、アプリ内またはブラウザーに保持します。

別の形式へのエクスポートは、プロジェクトを変更しません。エクスポートのあとも、プロジェクトの保存先は同じです。以前から *未保存* と表示されていた場合は、今も *未保存* と表示されます。

### エクスポートで失われるもの

各アダプターは、その形式が知っている内容だけを引き継ぎます。

**MS Project XML** では、タスク、関係、カレンダー、リソース、割り当て、制約、期限、状態日が引き継がれます。ベースラインは、有効な一つだけが引き継がれます。アクティビティコード、カスタムフィールド、メモ、外部関係は引き継がれません。タスクの二つ目の制約は、引き継がれません。*必須（ピン留めロジック）* が選ばれていない *指定日に開始 (MSO)* または *指定日に終了 (MFO)* の制約は、*指定日以降に開始 (SNET)* または *指定日以降に終了 (FNET)* として戻ります。*手動スケジュール* と、タスクの *山崩し遅延* は戻りません。ハンモックは、計算された日付を持つ通常のタスクになります。

**Primavera P6 XML** では、タスク、関係、カレンダー、リソース、割り当て、制約、状態日が引き継がれます。ベースライン、期限、アクティビティコード、カスタムフィールド、メモ、外部関係は引き継がれません。ここでも、ハンモックは通常のタスクになります。P6 では、ラグを割合で指定できません。アプリは、そのラグを固定の日数に変換します。暦日のラグは、稼働日のラグになります。

**CSV** はタスクの一覧です。ファイルには、タスクごとに次の列があります: タスク ID、WBS、レベル、名前、期間、開始、終了、先行タスク、作業区分、カスタムの作業区分の ID（`OPS Custom Task Type ID`）、ステータス、完了率、実績開始日と実績終了日、クリティカル、トータルフロート、説明。リソース、割り当て、カレンダー、制約、期限、ベースライン、状態日は含まれません。列の見出しは、常に英語です。

**IFC だけが、計算プロファイルと計算オプションを保持します。** CSV、MS Project XML、Primavera P6 XML にエクスポートすると、プロファイルはファイルに入りません。計算オプションのうち、MS Project XML が書き込むのは、最大でクリティカルのしきい値だけです。このようなファイルは、*Open Planner Studio* として再び開きます。プロジェクトが *Primavera P6* または *Microsoft Project* の計算プロファイルで計算されていた場合（例えば `.xer` や `.mpp` から来た場合）、日付がそのためにずれることがあります。計算プロファイルとは何かは、[計算プロファイルと規則](docs://uitleg-rekenprofielen) で説明しています。

プロジェクトが Primavera ファイル（`.xer`）から来ている場合は、途中で IFC として保存していても、CSV、MS Project XML、P6 XML にエクスポートすると、アプリは次のメッセージを表示します: *CSV へのエクスポートでは XER のソース情報が失われます。* MS Project XML の場合は、*CSV* の代わりに *MSPDI* と表示されます。P6 XML の場合は、*P6* と表示されます。IFC では、このメッセージは表示されません。IFC ファイルには、Primavera のソースファイルが一緒に保存されるからです。[Primavera P6 ファイル (.xer) を開く](docs://howto-xer-openen) を参照してください。

アプリは、エクスポート時にさらに二つのことを行います。スケジュールが古い場合は、先に再計算してから、エクスポートします。また、循環依存があるスケジュールはエクスポートしません。代わりに、ループを示すメッセージが表示されます。例: *タスク間に循環依存があります: Set up site → Demolish existing extension → Set up site*

### 保存、自動保存、クラッシュ復元

これらは三つの別の機能です。よく似ていますが、書き込み先が異なります。

**保存** は、ユーザーが自分で行う操作です。アプリは、プロジェクトをファイルに書き込み、*未保存* の印を消します。

**自動保存** は、既定ではオフです。プロジェクトごとに、ユーザーが自分でオンにします。オンのとき、アプリは変更があるたびに、ウィンドウを表示せずに同じファイルへ書き込みます。書き込みは、最大で十秒に一回です。プロジェクトにファイルがある場合にだけ動作します。[自動保存をオンにする](docs://howto-automatisch-opslaan) を参照してください。

**クラッシュ復元** は、常にオンです。どこかに変更があると、アプリは、ユーザーが変更していないプロジェクトも含めて、開いているすべてのプロジェクトの復元用コピーを保持します。これも最大で十秒に一回です。このコピーは、プロジェクトファイルには入りません。デスクトップアプリでは、アプリのデータフォルダーに保存されます。ブラウザーでは、ブラウザーのストレージに保存されます。次回の起動時に、アプリはそのコピーを提示します。詳しくは [クラッシュ後の復元](docs://howto-herstellen-na-een-crash) を参照してください。クラッシュ復元は、プロジェクトファイルへは決して書き込みません。

コピーは最大で十秒に一回保持されるため、クラッシュすると、最後の数秒の作業を失う場合があります。

### デスクトップとブラウザー

デスクトップアプリとブラウザー版は、プロジェクトを同じように扱います。ただし、ファイルの書き込み方法が異なります。

デスクトップでは、アプリは実際のパスを使います。*保存* は、ファイルへ直接書き込みます。通常、アプリはまず隣に一時ファイル（`.ops-save.tmp`）を書き込みます。その後で、元のファイルを置き換えます。そのため、書き込みの途中でクラッシュしても、古いファイルは失われません。変更があるままアプリを閉じると、プロジェクトごとに保存するかどうかを尋ねられます。正常に終了すると、復元用のコピーは削除されます。

ファイルを好きな場所に保存できるブラウザー（Chrome や Edge など）では、通常の開く・保存ウィンドウが表示されます。その後、*保存* はファイルへ直接書き込みます。開いたファイルの場合は、ブラウザーが一度だけ許可を求めます。*最近* の一覧も使えますが、ファイル名だけが表示されます。

その機能がないブラウザー（Firefox など）では、アプリはファイル選択ダイアログでファイルを開き、ダウンロードとして保存します。*保存* を選択すると、メッセージ *ダウンロードとして保存しました。「name.ifc」はダウンロードフォルダーにあります。…* が表示されます。この説明は、セッションごとに一回表示されます。*名前を付けて保存* やエクスポートでは、*ダウンロードとして保存しました。「name.ifc」はダウンロードフォルダーにあります。この環境では、アプリが選択した場所に直接書き込むことはできません。* が表示されます。ブラウザーは保存ウィンドウを表示できても、プロジェクトのファイルへ書き戻せない場合、*保存* を選択するたびに保存先を尋ねられます。この説明も、セッションごとに一回表示されます。*ファイル › 最近* はありますが、空のページが開きます。また、自動保存は使えません。アプリが選択した場所へ書き込めない環境では、同じメッセージが表示されます。

## 例: サンプルプロジェクトをエクスポートする

サンプル *Refurbishment & Extension of a Family Home*（*ファイル › サンプル*）を例に使います。このプロジェクトには、20 件のタスクがあります。そのうち 4 件はフェーズ、2 件はマイルストーンです。関係は 16 件です。リソースは 6 件あり、割り当ては 8 件あります。ベースラインは 1 件、*Demo resource library* へのリンクが 1 件あります。タスク *Demolish existing extension* には、2027年5月14日を指定した *指定日以降に開始 (SNET)* の制約があります。*Handover inspection* には、2027年7月29日の期限があります。スケジュールは2027年7月7日に終了します。

次は、各形式から戻ったプロジェクトの内容です。エクスポートしたファイルを再び開いてから測定しています。

- IFC ファイルは、すべてを戻します: 20 件のタスク、16 件の関係、6 件のリソース、8 件の割り当て、ベースライン、制約、期限、リソースライブラリへのリンク。スケジュールは、再び2027年7月7日に終了します。
- MS Project XML ファイルも、リソースライブラリへのリンクを除いて、すべてを戻します。スケジュールは2027年7月7日に終了します。
- P6 XML ファイルは、タスク、関係、リソース、割り当て、制約を戻します。ベースラインと期限はありません。制約は残っているため、スケジュールは今も2027年7月7日に終了します。
- CSV ファイルは、20 件のタスクと 16 件の関係を戻します。リソース、割り当て、ベースライン、制約、期限はありません。プロジェクト名は *CSV Import* になります。制約がないため、作業が前倒しになります。スケジュールは2027年7月2日に終了します。暦日で 5 日早くなります。

その制約がなければ、サンプル自体も2027年7月2日に終了します。つまり、違いの原因は、CSV ファイルが持たない制約です。

## 結果と誤解しやすい点

**エクスポートはバックアップではありません。** すべてを保持するのは IFC だけです。プロジェクトを残したい場合は、IFC として保存してください。エクスポートは、別の形式が必要な人にだけ使ってください。

**エクスポートしたファイルを再び開いても、同じスケジュールになるとは限りません。** アプリは、開くたびに、その形式に属する計算プロファイルで必ず再計算します。CSV の例の制約のように、ロジックが欠けている場合や、プロファイルの計算が異なる場合は、結果が変わります。

**エクスポートも *最近* に入ります。** デスクトップと、ファイルへのアクセスができるブラウザーでは、エクスポートも保存したプロジェクトと同じように *最近* に入ります（進捗シートは入りません）。そこから開くと、その形式のインポートとして開きます。

**保存は、クラッシュ復元と同じではありません。** クラッシュ復元は、クラッシュのあとに役立ちますが、保存の代わりにはなりません。そのため、タブやアプリを閉じる前に保存してください。
