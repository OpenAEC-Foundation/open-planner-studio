# MS Project ファイル (.mpp) を開く

目標: Microsoft Project のスケジュールを、先に書き出さずにアプリで直接開きます。

## 必要なとき

請負業者、コンサルタント、またはクライアントが、スケジュールを `.mpp` ファイルで送ってきます。そのスケジュールを表示、計算、またはさらに編集したい場合に使います。アプリは MS Project 2010 から 2021 までの `.mpp` ファイルを読み込みます。読み込みのみを行います。`.mpp` への書き込みは行わず、ファイルを変更することもありません。アプリは、ファイルからスケジュールそのものを取り込みます。取り込むのは、構造と期間と制約を持つタスク、ラグ付きの関係、カレンダー、リソース、割り当て、進捗です。アプリは、MS Project が自ら計算した日付とフロートも読み込みます。ただし、それらは *記録された日付* ビューでのみ使い、入力としては決して使いません。

## 手順

1. *ホーム › ファイル › 開く* を選択するか、Ctrl+O を押します。`.mpp` ファイルを選択します。
2. プロジェクトは新しいタブで開きます。空のままで変更されていない場合は、現在のタブで開きます。プロジェクトにはファイルがありません。後で *保存* を選択すると、新しい IFC ファイルが作成されます。その後、短いウィンドウで、アプリがファイルから引き継いだものと、保存の仕組みを説明します。詳しくは [ファイルを開くことと保存すること](docs://howto-bestand-openen-en-opslaan) を参照してください。
3. 下部のメッセージを読みます: *このプロジェクトは Microsoft Project として計算されます。変更は ファイル → プロジェクト情報 → 計算プロファイルとオプション で行えます。* アプリは、このプロジェクトを MS Project の計算ルールで計算します。計算プロファイルは *Microsoft Project* です。*計算プロファイルを開く* を選択すると、その設定に移動します。*詳細を見る* を選択すると、計算プロファイルについてのヘルプが開きます。
4. リボンの下にメッセージが表示されているか確認します: *ファイルに記録されている日付を表示しています。再計算すると 4 件のタスクがずれます。* その場合、それらのタスクでは、アプリの結果が MS Project が保存した日付と異なります。手順 3 のメッセージの下にも、次の行が表示されます: *ファイルに記録された日付をそのまま表示しているタスク: 4 件（再計算していません）*。その意味と、アプリ自身の計算に切り替える方法は [記録された日付](docs://uitleg-datums-zoals-opgeslagen) に記載されています。
5. *このファイルには時間単位の計画が含まれています。* と、*時間計画を有効にする* ボタンが表示される場合、ファイルには時間単位のデータが含まれています。[時間計画を有効にする](docs://howto-urenplanning-aanzetten) を参照してください。

ファイルに分割、山崩し、またはリソース主導の計画のタスクが含まれる場合、別のメッセージも追加されます。例: *この MS Project ファイルには、分割・山崩し・リソース主導で計画されたタスクが 3 件含まれています。そのまま読み込まれ、表示されます。* タスクが一つだけの場合は、メッセージの言い回しが変わります。

## 落とし穴と、その場合のアプリの動作

**すべてが引き継がれるわけではありません。** 開いた後、アプリは一つのメッセージで、引き継がなかったものを伝えます: *この MS Project ファイルの一部は取り込まれませんでした。* その下に、項目ごとに一行ずつ、件数とともに表示されます。例: *2 件のベースラインは取り込まれませんでした。* `.mpp` の場合、手順 3 の計算プロファイルについての文が、このメッセージの最初の行になります。メッセージは、× を選択するまで表示されたままです。何も失われない場合、このメッセージは表示されません。行には、次の内容が含まれることがあります:

- 挿入されたプロジェクト（サブプロジェクト）: アプリはそれを通常のタスクとして読み込み、別のファイルへのリンクは引き継ぎません。
- 別のプロジェクトからの外部タスク: アプリはそれを通常のタスクとして読み込みます。
- ベースライン: `.mpp` からはベースラインを一切引き継ぎません。MS Project XML からは、タスクのベースライン 0 のみを引き継ぎ、その中でも日付と期間だけです（時間単位のタスクでは時刻も。作業とコストは引き継がず、リソースと割り当てのベースラインも引き継ぎません）。
- MS Project XML の場合: タスクと異なる日付のベースラインを持つ割り当て。アプリはタスクのベースラインだけを保持します。両者が同じであれば、何も失われず、アプリは何も報告しません。同じ日の別の時刻も違いとみなされます。
- 値を持つカスタムフィールド（例: 参照テーブルの値やアウトラインコード）。アプリは `.mpp` のはい/いいえフィールドを数えません。
- リソースと割り当てのメモ（画像だけのメモを含む）。`.mpp` ではタスクのメモも含みます（MS Project XML では、タスクのメモは説明として引き継がれます）。
- ハイパーリンク。
- タスクの固定コスト。
- リソースの単価: `.mpp` からは単価を一切引き継ぎません。MS Project XML からは標準単価のみ引き継ぎます。
- MS Project XML の場合のみ: 手動スケジュールのタスク（アプリが自動でスケジュールします）、非アクティブのタスク（計算に含まれます）、山崩し遅延。
- `.mpp` の場合のみ: MS Project のクリティカルのしきい値。アプリはしきい値 0 を使います。

MS Project で自分で入力した WBS は引き継がれます。それ以外の場合、アプリは構造に従ってタスクに番号を付けます。

**MS Project 2007 以前のファイル。** アプリはこのファイルを拒否し、次のように報告します: *この .mpp ファイルは古い形式（Project 2007 以前）を使用しています。MS Project で XML としてエクスポートし（ファイル → 名前を付けて保存 → XML）、そのファイルを開いてください。* メッセージの下に、アプリは技術的な理由を英語で追加します。

**パスワードで保護されたファイル。** アプリは次のように報告します: *この .mpp ファイルはパスワードで保護されています。MS Project で XML としてエクスポートし（ファイル → 名前を付けて保存 → XML）、そのファイルを開いてください。* ここでも、メッセージには英語の技術的な理由が付きます。

**`.mpp` ではないファイル。** *ファイルを開けませんでした* と表示され、技術的な理由が付きます。

**XML で開くと計算が異なります。** `.mpp` の代わりに MS Project の XML エクスポートを開くと、アプリは計算プロファイル *Open Planner Studio* で計算します。*Microsoft Project* に関するメッセージは表示されません。その場合、日付は `.mpp` ファイルの場合と異なることがあります。XML エクスポートでも、アプリは何を引き継がないかを伝えます。詳しくは *すべてが引き継がれるわけではありません* を参照してください。

**編集すると、MS Project の制御が解除されます。** MS Project の日付ウィンドウによって計画されたタスクを編集すると、アプリはプロジェクトごとに一度だけ、次のように報告します: *この編集の後、MS Project の時間配分はもう 2 件のタスクを制御していません。元の配分はファイルに保存されたままです。* タスクが一つだけの場合は、メッセージの言い回しが変わります。

**保存しても `.mpp` は上書きされません。** プロジェクトにはファイルがありません。*保存* を選択すると、新しい IFC ファイルの保存先を尋ねられます。
