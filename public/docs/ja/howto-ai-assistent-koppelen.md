# AI アシスタントを接続する（MCP）

目標: AI アシスタントがスケジュールを一緒に確認し、変更できるようにします。AI アシスタントが何をしているかがわかり、ご自身で決めた制限があるようにします。

## 利用するとき

AI アシスタントに、スケジュールを読み取らせたり、分析させたり、変更させたりしたい場合に使います。たとえば、最初の WBS の下書きを作らせたり、タスクを修正させたり、クリティカルパスを説明させたりできます。これは **Model Context Protocol**（MCP）で動作します。MCP は、AI アシスタントがプログラムのツールを使えるようにする標準です。このために Open Planner Studio は、お使いのコンピューター上で小さなサーバー、**ブリッジ** を動かします。ブリッジには一連のツールがあり、名前はすべて `planner_` で始まります。タスク、関係、リソース、カレンダー、ベースライン、ドキュメント、ファイルを読み取ったり変更したりします。どのツールがあり、何を拒否するかは [AI ツール](docs://ref-ai-tools) にあります。この連携がこの形になっている理由は [AI 連携のしくみ](docs://uitleg-ai-koppeling) にあります。

ブリッジはデスクトップアプリでのみ動作します。ブラウザーで AI モードをオンにすると、*AI* タブは表示されます。しかし、ボタン *ブリッジを開始* はグレーで、テキスト *ブリッジはデスクトップアプリでのみ動作します。* が表示されます。この記事の残りの部分は、デスクトップアプリについてです。ブラウザーでは、*今すぐバックアップ* と *バックアップフォルダーを開く* もグレーです。

## 手順

### 1. AIモードを有効にする

1. *設定 › プロジェクト › アプリ設定* を選択します。*ファイル › アプリ設定* を選択することもできます。または、上部の歯車アイコンを選択します。
2. *詳細設定* タブを選択し、*AIモードを有効にする* をオンにします。リボンに *AI* タブが表示されます。
3. アプリの起動直後からブリッジを稼働させたい場合は、*ブリッジを自動的に開始* もオンにします。これは AI モードがオンのときにだけ切り替えられ、デスクトップアプリでのみ動作します。既定ではオフです。ポートを開くことは意図的な選択だからです。

AI モードをオフにすると、ブリッジは停止し、*AI* タブは消えます。

### 2. ブリッジを開始する

1. *AI* タブに移動し、グループ *サーバー* の下の *ブリッジを開始* を選択します。
2. ボタンの横にあるステータスを確認します。*オフ*、*ポート 3877 で稼働中*、*ポート 3877 は使用中です* または *エラー* と表示されます。開始に成功すると、*ポート 3877 で稼働中* と表示され、ボタンは *ブリッジを停止* になります。*ポート 3877 は使用中です* または *エラー* のときは、ボタンは *ブリッジを開始* のままです。注意点を参照してください。

ブリッジは、お使いのコンピューターの中だけで、一つのポートを待ち受けます。既定のポートは 3877 です。グループ *接続* では、*ポート* の下で別のポートを選べます。ただし、ブリッジが停止しているときだけです。

### 3. AI アシスタントを接続する

1. グループ *接続* の *接続* を選択します。ウィンドウ *接続情報* が開きます。
2. クライアントに必要なものを選択します。下を参照してください。
3. トークンは非表示になっています。目のアイコンで表示します。コピーボタンは、画面でトークンが隠れていても、常に実際の値をコピーします。
4. AI アシスタントに、ツールの一覧を要求させます。この確認は、接続用プロンプトにも含まれています。アシスタントには、接頭辞 `planner_` の付いたツールが表示されるはずです。想定される数は、接続用プロンプトに書かれています。

ウィンドウでは、接続する方法を三つ選べます。

- *設定スニペット*: クライアントの MCP 設定に貼り付ける設定の一部です。
- *接続用プロンプト*: AI アシスタントに貼り付ける文章です。貼り付けると、アシスタントは自分で接続します。
- *エンドポイント* と *認証*: 個別の情報です。エンドポイントは `http://localhost:3877/mcp` で、トランスポートは *streamable HTTP* です。すべてのリクエストには、ヘッダー `Authorization: Bearer` と、その後にトークンが必要です。お使いのクライアントは MCP セッションにも対応している必要があります。接続すると、ブリッジはヘッダー `Mcp-Session-Id` でセッションコードを渡し、そのコードがないあとのリクエストはすべて拒否します。Claude Code と `mcp-remote` は、この処理を自動で行います。

**アプリを更新したあとは、もう一度接続してください。** お使いの AI クライアントが古いバージョンのアプリにすでに接続していた場合、そのクライアントはまだセッションコードを送りません。そのため、ブリッジはすべてのリクエストを拒否します。更新のあとにもう一度接続してください。Claude Code では新しいセッションを開始し、Claude Desktop は完全に終了してから、もう一度起動してください。

**Claude Code.** 設定スニペットは Claude Code にそのまま使えます。ターミナルで次のコマンドを入力します。`<token>` の代わりに、ご自身のトークンを入れてください:

```
claude mcp add --transport http open-planner-studio http://localhost:3877/mcp --header "Authorization: Bearer <token>"
```

スニペットは、プロジェクトフォルダーにある `.mcp.json` ファイルに入れることもできます。その場合、そのファイルは git に入れないでください。トークンで計画へのアクセスが許可されるからです。`.mcp.json` のサーバーは、Claude Code で初めて使うときに承認が必要です。

**Claude Desktop.** 設定スニペットは Claude Desktop にはそのまま使えません。ファイル `claude_desktop_config.json` には、アドレスではなく、Claude Desktop が自分で起動するプログラムを指定します。そのため、間に外部ツール `mcp-remote` を使います。このツールには Node.js が必要です。Claude Desktop で *設定 › 開発者 › 設定を編集* を選択し、次の内容をファイルに書き込みます（ご自身のトークンを入れてください）。そのあと Claude Desktop を再度起動します:

```
{
  "mcpServers": {
    "open-planner-studio": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:3877/mcp", "--header", "Authorization:${AUTH_HEADER}"],
      "env": { "AUTH_HEADER": "Bearer <token>" }
    }
  }
}
```

トークンは `args` ではなく `env` に入れてあります。これは意図した設計です。Windows では、Claude Desktop がスペースを含む引数を壊すからです。Claude の *カスタムコネクター*（*カスタマイズ › コネクター*）は、ブリッジでは動作しません。Claude はその場合、Anthropic のクラウドから接続します。そのクラウドは、ご自身のコンピューターにあるブリッジには届きません。

グループ *接続* には、*トークン* フィールドもあります。これは、アプリが作成してこのコンピューターに保存する、長くランダムなコードです。ウィンドウには、*このトークンは開いている工程表へのアクセスを許可します。他人と共有しないでください。* と表示されます。アイコン *新しいトークン* で、新しいトークンを作成します。アプリは最初に *新しいトークンを生成すると、既存の接続がすべて切断されます。続行しますか？* と確認します。ブリッジが稼働中であれば、新しいトークンで再起動します。古いトークンは使えなくなります。

### 4. AI の動作を確認する

1. グループ *アクティビティ* の *アクティビティパネル* を選択します。サイド列でパネル *AIアクティビティ* が開きます。
2. ブリッジへの呼び出しはそれぞれ一行に表示され、新しいものが上に来ます。時刻、何が起きたか、かかった時間、成功したかどうかが表示されます。行を選択すると、*引数* と *応答* が展開されます。
3. *クリア* を選択すると、一覧が空になります。パネルは直近 500 件の呼び出しを保持します。まだ何も起きていない間は、*まだAIアクティビティはありません。ブリッジの呼び出しがここに表示されます。* と表示されます。

AI モードがオンのとき、ステータスバーの右下に *AI* の付いた点があります。その色でブリッジの状態がわかります。点を選択すると、*AI* タブに移動します。

### 5. 制限を設定する

*安全性* の下には、AI を制限するボタンがあります。

- *一時停止*: AI は一時的に何も変更できませんが、読み取りは引き続き許可されます。ブリッジは稼働したままです。ボタンは *再開* に変わります。
- *読み取り専用*: これがオンの間、何かを変更するツールはすべて拒否されます。
- *自動バックアップ: オン*: AI がドキュメントを初めて変更する前に、アプリは IFC のバックアップを書き込みます。これは既定でオンです。ボタンでオフにすると、*自動バックアップ: オフ* と表示されます。この書き込みは、ブリッジを開始するたびに、ドキュメントごとに一度だけ行われます。
- *今すぐバックアップ*: 開いているドキュメントのバックアップを、すぐに作成します。その後、ファイル名と一緒に *バックアップを作成しました:* と表示されます。
- *バックアップフォルダーを開く*: バックアップが入っているフォルダーを開きます。

バックアップは、アプリのデータフォルダー内の `ai-backups` フォルダーにあります。アプリは新しいバックアップを保持し、古いものは間引きます。正確な方法は [AI ツール](docs://ref-ai-tools) にあります。

### 6. アシスタントに上手に計画させる

アシスタントは、計画のルールを知っているときにだけ、うまく計画できます。なぜそれが大切で、ルールに何が書かれているかは、[AI 連携の仕組み](docs://uitleg-ai-koppeling) で読めます。次の手順は、ご自身で行います:

1. **基本ルールには何もする必要はありません。** 接続するときに、ルールは自動的に届きます。お使いのクライアントがそれをシステムプロンプトに入れるかどうかは、クライアントによります。
2. **ガイドを読ませます。** ウィンドウ *接続情報* の接続用プロンプトは、ツール `planner_get_planning_guide` でガイドを読むよう、アシスタントに求めます。プロンプトを使わない場合は、次のように頼んでください: *変更する前に、まず planner_get_planning_guide で計画ガイドを読んでください。* ガイドは `https://open-planner-studio.open-aec.com/agent/planning-guide.md` で自分でも読めます。
3. **任意: スキルを入れます。** これは、スキルに対応したアシスタントでのみ動作します。*goed-plannen* と *progress-update* の `SKILL.md` を、アシスタントが使うプロジェクトフォルダーの `.claude/skills/goed-plannen/SKILL.md` と `.claude/skills/progress-update/SKILL.md` に置きます。すべてのプロジェクトで使うには、`~/.claude/skills/` の下に置きます。

ファイルは二つの方法で入手できます。アシスタントに、`part` を `skill` にして、ツール `planner_get_planning_guide` を呼び出させてください。応答には両方のテキストと、各スキルを置く場所が含まれます。または、`https://open-planner-studio.open-aec.com/skills/goed-plannen/SKILL.md` と `https://open-planner-studio.open-aec.com/skills/progress-update/SKILL.md` からダウンロードします。アプリの古いバージョンの *goed-plannen* がまだある場合は、置き換えてください。その古いテキストはオランダ語で書かれており、アシスタント向けのガイドではなく、ヘルプ記事を指しています。

アシスタントが本当にガイドを読んだかどうかは、*アクティビティパネル* で確認できます。その場合、`planner_get_planning_guide` の呼び出しが表示されます。アシスタントが最後に出す回答には、前提の一覧が含まれているはずです。見積もった期間、選んだ分割、自分で作った関係、そして設定したすべての制約です。その一覧がない場合は、求めてください。*progress-update* に従って進捗を更新したあと、回答には状態日、新しい終了日、ベースラインに対する差異が示されているはずです。

## 注意点と、そのときのアプリの動作

**AI が行った変更を取り消したい場合があります。** AI による変更は、それぞれ一つの手順です。*元に戻す*（Ctrl+Z）で取り消せます。AI が一まとまりとして渡す一連の変更は、一つの手順になります。その後、プロジェクトは未保存として表示されます。変更の後、スケジュールは再計算されるので、F5 を自分で押す必要はありません。

**アプリが AI からの呼び出しを拒否します。** *一時停止* と *読み取り専用* がオンのとき、アプリはすべての変更を拒否します。読み取りは可能なままで、古くなったスケジュールの再計算も含みます。バーをドラッグしたり、フィールドに入力したりして、自分で編集している最中の場合、AI は編集前の日付を、古いという通知と一緒に受け取ります。ダイアログを開いている場合、たとえば設定、タスクダイアログ、ようこそウィンドウ、またはプレゼンテーションモードがオンの場合、アプリはダイアログを閉じるまで、読み取りを含むすべての呼び出しを拒否します。その場合、AI は開いているものの内部名を含むエラーメッセージを受け取ります。たとえば `showTaskDialog` です。`planner_get_planning_guide` だけが動作し続けます。スケジュールを読まないからです。

**AI が動いている間に、タブを切り替えます。** AI は、最初の変更が入ったドキュメントを扱います。その間にタブを切り替えると、アプリは、別のタブを扱いたいことを AI が確認するまで、次の変更を拒否します。こうして、間違ったプロジェクトに何も入らないようにします。

**AI が、ファイルを書き込んだり開いたりすることがあります。** AI は、スケジュールを IFC ファイルとして書き込み、スケジュールファイルを新しいタブとして開けます。これは、ユーザーフォルダーの中だけで行えます。既存のファイルを上書きするのは、明示的に求めた場合だけです。

**ステータスは *ポート 3877 は使用中です* です。** 別のプログラムがそのポートを使用しています。アプリのメッセージは、その下に表示されます。そのとき、ブリッジは稼働していないのに、ポート欄はロックされたままです（*サーバーが停止しているときだけ編集できます。*）。停止ボタンもありません。これは既知の欠点です。修正されるまでは、*AIモードを有効にする* をオフにしてから、もう一度オンにしてください。するとステータスは *オフ* に戻り、別のポートを選べます。エンドポイントにポートが含まれるため、接続情報をもう一度コピーしてください。

**新しいトークンのあとで、クライアントが接続できません。** 新しいトークンは、既存の接続をすべて切断します。クライアントに新しいトークンを渡すか、設定スニペットをもう一度貼り付けてください。

**ブリッジを自分で停止すると、自動では開始されません。** *ブリッジを自動的に開始* は、アプリの起動ごとに一度だけ動作します。ブリッジを自分で停止した場合、アプリは黙って再びオンにはしません。

**タブ *AI* が消えています。** AI モードがオフです。手順 1 でオンにしてください。

**ブラウザーのウェブページは、ブリッジと通信できません。** ブリッジは、ブラウザーから届くすべてのリクエストと、正しいトークンがないすべてのリクエストを拒否します。
