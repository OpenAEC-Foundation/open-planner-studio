# MCP クライアントを接続する

目的: MCP クライアントがスケジュールを確認して、操作できるようにします。何をしているかを把握でき、制限は自分で設定できます。

## かんたん: Claude に任せる

Claude Desktop または Claude Code を使っていますか。その場合、Claude が接続そのものをインストールできます：

1. 下の *プロンプトをコピー* をクリックします。
2. Claude との新しいチャットにプロンプトを貼り付けて、送信します。

その後、Claude は Open Planner Studio の拡張機能をインストールし、途中で何をしているかを説明します。自分で行う必要がある操作（例えば Claude Desktop で *インストール* をクリックする操作）がある場合は、Claude がどのクリックかを正確に伝えます。この操作にトークンは必要ありません。

```prompt
Open Planner Studio の拡張機能を私のためにインストールしてください。そうすれば、Open Planner Studio で私の工事スケジュールを読み取り、変更できるようになります。できる限り自分で行ってください。各ステップの前に、何をするのか、なぜそうするのかを平易な一文で伝えてください。私に対応が必要な場合は、一度に一つだけ質問し、私の回答を待ってください。私が自分で何かをしなければならない場合は、どのクリックまたは操作か、そしてどこで行うかを正確に伝えてください。

知っておくべきこと：
- 拡張機能は一つのファイルです。ファイル名は open-planner-studio-<version>.mcpb で、最新リリースにあります: https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest 。直接のリンクは https://api.github.com/repos/OpenAEC-Foundation/open-planner-studio/releases/latest にあります（名前が .mcpb で終わるファイル）。このファイルは ZIP ファイルです。
- 拡張機能は Open Planner Studio のデスクトップアプリでも、アプリなしでも動作します。アプリが開いていて、その MCP ブリッジが動いている場合は、アプリで開いているプロジェクトを操作してください。アプリを閉じている場合は、私が選んだ作業フォルダーにあるスケジュールファイルを操作してください。
- インストールには、トークンもパスワードも必要ありません。私に求めないでください。また、トークンを読んだり表示したりしないでください。

Claude Desktop で実行している場合：
1. ファイルをダウンロードして私のコンピューターで開けるなら、その .mcpb ファイルでそうしてください。できない場合は、直接のダウンロードリンクを私に伝え、ダウンロードが完了したらファイルをダブルクリックするよう私に伝えてください。
2. Claude Desktop に拡張機能 Open Planner Studio が表示されます。私にインストールをクリックするよう伝えてください。続けて、作業フォルダーで、私のスケジュールファイルがあるフォルダーを選ぶよう私に伝えてください。
3. 私に、新しいチャットを始めて、そこで見えている Open Planner Studio のツールを尋ねるよう伝えてください。

Claude Code で実行している場合：
1. Node.js 22 以降がインストールされているか確認してください。インストールされていない場合は、インストール方法を私に伝えて、作業を止めてください。
2. スケジュールファイルがあるフォルダーを私に尋ねてください。それが作業フォルダーです。
3. .mcpb ファイルをダウンロードし、私のユーザーフォルダーの中の新しい専用フォルダーに展開してください。その中の manifest.json を読んでください。サーバーの起動方法は server.mcp_config に書かれています。 ${__dirname} を展開したフォルダーに、 ${user_config.workdir} を作業フォルダーに置き換えてください。
4. claude mcp list を実行してください。その一覧に、名前が open-planner-studio のサーバーがすでにある場合は、置き換えてよいかを私に尋ねてください。その設定にはトークンが含まれている場合があるため、設定を表示しないでください。
5. サーバーを私のユーザーアカウントに追加してください。例：claude mcp add open-planner-studio --scope user -e OPS_MCP_ROOT=<working folder> -- node <unpacked folder>/server/index.mjs
6. 私に、新しい Claude Code セッションを始めるよう伝えてください。そこで /mcp を実行すると、 open-planner-studio が接続されているかどうかが分かる、と伝えてください。

Claude Desktop や Claude Code 以外で実行している場合（例えば claude.ai をブラウザーで使う場合）は、これには Claude Desktop か Claude Code が必要だと私に伝えてください。どこで実行しているか分からない場合は、私に尋ねてください。

インストールが終わったら、次の内容を数文で説明してください：
- 開いているアプリで作業を許可する方法：Open Planner Studio で 設定 › プロジェクト › アプリの設定 を選び、詳細設定 タブで MCP 接続を許可 をオンにしてください。次に、MCP タブで ブリッジを開始 をクリックしてください。
- アプリを使わない場合、変更は保存して初めてファイルに入ること。また、アプリが開いている間は、既存のファイルを上書きしないこと。
手順が失敗した場合は、何が問題だったのか、私に何ができるかを一文で伝えてください。推測しないでください。
```

自分で行いたいですか、それとも別の MCP クライアントを使っていますか。その場合は、以下の手順に従ってください。

## この機能が必要な場合

MCP クライアントに、スケジュールを読み取らせ、分析させ、変更させたい場合に使います。例えば、最初の WBS を作成させる、タスクを修正させる、クリティカルパスを説明させる、といった用途です。これは **Model Context Protocol**（MCP）を使って行います。MCP は、AI プログラム（**MCP クライアント**）が別のプログラムのツールを使えるようにする標準です。そのため、Open Planner Studio は、このコンピューター上で小さなサーバー（**ブリッジ**）を動かします。一連のツールを提供します。ツール名はすべて `planner_` で始まります。ツールでは、タスク、関係、リソース、カレンダー、ベースライン、ドキュメント、ファイルの読み取りと変更を行えます。どのツールがあり、何を受け付けないかは [MCP ツール](docs://ref-ai-tools) に書かれています。MCP クライアントは、コピーではなく、開いているプロジェクトを操作します。追加したタスクは、すぐに Gantt に表示されます。また、手動で操作するときと同じ計算と同じ *元に戻す* の履歴を使います。

ブリッジはデスクトップアプリでのみ動作します。ブラウザーで MCP 接続を許可すると、*MCP* タブは表示されますが、ボタン *ブリッジを開始* はグレーで、テキスト *ブリッジはデスクトップアプリでのみ動作します。* が表示されます。この記事の残りは、デスクトップアプリについてです。ブラウザーでは、*今すぐバックアップ* と *バックアップフォルダーを開く* もグレーで表示されます。

## 手順

### 1. MCP 接続を許可する

1. *設定 › プロジェクト › アプリ設定* を選択します。*ファイル › アプリ設定* を選択するか、上部の歯車アイコンを選択することもできます。
2. *詳細設定* タブを選択し、*MCP接続を許可* をオンにします。リボンに *MCP* タブが表示されます。
3. ブリッジをアプリの起動直後から稼働させたい場合は、*ブリッジを自動的に開始* もオンにします。これは MCP 接続がオンのときにだけ切り替わり、デスクトップアプリでのみ動作します。既定ではオフです。ポートを開くことは意図的な選択だからです。

MCP 接続をオフにすると、ブリッジは停止し、*MCP* タブは消えます。

### 2. ブリッジを開始する

1. *MCP* タブに移動し、*サーバー* の下にある *ブリッジを開始* をクリックします。
2. ボタンの横にある状態を確認します。状態は *オフ*、*ポート 3877 で稼働中*、*ポート 3877 は使用中です* または *エラー* です。開始に成功すると、*ポート 3877 で稼働中* と表示され、ボタンは *ブリッジを停止* になります。*ポート 3877 は使用中です* または *エラー* の場合、ボタンは *ブリッジを開始* のままです。注意点を参照してください。

ブリッジは、お使いのコンピューター上でのみ待ち受け、1 つのポートを使います。既定では 3877 です。*接続* グループでは、*ポート* の下で別のポートを選択できます。ただし、ブリッジが停止しているときに限ります。接続は、お使いのコンピューター上の暗号化されていない HTTP です。アプリ自体は何も送信しません。お使いのスケジュールを MCP クライアントがどう扱うか（たとえば、そのプロバイダーがどう扱うか）は、アプリの範囲外です。

### 3. MCP クライアントを接続する

1. *接続* グループの *接続* をクリックします。*接続情報* ウィンドウが開きます。
2. クライアントに必要なものを選択します。下を参照してください。
3. トークンは非表示になっています。目のアイコンを選択すると表示されます。コピーボタンは、画面でトークンが隠れている場合でも、常に実際の値をコピーします。
4. MCP クライアントに、ツールの一覧を要求させます。この確認は接続用プロンプトにも含まれています。クライアントには、`planner_` で始まるツールが見えるはずです。想定される数は接続用プロンプトに書かれています。

このウィンドウには、接続方法が 4 つあります：

- *Claude に任せる*：この記事の冒頭と同じプロンプトです。ボタン *プロンプトをコピー* で使います。Claude Desktop と Claude Code 向けです。このためにトークンは必要ありません。
- *設定スニペット*：MCP クライアントの設定に貼り付ける、設定の一部です。
- *接続用プロンプト*：MCP クライアントに貼り付けるテキストです。貼り付けると、クライアントは自分で接続します。
- *エンドポイント* と *認証*：個別の詳細です。エンドポイントは `http://localhost:3877/mcp` で、トランスポートは *streamable HTTP* です。すべてのリクエストには、ヘッダー `Authorization: Bearer` に続けてトークンを指定する必要があります。クライアントは MCP セッションにも対応している必要があります。接続すると、ブリッジはヘッダー `Mcp-Session-Id` でセッションコードを渡します。それ以降、このコードのないリクエストはすべて拒否されます。Claude Code と `mcp-remote` は、これを自分で行います。

**アプリを更新したら、もう一度接続してください。** MCP クライアントが、古いバージョンのアプリにすでに接続していた場合、まだセッションコードを送らないため、ブリッジはすべてのリクエストを拒否します。そのため、更新後にもう一度接続してください。Claude Code では新しいセッションを開始し、Claude Desktop は完全に終了してから、もう一度起動します。

**Claude Code。** 設定スニペットは、Claude Code にそのまま使えます。ターミナルで次のコマンドを入力します。`<token>` の部分は、お使いのトークンに置き換えます：

```
claude mcp add --transport http open-planner-studio http://localhost:3877/mcp --header "Authorization: Bearer <token>"
```

設定スニペットは、プロジェクトフォルダーの `.mcp.json` ファイルに入れることもできます。その場合、そのファイルを git に入れないでください。トークンがあると工程表にアクセスできてしまうためです。`.mcp.json` のサーバーは、Claude Code で初回に承認する必要があります。

**Claude Desktop。** Claude Desktop には拡張機能があります。ファイルは `open-planner-studio-<version>.mcpb` です。Claude Desktop は、ダブルクリックでインストールします。この拡張機能には Node.js は必要ありません。拡張機能は、アプリがあってもなくても動作します。この記事の冒頭にあるプロンプトを使うほうが速く設定できます。以下は手順を手作業で示したものです。

1. 最新のリリースから `.mcpb` ファイルをダウンロードします：`https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest`。
2. ファイルをダブルクリックします。Claude Desktop が開き、拡張機能 *Open Planner Studio* が表示されます。インストールします。ダブルクリックが機能しない場合は、Claude Desktop で *設定 › 拡張機能* を開き、そこでファイルをインストールします。
3. *作業フォルダー* で、お使いのスケジュールファイルがあるフォルダーを選択します。Claude は、アプリが閉じているときにだけこのフォルダーを使います。その後、Claude は、このフォルダーの中だけを読み書きします。
4. 拡張機能をオンにして、新しいチャットを開始します。Claude に、Open Planner Studio のどのツールが見えるかを尋ねます。

トークンやポートを入力する必要はありません。ブリッジが稼働している間、拡張機能はアプリを自分で見つけます。Claude からの質問ごとに、拡張機能は次のいずれかを選び直します：

- *アプリが開いていて、ブリッジが稼働している*：Claude は、アプリで開いている工程表を操作します。変更は、そのたびにすぐアプリに表示されます。
- *アプリが閉じている、またはブリッジがオフ*：Claude は、作業フォルダーにあるスケジュールファイルを操作します。変更がファイルに入るのは、Claude がファイルを保存したときだけです。自動保存はありません。アプリが開いている間、Claude は既存のファイルを上書きせず、新しい名前で保存します。

Claude が操作している間にアプリが開いたり閉じたりすると、拡張機能は切り替わり、その旨を Claude に伝えます。Claude は、まず工程表を選び直すか開き直し、そのあとで初めて変更を加えます。Claude にアプリなしの未保存の変更がある場合、拡張機能は、Claude が保存するまで、アプリなしで操作を続けます。こうして、変更が失われることはありません。拡張機能がアプリに接続できず、使える作業フォルダーもない場合、Claude に見えるのはツール `open_planner_studio_status` だけです。そのツールには、何をすべきかを示すメッセージが表示されます。

**拡張機能を使わない Claude Desktop。** 拡張機能を使えない場合は、外部ツール `mcp-remote` で Claude Desktop を接続します。設定スニペットは、Claude Desktop にそのままは合いません。`claude_desktop_config.json` ファイルには、アドレスではなく、Claude Desktop が自分で起動するプログラムを指定します。`mcp-remote` には Node.js が必要です。Claude Desktop で *設定 › 開発者 › 設定を編集* を選択し、お使いのトークンを使って次の内容をファイルに入れ、Claude Desktop をもう一度起動します：

```
{
  "mcpServers": {
    "open-planner-studio": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:3877/mcp", "--header", "Authorization:${AUTH_HEADER}"],
      "env": { "AUTH_HEADER": "Bearer <token>" }
    }
  }
}
```

トークンは `args` ではなく `env` に入れています。これは意図的です。Windows では、Claude Desktop がスペースを含む引数を壊すためです。Claude の *カスタムコネクター*（*カスタマイズ › コネクター*）は、ブリッジでは動作しません。Claude は Anthropic のクラウドから接続するため、お使いのコンピューター上のブリッジには届かないからです。

*接続* グループには、*トークン* フィールドもあります。これは、アプリが作成して、このコンピューターに保存する、長いランダムなコードです。ウィンドウには、*このトークンは開いている工程表へのアクセスを許可します。他人と共有しないでください。* と表示されます。*新しいトークン* アイコンで、新しいトークンを作成します。アプリは最初に、*新しいトークンを生成すると、既存の接続がすべて切断されます。続行しますか？* と確認します。ブリッジが稼働している場合は、新しいトークンで再起動し、古いトークンは使えなくなります。

**拡張機能がアプリを見つける仕組み。** ブリッジが稼働している間、デスクトップアプリは、ポートとトークンを、アプリのデータフォルダーにあるファイル `mcp/runtime.json` に書き込みます。Claude Desktop 用の拡張機能は、質問ごとにそのファイルを読みます。Linux と macOS では、このファイルを読めるのはお使いのユーザーアカウントだけです。Windows では、プロファイルフォルダーの既定の ACL がファイルを保護します。アプリは、これを個別には確認しません。ブリッジを停止するか、MCP 接続をオフにすると、アプリはファイルを削除します。アプリは、MCP 接続がオフでも、開いているファイルの一覧を `mcp/open-files.json` に保持します。そのファイルがある間、拡張機能とヘッドレス MCP サーバーは既存のファイルを上書きしません。お使いが開いたばかりで、まだ一覧にないファイルも同様です。新しいファイルは作成できます。読み取りも許可されています。その場合、Claude はディスク上のバージョンを見ます。まだ保存されていないお使いの変更は含まれません。

### 4. MCP クライアントの動作を確認する

1. *アクティビティ* の下にある *アクティビティパネル* をクリックします。右側の欄に *MCP アクティビティ* パネルが開きます。
2. ブリッジへの呼び出しは、それぞれ 1 行ずつ表示され、最新のものが上にあります。行には、時刻、何が起きたか、かかった時間、成功したかどうかが示されます。行をクリックすると、*引数* と *応答* が展開されます。
3. *クリア* を選択すると、一覧が空になります。パネルには直近 500 件の呼び出しが残ります。何も起きていない間は、*まだ MCP アクティビティはありません。ブリッジへの呼び出しがここに表示されます。* と表示されます。

MCP 接続がオンのときは、ステータスバーの右下に *MCP* の付いた点が表示されます。その色はブリッジの状態を示します。点をクリックすると、*MCP* タブに移動します。

### 5. 制限を設定する

*安全性* には、MCP クライアントを制限するためのボタンがあります：

- *一時停止*：MCP クライアントは、一時的に何も変更できません。読み取りは引き続き許可されます。ブリッジは有効なままです。ボタンは *再開* に変わります。
- *読み取り専用*：これがオンの間、何かを変更するすべてのツールは拒否されます。
- *自動バックアップ: オン*：MCP クライアントがドキュメントに対して最初の変更を加える前に、アプリは IFC バックアップを書き込みます。これは既定でオンです。ボタンでオフにすると、*自動バックアップ: オフ* と表示されます。バックアップは、ブリッジを開始するたびに、ドキュメントごとに 1 回作成されます。
- *今すぐバックアップ*：現在のドキュメントのバックアップを、すぐに作成します。その後、ファイル名を添えて *バックアップを作成しました：* と表示されます。
- *バックアップフォルダーを開く*：バックアップのあるフォルダーを開きます。

バックアップは、アプリのデータフォルダーにあるフォルダー `ai-backups` に保存されます。アプリは最近のバックアップを残し、古いバックアップは間引きます。正確な仕組みは [MCP ツール](docs://ref-ai-tools) に書かれています。

### 6. MCP クライアントに適切に計画させる

MCP クライアントが適切に計画できるのは、計画のルールを知っているときだけです。お使いご自身が行う作業は次のとおりです：

1. **基本ルールには何もしなくて構いません。** ルールは接続時に一緒に送られます。ブリッジは、MCP ハンドシェイクの `instructions` フィールドでルールを送ります。クライアントがシステムプロンプトに入れるかどうかは、クライアント次第です。
2. **ガイドを読ませます。** *接続情報* ウィンドウの接続用プロンプトは、MCP クライアントに、ツール `planner_get_planning_guide` でガイドを読むよう求めます。プロンプトを使わない場合は、次の文をクライアントに伝えてください：*何かを変更する前に、まず planner_get_planning_guide で計画ガイドを読んでください。* ガイドは、次のアドレスで直接読むこともできます：`https://open-planner-studio.open-aec.com/agent/planning-guide.md`。
3. **任意：スキルをインストールします。** これは、スキルに対応した MCP クライアントでのみ動作します。*goed-plannen* と *progress-update* の `SKILL.md` ファイルを、MCP クライアントが使うプロジェクトフォルダーの `.claude/skills/goed-plannen/SKILL.md` と `.claude/skills/progress-update/SKILL.md` に置きます。すべてのプロジェクトで使う場合は、`~/.claude/skills/` に置きます。

ファイルは 2 通りの方法で入手できます。MCP クライアントに、`part` を `skill` に設定して、ツール `planner_get_planning_guide` を呼び出すよう依頼します。応答には両方のテキストと、各スキルを置く場所が含まれます。または、次のアドレスからダウンロードします：`https://open-planner-studio.open-aec.com/skills/goed-plannen/SKILL.md` と `https://open-planner-studio.open-aec.com/skills/progress-update/SKILL.md`。アプリの古いバージョンの *goed-plannen* がまだある場合は、置き換えてください。その古いテキストはオランダ語で、MCP クライアント向けのガイドではなく、ヘルプ記事を案内しています。

MCP クライアントが本当にガイドを読んだかどうかは、*アクティビティパネル* で確認できます。その場合、`planner_get_planning_guide` の呼び出しが表示されます。クライアントが最後に出す回答には、前提の一覧が含まれているはずです。その一覧には、見積もった期間、選んだ分解、クライアントが自分で作成した関係、クライアントが設定したすべての制約が含まれます。一覧がない場合は、求めてください。*progress-update* に従って進捗を更新したあとは、回答に状態日、新しい終了日、そして *ベースライン* に対する差異が書かれているはずです。

## 注意点とアプリの動作

**MCP クライアントが、取り消したい変更を加えた場合。** MCP クライアントによる変更は、それぞれ *元に戻す*（Ctrl+Z）で取り消せる 1 つの手順です。MCP クライアントが 1 まとまりとして渡す一連の変更は、1 つの手順になります。その後、プロジェクトは未保存として表示されます。変更のあとは、スケジュールが再計算されるため、F5 を自分で押す必要はありません。

**アプリが MCP クライアントの呼び出しを拒否する場合。** *一時停止* と *読み取り専用* がオンのとき、アプリはすべての変更を拒否します。読み取りは可能なままで、古くなったスケジュールの再計算も含まれます。お使いご自身が編集の途中である場合（たとえばバーをドラッグしているときや、フィールドに入力しているとき）、MCP クライアントは、お使いの編集前の日付を、古くなっているという通知付きで受け取ります。ダイアログを開いている場合（たとえば設定、タスクダイアログ、ようこそウィンドウ）や、プレゼンテーションモードがオンの場合は、ダイアログを閉じるまで、アプリは読み取りを含むすべての呼び出しを拒否します。その場合、MCP クライアントは、開いているものの内部名を含むエラーメッセージを受け取ります。たとえば `showTaskDialog` です。`planner_get_planning_guide` だけは動作し続けます。スケジュールを読まないためです。

**MCP クライアントの操作中にタブを切り替える場合。** MCP クライアントは、最初の変更が入ったドキュメントを操作します。その間にタブを切り替えると、アプリは、MCP クライアントが別のタブを操作する意思を確認するまで、次の変更を拒否します。こうして、誤ったプロジェクトに何かが入ることはありません。MCP クライアントが自分でドキュメントを開いたり複製したりした場合は、その後、その新しいドキュメントを操作します。

**MCP クライアントがファイルを書き込んだり開いたりする場合。** MCP クライアントは、スケジュールを IFC ファイルとして書き込み、スケジュールファイルを新しいタブとして開けます。これは、お使いのユーザーフォルダーの中でのみ可能です。既存のファイルを上書きするのは、MCP クライアントが明示的に求めた場合だけです。

**状態が *ポート 3877 は使用中です* の場合。** 別のプログラムがそのポートを使用しています。アプリのメッセージは、その下に表示されます。その場合、ポートフィールドは、ブリッジが稼働していなくてもロックされたままです（*サーバーが停止しているときだけ編集できます。*）。停止ボタンもありません。これは既知の欠点です。修正されるまでは、*MCP接続を許可* をオフにしてから、もう一度オンにしてください。状態は *オフ* に戻り、別のポートを選べるようになります。エンドポイントにはポートが含まれるため、接続情報をもう一度コピーしてください。

**新しいトークンのあとでクライアントが接続できない場合。** 新しいトークンは、既存のすべての接続を切断します。クライアントに新しいトークンを設定するか、設定スニペットをもう一度貼り付けてください。Claude Desktop の拡張機能は、新しいトークンを自分で読み取ります。そこでは何もする必要はありません。

**ブリッジをご自身で停止した場合は、自動では開始しません。** *ブリッジを自動的に開始* は、アプリを起動するたびに 1 回だけ動作します。ブリッジをご自身で停止すると、アプリは黙って再びオンにはしません。

**タブ *MCP* がなくなった場合。** MCP 接続がオフになっています。手順 1 でオンにしてください。

**お使いのブラウザーのウェブページは、ブリッジと通信できません。** ブリッジは、ブラウザーから届くすべてのリクエストと、正しいトークンのないすべてのリクエストを拒否します。

## アプリを使わない場合

デスクトップアプリを使わずに動く MCP サーバーもあります。それが **ヘッドレス MCP サーバー** です。同じ `planner_*` ツールを提供しますが、開いているプロジェクトではなく、ディスク上のスケジュールファイルを操作します。そのため、Gantt チャートに変更は表示されず、アプリの *元に戻す* は、これらの変更には適用されません。アプリを開きたくない場合や、画面のないコンピューターで使う場合に利用します。

Claude Desktop 用の拡張機能は、アプリを閉じている場合にこのサーバーを自動で起動します（手順 3 を参照）。以下の手順は、Claude Code など別の MCP クライアント向けです。

このリリースには、すぐに使えるサーバーのダウンロードは含まれていません。`npm run build:mcp-server` を使い、ソースコードからビルドします。そのためには Node.js 22 以降が必要です。結果は、一つのファイル `server.mjs` です。

1. スケジュールファイルを置く作業フォルダーを選びます。サーバーは、そのフォルダーの中だけを読み書きします。
2. MCP クライアントを接続します。Claude Code の場合のコマンドは、手順の後に記載しています。
3. MCP クライアントに、スケジュールを開くよう依頼します（例: `~/plan.ifc`）。このサーバーでは、`~` が作業フォルダーを指します。
4. MCP クライアントに、結果を保存するよう依頼します。自動保存はありません。MCP クライアントが `planner_export_ifc` を使ってファイルを書き込みます。保存されなかった内容は、サーバーが停止すると失われます。

Claude Code の手順 2 では、ターミナルで次のコマンドを入力します。パスは、お使いの環境のものに置き換えてください。

```
claude mcp add open-planner -- node /path/to/server.mjs --root /path/to/working-folder
```

ドキュメントごとに、最初の変更の前に、サーバーはアプリと同様に MCP バックアップを作成します。作業フォルダーの外のパスを指定した MCP クライアントは、シンボリックリンク（ショートカット）経由の場合も含めて拒否されます。アプリが開いている間、サーバーは既存のファイルを上書きしません。
