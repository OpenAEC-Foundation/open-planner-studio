# スプレッドシートから進捗をインポートする

目標：現場スタッフがスプレッドシートに入力した進捗を、一度にスケジュールへ入れます。タスクを一つずつ自分でクリックする必要はありません。

## 必要になる場面

下請け業者や現場監督はアプリを持っていませんが、毎週、作業の状態を報告します。何パーセント完了したか、いつ開始したか、いつ終了したかです。タスクを記載したシートを送ります。相手は三つの列に入力し、返送します。アプリは、そこからタスクごとに三つの値だけを読み取ります：完了率、実績開始日、実績終了日。スケジュールのほかの部分は変更されません。アプリがその進捗をどう扱うかは、[進捗、状態日、ベースライン](docs://uitleg-voortgang)で説明しています。

## 手順

### 1. 状態日を設定して計算する

[進捗を更新する](docs://howto-voortgang-bijwerken)の説明どおりに状態日を設定します。現場監督は、その日まで（その日を含む）の実績日を入力します。スケジュールが最新でない場合、アプリはシートを作成する前に再計算します。

### 2. シートを作成する

*計画 › 進捗 › 進捗シートをエクスポート* を選択します。同じボタンが *テーブル* タブと *レポート* タブにもあります。アプリは Excel ファイルを作成し、ファイル名として *(プロジェクト名)-voortgang.xlsx* を提案します。ブラウザーでは、ファイルはダウンロードフォルダーに保存されます。CSV 形式がよい場合は、*ファイル › エクスポート › 進捗シート（CSV）* を選択します。Excel 形式のシートも、*進捗シート（Excel）* として用意されています。

シートには八つの列があります。列名は英語のままで、その後ろにアプリの言語で短い説明が付きます：

- `OPS Task ID`、`WBS`、`Name` は、タスクを見分けるためだけにあります。変更しないでください。
- `Start` と `Finish` は計画された日付で、参考用です。アプリがこれらを書き戻すことはありません。
- `Completion (%)`、`Actual Start`、`Actual Finish` は、入力する列です。

Excel シートは、パスワードなしで保護されています。編集できるのは、入力する三つの列だけです。Excel は、パーセンテージが 0〜100 の間にあるか、また実績日が日付であるかを確認します。フェーズ（サマリータスク）は灰色で示され、*— 要約タスク：入力しないでください* と表示されます。

### 3. 入力してもらう

現場監督は、タスクごとに次の項目を入力します：

- `Completion (%)`：0 から 100 まで（100 を含む）。アプリは小数も読み取ります（カンマまたはピリオド。例：33,3 や 33.3）。CSV の説明では、今も整数を入力するよう求めています。地域設定が異なる表計算ソフトでは、8,38 が 838 と読まれることがあります。
- `Actual Start`（実績開始日）と `Actual Finish`（実績終了日）：Excel では、お使いの地域設定の日付として入力します。CSV では dd-mm-yyyy または yyyy-mm-dd 形式で入力します。

空欄のままの項目は、何も変更しません。そのため、空欄で既存の進捗が消えることもありません。その操作はアプリでのみ行えます。まだ開始していないタスクは、完全に空欄のままにします。

### 4. シートを読み込む

1. *計画 › 進捗 › シートから進捗を更新* を選択します（*テーブル* タブと *レポート* タブにもあります）。または *ファイル › インポート › シートから進捗を更新* を選択します。*シートから進捗を更新* ウィンドウが開きます。
2. *ファイルを選択*… をクリックし、入力済みの `.xlsx` ファイルまたは `.csv` ファイルを選択します。
3. CSV の日付があいまいな場合、アプリは *日が先か、月が先か？* と尋ねます。ファイルの日付を二通りに読んだ結果を表示します。正しい日付をクリックします。
4. プレビューが表示されます。上部には四つのカウンターがあります：*適用済み*、*変更なし*、*紐付け待ち*、*拒否*。その下に、タスクごとの変更内容が表示されます。例：*完了率: 0% → 100%*。
5. プレビューを確認し、*適用* をクリックします。ウィンドウに *結果* が表示されます。カウンターと、拒否された行および理由が含まれます。最後に *閉じる* をクリックします。

プレビューを飛ばすことはできません。*適用* ボタンは、適用するものがない間は無効になっています。

### 5. スケジュールを再計算する

読み込んだだけでは、スケジュールは自動的に再計算されません。**計算**（F5）を押します。たとえば *計画 › スケジュール › 計算* から実行します。ただし *自動計算* がオンの場合は、この操作は不要です。

## 単純には当てはまらない行

アプリは、すべての行をタスクに紐付けます。まず `OPS Task ID` で紐付け、それがない場合は WBS 番号で紐付けます。

**紐付けが不確実。** アプリがタスクを WBS 番号だけで見つけた場合、その行は *紐付けが不確実* の下に表示され、*確定* と *変更* があります。何もしない場合も、その行は適用されます。そのため、タスクが正しいか確認してください。*確定* を選ぶと、その行はこの一覧から外れます。適用される内容は変わりません。*変更* を選ぶと、別のタスクを選べます。*紐付けを解除* で、自分で作った紐付けを削除できます。注意：同じ WBS 番号を持つ別のプロジェクトのシートも、やはり *紐付けが不確実* の下で紐付けられます。その場合も、*適用* をクリックすると適用されます。

**紐付け待ち。** アプリがタスクを見つけなかった場合、または同じ WBS 番号のタスクが複数ある場合、その行は *紐付け待ち* の下に表示されます。*タスクを選択*… で正しいタスクを選びます。WBS 番号または名前で検索できます。紐付けしない場合、その行は拒否されます。

## 注意点と、アプリの動作

当てはまらない行は、理由を付けて拒否されます。シートのほかの行は、そのまま処理されます。主なメッセージは次のとおりです：

- *実際の日付がステータス日より後です。* 状態日をあとの日付に設定するか、シートを修正してください。
- *このタスクはステータス日より後に開始する計画です。まずシートに実際の開始日を入力してください。* アプリは開始日を推測しません。シートで指定してください。
- *パーセンテージが0〜100の範囲外です。小数点記号を確認してください。地域設定が異なる表計算ソフトでは「8.38」が838と読み取られることがあります。*
- *サマリータスクはシートから進捗を受け取れません。* フェーズの進捗は、その下のタスクから決まります。
- *実終了が実開始より前です。*
- *日付を読み取れません。* と *パーセンテージを読み取れません。*
- *入力された値が矛盾しています。* たとえば、実績終了日があるのに完了率が100%未満の場合です。
- *この行に対応するタスクが見つかりません。* シートに書かれたタスク ID と WBS 番号が、このプロジェクトにありません。
- *このWBSコードは複数のタスクに存在します — 行を手動で紐付けてください。*
- *このタスクはすでに別の行が確保しています。* 二つの行が同じタスクを指しています。
- *プランナーに拒否されました。* プランナー自身による別の拒否で、独自のメッセージはありません。

ファイル全体が拒否された場合は、ウィンドウに次のいずれかのメッセージが表示されます：*このファイルには行をタスクに紐付ける「OPS Task ID」列も「WBS」列もありません。*、*このファイルには完了率・実開始・実終了のいずれの列もありません。*、*このファイルは大きすぎて進捗シートとして読み込めません。*（16 MB超）、*このファイルは行数が多すぎて進捗シートとして読み込めません。*（50,000行超）、*このファイルはパスワードで保護されているため読み込めません。* または *このファイルは進捗シートとして読み込めませんでした。*

**状態日なし。** まだ状態日がなく、インポートで進捗を適用する場合、アプリは状態日を今日に設定し、そのことを通知します。そのため、先に自分で設定してください。

**一度にまとめて元に戻せます。** シート全体の適用は、Ctrl+Z の一回で元に戻せます。

**入力した内容だけが対象です。** スケジュールとの差がない行は *変更なし* として扱われます。シートに行がないタスクは、そのまま変わりません。
