# 構造を調整する

目標は、タスクをフェーズとサブタスクに配置し、その順序を変更して、WBS 番号を正しく保つことです。

## この作業が必要な場合

スケジュールはツリー構造です。フェーズ（サマリータスク）の下にサブタスクがあります。たとえば、*Foundation* の下に *Groundwork*、*Reinforcement*、*Pouring* があります。このツリーを調整するのは、フェーズの下にタスクを配置したいとき、タスクをそこから外したいとき、または順序が正しくないときです。**WBS コード**（1、1.1、1.2、2、…）は、そのツリーにおけるタスクの番号です。

## 手順

### タスクをインデントする

1. タスクを選択します。複数のタスクを選択しても問題ありません。
2. *計画 › 構造 › インデント* を選択します。Alt+→（または Alt+Shift+→）を使うこともできます。右クリックメニューの *インデント* を選択することもできます。

タスクは、同じ階層の直前のタスクの最後のサブタスクになります。その結果、そのタスクはサマリータスクになります。連続した範囲を選択すると、範囲全体がインデントされます。同じ階層に直前のタスクがない場合は、何も起こらず、メッセージも表示されません。

### タスクのインデント解除

*計画 › 構造 › インデント解除* を選択するか、Alt+←（または Alt+Shift+←）を押すか、右クリックメニューの *インデント解除* を選択します。

タスクは、それまでぶら下がっていたフェーズの直後に、同じ階層のタスクとして配置されます。そのタスクのサブタスクも一緒に移動します。そのフェーズで後ろにあったタスクは、そのフェーズに残ります。最上位のタスクは、これ以上インデント解除されません。

### タスクを移動する

移動する方法は三つあります。

- **キーボードを使います。** Alt+↑ と Alt+↓ は、タスクを同じ階層の隣のタスクと入れ替えます。サマリータスクは、そのサブタスクも一緒に移動します。その階層の最上部または最下部では、何も起こりません。複数のタスクを選択しているときは、最初にクリックしたタスクだけが移動します。
- **タスクテーブルでドラッグします。** 行の上で押したまま、縦にドラッグします。行の上端の部分は *前* を、下端の部分は *後* を意味します。サマリータスクの中央部分にドロップすると、タスクはそのサマリータスクの最後のサブタスクとして配置されます。通常のタスクの中央部分は、最も近い端として扱われます。複数選択の一部である行をドラッグすると、選択全体が移動します。
- **Gantt でドラッグします。** バーを縦にドラッグして、別の行に移動します。これはタスクテーブルでのドラッグと同じように動作し、日付は変わりません。横にドラッグすると、代わりに日付が移動します。

各移動は、*元に戻す*（Ctrl+Z）の一つの操作として扱われます。

### WBS 番号を最新に保つ

*計画 › 構造* にある *WBS auto* ボタンを確認します。

- **オン（新しいプロジェクトの既定値）。** この設定のないファイルを開いたときも、すべての WBS コードがすでにツリーの番号（1、1.1、1.2 …）と一致していれば、オンになります。コードは変わりません。この設定のない空のファイルも、新しいプロジェクトと同じように *オン* になります。アプリは、追加、削除、移動のたびにツリー全体を再採番します。このとき WBS コードは読み取り専用になり、タスクテーブルや *プロパティ* パネルに入力できません。*WBS を再採番* は無効になります。
- **オフ。** 独自のコード（たとえば *A1000*）を持つファイル、またはツリーと一致しないコードが一つでもあるファイルでは、既定値です。コードは、移動やインデントの後もそのまま残ります。コードは自分で入力します。*WBS* 列、または *プロパティ* の *WBS コード* フィールドに入力します。または、*WBS を再採番* で一度だけ再採番します。これにより、自分で入力したコードも上書きされます。

*WBS auto* をオンにすると、アプリはすぐにツリーに番号を付けます。*WBS auto* と *WBS を再採番* は、どちらも *元に戻す* で取り消せます。

## 注意点とアプリの動作

**フィルター、グループ化、または並べ替えがオンになっています。** このとき表示されている順序はスケジュールの順序ではないため、アプリは構造を固定します。*インデント* と *インデント解除* は無効になり、ツールチップに *フィルター/グループ化/並べ替え中は使用できません* と表示されます。Alt+→ またはドラッグを行うと、同じ文章が赤いメッセージ行に表示されます。その行には *クリア* ボタンがあります。*クリア* を押すと、フィルター、グループ化、並べ替えがまとめて解除されます。Ctrl+Z では戻せません。メッセージ行は、× をクリックするか、Ctrl+Z か Ctrl+Y を押すか、別のドキュメントに移動するまで残ります。このとき、右クリックメニューには *インデント* と *インデント解除* が表示されません。

Alt+↑ と Alt+↓ は、このような表示でも動作します。メッセージは表示されません。フィルターだけの場合は、新しい順序がすぐに表示されます。並べ替えの場合は、スケジュールの順序は変わりますが、*クリア* を押してから初めて表示されます。

**WBS auto がオフです。** このことは、独自のコードを持つファイル、またはこの設定をオフとして保存しているファイルで起こります。新しいタスクには、ツリーでの位置に合うコードが付きます。ほかのタスクがすでに同じコードを持っていても、そうなります。そのため、同じ番号が重複することがあります。インデントの後も、コードがツリーと一致しなくなります。*WBS を再採番* で、この両方を直せます。

**マイルストーンにサブタスクが付きます。** マイルストーンは時点であり、サブタスクを持ちません。アプリはマイルストーンのフラグを外し、その旨を知らせます。

**リソースの割り当てがあるタスクにサブタスクが付きます。** サマリータスクは、割り当てを自分では持てません。そのため、アプリはまず *タスクがサマリータスクになります* ウィンドウで、その扱いを尋ねます。これは、タスクをインデントするとき、タスクで *サブタスクを追加* や *マイルストーンを追加* を使うとき、テンプレートを挿入するとき、そして *タスクの編集* で新しい *親タスク* を選ぶときに起こります。既存のタスクでも、新しいタスクでも同じです。*タスクの編集* では、この質問は保存の前に表示されます。ここで *キャンセル* を選ぶと、*タスクの編集* は変更を保ったまま開いたままになります。次のいずれかを選びます。

- *キャンセル*: 何も変わりません。構造も元のままです。
- *割り当てを削除*: タスクはサブタスクを持ち、その割り当ては削除されます。その割り当ての実績作業も削除されます。
- *「…」に移動*: 割り当ては、実績作業とともに、それを持てる最初の新しいサブタスクに移ります。マイルストーンやサマリータスクは割り当てを持てません。

そのサブタスクにすでに同じリソースが割り当てられている場合、または適切なサブタスクがない場合は、*移動* が無効になります。ウィンドウ内のオレンジ色の表示に理由が書かれています。

割り当てにすでに実績作業がある場合、オレンジ色の表示には、リソースごとの時間数が書かれます。たとえば *Metselaar の割り当てには、すでに 8 時間の実績作業があります。削除すると、その実績作業は破棄されます。* と表示されます。この場合、*キャンセル* が既定のボタンです。Enter を押しても何も変わりません。それでも割り当てを削除したい場合は、*割り当てを削除* を自分でクリックします。

ウィンドウが開いている間は、ウィンドウの外のショートカットは一切動作しません。*元に戻す*、*貼り付け*、Delete、F5、Ctrl+S も含みます。一つの操作で同時に複数のサマリータスクができる場合、ウィンドウにはタスクごとのリソースが表示され、選んだ内容はそのすべてに適用されます。一度の *元に戻す*（Ctrl+Z）で、操作全体が取り消されます。

**関係が循環を作ります。** サマリータスクの関係は、そのサブタスクにも適用されます。そのため、移動によって循環ができる場合、アプリは移動を拒否し、*この移動はスケジュールに循環を作ります（…）* というメッセージを表示します。何も変わりません。

**タスクと、その所属フェーズの間の関係。** すでに関係があるフェーズの下にタスクを配置すると、その関係は残りますが、計算にはもう使われません。アプリはその旨を知らせます。サマリータスクの関係について詳しくは、[関係とラグ](docs://uitleg-relaties) を参照してください。

**スケジュールが最新ではなくなります。** 別のフェーズへの移動によって、日付が変わることがあります。**計算**（F5）を押してください。同じフェーズ内で順序を入れ替えるだけでは、日付は変わりません。
