# AIアシスタントを接続する（MCP）

Open Planner Studio は、AIアシスタントに向けて自らを開放できます。AIモードをオンにすると、アプリ自体が **MCPサーバー** になります。Claude のようなアシスタントが、いま開いているそのウィンドウに接続し、スケジュールを読み取り、変更を加えられるようになるのです。作業の様子はその場で見えます — アシスタントが追加したタスクはすぐにガントに現れます — そして、アシスタントが行ったことはすべて、Ctrl+Z 一回で元に戻せます。

これは、ファイルをエクスポートしてどこかで編集し、また取り込むというやり方とは根本的に違うモデルです。コピーは存在せず、中間形式もなく、自分とアシスタントが別々のものを見ている瞬間もありません。このガイドでは、AIモードのオンにし方、アシスタントの接続方法、アシスタントにできることとできないこと、うまくいかないときの対処法を説明します。

## ここで学ぶこと

- AIモードをオンにし、AIタブを見つける。
- ブリッジを起動する、そしてアプリと一緒に自動的に起動させる。
- アシスタントを接続する — 用意されたプロンプトを使う方法と、設定スニペットを使う方法。
- アシスタントがスケジュールに対して何をできるか。
- 安全機能：一時停止、読み取り専用、自動バックアップ、アクティビティログ。
- 接続がうまくいかないときの対処法。

ブリッジが動作するのは **デスクトップアプリのみ** です。ブラウザ版でも AI タブ自体は表示されますが、サーバーそのものはデスクトップシェル側で動作しているため、ブラウザ版では起動できません。

## 有効にする

AIモードは既定でオフになっています。オンにするには **設定 → アプリケーション → AIモードを有効にする** を使います — 歯車アイコン、リボンの **設定** タブ、**ファイル → 設定** のいずれからでも、同じスイッチが表示されます。

オンにすると、リボンに追加の **AI** タブが現れます。AIモードを再びオフにすると、そのタブは消え、動作中のブリッジも即座に停止します — タブが表示されていない状態で、サーバーだけが陰で待ち受け続けることは決してありません。

その下には **ブリッジを自動的に開始** があります。これをオンにすると、アプリを開くと同時にサーバーが起動するため、AIタブを開かなくてもアシスタントが接続できます。既定ではオフです。自分のマシンで待ち受けポートを開くことは、意識的に選ぶべきことだからです。

## AIタブ

タブは4つのグループで構成されています。

**サーバー** — **ブリッジを開始**（または **ブリッジを停止**）ボタンと、その横に表示されるステータスです：*オフ*、*ポート 3877 で稼働中*、*ポート … は使用中です*、または *エラー*。同じステータスはステータスバー右下の色付きドットとしても表示されるため、ほかのタブにいてもブリッジが生きているかどうかがわかります。

**接続** — ポート番号（サーバーが停止しているときのみ編集でき、稼働中のサーバーは自分のポートを保持し続けます）、トークン、そして **接続** ボタンです。トークンは既定では隠されており、目のアイコンで表示、コピーボタンでコピーできます。**新しいトークン** で新規に発行します。ただし発行し直すと、既存の接続は *すべて* 切断されます — どれも古いトークンを使っているためで、だからこそアプリは先に確認を求めます。

**安全性** — **一時停止**、**読み取り専用**、**自動バックアップ** のスイッチ、そして **今すぐバックアップ** と **バックアップフォルダーを開く** の各ボタンです。それぞれの働きは、後述の *安全機能* で説明します。

**アクティビティ** — **アクティビティパネル** ボタンで、アシスタントが行ったすべての呼び出しの一覧が開きます：時刻、ツール名、所要時間、成功したかどうか。各行を展開すると引数と応答を確認できます。これがログです — アシスタントが何をしたかを、本人の申告だけに頼る必要はありません。

## アシスタントを接続する

**接続** をクリックします。開くウィンドウには、1つずつコピーできる4つのブロックがあります。

1. **エンドポイント** — ブリッジが待ち受けるアドレスで、既定では `http://localhost:3877/mcp` です。トランスポートはストリーミング HTTP です。
2. **認証** — すべてのリクエストに付けなければならない HTTP ヘッダーで、`Authorization: Bearer …` の形式です。
3. **設定スニペット** — お使いのクライアントの MCP 設定に貼り付けるための、そのまま使える JSON ブロックです。
4. **接続用プロンプト** — アシスタントにそのまま貼り付けるテキストで、渡すとアシスタント自身が接続し、その後自分のツール一覧を確認します。

最後のプロンプトが一番手っ取り早く、MCP サーバーを追加できるアシスタントであれば、どれでも使えます。このプロンプトは意図的に特定のベンダーに依存しない書き方になっています。アドレス、トークン、そして接続後にアシスタントが確認すべきことだけを伝える内容なので、どの提供元のアシスタントでも同じように機能します。

接続が完了したかどうかは、アシスタントが自分のツール一覧を取得できたかで判断できます。`planner_` で始まるツールが40個近く見えるはずです。1つも見えない場合は、ブリッジが起動していないか、トークンが間違っています。

トークンは、あなたが今開いているプランへのアクセス権を与えるものです。パスワードと同じように扱ってください — 共有ドキュメントに書いたり、ほかの人とのチャットで送ったりしないでください。

## アシスタントができること

ツール群は、あなたが自分でアプリ内で行うことのほぼすべてをカバーしています。

- **読み取り** — プロジェクト概要、タスク一覧、タスク1件の詳細、クリティカルパス、リソースとそのヒストグラム、カレンダー、ベースライン、そしてベースラインとの比較。
- **計画** — タスクの作成（フェーズとサブタスクを含む WBS 全体を一度に作成することも可能）、変更、移動、削除。関係の追加、変更、削除。進捗の記録。
- **セットアップ** — リソースの作成と割り当て、カレンダーと非稼働日の管理、ベースラインの保存とアクティブ化、山崩し。
- **管理** — ドキュメントの作成、複製、切り替え、スケジュールファイルのインポート、IFC へのエクスポート。

このリスト自体よりも重要なことが2つあります。

**アシスタントは、一連の手順を1つのスクリプトとしてまとめて実行できます。** ツールを1つずつ呼び出す代わりに、一連の手順をひとまとまりとして提出できるのです。これは単に速いというだけではありません — そのスクリプト全体が、履歴の中では1ステップになります。40件のタスクとその関係すべてを一度に組み立てたとしても、Ctrl+Z 一回でそっくり取り消せます。途中で構造的な問題が起きた場合は、中途半端なスケジュールが残るのではなく、スクリプト全体が丸ごとロールバックされます。

**スケジュールは、変更のたびに再計算されます。** アシスタントが別途それを依頼する必要はなく、そのため気づかないまま古い日付で作業を続けてしまうこともありません。

## アシスタントができないこと

ブリッジは、アプリそのものよりも意図的に狭い範囲に限定されています。頼んでもアシスタントには絶対にできないことがいくつかあり、その場合は代わりにどうすればよいかを説明する拒否が返ってきます。これはチャイルドロックのようなものではありません — どの場合も、いま見ているプロジェクトの範囲を超えて影響が及ぶ何かだからです。

**リソースライブラリ自体。** アシスタントは、ライブラリのリソースやカレンダーを作成・変更・削除できません。ライブラリはあなたのすべてのプロジェクトから共有されるアプリ全体のデータであり、そこへの編集は通常の元に戻す履歴の対象外です。1つの単価変更が、開いてすらいないプロジェクトにまで波及し、それを取り消す手段もなくなってしまいます。これは自分自身の手で、**ファイル → ライブラリ** から行ってください。

**継承されたリソースの固定項目。** リソースがライブラリ由来の場合、そのリソースが *何であるか* を決めるのはライブラリです：名前、種類、説明、単価/時間、単位。これらの項目が Resources タブでプレーンテキストとして表示されているのには理由があります — あなた自身もそこでは編集できません — そしてアシスタントも同様に手を出せません。一方で *プロジェクト* 側が決める項目、つまり最大単位数、時期別の可用性、カレンダー、班への所属は、引き続きアシスタントも扱えます。それでも別の単価に変更するよう頼むと、拒否の返答は本当の2つのルートを示します。ライブラリ側で変更する（この場合は *すべての* プロジェクトに適用されます）か、先にそのリソースをライブラリから切り離すかです — 切り離した後はプロジェクト専有になり自由に編集でき、その切り離し自体も Ctrl+Z で取り消せます。

**どのカレンダーをプロジェクトカレンダーにするか。** そのカレンダーの中身を編集することはできますが、プロジェクトが使うカレンダーそのものを入れ替えるのは、カレンダーライブラリで自分自身が行うことです。複数クリティカルパスの設定のような、スケジューリングのオプションについても同じことが言えます。

**アプリそのもの。** 設定、テーマ、言語、拡張機能、アップデーターに対するツールはありません。アシスタントは、あなたのプログラムの設定には一切手を加えません。

**ファイル — 可能ですが、範囲は限られます。** インポートとは、ディスク上のスケジュールファイルを読み取れるということであり、エクスポートとは IFC を書き出せるということです。書き出し先はあなたの個人フォルダー内に限られ、明示的に頼まない限り既存のファイルが上書きされることはありません。また、エクスポートは「保存」でもありません — あなたのドキュメントはアプリ上で未保存のままなので、アシスタントがあなたの気づかないうちにプロジェクトファイルを置き換えてしまうことはありません。

リソース一覧を取得すると、アシスタントはすぐに、どのリソースがライブラリ由来か、どのリソースライブラリに属しているか、そしてどの項目が固定されているかを把握します。壁にぶつかってから初めて知る、ということはありません。

## 安全機能

**一時停止** はブリッジを稼働させたまま、あらゆる変更を拒否します。読み取りは引き続き可能です。自分で何か作業したいときに、接続を切らずに済むので便利です。

**読み取り専用** も同じ効果を持ちますが、一時的な措置ではなく方針として機能します。アシスタントに、何も変更させることなくスケジュールを分析・報告・比較させたいときに使います。

**自動バックアップ** は、あるドキュメントへの最初の変更の前に、自動的に IFC のコピーを作成します。これはセッションごと・ドキュメントごとに1回だけ行われるため、呼び出すたびにファイルの山ができるわけではありません。**今すぐバックアップ** はそれを即座に実行します — アシスタントに思い切ったことをさせる直前などに便利です。**バックアップフォルダーを開く** で保存先に移動できます。アプリはドキュメントごとに直近10件を保持します。

これに加えて、通常の元に戻す履歴があり、アシスタントもそれをあなたと共有しています。アシスタントが行ったことはあなたが元に戻せますし、逆にアシスタント自身も元に戻す・やり直すことができます — undo と redo は、アシスタントの持つツールの一部でもあるからです。

## うまくいかないとき

**「ポート … は使用中です」。** すでに何かがそのポートで待ち受けています。多くの場合、これはこのアプリの2つ目のウィンドウです — ブリッジは一度に1つのウィンドウしか扱えません。もう一方のウィンドウを閉じるか、サーバーが停止している間に別のポート番号を選んでください。

**アシスタントから応答がない、または固まってしまう。** これは、サーバーの背後にあったウィンドウが閉じられたり、再読み込みされたりした場合に起こります。ブリッジを停止してもう一度起動してください。それでも解決しない場合は、アプリを再起動してください。まだ生きているか不安なときは、ステータスバーのステータスドットを確認してください。

**アシスタントにツールが1つも見えない、またはアクセスエラーが返る。** その場合はトークンが間違っています。これは主に、いったん接続を確立した後で **新しいトークン** をクリックしたときに起こります — アシスタント側はまだ古いトークンを使い続けています。**接続** ウィンドウから新しいトークンをコピーし、クライアント側の設定を更新してください。

**アシスタントは成功したと言っているのに、何も起きていない。** アクティビティパネルで、実際に何が呼び出され、何が返ってきたかを確認してください。拒否があった場合は、ほぼ必ず、問題のあった項目と代替手段の両方が示されます。

## AI アシスタントに良い計画を立てさせる

ツールを把握しているアシスタントでも、計画担当者には使えないスケジュールを作ってしまうことがあります。依存関係のないタスク、すべてのタスクに固定日付、あるいは維持できないほど細かい分解などです。それを防ぐ原則はガイド [良い計画づくり](docs://gids-goed-plannen) にまとまっています。着手前にアシスタントに読ませるか、指示の中で参照してください。さらに Open Planner Studio のソースには `.claude/skills/goed-plannen/` に短いエージェント用スキルがあり、中身は同じガイドを参照したうえで、エージェント固有の点だけを補います。`planner_` ツールを使う順序と、ユーザーに何を報告するかです。
