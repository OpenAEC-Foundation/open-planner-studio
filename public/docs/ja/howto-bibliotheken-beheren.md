# リソースライブラリの管理と共有

目的：リソースライブラリを作成および削除します。ライブラリにカレンダーを入れます。ライブラリをエクスポートまたはインポートします。目的は、バックアップまたは別のコンピューターでの利用です。

## この作業が必要なとき

リソースライブラリは、プロジェクトファイルの中ではなく、アプリの中にあります。デスクトップアプリでは、このコンピューター上のファイルに保存されます。ブラウザーでは、そのブラウザーの保存領域に保存されます。同期はされません。ブラウザーのサイトデータを消去すると、リソースライブラリは失われます。そのため、バックアップとしてエクスポートしてください。同僚が同じ作業班と単価を使いたい場合は、リソースライブラリをファイルとして渡します。組織に、それぞれ独自の作業班を持つ複数の事業会社がある場合は、会社ごとに別のリソースライブラリを作成します。新しいプロジェクトでは、どのリソースライブラリを使うかを選びます。

リソースライブラリとは何かは、[リソースライブラリ](docs://uitleg-resourcebibliotheek)で説明しています。ここではリソース自体は編集せず、リソースパネルで編集します。[リソースライブラリの使い方](docs://howto-resourcebibliotheek-gebruiken)を参照してください。

## 手順

### 管理画面を開く

*ファイル › ライブラリ* を選択します。左側にリスト *リソースライブラリ* があります。右側には、クリックしたリソースライブラリの詳細が表示されます。詳細は、名前、ボタン、リスト *カレンダー* です。画面の上部に、リソースは *リソース* タブで管理する旨が表示されます。

### 作成、名前の変更、既定のリソースライブラリの選択

1. リストの上にあるプラス記号（*リソースライブラリを追加*）をクリックします。リソースライブラリ *新しいリソースライブラリ* が追加され、すぐに選択されます。
2. 右側の上部にある名前欄に新しい名前を入力します。Enter キーを押すか、欄の外をクリックします。アプリは空の名前を受け付けません。
3. *既定に設定* をクリックすると、今後の新しいプロジェクトで、このリソースライブラリが初期選択されるようになります。既定のリソースライブラリには、リストに星印が付きます。

### リソースライブラリにカレンダーを入れる

1. *カレンダー* の下で、*プロジェクトから* をクリックします。アクティブなプロジェクトのカレンダーを含む一覧が開きます。
2. 取り込みたいカレンダーの後ろにある小さな矢印をクリックします。一覧の上に *追加しました。* と表示されます。このリソースライブラリにすでに紐づいているカレンダーには、名前の後ろに *リンク済み* と表示されます。
3. カレンダーは、これでリソースライブラリの *カレンダー* リストに入ります。鉛筆のアイコン（*編集*）で名前を変更し、チェックマークで保存します。ゴミ箱のアイコンを押すと、カレンダーは確認なしですぐに削除されます。プロジェクトにあるコピーは残ります。

*カレンダー* の後ろに、バージョン番号が表示されます（例：*v2*）。リソースライブラリを変更するたびに、番号が上がります。リソースライブラリのカレンダーは、それを使うリソースを割り当てると、プロジェクトに一緒に移ります。*リソース* タブの *ライブラリ* 表示にある *カレンダー* 列で、カレンダーをリソースに紐づけます。

### リソースライブラリをエクスポートする

1. 一覧からリソースライブラリを選択します。
2. *エクスポート* をクリックします。
3. デスクトップアプリと Chrome および Edge では、ファイルを保存する場所を選択します。ほかのブラウザーでは、ファイルはダウンロードフォルダーに直接保存され、アプリがその旨を表示します。ファイル名は `bibliotheek-` に続けてリソースライブラリの名前を付けたものになり、末尾は `.ifc` です。

ボタンの下に、*エクスポートはバックアップも兼ねます。ファイルは安全な場所に保管してください。* と表示されます。

### リソースライブラリをインポートする

1. *インポート* をクリックします。一覧で選択していたリソースライブラリ向けに、ウィンドウ *ライブラリをインポート* が開きます。
2. *ファイルを選択…* をクリックし、エクスポートで作成された `.ifc` ファイルを選びます。ファイルにリソースライブラリが含まれていない場合は、*このIFCファイルにはリソースライブラリが含まれていません。* と表示されます。
3. アプリには、ファイルの内容が表示されます。例：*カレンダー 2 件、リソース 5 件（バージョン 3）。*
4. 実行する操作を選びます。詳細は下で説明します。
5. *追加* または *置き換える* をクリックします。中止する場合は、*キャンセル* をクリックします。

選択肢は二つあります。

- *新しいリソースライブラリとして追加*：ファイルは、既存のリソースライブラリの横に、別のリソースライブラリとして追加されます。その下に、どの名前で追加されるかが表示されます。例：*「Mijn resourcebibliotheek (2)」として追加されます。* 何も失われません。また、アクティブなプロジェクトは、そのプロジェクト自身のリソースライブラリに紐づいたままです。
- *既存のリソースライブラリを置き換える*：選択したリソースライブラリの内容全体が、ファイルの内容に置き換えられます。アプリもこれを表示します：*インポートすると、選択したリソースライブラリのプール全体が置き換えられます。* リソースライブラリが二つ以上ある場合は、*リソースライブラリにインポート* の下で、置き換える先を選びます。ローカルのリソースライブラリがファイルより新しい場合、アプリは警告します：*ローカルのライブラリの方が新しいため、インポートすると変更が上書きされる可能性があります。*

アプリが自動で選択肢を提案します。既定のリソースライブラリを含むファイルの場合は、*新しいリソースライブラリとして追加* が初期選択されます。ファイルのリソースライブラリがこのコンピューターにすでにあり、既定ではない場合は、*既存のリソースライブラリを置き換える* が初期選択され、そのリソースライブラリが選ばれた状態になります。迷う場合は、追加を選択してください。追加では何も上書きされません。

### リソースライブラリを削除する

1. 一覧でリソースライブラリを選択し、*リソースライブラリを削除* をクリックします。最後の一つのリソースライブラリでは、ボタンが灰色になります。リソースライブラリは常に一つ残るためです。
2. *削除* で確認します。質問は *このリソースライブラリを削除しますか？* です。開いているプロジェクトがこのリソースライブラリに紐づいている場合は、*このリソースライブラリは1件の開いているプロジェクトに紐づいています。削除するとそれらのプロジェクトとの紐づけが解除されます。続行しますか？* と表示されます。プロジェクトが複数ある場合は、件数だけを変えて同じ文が表示されます。例：*2件の開いているプロジェクトに紐づいています*

その後、リソースライブラリは、中にあるすべてのリソースとカレンダーとともに削除されます。このリソースライブラリを使っていた開いているプロジェクトは、紐づけが解除されます。それらのプロジェクトのリソースは、通常のプロジェクトのリソースとして残ります。内容を残したい場合は、先にエクスポートしてください。

### プロジェクトをそのリソースライブラリと一緒に渡す

プロジェクトファイルには、リソースのコピーが含まれています。リソースライブラリ全体も渡したい場合は、次の手順に従ってください。エクスポートそのものについても、[エクスポート](docs://howto-exporteren)で説明しています。

1. リソースライブラリに紐づいているプロジェクトを開き、*ファイル › エクスポート* を選択します。
2. *ライブラリファイルも一緒に保存* にチェックを入れます。このチェックボックスは、紐づいたプロジェクトでのみ表示されます。
3. カード *IFC* を選択し、ファイルを保存します。アプリは続けて二つ目のファイルも求めます。このファイルの名前は、プロジェクトの名前に `-bibliotheek` を付けたものになり、リソースライブラリを含みます。

このチェックボックスは IFC のエクスポートでのみ働き、ほかのエクスポート形式では働きません。同僚は、上で説明したとおりに二つ目のファイルをインポートします。

## 注意点と、その場合にアプリが行うこと

**二人のプランナー、二つのリソースライブラリ。** アプリは、コンピューター間でリソースライブラリを同期しません。インポートのウィンドウには、これについての警告が常に表示されます：*注意：ライブラリはコンピューター間で同期されません。二人のプランナーが同じリソースライブラリを使うと、ライブラリの内容が食い違うことがあります。組織が事業会社をまたいで作業班を共有している場合は、共有のリソースライブラリを一つ、意図的に選んでください。*

**置き換えると、すべてが上書きされます。** 選択したリソースライブラリにあった内容は、すべて失われます。また、リソースライブラリの変更は *元に戻す* の対象外です。確かでない場合は、先にエクスポートしてください。プロジェクトには、それぞれのコピーが残ります。アプリは、新しいファイルにまだ存在するコピーを更新します。新しいファイルにもうないコピーには、*ライブラリにはもう存在しません* という印が付き、そのまま使えます。コピーが異なる場合は、ウィンドウ *リソースライブラリにリンク* が開きます（[リソースライブラリの使い方](docs://howto-resourcebibliotheek-gebruiken)を参照）。

**一覧からカレンダーを削除すると、すぐに実行されます。** アプリは確認を求めません。一方で、リソースを削除する場合は確認を求めます。これは欠点のように見えます。リソースライブラリの変更は *元に戻す* の対象外です。
