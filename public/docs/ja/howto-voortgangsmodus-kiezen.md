# 進捗モードの選び方

目的: 先行タスクがまだ実行中のときにすでに開始しているタスクの残作業を、アプリが関係に従って（Retained Logic）計画するか、実際に起きることに従って（Progress Override）計画するかを決めます。

## この手順が必要な場合

現場では、実際の工事が論理より先に進むことがよくあります。左官がまだ別の場所で仕事をしている間に、塗装工はすでに漆喰が塗られた部屋で仕事を始めます。スケジュールでは、これは、たとえば、後続タスクが先行タスクの終わる前に開始する終了-開始の関係です。アプリはこれを **順序外進捗** と呼びます。ステータスバーに *順序違反の関係: N 件* と表示されている場合、このケースがあります。進捗モードは、アプリが後続タスクの残作業をどのように計画するかを決めます。両方のモードの動作は、計算例とともに [進捗、状態日、ベースライン](docs://uitleg-voortgang) に書かれています。

## 手順

1. [進捗の更新](docs://howto-voortgang-bijwerken) で説明したとおりに、進捗を更新して状態日を設定します。
2. *計画 › ベースラインと進捗 › 進捗モード* に移動し、一覧を開きます。
3. *Retained Logic* または *Progress Override* を選択します。
4. **計算**（F5）を押します。たとえば *計画 › スケジュール › 計算* から実行できます。選択すると、スケジュールは古くなります。ステータスバーに *古くなっています — 再計算してください（F5）* と表示されます。*自動計算* が有効な場合、アプリがこれを自動で行います。

どのように選びますか？

- **Retained Logic** が既定です。関係は有効なままです。後続タスクの残作業は、先行タスクが終わってから初めて開始します。順序が本当に固定されている場合、または慎重に計画したい場合は、これを選択します。
- **Progress Override** では、実際の状況が優先されます。後続タスクの残作業は、先行タスクを待たずに状態日に開始します。後続タスクが実際に仕事を続けていて、終了日がまだ実行中の先行タスクに左右されるべきでない場合は、これを選択します。

## 結果の確認

- ステータスバーのメッセージ *順序違反の関係: N 件* をクリックします。*警告* パネルが開きます。このパネルは *計画 › スケジュール › 警告* からも開けます。すべての関係がこのパネルに、次の文言とともに表示されます: *順序違反: 後続タスクの進捗が関係と矛盾しています*。例: *4.2 Plastering → 4.5 Painting (FS)*。
- 後続タスクのバーを確認します。Retained Logic では、バーは先行タスクの終了後まで続きます。Progress Override では、バーはより早く終わります。説明の例では、これは7月27日（火曜日）対7月22日（木曜日）です。

## 注意点とアプリの動作

**違いはありません。** このモードが効果を持つのは、先行タスクがまだ終わっていないのに、すでに開始しているタスクだけです。そのようなタスクがなければ、何も変わりません。

**メッセージは残ります。** Progress Override では、順序外進捗のメッセージは解消されません。モードはアプリの計算方法を決めます。関係と進捗の矛盾は残ります。関係が正しくなくなった場合は、変更してください（[関係の追加](docs://howto-relaties-leggen)）。

**プロジェクトに属します。** この選択は、プロジェクトファイルと一緒に保存されます。プロジェクト全体に適用され、Ctrl+Z で元に戻せます。新しいプロジェクトは Retained Logic に設定されます。

**P6 ファイル。** Primavera P6 のファイル（.xer）を開くと、アプリはモードをそのファイルから取得します。P6 には、Retained Logic と Progress Override のほかに Actual Dates もあります。アプリはその第三のモードを知りません。そのようなファイルは Retained Logic として計算されます。インポートのメッセージでは、これは *安全なフォールバックを使った P6 計画設定: 1* として数えられます。

**計算プロファイル。** Primavera P6 プロファイルでは、Progress Override は後方にも働きます。先行タスクの遅い日付とフリーフロートに影響します（規則 *Progress Override は開始済みの後続を後方計算でも無視する*）。Open Planner Studio と Microsoft Project のプロファイルでは、そうではありません。規則は *設定 › プロジェクト › プロジェクト設定* にあり、ブロック *計算プロファイルとオプション* に含まれています。説明の例では、この後方への作用は見えません。
