# プロジェクトの移動

目的：スケジュール全体を新しい開始日に移動し、移動が終了にどう影響するかを事前に確認します。

## 必要になる場面

工事の開始がずれます。許可が遅れる場合や、以前の住宅のスケジュールを次の住宅に再利用する場合です。タスクを一つずつ移動するのは手間がかかります。**プロジェクトを移動** を使うと、新しい開始日を一つ入力するだけで、アプリがすべてを一緒にずらします。

プロジェクト終了日は、開始と同じ日数だけ移動するとは限りません。**カレンダー** は一緒には移動しません。祝日、建設業休暇、冬季の休止は固定日のままです。例：*ホーム › ファイル › 新規* で、*開始日* が 29-09-2026、*国* が *オランダ*、*建設業休暇* が *なし* のプロジェクトを作成します。そのプロジェクトに、30 稼働日のスケジュールを入れます。このスケジュールは 2026年11月9日に終了します。2026年12月14日に移動すると、暦日で 76 日後ろになります。すると、終了は 2027年1月26日になります。これは 78 日後ろです。12月25日と1月1日が、スケジュール内で休みになるためです。期間は 30 稼働日のままです。ウィンドウのプレビューで、何かを変更する前にこれを確認できます。

## 手順

1. *計画 › スケジュール › プロジェクトを移動…* を選択します。プロジェクトに開始日がない間、ボタンは使えません。
2. *現在のプロジェクト開始日* で、プロジェクトが今どこから始まるかを確認します。*新しいプロジェクト開始日* で、新しい日付を選択します。
3. プロジェクトにベースラインがあると、チェックボックス *ベースラインも移動する* が表示されます。移動を差異として引き続き確認したい場合は、オフのままにします（「落とし穴とアプリの動作」を参照）。
4. *プレビューを計算* をクリックします。アプリは移動後のスケジュールを全体について計算しますが、プロジェクトは何も変更しません。
5. プレビューを確認します（下記参照）。正しければ *移動* をクリックします。

プレビューには次の内容が表示されます：

- 暦日での移動量（*移動量：暦日で 76 日後ろへ*）；
- *プロジェクト開始日* と *プロジェクト終了日*、移動前から移動後まで；
- カレンダーが影響する場合は赤い警告、またはプロジェクトの期間は変わらないというメッセージ；
- 移動するタスクの数と、一緒に移動するもの；
- 読むべき警告（「落とし穴とアプリの動作」を参照）。

アプリは新しいスケジュールをすぐに計算するため、**計算**（F5）を使う必要はありません。また、表示をプロジェクト全体に合わせます。この操作全体が一つの操作になるため、*元に戻す*（Ctrl+Z）で一度に取り消せます。

*移動* ボタンは、エラーのないプレビューの後で、かつ新しい日付が現在の日付と異なる場合にのみ使えます。日付またはチェックボックスを変更すると、プレビューは消えます。もう一度計算してください。

### 一緒に移動するものと、しないもの

移動するもの：すべてのタスクの開始と終了、実績開始日と実績終了日、制約の日付（厳格な必須固定も含む。[制約と期限](docs://uitleg-constraints) を参照）、期限、状態日、外部関係のアンカー、リソースの利用可能量の段階。プロジェクト開始日も移動します。入力済みの場合は、プロジェクト終了日も一緒に移動します。

移動しないもの：

- カレンダー。そのため、祝日、建設業休暇、冬季の休止は移動しません。
- ベースライン。ただし *ベースラインも移動する* をオンにした場合は除きます。
- 種類が *日付* で、入力済みのカスタムフィールド。

## 落とし穴とアプリの動作

**終了は、開始とは異なる日数だけ移動します。** プレビューで、終了が開始より多くまたは少ない暦日だけ移動する、または稼働日でのプロジェクトの期間が変わることがわかると、数値付きの赤い警告を表示します。その場合でもキャンセルできます。

**ベースラインはそのまま残ります。** ベースラインは、差異を測るために存在します。チェックボックスをオフにしてプロジェクトを移動すると、その移動はベースラインからの差異として表示されます。チェックボックスをオンにすると、ベースラインもスケジュールと一緒に移動します。移動するのは日付だけです。ベースラインを保存した日付は変わりません。

**進行中のプロジェクト。** 実績日も一緒に移動します。進捗をすでに入力したプロジェクトでは、これが常に望ましいとは限りません。アプリは警告します：*進行中のプロジェクトでこれが正しいか確認してください。*

**外部関係。** 自分のプロジェクトのアンカーは一緒に移動しますが、元のプロジェクトは移動しません。移動後は、*ホーム › タスク › リンク ▾ › すべての外部関係を更新* でリンクを更新します。[別のプロジェクトへの外部関係](docs://howto-externe-relaties) を参照してください。

**祝日が十分な範囲をカバーしていません。** 生成済みの祝日があるカレンダーは、いくつかの年をカバーします。移動したスケジュールがその範囲を超える場合、アプリはその年を祝日なしで計算します。プレビューは次のように警告します。例：*カレンダー「Bouwkalender NL」の生成済み祝日は 2025–2029 をカバーしていますが、移動後の工程は 2030 年まで続きます。祝日を再生成してください。*先にプロジェクトを移動してください。次に *計画 › カレンダー › カレンダー* を開きます。祝日の横に *再生成* と表示されるようになります。*適用* で確定すると、アプリは再計算します。新しい祝日の範囲はプロジェクトの日付に従うため、移動の前に再生成しても効果はありません。

**日付が過去です。** これは許可されていますが、プレビューがそれを伝えます：*新しい開始日は過去の日付です。*

**プロジェクト設定でプロジェクト開始日を変更することは、別の操作です。** *設定 › プロジェクト › プロジェクト設定* で開始日を変更し、*適用* を選択しても、スケジュールは移動しません。先行タスクも制約もないタスクのうち、新しい開始日より前になるものだけが、その日付まで移動します。アプリは、その数を知らせます。すべてを移動したい場合は、*プロジェクトを移動…* を使ってください。
