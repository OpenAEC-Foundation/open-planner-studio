# 関係とラグ

なぜれんが積み工事は、基礎ができてから初めて始まるのでしょうか。また、屋根部材の納品が遅れると、なぜ屋根の設置が一週間遅れるのでしょうか。これは、タスク同士の関係によって決まります。この記事では、アプリが認識する四種類の関係、ラグとリードの働き、ラグを数えるカレンダー、フェーズに置いた関係の扱い、そして、どの関係がタスクの開始日を決めるかを説明します。

この記事の規則と例は、計算プロファイル *Open Planner Studio* を使う新しいプロジェクトに当てはまります。稼働週は月曜日から金曜日までです。

## 基本的な考え方

**関係** は、二つのタスクが互いに依存していることを記録します。最初のタスクが**先行タスク**、二番目のタスクが**後続タスク**です。関係は下限です。後続タスクは、関係が許す日付より早く開始することも終了することもありません。ただし、それより遅く開始または終了することはあります。タスクに先行タスクが複数ある場合、そのタスクは、それらすべての関係から導かれる最も遅い日付まで待ちます。

関係には四種類あります。種類ごとに、先行タスクのどの時点（開始または終了）が、後続タスクのどの時点と結び付くかが異なります：

- **FS（終了-開始）。** 後続タスクは、先行タスクが終了して初めて開始します。屋根部材は、壁が立ち上がって初めて取り付けます。これは断然よく使われる関係です。
- **SS（開始-開始）。** 後続タスクは、先行タスクが開始して初めて開始します。タスクは重なることがあります。配管は、れんが積み工事が進行中になるとすぐに開始できます。
- **FF（終了-終了）。** 後続タスクは、先行タスクが終了して初めて終了します。目地仕上げは、れんが積み工事が終わるまで完了できませんが、開始はそれより早くてもかまいません。
- **SF（開始-終了）。** 後続タスクは、先行タスクが開始して初めて終了します。この種類はまれです。例として、仮設の排水は、基礎のれんが積み工事が開始して初めて停止できます。

関係には、**ラグ** を付けることもできます。ラグは、二つのタスクの間の待ち時間です。例えば、養生が必要なコンクリートの待ち時間です。負のラグは**リード**と呼ばれます。その場合、後続タスクは先行タスクが終了する前に開始するため、タスクが重なります。

## アプリの計算方法

### 四種類の関係

アプリは、関係ごとに後続タスクが開始できる最も早い日付を計算します。そして、タスクのすべての関係のうち最も遅い日付を採用します。ラグがない場合の動作は次のとおりです：

- FS の場合、後続タスクは先行タスクの終了後、最初の稼働日に開始します。
- SS の場合、後続タスクは先行タスクと同じ日に開始します。
- FF の場合、後続タスクは先行タスクと同じ日に終了します。開始日を求めるため、アプリは後続タスクの期間を逆算します。したがって、後続タスクが 3 稼働日の場合、先行タスクの終了の 2 稼働日前に開始します。
- SF の場合、後続タスクは先行タスクが開始する日に終了します。ここでも、アプリは後続タスクの期間を逆算します。

これらは下限です。ほかの関係や制約がそれを求める場合、後続タスクは遅く開始します。すべての日付は、**計算**（F5）を実行した後にのみ表示されます。ステータスバーに *古くなっています — 再計算してください（F5）* と表示されている間、バーは前回の計算に基づいています。

### ラグとリード

ラグは、次の四つの方法で指定できます：

- **稼働日**（`3` または `3d`）：アプリは休日と週末を飛ばします。これが既定です。
- **暦日**（`3ed`。e は *経過* 時間の略です）：すべての日が数えられます。土曜日と日曜日も含みます。養生など、作業が行われずに続く待ち時間の単位です。
- 先行タスクの期間に対する**割合**（`40%`）：アプリは計算のたびにこれを再計算し、整数の日数に丸めます（2.5 日は 3 日になります）。
- **稼働時間**（`4h`）：アプリは、ラグを *ラグカレンダー* で数えます。既定では先行タスクのカレンダーです。先行タスクが日タスクで、かつ、そのカレンダーに独自の帯がない場合（例：標準カレンダー）、アプリは時間を整数の稼働日に換算します。換算は最も近い整数の日に丸めます（半日は切り上げます）。稼働日が 8 時間の場合、`2h` と `3h` は 0 日、`4h` から `11h` まで（両端を含む）は 1 日、`12h` は 2 日になります。そのカレンダーに独自の帯がある場合、または先行タスクが時間タスクである場合、ラグは稼働時間のまま正確に数えられます。

FS で N 稼働日のラグがある場合の規則は次のとおりです。先行タスクの終了後の N 稼働日は待ち時間です。後続タスクは、その次の稼働日に開始します。SS と FF の場合、ラグはそれぞれ先行タスクの開始と終了に加算されます。負のラグは逆方向に数えます。FS で 1 稼働日のリードを付けると、後続タスクは先行タスクが終了する日に開始できます。

リードによって、タスクをプロジェクト開始日より前に置くことはできません。そうなる場合、アプリは後続タスクをプロジェクト開始日に留め、*警告* パネルに次のように表示します：*リードがプロジェクト開始で切り詰められました — 関係が完全には守られていません*

### ラグが数えられるカレンダー

すべてのタスクには、独自のカレンダーを設定できます。稼働日で表したラグでは、どのカレンダーで稼働日を数えるかが重要です。その選択は *ラグカレンダー* の項目で決めます。選択肢は四つです：*先行*、*後続*、*24時間*、*プロジェクトカレンダー*。既定では、ラグは **先行タスク** のカレンダーで数えられます。この項目は *設定 › プロジェクト › プロジェクト設定* にあります。*計算プロファイルとオプション* のブロック内、*このプロジェクトの計算オプション* の項目です。この選択はプロジェクトファイルに保存され、*適用* をクリックした後にのみ有効になります。その後、スケジュールは再計算されます。

暦日のラグ（`3ed`）は、どの *ラグカレンダー* を選んでも、常にすべての日を数えます。

### サマリータスクへの関係

関係は、フェーズ内のタスクではなく、フェーズ（サマリータスク）に置くこともできます。内部では、アプリはその関係をフェーズ内のすべてのタスクに置きます：

- フェーズを **先行タスク** として FS または FF で置く場合：後続タスクは、フェーズ内で最後に終了するタスクが終わるまで待ちます。
- フェーズを **後続タスク** として FS または SS で置く場合：フェーズ内のすべてのタスクが先行タスクを待ちます。フェーズ内のほかのタスクとは無関係です。
- フェーズを **先行タスク** として SS または SF で置く場合：後続タスクは、フェーズ自体の開始ではなく、フェーズ内で **最後に** 開始するタスクの開始を待ちます。これは思ったより慎重な動作です。後続タスクが早すぎる開始になることはありませんが、意図したより遅くなることがあります。後続タスクをフェーズの開始に従わせたい場合は、関係をフェーズ内の最初のタスクに置いてください。
- フェーズを **後続タスク** として FF または SF で置く場合：フェーズ内のすべてのタスクは、終了の条件を自分で満たさなければなりません（FF では先行タスクの終了以降、SF では先行タスクの開始以降に終わる必要があります）。これは、ずっと早く終えられたはずのタスクでも同じです。そのような関係は、フェーズ内の最後のタスクに置くことをおすすめします。

タスクと、そのタスクが含まれるフェーズとの間の関係は許可されていません。

### 駆動関係

後続タスクに先行タスクが複数ある場合、通常は一つの関係が開始日を決めます。駆動関係は、後続タスクが現在より一日でも早く開始することを防いでいる関係です。このような関係を **駆動関係** と呼びます。同点の場合は、駆動関係が複数あります。駆動関係は、表の *先行タスク* 列と *後続タスク* 列の稲妻のマーク、*駆動* 列（表見出しの右側にある **+**、*依存関係* の下）、そして経路をたどるときのより濃い色合いで見分けられます。その経路を開く方法は、[経路のトレース](docs://howto-pad-traceren) にあります。

駆動関係は、期間ではなく日付について示します。短い先行タスクも、例えば長いラグが原因で駆動関係になることがあります。その例は、以下の計算例で示します。

## 計算の例

これらの例では、別々の小さなプロジェクトを使います。特に記載がない限り、すべて2027年6月7日（月曜日）から始まります。クリティカルパスやフロートなどの用語は、[クリティカルパスとフロート](docs://uitleg-kritiek-pad) で説明しています。関係のネットワークを自分で作成して確認するのは、チュートリアル2「関係とクリティカルパス」で行う作業です。

### 四種類を並べて比較

*Pour foundation* は5稼働日かかります。6月7日（月曜日）から6月11日（金曜日）までです。*Build walls*（5稼働日）は FS で続き、6月14日（月曜日）から6月18日（金曜日）まで行われます。それぞれ3稼働日の四つのタスクが *Build walls* から分かれて接続しています。それぞれ異なる種類の関係を持ちます：

- *Place roof elements*（FS）は6月21日（月曜日）に開始します。これはれんが積み工事の後の最初の稼働日です。6月23日（水曜日）に完了します。
- *Pipework*（SS）は、れんが積み工事と同時に6月14日（月曜日）に開始し、6月16日（水曜日）に完了します。
- *Pointing*（FF）は、れんが積み工事と同時に6月18日（金曜日）に完了している必要があります。3稼働日なので、6月16日（水曜日）に開始します。
- *Dewatering*（SF）は、れんが積み工事が始まる日である6月14日（月曜日）に終了しなければなりません。3稼働日を逆算すると（6月10日（木曜日）、6月11日（金曜日）、6月14日（月曜日））、開始日は6月10日（木曜日）になります。

クリティカルパス上にあるのは *Place roof elements* だけです。プロジェクトは6月23日（水曜日）に完了します。*Pipework*、*Pointing*、*Dewatering* には、それぞれ5、3、7稼働日のフロートがあります。

### 数字で見るラグとリード

*Pour foundation* は6月18日（金曜日）に完了します。*Build walls*（2稼働日）は FS で続きます。ラグが開始日に与える影響は次のとおりです：

- ラグがない場合、れんが積み工事は6月21日（月曜日）に開始します。
- ラグ `3`（3 稼働日）の場合、6月21日（月曜日）、6月22日（火曜日）、6月23日（水曜日）が待ち時間です。れんが積み工事は6月24日（木曜日）に開始します。
- ラグ `3ed`（3暦日）の場合、土曜日、日曜日、月曜日が数えられます。れんが積み工事は6月22日（火曜日）に開始します。
- ラグ `-1`（一稼働日のリード）の場合、れんが積み工事は6月18日（金曜日）に開始します。その日は *Pour foundation* が完了する日です。
- ラグ `40%` の場合、ラグは5稼働日の40%、つまり2稼働日です。れんが積み工事は6月23日（水曜日）に開始します。
- ラグ `50%` の場合、ラグは2.5稼働日で、3稼働日に丸められます。れんが積み工事は6月24日（木曜日）に開始します。

### ラグを数えるカレンダー

*Build walls*（4稼働日）は、プロジェクトカレンダー（月曜日から金曜日）上にあり、6月10日（木曜日）に完了します。*Pointing*（2稼働日）は、ラグ `3` を付けて FS で続きます。土曜日と日曜日も稼働日となるカレンダー上にあります。そのため、開始日は *ラグカレンダー* によって決まります：

- *先行*（既定）：ラグは、れんが積み工事のカレンダーで数えます。6月11日（金曜日）、6月14日（月曜日）、6月15日（火曜日）が待ち時間です。*Pointing* は6月16日（水曜日）に開始します。
- *後続*：ラグは、*Pointing* のカレンダーで数えます。6月11日（金曜日）、6月12日（土曜日）、6月13日（日曜日）が待ち時間です。*Pointing* は6月14日（月曜日）に開始します。
- *24時間*：すべての暦日が数えられます。ここでも金曜日、土曜日、日曜日が待ち時間です。*Pointing* は6月14日（月曜日）に開始します。
- *プロジェクトカレンダー*：ラグは、*先行* の場合と同じく、プロジェクトカレンダーで数えます。*Pointing* は6月16日（水曜日）に開始します。

### フェーズへの関係

*Foundation* は、二つのタスクを含むフェーズです。*Excavate*（2稼働日、6月7日（月曜日）と6月8日（火曜日））と、その後の *Pour*（3稼働日、6月9日（水曜日）から6月11日（金曜日）まで）です。*Build walls* は、フェーズ *Foundation* に FS で続き、6月14日（月曜日）に開始します。アプリは、*Build walls* が、最後に終了するタスクである *Pour* を待つように設定します。

フェーズを後続タスクとする場合：*Permit*（3稼働日、6月9日（水曜日）に完了）は、FS でフェーズ *構造* に続きます。フェーズには *Build walls*（4稼働日）と、その後の *Lay floor*（2稼働日）が含まれます。フェーズ内のすべてのタスクは *Permit* を待ちます。*Build walls* は6月10日（木曜日）に開始し、6月15日（火曜日）に完了します。*Lay floor* も、れんが積み工事を待ち、6月16日（水曜日）から6月17日（木曜日）まで行われます。

フェーズから SS で続く場合：フェーズ *Finishing* には、*Plastering*（2稼働日、6月7日と6月8日）、その後の *Painting*（3稼働日、6月9日から6月11日まで）、その後の *Snagging*（2稼働日、6月14日と6月15日）が含まれます。*Cleaning* は、フェーズに SS で続きます。6月7日（月曜日）に開始すると予想するかもしれません。しかし、アプリは *Cleaning* を、最後に開始するタスクである *Snagging* の開始まで待たせます。その開始日は6月14日（月曜日）です。

### 駆動関係の例

*Pour foundation*（2稼働日）は、6月7日（月曜日）から6月8日（火曜日）まで行われます。その後、二つの分岐があります：

- *Build walls*（5稼働日）：6月9日（水曜日）から6月15日（火曜日）まで。
- *Order roof elements*（2稼働日）：6月9日（水曜日）と6月10日（木曜日）。

*Place roof elements*（3稼働日）は、その両方に続きます。れんが積み工事の後に FS で続き、注文（納期）の後に FS とラグ `5` で続きます。れんが積み工事からは、設置は6月16日（水曜日）に開始できます。注文からは、6月11日（金曜日）、6月14日（月曜日）、6月15日（火曜日）、6月16日（水曜日）、6月17日（木曜日）が待ち時間です。*Place roof elements* は6月18日（金曜日）に開始します。注文はれんが積み工事よりずっと短いにもかかわらず、その関係が駆動関係です。れんが積み工事には、2稼働日のフロートがあります。

## 結果と誤解

**「関係はタスクを固定する。」** いいえ、関係は下限です。後続タスクは、関係が示す日付に最も早く開始します。ほかの関係や制約がそれを求める場合は、より遅く開始します。制約がどのように関係するかは、[制約と期限](docs://uitleg-constraints) で説明しています。

**「SS は、タスクが同時に開始することを意味する。」** SS は、後続タスクが先行タスクの開始より前に開始できないことだけを示します。後続タスクにほかの先行タスクがあり、それがより遅く終了する場合、後続タスクはより遅く開始します。

**「FF では、後続タスクは同じ日に開始する。」** いいえ、FF では終了日が一致します。そのため、短い後続タスクは先行タスクより遅く開始します。例の *Pointing* のように。

**「日数のラグは暦日を数える。」** 既定では、ラグは先行タスクのカレンダーで稼働日を数えます。養生や乾燥のように週末も数える場合は、暦日（`ed`）を使います。

**「関係のないタスクは問題ない。」** 先行タスクがないタスクは、計画された開始日に開始します。後続タスクがないタスクは、プロジェクトの終了日までフロートを得ます。そのため、関係を付け忘れると、タスクには十分な余裕があるように見えます。誤解の詳細は、[クリティカルパスとフロート](docs://uitleg-kritiek-pad) を参照してください。

**「フェーズへの関係は一つの関係である。」** 計算では、フェーズ内のタスクごとに一つの関係になります。フェーズへタスクを移動したり、フェーズからタスクを移動したりすると、それらのタスクに適用される関係も変わります。
