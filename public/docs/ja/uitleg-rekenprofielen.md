# 計算プロファイルと規則

同じスケジュールでも、適用する計算ルールによって異なる日付になることがあります。この記事では、Primavera P6 と Microsoft Project が一部の点で異なる計算をする理由を説明します。アプリがその違いを **計算プロファイル** にどう記録するかも説明します。さらに、プロファイルがプロジェクトごとに自分で設定する計算オプションとどう異なるかも説明します。一つの小さなネットワークを使った作業例で、これが日付にどう影響するかを示します。

## 概念

タスク、関係、カレンダーで、スケジュールの大部分は決まります。しかし、すべてが決まるわけではありません。状態日を設定したとき、まだ始まっていない作業はどうなりますか。すでに進行中のタスクの残作業は、どこから始まりますか。期限を過ぎたとき、タスクのフリーフロートはいくつになりますか。ネットワークはこれについて何も示しません。スケジュール計算のパッケージは、そのためのルールを 1 つ選ぶ必要があります。アプリは、Primavera P6 と Microsoft Project のルールが異なる点をいくつか把握しています。

アプリは、このような選択肢を **規則** と呼びます。**計算プロファイル** は、1 つのパッケージに属する規則の集まりです。アプリには三つのプロファイルがあります。

- *Open Planner Studio*: 新しいプロジェクトが計算に使うプロファイルです。規則はどれもオンになっていません。
- *Primavera P6*: アプリが P6 から把握している規則です。
- *Microsoft Project*: アプリが Microsoft Project から把握している規則です。

つまり、プロファイルはパッケージの計算方法を示します。プロジェクトで何を望むかは、プロファイルには含まれません。プロジェクトで何を望むかを示すものが **計算オプション** です。たとえば、どの程度少ないフロートでタスクをクリティカルとみなすか、または、どのカレンダーでラグを数えるかなどの選択肢です。これらはプロジェクトごとに設定します。

## アプリの計算方法

### 規則と計算オプション

規則は切り替えスイッチです。オンまたはオフになります。どのスイッチをオンにするかは、プロファイルが決めます。計算オプションは、ユーザーが選ぶ設定です。違いは、アプリ内の *計算プロファイルとオプション* ブロックで確認できます。

- **規則** は *このプロファイルの規則* の下にあり、内容ごとにまとめられています。たとえば *進捗と完了済みの作業*、*関係とラグ*、*フロートと遅い日付* です。この部分は、最初は折りたたまれています。見出しには規則の数が表示され、プロファイルが既定値から外れている場合は *変更: 1* のようなラベルも表示されます。見出しをクリックすると展開されます。組み込みプロファイルでは、各行に *オン* または *オフ* のラベルがあります。この値は参考情報で、変更できません。カスタムプロファイルでは、各行にチェックボックスがあり、その後ろに基準の値が表示されます（*基準: オン* または *基準: オフ*）。選択がその値と異なる場合、その行が目立ち、*基準に戻す* が表示されます。行の後ろにある i アイコンを押すと、その規則の説明が開きます。マウスを重ねるか、Tab キーで移動するか、タップします。規則を変更したい場合は、先にその説明を読んでください。規則が時間計画のときだけ、または .xer のタスクだけに働く場合は、その横の青いラベルがそれを示します。*時間計画のときのみ* または *.xer のタスクのみ* です。時間計画とは、帯のある稼働時間のカレンダー、時間単位の期間を持つタスク、または *ラグカレンダー* が *24時間* に設定されている状態のことです。日単位のカレンダーと日単位のタスクだけのプロジェクトは、*ラグカレンダー* が *24時間* でない限り、*時間計画のときのみ* の規則の影響を受けません。その場合、ラグは時間で数えられ、ラグに関する規則は何かを変えることがあります。
- **計算オプション** は *このプロジェクトの計算オプション* の下にあります。ほかには *クリティカルの定義*、*フロート計算*、*オープンエンドタスクをクリティカルにする*、*準クリティカルとしてマーク*、*ラグカレンダー* があります。これらは、計算プロファイルがどう計算するかではなく、このプロジェクトで何を望むかを示します。その働きは [クリティカルパスとフロート](docs://uitleg-kritiek-pad) と [関係とラグ](docs://uitleg-relaties) で説明しています。

それぞれの例です。「タスクのトータルフロートが 0 以下であればクリティカル」は計算オプションです。しきい値を 4 に設定できます。その場合、4 稼働日以下のフロートを持つすべてのタスクがクリティカルになります。「まだ始まっていない作業を状態日に移動する」は規則です。Open Planner Studio と Primavera P6 はこれを行いますが、Microsoft Project は行いません。

プロファイルと計算オプションは、アプリではなくプロジェクトファイルに属します。プロジェクトを保存すると、それらも一緒に保存されます。そのため、同じアプリ内の 2 つのプロジェクトが、異なるプロファイルで計算することがあります。プロファイルがないプロジェクトは、Open Planner Studio として計算されます。

プロジェクトが .xer ファイルから来ている場合、ブロックの下部に *ソースファイルの設定* も表示されます。これは、ファイルと一緒に持ち込まれた計算オプションで、Primavera だけが把握しているものです。ここでは変更できません。既定の設定を使うボタンや別のプロファイルを選んでも、それらはそのまま残ります。新しいプロジェクトには、*Primavera P6* を選んでも *ソースファイルの設定* はありません。

### プロファイルを選ぶ場所

新しいプロジェクトの場合、プロファイルは *新規プロジェクト* ウィンドウにあります。このウィンドウは *ホーム › ファイル › 新規* から開きます。そこで *計算プロファイル* はドロップダウンリストです。ここでプロファイルを選ぶと、アプリは入力済みの計算オプションを、そのプロファイルの既定値に置き換えます。残るのはソースファイルの設定だけです。*Primavera P6* を選ぶと、*フロート計算* は *終了フロート* になります。*Microsoft Project* と *Open Planner Studio* では、すべての計算オプションが既定値になるため、*フロート計算* は *自動（既定）* です。状態日がある場合、MS Project 自身もこのように計算します。開始済みのタスクは終了フロートを使い、ほかのすべてのタスクは開始フロートと終了フロートのうち小さい方を使います。

既存のプロジェクトの場合、プロファイルは *設定 › プロジェクト › プロジェクト設定* の下で選びます。*計算プロファイルとオプション* ブロックの、ドロップダウンリスト *計算プロファイル* です。同じ場所には *ファイル › プロジェクト設定* からも移動できます。ここでプロファイルを切り替えると、規則だけが変わります。計算オプションはそのままです。計算オプションがプロファイルの既定値と異なる場合、オプションの上にあるオレンジ色のブロックがそれを示します。これは、開いたファイルから計算オプションを読み込んだ場合などに、意図したものであることが多いです。とにかく既定値に戻したい場合は、そのブロックで *… の既定の設定を使う* を選びます。× ボタンを押すと、この開いたファイルについてはブロックが非表示になります。

*適用* を押すまで、変更はフォーム内にだけ存在します。*適用* を押すと、*自動計算* がオフでも、アプリはすぐにスケジュールを再計算します。タスクが移動した場合、アプリは件数を表示します。例：*適用後に 4 件のタスクが移動しました。* 切り替え全体は、*元に戻す* の 1 回で取り消せます。*プロジェクト設定* を開いたまま *元に戻す* または *やり直し* を押すと、ブロックはプロジェクトの状態に従います。ブロック内の変更をすでに自分で行っていた場合は、その選択が残り、黄色のブロックが、*適用* を押すとその選択が戻ることを示します。

組み込みの 3 つのプロファイルは変更できません。ほかの規則を変えたい場合は、カスタムプロファイルを作ります。カスタムプロファイルは、このアプリ内の他のプロジェクト用に、テンプレートとして保存することもできます。プロジェクトは常に自分のコピーを持ちます。テンプレートを後から変更しても、プロジェクトは一緒には変わりません。手順は [計算プロファイルの選択と作成](docs://howto-rekenprofiel-kiezen) に説明されています。

### アプリがプロファイルを自動で選ぶ場合

ファイルを開くと、アプリは形式に基づいてプロファイルを提案します。

- .mpp ファイル（Microsoft Project）は、プロファイル *Microsoft Project* で開きます。
- .xer ファイル（Primavera P6）は、プロファイル *Primavera P6* で開きます。
- *MS Project XML*、*Primavera P6 XML*、または *CSV（セミコロン区切り）* の形式のファイルは、プロファイルの通知なしに *Open Planner Studio* で開きます。
- 独自のプロジェクト（.ifc）は、そのファイルに保存されたプロファイルで開きます。

.mpp ファイルまたは .xer ファイルの場合、アプリはプロファイルを通知します: *このプロジェクトは Microsoft Project として計算されます。変更は ファイル → プロジェクト情報 → 計算プロファイルとオプション で行えます。* 通知内の *計算プロファイルを開く* ボタンで、すぐにプロジェクト設定へ移動します。.xer ファイルの場合、この行は、ファイルを開いたときの通知の 1 行目の詳細になります。通知の詳細は [Primavera P6 ファイル（.xer）を開く](docs://howto-xer-openen) と [MS Project ファイル（.mpp）を開く](docs://howto-mpp-openen) に説明されています。

.mpp ファイルの場合、アプリはプロファイルだけを設定します。計算オプションは空のままです。これは、プロファイル *Microsoft Project* の新しいプロジェクトと同じです。*フロート計算* は *自動（既定）* です。そのため、開いた .mpp ファイルと、*Microsoft Project* の新しいプロジェクトは、フロートを同じように計算します。

## 作業例：一つのネットワーク、三つのプロファイル

この例は小さなネットワークです。カレンダーには、月曜日から金曜日までの稼働週があります。これらの週には非稼働日はありません。進捗モードは Retained Logic（既定）です。プロジェクト開始日は 2027年6月7日（月）です。すべてのタスクは稼働日で示します。

- *Pour foundation*: 5 稼働日、計画された開始日は 6月7日（月）。
- *Lay walls*: 5 稼働日、*Pour foundation* の後（終了-開始）。
- *Order window frames*: 3 稼働日、先行タスクなし、計画された開始日は 6月7日（月）。
- *Fit roof*: 2 稼働日、*Lay walls* の後、かつ *Order window frames* の後。このタスクの終了が引き渡しです。

数値はアプリの計算エンジンで計算しました。*プロパティ* パネルの *CPM 結果* の下で確認できます。

**状態日も進捗もない場合、三つのプロファイルはこのネットワークを同じように計算します。** *Pour foundation* は 6月7日（月）から 11日（金）まで実行されます。*Lay walls* は 6月14日（月）から 18日（金）まで、*Fit roof* は 6月21日（月）と 22日（火）に実行されます。引き渡しは 6月22日（火）です。*Order window frames*（6月7日（月）から 9日（水）まで）のトータルフロートは 7 稼働日です。

次に、状態を記録します。状態日は 6月9日（水）です。基礎は 6月7日（月）に始まり、進捗は 60 % です。したがって残作業は 2 稼働日です（5 × 40 %）。*Order window frames* はまだ始まっていません。[進捗と状態日](docs://uitleg-voortgang) の仕組みは、その記事に説明されています。ここでの問題は、プロファイルがこれをどう扱うかです。

### Open Planner Studio

基礎の残作業は、状態日の 6月9日（水）と 10日（木）に行われます。最早開始は実績開始日のままで、6月7日（月）です。最早終了は 6月10日（木）です。*Lay walls* は 6月11日（金）から 17日（木）まで、*Fit roof* は 6月18日（金）と 21日（月）に実行されます。

*Order window frames* は 6月7日（月）に計画された開始日でしたが、まだ始まっていません。未開始の作業は過去に置けません。そのため、アプリはそれを状態日に移動します。6月9日（水）から 11日（金）まで実行され、トータルフロートは 4 稼働日です。引き渡しは 6月21日（月）です。

### Primavera P6

一点を除き、すべて Open Planner Studio と同じです。その一点は、*Pour foundation* の最早開始が 6月9日（水）であることです。これは実績開始日ではなく、残作業の開始日です。これは、グループ *進捗と完了済みの作業* にある規則 *進行中タスク：最早開始 = 残作業の開始* によって行われます。これによって、終了とフロートは変わりません。引き渡しは 6月21日（月）です。

### Microsoft Project

ここでは日付が異なります。原因は、グループ *Microsoft Project と同じ進捗* にある二つの規則です。

*未開始タスクをステータス日付へ移動しない*: *Order window frames* は 6月7日（月）から 9日（水）のままです。この期間の一部は状態日より前ですが、移動しません。トータルフロートは 7 稼働日です。

*残作業は経過期間の後に再開*: 残作業は、状態日より前には始まりません。また、実績開始日に、すでに経過した時間（経過時間）を足した日より前にも始まりません。5 稼働日の 60 % は 3 稼働日です。つまり 3 稼働日分が完了しています。6月7日（月）に 3 稼働日を足すと、6月10日（木）です。これは状態日より後なので、残作業は 6月10日（木）と 11日（金）に行われます。*Lay walls* は 6月14日（月）から 18日（金）まで、*Fit roof* は 6月21日（月）と 22日（火）に実行されます。引き渡しは 6月22日（火）です。他の二つのプロファイルより 1 稼働日遅くなります。

### 変更した場合

**基礎の進捗が 60 % ではなく 20 % の場合。** その場合、残作業は 4 稼働日です。三つのプロファイルすべてで、基礎は 6月14日（月）に終了し、引き渡しは 6月23日（水）です。残作業に関する Microsoft Project の規則は、ここでは差を生みません。6月7日（月）に経過 1 稼働日を足すと 6月8日（火）になり、これは状態日より前です。このような規則は下限にすぎず、残作業を遅らせることしかできません。*Order window frames* と Primavera P6 の最早開始は、上で述べたように依然として異なります。Microsoft Project では、*Order window frames* のトータルフロートは 8 稼働日になります。

**状態日だけを設定し、進捗は入力しない場合。** Open Planner Studio と Primavera P6 では、ネットワーク全体が 6月9日（水）に移動します。基礎は 6月9日（水）から 15日（火）まで実行され、引き渡しは 6月24日（木）になります。これは状態日がない場合より 2 稼働日遅くなります。Microsoft Project では、すべてが元の位置のままで、引き渡しは 6月22日（火）です。

**自分でプロファイルを組み立てる場合。** Open Planner Studio で *新しいプロファイル* を使い、*Copy of Open Planner Studio* を元にしてカスタムプロファイルを作ります。そのうえで、*未開始タスクをステータス日付へ移動しない* だけをオンにします。進捗 60 % の場合、基礎は Open Planner Studio の日付のまま残ります（終了は 6月10日（木）、引き渡しは 6月21日（月））。*Order window frames* は 6月7日（月）から 9日（水）のままで、トータルフロートは 6 稼働日です。つまり、プロファイルは個別のスイッチをまとめたものです。それぞれを 1 つずつ変更できます。

**規則の代わりに計算オプションを使う場合。** Open Planner Studio で、*クリティカルの定義*（*トータルフロート ≤ しきい値*）の *しきい値（稼働日）* を 4 に設定すると、*Order window frames* はクリティカルになります。そのトータルフロートがちょうど 4 だからです。日付は変わりません。計算オプションは、プロジェクトに対する選択であり、プロファイルとは無関係です。

**期限を過ぎた場合。** *Fit roof* に 6月18日（金）の期限を設定します。Open Planner Studio では、*Fit roof* のトータルフロートは −1 稼働日になり、フリーフロートも同じく −1 です。Primavera P6 では、トータルフロートは −1 のままですが、フリーフロートは 0 になります。これは、グループ *フロートと遅い日付* にある規則 *フリーフロートを負にしない* によるものです。Microsoft Project では、両方とも −2 です。引き渡しが 1 日遅くなるためです。期限の仕組みは [制約と期限](docs://uitleg-constraints) に説明されています。

## 結果と誤解

**「プロファイルはアプリの設定です。」** いいえ。プロファイルと計算オプションは、プロジェクトに属し、ファイルと一緒に保存されます。アプリに属するのは、保存したテンプレートだけです。プロジェクトは常に、そのコピーを自分で持ちます。

**「エクスポートすると、プロファイルも一緒に保存されます。」** 保存されるのは、独自のプロジェクト形式（.ifc）の場合だけです。*MS Project XML*、*Primavera P6 XML*、または *CSV（セミコロン区切り）* にエクスポートすると、プロファイルはファイルに入りません。計算オプションのうち、MS Project XML へのエクスポートが書き出すのは、最大でもクリティカルのしきい値までです。アプリが警告を出すのは、.xer ファイルから取り込んだプロジェクトの場合だけです。自分で作成したプロジェクトでは、何も表示されません。そのためファイルは、プロファイルのメッセージなしに Open Planner Studio として開きます。例を見てください。プロファイル Microsoft Project と進捗 60 % のプロジェクトです。これを *MS Project XML* にエクスポートして、もう一度開きます。アプリは最初に、ファイルの日付を表示します。引き渡しは 6月22日（火）です。アプリに自分で再計算させると、6月21日（月）になります。エクスポートで失われるその他の内容は、[ファイルと形式](docs://uitleg-bestanden) にあります。

**「Primavera P6 プロファイルは、P6 と同じ結果を出します。」** アプリはそれを保証できません。プロファイルが切り替えるのは、アプリが P6 から知っている規則です。それは P6 のすべての設定ではありません。Retained Logic と Progress Override に加えて、P6 には三番目の進捗モード、Actual Dates があります。アプリはこれを知りません。そのため、このような .xer ファイルは Retained Logic として計算され、開いたときのメッセージにその旨が表示されます。例: *安全なフォールバックを使った P6 計画設定: 1*。Primavera P6 プロファイルの規則の中にも、.xer ファイルから取り込んだタスクでのみ動作するものがあります。例えば *未開始の LOE は目標ウィンドウを使う* と *実績日付を正確に取り込む* です。一部の規則では、説明にその旨が書かれています。「P6 の出所があるタスクのみ」。自分で作成したタスクでは、これらの規則は何もしません。

**「進捗モードはプロファイルの一部ですか。」** いいえ。Retained Logic または Progress Override は、プロジェクトごとに選ぶ別の設定です。プロファイルとは別に設定します。[進捗モードの選び方](docs://howto-voortgangsmodus-kiezen) を参照してください。Primavera P6 の規則の一つ、*Progress Override は開始済みの後続を後方計算でも無視する* は、Progress Override を選んだときにのみ動作します。

**「試しにプロファイルを切り替えて、結果を見ます。」** できます。*適用* は 1 回の操作で、*元に戻す* で取り消せます。プロファイルと日付は一緒に元に戻ります。ただし、日付は実際に動くことがあります。例では、Open Planner Studio から Microsoft Project に切り替えると、4 件のタスクがすべて移動します。メッセージは移動したタスクの数を数えて表示します。作業を続ける前に、その後のスケジュールを確認してください。.xer または .mpp を開いた後も、アプリがファイルの日付を表示している場合、プロファイルを切り替えるとこの表示をやめ、アプリが自分で計算します。その仕組みは [記録された日付](docs://uitleg-datums-zoals-opgeslagen) にあります。

**「例では四つの規則を示していますが、アプリの一覧はもっと長いです。」** ブロックの各行には、それぞれ説明があります。まずそれを読んでください。また、グループ *カスタムプロファイル専用* も確認してください。このグループの規則は、Primavera P6 を含むすべての組み込みプロファイルで無効です。有効にできるのはカスタムプロファイルだけです。*新しいプロファイル* で作成します。
