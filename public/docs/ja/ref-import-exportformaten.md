# インポートとエクスポートの形式

ファイル形式ごとに、開けるか、保存できるか、エクスポートできるかを示します。また、何が引き継がれて何が引き継がれないか、どの計算プロファイルで開くかも示します。この仕組みの理由と、数字を使った例は [ファイルと形式](docs://uitleg-bestanden) にあります。

## 概要

**開く** は IFC、CSV、MS Project XML、Primavera P6 XML、`.mpp`、`.xer` に対応しています。ファイル名の末尾が上記以外のファイルは、アプリが IFC として扱います。

**保存** は常に IFC 形式で書き込みます。開いた IFC ファイルだけが保存先になります。ほかの形式からのプロジェクトは、開いた後にファイルがありません。その場合、*保存* を選ぶと、IFC ファイルの保存先を尋ねられます。

**エクスポート** は IFC、MS Project XML、Primavera P6 XML、CSV、二種類の進捗シート（Excel と CSV）に対応しています。エクスポートはプロジェクトを変更しません。

**読み取り専用** は `.mpp` と `.xer` です。アプリはこれらを開けますが、書き込めません。

**PDF** はレポートからのみ出力されます（[レポートの種類](docs://ref-rapporttypes) を参照）。アプリは PDF を読み込みません。

**場所。** 開くには *ホーム › ファイル › 開く*、*ファイル › 開く*、または Ctrl+O を使います。エクスポートするには *ホーム › ファイル › エクスポート*、または *ファイル › エクスポート* を使います。記入済みの進捗シートは *ファイル › インポート* から読み込むか、*計画*、*テーブル*、*レポート* タブのリボングループ *進捗* にあるボタン *シートから進捗を更新* を使います。

**開くときの計算プロファイル。** どの形式も計算プロファイルを持って開きます。その内容は [計算オプションと規則](docs://ref-rekenopties-en-conventies) にあります。`.xer` は *Primavera P6*、`.mpp` は *Microsoft Project* で開きます。CSV、MS Project XML、P6 XML は *Open Planner Studio* で開きます。IFC は、ファイルに保存された計算プロファイルを使います。`.xer` と `.mpp` では、アプリはこの方法で計算すると表示します。計算プロファイルと計算オプションを保持するのは IFC だけです。計算オプションのうち、MS Project XML が書き込むのは最大でクリティカルのしきい値までです。他の形式のエクスポートを開き直すと、*Open Planner Studio* として計算されます。

## IFC

**開く** — はい、`.ifc` を開けます。アプリは IFC4 と IFC 4.3（ADD2 を含む）を読み込みます。IFC2X3 など、別のスキーマのファイルも開けます。最初に保存するとき、アプリが書き込めるスキーマを選びます（[IFC スキーマの選択](docs://howto-ifc-schema-kiezen) を参照）。計算プロファイル: ファイルに保存されているもの。

**保存** — はい。保存できる形式は IFC だけです。*保存* を選ぶと、プロジェクト全体が IFC ファイルとして書き込まれます。書き込みは、プロジェクトの IFC スキーマ（既定は IFC 4.3 ADD2）で行います。そのファイルが保存先になります。

**エクスポート** — はい。*IFC* として、プロジェクトの IFC スキーマで書き出します（既定は IFC 4.3 ADD2）。既定の名前は、プロジェクト名に `.ifc` を付けたものです。プロジェクトがリソースライブラリに関連付けられている場合、チェックボックス *ライブラリファイルも一緒に保存* は *ファイル › エクスポート* のカードの下にあります。オンにすると、アプリはプロジェクトの後に *projectname-bibliotheek.ifc* の保存先を尋ねます。このチェックボックスは *ホーム* タブの一覧にはありません。

**引き継がれるもの** — プロジェクトに属するものはすべてです。構造を持つタスク、期間、日付、進捗。ラグ付きの関係。制約と期限。カレンダー。リソースと割り当て（時間配分を含む）。ベースライン。アクティビティコードとカスタムフィールド。メモ。他のプロジェクトへの外部関係。中断。タスク種類とカスタムの作業区分。状態日、進捗モード、計算プロファイル、計算オプションなどのプロジェクト設定。リソースライブラリとの関連。`.xer` から開いたプロジェクトでは、元のソースファイルも一緒に引き継がれます。カスタムの作業区分は、IFC の型 `USERDEFINED` として保存され、名前は ObjectType フィールドに入ります。そのため、他の IFC プログラムでもタスクを通常どおり読めます。アプリは作業区分の固定 ID も保持するので、名前を変えてもリンクは壊れません。別のコンピューターでファイルを開くと、その作業区分は *このプロジェクトから* の下に表示され、相手側の *自分の作業区分* には表示されません。

**引き継がれないもの** — 画面の設定（ズーム、スクロール位置、選択中のタスク、折りたたんだフェーズ、選んだフィルターとグループ化）と、アプリの設定（[設定](docs://ref-instellingen)）です。*IFC* タブは、プロジェクトの IFC テキストを編集するエディターです。*IFC を生成* でテキストを更新し、*コピー* でクリップボードに入れ、*適用* でテキストをプロジェクトとして読み込みます。その場合、そのタブのプロジェクトは置き換えられます。

## MS Project XML (MSPDI)

**開く** — はい。アプリは、ルート要素 `Project` を持つ `.xml` ファイルを MS Project XML として認識します。この要素は MS Project の名前空間に属するか、名前空間を持ちません。計算プロファイル: *Open Planner Studio*。開いた後、アプリは引き継がれなかった内容を一つのメッセージで知らせます。詳しくは [MS Project ファイル (.mpp) を開く](docs://howto-mpp-openen) を参照してください。

**保存** — いいえ。このようなプロジェクトには保存先がありません。

**エクスポート** — はい。*MS Project XML* として（説明文: *Microsoft Project で開けます。完全な WBS 構造。*）。既定の名前は、プロジェクト名に `.xml` を付けたものです。

**引き継がれるもの** — 構造（階層と WBS）、期間、日付、進捗を持つタスク。時間またはパーセンテージのラグを含む関係。期限を含む制約。タスクとリソースのカレンダーを含むカレンダー。曲線または時間配分を含むリソースと割り当て。状態日。クリティカルのしきい値は、0 以上の整数の稼働日数として、*トータルフロート ≤ しきい値* と書き込まれます。タスクの説明（メモとして）。タスクのタスク種類（MS Project のタスク種類として）。カスタムの作業区分は、アプリが読み戻す自由なフィールド（`ExtendedAttribute`）に入ります。MS Project はこれを無視する場合があります。ベースラインのうち、有効なものだけが、ベースライン 0 として引き継がれます。時間を単位とするタスクは、その単位を保持します。マイルストーンは、その種類（開始、終了、または自動）を保持します。

**引き継がれないもの** — メモ（タスクのチェックリスト）、他のプロジェクトへの外部関係、アクティビティコードとカスタムフィールド、二つ目の制約、*手動スケジュール* の印、山崩し遅延、順序外進捗のタスクの再開点と停止点、MS Project プロファイルの規則 *残作業は経過期間の後に再開* と *未開始タスクをステータス日付へ移動しない*、そのほかの計算オプションです。時間配分のない中断タスクは、中断を除いて引き継がれます。

**開くときの祝日。** 派生カレンダーは、基になるカレンダーの例外日を引き継ぎます。独自の週の稼働日を持ち、例外日がないカレンダーには、祝日が入りません。基になるカレンダー、週の稼働日、例外日のいずれもない素のカレンダーだけが、標準のオランダの祝日を保持します。祝日がないと、終了日が変わることがあります。詳しくは [祝日と建設業休暇の生成](docs://howto-feestdagen-genereren) を参照してください。

**途中で変わるもの** — *必須（ピン留めロジック）* を選ばない *指定日に開始 (MSO)* または *指定日に終了 (MFO)* の制約は、*指定日以降に開始 (SNET)* または *指定日以降に終了 (FNET)* になります。ハンモックは、計算された日付を持つ通常のタスクになります。MS Project XML は、プロジェクトカレンダーの一日あたりの時間だけを保存します。ほかのカレンダーが独自の一日あたりの時間を持つ場合、ファイルを開くと、その稼働時間が一日あたりの時間になります。例えば、一日あたり 8 時間の設定で稼働時間が 10 時間なら、10 時間になります。このようなカレンダーの日単位のタスクは短くなります。例えば、5 日ではなく 4 日になります。

## MS Project ファイル (`.mpp`)

**開く** — はい。MS Project 2010 から 2021 までのファイルを開けます。計算プロファイル: *Microsoft Project*。アプリはファイルを読むだけです。`.mpp` を変更することはありません。MS Project 2007 以前のファイルと、パスワード付きのファイルは開けません。その場合、アプリは MS Project の XML エクスポートを案内するメッセージを表示します。開いた後、アプリは引き継がれなかった内容を一つのメッセージで知らせます。

**保存** — いいえ。保存先はありません。*保存* を選ぶと、新しい IFC ファイルが書き込まれます。

**エクスポート** — いいえ。

**引き継がれるもの** — 構造、期間、制約を持つタスク。ラグ付きの関係。カレンダー。リソースと割り当て。進捗。MS Project で自分で入力した WBS コード。MS Project が自分で計算した日付とフロートも読み込まれます。これは表示 *記録されたとおりの日付* で使われます。

**引き継がれないもの** — ベースライン、コストと単価、メモ、ハイパーリンク、MS Project のカスタムフィールド、サブプロジェクトと外部タスクの参照、クリティカルのしきい値。詳しくは [MS Project ファイル (.mpp) を開く](docs://howto-mpp-openen) を参照してください。

**由来とライセンス** — `.mpp` の読み込み機能は Open Planner Studio のために作られました。MPXJ（`github.com/joniles/mpxj`、Jon Iles ほか）のソースコードと構造に関する知識から派生しています。MPXJ は LGPL-2.1 の Java ライブラリです。構造とフィールドの定数は TypeScript に移植されました。Open Planner Studio 自体は LGPL-3.0 のオープンソースです。`.xer` の読み込み機能は派生物ではありません。そこでは、MPXJ は理解の参考としてのみ参照されました。

## Primavera P6 XML

**開く** — はい。アプリは、ルート要素 `APIBusinessObjects` を持つ `.xml` ファイルを P6 XML として認識します。計算プロファイル: *Open Planner Studio*。

**一つのファイルに複数のプロジェクト。** タスクを持つ各プロジェクトは、独自のタブで開きます。タブ名は *プロジェクト名（プロジェクト ID）* です。タスクのないプロジェクトは飛ばします。有効なタブは、タスクが最も多いプロジェクトです。別のプロジェクトへの関係や、どのプロジェクトにも属さないタスクは引き継がれません。開いた後、アプリは開いたプロジェクトの数を知らせます。

**開くときの祝日。** MS Project XML と同じ規則が適用されます。独自の週の稼働日を持ち、例外日がないカレンダーには、祝日が入りません。

**ベースライン。** ファイル内の `<BaselineProject>` は、そのプロジェクトのベースラインになります。P6 が有効と表示するベースラインは、アプリでも有効になります。

**割り当ての単価。** 残作業がある場合、残りの単価（`RemainingUnitsPerTime`）が *単位/日* になります。残作業がない場合は、計画された単価（`PlannedUnitsPerTime`）になります。資材の場合、計画された単価はそのままです。アプリは、ファイルを開くときに何も再計算しません。P6 XML にエクスポートするときは、計画された単価を `PlannedUnitsPerTime` として書き込みます。残りの単価を `RemainingUnitsPerTime` として書き込むのは、割り当てが別の計画された単価を持つ場合だけです。

**読めるタスクがありません。** アプリは、読めるタスクが見つからなければ、タブを開きません。理由がわかっている場合は、理由とともに知らせます。例えば、`ObjectId` のないタスク、または XML ファイル内の XER の列名です。その場合は、P6 からプロジェクトを P6 XML として再度エクスポートするか、`.xer` として開いてください。

**保存** — いいえ。

**エクスポート** — はい。*Primavera P6 XML* として（説明文: *Oracle Primavera P6 用。*）。既定の名前は、プロジェクト名に `.xml` を付けたものです。プロジェクト ID があれば、その ID が丸かっこ（）内に入ります。MS Project XML のエクスポートにも同じ名前が付きます。違う名前は自分で付けてください。

**プロジェクト名とプロジェクト ID。** アプリは、P6 のプロジェクト ID をプロジェクト名とは別に保持します。`.xer` の場合と同じです。*プロジェクト設定* には名前だけが表示されます。例えば *Bid for Facility Extension* です。タブには *Bid for Facility Extension (OZB-05)* と表示されます。プロジェクト名を *Hall extension* に変えると、タブ名は *Hall extension (OZB-05)* になります。P6 XML にエクスポートすると、*OZB-05* がプロジェクト ID として、*Hall extension* が名前として書き戻されます。こうして P6 はプロジェクトを認識します。`.xer` から開いたプロジェクトは、そのプロジェクト ID も引き継ぎます。プロジェクトを IFC として保存しても、プロジェクト ID は残ります。名前の中の括弧（例えば *New build (phase 2)*）は、名前に残ります。プロジェクト ID がないプロジェクトは、エクスポート時にアプリから固有の ID を受け取ります。その ID は *OPS:* で始まります。

**引き継がれるもの** — WBS 構造と、期間、日付、進捗を持つタスク。ラグ付きの関係。制約（二つ目の制約も、ソフト制約として）。カレンダー。リソースと割り当て。状態日（`DataDate` として）。カスタムの作業区分は、専用のフィールド `OPS Custom Task Type` に入ります。アプリはこれを読み戻しますが、P6 は無視する場合があります。

**引き継がれないもの** — ベースラインと期限。アクティビティコード、カスタムフィールド、メモ、外部関係。計算オプション。祝日の名前。P6 には祝日ごとの名前がありません。再度開くと、祝日は *Holiday*、稼働の例外日は *Working exception* と呼ばれます。連続する非稼働日は、一つの範囲として戻ります。アプリは、P6 の上限より長い名前やコードを短くします。タスク名は 120 文字まで、タスク ID または WBS コードは 40 文字まで、WBS 名またはプロジェクト名は 100 文字までです。アプリは、短くした名前とコードの数を知らせます。P6 にはパーセンテージのラグがないため、アプリはそれを固定の日数に変換します。暦日のラグは稼働時間のラグになります。例えば、暦日の 3 日は稼働日の 3 日になります。ハンモックは通常のタスクになります。手動スケジュールのタスクは、計算された日付を持つ通常のタスクになります。一日未満の山崩し遅延は削除されます。

## Primavera ファイル (`.xer`)

**開く** — はい。計算プロファイル: *Primavera P6*。アプリはファイルを読むだけです。`.xer` を書き込むことはなく、ファイルを変更することもありません。タスクを持つプロジェクトごとに一つのタブを開きます。タスクがない、またはテーブルが壊れているファイルは、メッセージを表示して開きません。

**保存** — いいえ。保存先はありません。*保存* を選ぶと、元の `.xer` を中に入れた新しい IFC ファイルが書き込まれます。

**エクスポート** — いいえ。`.xer` から開いたプロジェクトを CSV、MS Project XML、P6 XML にエクスポートすると、アプリは XER のソース情報が失われると通知します。途中で IFC として保存していても、この通知は表示されます。IFC では何も失われません。

**引き継がれるもの** — WBS 構造と、期間、日付、制約、進捗を持つタスク。ラグ付きの関係。カレンダー。割り当てを持つリソース。アクティビティコード。カスタムフィールド（UDF）。メモ。P6 のスケジュール設定。種類が *Level of Effort* のタスクはハンモックになります。ベースラインのプロジェクトは、それを参照するプロジェクトの有効なベースラインになります。二つのプロジェクト間の関係は、アプリがソースデータとして保持します。

**割り当ての率。** 残作業が残っている場合は、残りの率（`remain_qty_per_hr`）が *単位/日* になります。残作業がない場合は、計画された率（`target_qty_per_hr`）になります。計画された作業、実績の作業、残作業は、ファイルのとおりに残ります。資材の場合、計画された率はそのままです。

**ファイルにない、空いている土曜日または日曜日。** 一部の P6 のエクスポートは、連続する複数の休日の中にある週末の休日を、その前の金曜日、またはその後の月曜日に移します。カレンダーが土曜日または日曜日に稼働する場合、その日は誤って稼働日になります。アプリが三日以上の休みの並びでそのパターンを見つけると、その週末の日を休みに戻します。カレンダーでは、その日は *カレンダーの例外（週末の再構築）* と呼ばれ、メッセージの *カレンダーの検出事項: N* の行に数えられます。週末に稼働しないカレンダーでは、何も変わりません。

**プロジェクト終了日までのフロート（終了日がない場合）。** P6 のオプションで、プロジェクト終了日までのフロートを計算するように設定されていますか。しかし、ファイルにはプロジェクトの終了日がなく、どのタスクにも計画された終了日がありませんか。その場合、アプリは *プロジェクト終了日までのフロートを計算* のオプションをオフにします。その後、遅い日付を最も遅い最早終了から逆算します。これは *安全なフォールバックを使った P6 計画設定: N* の行に数えられます。

**状態日の完了タスク。** 一部のファイルは、完了したタスクの実績日を記録せず、状態日を基準にしたウィンドウを記録します。ビュー *記録されたとおりの日付* では、そのようなタスクは状態日の位置にある細いバーになります。再計算でそれが別の場所に移ると、その分はストリップが示すタスク数に含まれます。規則 *ステータス日付ウィンドウ内の完了タスク* は、そのようなウィンドウを計算します。この規則を使った場合にだけ、完了タスクは計算オプション *完了タスク：データ日付からの遅い日付* によって、実際のフロートを得ます。この規則は近似です。アプリがこの動作を見たのは P3 の出力だけで、Primavera はどこでもそれを確認していません。そのため、組み込みのすべての計算プロファイルでオフになっています。*Primavera P6* でもオフです。*計算プロファイルとオプション* のブロックでオンにします。その後、プロジェクトはカスタムの計算プロファイルを受け取ります。詳しくは [計算オプションと規則](docs://ref-rekenopties-en-conventies) を参照してください。

**小数点としてカンマを使う数値。** P6 は、小数点と桁区切りの文字を、テーブル `CURRTYPE` に記録します。アプリは、期間、作業、フロートを変換する前に、これらの文字を読みます。その情報がない場合、アプリは小数点としてピリオドを使います。ファイルにまだ小数点のカンマを使った数値が含まれている場合、アプリは何も開きません。そうすると、数値を誤って読んだスケジュールが開かれることはありません。

**引き継がれないもの** — タスクのないプロジェクトと、二つのプロジェクト間の関係で、スケジュール内の実際の関係になるもの。詳しくは [Primavera P6 ファイル (.xer) を開く](docs://howto-xer-openen) を参照してください。

## CSV

**開く** — はい。アプリは `;` と `,` を区切り文字として読みます。列見出しは英語とオランダ語で認識します（例: `Name` または `Naam`、`Duration` または `Duur`、`Predecessors` または `Voorgangers`）。日付は *年-月-日*、*日-月-年*、または *日/月/年* の形式にできます。先行タスクは、WBS コード、関係の種類、ラグの順に書きます（例: `1.2FS+2d`）。計算プロファイル: *Open Planner Studio*。プロジェクト名は *CSV Import* になります。`Task Type` 列は、タスク種類ではなく作業区分を持ちます。アプリは見出し `Werksoort` と `Work category` も読みます。固定コード以外の `Task Type`（例: `CONSTRUCTION` や `INSTALLATION`。アプリ自身が書き込みます）は、*このプロジェクトから* の下にカスタムの作業区分になり、*自分の作業区分* には入りません。`OPS Custom Task Type ID` があると、カスタムの作業区分の ID が保持されます。

**保存** — いいえ。

**エクスポート** — はい。*CSV (;)* として（*汎用テーブルエクスポート。日付と期間を含むすべてのタスク。*）、カード *CSV（セミコロン区切り）* にあります。ファイルは区切り文字にセミコロンを使い、UTF-8（BOM 付き）で、列見出しは英語です。

**引き継がれるもの** — タスクごとに次の列があります：`OPS Task ID`、`WBS`、`Outline Level`、`Name`、`Duration (days)`、`Start`、`Finish`、`Predecessors`、`Task Type`、`OPS Custom Task Type ID`、`Status`、`Completion (%)`、`Actual Start`、`Actual Finish`、`Critical`、`Total Float`、`Description`。`Task Type` 列には作業区分が入ります。完了率は整数のパーセントで書かれます。時間のラグには、アプリの言語の時間記号が付きます。英語では `1.2FS+2h`、オランダ語では `1.2FS+2u` です。開くときは、どちらも読めます。

**引き継がれないもの** — リソース、割り当て、カレンダー、制約、期限、ベースライン、状態日。日付がビュー *記録されたとおりの日付* にある場合、エクスポートは、ソースファイルがそれを記録していなかったタスクについて `Critical` と `Total Float` を空のままにします。

## 進捗シート（Excel と CSV）

**開く** — はい。*ファイル › インポート*（*シートから進捗を更新*）から開くか、*計画*、*テーブル*、*レポート* の各タブのリボングループ *進捗* にある同じ名前のボタンから開きます。アプリは `.xlsx` と `.csv` を読み込みます。上限は 16 MB と 50,000 行です。これはプロジェクトを開くものではありません。開いているプロジェクトの進捗を更新します。詳しくは [シートから進捗をインポートする](docs://howto-voortgang-importeren) を参照してください。

**保存** — いいえ。

**エクスポート** — はい。*進捗シート（Excel）*（リストでは *進捗（Excel）*）と *進捗シート（CSV）*（*進捗（CSV）*）として。既定の名前は *projectname-voortgang* です。同じリボングループのボタン *進捗シートをエクスポート* を使うと、ワンクリックで Excel シートを作成します。Excel シートには、固定の列幅、ロックされたフィールド、日付チェックがあります。CSV シートは、同じ内容をプレーンテキストで持ちます。

**引き継がれるもの** — 列 `OPS Task ID`、`WBS`、`Name`、`Start`、`Finish`、`Completion (%)`、`Actual Start`、`Actual Finish`。読み込み時、アプリは `Completion (%)`、`Actual Start`、`Actual Finish` を使います。`Start` と `Finish` は日付の表記を認識するためだけに使われ、スケジュールは変わりません。アプリは行を `OPS Task ID` で、または一意の WBS コードでタスクに関連付けます。

**引き継がれないもの** — これらの列以外のすべてです。期間、関係、リソース、スケジュールのその他の部分。サマリータスクは、シートから進捗を受け取りません。

## PDF

**開く** — いいえ。

**保存** — いいえ。

**エクスポート** — はい。レポートから出力します。*レポート* タブのボタン *PDF エクスポート* を使います。アプリは、レポートをプリンターへ直接送りません。紙に出すには PDF を使います。内容はレポートの種類によって決まります。[レポートの種類](docs://ref-rapporttypes) と [レポートを作成して印刷する](docs://howto-rapport-maken-en-afdrukken) を参照してください。
