# エクスポート

目的: スケジュールを別の形式のファイルとして渡します。IFC を読まない相手や、別のパッケージで使う場合に使います。

## いつ必要か

コンサルタントは MS Project で作業します。発注者は Primavera で作業します。下請け業者は、タスクを Excel で受け取りたいと考えています。または、IFC を扱えないパッケージにスケジュールを送る必要があります。エクスポートは、別の形式のコピーです。プロジェクト自体を残したい場合は、保存してください。保存すると IFC で書き出され、すべての情報が一緒に保存されます。各形式が引き継ぐものと引き継がないものは、[ファイルと形式](docs://uitleg-bestanden) にあります。

## 手順

1. *ホーム › ファイル › エクスポート* を選択し、一覧から形式を選びます。または、*ファイル › エクスポート* を選択します。ここでは、すべての形式がカードになっており、短い説明があります。
2. ウィンドウで、名前と保存先を選択します。アプリは、プロジェクト名に形式ごとの末尾を付けた名前を提案します。進捗シートは *プロジェクト名-voortgang* という名前になり、可能な場合はダウンロードフォルダーで開きます。
3. 確認します。エクスポートが成功した場合、下のメッセージ以外は表示されません。*ファイル › エクスポート* から開いた場合は、ウィンドウをキャンセルしても、そのあと *ホーム* タブに戻ります。*ホーム* タブの一覧からエクスポートした場合は、ウィンドウをキャンセルしても何も起こりません。

ブラウザーがダウンロードとしてのみ保存する場合（Firefox など）は、手順 1 のあと、すぐにファイルがダウンロードフォルダーに入ります。次のメッセージが表示されます: *ダウンロードとして保存しました。「name.xml」はダウンロードフォルダーにあります。この環境では、アプリが選択した場所に直接書き込むことはできません。*

### どの形式を選びますか？

*ホーム* タブの一覧と、*ファイル › エクスポート* のカードには、同じ形式があります：

- *進捗（Excel）* と *進捗（CSV）*。カードでは *進捗シート（Excel）* と *進捗シート（CSV）*。ID、WBS、名前、日付、完了率だけを含む簡単なシートです。進捗を入力する担当者に回すためのシートです。
- *CSV (;)*。カードでは *CSV（セミコロン区切り）*。表計算ソフトで開くタスク一覧です。
- *MS Project XML*: Microsoft Project で開けます。
- *Primavera P6 XML*: Oracle Primavera P6 用です。
- *IFC*: アプリ独自の形式で、すべての情報を含みます。プロジェクトの IFC スキーマ（既定は IFC 4.3 ADD2）を使います。

### ライブラリファイル付きの IFC エクスポート

プロジェクトがリソースライブラリに関連付けられている場合、チェックボックス *ライブラリファイルも一緒に保存* は、*ファイル › エクスポート* のカードの下にあります。このチェックボックスをオンにして *IFC* を選択すると、アプリは保存先を二回尋ねます。最初はプロジェクト、次に *プロジェクト名-bibliotheek.ifc* です。このチェックボックスは *ファイル › エクスポート* にだけあり、*ホーム* タブの一覧にはありません。

### 進捗シートを読み戻す

入力済みの進捗シートを、*ファイル › インポート* から読み戻します。詳しくは [スプレッドシートから進捗をインポートする](docs://howto-voortgang-importeren) を参照してください。

## 注意点と、そのときのアプリの動作

**プロジェクトは変わりません。** プロジェクトのファイルは同じままです。もとから *未保存* の表示があった場合は、そのまま残ります。

**最新でないスケジュールは、先に再計算されます。** そのため、*計算* を選択し忘れた場合でも、最新の日付が得られます。

**エクスポートは、最近使ったファイルにも入ります。** これは進捗シートには当てはまりません。そこからエクスポートを開くと、その形式のインポートとして開きます。

**エクスポートがすべてを引き継ぐわけではありません。** CSV ファイルには、リソースも制約もありません。P6 XML には、ベースラインも期限もありません。計算プロファイルも一緒には引き継がれません。開き直したエクスポートは *Open Planner Studio* として計算されます。すべてを引き継ぐのは IFC だけです。数値の例は [ファイルと形式](docs://uitleg-bestanden) にあります。

**同じ .xml の形式が二つあります。** MS Project XML と Primavera P6 XML は、どちらも *プロジェクト名.xml* という名前になります。自分で別の名前を付けてください。そうしないと、後でどのファイルがどの形式か分からなくなります。

**循環依存のあるスケジュールは、エクスポートされません。** アプリは先に計算し、ループがあると停止します。*ホーム* タブには、*スケジュールを計算できませんでした* というメッセージが表示されます。その下に、たとえば *タスク間に循環依存があります: Set up site → Demolish existing extension → Set up site* と表示されます。*ファイル › エクスポート* では、ページには二つ目のテキストだけが表示されます。ループを解消してから、もう一度エクスポートしてください。

**Primavera のプロジェクトは、ソース情報が失われます。** そのようなプロジェクトを CSV、MS Project XML、P6 XML にエクスポートすると、アプリは次のメッセージを表示します: *CSV へのエクスポートでは XER のソース情報が失われます。* MS Project XML の場合は *MSPDI*、P6 XML の場合は *P6* と表示されます。詳しくは [Primavera P6 ファイル（.xer）を開く](docs://howto-xer-openen) を参照してください。

**タスクを分割したものは、その分割が失われます。** MS Project と Primavera は、分割を時間の配分としてしか扱えません。時間の配分がないタスクを分割したものが含まれている場合、MS Project XML または P6 XML にエクスポートすると、アプリは次のメッセージを表示します: *中断のあるタスク 2 件は中断なしでエクスポートされました。MS Project/P6 では中断を作業配分としてしか扱えません。* タスクが一件の場合は、*中断のあるタスク 1 件は中断なしでエクスポートされました。MS Project/P6 では中断を作業配分としてしか扱えません。* と表示されます。詳しくは [タスクを分割](docs://howto-taak-splitsen) を参照してください。

**表示が *記録どおりの日付* のときのスケジュール。** ソースファイルの日付を表示した状態で CSV にエクスポートすると、ソースファイルにその値が記録されていないタスクでは、アプリは `Critical` と `Total Float` を空のままにします。詳しくは [記録どおりの日付](docs://uitleg-datums-zoals-opgeslagen) を参照してください。
