# フィードバックの送り方

目的: エラーを報告したり、アイデアを伝えたりします。必要ならスクリーンショットも付けます。アプリから直接送れます。

## こんなときに使います

スケジュールが計算した結果が理解できないとき、ボタンが正しく動かないとき、またはアプリに必要な機能がないと感じるときです。よい報告は、開発者が問題を見つけるのに役立ちます。そのため、アプリ自体が報告にバージョン、オペレーティングシステム、言語を自動的に追加します。ご自身で書く内容によって、開発者が対応できるかどうかが決まります。何をしたか、何を期待したか、何が起きたかを書いてください。

## 手順

1. アプリのウィンドウ上部にある *フィードバックを送る* ボタンをクリックします。このボタンは常にタイトルバーにあります。ボタンの表示は 10 分ごとに変わります: *フィードバックを送る*、*バグを報告*、*新機能を提案*。ボタンは常に同じものです。*フィードバックを送信* ウィンドウが開きます。
2. 報告の種類を選びます。*動作しない* は、エラーの報告に使います。何かが本来どおりに動かない場合です。*アイデア* は、足りないものや変えたいものに使います。*質問またはコメント* は、そのほかの内容に使います。*動作しない* が既定で選ばれています。
3. *タイトル* を入力し、次に *説明* を入力します。空の欄には例が表示されます。タイトルの例は *例: 保存後にクリティカルパスが変わる* です。説明の欄には、質問 *何をしましたか。何を期待しましたか。実際に何が起きましたか。* が表示されます。ボタン *送信* がグレーの間は、その横のグレーの行に理由が表示されます。例: *タイトルを入力してください。* または、タイトルと説明を合わせて 10 文字以上入力する必要があることです。
4. 返信がほしい場合は、*メールアドレス* を入力します。この欄は任意です。報告が正常に送信されると、アプリはアドレスを記憶します。次回は、アドレスがすでに入力されています。
5. 何かを見せたい場合は、*スクリーンショットを添付* のチェックボックスをオンにします。アプリは、このウィンドウを除いたアプリの画面を撮影します。少し後に、小さなプレビューと、その横の三つのボタンが表示されます: *注釈を付ける*、*撮り直す*、*削除*。
6. *注釈を付ける* を選ぶと、編集画面が開きます。そこでは、画像に矢印、長方形、フリーハンドの線、テキストを追加できます。*覆う* で、名前や金額など、一緒に送ってはいけないものの上に黒い領域を描けます。その部分は、アプリが送る画像から実際に消えます。色を選べます。*元に戻す* で直前の操作を取り消し、*すべてクリア* で最初からやり直せます。変更を残すには *完了* をクリックします。変更を捨てるには *キャンセル*（または Esc）をクリックします。
7. *撮り直す* は新しいスクリーンショットを撮り、注釈を消します。*削除* はスクリーンショットを削除し、チェックボックスをオフにします。
8. フォームの下にあるグレーの行 *一緒に送信* を確認します。この行には、アプリが自動的に一緒に送るもの、つまりバージョン、オペレーティングシステム、言語が表示されます。例: *一緒に送信: v2026.10.1 · Windows · English*
9. *送信* をクリックします。送信中は、ボタンに *送信中*… と表示されます。
10. *ありがとうございます。報告を送信しました。* と表示されます。報告に対応する issue が GitHub に作成された場合は、ボタン *GitHub で表示* も表示されます。*閉じる* をクリックします。

## 報告の行き先

アプリは、報告を OpenAEC の Open Feedback Studio に送ります。そのためにアカウントは必要ありません。GitHub のアカウントも不要です。開発者は、報告を一覧で確認できます。Open Feedback Studio がそこで GitHub に接続されている場合、Open Feedback Studio は報告を公開の GitHub issue にもします。*動作しない* の場合、issue には *bug* ラベルが付きます。*アイデア* の場合は *enhancement* ラベルが付きます。説明の下には、Open Planner Studio のバージョン、オペレーティングシステム、アプリの言語を示す行があります。

## 注意点とアプリの動作

**報告は公開されることがあります。** 共有したくないものは書かないでください。スクリーンショットも同じです。画像には、そのときアプリに表示されているものがすべて写ります。たとえば、プロジェクトのタスク名やリソースなどです。アプリは、*スクリーンショットを添付* をオンにした時点でスクリーンショットを撮ります。画面がまだ正しくない場合は、ウィンドウを閉じ、画面を正しく整えてから、ウィンドウをもう一度開いて *撮り直す* をクリックしてください。見せたくないものは、*覆う* で隠してください。

**スクリーンショットが大きすぎます。** アプリは、送信前にスクリーンショットを小さくします。それでも大きすぎる場合は、画像なしで報告が送られます。お礼の画面には、そのとき *スクリーンショットが大きすぎたため、送信されませんでした。* と表示されます。

**送信できない場合があります。** ウィンドウにメッセージが表示され、入力したテキストは残ります。次の四つの場合があります:

- *報告が受け付けられませんでした。* テキストとメールアドレスを確認してください。リンクが大部分を占める報告は受け付けられません。
- *短時間に多くの報告を送信しました。* 1 時間後にもう一度試してください。
- *送信に失敗しました。* 接続がないか、サーバーが応答しません。もう一度試すか、*GitHub で開く* をクリックしてください。以前の試行が不確かだった場合、そのボタンはありません（下を参照）。
- *報告が届いたかどうか確証がありません。1 分ほど待ってから、もう一度送信してください。すでに届いていれば、自動的にわかります。* アプリが報告を送信した後に接続が切れました。入力したテキストは残ります。*GitHub で開く* ボタンはありません。報告がまだ届く可能性があるためです。この状態は、報告が送信されるか、すでに届いたと確認されるまで続きます。その間にウィンドウを閉じて開き直しても同じです。

**報告はすでに届いています。** すでに届いている報告をもう一度送信すると、フォームの上に次のメッセージが残ります: *この報告はすでに届いています。何か追加したい場合は、テキストを変更してもう一度送信してください。* 入力したテキストは残り、メールアドレスも記憶されます。何も追加しない場合は、*閉じる* をクリックします。次回は、フォームが空になります。さらに文字を入力すると、メッセージは消え、もう一度送信できます。ボタンの名前は再び *保存して閉じる* になり、テキストは残ります。

**GitHub で開く。** これは Open Feedback Studio を使わない方法です。この方法には GitHub のアカウントが必要です。スクリーンショットなしの場合、新しい issue を作成する GitHub のページがブラウザーで直接開きます。タイトルと説明は、すでに入力されています。スクリーンショットありの場合は、まず *もう少しで完了です — スクリーンショットはクリップボードにコピーされています。* と表示され、四つの手順が示されます。*OK、GitHub へ移動* をクリックします。issue のページにある大きなテキスト欄の中をクリックし、Ctrl+V（Mac では Cmd+V）を押します。次に、下部の *新しい issue を送信* をクリックします。その時点で初めて報告が送信されます。

**貼り付けが動かない場合があります。** GitHub の方法では、スクリーンショットはコンピューターにファイルとしても保存されます。デスクトップアプリでは、ウィンドウにそのパスが表示されます: *貼り付けできませんか？ スクリーンショットは次の場所にも保存しました:* そのパス *— そのファイルをテキスト欄にドラッグしてください。* ブラウザーでは、アプリは画像を `feedback-` に番号を続けた名前で、`.png` で終わるファイルとしてダウンロードします。ダウンロードフォルダーで見つけ、テキスト欄にドラッグしてください。

**スクリーンショットが失敗します。** 次のメッセージが表示されます: *スクリーンショットの撮影に失敗しました。スクリーンショットなしでもフィードバックを送信できます。* チェックボックスはオフになり、画像なしで報告を送信できます。

**送信前にウィンドウを閉じる場合。** フォームに入力がある場合、下部のボタンの名前は *保存して閉じる* です。フォームが空の場合は *閉じる* です。*保存して閉じる*、×ボタン、Esc でウィンドウが閉じます。報告は、送信するか *クリア* をクリックするまで、下書きとして残ります。ウィンドウをもう一度開くと、報告の種類、テキスト、メールアドレス、注釈付きのスクリーンショットがまだ残っています。下書きは、アプリを開いている間は残ります。アプリを終了すると消えます。報告が正常に送信されると、フォームは再び空になります。自分で最初からやり直す場合は、左下の *クリア* をクリックします。ウィンドウの横をクリックしても閉じません。送信中は、Esc を押してもウィンドウは閉じません。
