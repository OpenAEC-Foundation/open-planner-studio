# 記録された日付

Primavera または MS Project のスケジュールを開くと、そのパッケージで見た日付と違うことがあります。インポートが失敗したのでしょうか。通常はそうではありません。この記事では、アプリが自動で再計算する理由、ファイルの日付を表示するタイミング、その表示で空のままになる項目、そしてアプリ自身の計算に戻る方法を説明します。最後の例では、2 つのタスクを、この全体の流れに沿って追います。

## 概念

スケジュールファイルには 2 種類のデータが含まれます。1 つ目はロジックです。タスク、期間、関係、カレンダー、制約が含まれます。2 つ目は、そのパッケージ自身がこのロジックから計算した日付です。開くとき、*Open Planner Studio* はロジックを使い、自分で計算します。そのため、ファイル内の日付は入力ではありません。

アプリ自身の計算が、ファイルに書かれた日付と違う結果になる場合があります。その場合、どちらが正しいかはわかりません。ファイルには、パッケージが使ったロジックの一部が欠けている場合があります。また、パッケージが一部の点でアプリとは違う計算をしている場合もあります。そのため、アプリは**記録された**日付を表示できます。つまり、もう一方のパッケージがファイルに入れた日付です。こうすると、そのパッケージで見た内容と比較できます。

## アプリの扱い方

### アプリが使う計算プロファイル

アプリは **計算プロファイル** で計算します。計算プロファイルとは、計算ルール（規則）の集まりです。たとえば、タスクの計画された開始と制約を、どう扱うかを決めます。詳しくは [計算プロファイルと規則](docs://uitleg-rekenprofielen) を参照してください。組み込みのプロファイルは 3 つあります。*Primavera P6*、*Microsoft Project*、*Open Planner Studio* です。`.xer` は *Primavera P6* で、`.mpp` は *Microsoft Project* で開きます。CSV、MS Project XML、Primavera P6 XML は *Open Planner Studio* で開きます。プロジェクトの計算プロファイルは、*ファイル › プロジェクト設定* の *計算プロファイルとオプション* にあります。アプリで作成した IFC ファイルは、そのプロファイルを保持します。

### アプリが比較するタイミング

開くとき、アプリはファイルの内容を記録し、それを自身の計算結果と比較します。比較するのは次の場合です。

- Primavera ファイル（`.xer`）と Primavera P6 XML；
- MS Project XML と MS Project ファイル（`.mpp`）；
- 他のプログラムで作成した IFC ファイル。ファイルに最早日付が含まれているタスクが対象です；
- 出所を記憶しているアプリ作成の IFC ファイル。どの場合かは以下で説明します。

アプリは CSV ファイルを比較しません。CSV の開始日は入力であり、計算結果ではないからです。出所を記憶していない、アプリ作成の IFC ファイルも比較しません。

タスクに違いがない場合は、何も表示されません。今インポートしているファイルで 1 つ以上のタスクに違いがあれば、表示をすぐにオンにします。

Primavera ファイルの場合、アプリは計算プロファイル *Primavera P6* で計算します。これにより、ファイルの計画された開始が最早開始として保持されます。関係から求まる日付より後に、ファイルでも計画されているタスクは、その位置にそのまま残ります。この場合、違いは生じません。

### 表示される内容

リボンの下にバーがあります。そこには次のように表示されます：*ファイルに記録されている日付を表示しています。再計算すると 4 件のタスクがずれます。*　ソースが Primavera（`.xer` または Primavera P6 XML）の場合は、次のように表示されます：*Primavera が記録したスケジュールを表示しています。再計算すると 1 件のタスクがずれます。*　バーの右側には、ボタン *再計算* があります。このバーには × がありません。

メッセージもあります：*ファイルに記録された日付をそのまま表示しているタスク: 12 件（再計算していません）*。`.xer` の場合のみ、次の表示になります：*Primavera が記録した日付をそのまま表示しているタスク: 12 件（再計算していません）*。この件数には、ファイルに日付が記録されているすべてのタスクが含まれます。違いがないタスクも含みます。再計算後にずれるタスクの数は、バーに表示されます。ファイルに日付が記録されているタスクには、すべて *プロパティ* パネルの *開始* の真上に、オレンジ色のブロックが表示されます：*表示されているのは Primavera が保存した日付です。アプリの計算結果ではありません。* ほかのソースの場合は *表示されているのは、ファイルに記録されていた日付です。アプリの計算結果ではありません。* と表示されます。ブロックの 2 行目は、再計算したときにそのタスクがどうなるかを示します：*再計算すると、このタスクは変わります。* または *再計算しても、このタスクは変わりません。* Gantt、タスクテーブル、ステータスバーには、ファイルの日付が表示されます。

### 開始済みまたは完了したタスク

完了したタスクは、実際に作業が行われた日に配置されます。実績開始日から実績終了日までです。作業中のタスクは、実際に開始した日から始まります。終了は計算された終了日です。これは、この表示でも、再計算後でも、すべての計算プロファイルでも同じです。Primavera や MS Project と同じです。

このようなタスクでは、ファイルに別の最早日付が記録されていることがよくあります。Primavera は、作業中または完了したタスクの最早開始を状態日に設定します。その日付は *最早開始日* と *最早終了日* の列に表示されます。*開始* と *終了* の列には表示されません。そのため、完了したタスクが違いとして数えられることは決してありません。作業中のタスクは、終了日が異なる場合にのみ数えられます。

開始済みのタスクでは、開始日をもう入力できません。タスクテーブル、*プロパティ* パネル、*タスクの編集* では、開始日が読み取り専用になります。完了したタスクでは、タスクテーブルの終了日も同様です。代わりに、進捗で *実績開始日* または *実績終了日* を変更してください。Gantt では、そのようなタスクのバーは動きません。その場合はメッセージが表示されます。

### この表示で空のままになる項目

この表示では、アプリは何も計算しません。ファイルに記録された内容だけを表示します。そのため、フロートとクリティカルパスは、ファイルに含まれている場合のみ表示されます。ファイルにクリティカルタスクが記録されていない場合、ステータスバーには 0 件のクリティカルタスクと表示されます。これは、パッケージ自体のクリティカルパスについては何も示しません。計算によってのみ得られる情報は、この表示には存在しません。つまり、スケジュールを決めている関係、制約違反、順序が崩れたタスク、準クリティカルタスクです。

ファイルがタスクのすべてを記録していない場合、*プロパティ* パネルのブロックには 3 行目が追加されます。たとえば *このタスクについて、Primavera は一部の情報を保存していません。不足している項目: フリーフロート。* です。ほかのソースの場合は *ファイルには、このタスクのすべての情報が含まれていません。* と表示されます。最初の 2 行はそのまま残ります。そのため、そのタスクでも、日付がファイル由来であることと、再計算するとタスクが変わるかどうかが分かります。不足している値の名前は、タスクテーブルの列と同じです。CSV 書き出しでは、そのタスクの *クリティカル* 列と *トータルフロート* 列は空のままになります。架空の 0 は入りません。

### 表示を終了する

表示を終了する方法は 2 つあります：

- バーの *再計算* をクリックするか、*計算*（F5）を選択します。アプリは自身のルールで計算します；
- 日付を変えられるものを変更します。たとえば、タスクの期間や新しいタスクです。*自動計算* がオフでも、アプリは表示を終了し、すぐに再計算します。名前、説明、作業区分、タスク種類を変更しても、この動作は起こりません。表示はオンのままです。

リソースライブラリからのカレンダー変更では、表示はオンのままで、ファイルの日付もそのまま残りますが、バーの数は更新されます。

表示を終了したあと、表示に戻すボタンはありません。再計算の直後、または同様の編集の直後に限り、Ctrl+Z で表示を戻せます。それ以外の場合は、元のファイルを開き直せます。`.xer` の場合、再計算後に保存して編集していない IFC ファイルを開くと、同様に表示が再びオンになります。

### クラッシュ復元

表示中にクラッシュしたプロジェクトを復元すると、表示はオンのままです。表示がオフだった場合、アプリはファイルの日付を忘れます。前面に開いていたプロジェクトは、以前と同じバーを表示します。別のタブにあるプロジェクトは、数字のないバーを表示します：*ファイルに記録されている日付をそのまま表示しています。再計算は行われていません。* [クラッシュ後の復元](docs://howto-herstellen-na-een-crash) を参照してください。

### 保存と再度開く

表示を使っている間に保存すると、アプリは表示中の日付をソースの形式とともに IFC ファイルに書き込みます。その IFC ファイルを後で開き直すと、表示は再びオンになります。新しいメッセージは出ません。表示で名前など日付に影響しない内容を変更した場合も同じです。アプリは、保存したときの状態のままファイルを開きます。

表示を離れたあとに、再計算または日付を変えうる編集を行ってから保存すると、ファイルにはアプリ自身の計算結果が入ります。開き直すと、その計算結果が見えます。バーも*プロパティ* パネルのブロックもありません。例外が 1 つあります。再計算だけを行い、編集しなかった `.xer` です（上を参照）。編集したスケジュールが、今のスケジュールになります。ソースパッケージの古い日付は、もうそれに属しません。それでも見たい場合は、元のファイルを開き直してください。

## 作業例: 増築

Primavera ファイル *Uitbouw*（増築）を開き、2 つのタスクがあるとします。カレンダーには祝日がありません。2027年では、5月6日が昇天祭、5月17日が聖霊降臨の月曜日です。カレンダーに祝日があると、日付が異なる結果になります。*Fundering storten*（基礎の打設）は 5 稼働日、*Metselwerk*（レンガ積み）は 10 稼働日かかります。*Metselwerk* は Fundering の後に、終了-開始の関係で続きます。ファイルには、Fundering が 2027年5月3日（月）から5月7日（金）まで、Metselwerk が 2027年5月17日（月）から5月28日（金）までと記録されています。これは、関係が許す最早開始より 1 週間後です。ファイル内の Metselwerk の計画された開始は、2027年5月10日（月）です。

開いた直後は、ファイルの日付が表示されます。ステータスバーには *終了: 28-05-2027* と *クリティカルパス：2 タスク、20 稼働日* と表示されます。バーには、再計算すると 1 件のタスクがずれると表示されます。両方のタスクにオレンジ色のブロックが表示されます：*表示されているのは Primavera が保存した日付です。アプリの計算結果ではありません。* その下の Metselwerk には *再計算すると、このタスクは変わります。* と表示されます。Fundering には *再計算しても、このタスクは変わりません。* と表示されます。

*再計算* を選ぶと、Fundering は 5月3日から 7日のままです。Metselwerk は、Fundering が終わったあとの稼働日である 5月10日（月）に始まり、5月21日（金）に終わります。スケジュールは 2027年5月21日に終わり、20 稼働日ではなく 15 稼働日にわたります。クリティカルパスは同じ 2 タスクで構成されます。

違う場合はどうなりますか。

- ファイルでも Metselwerk が 5月17日（月）に計画されている場合、計算プロファイル *Primavera P6* はその開始を保持します。計算結果は 5月17日から 28日までです。違いはなく、表示はオンになりません。
- 表示中にタスクを追加します。同じ再計算が行われます。Metselwerk は 5月10日から 21日に移ります。
- 表示中に保存し、編集せずに IFC ファイルを開き直します。Metselwerk は 5月17日から 28日に戻ります。
- 再計算し、それ以上編集せずに保存して、IFC ファイルを開き直します。表示は再びオンになり、Metselwerk は 5月17日から 28日です。
- 表示で Metselwerk の名前だけを変更し、保存して開き直します。表示は再びオンになり、Metselwerk は 5月17日から 28日です。
- 表示でタスクを追加し、保存して開き直します。アプリはファイルの日付を忘れます。Metselwerk は 5月10日から 21日で、バーもブロックもありません。
- ファイルでは、Fundering はすでに完了しています。実際に 5月3日に開始し、5月7日に終了しました。ファイルは状態日を最早開始として記録しています。Fundering のバーは、表示でも再計算後も 5月3日から 7日のままです。Fundering は違いとして数えられません。

## 結果と誤解しやすい点

**違いはインポートの誤りではありません。** アプリは自身のルールで計算します。`.xer` は計算プロファイル *Primavera P6* で、`.mpp` は *Microsoft Project* で、CSV、MS Project XML、Primavera P6 XML は *Open Planner Studio* で計算します。ソースパッケージの日付が異なる理由は、ファイルにあることも、パッケージにあることもあります。表示は、日付が *違う* ことを示します。

**表示は計算結果ではありません。** アプリは日付を計算していません。自分のスケジュールの結果として、そのまま引き継がないでください。

**表示中に保存すると、ソースパッケージの日付が保持されます。** その場合、IFC ファイルには、アプリが計算する内容ではなく、ソースパッケージが示した内容が入ります。

**日付を変えうる編集のあとでは、ファイルの日付は戻りません。** そのような編集で表示を離れた場合、保存して開き直したあとに見えるのは、アプリ自身の計算結果だけです。名前を変えるだけの編集は含まれません。その場合、表示はオンのままです（*保存と再度開く* を参照）。ソースパッケージの日付を見たい場合は、元のファイルを開き直してください。
