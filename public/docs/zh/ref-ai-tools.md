# AI 工具 (planner_*)

这里列出 AI 助手可以通过桥接器调用的所有工具，按组分类，并说明每个工具做什么以及在什么情况下会被拒绝。它们都以 `planner_` 开头。*连接信息* 窗口中的连接提示会显示当前编号。助手还会通过桥接器本身（`tools/list`）获得带说明的完整列表。连接的工作原理见 [AI 连接的工作原理](docs://uitleg-ai-koppeling)。如何开启连接见 [连接 AI 助手（MCP）](docs://howto-ai-assistent-koppelen)。

## 如何阅读本列表

**读取**表示：该工具不更改任何内容。在 *暂停* 和 *只读* 期间，它也可以使用。打开的对话框会阻止它（见下文 *工具被拒绝时*）。读取工具总是给出当前日期。如果计划已过时，它会先重新计算，即使在 *暂停* 和 *只读* 期间也是如此。这两种模式只阻止更改，读取时仍会重新计算。如果你正在编辑（拖动任务条、在字段中输入），它不会重新计算。助手会拿到编辑前的日期，并附带一条说明，指出这些日期已过时。如果项目处于 *按记录日期* 视图，它也不会重新计算。助手会拿到记录的日期，并附带一条说明，指出这些日期未经重新计算。

**更改**表示：该工具会更改你的项目。在 *暂停*、*只读* 期间以及对话框打开时，它会被拒绝。下面没有标记的工具也是如此（`planner_undo`、`planner_redo`、文件工具和文档工具，`planner_list_documents` 除外）。每次更改都是撤销历史中的一步。如果项目数据有变化，应用会在之后自动重新计算计划。你不必按 *计算*。在每个文档第一次更改前，如果 *自动备份* 已开启，应用会写一份备份。

**批量**表示：一次调用可以包含多个项目。无效项目会被拒绝并给出原因，有效项目则保留。响应会列出被拒绝的项目。

## 读取：计划

- `planner_get_project_info`（读取）— 项目详情和关键数字：任务、关系、资源和里程碑的数量、状态日期、项目完成日期与工期、计划是否已过时、计算配置文件，以及日历摘要。很适合作为第一个调用。
- `planner_get_project_overview`（读取）— 一次响应中给出整个 WBS 树：每个任务的 id、WBS、名称、工期、最早日期、进度、是否关键，以及带有关系 id 的外向关系。
- `planner_list_tasks`（读取）— 任务列表，可按关键、状态、日期窗口、没有关系的任务进行筛选，并支持分页。
- `planner_get_task`（读取）— 单个任务的详细信息：日期、浮时、进度、约束、截止日期、日历、分配、前置任务和后续任务、中断。
- `planner_get_critical_path`（读取）— 关键任务及其总浮时，以及驱动关键路径的关系。
- `planner_list_resources`（读取）— 资源列表，包含产能、费率、日历、班组、可用性和分配摘要。如果资源来自资源库，会显示哪些字段是固定的。
- `planner_get_resource_histogram`（读取）— 每个资源的负荷与产能对比，按天、周或月（默认按周）。没有时间窗口也没有资源时，给出每个资源的摘要。有时间窗口或资源时，给出完整序列，以及导致过度分配的任务。
- `planner_get_calendars`（读取）— 所有日历及其完整定义，以及使用它们的任务和资源数量。

## 读取：基线与差异

- `planner_list_baselines`（读取）— 已保存的基线，以及哪一个是激活的基线。
- `planner_compare_baseline`（读取）— 将当前计划与激活的基线比较。只列出有差异的任务，以及项目完成日期的差异，单位为当前项目日历上的工作日。没有激活的基线时会拒绝。
- `planner_analyze_delay`（读取）— 相对于激活基线的延迟分析：交付的差异，以及已移动的关键任务。没有激活的基线时会拒绝。

## 任务与结构

- `planner_add_tasks`（更改，批量）— 创建任务，包括一次调用中的嵌套 WBS。每个任务都会获得自己的临时名称（`tmp-…`），以便子任务引用其父任务。没有工期时，任务获得 5 个工作日。里程碑的工期为 0。同一次调用中的所有任务要么一起成功，要么一起失败。
- `planner_update_tasks`（更改，批量）— 更改现有任务的字段：名称、描述、带单位（天或小时）的工期、工期类型、工作类别、里程碑、强制、优先级、约束、截止日期、日历和任务类型。此外还可以更改进度：完成百分比、实际开始日期和实际完成日期。任何其他键都会被拒绝，并附带原因。
- `planner_delete_tasks`（更改）— 删除任务，包括其整个子树、关系和分配。响应会准确列出随之删除的内容。
- `planner_move_task`（更改）— 将任务移到另一个父任务下，并指定位置。循环引用，或把任务放到它自己下面，都会被拒绝。
- `planner_set_task_splits`（更改）— 设置一个任务的中断：工作多少个工作日（或工作时间）后中断，以及暂停多少个工作日（或工作时间）。空列表会取消所有中断。见 [拆分任务](docs://howto-taak-splitsen)。

## 关系

- `planner_add_dependencies`（更改，批量）— 创建关系，指定类型（`FS`、`SS`、`FF`、`SF` 或长格式）和延隔，例如 `+2d`。
- `planner_update_dependencies`（更改，批量）— 按关系 id 更改现有关系的类型、延隔、前置任务或后续任务。这是一步操作，无需删除后重新创建。
- `planner_remove_dependencies`（更改，批量）— 按关系 id 删除关系。

## 项目与日历

- `planner_update_project`（更改）— 名称、描述、作者、公司、开始日期、结束日期、状态日期、进度模式，以及任务类型的项目默认值。开始日期是新任务的锚点。如果助手之后再设置它，只有松散任务会跟着移动（即没有前置任务、也没有设定下限的约束，例如 *不得早于…开始*）。响应会用 `anchorsClamped` 报告数量。计划的其余部分保持不动，见 [新建项目与项目信息](docs://ref-projectinfo)。状态日期不是标签，而是计算的参考日期：在没有进度的计划上，一切都会跟着移动。结束日期只是元数据。
- `planner_move_project`（更改）— 将整个现有计划移到新的开始日期。日历不会一起移动，因此完成日期的天数变化可能与开始日期不同。基线保持不变，除非助手明确要求它们一起移动。见 [移动项目](docs://howto-project-verplaatsen)。
- `planner_update_calendar`（更改，批量）— 更改或创建日历：工作日、工作时间、休息、时段、假日（按国家和地区生成，或逐条指定）以及工作例外。它不能更改哪个日历是项目日历。

## 资源与单位

- `planner_manage_resources`（更改，批量）— 创建、更改或删除资源：名称、类型（人工、设备、材料、分包商或班组）、描述、最大单位数、每小时成本、单位、日历、班组，以及随时间变化的可用性。在助手明确确认之前，它拒绝删除仍有分配的资源。对于来自资源库的资源，名称、类型、描述、每小时费率和单位都是固定的。
- `planner_manage_assignments`（更改，批量）— 添加、更改、移动或删除分配：每个工作日的单位数、曲线和剩余工时。只适用于叶子任务，且同一资源在同一任务中只能出现一次。更改单位会对工期产生什么影响，取决于该任务的任务类型，见 [任务类型：工期、单位和工时](docs://uitleg-werkregels)。
- `planner_level_resources`（更改）— 执行资源平衡，消除过度分配。默认在浮时范围内进行，因此完成日期保持不变。使用 `constrainToFloat: false` 时，完成日期可能移动。使用试运行时，助手会先得到预览，且不更改任何内容。它会跳过材料。见 [资源平衡](docs://uitleg-nivelleren)。
- `planner_clear_leveling`（更改）— 清除所有资源平衡延迟。

## 管理基线

- `planner_save_baseline`（更改）— 将当前计划保存为基线，并立即将其设为激活状态。它会先重新计算已过时的日期。不能在脚本中使用。
- `planner_activate_baseline`（更改）— 激活一个基线，或不激活任何基线。
- `planner_rename_baseline`（更改）— 重命名一个基线。
- `planner_delete_baseline`（更改）— 删除一个基线。如果删除的是激活的基线，剩下的最后一个基线会变为激活状态。如果没有剩下的基线，则不激活任何基线。

## 撤销

- `planner_undo` 和 `planner_redo` — 在激活文档中撤销或重做一步。历史与你的撤销历史相同。响应会说明是否真的还原了任何内容。

## 文档与文件

- `planner_list_documents`（读取）— 所有打开的文档，包括标题、是否为激活状态、是否已修改、任务数、项目开始和计算出的完成日期。
- `planner_new_document` — 在自己的标签页中新建一个空白文档，不会打开 *新建项目* 窗口。
- `planner_duplicate_document` — 将激活文档复制到新标签页，用于假设分析或投标变体。副本是独立的，没有文件路径。
- `planner_switch_document` — 将另一个文档设为激活状态。切换标签页后，也可以用它确认助手正在处理哪个文档。
- `planner_import_schedule` — 从磁盘打开计划文件作为文档：`.ifc`、`.xml`（Primavera P6 或 MS Project，根据内容识别）、`.csv`、`.xer`，以及 `.mpp`（MS Project 2010 至 2021）。不会与当前计划合并。CSV 没有日历，因此日期可能移动。仅限你的用户文件夹内。导入 CSV、XML 或 `.mpp` 后，文档没有保存目标。只有 IFC 会接管其路径。
- `planner_export_ifc` — 将激活文档写为 IFC 文件，使用项目的 IFC 架构（默认为 IFC 4.3 ADD2）。仅限你的用户文件夹内，且只有在明确要求时才会覆盖已有文件。如果文档是以应用无法写入的架构打开的（例如 IFC2X3），该工具会拒绝覆盖该文件本身。项目保持未保存状态。

## 指南与来源说明

- `planner_get_planning_guide`（读取）— 供助手使用的英文指南（[做好计划](docs://gids-goed-plannen) 的原则，以及每条原则对应的工具），以及两个技能 *goed-plannen*（设置计划）和 *progress-update*（更新进度），或全部内容。用 `part` 选择：`guide`、`skill`（两个技能）或 `both`。默认为 `both`。对每个技能，它会返回应放置的位置和下载地址。参数 `language` 仍为旧版助手保留，但文本始终为英文。不会改动计划。
- `planner_inspect_xer_provenance`（读取）— 检查已打开的 Primavera P6 文件（`.xer`）所保留的来源语义：文件包含什么，并附带导入与诊断的计数。文件中的自由文本字段默认不可见，助手必须明确请求才能看到。资源名称默认同样不可见，因为 P6 中的资源通常是一个人；资源代码保持可见。助手在请求这些名称之前，必须先征得你的许可，因为之后这些名称会发送给 AI 提供方。不能在脚本中使用。

## 脚本

- `planner_batch` — 将最多 100 个步骤的脚本作为一次更改运行：一个撤销步骤、一次重新计算、一份备份。如果某一步在结构上失败，整个脚本会回滚。响应会逐步说明哪些已执行、哪些失败、哪些未到达。`planner_add_tasks` 生成的临时名称（`tmp-…`）可在后续步骤中使用。以下操作不能作为步骤：`planner_batch` 本身、撤销和重做、文档和文件工具、`planner_save_baseline`、`planner_get_planning_guide` 和 `planner_inspect_xer_provenance`。脚本不是编程语言：没有变量、条件或循环。

## 工具被拒绝时

助手随后会收到一个带错误代码和说明的响应。

- `PAUSED` — *暂停* 已开启。
- `READ_ONLY` — *只读* 已开启。
- `DIALOG_OPEN` — 有对话框打开。这对读取同样适用，但 `planner_get_planning_guide` 除外。响应会用其内部名称说明打开的是什么，例如 `showTaskDialog`。
- `DOC_DRIFT` — 助手工作时你切换了标签页。它必须用 `planner_switch_document` 确认它处理的是哪个文档。
- `VALIDATION` — 参数与架构不匹配，或请求的更改不被允许。响应会指明字段。
- `NOT_FOUND` — id 或文档不存在。
- `CYCLE` — 更改会产生循环引用。该调用中的全部内容都会回滚。
- `SCOPE` — 文件路径位于你的用户文件夹之外。
- `BACKUP_FAILED` — 更改前的备份失败。更改未执行。
- `INTERNAL` — 运行工具时出现意外错误，例如文件操作失败。响应会给出原始错误信息。
- `STALE_PRECONDITION` — 是桥接器契约的一部分，但目前没有任何工具返回此代码。

等待队列超过 110 秒的请求，应用将不再执行。客户端已收到超时，若执行则重试时会造成两次更改。超过 120 秒的调用，桥接器会返回超时。

## 助手无法设置的内容

就任务而言，助手无法设置：吊床任务、手动计划、第二个约束、备注、颜色、活动代码、自定义字段、外部关系，以及手动设置的资源平衡延迟。应用会自行计算 WBS 代码。在项目层面，助手无法更改计算配置文件和计算选项。设置、主题、语言、扩展和更新都超出其范围，资源库也是如此。它也没有报表、布局、筛选或视图的功能。原因见 [AI 连接的工作原理](docs://uitleg-ai-koppeling)。

## 应用存储的内容

- **令牌** 保存在这台电脑上，即应用的已存储设置中。它长 64 个字符，且是随机生成的。*生成新令牌* 会替换它。
- **端口** 默认为 3877，只能在桥接器停止时更改。
- **活动面板** 只在应用打开期间保留最近 500 次调用。参数和响应每个字段最多保留 20 kB，超出部分会被截断。*清除* 会清空列表。
- **备份** 位于应用数据文件夹中的 `ai-backups` 文件夹内。*打开备份文件夹* 会直接带你到那里。备份命名为 `<project name>-<timestamp>.ifc`。已保存的项目文件在所有会话中共用一个文件夹。从未保存的文档，每个会话都有自己的文件夹。每次启动桥接器时，每个文档会生成一份备份，此外还有你用 *立即备份* 自行创建的备份。
- **自动清理** 会按文件夹自动进行。最近 7 天内的备份全部保留，最多 20 份。正在运行的会话所生成的备份始终保留。之后，30 天内每周保留一份，一年内每月保留一份，此后每年保留一份。从未保存的文档，其备份在一年后会被完全删除。文件夹中不属于应用的文件不会被处理。
