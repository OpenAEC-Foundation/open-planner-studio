# 选择进度模式

目标：决定应用如何计划已开始、但前置任务仍在进行的任务的剩余工时：按照关系（Retained Logic），还是按照实际发生的情况（Progress Override）。

## 何时需要

在现场，工作往往会超前于逻辑关系。油漆工已经开始在已抹灰的房间里工作，而抹灰工仍在别处忙碌。例如，在计划中，这就是一个完成-开始关系，其后续任务在前置任务完成之前就开始了。应用将此称为 **顺序外进度**。如果状态栏显示 *N 个乱序关系*，就说明存在这种情况，进度模式决定应用如何计划后续任务的剩余工时。两种模式的作用及一个示例，见 [进度、状态日期与基线](docs://uitleg-voortgang)。

## 步骤

1. 按 [更新进度](docs://howto-voortgang-bijwerken) 所述，更新进度并设置状态日期。
2. 前往 *计划 › 基线与进度 › 进度模式*，然后打开列表。
3. 选择 *Retained Logic* 或 *Progress Override*。
4. 按 **计算**（F5）。例如，可通过 *计划 › 进度 › 计算*。此选择会使计划变为过期：状态栏显示 *已过期 — 请重新计算（F5）*。如果已开启 *自动计算*，应用会自动执行此操作。

如何选择？

- **Retained Logic** 是默认值。关系保持有效：后续任务的剩余工时只有在前置任务完成后才开始。如果顺序确实固定，或你想谨慎地计划，请选择此项。
- **Progress Override** 让实际情况优先。后续任务的剩余工时从状态日期开始，无需等待前置任务。如果后续任务确实仍在持续工作，且完成日期不应依赖仍在进行中的前置任务，请选择此项。

## 检查结果

- 点击状态栏中的消息 *N 个乱序关系*。*警告* 面板会打开。也可以通过 *计划 › 进度 › 警告* 打开。每个关系都会列在其中，并显示文字 *顺序错误：后续任务的进度与关系矛盾*，例如 *4.2 Plastering → 4.5 Painting (FS)*。
- 查看后续任务的任务条。在 Retained Logic 下，它会一直运行到前置任务完成之后。在 Progress Override 下，它会更早完成。在说明中的示例里，这是7月27日（星期二），对比7月22日（星期四）。

## 注意事项与应用的行为

**没有差异。** 进度模式只对那些已开始、但其前置任务尚未完成的任务有影响。没有这样的任务，就没有任何变化。

**消息仍然存在。** Progress Override 不能解决顺序外进度的消息。进度模式决定应用如何计算；关系与进度之间的矛盾依然存在。如果关系已不再正确，请修改它（[添加关系](docs://howto-relaties-leggen)）。

**它属于项目。** 此选择会与项目文件一起保存，适用于整个项目，并可用 Ctrl+Z 撤销。新项目使用 Retained Logic。

**一个 P6 文件。** 如果你打开 Primavera P6 文件（.xer），应用会从文件中读取模式。除了 Retained Logic 和 Progress Override，P6 还有 Actual Dates。应用不认识第三种模式；这样的文件会按 Retained Logic 计算。导入消息会将其计为 *使用安全回退的 P6 排程设置：1*。

**计算配置文件。** 在 Primavera P6 配置文件中，Progress Override 也会逆向生效，影响前置任务的最晚日期和自由浮时（约定 *进度覆盖在逆推时也忽略已开始的紧后作业*）。在 Open Planner Studio 和 Microsoft Project 配置文件中，情况并非如此。你可以在 *设置 › 项目 › 项目设置* 下的 *计算配置文件和选项* 块中找到这些约定。在说明中的示例里，看不到这种逆向影响。
