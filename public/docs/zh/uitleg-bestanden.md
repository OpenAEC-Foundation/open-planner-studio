# 文件和格式

你保存的文件里究竟有什么？导出到另一个软件包时，你的计划会发生什么？本文说明应用如何处理文件：IFC 是它自己的格式，其他格式作为转换器；说明导出会遗漏什么，以及保存、自动保存和崩溃恢复有何不同。文末示例用数字展示导出的实际结果。

## 基本概念

Open Planner Studio 有一种自有的文件格式：**IFC**，这是 buildingSMART 提出的建筑信息开放交换格式。应用会写入项目的 IFC 模式，默认为 IFC 4.3 ADD2（参见[选择 IFC 模式](docs://howto-ifc-schema-kiezen)）。在导出列表中，它名为*IFC*。没有第二种专有项目文件。*保存*会把整个项目写入一个 IFC 文件（`.ifc`），*打开*则会读回此类文件。想查看文件里有什么？*IFC* 选项卡是一个编辑器，显示你项目的 IFC 文本；*生成 IFC* 会刷新该文本，*复制*会将其放到剪贴板上。如果你更改该文本，*应用*会将其作为你的项目加载。这会完全替换该标签页中的项目。

所有其他格式都是**适配器**：它们在另一个程序的模型和应用的模型之间转换。应用读取 CSV、MS Project XML、Primavera P6 XML、MS Project 文件（`.mpp`）和 Primavera 文件（`.xer`）。它写入 CSV、MS Project XML、Primavera P6 XML 和两种进度表。你无法导出为 `.mpp` 或 `.xer`。

为什么这个区别很重要？转换器只能带过去双方都知道的内容。应用的 IFC 文件会保留属于你项目的全部内容。其他每种格式都缺少其中一部分，缺少的部分会留在原处。

## 应用如何处理文件

### 打开时会发生什么

应用根据后缀选择读取器：`.ifc`、`.csv`、`.xml`、`.mpp` 或 `.xer`。对于 `.xml` 文件，它会查看文件内容，判断是 MS Project XML 还是 Primavera P6 XML。未知后缀按 IFC 处理。如果文件不是 IFC，应用会报告*打开文件失败*，并附上原因。

每个文件都在自己的标签页中打开。例外是仍为空且未修改的标签页：该标签页会接管这个文件。一个 Primavera 文件可以生成多个标签页，每个有任务的项目各一个。

打开后，应用总会重新计算。如果文件来自另一个软件包，日期可能与文件中记录的不同。详见[记录的日期](docs://uitleg-datums-zoals-opgeslagen)。

只有 IFC 文件会成为**保存目标**，即*保存*写回的文件。CSV、XML、`.mpp` 或 `.xer` 文件不会成为保存目标。这类项目打开后没有文件；之后*保存*会询问新 IFC 文件应存放的位置。这样，按 Ctrl+S 时，永远不会用 IFC 文本覆盖你的原始文件。

### 保存会写入什么

*保存*总是写入整个项目。其中包括：

- 带结构、工期、日期和进度的任务；
- 带延隔、约束和截止日期的关系；
- 日历、资源和分配，包括曲线；
- 基线、活动代码、自定义字段和备注；
- 与其他项目的外部关系；
- 项目设置，例如状态日期、计算配置文件和计算选项；
- 与资源库的链接。

你在屏幕上设置的内容不属于项目，也不会一起保存：缩放、滚动位置、所选任务和已折叠的阶段。应用设置（例如语言和主题）也不在文件中。应用自己保存这些设置，位置在应用内或浏览器中。

导出为其他格式不会更改你的项目。导出后，项目仍有相同的保存目标。如果之前已标记为*未保存*，它仍会标记为*未保存*。

### 导出会丢失什么

每个适配器都会保留其格式所包含的内容。

**MS Project XML** 会保留任务、关系、日历、资源、分配、约束、截止日期和状态日期。在你的基线中，只有当前激活的那一个会保留下来。活动代码、自定义字段、备注和外部关系不会被保留。任务上的第二个约束不会被保留。如果约束*必须开始于 (MSO)*或*必须完成于 (MFO)*未选择*强制（钉住逻辑）*，它会变回*不得早于…开始 (SNET)*或*不得早于…完成 (FNET)*。任务的*手动计划*和*资源平衡延迟*不会恢复。吊床任务会变成带有计算日期的普通任务。

**Primavera P6 XML** 会保留任务、关系、日历、资源、分配、约束和状态日期。基线和截止日期不会保留，活动代码、自定义字段、备注和外部关系也不会。吊床任务在这里同样会变成普通任务。P6 没有百分比形式的延隔：应用会把这种延隔转换为固定的天数。以日历日计的延隔会变为以工作日计的延隔。

**CSV** 是任务列表。每个任务在文件中有这些列：task id、WBS、level、name、duration、start、finish、predecessors、work category、自定义工作类别的 id（`OPS Custom Task Type ID`）、status、completion、actual start and finish、critical、total float 和 description。资源、分配、日历、约束、截止日期、基线和状态日期都不在其中。列标题始终为英文。

**只有 IFC 会保存计算配置文件和计算选项。** 如果你导出为 CSV、MS Project XML 或 Primavera P6 XML，文件中就不会有计算配置文件；在计算选项中，MS Project XML 最多只会写入关键阈值。这种文件会以 *Open Planner Studio* 重新打开。如果你的项目使用 *Primavera P6* 或 *Microsoft Project* 计算，例如项目来自 `.xer` 或 `.mpp`，日期可能因此变化。计算配置文件是什么，在[计算配置文件和约定](docs://uitleg-rekenprofielen)中说明。

如果你的项目来自 Primavera 文件（`.xer`），即使你中间保存过 IFC，应用在导出为 CSV、MS Project XML 或 P6 XML 后，也会显示：*导出为 CSV 会丢失 XER 源信息。* 对于 MS Project XML，它会显示 *MSPDI*，而不是 *CSV*；对于 P6 XML，它会显示 *P6*。IFC 不会显示该消息：IFC 文件会一并保留 Primavera 的源文件。见[打开 Primavera P6 文件 (.xer)](docs://howto-xer-openen)。

应用在导出时还会做另外两件事。如果计划已过期，它会先重新计算，再导出。另外，如果存在循环依赖，它不会导出该计划：你会收到包含该循环的消息，例如*任务之间存在循环依赖：Set up site → Demolish existing extension → Set up site*。

### 保存、自动保存和崩溃恢复

这是三件不同的事。它们看起来相似，但写入的位置不同。

**保存**是你主动执行的操作。应用会把项目写入你的文件，并去掉*未保存*标记。

**自动保存**默认关闭，你需要为每个项目单独开启。开启后，只要有更改，应用就会在没有窗口的情况下写入同一个文件，每十秒最多一次。它只在项目已经有文件时有效。见[开启自动保存](docs://howto-automatisch-opslaan)。

**崩溃恢复**始终开启。只要任何地方有更改，应用就会保存所有已打开项目的恢复副本，同样最多每十秒一次，包括你自己没有更改的项目。该副本不在项目文件中：在桌面应用中，它位于应用的数据文件夹；在浏览器中，它位于浏览器的存储空间中。下次启动时，应用会提供该副本。详见[崩溃后恢复](docs://howto-herstellen-na-een-crash)。崩溃恢复从不写入你的项目文件。

由于副本最多每十秒保存一次，崩溃时你可能丢失最后几秒的工作。

### 桌面和浏览器

桌面应用和浏览器版本对你的项目的处理方式相同，但写入文件的方式不同。

在桌面上，应用使用真实路径。*保存*会直接写入你的文件。通常，应用会先写入旁边的临时文件（`.ops-save.tmp`），然后才替换你的文件，所以写入一半时崩溃，不会截断你的旧文件。如果你关闭带有未保存更改的应用，它会逐个项目询问是否保存。正常退出时，应用会清除其恢复副本。

在可以将文件保存到任意位置的浏览器中（例如 Chrome 和 Edge），你会看到普通的打开和保存窗口。之后，*保存*会直接写入该文件；对于你打开的文件，浏览器会询问一次权限。*最近*列表可用，只显示文件名。

在无法这样做的浏览器中（例如 Firefox），应用通过文件选择器打开文件，并通过下载来保存。使用*保存*时，消息*已保存为下载文件：“name.ifc”位于您的下载文件夹中。…*会在每个会话中解释一次。使用*另存为*和导出时，你会看到*已保存为下载文件：“name.ifc”现在位于您的下载文件夹中。当前环境不允许应用直接写入您选择的位置。* 如果浏览器可以显示保存窗口，但无法写回项目文件，*保存*每次都会重新询问保存位置。应用也会在每个会话中用一条消息解释一次。*文件 › 最近*也有，但会打开空白页，而且自动保存不可用。在任何不允许应用写入你所选位置的环境中，你都会看到同样的消息。

## 示例：导出示例项目

以示例 *Refurbishment & Extension of a Family Home*（*文件 › 示例*）为例。它有 20 个任务，其中 4 个阶段和 2 个里程碑，以及 16 个关系。它有 6 个资源、8 个分配、1 个基线，以及一个指向 *Demo resource library* 的链接。任务 *Demolish existing extension* 有约束 *不得早于…开始 (SNET)*，日期为 2027年5月14日；*Handover inspection* 有截止日期 2027年7月29日。计划的结束日期是 2027年7月7日。

下面是导出文件重新打开后，项目从每种格式恢复的结果：

- IFC 文件会全部恢复：20 个任务、16 个关系、6 个资源、8 个分配、基线、约束、截止日期和资源库链接。计划再次于 2027年7月7日结束。
- MS Project XML 文件也会全部恢复，但资源库链接除外。计划于 2027年7月7日结束。
- P6 XML 文件会恢复任务、关系、资源、分配和约束。基线和截止日期缺失。计划仍于 2027年7月7日结束，因为约束仍在其中。
- CSV 文件会恢复 20 个任务和 16 个关系。资源、分配、基线、约束和截止日期缺失，项目名称为 *CSV Import*。没有约束时，工作会提前：计划于 2027年7月2日结束，比原来早五个日历日。

没有该约束时，示例本身也于 2027年7月2日结束。因此，差异来自 CSV 文件没有保留的那个约束。

## 后果和常见误解

**导出不是备份。** 只有 IFC 会保留全部内容。如果你想保留项目，请保存为 IFC。只有需要其他格式的人才需要导出。

**重新打开导出的文件，不一定得到相同的计划。** 应用在打开时总会按该格式所属的计算配置文件重新计算。如果缺少逻辑（如 CSV 示例中的约束），或配置文件的计算方式不同，结果就会改变。

**导出的文件也会出现在最近列表中。** 在桌面以及支持文件访问的浏览器中，导出的文件会像已保存的项目一样出现在*最近*中（进度表除外）。如果你从那里打开它，它会作为该格式的导入打开。

**保存和崩溃恢复不是一回事。** 崩溃恢复能在崩溃后帮你，但不能替代保存。所以在关闭标签页或应用之前，先保存。
