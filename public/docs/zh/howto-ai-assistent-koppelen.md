# 连接 MCP 客户端

目标：让 MCP 客户端读取并处理你的计划。你可以看到它做了什么，也可以自己设定限制。

## 快速方法：让 Claude 自己完成

你使用 Claude Desktop 还是 Claude Code？那么 Claude 可以自己设置连接：

1. 点击下方的 *复制提示词*。
2. 将提示词粘贴到与 Claude 的新对话中，然后发送。

随后，Claude 会为 Open Planner Studio 安装扩展，并在过程中说明它的作用。如果你必须亲自操作，例如在 Claude Desktop 中点击 *安装*，Claude 会准确告诉你点哪一处。你不需要为此提供令牌。

```prompt
请为我安装 Open Planner Studio 扩展，这样你就能在 Open Planner Studio 中读取和更改我的施工计划。尽你所能自己完成。每一步之前，用一句简单的话说明你要做什么以及为什么。如果需要我配合，每次只问一件事，并等待我的回答。如果我必须亲自操作，请准确告诉我要点哪一个按钮或执行哪一个操作，以及在哪里操作。

你需要知道的事：
- 扩展是一个文件，open-planner-studio-<version>.mcpb，位于最新发布版本中，你可以在 https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest 找到它。直接链接在 https://api.github.com/repos/OpenAEC-Foundation/open-planner-studio/releases/latest 中（文件名以 .mcpb 结尾的那一个）。该文件是 ZIP 文件。
- 扩展既可以配合 Open Planner Studio 桌面应用使用，也可以不借助应用使用。当应用已打开且其 MCP 桥接正在运行时，你会在应用中打开的计划里工作。当应用已关闭时，你会在我选择的工作文件夹中处理计划文件。
- 安装不需要令牌，也不需要密码。不要向我索要，也不要读取或显示令牌。

如果你在 Claude Desktop 中运行：
1. 如果你可以下载文件并在我的电脑上打开，则用 .mcpb 文件完成这一步。如果不能，请把直接下载链接交给我，并告诉我下载完成后双击该文件。
2. 随后 Claude Desktop 会显示 Open Planner Studio 扩展。告诉我点击“安装”（Install）。然后告诉我在工作文件夹（Working folder）处选择存放我的计划文件的文件夹。
3. 告诉我开启一个新对话，并在那里询问你能看到哪些 Open Planner Studio 工具。

如果你在 Claude Code 中运行：
1. 检查是否已安装 Node.js 22 或更新版本。如果没有，请告诉我如何安装，然后停止。
2. 询问我存放计划文件的是哪个文件夹。这就是工作文件夹。
3. 下载 .mcpb 文件，并将其解压到我的用户文件夹中一个新的独立文件夹里。在那里读取 manifest.json 文件，其中 server.mcp_config 说明服务器如何启动。把 ${__dirname} 替换为解压后的文件夹，把 ${user_config.workdir} 替换为工作文件夹。
4. 运行 claude mcp list。如果已经有名为 open-planner-studio 的服务器，请询问我是否可以替换它。不要显示它的设置，因为其中可能包含令牌。
5. 为我的用户账户添加服务器，例如：claude mcp add open-planner-studio --scope user -e OPS_MCP_ROOT=<工作文件夹> -- node <解压后的文件夹>/server/index.mjs
6. 告诉我开启一个新的 Claude Code 会话，并说明在那里 /mcp 可以显示 open-planner-studio 是否已连接。

如果你在其他地方运行，例如浏览器中的 claude.ai 网站，请告诉我这需要 Claude Desktop 或 Claude Code。如果你不知道自己在哪里运行，请询问我。

安装完成后，用几句话说明：
- 我如何让你在打开的应用中工作：在 Open Planner Studio 中，选择 设置 › 项目 › 应用设置，在 高级选项卡中打开 允许 MCP 连接。然后在 MCP 选项卡上点击 启动桥接。
- 不使用应用时，只有保存后更改才会进入文件；并说明应用打开时，你不会覆盖已有文件。
如果某个步骤失败，请用一句话告诉我出了什么问题，以及我可以怎么做。不要猜测。
```

你更想自己操作，还是使用其他 MCP 客户端？那么请按下面的步骤操作。

## 何时需要

你希望 MCP 客户端读取、分析或更改你的计划。例如，让它起草第一版 WBS、修正任务，或解释关键路径。这通过 **Model Context Protocol**（MCP）实现：这是一种标准，使 AI 程序（即 **MCP 客户端**）能够使用另一个程序的工具。为此，Open Planner Studio 会在你自己的电脑上运行一个小型服务器，即 **桥接**。它提供一组工具，名称都以 `planner_` 开头：读取和更改任务、关系、资源、日历、基线、文档和文件。有哪些工具，以及它们会拒绝做什么，见 [MCP 工具](docs://ref-ai-tools)。MCP 客户端在你打开的项目中工作，而不是在副本中：它添加的任务会立即显示在 Gantt 图中。它使用与你相同的计算，以及相同的 *撤销* 历史。

桥接功能仅在桌面应用中可用。如果你在浏览器中允许 MCP 连接，你确实会看到 *MCP* 选项卡，但按钮 *启动桥接* 呈灰色，并显示文字 *桥接功能仅在桌面应用中可用。* 本文其余部分针对桌面应用。在浏览器中，*立即备份* 和 *打开备份文件夹* 同样呈灰色。

## 步骤

### 1. 允许 MCP 连接

1. 选择 *设置 › 项目 › 应用设置*。你也可以选择 *文件 › 应用设置*，或者顶部的齿轮图标。
2. 选择 *高级* 标签页，并打开 *允许 MCP 连接*。*MCP* 标签页会出现在功能区中。
3. 如果你希望应用一启动就让桥接运行，也请打开 *自动启动桥接*。只有在 MCP 连接打开时，才能打开它。它只在桌面应用中有效。默认是关闭的，因为打开端口是一个有意的选择。

如果你关闭 MCP 连接，桥接会停止，*MCP* 标签页也会消失。

### 2. 启动桥接

1. 切换到 *MCP* 标签页，在 *服务器* 组中点击 *启动桥接*。
2. 查看按钮旁边的状态。它会显示 *已关闭*、*已在端口 3877 上运行*、*端口 3877 被占用* 或 *错误*。如果启动成功，它会显示 *已在端口 3877 上运行*，按钮名称变为 *停止桥接*。如果显示 *端口 3877 被占用* 或 *错误*，按钮仍为 *启动桥接*；见下方的常见问题。

桥接只在你自己的电脑上监听，并且只使用一个端口。默认端口是 3877。在 *连接* 组中，你可以在 *端口* 字段里选择另一个端口，但只能在桥接停止时更改。连接是你自己电脑上的普通 HTTP。应用本身不会向外发送任何数据。MCP 客户端如何处理你的计划，例如其提供方如何处理，不在应用的范围之内。

### 3. 连接 MCP 客户端

1. 在 *连接* 组中点击 *连接*。*连接信息* 窗口会打开。
2. 选择你的客户端需要的内容，见下文。
3. 令牌是隐藏的。点击眼睛图标即可显示令牌。复制按钮始终复制真实的值，即使屏幕上隐藏了令牌。
4. 让 MCP 客户端请求工具列表。这项检查也写在连接提示词中：客户端应能看到前缀为 `planner_` 的工具。预期数量同样写在连接提示词中。

该窗口提供四种连接方式：

- *让 Claude 来处理*：与本文开头相同的提示词，配合 *复制提示词* 按钮使用。适用于 Claude Desktop 和 Claude Code。这种方式不需要令牌。
- *配置片段*：一段配置，你把它粘贴到客户端的 MCP 设置中。
- *连接提示词*：一段文本，你把它粘贴到 MCP 客户端中，之后客户端会自行连接。
- *端点* 和 *身份验证*：分开显示的详细信息。端点是 `http://localhost:3877/mcp`，传输方式为 *streamable HTTP*。每个请求都需要一个头部 `Authorization: Bearer`，后面跟着你的令牌。你的客户端还必须支持 MCP 会话：连接时，桥接会在头部 `Mcp-Session-Id` 中给出一个会话代码，之后每个不带该代码的请求都会被拒绝。Claude Code 和 `mcp-remote` 会自动完成这一步。

**应用更新后请重新连接。** 如果你的 MCP 客户端之前已连接到旧版本的应用，它还不会发送会话代码，桥接会拒绝每个请求。因此，更新后请重新连接：在 Claude Code 中启动新会话，并完全退出 Claude Desktop，然后再次启动它。

**Claude Code。** 配置片段可以直接用于 Claude Code。在终端中运行下面的命令，并把 `<token>` 换成你自己的令牌：

```
claude mcp add --transport http open-planner-studio http://localhost:3877/mcp --header "Authorization: Bearer <token>"
```

你也可以把配置片段放进项目文件夹中的文件 `.mcp.json`。之后不要把该文件加入 git，因为令牌可以访问你的计划。来自 `.mcp.json` 的服务器，首次使用时必须在 Claude Code 中批准。

**Claude Desktop。** Claude Desktop 有一个扩展，即文件 `open-planner-studio-<version>.mcpb`。双击该文件即可由 Claude Desktop 安装。这不需要 Node.js。该扩展既可以配合应用使用，也可以在没有应用时使用。使用本文开头的提示词会更快；下面是手动步骤。

1. 从最新发布版本下载 `.mcpb` 文件：`https://github.com/OpenAEC-Foundation/open-planner-studio/releases/latest`。
2. 双击该文件。Claude Desktop 会打开并显示扩展 *Open Planner Studio*。请安装它。如果双击无效，请在 Claude Desktop 中打开 *设置 › 扩展*，然后在那里安装该文件。
3. 在 *工作文件夹* 字段中，选择包含你计划文件的文件夹。只有在应用关闭时，Claude 才会使用该文件夹。之后，Claude 只会在该文件夹中读取和写入。
4. 启用扩展，然后开始新的对话。询问 Claude 能看到 Open Planner Studio 的哪些工具。

你无需输入令牌或端口：桥接运行时，扩展会自行找到应用。对于 Claude 发出的每个请求，扩展都会重新选择一次：

- *应用已打开且桥接正在运行*：Claude 在应用中打开的计划里工作。你会立即在应用中看到每项更改。
- *应用已关闭，或桥接已关闭*：Claude 在工作文件夹中的计划文件上工作。只有 Claude 保存文件后，更改才会进入文件。没有自动保存。应用打开时，Claude 不会覆盖已有文件，而是以新名称保存。

如果应用在 Claude 工作时打开或关闭，扩展会切换，并告知 Claude。之后 Claude 会先重新选择或打开计划，然后才做任何更改。如果应用未打开时 Claude 仍有未保存的更改，扩展会继续在不打开应用的情况下工作，直到 Claude 保存这些更改。这样就不会丢失任何工作。如果扩展无法连接到应用，并且没有可用的工作文件夹，Claude 只能看到工具 `open_planner_studio_status`，其中的消息会告诉你该怎么做。

**不使用扩展的 Claude Desktop。** 如果你无法使用扩展，请用外部工具 `mcp-remote` 连接 Claude Desktop。配置片段不能直接用于 Claude Desktop：在文件 `claude_desktop_config.json` 中，你需要填写一个由 Claude Desktop 自行启动的程序，而不是地址。`mcp-remote` 需要 Node.js。在 Claude Desktop 中选择 *设置 › 开发者 › 编辑配置*，把下面的内容放入该文件（并填入你自己的令牌），然后重新启动 Claude Desktop：

```
{
  "mcpServers": {
    "open-planner-studio": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:3877/mcp", "--header", "Authorization:${AUTH_HEADER}"],
      "env": { "AUTH_HEADER": "Bearer <token>" }
    }
  }
}
```

令牌放在 `env` 中而不是 `args` 中，这是有意为之：在 Windows 上，Claude Desktop 会破坏包含空格的参数。Claude 中的 *自定义连接器*（*自定义 › 连接器*）无法与桥接配合使用。这时 Claude 会从 Anthropic 云端连接，而云端无法访问你自己电脑上的桥接。

在 *连接* 组中，还有 *令牌* 字段。它是应用为你生成的一段长而随机的代码，并保存在这台电脑上。窗口中会显示 *该令牌可访问当前打开的计划，请勿与他人分享。* 点击 *生成新令牌* 图标即可生成新令牌。应用会先询问 *生成新令牌会断开所有现有连接。是否继续？* 如果桥接正在运行，它会用新令牌重新启动，旧令牌将不再有效。

**扩展如何找到应用。** 桥接运行时，桌面应用会把端口和令牌写入应用数据文件夹中的文件 `mcp/runtime.json`。Claude Desktop 的扩展每次请求时都会读取该文件。在 Linux 和 macOS 上，只有你的用户账户可以读取该文件。在 Windows 上，用户文件夹的默认 ACL 会保护该文件；应用不会单独检查这一点。当你停止桥接或关闭 MCP 连接时，应用会删除该文件。即使 MCP 连接已关闭，应用仍会在 `mcp/open-files.json` 中保存打开文件的列表。只要该文件存在，扩展和无界面 MCP 服务器就不会覆盖任何已有文件，包括你刚打开、但尚未列入其中的文件。允许新建文件。读取同样允许：此时 Claude 看到的是磁盘上的版本，不含你尚未保存的更改。

### 4. 查看 MCP 客户端的操作

1. 在 *活动* 组中点击 *活动面板*。*MCP 活动* 面板会在侧边栏中打开。
2. 桥接的每次调用都占一行，最新的在最上面：包括时间、发生了什么、耗时多久，以及是否成功。点击某一行即可展开 *参数* 和 *响应*。
3. 点击 *清除* 即可清空列表。面板会保留最近 500 次调用。在尚未发生任何调用时，它会显示 *还没有 MCP 活动。桥接调用会显示在这里。*

MCP 连接打开时，状态栏右下角会出现一个带 *MCP* 字样的圆点。它的颜色显示桥接的状态。点击圆点会跳转到 *MCP* 标签页。

### 5. 设定限制

在 *安全* 组中有以下按钮，用来限制 MCP 客户端：

- *暂停*：MCP 客户端暂时不能做任何更改，但仍可以读取。桥接保持活动状态。按钮会变为 *恢复*。
- *只读*：开启时，所有会更改内容的工具都会被拒绝。
- *自动备份：开*：在某个文档中，MCP 客户端第一次更改之前，应用会写入一份 IFC 备份。该选项默认开启。点击按钮即可关闭它，之后它会显示 *自动备份：关*。每次启动桥接后，每个文档只会备份一次。
- *立即备份*：立即为当前活动文档创建备份。之后会显示 *已创建备份：* 以及文件名。
- *打开备份文件夹*：打开包含备份的文件夹。

备份位于应用数据文件夹中的 `ai-backups` 文件夹里。应用会保留较新的备份，并精简较旧的备份；具体做法见 [MCP 工具](docs://ref-ai-tools)。

### 6. 让 MCP 客户端做好计划

MCP 客户端只有知道计划规则，才能做好计划。以下是你自己需要完成的操作：

1. **核心规则无需你做任何操作。** 连接时，桥接会在 MCP 握手的 `instructions` 字段中一并发送这些规则。客户端是否把它们放入系统提示词，取决于客户端本身。
2. **让客户端阅读指南。** *连接信息* 窗口中的连接提示词会要求 MCP 客户端使用工具 `planner_get_planning_guide` 阅读指南。如果你不使用该提示词，请对客户端说：*在更改任何内容之前，先用 planner_get_planning_guide 阅读计划指南。* 你也可以自己在 `https://open-planner-studio.open-aec.com/agent/planning-guide.md` 阅读该指南。
3. **可选：安装技能。** 这只适用于支持技能的 MCP 客户端。把 *goed-plannen* 和 *progress-update* 的 `SKILL.md` 分别放入 `.claude/skills/goed-plannen/SKILL.md` 和 `.claude/skills/progress-update/SKILL.md`，位于 MCP 客户端工作所在的项目文件夹中；如果要用于所有项目，则放在 `~/.claude/skills/` 下。

你有两种方式获取这些文件。让 MCP 客户端调用工具 `planner_get_planning_guide`，并将 `part` 设为 `skill`：响应中会包含这两份文本，以及每个技能应放置的位置。或者从 `https://open-planner-studio.open-aec.com/skills/goed-plannen/SKILL.md` 和 `https://open-planner-studio.open-aec.com/skills/progress-update/SKILL.md` 下载。如果旧版应用中的 *goed-plannen* 仍然存在，请替换它：旧文本是荷兰语，指向的是帮助文章，而不是供 MCP 客户端使用的指南。

你可以在 *活动面板* 中看到 MCP 客户端是否真的读取了指南：如果读取过，就会有一次 `planner_get_planning_guide` 调用。它给出的最终回答应包含一份假设清单：估计的工期、所选的任务分解、它自己创建的关系，以及它设置的每个约束。如果缺少该清单，请要求它提供。按照 *progress-update* 完成进度更新后，回答中应写明状态日期、新的完成日期，以及相对于基线的差异。

## 常见问题，以及应用随后的处理方式

**MCP 客户端做了你想撤回的更改。** MCP 客户端的每次更改都是一个步骤，你可以用 *撤销*（Ctrl+Z）撤回它。MCP 客户端整体提交的一系列更改算作一个步骤。之后，项目会显示为未保存。每次更改后，计划都会重新计算，因此你无需自己按 F5。

**应用拒绝了 MCP 客户端的一次调用。** 开启 *暂停* 和 *只读* 时，应用会拒绝所有更改，但仍允许读取，包括对过期计划的重新计算。如果你自己正在编辑，例如拖动任务条或在字段中输入，MCP 客户端会拿到你编辑前的日期，并收到一条提示，说明这些日期已过期。如果你打开了对话框（例如设置、任务对话框或欢迎窗口），或者开启了演示模式，应用会拒绝所有调用，包括读取，直到你关闭对话框为止。这时，MCP 客户端会收到一条错误消息，其中包含当前打开内容的内部名称，例如 `showTaskDialog`。只有 `planner_get_planning_guide` 仍能正常工作，因为它不读取你的计划。

**MCP 客户端工作时，你切换了文档标签页。** MCP 客户端会在其第一次更改所在的文档上工作。如果你在此期间切换了标签页，应用会拒绝它的下一次更改，直到它确认要改为在另一个标签页上工作。这样，内容就不会进入错误的项目。如果 MCP 客户端自己打开或复制了文档，之后它会在该新文档中工作。

**MCP 客户端写入或打开了文件。** MCP 客户端可以把计划写成 IFC 文件，也可以把计划文件作为新标签页打开。它只能在你的用户文件夹内这样做。只有当它明确要求时，才会覆盖已有文件。

**状态是 *端口 3877 被占用*。** 另一个程序正在使用该端口。应用的消息显示在其下方。此时端口字段会保持锁定（*仅可在服务器停止时编辑。*），即使桥接并未运行，也没有停止按钮。这是一个已知的缺点。在修复之前：先关闭再打开 *允许 MCP 连接*。之后状态会恢复为 *已关闭*，你就可以选择另一个端口。然后请重新复制连接信息，因为端点中包含端口。

**生成新令牌后，客户端无法连接。** 这会断开所有现有连接。请把新令牌交给客户端，或者重新粘贴配置片段。Claude Desktop 中的扩展会自行读取新令牌，你无需在那里做任何操作。

**你自己停止了桥接，它不会自行启动。** *自动启动桥接* 在每次应用启动时只会生效一次。如果你自己停止了桥接，应用不会悄悄地重新打开它。

**标签页 *MCP* 不见了。** MCP 连接已关闭。请在步骤 1 中打开它。

**浏览器中的网页无法与桥接通信。** 桥接会拒绝每个来自浏览器的请求，以及每个没有正确令牌的请求。

## 不使用应用

还有一个可以在没有桌面应用的情况下运行的 MCP 服务器：**无界面 MCP 服务器**。它提供相同的 `planner_*` 工具，但它处理的是磁盘上的计划文件，而不是你打开的项目。因此，你在 Gantt 图表中看不到这些更改，而且应用中的 *撤销* 对它们不起作用。如果你不想打开应用，或者在没有屏幕的电脑上使用，请使用它。

Claude Desktop 的扩展会在应用关闭时自行启动此服务器（见第 3 步）。以下步骤适用于其他 MCP 客户端，例如 Claude Code。

本发布版本不包含现成的服务器下载。你需要使用 `npm run build:mcp-server` 从源代码构建它；为此需要 Node.js 22 或更高版本。结果是一个文件，即 `server.mjs`。

1. 选择一个用于存放计划文件的工作文件夹。服务器只在该文件夹中读写。
2. 连接你的 MCP 客户端。对于 Claude Code，命令在这些步骤下方。
3. 让 MCP 客户端打开一个计划，例如 `~/plan.ifc`。在此服务器中，`~` 表示工作文件夹。
4. 让 MCP 客户端保存结果。没有自动保存：MCP 客户端通过 `planner_export_ifc` 写入文件。未保存的内容会在服务器停止时丢失。

对于 Claude Code 的第 2 步，请在终端中输入以下命令，并使用你自己的路径：

```
claude mcp add open-planner -- node /path/to/server.mjs --root /path/to/working-folder
```

在每个文档的第一次更改之前，服务器会创建一份 MCP 备份，与应用相同。MCP 客户端如果选择工作文件夹之外的路径（包括通过快捷方式，即符号链接），会被拒绝。应用打开时，服务器不会覆盖已有文件。
