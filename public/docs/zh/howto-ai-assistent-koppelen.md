# 连接 AI 助手（MCP）

目标：让 AI 助手阅读并处理你的计划。你可以看到它做了什么，并且可以自行设定限制。

## 何时需要这样做

你想让 AI 助手阅读、分析或更改你的计划。例如，让它起草第一个 WBS、修正任务或解释关键路径。这通过 **Model Context Protocol**（MCP）实现：它是一项标准，让 AI 助手可以使用程序的工具。为此，Open Planner Studio 会在你自己的电脑上运行一个小型服务器，即 **桥接**。它提供一组工具，名称都以 `planner_` 开头：读取和更改任务、关系、资源、日历、基线、文档和文件。哪些工具可用，以及它们会拒绝哪些操作，见 [AI 工具](docs://ref-ai-tools)。为什么连接这样工作，见 [AI 连接的工作原理](docs://uitleg-ai-koppeling)。

桥接只在桌面应用中可用。如果你在浏览器中开启 AI 模式，会看到 *AI* 标签页，但按钮 *启动桥接* 是灰色的，文字为 *桥接功能仅在桌面应用中可用。* 本文其余部分针对桌面应用。在浏览器中，*立即备份* 和 *打开备份文件夹* 也是灰色的。

## 步骤

### 1. 开启 AI 模式

1. 选择 *设置 › 项目 › 应用设置*。你也可以选择 *文件 › 应用设置*，或顶部的齿轮图标。
2. 选择 *高级* 标签页，然后开启 *启用 AI 模式*。功能区中会出现 *AI* 标签页。
3. 如果你希望应用一启动桥接就运行，也请开启 *自动启动桥接*。此选项只在开启 AI 模式时才起作用，且只在桌面应用中有效。默认关闭，因为开放端口是一项需要慎重决定的操作。

如果你关闭 AI 模式，桥接会停止，*AI* 标签页会消失。

### 2. 启动桥接

1. 切换到 *AI* 标签页，在 *服务器* 下点击 *启动桥接*。
2. 查看按钮旁边的状态。状态显示 *已关闭*、*已在端口 3877 上运行*、*端口 3877 被占用* 或 *错误*。如果启动成功，状态会显示 *已在端口 3877 上运行*，按钮变为 *停止桥接*。若显示 *端口 3877 被占用* 或 *错误*，按钮保持为 *启动桥接*；参见下文的问题说明。

桥接只监听你自己的电脑，且只使用一个端口。默认是 3877。在 *连接* 组中，你可以在 *端口* 下选择另一个端口，但只在桥接已停止时才能选择。

### 3. 连接 AI 助手

1. 在 *连接* 下点击 *连接*。窗口 *连接信息* 随即打开。
2. 选择你的客户端需要的连接方式，见下文。
3. 令牌已隐藏。点击眼睛图标即可显示。复制按钮始终复制真实值，即使屏幕上隐藏了令牌。
4. 让助手请求工具列表。这项检查也写在连接提示词中：助手应能看到以 `planner_` 开头的工具。预期数量同样写在连接提示词中。

该窗口提供三种连接方式：

- *配置片段*：一段配置，你将其粘贴到客户端的 MCP 设置中。
- *连接提示词*：一段文字，你将其粘贴到 AI 助手中，之后助手会自行连接。
- *端点* 和 *身份验证*：分别列出的详细信息。端点为 `http://localhost:3877/mcp`，传输方式为 *streamable HTTP*。每个请求都需要一个请求头 `Authorization: Bearer`，后跟你的令牌。你的客户端还必须支持 MCP 会话：连接时，桥接会在请求头 `Mcp-Session-Id` 中给出会话代码，之后每个没有该代码的请求都会被拒绝。Claude Code 和 `mcp-remote` 会自行处理这一点。

**更新应用后请重新连接。** 如果你的 AI 客户端之前已连接到旧版本的应用，它还不会发送会话代码，桥接会拒绝每个请求。因此更新后请重新连接：在 Claude Code 中开始新的会话，并完全退出 Claude Desktop 后再重新启动它。

**Claude Code。** 配置片段可直接用于 Claude Code。在终端中执行以下命令，并用你自己的令牌替换 `<token>`：

```
claude mcp add --transport http open-planner-studio http://localhost:3877/mcp --header "Authorization: Bearer <token>"
```

你也可以把配置片段放入项目文件夹中的 `.mcp.json` 文件。此时请勿将该文件纳入 git，因为令牌可访问你的计划。来自 `.mcp.json` 的服务器首次使用时，必须在 Claude Code 中获得批准。

**Claude Desktop。** 配置片段不能直接用于 Claude Desktop。在文件 `claude_desktop_config.json` 中，你要填写的是 Claude Desktop 自行启动的一个程序，而不是地址。因此需要在中间使用外部工具 `mcp-remote`，它需要 Node.js。在 Claude Desktop 中选择 *设置 › 开发者 › 编辑配置*，将以下内容（填入你自己的令牌）放入该文件，然后重新启动 Claude Desktop：

```
{
  "mcpServers": {
    "open-planner-studio": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:3877/mcp", "--header", "Authorization:${AUTH_HEADER}"],
      "env": { "AUTH_HEADER": "Bearer <token>" }
    }
  }
}
```

令牌故意放在 `env` 中，而不是 `args` 中：在 Windows 上，Claude Desktop 会破坏包含空格的参数。Claude 中的 *自定义连接器*（*自定义 › 连接器*）无法与桥接配合使用。此时 Claude 会从 Anthropic 云端连接，而云端无法访问你自己电脑上的桥接。

在 *连接* 组中还有字段 *令牌*。它是应用为你生成并保存在这台电脑上的一段又长又随机的代码。窗口中会显示 *该令牌可访问当前打开的计划，请勿与他人分享。* 点击 *生成新令牌* 图标，即可得到新令牌。应用会先询问 *生成新令牌会断开所有现有连接。是否继续？* 如果桥接正在运行，它会使用新令牌重新启动，旧令牌随即失效。

### 4. 查看 AI 做了什么

1. 在 *活动* 下点击 *活动面板*。侧边栏中会打开 *AI 活动* 面板。
2. 桥接的每次调用都占一行，最新的在最上面：包括时间、发生了什么、耗时多长，以及是否成功。点击某一行即可展开 *参数* 和 *响应*。
3. 点击 *清除* 即可清空列表。面板会保留最近 500 次调用。在尚无任何操作时，它显示 *暂无 AI 活动。桥接调用将显示在此处。*

开启 AI 模式时，状态栏右下角有一个带 *AI* 字样的圆点。它的颜色显示桥接的状态，点击它会切换到 *AI* 标签页。

### 5. 设置限制

在 *安全* 下有用于限制 AI 的按钮：

- *暂停*：AI 暂时不能做任何更改，但仍可读取。桥接保持运行。按钮会变为 *恢复*。
- *只读*：开启时，所有会更改内容的工具都会被拒绝。
- *自动备份：开*：在 AI 第一次更改某个文档之前，应用会写入一个 IFC 备份。默认开启。点击该按钮可将其关闭，之后会显示 *自动备份：关*。每次启动桥接后，每个文档只会备份一次。
- *立即备份*：立即为当前活动文档创建备份。之后会显示 *已创建备份：* 加文件名。
- *打开备份文件夹*：打开包含备份的文件夹。

备份位于应用数据文件夹中的 `ai-backups` 文件夹里。应用会保留最近的备份，并精简较旧的备份；具体方式见 [AI 工具](docs://ref-ai-tools)。

### 6. 让助手做好计划

只有了解计划规则，助手才能做好计划。为什么这很重要，以及规则包含什么，你可以阅读 [AI 连接的工作原理](docs://uitleg-ai-koppeling)。以下是你需要自己做的事：

1. **核心规则无需你做任何操作。** 连接时会自动提供。客户端是否把它们放入系统提示词，取决于该客户端。
2. **让助手读取指南。** *连接信息* 窗口中的连接提示词会要求助手使用工具 `planner_get_planning_guide` 读取计划指南。如果你不使用该提示词，请让助手执行：*请先用 planner_get_planning_guide 读取计划指南，然后再做任何更改。* 你也可以自己在 `https://open-planner-studio.open-aec.com/agent/planning-guide.md` 阅读该指南。
3. **可选：安装技能。** 这只适用于支持技能的助手。把 *goed-plannen* 和 *progress-update* 的 `SKILL.md` 放在助手工作所在的项目文件夹中，路径为 `.claude/skills/goed-plannen/SKILL.md` 和 `.claude/skills/progress-update/SKILL.md`；若要在所有项目中使用，则放在 `~/.claude/skills/` 下的相同文件夹中。

你有两种方式取得这些文件。请助手调用工具 `planner_get_planning_guide`，并将 `part` 设为 `skill`：响应中包含两份文本，以及每个技能应放置的位置。或者从 `https://open-planner-studio.open-aec.com/skills/goed-plannen/SKILL.md` 和 `https://open-planner-studio.open-aec.com/skills/progress-update/SKILL.md` 下载。如果旧版应用中的 *goed-plannen* 仍然存在，请将其替换：那份旧文本是荷兰语，并指向帮助文章，而不是面向助手的指南。

你可以在 *活动面板* 中查看助手是否真的读取了指南：如果读取了，就会有一次 `planner_get_planning_guide` 调用。助手给出的最终答复应包含一份假设清单：估计工期、所选的分解方式、它自己建立的关系，以及它设定的每个约束。若清单缺失，请要求它提供。依照 *progress-update* 完成进度更新后，答复应写明状态日期、新的完成日期，以及相对基线的差异。

## 可能的问题及应用的处理方式

**AI 更改了你想撤销的内容。** AI 的每次更改都是一个步骤，你可以用 *撤销*（Ctrl+Z）撤销。AI 作为整体提交的一系列更改，算作一个步骤。之后，项目会显示为未保存。每次更改后，计划会重新计算，因此你无需自己按 F5。

**应用拒绝了 AI 的一次调用。** 开启 *暂停* 或 *只读* 时，应用会拒绝所有更改，但仍可读取，包括对过时计划的重新计算。如果你自己正在编辑，例如拖动任务条或在字段中输入，AI 会收到编辑前的日期，并附带日期已过时的提示。如果你打开了对话框，例如设置、任务对话框或欢迎窗口，或演示模式已开启，应用会拒绝所有调用（包括读取），直到你关闭该对话框。AI 随后会收到一条错误信息，其中包含所打开内容的内部名称，例如 `showTaskDialog`。只有 `planner_get_planning_guide` 仍可用，因为它不读取你的计划。

**AI 工作时你切换了标签页。** AI 会在其第一次更改所在的文档上工作。如果你在此期间切换标签页，应用会拒绝它的下一次更改，直到它确认要在另一个标签页上工作。这样，任何内容都不会进入错误的项目。

**AI 写入或打开文件。** AI 可以将计划写成 IFC 文件，也可以将计划文件作为新标签页打开。它只能在你的用户文件夹内进行这些操作。只有在它明确要求时，才会覆盖现有文件。

**状态为 *端口 3877 被占用*。** 另一个程序正在使用该端口。应用的消息显示在其下方。端口字段则保持锁定（*仅在服务器停止时可编辑。*），即使桥接并未运行，也没有停止按钮。这是已知的缺陷。在修复之前，请先关闭再开启 *启用 AI 模式*。状态会恢复为 *已关闭*，你就可以选择其他端口。然后重新复制连接信息，因为端点中包含端口号。

**客户端在生成新令牌后无法连接。** 新令牌会断开所有现有连接。请将新令牌提供给客户端，或再次粘贴配置片段。

**你自己停止了桥接，它不会自行启动。** *自动启动桥接* 每次应用启动时只生效一次。如果你自己停止了桥接，应用不会在后台悄悄将其重新开启。

***AI* 标签页不见了。** AI 模式已关闭。请在第 1 步中开启它。

**浏览器中的网页无法与桥接通信。** 桥接会拒绝所有来自浏览器的请求，以及所有没有正确令牌的请求。
