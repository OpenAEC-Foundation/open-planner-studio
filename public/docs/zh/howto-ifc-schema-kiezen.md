# 选择 IFC 架构

目标：将你的计划保存为你想要与之合并的建筑模型所用的 IFC 架构。

## 何时需要

默认情况下，应用会将项目保存为 IFC 4.3 ADD2。这是 IfcOpenShell 和 Bonsai 所创建文件中 IFC 4.3 的名称。如果你想将计划与建筑模型合并为一个 4D 文件，例如使用 IfcOpenShell 的 *MergeProjects* 配方（ifcpatch），两个文件必须有相同的架构。如果建筑模型是 IFC4 文件，IfcOpenShell 会拒绝将它与 IFC 4.3 计划合并。这时，请在此处选择模型的架构。

## 步骤

1. 打开 *项目设置*：*设置 › 项目 › 项目设置*，或 *文件 › 项目设置*。
2. 在 *保存时的 IFC 架构* 下，选择你的建筑模型的架构。
3. 点击 *应用*。项目现在为 *未保存*。
4. 使用 *保存*（Ctrl+S）或 *另存为* 保存。

三个选项：

- *IFC 4.3 ADD2（默认）* 会在文件的头部写入 `IFC4X3_ADD2`。
- *IFC 4.3* 会写入 `IFC4X3`。这是旧版应用写入 IFC 4.3 的方式。
- *IFC4* 会写入 `IFC4`，用于 IFC4 建筑模型。

## 注意事项和应用的行为

**合并放在最后一步。** 请勿在应用中打开合并后的 4D 文件（建筑模型加计划）再保存。应用只保留计划：墙体和建筑模型的其他部分都会丢失，即使你保留了架构。请在你自己的文件中更改计划，然后再次合并。

**当打开的文件使用另一种架构时，应用会先询问。** 例如，如果你打开 IFC4 文件，或旧版应用的 IFC 4.3 文件，应用不会简单地更改文件类型。你第一次使用 *保存* 或 *另存为* 时，应用会先询问：保留文件的架构，还是改用 IFC 4.3 ADD2。*保留 IFC4*（或 *保留 IFC 4.3*）是按 Enter 时选择的按钮。如果你按 Esc 或点击关闭按钮（×）关闭该问题，应用不会保存任何内容。

**应用每个文件只询问一次。** 你的选择会保存在文件本身中。之后再次打开时，应用不会再次询问。如果你在 *项目设置* 中自行选择架构并点击 *应用*，应用同样不会询问。

**应用无法写入的架构**（例如 IFC2X3）可以在应用中打开。你第一次保存时，问题会说明这一点，然后你从上面三种架构中选择一种。

**自动保存和崩溃恢复不会询问。** 它们会写入文件的架构，并把询问保留到你自己第一次保存时。对于应用无法写入的架构，*自动保存* 在你回答问题之前不会写入文件。

**新项目不会询问。** 新项目，以及来自 XER、MPP 或 CSV 等其他格式的项目，都以 *IFC 4.3 ADD2（默认）* 开始。

**文件内容不会改变。** 三种架构都能识别应用以相同方式写入的计划数据。只有头部的 `FILE_SCHEMA` 行不同。因此，选择另一种架构不会丢失任何内容。

**来自 IfcOpenShell 或 Bonsai 的 IFC 4.3 模型**，头部通常有 `IFC4X3_ADD2`，与应用的默认值相同。IfcOpenShell 不会将带有 `IFC4X3` 的计划合并进去。如有疑问，请查看模型文件顶部的 `FILE_SCHEMA` 行。

**撤销不会更改架构。** 架构属于文件，就像文件的存储位置一样。因此，在 *项目设置* 中的选择，以及保存时对问题的回答，都不是 *撤销* 的一个步骤。要恢复，请在 *项目设置* 中选择另一种架构。这样，*自动保存* 在你撤销编辑后，就不会悄悄写入另一种架构。
