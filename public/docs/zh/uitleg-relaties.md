# 关系和延隔

为什么砌墙要等地基完成后才开始？为什么屋面构件晚到时，屋面安装会推迟一周？原因在于你的任务之间的关系。在本文中，你将了解应用知道哪四种关系、延隔和提前量的作用、延隔以哪个日历计算、阶段上的关系会怎样，以及应用如何判断哪个关系决定任务的开始日期。

这些规则和示例适用于新项目，计算配置文件为 *Open Planner Studio*，工作周为周一至周五。

## 概念

**关系**记录两个任务之间存在依赖。第一个任务是**前置任务**，第二个是**后续任务**。关系是下限：后续任务绝不会早于关系允许的时间开始或完成，但可以更晚开始或完成。如果一个任务有多个前置任务，它会等待由所有这些关系得出的最晚日期。

共有四种。它们的区别在于前置任务的哪个时刻（开始或完成）与后续任务的哪个时刻相关联：

- **FS（完成-开始）。** 后续任务只有在前置任务完成后才开始。屋面构件只有在墙体砌好后才会安装。这是最常用的关系，远超其他几种。
- **SS（开始-开始）。** 后续任务只有在前置任务开始后才能开始。任务可以重叠：管道安装可以在砌墙已经开始时就开始。
- **FF（完成-完成）。** 后续任务只有在前置任务完成后才能完成。勾缝不能在砌墙完成前完成，但它可以更早开始。
- **SF（开始-完成）。** 后续任务只有在前置任务开始后才能完成。这种类型很少见。例如：临时降水只能在地基上的砌墙开始后才停止。

关系还可以有**延隔**：两个任务之间的等待时间，例如混凝土需要养护的时间。负的延隔称为**提前量**：后续任务则在前置任务完成前开始，因此两个任务会重叠。

## 应用如何计算

### 四种类型

对于每个关系，应用计算后续任务能够开始的最早日期，并取一个任务所有关系中的最晚日期。没有延隔时，计算方式如下：

- 使用 FS 时，后续任务在前置任务完成后的第一个工作日开始。
- 使用 SS 时，后续任务与前置任务在同一天开始。
- 使用 FF 时，后续任务与前置任务在同一天完成。为了求开始日期，应用会按后续任务的工期向前推算。因此，工期为 3 个工作日的后续任务，会比前置任务的完成日早 2 个工作日开始。
- 使用 SF 时，后续任务在前置任务开始的当天完成。这里同样按后续任务的工期向前推算。

这些是下限。如果另一个关系或约束要求，后续任务会更晚开始。所有日期只在 **计算**（F5）之后出现；只要状态栏显示 *已过期 — 请重新计算（F5）*，任务条仍显示上一次计算的结果。

### 延隔和提前量

延隔可以用四种方式表示：

- 以**工作日**表示（`3` 或 `3d`）：应用跳过休息日和周末。这是默认值。
- 以**日历天**表示（`3ed`，e 代表 *elapsed*，即实际经过时间）：每一天都计入，包括周六和周日。这个单位适用于不需要人工作业就持续进行的事情，例如养护。
- 以前置任务工期的**百分比**表示（`40%`）：应用在每次计算时重新算出该值，并取整为整天数（2.5 天变为 3 天）。
- 以**工作时间**表示（`4h`）：应用在延迟日历中计算延隔，默认是前置任务所用的日历。如果前置任务是天任务，且其日历没有自己的工作时段，例如标准日历，应用会把小时换算为整个工作日，并四舍五入到最接近的整天（半天向上取整）。工作日为 8 小时时，因此 `2h` 和 `3h` 得 0 天，`4h` 至 `11h`（含）得 1 天，`12h` 得 2 天。如果该日历有自己的工作时段，或前置任务是小时任务，则延隔按工作时间精确计算。

对于 FS 且延隔为 N 个工作日的规则如下：前置任务完成后的 N 个工作日为等待时间，后续任务在其后的第一个工作日开始。对于 SS 和 FF，延隔分别加在前置任务的开始和完成上。负的延隔向前计算：使用 FS 且提前量为 1 个工作日时，后续任务可以在前置任务完成当天开始。

提前量不能使任务早于项目开始。如果会发生这种情况，应用会把后续任务保持在项目开始日，并在 *警告* 面板中给出提示：*提前量被项目开始截断 — 关系未被完全遵守*。

### 延隔以哪个日历计算

每个任务都可以有自己的日历。如果延隔以工作日计算，哪个日历计算工作日就很重要。设置 *延迟日历* 决定这一点，有四个选项：*前置任务*、*后续任务*、*24 小时制* 和 *项目日历*。默认情况下，延隔按**前置任务**的日历计算。你可以在 *设置 › 项目 › 项目设置* 下找到该设置，位于 *计算配置文件和选项* 块中的 *此项目的计算选项* 处。该选择属于项目文件，只有在你点击 *应用* 后才生效；之后会重新计算计划。

以日历天表示的延隔（`3ed`）总是计入所有天，无论你选择哪个 *延迟日历*。

### 摘要任务上的关系

你可以把关系放在阶段（摘要任务）上，而不是放在其中的某个任务上。应用在内部会把该关系放在阶段中的每个任务上：

- 阶段作为**前置任务**，使用 FS 或 FF：后续任务会一直等到阶段中最后完成的任务结束。
- 阶段作为**后续任务**，使用 FS 或 SS：阶段中的每个任务都等待前置任务，与阶段中的其他任务无关。
- 阶段作为**前置任务**，使用 SS 或 SF：后续任务会等待阶段中**最晚**开始的任务开始，而不是等待阶段本身的开始。这比你预期的更保守：后续任务绝不会开始得太早，但可能比你想要的更晚。如果你希望后续任务跟随阶段的开始，请把关系放在阶段中的第一个任务上。
- 阶段作为**后续任务**，使用 FF 或 SF：阶段中的每个任务都必须自行满足完成要求（使用 FF 时，完成日不早于前置任务的完成日；使用 SF 时，完成日不早于前置任务的开始日），即使某个任务本可以早得多完成。这种关系最好放在阶段中的最后一个任务上。

任务与其所在阶段之间的关系不允许。

### 驱动关系

如果后续任务有多个前置任务，通常只有一个关系决定其开始日期：即让后续任务无法比现在提早一天开始的那个关系。这种关系称为**驱动**关系。如果出现并列，就会有多个驱动关系。你可以通过以下方式识别驱动关系：表格中 *前置任务* 和 *后续任务* 列里的闪电符号、*驱动* 列（在表头右侧的 **+**，位于 *关系* 下方），以及追踪路径时颜色更深的底色。打开该路径的方法见 [追踪路径](docs://howto-pad-traceren)。

驱动关系说明的是日期，而不是工期。较短的前置任务也可能是驱动关系，例如因为延隔较长；你可以在下面的示例中看到这一点。

## 示例

示例使用各自独立的小型项目，除非另有说明，均从 2027年6月7日（星期一）开始。关键路径和浮时等术语在 [关键路径和浮时](docs://uitleg-kritiek-pad) 中有说明。自己搭建并检查关系网络，是你在教程 2“关系和关键路径”中要做的事。

### 四种类型并排比较

*Pour foundation* 需要 5 个工作日：6月7日（周一）至 6月11日（周五）。*Build walls*（5 个工作日）以 FS 紧随其后，从 6月14日（周一）至 6月18日（周五）。有四个工期各为 3 个工作日的任务依附于 *Build walls*，各自使用不同类型：

- *Place roof elements*（FS）从 6月21日（周一）开始，即砌墙之后的第一个工作日，并于 6月23日（周三）完成。
- *Pipework*（SS）与砌墙一起从 6月14日（周一）开始，并于 6月16日（周三）完成。
- *Pointing*（FF）必须与砌墙一起于 6月18日（周五）完成。工期为 3 个工作日，因此它从 6月16日（周三）开始。
- *Dewatering*（SF）必须于 6月14日（周一）完成，即砌墙开始当天。向前推算 3 个工作日，即 6月10日（周四）、6月11日（周五）和 6月14日（周一），得出 6月10日（周四）开始。

只有 *Place roof elements* 在关键路径上；项目于 6月23日（周三）完成。*Pipework*、*Pointing* 和 *Dewatering* 的浮时分别为 5、3 和 7 个工作日。

### 数字中的延隔和提前量

*Pour foundation* 于 6月18日（周五）完成。*Build walls*（2 个工作日）以 FS 紧随其后。延隔对开始日期的影响如下：

- 没有延隔时，砌墙从 6月21日（周一）开始。
- 延隔为 `3`（三个工作日）时，6月21日（周一）、6月22日（周二）和 6月23日（周三）为等待时间；砌墙从 6月24日（周四）开始。
- 延隔为 `3ed`（三个日历天）时，计入周六、周日和周一；砌墙从 6月22日（周二）开始。
- 延隔为 `-1`（提前量为一个工作日）时，砌墙从 6月18日（周五）开始，即浇筑完成当天。
- 延隔为 `40%` 时，延隔为 5 个工作日的 40%，即 2 个工作日；砌墙从 6月23日（周三）开始。
- 延隔为 `50%` 时，延隔为 2.5 个工作日，取整为 3 个工作日；砌墙从 6月24日（周四）开始。

### 哪个日历计算延隔

*Build walls*（4 个工作日）位于项目日历上（周一至周五），于 6月10日（周四）完成。*Pointing*（2 个工作日）以 FS 和延隔 `3` 紧随其后，并位于一个周六和周日也是工作日的日历上。这时，开始日期取决于 *延迟日历*：

- *前置任务*（默认）：延隔按砌墙的日历计算。6月11日（周五）、6月14日（周一）和 6月15日（周二）为等待时间；*Pointing* 从 6月16日（周三）开始。
- *后续任务*：延隔按 *Pointing* 的日历计算。6月11日（周五）、6月12日（周六）和 6月13日（周日）为等待时间；*Pointing* 从 6月14日（周一）开始。
- *24 小时制*：每个日历天都计入。这里同样，周五、周六和周日为等待时间；*Pointing* 从 6月14日（周一）开始。
- *项目日历*：延隔按项目日历计算，与 *前置任务* 相同；*Pointing* 从 6月16日（周三）开始。

### 阶段上的关系

*Foundation* 是一个包含两个任务的阶段：*Excavate*（2 个工作日，6月7日（周一）和 6月8日（周二））和随后的 *Pour*（3 个工作日，6月9日（周三）至 6月11日（周五））。*Build walls* 以 FS 跟随阶段 *Foundation*，从 6月14日（周一）开始：应用会让它等待 *Pour*，即最后完成的任务。

阶段作为后续任务时：*Permit*（3 个工作日，于 6月9日（周三）完成）以 FS 连到阶段 *结构*。该阶段包含 *Build walls*（4 个工作日），然后是 *Lay floor*（2 个工作日）。阶段中的每个任务都等待许可：*Build walls* 从 6月10日（周四）开始，并于 6月15日（周二）完成。*Lay floor* 也等待砌墙，从 6月16日（周三）持续到 6月17日（周四）。

阶段以 SS 为前置时：阶段 *Finishing* 包含 *Plastering*（2 个工作日，6月7日和 6月8日），然后是 *Painting*（3 个工作日，6月9日至 6月11日），再然后是 *Snagging*（2 个工作日，6月14日和 6月15日）。*Cleaning* 以 SS 跟随该阶段。你可能预期它从 6月7日（周一）开始，但应用会让 *Cleaning* 等待 *Snagging* 的开始，即最晚开始的任务：6月14日（周一）。

### 什么是驱动

*Pour foundation*（2 个工作日）从 6月7日（周一）持续到 6月8日（周二）。随后有两个分支：

- *Build walls*（5 个工作日）：6月9日（周三）至 6月15日（周二）。
- *Order roof elements*（2 个工作日）：6月9日（周三）和 6月10日（周四）。

*Place roof elements*（3 个工作日）同时跟随两者：在砌墙之后以 FS 连接，并在订购之后以 FS 和延隔 `5` 连接（即交货时间）。从砌墙看，安装可以从 6月16日（周三）开始。从订购看，6月11日（周五）、6月14日（周一）、6月15日（周二）、6月16日（周三）和 6月17日（周四）为等待时间；安装从 6月18日（周五）开始。因此，与订购的关系是驱动关系，即使订购比砌墙短得多。砌墙有 2 个工作日的浮时。

## 后果和常见误解

**“关系会固定任务。”** 不对，关系是下限。后续任务最早在关系给出的日期开始，如果另一个关系或约束要求，则会更晚开始。约束如何配合，见 [约束和截止日期](docs://uitleg-constraints)。

**“SS 表示任务同时开始。”** SS 只表示后续任务不能早于前置任务开始。如果后续任务还有另一个更晚完成的前置任务，它会更晚开始。

**“使用 FF 时，后续任务在同一天开始。”** 不对，使用 FF 时完成日期相同。因此，较短的后续任务会比前置任务更晚开始，就像示例中的 *Pointing*。

**“以天计的延隔计算日历天。”** 默认情况下，延隔按前置任务的日历以工作日计算。对于养护或干燥这类周末也计入的情况，应使用日历天（`ed`）。

**“没有关系的任务不是问题。”** 没有前置任务的任务从其计划的开始日期开始，没有后续任务的任务则会获得直到项目结束的浮时。如果你忘记了某个关系，该任务看起来就有很多空间；请参阅 [关键路径和浮时](docs://uitleg-kritiek-pad) 中的常见误解。

**“阶段上的关系只算一个关系。”** 在计算中，它相当于阶段中每个任务各有一个关系。如果你把任务移入或移出阶段，适用于这些任务的关系也会随之改变。
