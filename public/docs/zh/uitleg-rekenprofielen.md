# 计算配置文件和约定

同一个计划可能得出不同的日期，取决于你应用哪套计算规则。本文说明 Primavera P6 和 Microsoft Project 在几点上的计算方式为何不同，应用如何在 **计算配置文件** 中记录这一差异，以及配置文件与你为每个项目自行设置的计算选项有何区别。下面的实例用一个小型网络说明，这对日期有什么影响。

## 概念

任务、关系和日历决定了计划的大部分内容，但不是全部。你设置状态日期后，尚未开始的工作会怎样？一个已在进行中的任务，其剩余工时从哪里开始？截止日期被错过时，任务的自由浮时是多少？网络本身对此没有说明。计划软件必须为此选定一条规则。应用知道 Primavera P6 和 Microsoft Project 的规则在若干点上不同。

应用将这类选择称为 **约定**。**计算配置文件** 是属于某一款计划软件的一组约定。应用有三个配置文件：

- *Open Planner Studio*：新项目使用的配置文件。没有开启任何约定。
- *Primavera P6*：应用从 P6 中了解到的约定。
- *Microsoft Project*：应用从 Microsoft Project 中了解到的约定。

因此，配置文件说明某个软件包如何计算。你为项目希望的设置不属于配置文件。那就是 **计算选项**：例如，浮时少到多少时任务才算关键，或延隔按哪个日历计算。这些选项你按项目设置。

## 应用如何计算

### 约定和计算选项

约定是一个开关：开启或关闭。配置文件决定哪些开关是开启的。计算选项是你自己做的选择。你可以在应用中看到两者的区别，在 *计算配置文件和选项* 区块中：

- **约定** 位于 *此配置文件的约定* 下，按主题分组，例如 *进度与已完成工作*、*关系与延隔* 和 *浮时与最晚日期*。该部分一开始是折叠的。其标题会显示约定的数量；如果配置文件有偏差，还会显示标签 *已更改：1*。点击标题即可展开。内置配置文件中，每一行有标签 *开启* 或 *关闭*。这些值仅供参考，无法更改。自定义配置文件中，每一行有一个复选框，后面显示基准值（*基准：开启* 或 *基准：关闭*）。如果你的选择与基准值不同，该行会突出显示，并出现 *恢复基准*。每行后面的 i 图标会显示该约定的说明。用鼠标指向它、用 Tab 键移到它，或点按它即可。如果你想更改某个约定，请先阅读其说明。如果某个约定只适用于小时计划，或只适用于来自 .xer 文件的任务，它旁边会出现一个蓝色标签，写明 *仅限小时计划* 或 *仅限来自 .xer 的任务*。小时计划是指：带有工作时段的日历、工期以小时计的任务，或将 *延迟日历* 设为 *24 小时制*。只有日历和以天计的任务的项目，不会受标有 *仅限小时计划* 的约定影响，除非延迟日历设为 *24 小时制*。这时延隔按小时计算，关于延隔的约定就可能产生影响。
- **计算选项** 位于 *此项目的计算选项* 下，其中有 *关键定义*、*浮动计算*、*开放式任务视为关键*、*标记为接近关键* 和 *延迟日历* 等。它们说明你对本项目的要求，而不是某个软件包如何计算。其作用见 [关键路径和浮时](docs://uitleg-kritiek-pad) 与 [关系和延隔](docs://uitleg-relaties)。

两者各举一例。“任务的总浮时为 0 或更少，则该任务为关键”是一个计算选项：你可以将阈值设为 4，那么浮时为 4 个工作日或更少的所有任务都会成为关键任务。“尚未开始的任务移到状态日期”是一个约定：Open Planner Studio 和 Primavera P6 会这样做，Microsoft Project 不会。

配置文件和计算选项属于项目文件，而不属于应用。保存项目时，它们会随项目一起保存。因此，同一应用中的两个项目可以使用不同的配置文件计算。没有配置文件的项目按 Open Planner Studio 计算。

如果你的项目来自 .xer 文件，该区块底部还会显示 *源文件中的设置*：其中是只有 Primavera 才知道、且文件带来的计算选项。你不能在此更改这些设置。使用 *使用 … 的默认设置* 按钮和切换到其他配置文件时，它们也保持不变。新建项目没有这些设置，即使选择 *Primavera P6* 也没有。

### 在哪里选择配置文件

对于新项目，配置文件位于 *新建项目* 窗口中，你可以通过 *首页 › 文件 › 新建* 打开该窗口。在那里，*计算配置文件* 是一个下拉列表。如果你在那里选择一个配置文件，应用会用该配置文件的默认值替换你已填写的计算选项；只有来自源文件的设置会保留。选择 *Primavera P6* 后，*浮动计算* 为 *结束浮动*。选择 *Microsoft Project* 或 *Open Planner Studio* 时，每个计算选项都是默认值，因此 *浮动计算* 为 *自动（默认）*。设置状态日期时，MS Project 本身也是这样计算的：已开始的任务使用结束浮动，其他任务取开始浮时和结束浮动中较小的值。

对于现有项目，你在 *设置 › 项目 › 项目设置* 下选择配置文件，即在 *计算配置文件和选项* 区块中的下拉列表 *计算配置文件* 里选择。你也可以通过 *文件 › 项目设置* 到达同一位置。在这里切换配置文件只会更改约定。你的计算选项保持不变。如果你的计算选项与配置文件的默认值不同，选项上方的橙色区块会提示这一点。这通常是有意为之，例如选项来自所打开的文件。如果你仍想使用默认值，请在该区块中选择 *使用 … 的默认设置*。叉号会为此打开的文件隐藏该区块。

在你按下 *应用* 之前，更改只存在于表单中。按下 *应用* 后，即使 *自动计算* 已关闭，应用也会立即重新计算计划。如果有任务移动，应用会显示移动的数量，例如 *应用后移动了 4 个任务。* 整个切换可以通过一次 *撤销* 撤回。如果你在项目设置打开时按下 *撤销* 或 *重做*，该区块会跟随项目的状态。如果你已自行更改了该区块中的内容，你的选择会保留，黄色区块会说明按下 *应用* 会恢复该选择。

三个内置配置文件无法更改。如需其他约定，请制作自定义配置文件；你也可以将它保存为模板，供此应用中的其他项目使用。项目始终保存自己的副本：之后更改模板，项目不会随之改变。操作步骤见 [选择或制作计算配置文件](docs://howto-rekenprofiel-kiezen)。

### 应用何时自行选择配置文件

打开文件时，应用会根据格式推荐一个配置文件：

- .mpp 文件（Microsoft Project）会以配置文件 *Microsoft Project* 打开。
- .xer 文件（Primavera P6）会以配置文件 *Primavera P6* 打开。
- 格式为 *MS Project XML*、*Primavera P6 XML* 或 *CSV（分号分隔）* 的文件会以 *Open Planner Studio* 打开，不显示配置文件消息。
- 你自己的项目（.ifc）会以其中保存的配置文件打开。

对于 .mpp 或 .xer 文件，应用会报告配置文件：*本项目按 Microsoft Project 计算。可通过 文件 → 项目信息 → 计算配置文件和选项 更改。* 消息中的按钮 *打开计算配置文件* 会直接带你到项目设置。对于 .xer 文件，这一行是文件打开消息中的第一行详细信息。关于该消息的更多内容，见 [打开 Primavera P6 文件（.xer）](docs://howto-xer-openen) 和 [打开 Microsoft Project 文件（.mpp）](docs://howto-mpp-openen)。

对于 .mpp 文件，应用只设置配置文件。计算选项保持为空，与使用 *Microsoft Project* 配置文件的新项目相同：*浮动计算* 为 *自动（默认）*。因此，打开的 .mpp 文件与使用 *Microsoft Project* 的新项目，计算浮时的方式相同。

## 实例：一个网络，三种配置文件

该实例是一个小型网络。日历的工作周为星期一至星期五，这几周没有休息日。进度模式为 Retained Logic（默认值）。项目开始日期为2027年6月7日（星期一）。所有任务均以工作日计。

- *Pour foundation*：5 个工作日，计划的开始日期为6月7日（星期一）。
- *Lay walls*：5 个工作日，在 *Pour foundation* 之后（完成-开始）。
- *Order window frames*：3 个工作日，没有前置任务，计划的开始日期为6月7日（星期一）。
- *Fit roof*：2 个工作日，在 *Lay walls* 和 *Order window frames* 之后。该任务的完成日期就是交付日期。

这些数字由应用的计算引擎算出。你可在 *属性* 面板的 *CPM 结果* 下查看。

**没有状态日期也没有进度时，三种配置文件对该网络的计算结果相同。** *Pour foundation* 从6月7日（星期一）至 6月11日（星期五）进行，*Lay walls* 从6月14日（星期一）至 6月18日（星期五），*Fit roof* 在6月21日（星期一）和6月22日（星期二）。交付日期为6月22日（星期二）。*Order window frames*（6月7日（星期一）至 6月9日（星期三））的总浮时为 7 个工作日。

现在记录状态。状态日期为6月9日（星期三）。*Pour foundation* 于6月7日（星期一）开始，完成度为 60%。因此，剩余工时为 2 个工作日（5 × 40%）。*Order window frames* 尚未开始。[进度与状态日期](docs://uitleg-voortgang) 的工作方式在该文章中说明。这里的问题是配置文件如何处理这些数据。

### Open Planner Studio

*Pour foundation* 的剩余工时从状态日期开始：6月9日（星期三）和6月10日（星期四）。最早开始仍为实际开始日期，即6月7日（星期一）。最早完成为6月10日（星期四）。*Lay walls* 从6月11日（星期五）至 6月17日（星期四），*Fit roof* 在6月18日（星期五）和6月21日（星期一）。

*Order window frames* 的计划开始日期为6月7日（星期一），但尚未开始。尚未开始的任务不能排在过去的时间里。因此，应用会将其移到状态日期：6月9日（星期三）至 6月11日（星期五），总浮时为 4 个工作日。交付日期为6月21日（星期一）。

### Primavera P6

除一点外，其余都与 Open Planner Studio 相同：*Pour foundation* 的最早开始为6月9日（星期三）。这是剩余工时的开始，而不是实际开始日期。这由约定 *进行中任务：最早开始 = 剩余工作的开始* 实现，该约定位于 *进度与已完成工作* 组中。因此完成日期和浮时不变。交付日期为6月21日（星期一）。

### Microsoft Project

这里日期不同。*按 Microsoft Project 的进度* 组中的两个约定造成了这一点。

*不将未开始的任务移到状态日期*：*Order window frames* 保持为6月7日（星期一）至 6月9日（星期三），即使这段时间部分早于状态日期。总浮时为 7 个工作日。

*剩余工作在已用工期之后恢复*：剩余工时不得早于状态日期开始，也不得早于实际开始日期加上已用时间。5 个工作日的 60% 即 3 个工作日已完成。6月7日（星期一）加 3 个工作日为6月10日（星期四）。该日期晚于状态日期，因此剩余工时在6月10日（星期四）和6月11日（星期五）进行。*Lay walls* 从6月14日（星期一）至 6月18日（星期五），*Fit roof* 在6月21日（星期一）和6月22日（星期二）。交付日期为6月22日（星期二），比其他两种配置文件晚一个工作日。

### 假设情况

**该任务的完成度为 20%，而非 60%。** 此时剩余工时为 4 个工作日。在三种配置文件下，该任务都在6月14日（星期一）完成，交付日期为6月23日（星期三）。Microsoft Project 中关于剩余工时的约定在这里没有影响：6月7日（星期一）加 1 个已用工作日为6月8日（星期二），该日期早于状态日期。这种约定是下限，只会使剩余工时更晚。*Order window frames* 和 Primavera P6 下的最早开始仍如上文所述有所不同。在 Microsoft Project 下，*Order window frames* 的总浮时则为 8 个工作日。

**你只设置状态日期，没有输入进度。** 在 Open Planner Studio 和 Primavera P6 下，整个网络都移到6月9日（星期三）。该任务随后从6月9日（星期三）至 6月15日（星期二）进行，交付日期变为6月24日（星期四）：比没有状态日期时晚两个工作日。在 Microsoft Project 下，一切保持原样，交付日期为6月22日（星期二）。

**你自行组合一个配置文件。** 如果你在 Open Planner Studio 下，通过 *新建配置文件* 制作自定义配置文件 *Open Planner Studio 副本*，并且只开启 *不将未开始的任务移到状态日期*，它就会生效。在 60% 进度下，*Pour foundation* 保留 Open Planner Studio 的日期（完成日期为6月10日（星期四），交付日期为6月21日（星期一））。*Order window frames* 确实保持在6月7日（星期一）至 6月9日（星期三），总浮时为 6 个工作日。因此，配置文件是若干独立开关的组合，你可以逐个更改。

**计算选项，而不是约定。** 如果你在 Open Planner Studio 下将 *关键定义*（*总浮时 ≤ 阈值*）的 *阈值（工作日）* 设为 4，*Order window frames* 就会成为关键任务，因为它的总浮时正好为 4。日期不变。计算选项是你为项目做出的选择，与配置文件无关。

**错过截止日期。** 为 *Fit roof* 设置6月18日（星期五）的截止日期。在 Open Planner Studio 下，*Fit roof* 的总浮时为 −1 个工作日，自由浮时同样为 −1。在 Primavera P6 下，总浮时仍为 −1，但自由浮时变为 0。这是约定 *自由浮时永不为负* 的作用，该约定位于 *浮时与最晚日期* 组中。在 Microsoft Project 下两者均为 −2，因为那里的交付日期晚了一天。截止日期的工作方式见 [约束和截止日期](docs://uitleg-constraints)。

## 后果与误解

**“计算配置文件是应用的一项设置。”** 不对。计算配置文件和计算选项属于项目，并随文件一起保存。只有你保留的模板属于应用，项目始终保留自己的副本。

**“如果我导出，我的计算配置文件也会一起导出。”** 只有使用你自己的项目格式（.ifc）时才会。如果你导出为 *MS Project XML*、*Primavera P6 XML* 或 *CSV（分号分隔）*，计算配置文件不会包含在文件中。在计算选项中，*MS Project XML* 导出最多只写入关键阈值。只有来自 .xer 文件的项目，应用才会对此发出警告。对于你自己创建的项目，不会显示任何消息。随后文件会以 Open Planner Studio 打开，且不显示计算配置文件消息。请看这个例子：计算配置文件为 Microsoft Project，进度为 60%。如果你将其导出为 *MS Project XML* 并再次打开，应用会先显示文件中的日期，交付日期为 6月22日（星期二）。如果让应用自行重新计算，则变为 6月21日（星期一）。导出时还会丢失哪些内容，见 [文件和格式](docs://uitleg-bestanden)。

**“Primavera P6 计算配置文件得出的结果与 P6 相同。”** 应用无法保证这一点。计算配置文件会启用应用已知的 P6 约定，但这些并非 P6 的全部设置。除 Retained Logic 和 Progress Override 外，P6 还有第三种进度模式 Actual Dates。应用不支持该模式：这类 .xer 文件会按 Retained Logic 计算，打开时的消息会报告此情况，例如显示为 *使用安全回退的 P6 排程设置：1。* Primavera P6 计算配置文件的部分约定也只对来自 .xer 文件的任务有效，例如 *未开始的 LOE 采用目标窗口* 和 *精确保留实际日期*。其中部分约定的说明会注明：“仅适用于具有 P6 来源的任务”。对于你自己创建的任务，这些约定不起作用。

**“进度模式是计算配置文件的一部分。”** 不对。Retained Logic 或 Progress Override 是每个项目单独的选择。它与计算配置文件分开设置，见 [选择进度模式](docs://howto-voortgangsmodus-kiezen)。Primavera P6 的一项约定，*进度覆盖在逆推时也忽略已开始的紧后作业*，只在 Progress Override 下生效。

**“我只要切换计算配置文件，看看会发生什么。”** 可以，因为一步 *撤销* 就能撤回 *应用* 的结果：计算配置文件和日期会一起恢复。但日期确实可能移动。在这个例子中，从 Open Planner Studio 切换到 Microsoft Project 会移动全部 4 个任务。消息会替你统计数量。再继续之前，请先查看计划。如果打开 .xer 或 .mpp 后，应用仍显示文件中的日期，切换计算配置文件会离开该视图，应用会自行计算。其原理见 [按保存时的状态显示日期](docs://uitleg-datums-zoals-opgeslagen)。

**示例展示了四项约定，应用中的列表更长。** 块中的每一行都有自己的说明。请先阅读说明。另请查看分组 *仅用于自定义配置*：这些约定在每个内置计算配置文件中都是关闭的，包括 Primavera P6。只有自定义计算配置文件才能开启它们：请使用 *新建配置文件* 创建一个。
