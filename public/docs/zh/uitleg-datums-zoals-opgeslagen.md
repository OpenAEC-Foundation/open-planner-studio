# 记录的日期

你从 Primavera 或 MS Project 打开一个计划，日期与你在该软件中看到的不同。导入出错了吗？通常没有。在本文中，你会了解：应用为什么自动重新计算，何时显示文件中的日期，此时哪些内容保持为空，以及如何返回应用自己的计算。文末的示例跟踪两个任务经历整个过程。

## 概念

计划文件包含两类数据。第一类是逻辑：任务、工期、关系、日历和约束。第二类是原软件根据这些内容自行计算出的日期。打开文件时，Open Planner Studio 使用逻辑并自行计算。因此，文件中的日期不是输入数据。

如果应用自己的计算得出的日期与文件所示不同，你无法判断哪一方正确。文件可能缺少原软件所用的逻辑。原软件在某些方面的计算也可能与应用不同。因此，应用可以显示**记录的日期**：即原软件写入文件的日期。这样，你就能与你在原软件中看到的内容进行比较。

## 应用如何处理

### 应用使用哪个计算配置文件

应用使用**计算配置文件**计算。计算配置文件是一组计算规则（约定），用于决定应用如何处理任务的计划开始日期和约束等内容。参见 [计算配置文件和约定](docs://uitleg-rekenprofielen)。应用内置三个配置文件：*Primavera P6*、*Microsoft Project* 和 *Open Planner Studio*。`.xer` 文件以 *Primavera P6* 打开，`.mpp` 文件以 *Microsoft Project* 打开。CSV、MS Project XML 和 Primavera P6 XML 以 *Open Planner Studio* 打开。项目的计算配置文件位于 *文件 › 项目设置* 下的 *计算配置文件和选项* 中。应用保存的 IFC 文件会保留其计算配置文件。

### 应用何时进行比较

打开文件时，应用会记录文件中的内容，并将其与自身的计算结果进行比较。比较适用于：

- Primavera 文件（`.xer`）和 Primavera P6 XML；
- MS Project XML 和 MS Project 文件（`.mpp`）；
- 来自其他程序的 IFC 文件，针对文件中含有最早日期的任务；
- 应用自身保存且记住了其来源的 IFC 文件。下文说明何时属于这种情况。

应用从不比较 CSV 文件：CSV 中的开始日期是输入数据，而不是计算结果。应用自身保存、但未记住来源的 IFC 文件同样不进行比较。

如果没有任务不同，你不会察觉任何变化。如果你当前导入的文件中至少有一个任务不同，应用会立即开启此视图。

对于 Primavera 文件，应用按计算配置文件 *Primavera P6* 计算。这会将文件中计划的开始日期保留为最早开始。因此，文件中比关系所要求的日期晚、但在文件中也有计划的任务会保持原位：此时没有差异。

### 你看到什么

功能区下方有一个提示栏：*你正在查看文件中记录的日期；重新计算将使 4 个任务偏移。* 若来源为 Primavera（`.xer` 或 Primavera P6 XML），则显示 *你正在查看 Primavera 记录的进度计划；重新计算将使 1 个任务偏移。* 栏的右侧是 *重新计算* 按钮。该栏没有叉号。

还有一条消息：*显示文件中记录日期（未重新计算）的任务：12 个。* 只有 `.xer` 文件才会显示 *显示 Primavera 记录日期（未重新计算）的任务：12 个。* 这个数字统计文件为其记录了日期的每个任务，包括不会不同的任务。重新计算后会不同的任务数量显示在提示栏中。对于文件记录了日期的每个任务，其*属性*面板中、在 *开始* 上方都会显示一个橙色区块：*你看到的是 Primavera 保存的日期，而不是应用的计算结果。* 使用其他来源时，显示 *你看到的是文件中的日期，而不是应用的计算结果。* 第二行说明重新计算时此任务会怎样：*重新计算时，此任务会发生变化。* 或 *重新计算时，此任务保持不变。* Gantt、任务表和状态栏显示的都是文件中的日期。

### 已开始或已完成的任务

已完成的任务位于它实际发生的那些日期上：从实际开始日期到实际完成日期。进行中的任务在它实际开始的那一天开始，并在计算得出的完成日期结束。这在此视图中、重新计算后，以及使用每个计算配置文件时都适用，与 Primavera 和 MS Project 中相同。

对于此类任务，文件通常会记录其他的最早日期。Primavera 会将进行中或已完成任务的最早开始日期设为状态日期。你会在 *最早开始* 和 *最早完成* 列中看到这些日期，而不在 *开始* 和 *完成* 中。因此，已完成的任务永远不会计为差异。进行中的任务只有在完成日期不同时才计为差异。

对于已经开始的任务，你不能再输入开始日期。此时，在任务表、*属性*面板和*编辑任务*中，开始日期为只读。对于已完成的任务，任务表中的完成日期同样为只读。请改为通过进度修改 *实际开始日期* 或 *实际完成日期*。在 Gantt 中，此类任务的任务条不会移动；此时会出现一条消息。

### 此视图中保持为空的内容

在此视图中，应用不进行任何计算。它只显示文件中记录的内容。因此，只有文件包含浮时和关键路径时，你才会看到它们。如果文件没有记录关键任务，状态栏会显示 0 个关键任务。这并不能说明源软件包中的关键路径。只有通过计算才能得出的内容，在此视图中不存在：例如驱动计划的关系、违反限制的约束、顺序错误的任务和近关键任务。

如果文件没有为某个任务记录全部数据，*属性*面板中的橙色区块会多出第三行，例如 *Primavera 没有为此任务保存全部数据。缺少：自由浮时。* 使用其他来源时，显示 *文件没有包含此任务的全部数据。* 前两行保持不变：因此对于这样的任务，你仍然可以看到日期来自文件，以及重新计算时此任务是否会发生变化。缺失值的名称与任务表中的列名相同。在 CSV 导出中，此类任务的 *关键* 和 *总浮时* 列保持为空，而不会填入编造的零。

### 离开此视图

你可以用两种方式离开此视图：

- 点击提示栏中的 *重新计算*，或选择 *计算*（F5）。应用按照自身规则计算。
- 更改可能改变日期的内容，例如任务的工期或新增任务。即使 *自动计算* 已关闭，应用也会离开此视图并立即重新计算。更改名称、说明、工作类别或任务类型不会这样：此视图保持开启。

资源库中日历的更改会保持此视图开启，文件中的日期也保持不变，但会更新提示栏中的数字。

离开后，没有按钮可以切换回此视图。紧接在重新计算或此类编辑之后，Ctrl+Z 可以将其恢复。否则，你可以重新打开源文件。若来源为 `.xer`，则打开你在重新计算后保存、但未编辑过的 IFC 文件，也会再次开启此视图。

### 崩溃恢复

如果你在崩溃前处于此视图中，恢复项目后此视图保持开启。如果视图在崩溃前是关闭的，应用会忘记文件中的日期。处于活动状态的项目显示与之前相同的提示栏。位于另一个标签页上的项目会显示不带数字的提示栏：*你正在查看文件中记录的日期，尚未重新计算。* 参见 [从崩溃中恢复](docs://howto-herstellen-na-een-crash)。

### 保存与重新打开

如果你在使用此视图时保存，应用会将显示的日期连同来源格式一起写入 IFC 文件。如果你之后再次打开该 IFC 文件，此视图会再次开启，且不会显示新消息。即使你在此视图中更改了不影响日期的内容（例如名称），也同样适用。应用会按你离开时的样子打开文件。

如果你离开此视图后再保存（通过重新计算，或通过可能改变日期的编辑），文件会保存应用自身的计算结果。再次打开时，你会看到该计算结果，没有提示栏，也没有*属性*面板中的区块。有一个例外：只重新计算、未编辑过的 `.xer`（见上文）。你编辑过的计划现在就是计划；源软件包中的旧日期不再属于它。如果你仍想查看这些日期，请重新打开源文件。

## 示例：扩建

假设你打开一个 Primavera 文件 *Uitbouw*（扩建），其中有两个任务，日历中没有假日。2027年5月6日是耶稣升天节，5月17日是圣灵降临节星期一。如果日历中设有假日，日期会有所不同。*Fundering storten*（浇筑基础）需要 5 个工作日，*Metselwerk*（砌砖）需要 10 个工作日。Metselwerk 通过完成-开始关系接在 Fundering 之后。文件记录：Fundering 从 2027年5月3日（星期一）到 5月7日（星期五）；Metselwerk 从 2027年5月17日（星期一）到 5月28日（星期五）。这比关系允许的最早开始晚了一周。文件中 Metselwerk 计划的开始日期是 2027年5月10日（星期一）。

打开后，你会立即看到文件中的日期。状态栏显示 *结束：28-05-2027* 和 *关键路径：2 个任务，20 个工作日*。提示栏报告重新计算时有 1 个任务不同。两个任务都显示橙色区块 *你看到的是 Primavera 保存的日期，而不是应用的计算结果。* 在 Metselwerk 下方显示 *重新计算时，此任务会发生变化。*，在 Fundering 下方显示 *重新计算时，此任务保持不变。*

点击 *重新计算* 后，Fundering 保持在 5月3日至7日。Metselwerk 现在从 5月10日（星期一）开始，即 Fundering 结束后的第一个工作日，并于 5月21日（星期五）完成。计划于 2027年5月21日结束，跨越 15 个工作日，而不是 20 个。关键路径由同样的 2 个任务组成。

如果情况不同呢？

- 如果文件中 Metselwerk 也计划在星期一 5月17日，计算配置文件 *Primavera P6* 会保留该开始日期。计算结果为 5月17日至28日，没有差异，此视图不会开启。
- 你在此视图中新增一个任务：同样会重新计算。Metselwerk 移至 5月10日至21日。
- 你在此视图中保存，然后不做编辑直接重新打开 IFC 文件：Metselwerk 回到 5月17日至28日。
- 你重新计算，保存后不再编辑，然后重新打开 IFC 文件：此视图再次开启，Metselwerk 位于 5月17日至28日。
- 你只在此视图中更改 Metselwerk 的名称，保存后重新打开：此视图再次开启，Metselwerk 位于 5月17日至28日。
- 你在此视图中新增一个任务，保存后重新打开：应用会忘记文件中的日期。Metselwerk 位于 5月10日至21日，没有提示栏，也没有区块。
- Fundering 在文件中已经完成：它实际于 5月3日开始，5月7日实际完成。文件将状态日期记录为其最早开始。Fundering 的任务条仍位于 5月3日至7日，无论是在此视图中还是重新计算后。Fundering 不计为差异。

## 后果与常见误解

**差异不是导入错误。**应用按照自身规则计算。对于 `.xer`，使用计算配置文件 *Primavera P6*；对于 `.mpp`，使用 *Microsoft Project*；对于 CSV、MS Project XML 和 Primavera P6 XML，使用 *Open Planner Studio*。源软件包中的日期为何不同，原因可能出在文件中，也可能出在源软件包中。此视图会告诉你日期*有*差异。

**此视图不是计算结果。**应用没有计算这些日期。不要直接把它们当作你自己计划的结果。

**在此视图中保存会保留源软件包的日期。**此时 IFC 文件保存的是源软件包所记录的内容，而不是应用会计算出的结果。

**在可能改变日期的编辑之后，文件中的日期不会再回来。**如果你通过这种编辑离开了此视图，只有在保存并重新打开后，你才会看到应用自身的计算结果。更改名称不算在内：此视图会保持开启（见*保存与重新打开*）。如果你想查看源软件包中的日期，请重新打开源文件。
