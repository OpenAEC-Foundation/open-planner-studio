# 导入和导出格式

按文件格式列出：能否打开、保存和导出，哪些内容会带过去，哪些不会，以及打开时使用哪个计算配置文件。背后的原因和一个带数字的示例，见 [文件和格式](docs://uitleg-bestanden)。

## 概览

**打开**支持 IFC、CSV、MS Project XML、Primavera P6 XML、`.mpp` 和 `.xer`。应用会把其他后缀的文件当作 IFC 处理。

**保存**始终写入 IFC。只有已打开的 IFC 文件会成为保存目标。从其他格式打开的项目，打开后没有文件，因此*保存*会询问 IFC 文件应存放的位置。

**导出**支持 IFC、MS Project XML、Primavera P6 XML、CSV，以及两种进度表（Excel 和 CSV）。导出不会更改你的项目。

**只读**格式是 `.mpp` 和 `.xer`：应用可以打开它们，但不能写入。

**PDF** 只能从报表导出（见 [报表类型](docs://ref-rapporttypes)）。应用不读取 PDF。

**位置。** 打开：*首页 › 文件 › 打开*、*文件 › 打开*，或按 Ctrl+O。导出：*首页 › 文件 › 导出*或*文件 › 导出*。你可以通过*文件 › 导入*读入已填写的进度表。也可以使用功能区中*进度*组里的按钮*从表格更新进度*，它位于*计划*、*表格*和*报告*选项卡上。

**打开时的计算配置文件。** 每种格式打开时都有一个计算配置文件。它是什么，见 [计算选项和约定](docs://ref-rekenopties-en-conventies)。`.xer` 使用 *Primavera P6* 打开，`.mpp` 使用 *Microsoft Project* 打开，CSV、MS Project XML 和 P6 XML 使用 *Open Planner Studio* 打开。IFC 保留文件中保存的配置文件。对于 `.xer` 和 `.mpp`，应用会说明项目以这种方式计算。只有 IFC 会保存计算配置文件和计算选项。在计算选项中，MS Project XML 最多只写入关键阈值。从其他格式导出的文件重新打开后，会以 *Open Planner Studio* 计算。

## IFC

**打开** — 支持，`.ifc` 文件。应用读取 IFC4 和 IFC 4.3（也包括 ADD2）。其他模式（例如 IFC2X3）的文件也可以打开。首次保存时，你需选择应用可以写入的模式（见 [选择 IFC 模式](docs://howto-ifc-schema-kiezen)）。计算配置文件：文件中的配置文件。

**保存** — 支持，而且它是唯一可以保存的格式。*保存*会把整个项目按项目的 IFC 模式（默认 IFC 4.3 ADD2）写成一个 IFC 文件。该文件成为保存目标。

**导出** — 支持，格式为 *IFC*，采用项目的 IFC 模式（默认 IFC 4.3 ADD2）。默认名称：项目名称加 `.ifc`。如果你的项目关联了资源库，复选框*同时保存资料库文件*位于*文件 › 导出*的卡片下方。勾选后，应用会在导出项目之后询问 *projectname-bibliotheek.ifc* 的保存位置。该复选框不在*首页*选项卡的列表中。

**哪些内容会带过去** — 属于项目的全部内容：带结构、工期、日期和进度的任务；带延隔的关系；约束和截止日期；日历；资源和分配，包括工时分布；基线；活动代码和自定义字段；备注；指向其他项目的外部关系；中断；任务类型和自定义工作类别；项目设置，如状态日期、进度模式、计算配置文件和计算选项；与资源库的关联。对于来自 `.xer` 的项目，原始源文件也会一起带过去。自定义工作类别以 IFC 类型 `USERDEFINED` 保存，其名称写在 ObjectType 字段中，因此其他 IFC 程序可以正常读取任务。应用还会保存工作类别的固定 ID，所以重命名不会破坏关联。如果有人在另一台电脑上打开该文件，该工作类别会出现在*来自此项目*下，而不会出现在他自己的*我的工作类别*中。

**哪些内容不会带过去** — 你对界面的设置（缩放、滚动位置、所选任务、折叠的阶段、所选筛选和分组），以及应用设置（[应用设置](docs://ref-instellingen)）。*IFC* 选项卡是一个编辑器，显示项目的 IFC 文本。*生成 IFC* 会刷新它，*复制* 会把文本放到剪贴板上，*应用* 会把文本作为你的项目加载，并替换该选项卡中的项目。

## MS Project XML (MSPDI)

**打开** — 支持。应用根据根元素 `Project` 识别 `.xml` 文件为 MS Project XML。该根元素位于 MS Project 命名空间中，或没有命名空间。计算配置文件：*Open Planner Studio*。打开后，应用会用一条消息告诉你它没有接收的内容；见 [打开 MS Project 文件 (.mpp)](docs://howto-mpp-openen)。

**保存** — 不支持。这类项目没有保存目标。

**导出** — 支持，格式为 *MS Project XML*（说明为 *可在 Microsoft Project 中打开，完整 WBS 结构。*）。默认名称：项目名称加 `.xml`。

**哪些内容会带过去** — 带结构（层级和 WBS）、工期、日期和进度的任务；带延隔的关系，延隔可以用小时或百分比；约束，包括截止日期；日历，包括任务日历和资源日历；资源和分配，包括曲线或工时分布；状态日期；关键阈值，为 0 或更大的整数工作日，并带有*总浮时 ≤ 阈值*；任务的说明（作为备注）；任务的任务类型（作为 MS Project 中的任务类型）；自定义工作类别，保存在自由字段（`ExtendedAttribute`）中，应用会读回它，MS Project 可能会忽略它。在你的基线中，只有当前激活的基线会带过去，作为基线 0。以小时计的任务保留其单位，里程碑保留其类型（开始、完成或自动）。

**哪些内容不会带过去** — 备注（任务上的检查清单）、指向其他项目的外部关系、活动代码和自定义字段、第二个约束、*手动计划*标记、资源平衡延迟、带顺序外进度的任务的恢复点和停止点、MS Project 计算配置文件的约定*剩余工作在已用工期之后恢复*和*不将未开始的任务移到状态日期*，以及其他计算选项。没有工时分布的中断任务会带过去，但不带其中断。

**打开时的假日。** 派生日历会继承其基础日历的例外日。自身有工作周且没有例外日的日历不会获得假日。只有既没有基础日历、也没有工作周和例外日的空白日历，才会保留荷兰的标准假日。如果假日缺失，你的完成日期可能会不同：见 [生成假日和建筑业假期](docs://howto-feestdagen-genereren)。

**沿途会改变的内容** — 约束*必须开始于 (MSO)*或*必须完成于 (MFO)*，如果未勾选*强制（钉住逻辑）*，会变成*不得早于…开始 (SNET)*或*不得早于…完成 (FNET)*。吊床任务会变成带计算日期的普通任务。MS Project XML 只为项目日历保存每天小时数。另一个有自己每天小时数的日历，在打开文件时会把它的工作时间当作每天小时数。例如，每天小时数为 8，但工作时间为 10 小时，会变为 10。这类日历上以天计的任务随之变短，例如从 5 天变为 4 天。

## MS Project 文件 (`.mpp`)

**打开** — 支持，来自 MS Project 2010 至 2021 的文件。计算配置文件：*Microsoft Project*。应用只读取文件，从不更改你的 `.mpp`。来自 MS Project 2007 或更早版本的文件，以及有密码保护的文件，应用会拒绝打开，并显示一条消息，指向 MS Project 的 XML 导出。打开后，应用会用一条消息告诉你它没有接收的内容。

**保存** — 不支持，也没有保存目标：*保存*会写入一个新的 IFC 文件。

**导出** — 不支持。

**哪些内容会带过去** — 带结构、工期和约束的任务；带延隔的关系；日历；资源和分配；进度；你在 MS Project 中自己填写的 WBS 代码。MS Project 自己计算的日期和浮时也会被读取，用于视图*按记录的日期*。

**哪些内容不会带过去** — 基线、成本和费率、备注、网址链接、MS Project 的自定义字段、子项目和外部任务的链接，以及关键阈值。见 [打开 MS Project 文件 (.mpp)](docs://howto-mpp-openen)。

**来源和许可** — 这个 `.mpp` 读取器是为 Open Planner Studio 编写的，源自 MPXJ 的源代码和结构知识（`github.com/joniles/mpxj`，Jon Iles 等人）。MPXJ 是一个以 LGPL-2.1 许可的 Java 库。结构和字段常量已移植到 TypeScript。Open Planner Studio 本身是 LGPL-3.0 许可下的开源软件。`.xer` 读取器不是衍生作品：它只把 MPXJ 作为理解的参考来源。

## Primavera P6 XML

**打开** — 支持。应用根据根元素 `APIBusinessObjects` 识别 `.xml` 文件为 P6 XML。计算配置文件：*Open Planner Studio*。

**同一文件中的多个项目。** 每个有任务的项目会在各自的选项卡中打开，名称为*项目名称（项目 ID）*。应用会跳过没有任务的项目。当前选项卡是任务最多的项目。应用不会带过去指向其他项目的关系，也不会带过去不属于任何项目的任务。打开后，应用会报告打开了多少个项目。

**打开时的假日。** 与 MS Project XML 适用相同的规则：自身有工作周且没有例外日的日历不会获得假日。

**基线。** 文件中的 `<BaselineProject>` 会成为其项目的一个基线。P6 标记为激活的基线，在应用中也处于激活状态。

**分配的费率。** 如果仍有剩余工作，剩余费率（`RemainingUnitsPerTime`）会成为*单位/天*。否则使用计划的费率（`PlannedUnitsPerTime`）。对于材料，计划的费率保持不变。应用打开文件时不会重新计算任何内容。导出为 P6 XML 时，它会把计划的费率写为 `PlannedUnitsPerTime`。只有当分配有单独的计划的费率时，它才会把剩余费率写为 `RemainingUnitsPerTime`。

**无法读取的任务。** 如果应用找不到它能读取的任务，它不会打开选项卡。它会报告此情况，已知原因时一并给出原因。例如：没有 `ObjectId` 的任务，或 XML 文件中出现的 XER 列名。此时，请从 P6 重新将项目导出为 P6 XML，或将其作为 `.xer` 打开。

**Save** — 不支持。

**导出** — 支持，格式为 *Primavera P6 XML*（说明为 *适用于 Oracle Primavera P6。*）。默认名称：项目名称加 `.xml`，如果项目有项目 ID，则在括号中加上项目 ID。MS Project XML 导出的名称相同，因此请自行为它们取不同的名称。

**项目名称与项目 ID。** 应用会将 P6 中的项目 ID 与项目名称分开保存，`.xer` 也是如此。*项目设置*只显示名称，例如 *Bid for Facility Extension*。选项卡显示 *Bid for Facility Extension (OZB-05)*。如果你把项目重命名为 *Hall extension*，选项卡会显示 *Hall extension (OZB-05)*。导出为 P6 XML 时，它会把 *OZB-05* 写回为项目 ID，并把 *Hall extension* 写为名称。这样 P6 就能识别该项目。来自 `.xer` 的项目也会带上它的项目 ID。将项目保存为 IFC 时，项目 ID 保持不变。名称本身中的括号，例如 *New build (phase 2)*，会保留在名称中。没有项目 ID 的项目，在导出时会由应用获得一个唯一的 ID，以 *OPS:* 开头。

**哪些内容会带过去** — WBS 结构，以及带工期、日期和进度的任务；带延隔的关系；约束（也包括第二个约束，作为软约束）；日历；资源和分配；状态日期（作为 `DataDate`）；自定义工作类别，保存在它自己的字段 `OPS Custom Task Type` 中。应用会读回它，P6 可能会忽略它。

**哪些内容不会带过去** — 基线和截止日期；活动代码、自定义字段、备注和外部关系；计算选项；假日的名称。P6 不为每个非工作日设置名称：重新打开后，假日会称为*假日*，工作例外会称为*工作例外*。连续的非工作日会作为一个范围返回。应用会缩短超过 P6 允许长度的名称或代码：任务名称缩短到 120 个字符，任务 ID 或 WBS 代码缩短到 40 个字符，WBS 或项目名称缩短到 100 个字符。它会报告缩短了多少个名称和代码。P6 不支持以百分比计的延隔：应用会把它换算为固定的天数。以日历天计的延隔会变为以工作时间计的延隔：3 个日历天会变为 3 个工作日。吊床任务会变为普通任务，手动计划的任务会变为带计算日期的普通任务，少于一天的资源平衡延迟会被丢弃。

## Primavera 文件 (`.xer`)

**打开** — 支持。计算配置文件：*Primavera P6*。应用只读取文件：它不会写入 `.xer`，也从不更改你的文件。每个包含任务的项目会打开一个标签页。没有任务，或表格已损坏的文件，应用会拒绝打开，并显示一条消息。

**保存** — 不支持，也没有保存目标：*保存*会写入一个新的 IFC 文件，其中包含原始 `.xer`。

**导出** — 不支持。如果你把从 `.xer` 来的项目导出为 CSV、MS Project XML 或 P6 XML，应用会报告 XER 源信息会丢失，即使你中间已将项目保存为 IFC。导出为 IFC 则不会丢失任何内容。

**哪些内容会带过去** — WBS 结构，以及带工期、日期、约束和进度的任务；带延隔的关系；日历；带分配的资源；活动代码；自定义字段（UDF）；备注；P6 的排程设置。类型为 *Level of Effort* 的任务会变为吊床任务。基线项目会成为引用它的项目的激活基线。两个项目之间的关系会由应用保留为源数据。

**分配的速率。** 如果仍有剩余工时，剩余速率（`remain_qty_per_hr`）会变为*单位/天*。否则，计划速率（`target_qty_per_hr`）会变为*单位/天*。计划工时、实际工时和剩余工时与文件中的保持一致。对于材料，计划速率保持不变。

**一个不在文件中的空闲周六或周日。** 一些 P6 导出会把连续空闲日中的一个周末空闲日，移到前面的周五或后面的周一。如果日历在周六或周日工作，该日会被错误地变为工作日。如果应用在至少三个连续空闲日的区块中看到这种模式，它还是会把该周末日设为空闲。在日历中，该日称为*日历例外（周末重建）*，并计入消息中的*日历发现：N。*一行。在周末不工作的日历上，什么都不会改变。

**没有完成日期时，浮时计算到项目完成。** P6 中是否开启了计算浮时至项目完成的选项，但文件中项目没有完成日期，且没有任何任务有计划完成日期？如果是，应用会关闭选项*计算浮时至项目完成日期*。然后它会从最晚的最早完成日期往回计算最晚日期。这会计入消息中的*使用安全回退的 P6 排程设置：N。*一行。

**状态日期上已完成的任务。** 有些文件不记录已完成任务的实际日期，而是记录状态日期上的一个时间窗口。在视图*按记录的日期*中，这样的任务会是状态日期上的一个窄任务条。如果重新计算把它放到另一个位置，它就会计入该条带给出的任务数。约定*状态日期窗口中的已完成任务*会计算这样的窗口。只有使用该约定时，已完成任务才会通过计算选项*已完成任务：最晚日期从数据日期起算*获得真实的浮时。这个约定是一种近似：应用只在 P3 的输出中见过这种行为，而 Primavera 在任何地方都没有证实它。这就是为什么它在每个内置计算配置文件中都是关闭的，包括 *Primavera P6*。你可以在区块*计算配置文件和选项*中开启它；这样，项目会获得一个自定义配置文件。参见 [计算选项和约定](docs://ref-rekenopties-en-conventies)。

**带小数逗号的数字。** P6 在表 `CURRTYPE` 中记录小数分隔符和千位分隔符。应用会先读取这些字符，然后再转换工期、工时和浮时。如果缺少这些信息，应用会使用点号作为小数分隔符。如果文件中仍有带小数逗号的数字，应用就不会打开任何内容。这样，数字读取错误的计划就不会被打开。

**哪些内容不会带过去** — 没有任务的项目，以及两个项目之间的关系（不会变为计划中的真实关系）。见 [打开 Primavera P6 文件 (.xer)](docs://howto-xer-openen)。

## CSV

**打开** — 支持。应用把 `;` 和 `,` 当作分隔符。它能识别英文和荷兰文的列标题，例如 `Name` 或 `Naam`、`Duration` 或 `Duur`、`Predecessors` 或 `Voorgangers`。日期可以是*年-月-日*、*日-月-年*或*日/月/年*。前置任务要写成 WBS 代码、关系类型和延隔，例如 `1.2FS+2d`。计算配置文件：*Open Planner Studio*。项目名称为 *CSV Import*。`Task Type` 列存放的是工作类别，而不是任务类型。应用也会读取列标题 `Werksoort` 和 `Work category`。不属于固定代码的 `Task Type` 值（例如应用自己写入的 `CONSTRUCTION` 或 `INSTALLATION`）会变为*来自此项目*下的自定义工作类别，而不是*我的工作类别*。若有 `OPS Custom Task Type ID`，则会保留自定义工作类别的 ID。

**保存** — 不支持。

**导出** — 支持，格式为 *CSV (;)*（*通用表格导出，包含所有任务的日期和工期。*），位于卡片 *CSV（分号分隔）* 上。文件使用分号作为分隔符，采用带 BOM 的 UTF-8 编码，列标题为英文。

**哪些内容会带过去** — 每个任务包含以下列：`OPS Task ID`、`WBS`、`Outline Level`、`Name`、`Duration (days)`、`Start`、`Finish`、`Predecessors`、`Task Type`、`OPS Custom Task Type ID`、`Status`、`Completion (%)`、`Actual Start`、`Actual Finish`、`Critical`、`Total Float` 和 `Description`。`Task Type` 列存放工作类别。完成度以整数百分比计。延隔以小时计时时，会使用应用语言的小时符号：英文为 `1.2FS+2h`，荷兰文为 `1.2FS+2u`。打开文件时两种都能读取。

**哪些内容不会带过去** — 资源、分配、日历、约束、截止日期、基线和状态日期。如果日期以*按记录的日期*视图显示，对于源文件未记录该信息的任务，导出会将 `Critical` 和 `Total Float` 留空。

## 进度表（Excel 和 CSV）

**打开** — 支持，通过*文件 › 导入*（*从表格更新进度*），或通过功能区组*进度*中同名的按钮，位于*计划*、*表格*和*报告*选项卡上。应用读取 `.xlsx` 和 `.csv`，最多 16 MB 和 50,000 行。这不会打开项目：它会更新你已打开项目的进度。见 [从表格导入进度](docs://howto-voortgang-importeren)。

**保存** — 不支持。

**导出** — 支持，格式为*进度表（Excel）*（列表中为*进度（Excel）*）和*进度表（CSV）*（列表中为*进度（CSV）*）。默认名称：*项目名称-进度*。同一功能区组中的按钮*导出进度表*可一键生成 Excel 表。Excel 表有固定的列宽、锁定的字段和日期检查。CSV 表的内容相同，但为纯文本。

**哪些内容会带过去** — 包含以下列：`OPS Task ID`、`WBS`、`Name`、`Start`、`Finish`、`Completion (%)`、`Actual Start` 和 `Actual Finish`。读入时，应用使用 `Completion (%)`、`Actual Start` 和 `Actual Finish`。`Start` 和 `Finish` 只用于识别日期格式，不会更改你的计划。应用按 `OPS Task ID` 将行与任务关联，否则按唯一的 WBS 代码关联。

**哪些内容不会带过去** — 这些列以外的一切：工期、关系、资源和计划的其余部分。摘要任务不会从进度表获得进度。

## PDF

**打开** — 不支持。

**保存** — 不支持。

**导出** — 支持，从报表导出：在*报告*选项卡上使用按钮*导出 PDF*。应用不会自行把报表发送到打印机。要得到纸质版，需经由 PDF。内容取决于报表类型。见 [报表类型](docs://ref-rapporttypes) 和 [制作和打印报表](docs://howto-rapport-maken-en-afdrukken)。
