# 连接 AI 助手（MCP）

Open Planner Studio 可以向 AI 助手开放自己。开启 AI 模式后，应用本身就变成一个 **MCP 服务器**：像 Claude 这样的助手会连接到你此刻正打开的窗口，读取你的计划并对其进行修改。你可以全程旁观——它新增的每一个任务都会立即出现在甘特图中——而助手所做的一切，你都可以用一次 Ctrl+Z 撤销。

这与“导出一个文件、拿到别处修改、再导入回来”是完全不同的模式。这里没有副本，没有中间格式，也不存在你和助手看到的东西不一致的时刻。本指南将说明如何开启这项功能、如何连接一个助手、它能做什么和不能做什么，以及连接失败时该怎么办。

## 您将在此学到什么

- 开启 AI 模式，并找到 AI 标签。
- 启动桥接，以及让它随应用自动启动。
- 连接一个助手——通过一段现成的提示词，或一段配置片段。
- 一个助手可以对你的计划做什么。
- 安全控制项：暂停、只读、自动备份和活动记录。
- 连接失败时该怎么办。

桥接功能**仅在桌面应用中可用**。浏览器构建版本中 AI 标签同样可见，但服务器本身运行在桌面客户端内部，无法在浏览器中启动。

## 开启方式

AI 模式默认关闭。通过 **设置 → 应用程序 → 启用 AI 模式** 开启它——齿轮图标、设置功能区标签，或文件 → 设置，三处显示的是同一个开关。

开启之后，功能区中会出现额外的 **AI** 标签。再次关闭 AI 模式，该标签会随即消失，正在运行的桥接也会立即停止——因此绝不会出现标签已经不在、服务器却仍在监听的情况。

下方是**自动启动桥接**开关。开启后，服务器会在你打开应用的同时立即上线，这样助手无需你先打开 AI 标签就能连接。它默认关闭：在自己的电脑上开放一个监听端口，理应是一个刻意的选择。

## AI 标签

该标签由四个分组组成。

**服务器** —— **启动桥接**（或**停止桥接**）按钮，旁边是状态：*已关闭*、*已在端口 3877 上运行*、*端口 … 被占用* 或 *错误*。同样的状态还会以一个彩色圆点的形式出现在状态栏右下角，因此无论你在哪个标签，都能看到桥接是否存活。

**连接** —— 端口号（仅在服务器已停止时可编辑；运行中的服务器会锁定其端口）、令牌，以及**连接**按钮。令牌默认隐藏；眼睛图标按钮可以显示它，复制按钮可以取走它，**生成新令牌**则会生成一个全新的令牌。请注意，最后这一项会断开**所有**已建立的连接，因为它们携带的都是旧令牌——这也是应用会先要求确认的原因。

**安全** —— **暂停**、**只读**、**自动备份**开关，以及**立即备份**和**打开备份文件夹**按钮。它们各自的作用，见下文*安全控制项*一节。

**活动** —— **活动面板**按钮打开一份列表，记录助手发起的每一次调用：时间戳、工具名称、耗时，以及是否成功。展开任意一行即可查看参数和返回结果。这就是你的日志：你不必单凭助手的说法来判断它做了什么。

## 连接一个助手

点击**连接**。打开的窗口中有四个可以逐一复制的区块：

1. **端点** —— 桥接监听的地址，默认是 `http://localhost:3877/mcp`。传输方式为流式 HTTP。
2. **身份验证** —— 每次请求都必须附带的 HTTP 请求头，形式为 `Authorization: Bearer …`。
3. **配置片段** —— 一段可直接粘贴进你的客户端 MCP 配置中的现成 JSON。
4. **连接提示词** —— 一段可以直接粘贴给助手的文字；助手会自行完成连接，随后核对自己的工具列表。

最后这一项是最快的路径，适用于任何支持添加 MCP 服务器的助手。这段提示词刻意做到与厂商无关：它只提及地址、令牌，以及助手事后应当核实的内容，因此不论使用哪家的助手，效果都是一样的。

一旦助手能够列出自己的工具，连接就算完成。它应该能看到约四十个工具，全部以 `planner_` 开头。如果一个都看不到，说明桥接没有启动，或者令牌不对。

这个令牌授予的是访问你当前打开的计划的权限。请像对待密码一样对待它：不要放进共享文档，也不要发进有其他人在场的聊天。

## 助手可以做什么

这些工具覆盖了你自己在应用里做的几乎所有事情：

- **读取** —— 项目概览、任务列表、单个任务的详情、关键路径、资源及其直方图、日历、基线，以及与某条基线的对比。
- **排程** —— 创建任务（一次性建好包含各阶段和子任务的整个 WBS）、修改、移动和删除任务；添加、更改和移除关系；记录进度。
- **配置** —— 创建并分配资源，管理日历和非工作日，保存并激活基线，执行资源平衡。
- **管理** —— 创建、复制和切换文档，导入计划文件，以及导出为 IFC。

比这份清单本身更重要的，是下面这两点。

**助手可以把一系列步骤打包在一个脚本里执行。** 它不必逐个调用工具，而是可以把一连串步骤作为一个整体一次性提交。这不仅仅意味着更快：整个脚本会成为你操作历史中的**一步**。如果它一次性搭建出一份包含四十个任务及其全部相互关系的计划，一次 Ctrl+Z 就能把它整个撤掉。如果执行到一半出现结构性错误，整个脚本会被整体回滚，而不会让你留下一份烂尾的计划。

**每次修改之后，计划都会被重新计算。** 助手不需要另外去请求计算，因此也不会在不知不觉中基于过期的日期继续工作。

## 助手不可以做什么

桥接的能力刻意比应用本身要窄。有几件事，即使你要求，助手也无法完成——它会得到一个拒绝，并附带真正可行的路径说明。这不是一种“儿童锁”：每一种情况都是因为它触及的范围超出了你此刻正在查看的这个项目。

**资源库本身。** 助手无法新建、修改或删除库中的资源或日历。资源库是跨你所有项目共享的应用级数据，对它的修改也落在通常的撤销历史之外。一次费率变更就会波及那些甚至没有打开的项目，而且无法撤回。这件事你得自己动手，在文件 → 资源库中完成。

**继承资源的固定字段。** 如果一个资源来自资源库，那么“这个资源是什么”由资源库决定：名称、类型、描述、费率/小时和单位。这些字段在资源标签中之所以显示为纯文本——你自己在那里也无法编辑它们——正是出于这个原因，助手同样无法触碰它们。**项目**自己决定的部分则依旧可以由它操作：最大单位数、分时段可用性、日历以及所属班组。如果你仍然要求改动费率，拒绝信息会给出两条真正可行的路径：在资源库中修改它（这样会作用于**每一个**项目），或者先将该资源与资源库取消关联——之后它就变成项目专属、完全可编辑，而这个取消关联的动作本身也可以用 Ctrl+Z 撤销。

**项目日历用的是哪一份日历。** 助手可以编辑该日历的内容，但更换项目所使用的日历，得你自己在资源库中完成。多关键路径这类排程选项同理。

**应用本身。** 没有任何工具可以操作设置、主题、语言、扩展或更新程序。助手不会改动你程序的任何配置。

**文件——可以，但有边界。** 导入意味着它可以从你的磁盘读取一份计划文件，导出意味着它可以写出一份 IFC。写入被限制在你的个人文件夹内，而且除非明确要求，否则绝不会覆盖已有文件。导出也不等于“保存”：你的文档在应用中依然会标记为未保存，所以它无法在你不知情的情况下替换你的项目文件。

在查询资源列表时，助手会立即看到哪些资源来自资源库、属于哪个资源库，以及哪些字段是固定的。它不必先撞上限制才知道这些信息。

## 安全控制项

**暂停**让桥接保持在线，但拒绝一切修改；读取操作仍然可用。当你想自己动手做点什么、又不想断开连接时很有用。

**只读**效果相同，但它是一种持续的状态，而不是临时的暂停：让助手可以分析、汇报或对比你的计划，同时无法改动任何内容。

**自动备份**会在一个文档第一次被修改之前，自动写出一份 IFC 副本。这在每个会话、每个文档中只会发生一次，所以不会因为每次调用都堆出一堆文件。**立即备份**会立刻执行一次，比如在你放手让助手做一件有较大影响的事情之前用得上。**打开备份文件夹**会带你去它们所在的位置；应用为每个文档保留最近十份。

除此之外还有普通的撤销历史，助手与你共用这份历史。它做的任何事，你都能撤销——反过来助手自己也能这么做，因为撤销和重做同样在它的工具箱里。

## 出现问题时

**“端口 … 被占用。”** 已经有别的东西在监听那个端口了。通常是这个应用的第二个窗口：桥接一次只能服务一个窗口。关闭另一个窗口，或者在服务器停止运行时换一个端口号。

**助手没有收到响应，或者一直卡住。** 这通常发生在服务器背后的那个窗口已经消失或被重新加载之后。停止桥接再重新启动；如果还不行，重启应用。拿不准它是否还活着，就看状态栏里的那个状态圆点。

**助手看不到任何工具，或者报告一个访问错误。** 那说明令牌不对。这种情况多半发生在连接已经建立之后又点击了**生成新令牌**：助手手里拿的还是旧令牌。从**连接**窗口复制新令牌，并更新你客户端里的配置。

**助手说成功了，但什么也没发生。** 去活动面板看看它实际调用了什么、返回了什么。如果那里有一条拒绝记录，它几乎总会同时说明哪个字段出了问题，以及可行的替代方案。

## 让您的 AI 助手做好计划

即便助手熟悉所有工具，它仍可能做出一份计划人员用不上的进度计划：任务之间没有逻辑关系、每项任务都钉死日期，或者分解得太细而无法维护。避免这些问题的原则写在指南 [做好计划：从需求到可靠的进度计划](docs://gids-goed-plannen) 中——让助手在动手之前先读一遍，或在您的指令中引用它。此外，Open Planner Studio 的源代码中还有一个简短的 agent skill，位于 `.claude/skills/goed-plannen/`，其内容同样指向该指南，只补充与 agent 相关的部分：按什么顺序调用 `planner_` 工具，以及应向用户回报什么。
