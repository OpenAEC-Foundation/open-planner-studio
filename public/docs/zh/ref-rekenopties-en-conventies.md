# 计算选项和约定

这里列出决定应用如何计算计划的所有选择。你可以在区块 *计算配置文件和选项* 中找到它们：配置文件、每个配置文件的 27 个约定，以及项目的计算选项。为什么 P6 和 MS Project 的计算方式不同，说明见 [计算配置文件和约定](docs://uitleg-rekenprofielen)；这对你的日期有什么影响，见 [按记录的日期](docs://uitleg-datums-zoals-opgeslagen)。

## 在哪里找到它们以及它们如何工作

选择 *设置 › 项目 › 项目设置*，或 *文件 › 项目设置*。底部是区块 *计算配置文件和选项*。在 *新建项目* 窗口中只有下拉列表 *计算配置文件*：你做出选择后，应用会立即套用该配置文件的默认选项。

**按项目设置，而非按应用设置。** 配置文件和选项属于项目文件，并随 *保存*（IFC）一起保存。因此，两个人打开同一个文件时，会以相同方式计算。CSV 和 P6 XML 不包含它们；在计算选项中，MS Project XML 最多只保留关键阈值。见 [导入和导出格式](docs://ref-import-exportformaten)。你自己的模板适用于整个应用：应用会把它们保存在这台设备上。

**只在应用时生效。** 你在此区块中所做的更改，在你点击 *应用* 之前只是草稿。之后，即使 *自动计算* 已关闭，应用仍会重新计算计划。如果有任务移动，它会显示移动了多少个任务（*应用后移动了 3 个任务。*）。如果没有任务移动，则不显示任何消息。这算作一步，可以用 *撤销* 撤回。应用后，视图也会切换到 *按记录的日期*。没有实际变化的更改不会产生任何效果。在 *文件 › 项目设置* 中，你可以用 *放弃* 丢弃草稿。

## 计算配置文件

**计算配置文件** — 应用计算时所依据的基础。你可以从 *Primavera P6*、*Microsoft Project* 和 *Open Planner Studio* 中选择，也可以选择你自己的模板或本项目的自定义配置文件。默认值：新项目以及没有配置文件的项目使用 *Open Planner Studio*。作用：配置文件会开启或关闭下面 27 个约定中的每一个。你打开的文件会获得其格式对应的配置文件：`.xer` 按 *Primavera P6* 计算，`.mpp` 按 *Microsoft Project* 计算，CSV、MS Project XML 和 P6 XML 则按 *Open Planner Studio* 计算。IFC 文件会保留其中存储的配置文件。来自较早文件、与内置配置文件有偏差的配置文件，会称为 *Primavera P6（已修改）*，即基础的名称加上（已修改）。只要项目以该方式计算，该行就会在列表中单独保留。普通的 *Primavera P6* 行是纯粹的基础，不含这些偏差；如果你选择它，会有一个区块说明这一点。如果你选择另一个内置配置文件，例如 *Microsoft Project*，这些偏差会保持不变：再次选择 *Primavera P6* 会重新带来它们，即使在保存并再次打开之后也是如此。如果你在项目设置中选择另一个配置文件，计算选项保持不变；如果它们与新配置文件的默认值不同，计算选项上方会出现一个橙色区块加以说明（见 *此项目的计算选项*）。位置：区块 *计算配置文件和选项*，下拉列表 *计算配置文件*。

**新建配置文件** — 从所选配置文件创建一个自定义配置文件。作用：应用会要求输入名称，并建议 *Primavera P6 的副本*（或你开始时所用配置文件的副本）。*创建* 会生成一个带有所有当前值的自定义配置文件，包括较早文件的偏差，并展开 *此配置文件的约定*。不能使用空名称。之后可以用字段 *此自定义配置文件的名称* 更改名称；没有名称时，*应用* 会拒绝它。项目只有在 *应用* 之后才会使用新配置文件。位置：在列表 *计算配置文件* 旁边。*新建项目* 不显示此按钮。

**勾选或取消勾选一个约定** — 只在自定义配置文件中可用。作用：配置文件随后会偏离其基础。*恢复基准* 会恢复基础值。三个内置配置文件不能更改。位置：区块 *此配置文件的约定*。

**另存为模板**、**从此项目更新模板**、**从模板更新** 和 **删除模板** — 将自定义配置文件作为模板进行管理。作用：模板是一个已保存的配置文件，你可以在任何项目中选择它；项目会保留它自己的副本。如果项目的配置文件与其模板不同，会显示 *此配置文件与模板“…”不同。* 模板不保存在项目文件中。*另存为模板* 会显示模板已保存。如果保存失败，原因是已有 100 个模板，或应用存储空间已满，随后会显示错误消息。*删除模板* 会先要求确认。位置：在下拉列表下方，适用于自定义配置文件。

## 各计算配置的约定

约定是一条规则，各计划软件在这条规则上各不相同。每条约定都是开或关。*此配置文件的约定* 这部分默认折叠。其标题显示约定的数量；如果该配置有偏差，还会显示标记 *已更改：2*。展开后，区块会显示每条约定的值，有偏差的组上会显示标记 *已更改：2*。对于自定义配置，始终显示基准值（*基准：开* 或 *基准：关*）。对于内置配置，只有出现偏差时才显示基准值。对于内置配置，值是标签 *开* 或 *关*，仅供参考。对于自定义配置，值是复选框，有偏差时会出现按钮 *恢复基准*。内置配置上的偏差来自较旧的文件。该行有橙色背景，并有一个区块写明它正在使用中；要改动它，请使用 *新建配置文件*。每行后面的 i 图标显示说明：用鼠标指向它、用 Tab 键聚焦它，或点击或轻触它时即显示。Esc 键只关闭说明，不关闭其下方的窗口。点击其他地方也会关闭说明。页面滚动时，已聚焦图标的说明保持显示。如果某条约定只适用于小时计划，或只适用于来自 `.xer` 文件的任务，该行旁边会有蓝色标签注明：*仅限小时计划* 或 *仅限来自 .xer 的任务*。下文 *条件* 中的 *仅在小时计划下*，与该标签含义相同：指使用带时段的日历，任务工期以小时计算，或 *延迟日历* 设为 *24 小时制*（此时延隔按小时计算）。每条约定的默认值，取决于所选内置配置的设定。*Open Planner Studio* 中所有约定都关闭。每条约定下方说明了 *Primavera P6* 和 *Microsoft Project* 各自的做法。

### 进度与已完成的工作

**在逆推计算中保留实际日期** — 逆推计算时，已开始的任务把其记录的开始日期保留为最晚开始，除非开启了 *进行中任务：最早开始 = 剩余工作的开始*（如在 *Primavera P6* 中那样）。此时其最晚开始为剩余工作的开始。已完成的任务把其实际日期保留为最晚日期。因此，已完成的后续任务不会把未完成的前置任务拉回过去。条件：仅在有状态日期时。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**进行中任务：最早开始 = 剩余工作的开始** — 进行中任务的最早开始和最晚开始，指向剩余工时开始的位置（即状态日期和关系边界中的较晚者），而不是指向实际开始日期。逆推计算经过开始-开始关系时，只计入进行中前置任务的剩余工期；这最后一点只适用于小时计划。条件：是选项 *进行中紧前任务的开始-开始 (SS) 延迟计算起点* 和约定 *进行中前置任务已经过的开始-开始 (SS) 延隔不计* 的依据。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**按实物进度完成的任务位于数据日期** — 已完成的任务在状态日期处为单个点；若前置任务有要求，则位于更晚的日期，而不是位于其实际日期。条件：仅在小时计划下且有状态日期时，适用于来自 `.xer` 文件的已完成任务和里程碑，其完成百分比类型为 *实物*，实际完成不晚于状态日期，且没有暂停和恢复（suspend/resume）。对于其他完成百分比类型（包括 P6 的默认工期），尚未测量，应用不会套用此规则。需要 *进行中任务：最早开始 = 剩余工作的开始*。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**计划开始不是进行中任务的下限** — 文件中的计划开始，对进行中任务（已有实际开始且完成度小于 100%）不是下限：其剩余工时从状态日期开始，紧接其前置任务之后，即使其计划开始更晚。这是 *计划开始作为额外下限* 的对应规则。条件：仅当 *计划开始作为额外下限* 开启时才有效。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**Progress Override 在最晚侧也忽略已开始的后续任务** — 从未完成的前置任务到已开始且未完成的后续任务的关系，在该前置任务的最晚侧或自由浮时中都不计入。因此，后续任务不会向后施加压力，也不是驱动关系。条件：仅在进度模式为 *Progress Override* 时。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

### 关系与延隔

**后续任务从完成边界开始** — 无延隔的完成-开始关系中，若后续任务恰好在前置任务的完成处开始（即在时段结束处），则后续任务可紧接该完成点开始，而不是从下一个时段的开始处开始。逆推计算时，后续任务的最晚开始直接显示为某个时段的开始。条件：仅在小时计划下。文件本身不作标记：应用在打开 `.xer` 文件时自行识别这类关系。你自己创建的关系不适用此规则。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**从完成边界出发的逆推延隔** — 逆推计算时，若应用从某个时段精确的完成边界减去一段以工作时间计的延隔，且正好落在某个时段的开始处，则该点成为前一时段的完成边界。对于无延隔的完成-完成关系，若最晚完成位于时段结束处，也保留在该边界上。条件：仅在小时计划下。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**已完成前置任务已经过的延隔不计** — 对于已完成前置任务之后的正的时段延隔，只计入截至状态日期尚未过去的部分：即延隔减去实际完成与状态日期之间的时段时间，且不小于 0。条件：仅在小时计划下且有状态日期时，并且只适用于来自 `.xer` 文件的任务。在最晚侧生效；正推时，只对带有状态日期点或窗口的已完成前置任务生效（见 *按实物进度完成的任务位于数据日期* 和 *顺序外完成的任务等待其紧前任务*）。仅位于其实际日期处的已完成任务保留完整延隔。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**进行中前置任务已经过的开始-开始 (SS) 延隔不计** — 对于进行中前置任务的开始-开始（SS）关系，且具有正的时段延隔，只计入尚未过去的那部分延隔：即延隔减去前置任务实际开始与状态日期之间的时段时间，且不小于 0。正推时，这从前置任务剩余工时的开始计起；逆推时，前置任务的最晚开始等于后续任务的最晚开始减去该剩余延隔。条件：仅在小时计划下。需要 *进行中任务：最早开始 = 剩余工作的开始*。选项 *进行中紧前任务的开始-开始 (SS) 延迟计算起点* 选择起点。延隔为 0 或更小、以钟点计的延隔，以及完成-开始关系，照常计算。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**最早完成不早于完成-完成边界** — 对于完成-完成关系，后续任务的最早完成永远不早于前置任务的完成加上延隔。若该边界落在后续任务工作时间之外，则最早完成变为该边界之后的第一个工作边界；开始日期保持不变。条件：仅在小时计划下，且有时段延隔时；不适用于硬性完成约束或吊床任务。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

### 里程碑与 LOE 任务

**里程碑跟随计划的日历边界** — 无工期的里程碑停留在文件所计划的日历边界上：计划在某天开始处的里程碑仍为开始里程碑；计划在某时段结束处的里程碑，可能落在前置任务的完成处。条件：仅在小时计划下。工期为 0 的任务也可以以这种方式位于两个边界上（开始在下一时段开始处，完成在上一时段结束处），但仅当它来自 `.xer` 文件且其计划完成早于计划开始时。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**未开始的 LOE 活动使用目标窗口** — 尚未开始的 LOE 任务（应用中的吊床任务），若其目标窗口完整，则以该目标窗口作为其跨度。条件：仅在小时计划下，且仅当该活动来自 `.xer` 文件，其只有开始-开始的入边关系和完成-完成的出边关系，且没有延隔时。此规则的依据薄弱：只有一个文件。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**与开始里程碑的完成-完成关系绑定到里程碑本身** — 与开始里程碑（工期为零，类型为 *开始*）的完成-完成关系，绑定到该里程碑本身的最晚完成，而不是里程碑当天的开始。因此，前置任务的自由浮时不再短一个工作日。该里程碑的最早开始从不改变。条件：仅在小时计划下；完成里程碑保持不变。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

### 浮时与最晚日期

**自由浮时永不为负** — 若最晚约束无法满足，总浮时仍为负，但自由浮时变为 0，而不是负数。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**按任务自身日历计算自由浮动** — 未开始任务的自由浮时，按每条关系，在任务自身的日历中计算，而不是在后续任务的日历中计算。这对完成-开始、开始-开始和完成-完成关系都成立。带延隔（不为 0）的关系，只有在延隔日历为 *前置任务* 时才适用；否则保留后续任务的日历。无延隔的关系始终适用。已开始但未完成的任务，只在无延隔的完成-开始关系下适用。条件：仅在小时计划下。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**在任务自身日历上的最晚完成** — 若后续任务施加的最晚完成落在任务自身工作时间之外，则最晚完成变为任务自身日历上前一个期间的结束。更严格的约束或截止日期优先。这是 *按任务自身日历计算自由浮动* 在最晚侧的对应规则。条件：仅在小时计划下，且不适用于项目完成。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**ALAP 任务尽可能晚，以后续任务允许为限** — 未开始且带有约束 *越晚越好 (ALAP)* 的任务，其最早完成取其后续任务按其最早日期所允许的最严格边界（精确到分钟），其最早开始则为该完成减去其工期。任务自身的计划窗口不计入；下限为其前置任务和状态日期。条件：仅在小时计划下；在按天的日历上，仍按整工作日的常规步长计算。ALAP 任务尽可能晚，后续任务先算，ALAP 链因此衔接起来。这在每个配置中都成立，并以整个工作日为单位。本约定增加了按后续任务最早日期进行的、精确到分钟的定位。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

### 文件中的日期与时刻

**计划开始作为额外下限** — 文件中的计划开始，作为网络之外的额外下限计入，但只有当开始和完成都比网络所允许的时间晚一个以上日历日时才适用。普通的开始在下一个工作时段，不会触发此规则。条件：只要 *计划开始不是进行中任务的下限* 开启，它就不适用于进行中任务；也不适用于由其后续任务定位的未开始 ALAP 任务，即 *ALAP 任务尽可能晚，以后续任务允许为限*。此约定不看任务来自何处，只看其计划开始和计划完成。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**精确保留实际日期** — 已记录的实际开始和完成日期，连同其时刻，保持精确，不会移到时段的边缘。条件：仅适用于来自 `.xer` 文件的任务。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

**里程碑上精确的约束时刻** — 带日期和时刻的约束（SNLT、MSO、FNLT 或 MFO）作用于无工期的里程碑时，是一个精确的点，即使该点恰为某时段的开始。条件：仅在小时计划下，且在最晚侧；正推时，此类时刻在所有配置中已经是精确的。默认：Primavera P6 下为开，Microsoft Project 和 Open Planner Studio 下为关。

### 与 Microsoft Project 相同的进度处理

**剩余工时在已过工期之后恢复** — 进行中任务的剩余工时，从状态日期、前置任务边界和实际开始加上已用时间这三者中的最晚者开始。在 *Primavera P6*（Retained Logic）下，只计入前两者；第三个下限只能使剩余工时更晚。条件：不适用于 *Progress Override*，不适用于没有剩余工时的情况，也不适用于文件为任务给出恢复日期（Resume）的情况（仅当任务最多只有一个分配时）。默认：Microsoft Project 下为开，Primavera P6 和 Open Planner Studio 下为关。

**不要把未开始的任务移到状态日期** — 没有进度的任务不会自行移到状态日期当天或之后。关闭此项后，会应用 P6 在 Retained Logic 下确实具有的下限。默认：Microsoft Project 下为开，Primavera P6 和 Open Planner Studio 下为关。

### 仅限自定义配置

这些约定在每个内置配置中都是关闭的，包括 Primavera P6。只有自定义配置能开启其中的约定：请使用 *新建配置文件* 创建一个。

**完成里程碑作为边界窗口** — 完成里程碑可以位于两个相邻的日历边界上：最早开始在某时段的开始处，最早完成在前一时段的结束处。在最晚侧，没有后续任务但有前置任务的完成里程碑，会把其最早日期作为最晚日期，因此会对其任务链施加向后的压力，除非开启了 *计算浮时至项目完成日期*。其自由浮时仍为到项目完成之间的空间。条件：边界窗口（最早开始和最早完成位于两个边界上）只有在文件以该方式计划里程碑时才适用：计划完成早于计划开始。对任务链的压力适用于每个没有后续任务的完成里程碑。仅在 P3 的输出中见过；对 P6 计算的文件没有影响。默认：在每个内置配置中均为关。

**状态日期窗口中的已完成任务** — 已完成的任务以状态日期窗口作为其最早日期，且该窗口计入项目完成和浮时。条件：仅在有状态日期时，适用于来自 `.xer` 文件的已完成任务，其完成百分比类型为工期，任务类型为 *固定工期和工时*（在 P6 中：Fixed Duration & Units）；不适用于里程碑。需要 *进行中任务：最早开始 = 剩余工作的开始*。仅在 P3 的输出中见过。默认：在每个内置配置中均为关。

**已完成的 LOE 活动经由其实际完成日期** — 只有一个开始-开始入边关系、且没有后续任务的已完成 LOE 任务，沿着经由其实际完成日期的路线计算，而不走常规的吊床路线。条件：仅适用于来自 `.xer` 文件的任务；需要 *进行中任务：最早开始 = 剩余工作的开始*、*在逆推计算中保留实际日期* 和 *精确保留实际日期*。仅在 P3 的输出中见过。默认：在每个内置配置中均为关。

**已完成的前置任务不超过状态日期** — 若已完成的前置任务，按其实际完成日期，结束于状态日期之后，则完成-开始和完成-完成关系从状态日期窗口的边界计算，而不是从该实际完成日期计算。开始-开始关系仍按实际开始计算。条件：仅在小时计划下且有状态日期时。默认：在每个内置配置中均为关。

**顺序外完成的任务等待其紧前任务** — 若已完成的任务，其某个前置任务尚未完成（顺序外），则其零剩余窗口不在状态日期处，而在状态日期与该前置任务的常规关系边界两者中的较晚者处。条件：仅在小时计划下。适用于 *状态日期窗口中的已完成任务* 的状态日期路线，因此也只适用于来自 `.xer` 文件的任务。该约定与 *进行中任务：最早开始 = 剩余工作的开始* 也必须开启。不适用于 *Progress Override*。默认：在每个内置配置中均为关。

## 此项目的计算选项

这些选项位于 *此项目的计算选项* 下，在约定的下方。如果项目已应用的计算选项与所选配置文件的默认值不同，顶部会出现一个橙色区块。如果你自己更改了字段，区块会等到你选择 *应用* 或 *放弃* 才消失；否则它显示的值会与字段不一致。选择其他配置文件后，区块会立即更新。对于每一处差异，它都会列出字段名、当前值和默认值，例如 *关键定义：最长路径（默认：总浮时 ≤ 0 小时）*。空字段按该字段显示的默认值计算。对于自定义配置文件，适用其基础配置文件的默认值。按钮 *使用 Primavera P6 的默认设置*（带配置文件名称）会把字段设为该默认值。应用只在你选择 *应用* 后一次性计算，并且可以用 *撤销* 一步还原。叉号会为这个打开的文件隐藏该区块。重新打开文件，或出现新的差异时，区块会再次出现。没有差异时，不显示区块。该按钮对源文件选项的处理方式见 *源文件中的设置*。各配置文件的默认值如下：*Open Planner Studio* 和 *Microsoft Project* 没有自己的值，因此下方每个选项都是默认值（对于 *Microsoft Project*，有状态日期时的 *自动（默认）* 也是 MS Project 自身的浮时规则）。*Primavera P6* 将 *延迟日历* 设为 *前置任务*，*关键定义* 设为 *总浮时 ≤ 阈值*，阈值为 0 小时，*浮动计算* 设为 *结束浮动*，*开放式任务视为关键* 设为关闭，*进行中紧前任务的开始-开始 (SS) 延迟计算起点* 设为 *剩余工作开始（P6：最早开始）*。`.xer` 文件本身也会带入一些值。

**关键定义** — 决定哪些任务是关键任务。可从 *总浮时 ≤ 阈值* 和 *最长路径* 中选择。默认值：*总浮时 ≤ 阈值*，阈值为 0。效果：选择 *总浮时 ≤ 阈值* 时，如果任务的总浮时小于或等于阈值，它就是关键任务。选择 *最长路径* 时，如果任务位于通往最后完成时间的链上，它就是关键任务。如果有几个结束任务的完成时间相同，它们各自的链都算数。此时浮时不起作用。两种情况下，已完成的任务都不是关键任务，吊床任务也不是。它适用于 Gantt、表格、里程碑概览和报表。位置：*此项目的计算选项*。

**阈值（工作日）** — *总浮时 ≤ 阈值* 的界限。默认值：0。效果：阈值可以是负数。由 `.xer` 文件带入的阈值，或由 *Primavera P6* 默认值设定的阈值（0 小时），以小时为单位，此时称为 *阈值（小时，按任务日历）*。应用会按任务自己的日历，以小时比较每个任务。位置：*此项目的计算选项*，位于 *关键定义* 旁边。

**浮动计算** — 决定总浮时如何计算。可从 *自动（默认）*、*最小值（开始/结束）*、*开始浮动* 和 *结束浮动* 中选择。默认值：*自动（默认）*，*Microsoft Project* 下也是如此；*Primavera P6* 设为 *结束浮动*。效果：*开始浮动* 是最晚开始减去最早开始，*结束浮动* 是最晚完成减去最早完成，*最小值（开始/结束）* 是两者中较小的一个。*自动（默认）* 对进行中的任务（有实际开始日期或进度，并且有状态日期）使用结束浮动，对其他所有任务使用较小值。有状态日期时，这就是 MS Project 的规则。没有状态日期时，进度不计入，已开始的任务也取较小值；此时 MS Project 仍会对已开始的任务取结束浮动。打开的 .mpp 文件，以及选择 *Microsoft Project* 的新项目，都按这种方式计算。*最小值（开始/结束）* 对进行中的任务也取较小的一个。位置：*此项目的计算选项*。

**开放式任务视为关键** — 没有后续任务的任务。默认值：关闭。效果：开启时，此类任务的总浮时和自由浮时为 0，因此在 *总浮时 ≤ 阈值* 的关键定义下，它会成为关键任务（已完成的除外）。关闭时，按正常方式计算浮时，直到项目结束。位置：*此项目的计算选项*。

**标记接近关键** — 标记几乎没有浮时的任务。默认值：关闭。效果：开启后会设置一个阈值，默认为 2 个工作日（字段 *阈值*）。总浮时大于 0 且不超过该阈值的任务称为 *接近关键*。总浮时正好为 0 的任务是关键任务，不计入。你可以在表格的 *接近关键* 列、报表以及 Gantt 中看到它。在 Gantt 中，任务条会变成琥珀色（除非该任务是关键任务）。该字段以工作日为单位。开启 *启用小时计划* 后，如果工期显示为 *始终按小时*，该字段以小时为单位；如果工期显示为 *自动（按任务自身单位）* 且项目日历是小时日历，该字段同样以小时为单位。位置：*此项目的计算选项*。

**多条浮时路径** — 按浮时为任务链编号。默认值：关闭。效果：开启后，任务会在表格的 *浮时路径* 列中获得一个编号。在 Gantt 中，路径 2 及更高路径的任务条会获得各自的底色，除非它们是关键任务或接近关键任务。关闭时，该列留空。位置：*此项目的计算选项*。

**方法** — 路径如何产生，与 *多条浮时路径* 一起使用。可从 *自由浮动（剥离法）* 和 *总浮时（排序法）* 中选择。默认值：*自由浮动（剥离法）*。效果：选择 *自由浮动（剥离法）* 时，应用会逐层剥离任务链。它先选出完成时间最晚的任务，并加入通过驱动关系与之相连的前置任务：这就是路径 1。对于剩余任务，它以同样方式得出路径 2，依此类推。共享的前置任务保留其首次出现的路径编号。选择 *总浮时（排序法）* 时，编号是任务总浮时的排名：最小值为 1，次小值为 2。吊床任务不参与计算。位置：*此项目的计算选项*。

**最大路径数** — 有多少条路径会获得编号。默认值：10。效果：超出前 *最大路径数* 条路径或排名的任务不获得编号。位置：*此项目的计算选项*，与 *多条浮时路径* 一起。

**延迟日历** — 工作时间的延隔按哪个日历计算。可从 *前置任务*、*后续任务*、*24 小时制* 和 *项目日历* 中选择。默认值：*前置任务*。效果：2 天的延隔按你所选日历中的工作日计算。位置：*此项目的计算选项*。另见 [关系和延隔](docs://uitleg-relaties)。

**进行中紧前任务的开始-开始 (SS) 延迟计算起点** — 这是约定 *进行中前置任务已经过的开始-开始 (SS) 延隔不计* 的一种变体。可从 *剩余工作开始（P6：最早开始）* 和 *状态日期（P6：实际开始日期）* 中选择。默认值：*剩余工作开始（P6：最早开始）*。效果：对于开始-开始（SS）关系，如果前置任务正在进行且有正的工作时间延隔，选择 *剩余工作开始（P6：最早开始）* 时，后续任务从前置任务剩余工作的开始时间加上剩余延隔后开始。选择 *状态日期（P6：实际开始日期）* 时，后续任务从状态日期加上剩余延隔后开始，并且该关系不会对进行中的前置任务做逆向约束。剩余延隔是延隔减去实际开始日期与状态日期之间的工作时间，且不小于 0。延隔为 0 或更小、以时钟小时计的延隔，以及以天为单位的计划，都保持正常行为。只有当约定 *进行中前置任务已经过的开始-开始 (SS) 延隔不计* 和 *进行中任务：最早开始 = 剩余工作的开始* 都开启时，此选择才有效。否则下拉框会被禁用，并显示 *仅在惯例“…”开启时生效。* 如果所选延隔日历上没有小时计划，下拉框同样被禁用，并显示 *仅在小时计划下生效：日历需包含工作时段，或任务以小时计算。本项目所选的延隔日历两者都没有。* 使用 *24 小时制* 时始终启用小时计划；使用 *项目日历* 时，若项目日历包含工作时段则启用；使用 *前置任务* 和 *后续任务* 时，若项目的某个日历包含工作时段或某个任务以小时计算则启用。位置：*此项目的计算选项*。

### 源文件中的设置

这些选项来自 Primavera P6 的 `.xer` 文件，且为只读。只有项目包含这些选项时，区块 *源文件中的设置* 才会出现，即项目来自 `.xer` 文件时。这些选项参与计算。按钮 *使用 … 的默认设置* 和其他配置文件都会保持文件中的原样。它们也不计为差异。新建项目不会获得这些选项，即使选择 *Primavera P6* 也一样。

**使用预期完成日期（P6：Use Expected Finish Dates）** — 默认值（若文件未说明）：开启。效果：P6 中有预期完成日期的进行中任务，会以该日期作为最早完成。位置：*源文件中的设置*。

**计算浮时至项目完成日期** — 默认值：关闭。效果：项目的完成日期是最晚日期的基准。如果文件中没有完成日期，应用会计算到网络的结束。位置：*源文件中的设置*。

**已完成任务：最晚日期从状态日期起算** — 默认值（若文件未说明）：开启。效果：已完成任务在最晚端也会在状态日期上获得零剩余工期，并带有有意义的浮时。它只与约定 *状态日期窗口中的已完成任务* 一起生效，该约定在每个内置配置文件中都是关闭的。如果该约定关闭，会显示 *仅与规则“…”一起生效，该规则当前已关闭。* 位置：*源文件中的设置*。
