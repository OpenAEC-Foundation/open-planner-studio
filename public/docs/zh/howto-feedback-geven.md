# 提供反馈

目标：直接在应用中报告错误或提出想法，可选择附加截图。

## 何时需要此操作

计划计算出你不理解的结果，某个按钮没有做它应该做的事，或者你在应用中找不到某些内容。好的报告能帮助开发者找到问题。因此，应用会自行把版本、操作系统和语言放入你的报告中。你自己描述的内容决定开发者能否据此采取行动：你做了什么、你预期什么，以及实际发生了什么。

## 步骤

1. 点击窗口顶部的按钮 *发送反馈*。该按钮始终位于标题栏中。它的文字每十分钟变化一次：*发送反馈*、*报告缺陷* 和 *提出新功能*。它始终是同一个按钮。随后会打开 *发送反馈* 窗口。
2. 选择反馈类型。*功能异常* 用于报告错误：某个功能没有按预期工作。*想法* 用于你希望有但缺少，或希望改变的内容。*问题或意见* 用于其他情况。默认选中 *功能异常*。
3. 填写 *标题*，然后填写 *描述*。空白字段会显示示例：标题示例为 *例如：保存后关键路径跳动*，描述字段显示问题 *你做了什么，你期望什么，实际发生了什么？*。只要 *发送* 按钮为灰色，旁边的灰色文字会说明原因，例如 *请填写标题。*，或说明标题和描述合计至少要写 10 个字符。
4. 如果你希望收到回复，请填写 *电子邮件地址*。该字段可不填。成功发送反馈后，应用会记住该地址，因此下次已自动填入。
5. 如果你想展示某些内容，请开启 *附加截图*。应用随后会截取应用界面的图片，不包括本窗口。稍后你会看到一个小预览图，旁边有三个按钮：*标注*、*重新截图* 和 *移除*。
6. *标注* 会打开编辑器。你可以在图片上添加箭头、矩形、手绘线条和文字。使用 *遮盖* 可在不应随附的内容上画一块黑色区域，例如姓名或金额。该部分会从应用发送的图片中真正移除。你可以选择颜色，用 *撤销* 撤回上一步操作，或用 *清除全部* 重新开始。点击 *完成* 保存更改，或点击 *取消*（或 Esc）放弃更改。
7. *重新截图* 会生成新的截图，并清除你的标注。*移除* 会删除截图并取消勾选复选框。
8. 查看表单下方的灰色行 *随附*。该行显示应用自动随附的内容：版本、操作系统和语言，例如 *随附：v2026.10.1 · Windows · English*。
9. 点击 *发送*。发送期间，按钮显示 *正在发送…*。
10. 你会看到 *谢谢，你的反馈已发送。* 如果为你的反馈在 GitHub 上创建了议题，还会出现 *在 GitHub 上查看* 按钮。点击 *关闭*。

## 你的反馈去向

应用会将你的反馈发送到 OpenAEC 的 Open Feedback Studio。这不需要账户，在 GitHub 上也不需要。开发者会在其概览中看到你的反馈。如果该处已与 GitHub 连接，Open Feedback Studio 还会将其转为 GitHub 上的公开议题。选择 *功能异常* 时，议题会带上标签 *bug*；选择 *想法* 时，议题会带上标签 *enhancement*。在你的描述下方会有一行，内容为 Open Planner Studio 的版本、你的操作系统和应用语言。

## 注意事项及应用的处理方式

**你的反馈可能会公开。** 不要在其中填写任何你不想分享的内容。截图也是如此：图片会显示当时应用中所有可见的内容，例如你项目中的任务名称和资源。应用会在你开启 *附加截图* 时截取屏幕。如果屏幕还不对，请关闭窗口，把屏幕调整好，再重新打开窗口并点击 *重新截图*。用 *遮盖* 隐藏你不想展示的内容。

**截图太大。** 应用会在发送前先缩小截图。如果仍然太大，反馈会在没有图片的情况下发送。感谢页面随后会显示 *截图太大，未随附发送。*

**发送失败。** 窗口中会出现一条消息，你的文字会保留。有四种情况：

- *反馈未被接受。* 请检查文字和电子邮件地址。主要由网址组成的反馈会被拒绝。
- *你在短时间内发送了很多反馈。* 请一小时后再试。
- *发送失败。* 没有网络连接，或服务器无响应。请再试一次，或点击 *在 GitHub 上打开*。如果之前的发送结果不确定（见下文），则不会出现该按钮。
- *我们无法确定你的反馈是否已送达。请等待一分钟后再次发送；如果已经送达，我们会自动识别。* 应用发送反馈后，连接中断了。你的文字会保留。这种情况下不会出现 *在 GitHub 上打开* 按钮，因为你的反馈仍可能到达。在反馈发送成功或已被接收之前，该按钮都不会出现，即使你中途关闭窗口并重新打开也是如此。

**反馈已被接收。** 如果你发送的反馈已经存在，表单上方会显示以下提示：*我们已收到此反馈。想补充些什么？请修改文本后再次发送。* 你的文字和电子邮件地址会保留。如果不想补充内容，请点击 *关闭*；下次打开时表单为空。如果你又输入了内容，该提示会消失，你可以再次发送；此时按钮会再次显示为 *保存并关闭*，并保留你的文字。

**在 GitHub 上打开。** 这是不经过 Open Feedback Studio 的途径。使用此途径，你需要一个 GitHub 账户。没有截图时，用于创建新议题的 GitHub 页面会直接在浏览器中打开，标题和描述已预先填写。有截图时，你会先看到 *即将完成 — 截图已复制到剪贴板。* 以及四个步骤。点击 *确定，前往 GitHub*，在议题页面的大文本框中点击，然后按 Ctrl+V（Mac 上为 Cmd+V）。然后点击底部的 *提交新议题*。只有这样，你的反馈才会发送。

**粘贴不起作用。** 在 GitHub 途径中，截图也会另存为你电脑上的文件。在桌面应用中，窗口会显示该路径：*粘贴不了？我们还将截图保存到* 该路径 *— 将该文件拖入文本区域。* 在浏览器中，应用会将图片下载为 `feedback-` 加数字编号并以 `.png` 结尾的文件。你可以在下载文件夹中找到它，并将其拖入文本区域。

**截图失败。** 窗口会显示 *截图失败。您仍然可以在没有截图的情况下发送反馈。* 复选框会被取消勾选，你可以不带图片发送反馈。

**你在发送前关闭窗口。** 如果表单中有内容，底部按钮显示为 *保存并关闭*；表单为空时，显示为 *关闭*。*保存并关闭*、× 按钮和 Esc 都会关闭窗口，你的反馈会保存为草稿，直到你发送它或点击 *清除*。再次打开窗口时，反馈类型、文字、电子邮件地址和带标注的截图仍然保留。只要应用保持打开，草稿就会保留；退出应用后，草稿会消失。成功发送反馈后，表单会再次变为空白。如果你想自己重新开始，请点击左下角的 *清除*。点击窗口外侧不会关闭窗口。发送期间，Esc 不会关闭窗口。
