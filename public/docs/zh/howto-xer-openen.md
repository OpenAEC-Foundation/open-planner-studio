# 打开 Primavera P6 文件（.xer）

目标：直接在应用中打开 Primavera P6 的计划，无需先导出为 XML。

## 何时需要此操作

客户或总承包商在 Primavera 中工作，并以 `.xer` 文件交付他们的计划。你想查看、计算或添加内容。应用只读取 `.xer` 文件：它不会写入 `.xer`，也不会更改你的文件。应用从文件中读取 WBS 结构，以及带有工期、日期、约束和进度的任务，带延隔的关系，日历，带分配的资源，还有活动代码、自定义字段（UDF）、备注和 P6 的计划设置。类型为 *工作量级别* 的任务会成为吊床任务。

## 步骤

1. 选择 *首页 › 文件 › 打开*，或按 Ctrl+O。选择 `.xer` 文件。
2. 应用会为每个包含任务的项目打开一个标签页。任务最多的项目是当前标签页。如果 P6 项目 ID 与项目名称不同，标签页名称为 *项目名称（项目 ID）*。*项目设置* 只显示名称。如果你重命名项目，项目 ID 会保留在名称之后。随后会出现一个窗口，简要说明应用从文件中接管了哪些内容，以及保存方式如何运作；见 [打开和保存文件](docs://howto-bestand-openen-en-opslaan)。
3. 阅读底部的消息。对于包含三个项目的文件，消息可能如下所示：*已打开 XER 文件：3 个项目文档。* 其下方是说明应用所做操作的行。见下面的标题。
4. 检查功能区下方是否有一个栏，显示：*你正在查看 Primavera 记录的进度计划；重新计算将使 1 个任务偏移。* Primavera 会在文件中记录其自身计算出的日期。如果应用的计算与这些日期不同，只要你不做任何更改，应用就会显示 Primavera 的日期。已开始或已完成的任务始终使用其实际日期，与 Primavera 中一样。其含义以及如何切换到应用自己的计算，见 [按记录的日期](docs://uitleg-datums-zoals-opgeslagen)。消息 *此文件包含按小时的计划。* 也可能出现，并带有按钮 *启用小时计划*。见 [启用小时计划](docs://howto-urenplanning-aanzetten)。
5. 用 Ctrl+S 保存项目。由于 `.xer` 从不会被覆盖，应用会询问新的 IFC 文件保存位置。它建议以 *项目名称（项目 ID）* 作为文件名。

### 消息下方的行

消息的第一行给出已打开的标签页数量。其下方只显示适用的行。以下各行需要你注意：

- *本项目按 Primavera P6 计算。可通过 文件 → 项目信息 → 计算配置文件和选项 更改。* 应用按照 Primavera 的计算规则计算此项目。使用 *打开计算配置文件* 即可进入该设置。
- *已排除的基线项目：1* 和 *已具体化的基线：1*。如果 P6 中的某个项目将另一个项目指定为其基线，那个项目不会作为单独的标签页打开。它会成为引用它的项目的当前基线。
- *已使用保护性基线回退。* 如果指定基线会导致没有任何项目打开，如果某个项目引用自身，或者项目之间相互循环引用，应用会直接打开所有项目，并且不创建基线。
- *已保留的外部关系：1* 两个项目之间的一种关系。应用将其保留为源数据，但不会把它变成你计划中的关系。
- *显示 Primavera 记录日期（未重新计算）的任务：12 个。* 这是 *按记录的日期* 视图显示 Primavera 日期的任务数量：包括文件中记录了日期的每个任务，而不只是有差异的任务。

其他行是对读取过程本身的诊断信息。它们不需要你做任何操作：

- 找到的项目数量。
- 跳过的空项目。
- 忽略的悬空基线引用。
- 不是纯 UTF-8 的文本编码。消息会说明是哪一种：对于阿拉伯语、西里尔字母或希腊语文本，应用会选择对应的 Windows 代码页，否则使用 Windows-1252。
- 没有计划的开始日期的任务。它们从状态日期或文件中的项目开始日期起算。
- 表、日历和数字中发现问题的计数，未知字段值的计数，以及应用替换为安全选择的 P6 排程设置的计数。

*了解更多* 会打开帮助中关于打开 Primavera 文件的内容。

## 易错点，以及应用随后的处理方式

**并非所有内容都会变成标签页或关系。** 没有任务的项目不会打开，基线项目不会作为单独的标签页打开，两个项目之间的关系也不会变成你计划中的关系。应用会在消息下方的行中报告这些情况。

**每个标签页都是一个独立的项目。** 如果你保存其中一个，IFC 文件会同时保留完整的原始 `.xer`。之后重新打开该 IFC 文件时，应用仍然知道 Primavera 的日期。如果该源存档已损坏，或另一个 IFC 程序改写了该文件，应用会报告：*此文件中的 XER 源存档不可用，已被略去；项目本身已完整打开。* 计划、计算配置文件和所有项目数据都是完整的。缺少的是：Primavera 保存的日期，以及 AI 和扩展所用的源来源信息。重新打开原始 `.xer`，即可恢复存档。

**IFC 文件会变大。** 由于 IFC 文件携带整个原始 `.xer`，它比没有存档的 IFC 文件大。对于较大的 `.xer`，你会在文件大小和保存所需时间上注意到这一点。如果一个 `.xer` 打开了多个项目，你保存的每个标签页都会携带整个 `.xer`，而不只是其自身的项目。

**导出为 CSV、MS Project XML 或 P6 XML 会丢失数据。** 应用会发出警告：*导出为 CSV 会丢失 XER 源信息。* IFC 不会丢失任何数据。

**文件中没有的空闲周六或周日。** 应用可以自行将该周末日设为空闲。该日在日历中称为 *日历例外（周末重建）*。其模式见 [导入和导出格式](docs://ref-import-exportformaten)。

**浮时计算至项目完成，但文件没有完成日期。** 如果文件没有完成日期，应用会关闭选项 *计算浮时至项目完成日期*。这会计入行 *使用安全回退的 P6 排程设置：N* 中。详情见 [导入和导出格式](docs://ref-import-exportformaten)。

**状态日期上的已完成任务。** 已完成的任务可能在 *按记录的日期* 视图中，以状态日期上的一个窄任务条显示。这不是你文件中的错误。说明及相关约定见 [导入和导出格式](docs://ref-import-exportformaten)。

**数字使用逗号作为小数分隔符。** 如果应用无法可靠地确定小数分隔符，就不会打开该文件。这样，读错数字的计划就永远不会打开。请向发送方索取新的导出文件。

**应用无法读取的文件。** 你会收到一条错误消息，并附有原因。以下是几个例子：

- *这不是有效或受支持的 XER 文件。*
- *XER 表缺少必填列。*
- *此 XER 文件中的 P6 项目不包含作业。*
- *无法可靠确定此 XER 文件的小数表示法。*

这时没有任何内容会打开。请在 P6 中检查该文件，或向发送方索取新的导出文件。
